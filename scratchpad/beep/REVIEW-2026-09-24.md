# CodeRabbit findings on the OMI model port (PR #1221, 2026-09-24)

These landed on PR #1221 while the port was under active edit in another lane, so they were not
fixed there. Each line is the reviewer's claim, unverified here; check it against the live file.

- `Announcement.ts:931` — `decodeAnnouncement` re-decodes the already-decoded `targeting` and
  `display` models through `optionalNull(Targeting)` / `optionalNull(Display)`; keep the raw wire values.
- `Conversation.ts:2129` — `conversation_ids` is `pg.jsonb()`; `textBoundsCheck` emits
  `char_length(...)`, which Postgres rejects on jsonb. Use `jsonbArrayLengthCheck` from `Port.ts`.
- `DevApiKey.ts:97` — the `DevApiKey.make` example passes an ISO string for `createdAt`; the decoded
  type is `DateTime.Utc`.
- `JitProactivity.ts:337` — examples call `DateTime.unsafeMake`; rc.117 exports `DateTime.makeUnsafe`.
- `KnowledgeLedgerSearch.ts:349` — `invalidAt`, `validTo`, `supersededBy` are compared with `null`
  while rows carry `Option` values; `O.none()` is an object, so open rows read as closed. Unwrap first.
- `MemoryImports.ts:316` — the batch request decodes `items` with `MemoryImportBatchItem`, so the
  identity rule in `CheckedMemoryImportBatchItem` never runs on the request path.
- `MemoryProduct.ts:216` — `R.fromEntries([...R.toEntries(value), ...extra])` lets an unknown key
  replace an existing `rest` key; the doc says unknown keys only fill holes.
- `MemorySearchGateway.ts:435` — the doc example imports `memoryAccessPolicyForOmiChat` from this
  module; it is exported by `ProductMemory.ts`.
- `Port.ts:133` — `optionDefault` decodes `NullOr(schema)` then `S.Option(schema)`, a double decode
  that fails when `Type` differs from `Encoded` (see `Kit.ts` 405-408); use `S.toType(schema)`.
- `ScreenFrame.ts:968` — `truncateCaption` keeps 160 code points but `boundedText` checks UTF-16
  units, so astral captions pass judgement and fail the frame decode; count consistently.
- `MemoryRecurrence.ts:72` — the aware-timestamp pattern validates shape only; `DateTime.makeUnsafe`
  still throws on `2020-02-31T25:00:00Z`. Route through `DateTime.make` / `UtcTimestamp`.
- `ProductMemory.ts:1426` — `sensitivityLabels` are compared without normalization in
  `basePolicyChecks`; `" HEALTH "` bypasses the restricted-sensitivity denial. Normalize first.
