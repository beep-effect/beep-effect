# Phase 14: schemas that carry their own rules (2026-11-18)

In process only. No swarm, deploy or container this phase. Everything here is in the working tree;
`bun run check` exits 0 and `bun run test` passes 222 tests.

## Initial values and defaults

Every field with one canonical starting value carries it (`@proto/kernel/Initial`): a constructor
default, so `State.make({})` is the initial state, and a decoding default, so a missing key reads
the same value. An optional field that starts absent is an optional key. Each owner's `initial` is
`State.make({})`.

- **Not defaulted, on purpose.** A grant's `expires` and `operations`, delegation references,
  invocation chains, `parentDelegation`, a run's `parent` and `previous`, allowances. Their empty
  value is the widest one, so they stay required and are refused when left out.
- **Left on `null`.** `corroboration` on `ProposalApproved`: the stored tapes hold `null` there.
- **Descriptions go first.** A key annotation placed after a decoding default, or after
  `S.OptionFromOptionalKey`, is left out of generated JSON Schema. The helpers take the description
  and apply it before the default.

## Ids have a pattern, and the published fact was re-pinned

All eleven ids are `IdText` (`@proto/kernel/Measure`): a letter or digit, then letters, digits,
`_`, `.`, `:`, `~` or `-`. Never empty, never a `/`, so an id is a stream-id or storage-path segment
as it is.

- **The re-pin.** `party/contract/test/snapshots/ClaimDecided.v1.schema.json` and `.v2.schema.json`
  were regenerated the same day. The only change: `org`, `claim` and each `reviewRuns` item now
  refer to the `IdTextCheck` definition instead of a bare string. This changes versions 1 and 2 of a
  published contract, which the freeze rule (D34, D40) otherwise forbids; the owner approved it
  because no producer ever emitted an id the pattern refuses, so no stored fact stops reading.
- **What the document does not show.** Effect 4.1.4 does not emit a `pattern` keyword for
  `S.isPattern`. The definition carries the title and the description of the rule; a consumer that
  validates with the JSON Schema alone does not enforce it.

## Tagged values are told apart by their schema

No direct `_tag` comparison remains. A set of tagged values that one site tells apart is declared
once as a union (`RunGrantRefusal`, `RunReportRefusal`, `ResumeParentTrigger`,
`MergeOnSamePartyTrigger`, `ClaimReviewEvent`, and one local to the runs gateway adapter), and
branches use its `match`, `isAnyOf` or `guards`. Service methods and exported helpers with a
subject are `dual`.

## Tables come from row schemas

The two Postgres adapters run on tables derived with `@beep/effect-drizzle`, defined in the host
beside each adapter. A projection store's rows are one table per generation. Migrations are
generated by drizzle-kit, committed under each host's `migrations/`, checked by
`bun run generated:check`, and applied on connect. Both adapters are held to the same laws as the
in-memory stores, on PGlite.

- **Not verified.** Anything only a cluster run shows: the row lock between two runners, two
  runners migrating at once, the production client's name transforms, and the new table name in
  `conformance/test/Own.conformance.ts`.
- **Old databases are not adopted.** A database created by the earlier adapters already holds the
  process tables and keeps its rows in `party_directory_rows`; the first migration does not move
  them.
- **What the library lacked** is in `notes/effect-drizzle-opportunities.md`.

## Annotations

Every event and every contract read has a plain `description`; each model view passes its
contract's annotations, so the two cannot drift. The two session errors are described.
