#3424 fixes one case of a wider gap. We hit another case of it on 2.0.0-beta.87, with the same root cause.

On a runner, `layerEntities` gives the model a namespace built as `makeNamespace(objects, { url: "", token: "", service: "" })`. `makeNamespace` routes a call through Effect Cluster only when the calling fiber has `Sharding`; otherwise it builds an HTTP RPC client from that empty URL. Entity handlers have `Sharding`. A fiber the model's Layer starts while it builds does not: the bootstrap builds the entrypoint Layer before the cluster Layer exists. #3424 covers the deploy's backfill runs (`Host.begin`). The same thing happens to every call the model makes from its own fibers.

Our failing case was a model whose Layer forks a poller with `Effect.forkScoped`. The poller reads another model's fact stream and sends a command for each fact. On a two-runner Effect Cluster (PostgreSQL 17, a single-node Docker swarm), every read the poller made failed with

```text
RpcClientError: HttpError: InvalidUrl (POST /rpc/)
```

The fact was published and never consumed, and a run waiting on it never concluded. A stream's `list`, a view's `get` and a command's `send` fail the same way from such a fiber.

Our change hands every call without `Sharding` the runner's own `Sharding`, waiting until the runner has joined. Calls that already carry `Sharding` are untouched:

```ts
const joined = yield* Deferred.make<Sharding.Sharding["Service"]>();
// in the Layer launched inside the cluster, beside the workflow engine:
yield* Deferred.succeed(joined, yield* Sharding.Sharding);

const inCluster = makeNamespace(objects as never, { url: "", token: "", service: "" });
const self = remote({
  getByName: (id: string) =>
    Effect.flatMap(Effect.serviceOption(Sharding.Sharding), (current) =>
      Option.isSome(current)
        ? inCluster.getByName(id)
        : Effect.flatMap(Deferred.await(joined), (sharding) =>
            Effect.provideService(inCluster.getByName(id), Sharding.Sharding, sharding),
          ),
    ),
} as never);
```

With it, the poller consumed the fact and the run completed, across a runner restart and across a `pg_dump` and restore into a fresh stack. It ran in every one of six deploy-and-test runs on the swarm. There is no in-process test for it, because the case needs the runner bootstrap.

The two changes capture the same `Sharding` at the same point. #3424 names its `Deferred` `joined` too, so as two pull requests they would conflict. Two ways to combine them:

- `begin` keeps its retry and scope, and the namespace above serves both, so the deploy's runs need no `Effect.provideService` of their own. This is the smaller diff if #3424 takes it.
- The fallback goes into `makeNamespace` in `@alchemy.run/effect-cluster` instead: a runner-wide `Sharding` for callers without one. This covers any platform built on `RunnerHost`, at the cost of changing a shared package.

Happy to send either as a commit on #3424, or as a follow-up once it lands.
