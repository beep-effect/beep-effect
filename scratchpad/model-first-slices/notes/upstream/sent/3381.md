We hit this on Effect Cluster too (2.0.0-beta.87, two runners, PostgreSQL 17, a single-node Docker swarm), and can confirm the cause.

We restored a dump of eleven writes, taken under one version of a model, into a stack running the next version, which adds a view over them. The view's backfill run logged `subtrees=0` and the view held nothing from before the deploy. With the directory's first-page cursor kept `undefined` on the wire, the run listed 4 subtrees and 8 instances, and the view held all 11 writes, in two runs. In process, with arguments carried through `JSON.stringify` as the cluster transport does, a view added over a ledger booked three times ended at 1 booking (only the live one); with the cursor kept `undefined`, at 4.

We read #3382's diff, and it covers our case. The directory listing goes through `remote(...)` in `EffectCluster/index.ts`, which now sends `encodeRpcArgs(args)`, and the entity spreads `decodeRpcArgs(payload.args)`. So `list(path, undefined)` arrives with `after === undefined`, and `makeNode(...).list` lists the children again without a `startAfter`. Our local fix was narrower: we dropped trailing `undefined` arguments before `JSON.stringify`. That covers only the cluster transport and only trailing positions. #3382 covers `makeFetchRpcStub` and `serveRpc` as well, and any position, so we would drop ours in favour of it.

One point for review, which we have not tested. #3382 changes what goes on the wire for an `undefined` argument: it sends a sentinel object where there was `null`. During a rolling deploy, a new caller can reach an entity still on the previous code. That entity spreads the sentinel object as `after`, so `after === undefined` is false and `startAfter` is set to an object. Whatever the storage then does with it, the listing still won't be the first page. Dropping trailing `undefined` arguments would keep the old wire format for the trailing case. It may be worth doing that, either instead of the sentinel for trailing positions or alongside it, until a release where every runner decodes the sentinel.
