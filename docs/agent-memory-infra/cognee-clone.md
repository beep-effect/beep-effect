# Cognee Clone Assessment

## TL;DR

Cognee passes the three hard gates for this comparison: it is self-hostable/local-first, the checked-out project is Apache-2.0, and it has clean HTTP/MCP/API surfaces plus a TypeScript client even though the core is Python (`/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/README.md:40`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/README.md:184`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/README.md:327`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/README.md:374`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/LICENSE:1`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/pyproject.toml:1`).

For Role A, Cognee is a strong donor/cache/projection candidate, not a system of record. The product doctrine requires durable truth to remain in claim/evidence/provenance/lifecycle records, with semantic layers treated as managed caches (`standards/memory-architecture/README.md:18`, `standards/memory-architecture/01-memory-layer-taxonomy.md:7`, `goals/agentic-professional-runtime/README.md:65`). Cognee's useful portable patterns are DataPoint metadata and embeddable-field annotations, provenance stamping, node-set scoping, ontology enrichment, rollbackable graph/vector writes, and Postgres/pgvector consolidation (`/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/infrastructure/engine/models/DataPoint.py:26`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/infrastructure/engine/models/FieldAnnotations.py:19`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/pipelines/operations/run_tasks_base.py:62`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/tasks/storage/add_data_points.py:64`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/ontology/rdf_xml/RDFLibOntologyResolver.py:36`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/README.md:327`).

## Architecture & storage

Cognee is built around a pipeline that turns raw inputs into typed graph/vector/relational projections. `cognify` is documented as raw-data-to-knowledge-graph processing with LLM, vector, graph, ontology, and temporal options; the default pipeline classifies documents, chunks them, extracts graph structure with an LLM, summarizes, and stores DataPoints (`/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/api/v1/cognify/cognify.py:43`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/api/v1/cognify/cognify.py:62`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/api/v1/cognify/cognify.py:290`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/tasks/graph/extract_graph_from_data.py:56`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/infrastructure/llm/extraction/knowledge_graph/extract_content_graph.py:41`).

The central model abstraction is `DataPoint`, a Pydantic model with generated IDs, timestamps, version, ontology validity, source pipeline/task/node-set/user/content-hash metadata, and feedback/importance weights (`/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/infrastructure/engine/models/DataPoint.py:26`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/infrastructure/engine/models/DataPoint.py:44`). Field annotations mark embeddable text, LLM context, and deduplication fields, and DataPoint derives embeddable properties from that metadata (`/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/infrastructure/engine/models/FieldAnnotations.py:19`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/infrastructure/engine/models/DataPoint.py:172`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/infrastructure/engine/models/DataPoint.py:203`).

Pipeline execution carries explicit context: dataset, user, data item, pipeline run ID, pipeline name, and provenance extras flow through `PipelineContext`, while task execution stamps source pipeline/task/user/node-set/content-hash onto produced DataPoints (`/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/pipelines/models/PipelineContext.py:5`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/pipelines/operations/run_pipeline.py:37`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/pipelines/operations/run_tasks_base.py:62`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/pipelines/tasks/task.py:119`). Storage writes build graph nodes/edges, deduplicate, index embeddings, write graph/vector engines, and optionally upsert a relational rollback ledger tied to user, dataset, data item, and pipeline run (`/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/tasks/storage/add_data_points.py:30`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/tasks/storage/add_data_points.py:64`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/tasks/storage/add_data_points.py:94`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/tasks/storage/add_data_points.py:129`).

Storage is explicitly poly-store. The README documents graph, vector, SQL session-cache, and metadata layers, including an all-Postgres option using Postgres graph storage plus pgvector and SQL cache (`/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/README.md:327`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/README.md:342`). Graph providers include Ladybug/Kuzu-like local files, Postgres graph, Neo4j, and Neptune paths; vector providers include LanceDB, pgvector, Neptune Analytics, and community adapters for ChromaDB, Qdrant, Weaviate, and Milvus; relational storage is SQLite or Postgres; cache storage can be Redis, filesystem, tapes, SQLite, or Postgres (`/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/infrastructure/databases/graph/config.py:20`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/infrastructure/databases/graph/get_graph_engine.py:244`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/infrastructure/databases/vector/create_vector_engine.py:153`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/infrastructure/databases/relational/create_relational_engine.py:49`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/infrastructure/databases/cache/get_cache_engine.py:101`).

The relational model is useful as a donor but insufficient as product authority. It records nodes, edges, datasets, data items, pipeline/task runs, content hashes, ACL/owner fields, and external metadata, but row-level-security comments are not active code and there is no product-grade accepted-claim lifecycle in these models (`/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/graph/models/Node.py:17`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/graph/models/Node.py:50`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/graph/models/Edge.py:16`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/data/models/Data.py:12`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/data/models/Dataset.py:10`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/pipelines/models/PipelineRun.py:8`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/pipelines/models/TaskRun.py:7`).

Node sets are a concrete categorization/scoping pattern worth porting. Ingestion stores `node_set` metadata, classification propagates it to `belongs_to_set`/`source_node_set`, graph-to-vector conversion writes node-set names into vector payloads, and chunk retrieval can filter by node set (`/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/tasks/ingestion/ingest_data.py:160`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/tasks/documents/classify_documents.py:60`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/graph/utils/get_graph_from_model.py:250`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/retrieval/chunks_retriever.py:23`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/retrieval/chunks_retriever.py:116`).

## Retrieval

Cognee has a broad retrieval mode enum covering summaries, chunks, RAG completion, hybrid completion, triplet completion, graph completion variants, Cypher, natural language, temporal, coding rules, lexical chunks, and agentic completion (`/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/search/types/SearchType.py:4`). The retriever factory maps those modes to graph, chunk, hybrid, BM25/lexical, temporal, coding-rule, Cypher, natural-language, and agentic retrievers, with agentic retrieval only enabled for explicit tool-capable calls (`/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/search/methods/get_search_type_retriever_instance.py:78`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/search/methods/get_search_type_retriever_instance.py:309`).

Routing is mixed deterministic/LLM. `recall` supports session-first, graph-only, session-only, and auto-fallthrough behavior, while `query_router.py` provides a no-LLM weighted router for temporal, coding, exact, summary, reasoning, and relationship queries; `select_search_type.py` can also use an LLM to choose a search type and falls back to RAG completion on invalid or failed selection (`/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/api/v1/recall/recall.py:361`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/api/v1/recall/recall.py:423`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/api/v1/recall/recall.py:628`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/api/v1/recall/query_router.py:1`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/api/v1/recall/query_router.py:49`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/search/operations/select_search_type.py:9`).

Recall quality is plausible but not proven enough by the clone alone for dev-tooling authority. The README cites BEAM benchmark positioning with a caveat that benchmark results are directional, and tests cover smoke retrieval such as `remember`/`recall` plus an integration assertion for a remembered phrase rather than a longitudinal coding-agent recall benchmark (`/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/README.md:398`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee-mcp/src/test_client.py:85`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/tests/integration/modules/agent_memory/test_agent_memory_integration.py:171`).

Graph completion retrieves triplets by combining vector collections, graph distance, edge types, chunks, and optional global context; the path can include answer-grounded `Evidence` objects, but that evidence is a retrieval artifact rather than the product's durable ClaimRecord authority (`/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/retrieval/graph_completion_retriever.py:35`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/retrieval/graph_completion_retriever.py:105`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/retrieval/graph_completion_retriever.py:214`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/retrieval/graph_completion_retriever.py:309`, `goals/agentic-professional-runtime/README.md:84`).

Hybrid and lexical retrieval are useful implementation donors. The hybrid retriever combines chunk, entity, fact, global context, and optional truth-subspace weighting; lexical retrieval has a simple in-memory BM25-style implementation over graph-loaded chunks (`/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/retrieval/hybrid_retriever.py:33`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/retrieval/hybrid_retriever.py:77`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/retrieval/hybrid_retriever.py:110`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/retrieval/lexical_retriever.py:46`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/retrieval/bm25_retriever.py:9`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/retrieval/bm25_retriever.py:61`).

## Provenance/temporal/ontology/lifecycle

Cognee has good ingestion provenance for a memory cache: DataPoints carry source pipeline/task/node-set/user/content-hash fields, pipeline context carries pipeline/user/dataset/data-item IDs, and storage writes a relational ledger that can be rolled back by pipeline or dataset (`/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/infrastructure/engine/models/DataPoint.py:44`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/pipelines/models/PipelineContext.py:5`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/pipelines/operations/run_tasks_base.py:62`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/tasks/storage/add_data_points.py:94`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/cognify/rollback.py:42`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/cognify/rollback.py:92`). That provenance is still not the product's authority model. The product doctrine requires accepted assertions to carry evidence, provenance, lifecycle, cost, stable source span IDs, and human-review boundaries; semantic memory is explicitly a managed cache or projection, not the source of truth (`standards/memory-architecture/README.md:18`, `standards/memory-architecture/README.md:34`, `standards/memory-architecture/01-memory-layer-taxonomy.md:84`, `goals/agentic-professional-runtime/README.md:65`, `goals/agentic-professional-runtime/README.md:84`).

Ontology support is a genuine Cognee strength. `cognify` accepts ontology configuration, the default resolver is RDFLib-based with fuzzy matching and ontology file paths, the resolver parses RDF/OWL-style formats and builds lookup tables for OWL classes/individuals, and ontology expansion marks ontology-derived nodes/edges valid while distinguishing extracted non-ontology edges (`/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/api/v1/cognify/cognify.py:201`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/ontology/get_default_ontology_resolver.py:6`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/ontology/rdf_xml/RDFLibOntologyResolver.py:36`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/ontology/rdf_xml/RDFLibOntologyResolver.py:209`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/ontology/rdf_xml/RDFLibOntologyResolver.py:267`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/graph/utils/expand_with_nodes_and_edges.py:38`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/graph/utils/expand_with_nodes_and_edges.py:77`, `/home/elpresidank/YeeBois/research/knowledge-graphs/repos/cognee/cognee/modules/graph/utils/expand_with_nodes_and_edges.py:294`).
