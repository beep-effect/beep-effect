## `@beep/lane-cockpit`

The lab's `turbo.json` extends the root and overrides only the `build` task.
Its build is the `noEmit` `tsrs -p tsconfig.check.json` check generated by
`bun run beep create-package`, so `build.outputs` is `[]`. `build.inputs` is the
root `build.inputs` without `!test/**`, the same override `apps/labs/api-docs`
carries. The root build excludes `test/**` because a package build normally
emits `src/` only. The lab's build compiles its tests instead:
`tsconfig.check.json` extends `tsconfig.json`, whose `include` lists `src`,
`test` and `vitest.config.ts`. With `!test/**` in place, a test edit that
broke the type check would not re-key `@beep/lane-cockpit#build`, and a cache
hit could replay a passing build over a failing program. The repo-cli test
`package-role-turbo-inputs.test.ts` ("keeps test sources in the build of every
workspace whose compiler program includes them") enforces the override. With
it, the build hashes `test/Board.test.ts`, `test/LaneSource.test.ts`,
`test/LanesBoard.test.tsx` and `test/fixtures.ts`. The override only adds
inputs.

Every other cached task inherits the root definition; the lab adds no
inputs, outputs, environment keys or cache flags to them.
`bunx turbo run build check lint lint:deprecated-apis lint:laws test
--filter=@beep/lane-cockpit --dry-run=json` on this head:

| Task | Command | Upstream | Inputs |
| --- | --- | --- | --- |
| `build` | `bun run beep:build` | `@beep/identity#build`, `@beep/schema#build` | 29 |
| `check` | `bun run beep:check` | `@beep/identity#build`, `@beep/schema#build` | 29 |
| `lint` | `bun run beep:lint` | none | 35 |
| `lint:deprecated-apis` | `beep-cli lint deprecated-apis --package .` | `@beep/identity#transit`, `@beep/schema#transit`, `@beep/repo-cli#lint:policy-fingerprint:lint-deprecated-apis` | 946 |

| `test` | `bun run beep:test` | `@beep/identity#transit`, `@beep/schema#transit`, `@beep/utils#transit` | 28 |

Each row hashes the lab's `src/`, `test/`, `package.json` and config files
(`build` hashes `test/` only because of the override above), plus the root
inputs every sibling lab carries. The tasks read nothing outside
those inputs:

- the frame tests render offscreen with `@textjs/react/testing` and decode
  fixtures built in `test/fixtures.ts`;
- the `LaneSource` tests spawn `printf` and a missing binary with no `cwd`,
  over a no-op file system, so they never read the checkout;
- no test runs `bun run beep session open`, the only command that reads the
  workstation session ledger. That path runs only in `src/main.ts`, which no
  task executes.

The six rows carry the same commands and cache flags as the recorded rows of
the sibling labs `@beep/ciops` and `@beep/semantica`. Only the upstream edges
differ, following each lab's workspace dependencies, and so do the `build`
inputs described above. This record grants reuse
on the same legacy terms and no qualification. The lab's uncached tasks
(`coverage`, `dev`, `lint:fix`, `package-test-typecheck`) stay uncached, and
its `start` script is not a Turbo task.
