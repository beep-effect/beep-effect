# Cached account headroom at session start

Text-mode `beep session open` now reads the existing private account-headroom
snapshot without starting provider usage polls. An expired report stays
`Unknown{stale}` with its original timestamp; a missing or corrupt report stays
Unknown. Explicit `beep palantiri parcel` and MCP reads retain their live refresh
behavior. The two-second hot-block bound and `palantiri-hot/v2` format are unchanged.

The cached source still obtains the independent configured-provider inventory.
A listing failure remains `Unknown{attribution-incomplete}`, and a newly configured
provider absent from the snapshot cannot appear covered. Local inventory can read
login metadata and Junie account presence; this change removes usage polling and
token refresh from the hot source, rather than claiming a file-only startup path.

Successful `beep accounts status` (including JSON), the default command's non-TTY
board, and completed TTY watch polls stage the report they already computed. The
persisted copy retains last-good readings only for Failed outcomes, preserving
original row timestamps and signed-in flags. NeedsLogin is definitive. The raw
board/JSON result remains unchanged. The existing atomic writer keeps directory
mode 0700 and file mode 0600; a staging failure warns on stderr without failing the command or polluting JSON stdout.
The watch's existing single-poll guard also bounds staging: one write per completed
poll, no writes on redraw and no overlapping watch polls.

The completed-retained `palantiri-parcels` packet records the decision in
`decisions/2026-11-06-serve-cached-account-headroom-at-session-start.md`; its SPEC
projection was regenerated by `beep goals decisions add`.

## Controlled evidence

A private fixture uses the actual `hotParcels`, live source and new cached source
with a fully synthetic AccountsUsage port. Its one fake account sleeps five
seconds; other hot sources fail immediately. It never loads the live accounts
layer or reads credentials, calls providers or refreshes tokens.

Two expired-cache reads and one missing-cache read on the live source produced
three poll starts, three interruptions and zero completions. The expired file
remained byte-identical; the missing file remained absent. Hot blocks took
2009.105, 2006.311 and 2006.713 milliseconds. Five reads through the implemented
cached source took 4.699, 2.158, 2.064, 1.685 and 1.511 milliseconds (median
2.064 ms), without starting another poll. Fresh, stale, missing, unknown-inventory
and missing-provider controls retained their expected freshness/Unknown states.

These numbers demonstrate the cancellation mechanism under a controlled delayed
source. They exclude CLI startup and real provider-inventory cost, are not an
alternating production session-open benchmark, and do not establish a two-second
saving in ordinary use: other hot parcels can dominate the block. No token
rotation harm was reproduced or claimed.

Private reproduction artifacts are under
`.beep/efficiency-wave3/fixtures/o2-1-{probe.ts,probe.log,results.json}` in the
implementation lane. They contain only synthetic fixture data.

## Validation

The focused Palantiri/accounts suites cover cache refusal without polling,
freshness and independent attribution, unchanged live refresh, both one-shot
accounts entrypoints, private write modes, repeated retention with original asOf,
signed-in flags, raw-report immutability, NeedsLogin replacement, and non-failing
staging errors. The TTY fixture uses an isolated memory filesystem and observes
exactly two atomic publications for its initial poll and explicit refresh, with
none from redraw; a failed poll publishes nothing. Both suites pass 96 tests.
Scoped Fallow audit passes across six changed CLI files with zero dead-code,
complexity or duplication findings (12.767 s). The scoped Effect-Vitest detector
adds zero findings; the existing accounts platform-provenance review remains unchanged.

CLI package quick verification passes lint (1.6 s) and check (8.4 s). The Palantiri
package's doc-only change passes its own quick verification (lint 0.1 s, check 0.3 s)
and full package verification (audit 14.6 s, docgen 3.0 s).
The CLI full package verification passes audit (152.1 s) and docgen (37.9 s).
The independently evaluated projection-hook candidate was rejected because its
measured median saving fell below its prespecified threshold; no hook change is
included here. No hosted or production proof is claimed by these local checks.
