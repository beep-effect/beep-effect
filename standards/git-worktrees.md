# Git Worktrees In `beep-effect`

This repo now uses **Git-native sibling worktrees** as the default way to do parallel feature work.

The goal is to replace duplicate full clones like `beep-effect2` and `beep-effect3` with multiple working directories that share one Git object database but keep separate branches, indexes, local caches, and IDE state.

## Workspace Layout

Canonical paths for this machine:

- Main checkout: `<checkout-root>`
- Worktree root: `<checkout-root>-worktrees`
- Starter worktree: `<checkout-root>-worktrees/playground`

Why this layout:

- It keeps worktrees **outside** the main repo directory.
- That matches current WebStorm guidance for Git worktrees.
- It avoids the nested-worktree layout Claude Code uses by default with `claude --worktree`.
  The Claude Code desktop app still creates `<checkout-root>/.claude/worktrees/<name>`
  on its own; those lanes are retirement-eligible too (see below), they are just
  not where `bun run beep worktree new` puts anything.

## What A Worktree Actually Is

`git worktree` lets one Git repository expose multiple working directories at once.

Important rules:

- The main checkout is already a worktree.
- All worktrees share the same Git history and object store.
- Each worktree has its own checked-out branch, working directory, and index.
- A branch can only be checked out in **one** worktree at a time.
- Deleting a worktree directory by hand leaves stale metadata behind. Prefer `git worktree remove`, then `git worktree prune`.

## Everyday Commands

List all worktrees:

```bash
git -C <checkout-root> worktree list
```

Create a new sibling worktree from `main`:

```bash
git -C <checkout-root> \
  worktree add <checkout-root>-worktrees/feature-x \
  -b worktree/feature-x \
  main
```

Create a worktree for an existing branch:

```bash
git -C <checkout-root> \
  worktree add <checkout-root>-worktrees/beepgraph \
  feat/beepgraph-messaging
```

Remove a worktree cleanly:

```bash
git -C <checkout-root> \
  worktree remove <checkout-root>-worktrees/feature-x
```

Prune stale metadata:

```bash
git -C <checkout-root> worktree prune
```

Lock a long-lived worktree so Git will not prune it accidentally:

```bash
git -C <checkout-root> \
  worktree lock <checkout-root>-worktrees/playground
```

Repair broken metadata if a path moved:

```bash
git -C <checkout-root> worktree repair
```

## `beep-effect` Workflow

Recommended flow for a new feature:

1. Start from the main checkout and make sure `main` is clean.
2. Add a sibling worktree under `<checkout-root>-worktrees`.
3. Open that worktree as its own project in WebStorm.
4. Run bootstrap commands inside that worktree.
5. Launch Claude Code or Codex CLI from that worktree root.

Bootstrap checklist for a fresh worktree:

```bash
git -C <checkout-root>-worktrees/playground submodule update --init --recursive
cd <checkout-root>-worktrees/playground
bun install
```

Then restore any local-only files you need:

- `.env`
- `.claude/settings.local.json`
- `CLAUDE.local.md`
- `.beep`

By default these do **not** follow you into a fresh worktree, which is usually what we want.

`.direnv/` is not on that list on purpose: it is a regenerable Nix profile cache with
absolute symlinks, and direnv rebuilds it on first entry (the global whitelist covers
every `beep-effect*` path, so no `direnv allow` is needed).

`.idea/` needs no manual restore step: the curated project config (root
`beep-effect.iml` with exclusions, `modules.xml`, inspection profile) is tracked in
Git and arrives with the checkout. The two machine-local IDE files worth carrying
(`.idea/compiler.xml`, `.idea/effect.intellij.xml` — platform-specific tsgo wiring)
are copied by `beep worktree new`; the rest (`workspace.xml`, etc.) stays ignored via
the whitelist `.idea/.gitignore` and is regenerated by the IDE per worktree.

## Tooling

`bun run beep worktree` automates the sibling-worktree workflow above. It
resolves the canonical worktrees root
(`<main-checkout>-worktrees`) from Git metadata, so the three subcommands work
from the main checkout or from any linked worktree. The manual commands and
checklist above remain the reference for what the tooling does under the hood.

```bash
bun run beep worktree new <name> [--branch <branch>]
bun run beep worktree remove <name> [--archive] [--delete-branch]
bun run beep worktree doctor
```

- `worktree new <name>` creates `<worktrees-root>/<name>` on a new branch
  (default `feat/<name>`, override with `--branch`/`-b`), then bootstraps it:
  `git submodule update --init --recursive`, `bun install`, and — when present
  in the main checkout — copies the local-only files `.env`,
  `.claude/settings.local.json`, `CLAUDE.local.md`, `.idea/compiler.xml`, and
  `.idea/effect.intellij.xml` (the rest of `.idea/` is Git-tracked and needs no
  copy). It prints a
  summary of what was copied, skipped, and the absolute path.
- `worktree remove <name>` refuses when the target worktree has uncommitted
  changes unless you use the preservation-first `--archive` mode. Forced
  removal is unsupported. Archive mode can also delete the preserved local
  branch with `--delete-branch`; otherwise the command prints the separate
  `git branch -D <branch>` cleanup command. Its archive fence grants the same
  exemption `yeet sweep --retire` does: the invoker's own ancestry and, under
  Claude Code (`CLAUDE_PID`), everything that session spawned into the lane,
  so a desktop session removes its own lane; started inside the lane, it
  steps out first and leaves an idle Claude Desktop Terminal panel shell in
  place. Other sessions' processes and a panel shell when the command starts
  elsewhere still refuse it.
- `worktree doctor` is read-only. It lists every worktree under the worktrees
  root with its branch, clean/dirty and unpushed status, missing bootstrap files
  (`.env`, `node_modules`), and any prunable metadata from
  `git worktree prune --dry-run`.

### Admission eviction protocol rollout

The machine-wide admission protocol defaults eviction-row emission to `off`.
Reaping still atomically claims dead leases and tickets and journals their
attempt termination, but it does not emit v2 admission eviction rows while an
older checkout could erase unknown rows during a locked rewrite. Only after
every live checkout runs the preservation release, enable emission with
`bun run beep quality scheduler protocol --enable-evictions`. Disable it before
introducing an older checkout; inspect the current state with
`bun run beep quality scheduler protocol`.

## Retiring a worktree

The sanctioned retirement command for a lane that may contain local residue is:

```bash
bun run beep worktree remove <name> --archive [--delete-branch]
```

`<name>` resolves under the sibling worktrees root first and then under the
clone's `.claude/worktrees/<name>`, so a Claude Code desktop lane retires with the
same command. After its pull request merged, the one-shot form is
`bun run beep yeet sweep --retire [--lane <path>]`: it archive-retires the
lane (the invoking worktree, or the one `--lane` names when run from the
clone), deletes the branch, and sweeps the owning clone (returned to `main`
only when it already stands there; a clone on another live branch keeps its
checkout and receives ref-only updates). Run it from inside
the lane, because `bun run beep` resolves the CLI from the checkout it runs in
and the clone's `main` may still be behind the merge; the command steps its
own process out of the lane before removal and the archive fence exempts the
invoking session's ancestry plus, when Claude Code names the session through
`CLAUDE_PID`, everything that session spawned into the lane (MCP servers, tool
shells, background jobs). Run from inside the lane, it also leaves an idle
Claude Desktop Terminal panel shell standing in the lane by cwd (the app
starts one in the session folder even when the panel is never opened, and
starts a new one when it exits) and removes the lane under it. Any other
holder (a panel shell running a command, any panel shell under `--lane`, an
editor, another session) still refuses the retirement and is named in the
error. Finish writes from session MCP servers and other exempt children before
retiring the lane: file writes after archive capture are not included. The
idle panel shell is the exception that is checked rather than trusted: a
shell whose context-switch count changed between the fence's first scan and
the post-capture rescan (it ran something, even a builtin redirect) leaves
the fenced copy preserved instead of deleted. This
process fence controls active writers, independently of the commit-count
decision to create an archive ref. Step the shell into the swept clone afterwards:
`CLONE="$(git rev-parse --path-format=absolute --git-common-dir)/.." && bun run beep yeet sweep --retire && cd "$CLONE"`.
`--lane <path>` also retires a leftover lane from any sibling lane of the same
clone; when only the clone is at hand and its checkout predates `--retire`,
run the lane's own CLI from the clone:
`cd <clone> && bun run <lane>/packages/tooling/tool/cli/src/bin.ts -- yeet sweep --retire --lane <lane>`.
The gate is a verdict the plan prints and the JSON documents carry
(`yeet-retire-sweep-plan/v2`, `yeet-retire-sweep-report/v2`): `pr-merged`
when the branch's pull request is MERGED and heads it; `pr-less-on-main` for
a branch that never headed a pull request whose tip `origin/main` already
contains (`git merge-base --is-ancestor`) while the tree is clean, the
leftover-lane case, in which the local branch is deleted and no remote branch
is touched; `refused` otherwise, with the first reason an operator would
check (pull request not MERGED or heading another branch, tip not on
`origin/main`, uncommitted changes).

Forced removal is unsupported and remains denied by agent policy. Archive mode
is the only removal path for local residue: the CLI inspects tracked and
untracked changes plus commits absent from the remote default branch and, when
configured, commits ahead of the branch upstream. A configured upstream whose
remote-tracking ref was pruned (GitHub deletes the head branch at merge and a
later `git fetch --prune` drops `refs/remotes/origin/<branch>` while
`branch.<name>.merge` still names it) never fails the `inspect-upstream` step:
unpushed commits are judged against `origin/<default>..HEAD` instead, and the
pruned state records a verdict — the tip is already on the default branch, a
merged pull request landed exactly this head (`gh pr list`, exact head match),
or `unverified`. The verdict records evidence; it does not override the
commit-count decision to create an archive ref. A squash-merged tip with a matching merged
PR still gets an archive ref when its commits are absent from the default
branch. Only `ancestor-of-base` has a zero base count and permits clean removal
when no other residue needs preservation. Doctor's boolean check uses the
commit counts without querying GitHub for receipt evidence. An initialized
submodule with uncommitted work cannot be represented by the top-level patch,
so archive retirement stops before removal and names the submodule that must
be committed or cleaned.
If preservation is needed, it completes all of these steps before removal:

1. Creates a new create-only
   `refs/archive/worktrees/<encoded-name>/<YYYYMMDD-HHMMSS>` ref at the old
   `HEAD`, after validating it with `git check-ref-format`. The encoded component
   is deterministic and Git-safe; the manifest retains the raw worktree name.
2. Writes tracked changes as `tracked.patch` using `git diff --binary HEAD`.
3. Copies every untracked, non-ignored file under `untracked/`, preserving its
   repository-relative path.
4. Writes a schema-decoded `manifest.json` with the raw name, branch, old `HEAD`,
   archive ref, repository hash, artifact paths, retirement reason, and the
   branch-upstream state (`unset`, `live`, or `pruned` with its verdict).

Residue defaults to
`~/.cache/beep/worktree-residue/<repo-basename>-<hash12>/<name>-<stamp>/`,
where `hash12` is derived from the absolute main-checkout path so same-named
clones cannot share a residue directory. Set `BEEP_WORKTREE_RESIDUE_ROOT` to
override the leading residue root. The override is resolved to an absolute path
and rejected when it equals or sits below the retiring worktree. Files are
copied, never moved, and the worktree is removed only after the ref, patch,
untracked copies, and manifest all succeed. A clean worktree with no unpushed
commits is removed normally and prints a receipt without creating residue.

The receipt prints the exact archive ref and artifact paths. To restore an
archived lane, choose a fresh path and run:

```bash
git worktree add <restore-path> <archive-ref>
git -C <restore-path> apply <residue-dir>/tracked.patch # when the patch exists
cp -a <residue-dir>/untracked/. <restore-path>/          # when untracked files exist
```

Without `--delete-branch`, the original local branch remains available. With
the flag, detached worktrees simply skip branch deletion. Each lane is expected
to retire its own worktree after its PR merges, or during the next worktree
sweep, using archive mode whenever local residue is present.

## Tool Integrations

### WebStorm

Default recommendation:

- Open each worktree as a **separate WebStorm project**.
- Do not treat sibling worktrees as attached subprojects inside one parent workspace.
- Do not nest worktrees inside `beep-effect/`.

Why:

- JetBrains documents worktree support as a single-repo project flow.
- Nested worktrees can be misdetected as multi-root projects.
- Separate projects keep changelists, run configs, branch state, and indexing cleaner.

Two good ways to create or open them:

- Use `git worktree add ...` in the terminal, then `File | Open`.
- Or use `Git | New Worktree` in WebStorm and let it open the new project.

### Claude Code

Default recommendation for this repo:

- Use manual Git worktrees.
- Launch Claude from the worktree root.
- Keep using the checked-in `.claude/settings.json` and `.mcp.json` project
  settings.

Good:

```bash
cd <checkout-root>-worktrees/playground
claude
```

Avoid as the primary local workflow:

```bash
claude --worktree
```

Why:

- Claude’s built-in worktree flow creates nested worktrees under `.claude/worktrees/`.
- That is convenient for quick disposable sessions, but it conflicts with the sibling layout that WebStorm handles best.

Still useful to know:

- Tracked `.claude/settings.json` and `.mcp.json` come along automatically in
  any worktree.
- The tracked Claude permissions auto-approve only named read-only `gh pr` and
  `gh run` commands from the GitHub CLI. The repository workflow retains the
  intentional `beep yeet publish` grant, but direct `git push` requires an
  approval. Direct `gh` mutations, unrestricted `gh api`, `codex exec`, force
  pushes, admin merges, and repository deletion require a separate approval or
  remain denied.
- Gitignored files like `.claude/settings.local.json`, `CLAUDE.local.md`, and
  `.env` do not.
- If you ever choose Claude-managed worktrees for throwaway tasks, `.worktreeinclude` can copy selected ignored files, but that is not part of the default `beep-effect` setup.

### Codex CLI

Default recommendation:

- Run one Codex session per worktree.
- Launch it from the worktree root, or use `-C`.

Good:

```bash
cd <checkout-root>-worktrees/playground
codex
```

Also good:

```bash
codex -C <checkout-root>-worktrees/playground
```

The project `.codex/config.toml` uses `approval_policy = "on-request"` and
`sandbox_mode = "workspace-write"`. Ordinary repository work stays inside the
checkout; GitHub network calls, writes outside the workspace, and privileged
`.git` operations cross an explicit approval boundary.

Why:

- Codex CLI is cwd-driven for instruction discovery, trust, and resume
  filtering.
- The repo’s checked-in `AGENTS.md` already fits that model well.

### Codex App

The Codex app has first-class worktree support, but treat it as an **optional parallel-agent workflow**, not the source of truth for the local repo layout.

Important differences:

- App-managed worktrees live under `$CODEX_HOME/worktrees`.
- They may start in detached `HEAD`.
- The app uses handoff semantics between local and worktree tasks.

Recommended use here:

- Use Git-native sibling worktrees for your day-to-day local workspace.
- Use Codex app worktrees only when you specifically want OpenAI-managed parallel task orchestration.

## Seats, Lanes, Registry And Drain

The fleet is every checkout that shares this repository's origin: each clone
and every linked worktree registered to it, wherever it lives (the sibling
`-worktrees` root, a clone's `.claude/worktrees`, `~/.t3/worktrees`,
`~/.codex/worktrees`). `bun run beep worktree fleet` derives it read-only;
`--join` adds the registry and session-ledger facts.

- **Seat**: a long-lived checkout with an authored, workload-named role:
  `main` (the operator's editor seat), `ops` (timers), `review`, `research`
  or `impl`. A seat is authored with
  `bun run beep worktree fleet register <checkout> --role <role>`; an
  explicit registration survives every rescan and is never drained.
- **Lane**: a linked worktree doing one piece of work. Its owning seat is the
  clone whose `.git` holds it (`git rev-parse --git-common-dir`). Create lanes
  with `bun run beep worktree new <name>`; the dedicated `lanes/` root and
  `beep worktree add` arrive with goals/lane-bootstrap.
- **Legacy clone**: an origin-matched full clone in a legacy discovery root
  (the numbered `beep-effectN` siblings). The scan registers these `legacy`
  on sight; every other unregistered checkout is registered `adopted`.

**Registry.** `~/.local/state/beep/fleet/<repo-key>/registry.json` authors only
what git cannot derive: seat role, owning seat, drain status
(`active`, `draining`, `retired`), retention exemption, and the grace start of
a draining checkout (`drainingSince`, `drainingHead`). Discovery roots come
from `BEEP_FLEET_ROOTS`, then `roots.json` beside the registry, then the
projects directory holding the main checkout. `fleet --join` adopts unknown
checkouts; `fleet describe <checkout>` shows one row with its ledger tail.

**Drain.** `bun run beep quality residue-reap --fleet` assesses every fleet
checkout against the `drainable` predicate on every run, dry-run by default.
A checkout is drainable only when all of these hold:

| Check | Refuses when |
| --- | --- |
| `seat-role` | the role is an authored seat (only `legacy` and `adopted` drain) |
| `retention-exempt` | the registry marks it exempt |
| `invoking-checkout` | the reap runs from inside it |
| `timer-host` | it is a systemd user unit's `WorkingDirectory` |
| `proof-unit` | an active `beep-proof-*` unit names it |
| `open-pr` | its checked-out branch has an open pull request |
| `session-ledger` | an open session-ledger row names it |
| `liveness` | it is live, or liveness is `unknown`: a probe could not confirm inactivity |
| `owned-worktrees` | (clone) a worktree is still registered to it; lanes retire first |
| `object-borrowers` | (clone) another clone reads its objects through `objects/info/alternates` |
| `local-only-work` | never refuses; local-only branches, tags, stashes or a detached HEAD need a verified bundle first |
| `clean-tree` | `git status` shows any change, untracked files included (ignored files are copied out at removal instead, see below; ignored directories other than `secrets/`, `.secrets/` and `*.local` are regenerable and removed) |
| `grace-window` | it has not stayed drainable at one HEAD for `--drain-grace-days` (default 7) |

Liveness reuses the fleet mirror's classifier with the reaper's process probe,
which drops pids it cannot read (other users' processes); transcript and tree
mtime must read inactive too. A failed observation, or a HEAD that moved,
restarts the grace window.

Removal happens only in an applied run that names the class:

```bash
bun run beep quality residue-reap --fleet --classes drainable          # wave preview, disk totals
bun run beep quality residue-reap --fleet --classes drainable --apply  # drain the eligible checkouts
```

The daily `beep-residue-reap.timer` (`--apply --fleet`, default classes)
records observations but never drains: `drainable` candidates it finds
eligible are kept with reason `drain-opt-in`. An applied wave re-checks every
eligible checkout immediately before removal, bundles its local-only work to
`~/.local/state/beep/fleet/<repo-key>/drain-bundles/` (refused unless
`git bundle verify` passes and every local-only commit is reachable from a
bundled head), copies every gitignored file (keys, `.env*`, credentials,
machine-local config) and every ignored `secrets/`, `.secrets/` or `*.local`
directory to `<bundle>.local/` beside it (refused above 512 MiB; other ignored
directories such as `node_modules/`, `dist/` and `.turbo/` are regenerable), reads the checkout once more
(same HEAD, still clean and dormant, no local-only commit outside the bundle),
files its Yeet attempt journals, removes it (`git worktree
remove` from the owning clone for a lane, an inode-bound tree removal for a
clone), and appends the decision with every check to `drain-journal.jsonl`
beside the registry. The wave report lists the disk held by registered legacy
clones before and after.

Restore a drained checkout's local work from its bundle:

```bash
git clone <origin-url> beep-effect-restored
git -C beep-effect-restored fetch <bundle> 'refs/*:refs/restored/*'
```

Order: lanes drain first, then their clone once `owned-worktrees` and
`object-borrowers` pass; timer hosts drain last, after their units move.
Never create another `beep-effectN` clone; start a lane instead.

## Repo-Specific Gotchas

- `flake.nix` now derives its Bun cache name from the active worktree root, so each worktree gets its own cache namespace.
- `.turbo`, `.beep`, and `node_modules` are intentionally local to
  each worktree. `.idea` is tracked (whitelist `.idea/.gitignore`); only its
  ignored machine-local files (`compiler.xml`, `effect.intellij.xml`,
  `workspace.xml`) stay per-worktree.
## Shared Multi-Agent Worktrees

When several agents (or an agent team) write into the **same** worktree
concurrently, the working directory and index are shared mutable state. Rules:

- **Cleanup must preserve shared state.** Direct `git stash drop` remains denied because
  its permission pattern cannot verify stash ownership. Yeet owns restoration and cleanup
  of its marked stashes. Agents may retire a worktree through `bun run beep worktree
  remove` (raw `git worktree remove` is not auto-approved because a trailing `--force`
  would slip past the prefix denial), delete a local branch, create
  archive refs under `refs/archive/`, and retire merged branches with `bun run beep yeet
  sweep`, all without operator approval. The committed `.claude/settings.json` allows exactly
  those and still denies the destroyers: `git worktree remove --force`, `git clean`,
  `git reset --hard`, `git checkout .`, `git stash clear/pop`, raw remote branch deletion,
  and force pushes. Preserve residue before removal; the archive-first
  `bun run beep worktree remove <name> --archive` lands in #956 and becomes the
  sanctioned path once merged.
- **Never `git stash` in a shared multi-agent worktree.** Stash sweeps *every*
  writer's uncommitted work into one stash entry, silently pulling other
  lanes' in-flight edits out from under them; a later `stash pop` then
  reapplies them onto a tree that has moved, producing conflicts or quiet
  duplication. If you personally need a clean tree, that is the signal to move
  your lane to its own worktree instead. (Yeet's `--staged-only` marked-stash
  flow is the one sanctioned exception — it is serialized inside a single
  publish operation, not a lane parking mechanism.)
- Same discipline for other whole-tree mutations while lanes are active:
  `git checkout -- .`, `git reset --hard`, and branch switches affect every
  writer, not just you.
- Serialize same-file writers up front (disjoint file sets per lane); if two
  lanes must touch one file, hand the file to one lane and have the other send
  a follow-up message.

(five-lane execution; the stash hazard is finding #3 in
