Agent Computer Access · Lesson 0001

The Playroom and the House

Why a sandboxed agent (Cowork) can make things for you, but only an agent on your actual computer (Claude Code) can work for you.

The five-year-old version

Cowork gives Claude a playroom. It's a clean, empty room in Anthropic's building. You slide papers in through a mail slot, Claude makes something nice, and slides it back out. Then the room is demolished. Every visit starts with a brand-new empty room.

Claude Code lets Claude into your house. Your desk, your filing cabinets, your tools, your printer, your calendar on the wall. Whatever it builds — a routine, a script, a tidied-up filing system — is still there tomorrow, working, even when Claude has gone home.

You can't hire a housekeeper who is only allowed in a playroom across the street.

That demolition detail isn't a metaphor — it's Anthropic's own description. In Cowork's cloud sessions, "each session gets its own sandbox, created when the session starts and destroyed when it ends," your files reach it only through a brokered connection to folders you explicitly connected, and its internet access runs through a mandatory allow-list proxy (Cowork architecture overview). Claude Code is the same agent brain, but it runs on your machine with the permissions of whoever launched it (Claude Code docs). Same engine, two very different rooms (DataCamp comparison).

Why the playroom can't do real automation

1. An automation is something that runs when you're not there

A routine, a nightly script, a "watch this folder and file whatever lands in it" — these live on a machine and keep running after the conversation ends. The sandbox is destroyed when the session ends, so there is nowhere for an automation to live. Claude Code can install the routine into the computer itself — a scheduled task, a watcher, a hook — and the machine keeps doing the work.

2. Work has to land where work happens

From the playroom, everything comes back out through the mail slot: a file to download, a page written through a connector. On your machine, the agent edits the real documents in the real folders, runs the real installed software, prints to the real printer, and the result is simply done — not delivered for you to go put away.

3. "But our systems of record are connected!" — the connector illusion

This is the rebuttal you'll hear, so learn it cold. A connector is a mail slot with a fixed shape: it exposes exactly the operations someone built — read this page, list those files, draft that email. But real work lives in the connective tissue between systems: the local folder where scans land, the desktop app with no API, the firm's docketing macro, the network drive, the fifteen-step routine a paralegal does across four programs. A person at a desk can drive all of that. An agent at that same desk can too. An agent in a sandbox can only touch what got a slot cut for it — and connector calls even run outside the sandbox, on Anthropic's servers, precisely to keep credentials out of the room.

4. A computer accumulates; a sandbox forgets

Your machine has years of setup in it: installed tools, logins, printers, mapped drives, scripts, muscle memory encoded as configuration. That accumulated state is what makes work fast. The sandbox starts empty every single time — an amnesiac employee with a strict visitor badge.

The honest steelman (say this before they do)

Fairness clause The sandbox is not a defect — it's a deliberate safety feature. If something goes wrong, the blast radius stays inside a disposable room; on a real machine, the agent can touch whatever you can touch, which is why Claude Code asks permission before acting (MintMCP security comparison). So the pitch is not "Cowork bad." It's: containment and capability are the same dial. Cowork is the right tool for trying things safely and for one-off document tasks. But an agent that cannot touch your machine cannot automate your machine — and automation is the part that compounds.
