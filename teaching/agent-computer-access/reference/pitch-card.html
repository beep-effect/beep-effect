Why agents need a real computer

The two-minute version. Print it, glance at it, say it in your own words.

The analogy (memorize this)

Cowork gives Claude a playroom: papers in through a mail slot, something nice comes back out, then the room is demolished. Claude Code lets Claude into the house: what it builds stays, and keeps working when it's gone. You can't hire a housekeeper who's only allowed in a playroom across the street.

The five beats

BeatOne line
1. Automation = unattendedAn automation runs when you're not there; the sandbox stops existing when you leave, so nothing can live in it.
2. Work must landSandbox output is a delivery you still have to put away; local output is simply done, in place.
3. Connector illusionConnectors are mail slots with fixed shapes; real work is the glue between systems, which only a desk-level agent can drive.
4. Computers accumulateYour machine holds years of tools, logins, and setup; the sandbox is an amnesiac with a visitor badge.
5. Same dialContainment and capability are one dial — Cowork turns it toward safe, Claude Code toward capable.

The rebuttal you will hear

“But our systems of record are already connected to Cowork” Connected means Claude can reach the operations someone built a slot for. It does not mean Claude can run the docketing macro, watch the scans folder, drive the desktop app with no API, or install the nightly routine. People don't do their jobs inside the systems of record — they do them between the systems, at a desk. That desk is the computer.

The steelman (say it first)

Be fair, then pivot "The sandbox is a genuine safety feature — small blast radius, great for trying things. But an agent that can't touch the machine can't automate the machine, and automation is where the compounding value is. Claude Code keeps safety by asking permission instead of by being locked in a room."
