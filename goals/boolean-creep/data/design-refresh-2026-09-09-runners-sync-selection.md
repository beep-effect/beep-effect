## Corrected canonical metadata

### `runners-bake-freshness`

- Source: `packages/tooling/tool/cli/src/commands/Runners/Runners.schemas.ts:304`
- Symbol: `BakeCheckReport`
- Members: `[lockfileMatches,bunArchiveMatches,bunVersionMatches,fresh,actualLockfileSha256,actualBunArchiveSha256,actualBunVersion]`
- Evidence: E4 at `packages/tooling/tool/cli/src/commands/Runners/Runners.service.ts:757-785`
- Cardinality: 128 representable / 27 legal
- Storage/exposure/tier: stored / wire / Tier 2
- Target: tagged union per probe with a full legacy codec

This expands the stable four-Boolean owner rather than adding an overlapping
record. Each lockfile, Bun-archive, and Bun-version probe has exactly three
states: missing actual, mismatch carrying expected and actual, or match carrying
the one equal value. The three probes vary independently, producing 27 rows.
Overall freshness is true only for match/match/match.

The target uses one parameterized private `BakeProbeResult` schema constructor,
instantiated with `Sha256Hex`, `Sha256Hex`, and `S.NonEmptyString`. Match owns a
single value so equality is structural in decoded state; encoding duplicates it
into the exact legacy expected and actual keys. Missing preserves optional-key
omission, and mismatch preserves both exact payloads. No 27-value combination
enum or residual match/fresh Boolean remains.

`checkBake` is the sole writer. Human output reads lockfile, Bun version, and
overall freshness at `Runners.command.ts:59-68`; the check exit gate and JSON
encoder are at lines 118-131. `BakeCheckReport` and `BakeCheckReportJson` remain
public through `commands/Runners/index.ts:30-40`. Repository search found no
JSON decoder consumer or contradictory fixture. The new decoder rejects all
101 incoherent structural combinations instead of silently normalizing them.

For all 27 coherent values, the codec must preserve exact existing JSON:
`amiId`, expected fields, optional actual-field omission, three match keys,
`fresh`, key order, SHA/version bytes, and JSON formatting. The public all-match
JSDoc example and the coherent fresh/stale fixtures at
`runners-bake.test.ts:94-107` remain exact rows. Schema-derived arbitrary tests
must cover all 27 cases rather than only the production all-match tuple.

### `sync-data-target-selection`

- Source: `packages/tooling/tool/cli/src/commands/SyncDataToTs/SyncDataToTs.command.ts:61`
- Symbol: `SyncDataTargetSelection`
- Members: `[all,targetId]`
- Evidence: E2 at `SyncDataToTs.command.ts:124-137`
- Cardinality: 4 representable / 2 legal
- Storage/exposure/tier: stored / internal / Tier 1
- Target: tagged union

Reuse the stable id while replacing its former D1 member assignment
`[all,includeAuthenticated]`. Valid selection is `all` with no id or
`target { targetId }` with all false. Both is the exact conflict error; neither
is the exact required-selection error. Unknown ids retain their separate typed
error and available-target list.

`includeAuthenticated` remains an independent Boolean beside the honest
selection. With all selection it controls whether authenticated targets join
public targets; with direct target selection it remains accepted and has no
effect. The design does not turn registered target ids into literals or reject
existing `--target ... --include-authenticated` invocations.

The carrier is private and has no encoded boundary. Raw CLI flags, aliases,
defaults, error text and precedence, repo-root/run-mode ordering, registry
order, serial execution, generated bytes, reporting, authenticated-source
privacy, and drift exits remain unchanged. Existing command behavior is covered
in `sync-data-to-ts.test.ts:829-949`; the design adds the four raw selection
pairs crossed with both include-authenticated values.
