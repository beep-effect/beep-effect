# Reflection — graph-3d-view (2026-07-16, claude)

## Summary

Shipped the full packet in one session: P0 design gate (DESIGN.md v2, hardened
by a codex adversarial review that produced eight accepted-or-answered
findings), a net-new `@beep/graph-3d` instanced three.js driver with stories
and a 5/5 browser lifecycle suite, worker-baked force-relaxed 3D depths, the
workbench 2D/3D toggle with an IRI-keyed selection transaction, and a
WebKitGTK 2.52.5 measurement of 60 fps at the 2,500-node target. Cosmos stayed
byte-identical (empty driver diff) and default. Verdict: the
design-gate-first, prose-parameter clean-room approach worked — every visual
constant traced to the frozen research, and the benchmark-before-commitment
rule caught nothing fatal because the P0 prototype had already de-risked the
stack.

## Tooling experience

- **Worked:** codex background jobs as one-file draft workers (projection
  schema, browser-test assertions, visualizer worker, atoms bridge — all four
  drafts were high quality and two self-fixed their own type errors in their
  verify loops); the committed scratchpad benchmark + headless
  Playwright-with-system-chromium as a reproducible FPS harness; spectacle +
  system MiniBrowser for a genuine WebKitGTK measurement when Playwright's
  Ubuntu WebKit build would not run on Arch; the storybook CI lane's existing
  playwright install doubling as hosted browser coverage for driver stories.
- **Didn't:** Playwright's bundled WebKit on a non-Ubuntu host (ICU soname
  mismatch — fell back to system webkit2gtk); browser-mode full-desktop QA
  (chat-only dev-token wiring; see finding).
- **Frustrating:** the `.repos/effect-v4` mass-deletion scare (another agent's
  intentional work, but unattributed at the time); lazy-atom value retention
  in registry-driven tests (three debug cycles to find mount-what-you-read).
- **Wished existed:** a repo-blessed harness for driving the workbench with a
  real document outside Tauri; a WebKitGTK WebDriver binary in the toolchain.

## Implementation improvement opportunities

- Community-aware link rest lengths in the worker relaxation (currently flat
  50 — the projection carries no per-node community; the client computes
  communities for color only).
- Optional screen-grid rectangle label admission as a renderer config flag
  (design in `research/label-anti-overlap.md` §3; rank/fade matches the
  reference today).
- Sparse `update()` (per-slot attribute writes) when `changedNodeIds` gains
  real topology-delta semantics — the instanced layout was designed for it.
- The 12.5k-edge stress case suggests headroom for richer ontologies; the
  10k-node/30k-edge relaxation guard is conservative and could be profiled up.

## Goal & prompt critique

The compact GOAL.md + binding routing law was the right shape — the packet
never needed re-reading the full research corpus after P0. Two edits I would
make: (1) a single phase-owned benchmark table (see finding), and (2) the

check; explicit staging). The `/goal` launcher arguments ("Use codex for all
other token heavy work") were honored and materially preserved the Fable
budget: all four heavy drafts plus the adversarial review ran on codex.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Verify benchmark evidence is auditable before writing a
  design gate — commit the harness, parameterize the configs, and measure the
  things the reviewer will ask for (pick cost, mount time, heap, label
  admission), because the adversarial review attacked exactly the
  unreproducible parts first.
- **HIGH — Critical:** In registry-driven atom tests, mount every atom you
  read and force side-effect atoms with a get — unmounted atoms recompute
  fresh state and silently ignore prior writes.
- **HIGH — Critical:** Spot-check drafted graph algorithms against
  known-answer topologies before shipping — a P4 path + two-triangle-bridge +
  star trio caught the community-detection draft two-coloring tree structures
  (synchronous label propagation) and then flooding through bridges
  (asynchronous), which drove the rewrite to betweenness-artery components.
- **MEDIUM — Best practice:** Route heavy drafting to background codex jobs
  with exactly one owned output file each and review diffs before commit;
  interleave your own authoring while they run — wall-clock cost of four
  drafts approached zero.
- **MEDIUM — Best practice:** When a platform binary won't run (Playwright
  WebKit on Arch), look for the system-native equivalent (webkit2gtk
  MiniBrowser + spectacle) before downgrading the evidence claim.
- **LOW — Consideration:** A reference visual grammar extracted as prose
  parameters is enough to reproduce a proprietary renderer's look clean-room;
  the parts that needed judgment were exactly the parts the reference never
  proved (2.5k scale, selection semantics, theming).
