## Archive of the ownerless rows

Two passes ran with the same decisions, mirroring the tool's dry/apply pair. The plan pass recorded, per row, the checkout fence, the citation check, the digest and the destination. The apply pass re-ran each checkout's fence immediately before its first move and re-hashed each row before moving it.

- **Fence.** The latest ledger row is not `open` or `blocked`. No process cwd is inside the checkout. The newest operational `.beep` write is at least 7 days old, the `CHECKOUT_LIVE_DAYS` fence. All 62 checkouts passed at plan and at apply.
- **Citation fence.** The tool's `citationSkip` was replicated: one `git --no-optional-locks grep --quiet --perl-regexp` per row in the owning checkout, over the same evidence roots and with the same pattern (the path, or an ancestor below `.beep` as a whole token). 175 rows are cited by their own checkout's tracked documents, so they stay in place as `evidence-referenced`, as w5's generated rows did.
- **Move.** Destination is `~/.cache/beep/residue/<checkout path under the projects root, or under the home directory>/<row>`, on the same btrfs filesystem, so each move is a rename. `mv -nT` for a directory, `mv -n` for a file.
- **Digest.** A file is hashed as itself. A directory is hashed as the sha256 of its sorted per-file `sha256  path` manifest, without a trailing newline. The restore precheck command is in `goals/repository-simplification-confidence/history/receipts/stage-3-a-local-residue.md`.
