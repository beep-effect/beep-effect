# Reflection — epistemic-memory-retention-projections

## Summary

The repo-native mechanism projects accepted edge authority into a standalone
report, preserves both time axes and endpoint dispositions, and rebuilds identical
JSON and text after complete store deletion. Policy has no production defaults
and the shipped registry admits nothing. This closeout is proposed with the final
implementation; publication and merge readiness require separate Yeet evidence.

## Tooling experience

The existing EdgeVersion and ClaimDisposition models, canonical encoder and
Drizzle/embedded-Postgres fixtures made the seam explicit without a migration.
Per-package coverage includes only each package's own source, so domain and
use-case tests live with their owning packages while the native rebuild drill
lives in server. Full package audits caught a directory-order assumption that a focused run had
not exposed. The standalone script needed its own typecheck because the package
configurations cover source and tests, not scripts. The goal's operator runbook
records supported invocation and its calibration boundaries.

## Implementation improvement opportunities

The deployment-owned calibration registry remains deliberately unimplemented:
product evidence, authenticated approval, revocation and evaluation quality must
be established before a deployment composes one. The shipped command remains
inert. A report directory has one writer; interrupted output is repaired by a
rebuild. Neither limitation changes accepted authority or imports a donor model.

## Goal and prompt critique

The compact goal correctly prioritizes the authority/projection seam. A useful
future edit is to name the pressure unit explicitly: canonical fact payload bytes
and row counts are measurable from current authority, whereas physical database
allocation, RAM, access frequency and model tokens are different measurements.
The P0 contract makes that choice explicit and reversible.

## Lessons

- **HIGH:** A schema-valid calibration record is not authentic approval. Keep
  registry membership behind a server-owned dependency and recheck policy,
  organization, mechanism and temporal bindings in the report service.
- **HIGH:** Prove deletion of the whole disposable store, then compare both bytes
  and answers and reread authority. Reusing old report files cannot prove rebuild.
- **HIGH:** Missing disposition is unresolved; a non-claim endpoint has no claim
  disposition. Neither case justifies silently labeling authority active.
