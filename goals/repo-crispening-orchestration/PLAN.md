## Policy Ratchet Shape (G4)

`standards/schema-crispening.policy.jsonc` minimal contract (P0 may extend,
never contradict):

```jsonc
{
  "schemaVersion": "schema-crispening-policy/v1",
  "cards": ["SFV4-fn-schema", "SFV4-normalization", "SFV4-null-return", "SFV4-getsomes-struct"],
  "families": {
    "foundation": { "blocking": false },
    "drivers": { "blocking": false },
    "tooling": { "blocking": false },
    "apps-slices": { "blocking": false }
  },
  // Optional per-package override; wins over the family flag.
  "ownerOverrides": {}
}
```

Resolution rule: a finding's `file` resolves to its owner package exactly as
the existing inventory `owner` field does (e.g. `@beep/infra`); owner →
family by path prefix — `packages/foundation/**` → `foundation`,
`packages/drivers/**` → `drivers`, `packages/tooling/**` → `tooling`,
`apps/**` + slice packages → `apps-slices`, and `packages/shared/**` +
`infra/**` per the P1 assignment recorded in `ops/progress.json` (until
assigned: non-blocking). Semantics: findings whose `ruleId` is in `cards`
and whose resolved family (or owner override) is `blocking: false` are
**fully exempt** from `schemaFirstLintHasFailures` — excluded from
`enforcedCandidates`, `missingEntries`, and `activeAdvisories` counts alike.
This is what lets the P0 detectors land repo-green before the P1 baseline
exists, and it is why the policy file must land **before** the detectors
(see `tasks/tasks.jsonc` ordering).

## Execution Notes

- Preserve unrelated worktree changes; do not fold unrelated fixes into a
  crispening wave commit.
- Fence 8 scopes **source edits**: a wave PR edits only its family's package
  sources, but MAY (and must) also update the orchestrator-owned artifacts —
  `standards/schema-crispening.policy.jsonc` (the family flip),
  `standards/schema-first.inventory.jsonc` (exception ledger), and this
  packet's `ops/progress.json` / burndown. Touching those is not a fence
  violation.
- Ship small, rebase-friendly, per-package PRs — a repo-wide sweep touching
  hundreds of files at once collides with concurrent work and is harder to
  review or revert.
- Maintain the seam with `goals/effect-native-migration`: crispening never
  performs native-collection migration (`Map`/`Set`/`Date`/`JSON`/`Array` →
  Effect-native) — fence 7 of this packet's Non-Goals keeps that seam entirely
  theirs; coordinate schema edits with the active `schema-first-*` packets
  touching the same files.
- Operational rule: never run manual `turbo`/`docgen`/`vitest` while a
  background `bun run beep yeet verify` is in flight for this packet — turbo
  daemon contention emits spurious `Failed to spawn` / docgen exit-1 noise;
  use read-only probes (`git`, `rg`/`tail` on the log) while a verify run is
  active.

## P4 Closeout Checklist

Before marking the packet closed (and `status` → `completed-retained` /
`complete`):

1. Write a closeout reflection via the `/reflect` skill (or copy
   `_template/history/reflections/_TEMPLATE.md`) to
   `history/reflections/<YYYY-MM-DD>-<agent>.md`. Critique the repo
   **tooling** (what worked, what didn't, what was frustrating, what you
   wished existed), the **implementation** (improvement opportunities), and
   the **goal/prompt** (would you revise it to be clearer/easier/more
   efficient?). Capture TODOs worth codifying. Its YAML frontmatter must
   validate against `ReflectionFrontmatter`.
2. Run `bun run beep lint reflection-artifacts` (this packet has
   `reflectionRequired: true`, so a missing/invalid reflection blocks
   closeout).
3. Update `README.md` (status, latest evidence) and `ops/manifest.json` phase
   statuses + `initiative.status`.
