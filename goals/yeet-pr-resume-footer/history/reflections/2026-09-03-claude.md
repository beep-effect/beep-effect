# Reflection — yeet-pr-resume-footer (2026-09-03, claude)

## Summary

Revived the Yeet PR provenance footer that CSF-007 removed, redesigned so the
public block is exactly `bun run beep yeet resume <n>` and every local fact
(session ids, paths, resume commands) stays in a workstation registry. PR #975
dogfooded the footer on itself, the live-session guard refused to fork the
publishing desktop session, and neither Greptile nor Codex Cloud filed a leak
finding against the footer. Verdict: shipped as designed; the packet's own
research docs were the only leak, and that was self-inflicted.

## Tooling experience

- **Worked:** the grill-with-docs session (seven ratified decisions in one
  round), the Workflow design panel (three lenses, red-teamed, judged) that
  killed the `cd "$BEEP_PROJECTS/<clone>"` idea before it shipped, detached
  Codex lanes with report files as the deliverable, `yeet publish
  --start-pr-early` so hosted checks arbitrated while local proofs queued,
  `yeet reply` drafts for nine threads in one pass, and GitHub's
  `userContentEdits` for the body race.
- **Didn't:** `bunx --bun vitest` (forks pool) hangs on this workstation; the
  turbo coverage wrapper stalls inside the Codex sandbox; `package-verify`
  blames untouched files when dependency dists are stale; `codex` silently
  lost its login mid-campaign and the lane died with 401s.
- **Frustrating:** a `git merge` piped through `grep` hid its dirty-tree
  refusal, so publish refused a stale base one cycle later; `goals doctor`
  called a minutes-old packet stale; the `goals bootstrap` plan has no writer.
- **Wished existed:** a conditional update for PR bodies; a Codex brief
  template with the sandbox-safe verification commands baked in.

## Implementation improvement opportunities

- PR 2 surfaces: `yeet link`, verify/repair ledger rows, re-assert on
  reply/closeout/merge, the Codex-lane `--add-dir` recipe, a Codex live guard.
- Fold the edit-history reconciliation into a reusable "contended body"
  helper for any other yeet write to a PR description.
- Publish the resume fence only after the number is known (done) and consider
  a `--print` guard that refuses to run outside a TTY (done) as a pattern for
  other local-only outputs.

## Goal & prompt critique

- `GOAL.md` should have listed "scrub research docs to placeholders" as an
  acceptance criterion; the SPEC covered the footer boundary but not the
  packet's own prose.
- The Codex briefs should have carried the sandbox-safe verification block
  from the first lane instead of being corrected lane by lane.

## TODOs worth codifying

- See the frontmatter `todos` list; the Codex brief template and the
  package-verify stale-dist hint are the two with the highest recurrence risk.

## Lessons (confidence-tiered)

- **HIGH — Critical:** exclude leak-shaped fields by schema, not policy — the
  Codex findings pipeline has no accepted-risk disposition, so the renderer's
  input type and a boundary property test are the only durable evidence.
- **HIGH — Critical:** never frame history rewriting as a remedy in this repo;
  force-push is denied and GitHub keeps PR commits viewable, so prevention
  (placeholders before the first push) is the whole game.
- **MEDIUM — Best practice:** after any main merge, reinstall and regenerate
  projections before trusting the cheap-gates tier locally.
- **MEDIUM — Best practice:** run multi-step git sequences as separate tool
  calls so an operator interrupt lands between steps, and re-derive state from
  `git status -sb` after any interrupt.
- **LOW — Consideration:** derived Claude session labels are publishable under
  the ratified policy, but pairing them with a path in prose is what reviewers
  read as a leak.
