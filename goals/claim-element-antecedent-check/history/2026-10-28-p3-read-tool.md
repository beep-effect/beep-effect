# P3 read-only claim review tool

The repository autonomy charter requires operator review to remain asynchronous and not block independent progress. Its precedence over the packet's serial phase prose is recorded in the SPEC Decision Log. Actual P2 attorney acceptance remains open; this implementation and its synthetic tests do not supply human agreement.

The practice toolkit now exposes twelve read-only tools, including `claim_self_check`. The new use-case tool accepts the existing normalized ClaimSelfCheck input and an optional actual Box file identifier. It invokes the existing candidate mapping and returns claim-finding ReviewItems, candidate/evidence envelopes and every undecomposed claim. Each item quotes the complete source claim, names the referring phrase and uses plain advisory language. Findings that have a dependency chain also show the claims checked. Pattern-not-covered items explicitly require manual review without an antecedent conclusion.

Review item ids use the candidate's document-scoped public identifier, while claimId retains the candidate row id. Tests demonstrate that reused spike row ids in different documents do not collide as review-item ids. When a genuine Box id is supplied, the SourceRef quotes the actual claim; otherwise sourceRefs stays empty and the full claim plus source-aligned candidate evidence remain available. No Box identifier or page is invented.

The server's real MCP handler composes the existing self-check over an explicitly unavailable public-source port. This local tool performs no source fetching or persistence and keeps the existing KG host credential-free. The public ClaimSelfCheck publication API remains unchanged. A real McpServer.callTool test returns the expected source-quoted item and term evidence, and the candidate lookup before and after the call is identical.

The existing ReviewItem schema round-trips generated items. An integration test records synthetic right/wrong verdicts against an actual generated item and verifies active/rejected ClaimDisposition projections, including the rejection note. The supporting implementation was already merged in review-verdict-envelope #1761 (commit 90ef963d43). Coverage tests retain undecomposed claims even with zero review items.

The new tool exposed an installed upstream JSON-schema failure for named fragments inside template-literal identifiers. The MCP boundary now uses the documented referencePolicy hook to keep scalar/union/template fragments inline and preserve structured and recursive references. Runtime codecs and domain models are unchanged. The regression exercises named union/string fragments in both parameter and success schemas, including rejection of an invalid prefix. This prerequisite repair is limited to the MCP schema-conversion boundary.

The final use-case verification includes dependency-chain presentation.
