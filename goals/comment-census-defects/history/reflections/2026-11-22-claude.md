# Reflection — comment-census-defects (2026-11-22, claude)

## Summary

All ten census defects reproduced on `origin/main` 809947c and were fixed with failing-then-passing
regression tests, one PR each: #3463 node-sync cwd, #3464 qa-capture EPERM, #3465 git
working-diff ref, #3469 nlp-mcp SSRF, #3470 wink spans, #3471 onnx tensors, #3475 YAML escaped
comment, #3476 runtime lint baseline, #3479 coverage floors, and this PR for oip-web anchors,
plus #3481 for the same wink offset cap in `WinkTokenization`, found while fixing #3470.
The misleading comment was corrected or removed in each. The verdict is good, but the hosted
gate caught five introduced follow-ups the lanes should have found locally.

## Tooling experience

- **Worked:** `beep worktree new` per lane and an Opus lane agent per defect let all ten fixes
  land within about an hour. `yeet final-check --skip <gate>=<reason>` followed by `yeet open`
  kept honest receipts under the push-first ruling. `lint effect-vitest --files` gives a fast
  scoped answer.
- **Didn't:** the readiness monitor's `job wait` returns on the first inbox wave, and a
  two-hour background wait timed out. Rollup jobs (Lint, Test Unit) show `skipped` when every
  shard passes, which reads like a failure at first glance.
- **Frustrating:** a commit-msg rejection (a body line over 100 chars) failed silently inside a
  chained command, and the inbox row was then acked against the wrong sha.
- **Wished existed:** a per-lane "dependents' tests" command, and a monitor verdict that waits
  for every check, not only the required ones.

## Implementation improvement opportunities

- The runtime-lint baseline guard reads other packages' test files, so turbo's cache for
  `@beep/lint-rules` does not see their changes; a stale row shows on the next cache miss.
- `WinkTokenization` rebuilt offsets from `precedingSpaces` with the same 65,534-space cap as the
  backend; found while fixing #3470 and fixed in #3481.

## Goal & prompt critique

- Add a "Dependents / inventories" column to the SPEC defect table (see findings).
- Put "push-first: skip local final-check gates and record them" in `GOAL.md` Workflow.

## TODOs worth codifying

- Occurrence-hash stability for effect-vitest exception rows across unrelated in-block edits.
- A monitor or gate guard that blocks a `final` while any check is pending.

## Lessons (confidence-tiered)

- **HIGH — Critical:** post `final` only when every check run on the head has completed — non-required Lint Policy caught introduced findings on #3470 and #3476.
- **HIGH — Critical:** never commit `effect-vitest --write` output; hand-carry moved rows — `--write` strips reviewed reasons.
- **MEDIUM — Best practice:** test a changed driver's dependents in the lane — the semantica digest red was predictable from the dependency graph.
- **LOW — Consideration:** when a review bot finds an edge case in new code (wink space cap, empty baseline), it is usually right; fix it in the same wave.
