# Reflection — party-slice (2026-11-06, claude)

## Summary

The party slice itself was built by the Codex lane and shipped in #2658 and
#2676; its own closeout reflection is `2026-11-03-codex.md`. This session
closed the packet: it found the goal stuck `active` after a verified receipt,
fixed the closeout route repo-wide (#2703), adopted the closeout, and recorded
an independent acceptance audit against main (#2720). One clean run on
`a3eb1c1005` passed every GOAL.md command, all five boundary scans, the three
party package-verify runs and 153 party tests.

## Tooling experience

- **Worked:** `goals completion refresh` receipts and `goals doctor` made the
  verified-but-unadopted state visible once rendered honestly; `yeet reply`
  resolved review threads with dispositions; `yeet open` let a one-file docs PR
  through while main was red.
- **Didn't:** `yeet publish --push-only` refused a plain commit; root
  `fallow:*:check` scripts need a base ref when run by hand; `final-check --skip`
  takes gate ids (`cheap-gates`, `lint-policy`), not the step labels it prints.
- **Frustrating:** the T3 server restart killed two background runs mid-way, and
  a log path containing `@beep/` silently produced an empty verification run.
- **Wished existed:** a per-SPEC-row PASS/FAIL proof command for goal audits.

## Implementation improvement opportunities

- The party slice is complete against SPEC; no slice code change is owed.
- law-practice-server's citation tests (not party-slice) need a fix PR; routed
  to the orchestrator and recorded in `history/2026-11-06-post-closeout-audit.md`.

## Goal & prompt critique

- GOAL.md should list the exact verification commands as one script and say
  that package-verify is required for the three party packages only.
- The launcher's done condition now names the adoption check; keep it terse,
  since `verification-route/GOAL.md` sits at 3996 of 4000 characters.

## TODOs worth codifying

- `goals set-status` adoption should also update the README Status prose.
- A one-pass Close-phase audit script per packet.

## Lessons (confidence-tiered)

- **HIGH — Critical:** A goal is done only when the adoption PR merges and
  `closeout.status == initiative.status` on main — receipt verification alone
  left party-slice `active` for two days.
- **MEDIUM — Best practice:** Attribute every red before acting; a one-file docs
  PR on a red main is finalized with named `--skip` reasons, not repaired in place.
- **LOW — Consideration:** Keep scratch log filenames free of `/` and `@`; an
  invalid redirect path makes a verification run report nothing.
