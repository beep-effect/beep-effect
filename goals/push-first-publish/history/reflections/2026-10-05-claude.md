# Reflection — push-first-publish (2026-10-05, claude)

## Summary

`yeet publish` is now push-first: cheap-gates and the head-install preflight gate the push,
the PR opens as a draft labelled `ready-for-heavy`, the detached readiness monitor is
submitted, and hosted CI is the authoritative proof. `--prove-first` keeps the old order
byte for byte, `--fast` and `--start-pr-early` are gone, the monitor gained
`ready-pending-flip`, and `yeet ready` flips a draft under the D10 gate. The packet went
from grill to code, doctrine, and its own live-path publish in one day.

## Tooling experience

- **Worked:** `yeet publish --plan --json` was the fastest proof that the planner order
  matched D1–D8 exactly; the existing plan-wiring tests made `--prove-first` byte-equality
  cheap to assert; the inbox waiver with `--actor/--shard/--expires-at` recorded the
  inherited red with attribution instead of a silent skip.
- **Didn't:** the headless lane ended while its own package-verify was still running, so
  no handoff was written; `bun run beep` in the primary clone failed on a missing
  `@beep/utils` until `bun install --frozen-lockfile` was re-run there.
- **Frustrating:** `beep goals bootstrap` compiles a complete materialization plan but
  refuses to write it; the ship-velocity packet owns the scheduler and parity doctrine but
  is closed, so there was no live packet to amend and a new one was needed.
- **Wished existed:** a `yeet publish --plan` diff against the previous binary's plan, so
  a planner change can be reviewed as a plan diff rather than a code diff.

## Implementation improvement opportunities

- `monitor --until-ready` could print the push-budget rule with each wave row so agents
  batch fixes without reading the skill.
- `yeet ready` could accept `--when-ready` to block on the job and flip in one step for
  packets that have no further waves.
- The label step records `skipped` for pre-existing PRs; a `--label` opt-in on an
  existing PR would remove the last manual `gh pr edit` from the fix loop.

## Goal & prompt critique

- Add to `GOAL.md` scope: "P3 publishes from this lane with the lane's own CLI; a publish
  from a clone on `main` exercises the old path and is not the live proof."
- The brief told the lane "do not commit; leave the tree dirty" but not "write the
  handoff before any long verification"; add that sentence to every lane brief.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Attribute a package-verify red before repairing — the only red
  here reproduced on clean main and had nothing to do with the diff; repairing it on the
  lane would have widened scope and hidden a main regression.
- **MEDIUM — Best practice:** Put the live proof of a tooling change in the packet's own
  PR — publishing this PR through the new default path is the acceptance test that no unit
  test can give.
- **LOW — Consideration:** A plan-only scaffolder is a half-tool; when a command compiles
  a plan it should also be able to apply it.
