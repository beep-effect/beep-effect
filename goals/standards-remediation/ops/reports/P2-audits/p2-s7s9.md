## Key mechanism finding (governs both clusters)

The schema-first inventory's `object-struct-schema` scan
(`SchemaFirst.ts:1726-1758`) only fires when
`callExpression.getExpression().getText() === "S.Struct"` (line 1740). It never
inspects `S.Class(...)` calls. `detectStructReason` (`:816-844`) always returns
`O.some(reason)` for *any* non-trivial `S.Struct(...)` shape (not-a-plain-object
-literal, invalid/spread keys, inline-nested, feeds-a-class, function-local) —
every branch still yields `status: "exception"`, so no branch of
`detectStructReason` actually removes an entry from the inventory. The only way
an `S.Struct(...)` call disappears from the 326-baseline is to stop being an
`S.Struct(...)` call — i.e. convert to a named `S.Class`. Confirmed in
`.repos/effect-v4/packages/effect/src/Schema.ts:12540-12569`: `S.Class`
provides `static check`, `static extend`, and `static mapFields` with the same
shape as `Struct`'s combinators, so nothing downstream that composes on the old
`S.Struct(...)` value (`.check`, `.mapFields`, feeding another `S.Class`, even
spread/computed keys) is lost by switching to `S.Class`. This is the mechanical
fix for effectively the entire S7 cluster and most of S9's
"not-a-plain-object-literal"/"spread" sub-buckets.

### Re-derivation detail for the 3 confirmed-stale/weak entries

- **`CreateThreadAtomInput`**: grepped the whole repo (`packages/agents/client`
  and `apps/`) for consumers — none exist outside the declaring file's own doc
  examples. The "consumed by app callers" premise in the recorded reason is not
  evidenced today. Converted `S.Struct({...}).annotate({...})` +
  a separate `export type CreateThreadAtomInput = typeof CreateThreadAtomInput.Type`
  into a single `class CreateThreadAtomInput extends S.Class<CreateThreadAtomInput>("CreateThreadAtomInput")({...}, {...}) {}`
  (dropping the now-redundant type alias, since the class name doubles as the
  type). Compiled clean in `packages/agents/client`.
- **`TypedTextSchema`**: this one's reason (function-local) *does* reproduce
  under the live detector (confirmed by re-reading `detectStructReason`'s
  branch order), but "function-local" is not itself an unconvertible verdict —
  it's a generic factory (`<K extends TextKind>(kind: S.Schema<K>) => S.Struct({...})`).
  Converted to declare a local class per call
  (`class TypedTextSchemaClass extends S.Class<TypedTextSchemaClass>("TypedTextSchema")({...}) {}`)
  and return the class. `makeTyped`'s `schema.make({...})` call sites are
  unaffected. Compiled clean in `packages/foundation/modeling/nlp`. This
  disproves the assumption that generic/parameterized struct factories are
  inherently unconvertible — the same local-class technique applies to S7's
  `GraphCollection`, `makeEventSchema`, and `LiteralKit`'s `union`.

### `LawEntities` — reproduced-in-code unconvertible (real negative-result attempt)

Attempted collapsing the interface + `LawEntitiesBase` + `class LawEntities
extends LawEntitiesBase {}` three-step dance into the repo's normal one-step
`class LawEntities extends S.Class<LawEntities>($I\`LawEntities\`)({...}) {}`
pattern (used everywhere else in the repo). `tsgo -b tsconfig.json` on
`packages/law-practice/use-cases` immediately failed:

```
src/IrToLaw/IrToLaw.ports.ts(51,14): error TS7056: The inferred type of this
node exceeds the maximum length the compiler will serialize. An explicit type
annotation is needed.
```

This reproduces the recorded reason exactly. `IrToLawShape.toLaw`'s
`EffectSchema<LawEntities, IrToLawExtractionError, never>()` output type
circularly references `LawEntities` in the same file, which is almost
certainly what pushes the self-referencing single-step `S.Class<LawEntities>`
inference over TS's serialization limit. The explicit `interface LawEntities`
+ explicit `S.Class<LawEntities, S.Struct<LawEntitiesFields>, {}>` type
annotation on the intermediate `LawEntitiesBase` is a load-bearing TS-inference
workaround, not stale scaffolding. **Confirmed unconvertible without a wider
refactor** (e.g. splitting `IrToLawShape` into a different file, or a
lazy/suspended schema reference) — out of scope for this audit; reverted
immediately after reproducing the error.

## Rulings

See the two JSON rulings printed to stdout. Summary: **no detector changes
needed for either cluster.** S7-struct's 9 entries are 100% code-fix
candidates (convert `S.Struct` → `S.Class`, preserving spreads/computed keys
as-is inside the class fields argument — nothing about spread or non-identifier
keys blocks `S.Class`). S9-manual's 37 entries split roughly into: a
majority convertible subset (same `S.Struct`→`S.Class` mechanical fix, whether
the recorded reason is stale like `CreateThreadAtomInput`/`FieldErrorEntry` or
live like `TypedTextSchema`/`NpmPackageJsonShape`/`TSNodeConfigShape`), and a
minority (`BM25VectorizerInstance`, `ToolCallRequest`, `FieldShellProps`,
`LawEntities` — roughly 4/11 sampled ≈ 36%) that are genuinely unconvertible:
runtime-method-bearing third-party/builder types, `ReactNode`-carrying UI
props, and one TS7056 inference-limit workaround. Extrapolated across the
full 37, expect roughly 22-27 convertible and 10-15 genuinely unconvertible
(non-schema-modelable data or compiler-limit workarounds).
