Verdict: **goal met**; the dominant cost was not the remediation itself but landing a 776-file umbrella PR against a fast-moving `main`.

## Tooling experience

- **Worked:** The regenerate-then-gate loop (`beep laws dual-arity --write/--check`, `beep lint schema-first --write`, `beep quality jsdoc-inventory` + `jsdoc-ratchet`, `beep quality knip`) made every inventory reconciliation deterministic and auditable. `TURBO_FORCE=1 turbo run check` as a fast repo-wide pre-push net (98–99/99) caught merge type-interactions cheaply. Per-package `check test docgen --filter` gave targeted proof before each push.
- **Didn't:** `git checkout --ours <file>` for hunk-level intent (whole-file footgun — see findings). `beep lint schema-first --write` dropped a documented exception on an unrelated line shift. Classic branch-protection API 404'd and hid the real ruleset gate.
- **Frustrating:** The merge-treadmill — four sequential main merges because each CI cycle let a new PR land. The Docgen affected/full lane-gate false-fail on the final commit. The jsdoc ratchet's `unsafeExampleFindings` `no-declare-statements` rule rejecting a `declare const` stub in an example for a type I couldn't otherwise construct without an assertion.
- **Wished existed:** A `beep merge-main` helper that fetches, merges, regenerates all inventories, runs the five gates, and reports in one command; and symbol-keyed exception entries so upstream line shifts don't re-red gates.

## Implementation improvement opportunities

- Symbol-key inventory exceptions (schema-first/jsdoc/dual-arity) instead of line-number keys.
- Teach `docgen:local` (or the ci lane) to auto-escalate affected→full when it detects a full-required reason, instead of exiting 1 and requiring a re-run.
- Consider a knip config so a new leaf package's `bun-types` reference resolves via the repo's `@types/bun` convention without each package re-declaring it (would also avoid the bun.lock churn that trips the Docgen lane-gate).

## Goal & prompt critique

I'd revise the PLAN's land strategy to explicitly budget for N main-merges during the final land, or split the terminal land into fast-merging sub-PRs. The GOAL/SPEC were otherwise unusually clear — the normative SPEC + API-corrections table + locked-rulings ledger made resumption across context windows reliable.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Prove merges with the affected packages' *tests*, not just typecheck — the `git checkout --ours` security-guard loss compiled cleanly and was only caught by a package test. Run the touched package's `test` before committing any non-trivial merge resolution.
- **HIGH — Critical:** `main` is gated by a ruleset of 17 required checks; you cannot merge (even `--admin`) until all are green, and auto-merge is off. Plan the final land around holding a green window while `origin/main` is unchanged.
- **MEDIUM — Best practice:** After any upstream merge that adds a package or exports, re-run all five gates — new exports reintroduce zero-baseline findings (jsdoc tags; knip `bun-types`→`bun` + `@types/bun`); fix at the source, never grow the baseline.
- **MEDIUM — Best practice:** A dep addition (bun.lock/package.json change) can flip the Docgen lane-gate to full-required; expect it and re-run the Docgen job rather than assuming a real docs regression.
- **LOW — Consideration:** For giant umbrella PRs, the regenerable inventory files conflict on nearly every main merge; resolving them is cheap (`checkout --ours` + regenerate) — the code conflicts are the real work, so triage conflicts by file class first.
