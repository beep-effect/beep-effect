# Reflection — effect-reference-workspace (2026-09-28, fable)

## Summary

The packet moved the Effect and effect-tsgo clones into
`$HOME/YeeBois/references/effect` and made that root a graft workspace. Every
beep checkout now reaches it through manifest-provisioned `.repos` links, and a
nightly `beep-refs-refresh` timer rebuilds its deep tier. The work shipped in
PR #1257 (merged 2026-09-25, `217e308592`) and PR #1271 (merged 2026-09-25
19:46 UTC, `9de64fb848`). The `refs-workspace-impl` worktree was retired on
2026-09-28 with the archive ref
`refs/archive/worktrees/refs-workspace-impl/20260928-050820`. The first two
scheduled nights failed. On 2026-09-26 the run ended with exit 130 when the user
manager restarted. On 2026-09-27 a model cooldown turned the run into a 10-hour
no-op. PR #1311 fixes the second failure and adds failure detail to receipts.
The verdict is that the workspace works. The nightly refresh is only trustworthy
from PR #1311 onward. P4's readback criterion was revised at closeout: the
packet's deliverable is the workspace, the tooling, the timer and this fix, and
the first two scheduled nights are recorded. Reading back the first clean
scheduled night is an operator follow-up in `research/OPPORTUNITIES.md`, from the
receipt at `$HOME/.local/state/beep/refs/last-refresh.json`.

## Tooling experience

- **Worked:** graft workspace mode federated both members on the first
  structural build. `scripts/setup-effect-ref.sh` relinked 152 checkouts with no
  failures. The `beep refs plan` dry run and the systemd unit rendering tests
  caught path and quoting problems before anything was installed.
- **Didn't:** `beep:check` is not the whole gate. `quality test-tsgo`,
  `knowledge refs --check`, oxlint `no-inline-schema-compile`, and the
  `SFV4-arbitrary-tests` advisory each failed hosted lanes or local gates after
  the package check was green.
- **Frustrating:** the 09-27 receipt showed two `build-failed` outcomes with no
  reason. Finding the 429 needed `journalctl --user -u cli-proxy-api`. A fresh
  worktree also needs its upstream `dist` outputs restored before
  `package-verify --quick` can typecheck.
- **Wished existed:** one pre-publish command that runs every Heavy / Lint
  Policy gate for a package. A proxy status endpoint that reports cooldowns
  without spending a request would also help.

## Implementation improvement opportunities

- The cooldown preflight from PR #1311 belongs in `beep graft deep refresh` too.
  The same cooldown broke `beep-graft-deep-refresh.service` on 2026-09-27.
- The refresh could cap how long a deep build may wait on the provider, rather
  than depend on the 5 h step timeout as the only backstop.
- A run killed by a user-manager restart, as on 09-26, writes no receipt. A
  start-of-run receipt with an in-flight marker would make that visible.

## Goal & prompt critique

- P4 in `PLAN.md` asked only to confirm the "next-morning deep tier". It should
  require a scheduled run started by the timer itself, with its receipt read
  back, because the seed run under a manual `systemctl start` hid both failure
  modes.
- The P1 slice list should name the four gates outside `beep:check` next to
  `package-verify`, so the implementation lanes run them before publishing.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Never let an unattended job honour a provider's
  `Retry-After` without a cap. The SDK slept 15.4 h on `Retry-After: 55516`,
  and only the step timeout ended the run.
- **HIGH — Critical:** Receipts must carry failure detail. An outcome without
  its reason sends the operator to the journals for every failure.
- **MEDIUM — Best practice:** Run `quality test-tsgo`, `knowledge refs --check`,
  oxlint, and `beep lint schema-first` before publishing, not only `beep:check`.
  Both PR #1257 and PR #1311 needed fixes from these gates.
- **LOW — Consideration:** A user-manager restart kills user units mid-run, as
  it did with exit 130 on 2026-09-26. Nightly jobs that run for hours should
  expect that and leave a trace when it happens.
