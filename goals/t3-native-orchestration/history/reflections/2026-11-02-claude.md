# Reflection — t3-native-orchestration (2026-11-02, claude)

## Summary

Deleted beep's agent-to-agent stack (`agent-message` CLI group, the
`AiProviderCliSession` adapters, `@beep/t3-code`, three orphaned ai-metrics
modules, the runbook, two cache-review records and five packets), rewrote the
orchestrate, operator-handoff, remote-development-agents and closeout skills plus
three runbooks and AGENTS.md around T3 Code's MCP tools, and proved the new
procedure live: Codex and Claude children launched with pinned models, two
message rounds each, interrupt verified terminal. Every gate named in the spec
passes locally; hosted CI is the proof of record.

## Tooling experience

- **Worked:** `beep delete-package --rewrite-packets` removed the package and ran
  every baseline writer in one go; `goals set-status` wrote the supersession;
  `knowledge semantic-delta` caught every dangling path; the T3 tools behaved as
  their schemas say (`delegate_task`, `t3_thread_send` with `clientRequestId`,
  `t3_thread_wait` on a `runId`, `t3_thread_read` with `afterPosition`,
  `t3_thread_interrupt`).
- **Didn't:** `te toolprune restore` removed nothing for the T3 tools (they were
  applied under another record); the deny list had to be edited and `kept`
  written by hand. `skills relock` only relocks vendored skills, so the §6 step
  for local skills is `skills update` alone.
- **Frustrating:** the semantic-delta gate reads the committed HEAD, so each
  wording fix needed a commit and a two-minute rerun; the cache-baseline request
  schema had to be read from source.
- **Wished existed:** a `retired:` tombstone writer for markdown and JSON, and a
  one-line "deny list hides these orchestrator tools" warning at session start.

## Implementation improvement opportunities

- The orchestrate skill's correlation rule (run id plus position) is the one
  that worked; a future `beep` helper could wrap send→wait→read with that rule
  and the stable `clientRequestId` derivation.
- `remote-development-agents` now carries `environmentId` placeholders; the
  fleet rollout goal fills them and should add the per-host `t3_environment_links`
  check to its readiness line.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Correlate a T3 reply by the send's `runId` and the item
  position after the sent message — a Codex run can stay `running` after its
  final message, so a completion-keyed wait hangs.
- **HIGH — Critical:** Write deleted paths as `retired:<slug>` plus a permalink
  everywhere outside archival directories before running `knowledge
  semantic-delta`, and commit before each run — the gate reads HEAD.
- **MEDIUM — Best practice:** Run `beep delete-package --dry-run` after the CLI
  importer is gone and clear its hard hits (fixture rows, CI partitions,
  `turbo.json` inputs) by hand before the real run; the tool refuses dependents
  and never overrides them.
- **LOW — Consideration:** A Codex child may not see the injected `t3-code`
  server; do not plan on children messaging each other until that is qualified.
