# Reflection — practice-box-provisioning (2026-09-03, claude)

## Summary

The practice Box tenant now carries the versioned starter tree: 32 folders under
the service identity, the attorney collaborated as Editor on the client folder,
metadata and retention honestly blocked by entitlement, and a fresh-process
re-plan that is all-Noop. The work shipped across PR #928 (driver surface and
reconciler), PR #947 (pre-apply hardening after an adversarial review judged the
merged reconciler unsafe), and PR #959 (the Sign 403 tolerance discovered by the
first live dry-run, plus this closeout). Verdict: complete, with the operator
paths that blocked it for weeks replaced rather than worked around.

## Tooling experience

- **Worked:** Codex Sol xhigh lanes for review and implementation kept Fable
  usage to orchestration; four Grok lanes turned Box and 1Password questions
  into cited facts; `bun run beep yeet publish --start-pr-early --monitor --pr`
  let hosted checks run while the local proof queued; `op-doctor` gave a
  one-line-per-surface acceptance that made the 1Password fix provable.
- **Didn't:** 1Password desktop CLI integration from agent sessions; the
  Codex sandbox cannot reach the network or the user bus, so its doctor runs
  had to be re-run unsandboxed; `--start-pr-early` refuses `--amend`.
- **Frustrating:** machine-wide admission held publishes in queue for up to
  27 minutes behind other sessions' merged previews; a docs-only PR inherited
  an `@beep/editor` coverage ratchet failure until main was merged in.
- **Wished existed:** a package-verify that detects stale dependency
  declarations after a main sync, and a tracked home for the operator runner.

## Implementation improvement opportunities

- Inventory: treat every observation-only 403 as permission-blocked (done for
  Sign in PR #959); consider the same for webhook listing.
- Runner: pass raw documents to services that decode; add the raw-versus-decoded
  contract to the package README.
- Plan artifact: expose the identity guard digests so a reviewer can confirm the
  tenant and subject from the artifact alone.

## Goal & prompt critique

- Replace "the staging drop is reported foreign" with "foreign resources under
  the anchor root are reported; resources under other users' roots are out of
  scope" so the criterion matches the ratified service-owned topology.
- Add to the GOAL workflow: "confirm the agent 1Password path with `op-doctor`
  before any live step"; the launcher assumed credentials would simply work.

## TODOs worth codifying

- A doctor-style repo check for the `op` shim and automation credential.
- UUID `op://` references or Connect-backed fan-outs before large parallel lanes.
- A tracked CLI home for the private runner so its apply path has tests.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Make unattended secret access a designed path (shim plus
  service account), never an approval loop — the desktop integration cost this
  packet weeks and is unsupported for headless agents by 1Password's own model.
- **HIGH — Critical:** An adversarial review before the first live mutation
  paid for itself twice: silent adoption and case-sensitive matching would have
  corrupted the first apply, and the live tenant still surfaced two more gaps.
- **MEDIUM — Best practice:** Keep observation reads tolerant and mutation
  preconditions strict; the reconciler's safety comes from fail-closed writes,
  not from failing reads.
- **LOW — Consideration:** Prefer `--start-pr-early` publishes and merge main
  before proving a branch whose base predates a coverage baseline change.
