## Proposed plan

1. Write a hold record for every override row in this file, using `patches/onnxruntime-node@1.30.0.md` as the template. Each record carries the package, the advisory ids above, the owner above, and an exit condition. For `minimatch`, `detailed-xml-validator` and the OTel exporter, record "compatibility/dedupe, no advisory" as the evidence.
2. In one PR, remove or relax the six range-satisfiable overrides: `@hono/node-server`, `browserslist`, `ip-address`, `nanoid`, `postcss`, `uuid`. Regenerate `bun.lock`, then run the required Security (OSV) lane. Expect `postcss` to land on 8.5.29 (satisfying `vite`), `browserslist` on 4.29.3 (satisfying `@serwist/next`), `docx` to get nanoid 6, and mermaid to get uuid 14.
3. Replace the global `brace-expansion ^5.0.12` with per-major floors (`1.1.21`, `2.1.7`, `5.0.12`) or nested overrides. Then drop `minimatch 10.2.5` and prove eslint, glob and archiver with the lint lanes.
4. Decide the exporter override: delete it (two exporter copies, both clean) or renew it with a recorded "single copy across Phoenix and own OTel" reason. Note that it currently overrides phoenix-otel's declared `^0.220.0`.
5. `protobufjs` and `sharp`: tie both exits to the `scratchpad/effect-ontology` / `@xenova/transformers` retirement question already open in H1.
6. `detailed-xml-validator` with `fast-xml-validator`: run the `@beep/schema` and `@beep/repo-cli` XML tests on `fast-xml-validator` 1.4.2 + `detailed-xml-validator` 2.2.0, then drop both pins or record the failure.
