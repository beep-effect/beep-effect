## Per-script notes

### CI group (2, 3, 4, 5)

- **Ordering.** Every lane-gate step runs before `uses: ./.github/actions/setup-monorepo-ci`. The setup lines are check.yml:230/384/497/659, heavy.yml:137, and storybook.yml:65. The gate exists so a `goals_only` PR skips setup entirely. Any CLI port therefore has two options. (a) Move classification into a job that already has runtime, such as the `admission` job (check.yml:61-120, which runs `bun run beep ci admission --github-output` after setup), and expose `goals_only`/`desktop_rust_relevant` as job outputs; the four check.yml lane jobs would then need `needs: [admission]`, and today only `heavy` has it (check.yml:123). (b) Keep a pre-runtime shell shim. heavy.yml and storybook.yml are separate workflows with their own gates.
- **Duplicated logic.** `CLI/Ci/HeavyAdmission.ts` `heavyDocsOnlyPattern` is documented as the shell `goals_document_pattern` "verbatim, widened". After the port, one schema-owned pattern family should back both `goals_only` and `docs_only`, so the regex lives in one place.
- **`ci-job-env.mjs` ordering inside the action.** The steps run in this order: Setup Bun (:232) → Setup Node (:244) → Export job environment (:256) → Restore Bun cache (:277) → Restore Turbo cache (:287, conditioned on `env.TURBO_TOKEN`) → Install (:298). A Ci port needs the install moved ahead of the export, with the Turbo-cache restore after both. Baked-runner detection (:186) and the bun cache key must keep working.
- **`ci-job-env.mjs` port checklist.** Drop the `.fallowrc.jsonc:87-88` exemption. Keep the action's explicit secret inputs (not `toJSON(secrets)`), as asserted by `T/ci-runner-security.test.ts:704,726`.
- **Older checkouts.** heavy.yml is `workflow_call` and runs from main against older PR checkouts. That is why `ci-runner-resources.sh` is behind `[[ -f ... ]]` (heavy.yml:212), and `T/ci-runner-security.test.ts:268` locks the fallback. A port to `bun run beep ci <resources>` needs the same capability probe, for example `bun run beep ci --help | grep`, or keep the file check until no supported PR base predates the port.
- **`ci-prune-apt-sources.sh` is untestable as written.** `/etc/apt/sources.list.d` and `sudo` are hardcoded. The brief's "synthetic filesystem fixtures" requires adding an override, such as `BEEP_APT_SOURCES_DIR` plus a sudo override, defaulting to today's behaviour.

### Reference provisioning (14, 16)

- `Refs.service.ts` already models the manifest (`readManifest`), plans `clone … -> …` lines (`plan`, ~:339-365), and implements `linkInto`. `linkInto` refuses a symlinked `.repos`, relinks, and keeps a non-symlink with a warning, which mirrors the script's `link_reference`. `beep worktree new` already calls it.
- Missing pieces: clone-missing-members, the per-clone `.git/info/exclude` append (`Refs.service.ts:57` documents the same artifact set, R3), and `$HOME`-literal root expansion parity (`resolveRoot`).
- A `refs provision`/`refs setup` subcommand that runs plan → clone missing → `linkInto` would replace the script. Remedy strings in Refs/Lint must then name the new command.

### Turbo remote-read setup (8)
