# Reflection — gov-legal-mcp (2026-07-31, claude)

## Summary

Shipped `packages/drivers/gov-legal-mcp`: one stdio MCP host exposing four bounded
read-only tools (`govinfo_search` hard-gated, `ecfr_list_titles`/`ecfr_search_results`/
`ecfr_get_structure` keyless) through shipped `@beep/mcp-kit` composition, with the
frozen deterministic naming contract (NFKD normalization, 64-char cap with 8-hex
SHA-256 suffix, fail-closed duplicate detection) and a byte-stable checked-in
collision report. Verdict: the two-phase Codex delegation (audit-then-implement
against a frozen contract) produced zero contract deviations and 12/12 green
offline tests.

## Tooling experience

- **Worked:** The P0-audit-first workflow — a single xhigh Codex run produced a
  240-citation frozen contract (tool inventory, naming algorithm, report schema,
  11-item test plan) that the P1 implementation run executed without a single
  judgment call. `bun run beep create-package gov-legal-mcp --family drivers`
  scaffolded wiring and identity registration cleanly. The mcp-kit surface
  (`gatedLayer`/`composeGatedLayers`/`sanitizedToolkit`/`annotateFourHints`)
  consumed exactly as shipped.
- **Didn't:** yeet prepare linted the user's untracked parallel work (see finding);
  the OSV lane failed transiently and smeared 129 blocking issues.
- **Frustrating:** verdict.json step attribution — the first failure surfaced as
  "failed in dual-arity" when the real failure was Biome inside lint:fix.
- **Wished existed:** a first-class "new package" yeet mode that pre-announces the
  governance gates a fresh package will hit.

## Implementation improvement opportunities

- The frozen audit should encode repo lint policy, not just external contracts;
  schema-shape choices (S.Struct vs S.Class) are law-bound in this repo.
- Codex sandbox could not run plain `bun install` (`.git/hooks` read-only for
  Lefthook); the orchestrator reran it outside the sandbox. Worth noting in the
  codex delegation memory for future package-creating runs.

## Goal & prompt critique

- `GOAL.md` was accurate and tight; the workflow ordering (naming first, gates
  second, server third) matched how the work actually decomposed. One improvement:
  the acceptance list could name the repo-wide pre-push gates (changeset, fallow
  boundaries, schema-first) so P2 plans include them from the start instead of
  discovering them in the first full verify.

## TODOs worth codifying

- New-package closeout checklist (see frontmatter todos).
- lint:fix:changed tracked-files scoping.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Freeze contracts at P0 and forbid P1 judgment calls — the
  audit-then-implement split across two Codex runs produced zero deviations and
  made review trivial; every P2 failure was a repo gate, not a design defect.
- **MEDIUM — Best practice:** Attribute before repairing — all three verify
  failures had different owners (user's parallel work, transient scanner, real
  introduced lint debt); only one deserved a code change.
- **LOW — Consideration:** For no-argument MCP tools, an annotated empty S.Class
  is the compliant boundary schema; reach for it directly instead of S.Struct({}).
