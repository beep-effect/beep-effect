# Reflection — skill-contract-kernel (2026-08-25, claude)

## Summary

`@beep/skill-contract` shipped in three PRs — the first vertical slice (#791), the kernel widening (#792: `SkillContract` root, applicability, evidence ladder, recovery and failure receipts, `GateSummary`, opaque completion), and the full `qa-inventory/v1` judge retrofit (#813) — with the SKILL.md projection and its re-extraction gate landing in the final PR alongside this closeout. Every acceptance criterion in `SPEC.md` is proven by tests rather than asserted: judge parity (82→85 Qa tests), completion reachability through `evaluateSkillCompletion`, completion-unrepresentability, 100% package coverage, and byte-equal re-render plus frontmatter decode equality for the committed artifact. Verdict: goal met; the expensive part was not the kernel but the proof loop around it.

## Tooling experience

- **Worked:** the yeet path end to end (`repair` → `publish --pr` → `monitor` → `reply` → `merge`/`sweep`); `verdict.json` and the lane collector made every red attributable; the schema-first lint, effect-imports law, tsconfig-sync, and jsdoc ratchet each caught real drift at the generator instead of in review; `S.toArbitrary` + `fcRuns` made the round-trip property tests almost free; Codex (gpt-5.6-sol xhigh) in an isolated worktree produced all three implementation slices with the orchestrator owning git and proof.
- **Didn't:** the TS2589 flake quarantine's full-lane rerun under peer-session load; the hosted Coverage Regression job log (unreadable through `gh`); `docgen:local`, which refuses local mode as soon as `bun.lock` moves; Vitest fork workers inside the Codex sandbox.
- **Frustrating:** every LSP-diagnostic fix in a test file (`preferTypedSchemaDecoder`, `strictEffectProvide`, `unnecessaryTypeofType`) surfaces only from the repo-wide `test-tsgo` lane after the 25 min proof has already been spent; the coverage ratchet's new-file rule names a percentage but not a line; `git worktree remove --force` / `git branch -D` are policy-denied, so a superseded Codex worktree has to be left for the operator.
- **Wished existed:** a load-aware yeet pre-flight; a package-scoped `test-tsgo`; a `yeet reply` that can post before the push and fill the sha in afterwards; a Codex sandbox profile that already knows the writable temp dir, the thread pool, and the offline lockfile update.

## Implementation improvement opportunities

- The gate registry is now ordered by executable dependency (decode → round → leaves → aggregate) and every gate is always-applicable; a future consumer with a genuinely conditional blocker needs the live applicability verifier the kernel's `conditional-gate-applicability-unverified` invariant is waiting for.
- `QaJudgeContract.evidenceSubject` binds to `sha256(<id>@<version>)` with the digest pinned and re-derived in the parity suite; once the SKILL.md artifact is the persisted contract, the subject should bind to the artifact digest instead (the digest seam the SPEC reserved).
- `verifySkillArtifact` keeps one `istanbul ignore next` on the unreachable render-failure branch; a schema-derived contract cannot make `@beep/md` fail, but a future `RenderError` fixture would let the branch be covered instead of ignored.
- `evaluateSkillCompletion` is exercised from the consumer suite with a hand-built gate summary; a `GateSummary` builder that folds a list of gate verdicts into the summary would remove that boilerplate from every consumer.

## Goal & prompt critique

- `GOAL.md` should name the two review-surfaced laws up front: registry order is observable and must match executable order; retrofitted gates are always-applicable unless a live applicability verifier ships. Both would have been designed in rather than reviewed in.
- The Codex briefs should require that every deliverable lands inside the worktree (`.beep/`) or the packet, and that the exact sandbox verification commands (`--pool=threads --maxWorkers=1`, `BUN_TMPDIR`) are listed instead of rediscovered per run.
- `SPEC.md`'s verification matrix lists `bun run beep yeet verify`; it should also list the hosted heavy lanes (Coverage Regression, Docgen) that the local proof does not replay, so attribution starts from the right surface.

## TODOs worth codifying

- Scoped `quality jsdoc-quality` / `quality test-tsgo` (changed packages or files).
- Sandbox-aware Vitest pool selection for Codex runs.
- Coverage ratchet: uncovered-unit locations for new-file regressions; heavy-runner logs through `gh`.
- Flake quarantine reruns at `--concurrency=1`; yeet load-aware pre-flight.
- Packet law text for registry order and gate applicability.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Prove completion reachability through the kernel evaluator in every consumer's parity suite — a contract that type-checks and passes its own gates can still be uncompletable by construction, and only the end-to-end `evaluateSkillCompletion` test shows it.
- **HIGH — Critical:** Attribute a red before rerunning: no-location TS2589 under load, a coverage new-file rule, and a genuine LSP diagnostic each have a different, cheap disproof (`--concurrency=1` build, `lcov.info` BRDA/DA rows, the package `check`), and only one of them is fixed by code.
- **MEDIUM — Best practice:** Keep gate reasons flow-neutral and carry decoder issues in the denied detail; adapters own operator wording. It keeps gates reusable across flows and keeps error causes intact.
- **MEDIUM — Best practice:** Snapshot a Codex worktree to a patch (with `git add -N` for new files) the moment the run ends, and keep the report next to it; the session scratchpad is disposable.
- **LOW — Consideration:** Render identifiers and URLs in projected Markdown as code spans; `@beep/md` escapes `-`/`.` in plain text and the artifact is read by agents as much as by people.
