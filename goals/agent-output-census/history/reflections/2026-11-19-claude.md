# Reflection — agent-output-census (2026-11-19, claude)

## Summary

The goal turned the 2026-11-18 transcript audit into a repeatable command.
`bun run beep ai-metrics census` reads a window of local Claude Code and Codex transcripts in about
a minute and prints the audit's tables, or the encoded report, from a schema that cannot hold free
text. The reproduction run is the first tracked baseline. It shipped as one pull request.

## Tooling experience

- **Worked:** The surviving scripts as the method reference. A scratch comparison script that
  printed aggregates only, run after every rule change, turned attribution into a loop of minutes.
  Running the old and new code against the same corpus state proved a refactor changed nothing.
- **Didn't:** One foreground implementer with no checkpoints. package-verify as the handoff bar,
  since five law lints sit outside it. The effect-vitest inventory refresh, which rewrites rows
  the change did not touch.

## What the reproduction showed

The audit's pipe-habit shares were low by 3 to 28 points, because its capture cut each command at
600 characters. The census reads the whole command, so its first run is the corrected baseline:
92.3% of verification runs are piped through a filter, 0.148 log digs follow each run, and a
verdict costs 1.24 turns. Goals that move these rows compare census run with census run.

The corpus is live. Six Codex session files left the sessions directory within ninety minutes of
the baseline run, and the Codex totals moved with them. A baseline file records the run that was
made; it is not a value a later run on the same window will reproduce.

## For the next goal

`gate-run-history`, `gate-report-rollout` and `ci-gate-reports` can now cite census rows. Each
should record a census run before it starts and after it lands, with the same window length.
