# Reflection — lint-advisory-hardening (2026-07-14, codex)

## Summary

The initiative shipped `beep lint policy`, a dedicated CI policy lane, hardened
false-positive-prone checkers, promotion of the selected advisory categories to
blocking policy, and a zeroed inventory. Its bookkeeping closure rides the
portfolio-consolidation PR, whose own verify lane supplies the final P2 evidence.

## Tooling experience

- **Worked:** A dedicated unscoped policy command and CI lane made the enforcement
  surface explicit, while the inventory gave promotion a measurable zero baseline.
- **Didn't:** Packet phase state did not follow the shipped implementation, leaving
  the manifest and README stale after the original delivery.
- **Frustrating:** The implementation was complete but portfolio views still
  presented it as active work because closure metadata had not been reconciled.
- **Wished existed:** An automatic closeout check that compares completed task and
  proof artifacts with manifest phase statuses before a packet can leave its PR.

## Implementation improvement opportunities

- Keep the policy lane unscoped so affected-file optimization cannot bypass
  repository-wide advisory enforcement.
- Preserve checker-specific regression tests whenever false-positive handling is
  changed; a zero inventory is only useful while the detectors remain precise.

## Goal & prompt critique

The staged order was sound: harden false positives, clear the measured backlog,
then promote selected advisories. Future prompts should add one explicit final
step: reconcile the packet manifest, README, PLAN, evidence, and reflection in
the shipping PR rather than leaving that bookkeeping to a later portfolio pass.

## TODOs worth codifying

- Add a closeout consistency check between manifest phases, task completion, and
  required reflection presence.
- Treat new advisory families as measured ratchets: reporting first, hardening and
  remediation second, blocking policy only after the baseline is controlled.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Keep repo-wide lint policy on a dedicated unscoped lane —
  affected-scope optimization must not turn quality policy into a partial check.
- **MEDIUM — Best practice:** Promote advisories only after false-positive
  hardening and inventory cleanup — enforcement is credible when its baseline is
  deliberate and near zero.
- **LOW — Consideration:** Automate packet-state reconciliation — stale metadata
  does not break code, but it distorts portfolio planning and closeout readiness.
