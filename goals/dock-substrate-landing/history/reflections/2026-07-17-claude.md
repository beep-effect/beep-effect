# Reflection — dock-substrate-landing (2026-07-17, claude)

## Summary

Graduated the scratchpad dock system into `@beep/dock` (PR #416) and
`@beep/dock-react` (PR #421), landed the professional-desktop dock shell with
persistent layout (PR #426), and drove a six-round browser QA loop to zero
required findings. All three PRs merged with 5/5 review scores, zero
unresolved threads, and full check suites; the packet closes complete.

## Tooling experience

- **Worked:** codex-companion background lanes for token-heavy builds and
  vision QA (gpt-5.6-sol judged 90+ screenshots across six rounds and its
  inventories were consistently evidence-precise); yeet publish/closeout as
  the merge-readiness spine; the playwright capture harness; Monitor-driven
  waiting; the kernel's own quality gates (fallow, dual-arity, knip) which
  caught real decomposition debt every time.
- **Didn't:** codex's browser backends were dead all session until the root
  cause surfaced — a desktop-app update had left `extension-host-config.json`
  missing beside the native-messaging host binary, and a stale config-less
  host process kept the bridge broken even after repair until killed. jsdom
  hid both pointer-capture click-swallow bugs. `Atom.debounce` is broken
  upstream.
- **Frustrating:** yeet's publish flow refuses amended-but-unstaged retries
  (soft-reset-and-republish is the reliable path); repair hints and check
  names misattributed failures more than once — reading the actual job logs
  remained mandatory; long background commands kept being killed by the 10
  minute cap until Monitor became the default waiting primitive.
- **Wished existed:** a first-class "drive the app and screenshot per
  scenario" harness in-repo; a codex flag to route browser work to the
  Chrome extension backend without magic prompt wording.

## Implementation improvement opportunities

- StrictMode-safe mounting for the ontology graph stack (upstream MUI X
  invariant currently absorbed by the surface boundaries).
- The estimated title-minima (7px/char) could learn real glyph widths from
  the first successful capture instead of a constant.
- Float cascade wraps at six offsets; a rebase step against the viewport
  would keep deep stacks on-screen.

## Goal & prompt critique

The grill-locked decisions held up end to end — none needed reopening. The
SPEC would improve with (a) per-acceptance evidence plans, and (b) an explicit
"live-browser pass required" gate for any milestone touching pointer
interactions; both would have converted discovered-in-QA defects into
planned work.

## TODOs worth codifying

- Browser QA loop as a reusable skill (capture manifest + vision inventory +
  fixer rounds + verification exit).
- Pointer-capture-with-buttons lint for gesture surfaces.
- Upstream MUI X issue tracking link in residuals.

## Lessons (confidence-tiered)

- **HIGH — Critical:** jsdom green is not click-works green — native pointer
  capture retargets releases and swallows button clicks invisibly to stubbed
  capture; only a live browser shows it. Two instances shipped in one package
  before the loop caught them.
- **HIGH — Critical:** run the exact CI command locally before calling a lane
  green; node-vitest vs bun-vitest differ in unhandled-error accounting.
- **MEDIUM — Best practice:** attribution before rerun paid off every time —
  of six red-check episodes, three were real introduced defects, two were the
  known flaky lanes, one was a stale-base refusal; blind reruns would have
  masked the real three.
- **MEDIUM — Best practice:** vision QA on captured screenshots is a strong
  stand-in when hands-on browser control is unavailable, and the two agree:
  the hands-on round confirmed every vision-round verdict it re-tested.
- **LOW — Consideration:** keep-alive claims need identity-based tests
  (node/component identity), not presence assertions — presence survives a
  remount that destroys all state.
