# Reflection — practice-document-identification (2026-10-07, claude)

## Summary

The identification passes moved from private python scripts into repository tooling (a `DocumentIdentification` slice in `@beep/law-practice` use-cases and server, and the `apps/practice-identify` command) and reproduced the pass-3 held-out numbers on the same salted split: identified 448 of 449, identified-content 51 of 51, candidate 194 of 194. PR #1536 merged as 5329c31d58 after three review rounds and a coverage hold that needed a baseline-only PR (#1540, 9c909f339a). The 844 identified and 616 organise moves were applied on the attorney's Box tree from the pass-3 plan with a full undo journal, and the second questionnaire shrank from 89 questions to 20 on a loopback preview.

## Tooling experience

- **Worked:** `yeet publish` → draft PR → `yeet ready` → readiness monitor and `yeet reply` with drafted thread bodies kept the review loop honest; the salted `--split-salt` flag made the private evaluation reproducible to the document; `beep quality package-verify` caught the typed-codec and pipeable-form rules before CI.
- **Didn't:** two commits lost their staged code to the pre-commit formatter and `yeet publish` refused the dirty tree without naming paths; `bun run beep lint effect-vitest --write` regenerates the whole inventory; the coverage ratchet accepted the file rows and withheld the totals row in the same run.
- **Frustrating:** every review round that touched a test file shifted inventory line numbers and reopened the effect-vitest gate; the GraphQL rate limit blocked `yeet reply` for a window during round 2.
- **Wished existed:** a `yeet publish --dry` that prints the exact gate verdicts without committing; a per-file inventory refresh; a ratchet message that names the two-PR pattern up front.

## Implementation improvement opportunities

- Contact identity as a ladder (D17) with one-field-per-card tests, now in place; a property test over `RawContactCard` arbitraries would pin it further.
- Direct unit tests for `Identification.pairs.ts` (index, links, register skip, organisation match) and RDAP branches, added in this follow-up; the port shapes remain covered only through layers and could take a shape round-trip test.
- The resolver's `resolve` is still 200 lines; the tiering, aliasing and token-vote helpers are extracted, the evidence collection could follow.

## Goal & prompt critique

- Write the measured rule into SPEC.md before porting: the weights, the score thresholds, the margin rule and the split hash. The first port used unweighted votes and did not match pass 3 until D12 pinned the rule.
- State the private input contract in GOAL.md: JSON carries every optional field as explicit `null`, outputs are never overwritten, every stage takes explicit paths. D14 and the `wx` write flag came out of failures that the launcher could have prevented.
- The goal could name the two-PR coverage pattern for any new package so the closeout plan budgets for it.

## Lessons (confidence-tiered)

- **HIGH — Critical:** compare `git rev-parse origin/<branch>` with `HEAD` and `git status` before every publish — a formatter hook can leave the code you meant to commit in the working tree, and the gates then judge the wrong tree.
- **HIGH — Critical:** measure on the attorney's own filing with a fixed, salted hold-out and port the rule as a written contract; a number fitted on machine attributions (the earlier 92%) is not evidence.
- **MEDIUM — Best practice:** when a review finding is one instance of a class (identity collisions), fix the class and add the one-field-per-case test in the same push; the next two rounds otherwise find the siblings.
- **MEDIUM — Best practice:** record hosted-verbatim coverage rows only after attributing them, and expect the package-total lowering to need its own baseline-only PR.
- **LOW — Consideration:** run every verification in the background through `beep-heavy` and poll the log; the longest single wait in this goal was the local proof, not CI.
