# Reflection — hold-ledger (2026-11-01, claude)

## Summary

The repo's dependency holds are now records in `hold-ledger/claims.jsonl`:
- each is a falsifiable claim on the epistemics envelope with a probe and an exit;
- the syncpack held list is generated from them;
- `holds lint` keeps config and ledger in step in the cheap gate;
- `deps:update` re-checks holds and retires the ones whose probes flipped.

Three PRs: #2404 (probe), #2450 (inventory and lint), #2453 (update, why, runbook). The first real result was useful: statelyai's control still reproduces the npm 404 and the candidate has passed twice, so it is ready to unpin, while the jsdom hold's control no longer reproduces and the hold is stale.

## Tooling experience

- **Worked:** cache-baseline reviews against the precedent docs; `lint policy-fingerprint --write` for the new seal; `yeet reply` for threads; MemoryFileSystem plus a fake spawner for probe tests.
- **Didn't:** `yeet publish --push-only` assumes the branch exists remotely and a reusable proof exists; the documented `gh pr create` fallback was needed twice.
- **Frustrating:** generated projections (identity profile, schema and span catalogs, cache baseline) each surfaced one at a time as separate reds.
- **Wished existed:** one command that regenerates every derived projection a change touches.

## Implementation improvement opportunities

- Admit holds through a `beep holds admit` command that writes a schema-checked row, instead of hand-encoding JSON lines.
- Let `holds update` open the reviewed change for flipped holds with override or patch anchors.

## Goal & prompt critique

- The SPEC listed `admit` among the commands but no acceptance criterion required it; either make it a criterion or drop it from Target Surfaces.

## TODOs worth codifying

- The root-lane registration checklist above.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Run a negative control before trusting a projection — the empty-list control exposed syncpack's match-all behaviour.
- **MEDIUM — Best practice:** Keep auto-retirement conservative: retire only when every checkable anchor is gone, and report partial loss for a person to decide.
- **LOW — Consideration:** Version ids in an append-only ledger should be chosen from the ids already present, not assumed consecutive.
