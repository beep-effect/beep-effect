## Gate

The C2 runtime applies six declarative rho-df rules (rdfs2, 3, 5, 7, 9,
11) and one explicit SKOS `broaderTransitive` rule with a naive fixpoint.
Every derived statement is content-addressed, and every `InferenceEvent`
retains its rule, engine identity, premise statement references, conclusion,
and explanation DAG. Validation checks each event against its own rule and
the complete closure; it never compares EYE's choice of premise set.

The required R2 selection contained all 25 W1 papers and all nine F1
fixtures. Live and cache-only replay produced byte-identical C2 reports. The archived
replay is a cache-only rerun executed on 2026-09-02 (21:40 CDT, `startedAt`
2026-09-03T02:40Z) after the ratified live run, so its sidecar postdates the live one; the earlier replay artifact had
preceded the live run and was replaced.

## EYE oracle

`eyereasoner` 21.1.18 embeds EYE 11.24.5 and is a dev-only dependency. The
committed `G-entailment/rdfs` suite contains one isolated case and normalized
EYE proof digest for every C2 rule. Each proof runs under `--restricted` in a
separate process with a 30-second parent deadline, a 65,536-byte input cap,
and a 1,048,576-byte output cap. All seven conclusion sets match runtime
closure, all proof outputs retain `r:Inference`, `r:evidence`, and `r:rule`,
and every runtime event validates independently.

EYE never appears in the runtime Layer. It only generates and checks the
committed oracle fixture.

## Crash identity

The crash probe uses the real file-backed PGlite Ledger Layer. Its regression
starts from an empty isolated ledger and records that empty projection digest.
The child schema-decodes a non-empty extraction fixture from a bounded file,
commits the batch transaction, flushes `projection-state-committed`, and sends
itself `SIGKILL` before any projection rebuild. Two fresh processes reopen the
same ledger and independently rebuild RDF. Their SHA-256 digests are equal and
differ from the empty precondition digest. The bounded log is archived at
[`history/c2/crash-identity.log`](./c2/crash-identity.log).

The full R2 report independently digests the complete in-memory C1 projection
and schema-encodes every committed extraction outcome and provenance event to
an isolated crash input file. The production child reads that file, commits
every projection-relevant batch transaction, and is killed after
`projection-state-committed` but before projection. A fresh child rebuilds
solely from the persisted crash ledger. The report retains equal independently
expected and after-restart projection digests,
`a56ba96c539095c3dcccfa883b736aac4ddceaf5caf7c03fcb29420476b7db1b`,
and closure digest
`93991e0c453d6ae0d850fcc86d284f886d99cc16e90d48eef99921a3de11cf94`.
