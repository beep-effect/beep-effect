# Merge Queue Lab Findings

Date observed: 2026-11-10 (UTC). Venue: branch `queue-lab` of
`beep-effect/beep-effect`, lab ruleset 26917133 (`merge_queue`: squash, build
concurrency 1, group size 1, no wait, `ALLGREEN`, a ten-minute check timeout;
required context `queue-lab-gate` from GitHub Actions). Ruleset 10240248 on
`main` was not changed.

Every row names the evidence file under [`evidence/`](./evidence/) that
backs it. Pull-request numbers are the synthetic lab entries (branches named
`queue-lab-<slug>`). Identities: **App** is the `beep-fleet-orchestrator`
installation token; **PAT** is the fleet fine-grained token
`tom-pc-1-wsl-beep-development` (login `kriegcloud`); **user** is the
operator's `gh` login (an org admin). The driver is the packet's
`ops/queue-lab.sh`.

## Verdict

**Go.** The verdict rule in `SPEC.md` holds on all three counts:

- Every identity the fleet merges with can enqueue (10c): the App, the
  fine-grained PAT and the operator login. The App can also jump and can
  enqueue workflow-touching pull requests.
- The lab ran in this repository (10b); no fallback was needed.
- No finding contradicts a ruling in the exploration's `DECISIONS.md`. The
  landed commit is the commit the group proved (6e). The unblocker route
  (pause, jump, resume) works (2a, 5d), with two adjustments carried below.

## Carried to the gated candidates

These do not change the verdict; they are constraints the later goals inherit.

- `yeet-queue-states`: enqueue as the App, never with `GITHUB_TOKEN` (10c);
  never enable auto-merge from `merge-gate` (9a); ejection reasons are
  `failed_checks`, `checks_timed_out`, `manual` (9d); cancel the runs of a
  dequeued or rebuilt group (4i, 5d); a flake is a re-enqueue, not a rerun
  (4d); queue state is GraphQL-only (9c).
- `yeet-queue-states` and `merge-queue-activation`: squash-commitlint predicts
  the repository default composition, which differs for one and for several
  commits (6c); `mergeStateStatus` never reports "queued" (R1); rule suites
  carry the enqueuer and the enqueue time (R2).
- `merge-queue-activation`: pausing needs a ruleset write, which the App
  cannot make; pause and resume as a fleet PAT, jump as the App, and allow a
  few minutes for resume (2a). A bypass merge works only for an unqueued pull
  request (5c) and restarts the building group (5e).
- `merge-group-parity`: no `if:` on a job that reports a required context
  (4e); no `concurrency.group` shared across merge groups (8d); callees of a
  reusable workflow need no trigger and report `caller / callee` (8c); group
  runs have secrets and a write token (7f); `merge_group` takes no path filter
  (4f); the push run still fires after each queue merge and needs a guard to
  shrink (6f).
- `queue-parameters`: the lab's toy group runs took under a minute, so the
  timeout for `main` comes from the parity goal's real p90, not from here.
