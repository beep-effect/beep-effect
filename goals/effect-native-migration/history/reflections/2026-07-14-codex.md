# Reflection — effect-native-migration (2026-07-14, codex)

## Summary

The retained deliverable is the completed historical migration run recorded by
five phases, seven symbol inventories, and 75 done package entries. Closeout
revealed a bookkeeping lag and preserved the crucial distinction between a
finished run and a claim that today's reorganized tree was freshly audited.

## Tooling experience

- **Worked:** `ops/progress.json` provided a resumable, countable execution
  ledger, while the July path check mapped that history onto the current tree.
- **Didn't:** Lifecycle status failed to follow the already-complete ledger.
- **Frustrating:** Twenty-five removed package paths could be mistaken for lost
  work if historical inventory and current topology were conflated.
- **Wished existed:** A closeout check that flags all-done progress ledgers whose
  initiative lifecycle is still active.

## Implementation improvement opportunities

- Treat the inventories and waiver markers as historical evidence, including
  entries for packages later removed from the repo.
- Require live source and barrel discovery for any future migration instead of
  replaying stale symbol or usage inventories.

## Goal & prompt critique

The goal was precise about category scope and hard deferrals, but its completion
contract should have required lifecycle reconciliation once all package entries
reached done. It should also label the final audit mode as historical or live so
an existence check cannot be read as new conformance proof.

## TODOs worth codifying

- Add an all-done-ledger advisory for active goal packets.
- Preserve removed-path counts in historical migration closeouts.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Do not turn historical completion into current audit
  claims — the July check proved path existence only.
- **MEDIUM — Best practice:** Let the execution ledger drive closeout — all five
  phases and 75 entries were already terminal.
- **LOW — Consideration:** Expand native-helper scope through new packets — the
  three deferred categories need their own modeling and acceptance rules.
