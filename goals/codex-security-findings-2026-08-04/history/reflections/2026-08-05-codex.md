# Reflection — codex-security-findings-2026-08-04 (2026-08-05, codex)

## Summary

The packet closed all 27 captured findings end to end: shared-root remediation,
full Yeet proof, green hosted checks, six resolved review threads, merged PR
#559, exact-ID dashboard closure, and a zero-open reconciliation. The packet is
complete and retained with both machine-readable and human closeout evidence.

## Tooling experience

- **Worked:** Yeet kept local and hosted proof aligned, while signed-in Chrome
  control allowed closure without reading cookies or exposing authentication
  values. The title guard made the captured ID list safe to execute.
- **Didn't:** The CSV row order ceased matching CSF numbering for the last seven
  items, and the Codex SPA intermittently returned a transient failed-fetch
  application error during read-only verification.
- **Frustrating:** Repeated page navigation dominated the closure work even
  after remediation and PR proof were complete.
- **Wished existed:** A beep-cli command that safely acquires an authenticated
  export, bootstraps a sanitized goal packet, and emits an immutable closure
  allowlist ready for later execution.

## Implementation improvement opportunities

- Keep the CSV's finding URL, ID, and title bound in a decoded schema rather
  than deriving identity from display order.
- Make closure resumable and idempotent: skip already-closed IDs, stop on title
  mismatch, and audit final reason plus open count.
- Retain hosted proof identifiers in packet closeout so CI and review claims are
  independently checkable after merge.

## Goal & prompt critique

Add this execution rule to future packets: "Before each closure, verify the
visible finding title matches the captured ID-to-title pair. Afterward, reopen
every exact ID read-only and require the intended reason plus zero packet-open
findings."

## TODOs worth codifying

- Execute the retained Fable 5 research, design, plan, and orchestration handoff
  for automated Codex security capture.
- Add a reusable closure ledger format that records attempted, closed, skipped,
  mismatched, and verified IDs without raw finding bodies.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Treat finding identity as an ID-to-title pair — display
  order can drift, while a mismatch guard prevents closing the wrong item.
- **HIGH — Critical:** A security packet is not closed at merge — verify the
  external scanner state and exact dismissal reason after the code lands.
- **MEDIUM — Best practice:** Use bounded retries only for read-only verification
  after transient SPA errors; never blindly repeat a mutation submission.
- **LOW — Consideration:** A browser-backed capture command is viable, but its
  secret boundary must be designed before choosing cookie export mechanics.
