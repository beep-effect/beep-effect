# CSF-022: Claims batch can falsely succeed with zero extractions

- Severity: Informational
- Codex ID: `e00ccb2a1044819196ebb84bafa91c0f`
- Source commit: `2c3e146dfb1dc03f07a31b1546b6c9d717252bba`
- Owner: practice KG claims batch outcome
- Status: remediated; local Yeet proof green

## Public Summary

Per-file extraction failures are collected, but the zero-success guard queries
the persistent global claim count instead of the current batch. A previously
populated database can make an all-failed batch report success.

## Current-HEAD Validation

Confirmed reachable at the current branch head before remediation; the exact affected surface and source commit are recorded above.

## Remediation

Based zero-extraction failure on the current batch outcomes instead of pre-existing global claim rows.

- `packages/law-practice/server/src/PracticeKg.claims.ts`
- `packages/law-practice/server/test/PracticeKg.projections.test.ts`
