# CSF-012: Tika Server engine trusts arbitrary file locators

- Severity: Medium
- Codex ID: `16f4c5222e84819197116842375028a9`
- Source commit: `a8a2ea56fd338e7d34ffa18285815b0fd05a52df`
- Owner: Tika Server driver file boundary
- Status: remediated; local Yeet proof green

## Public Summary

The Tika Server engine reads caller-provided file locators without an approved
root, canonical containment, regular-file validation, or a pre-read byte cap,
then sends the bytes to the configured endpoint.

## Current-HEAD Validation

Confirmed reachable at the current branch head before remediation; the exact affected surface and source commit are recorded above.

## Remediation

Removed file-locator reads from Tika Server; extraction now requires caller-supplied bytes or text.

Changed files:

- `packages/drivers/tika/src/Tika.server.ts`
