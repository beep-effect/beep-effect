# CSF-009: Gitleaks allowlist can hide 64-hex API tokens

- Severity: Medium
- Codex ID: `5ea0535e568c8191a8d1919b5fd90a24`
- Source commit: `44b0c974556ae08936a41e77f914a9a6cd1ec893`
- Owner: gitleaks configuration
- Status: remediated; local Yeet proof green

## Public Summary

A broad history-path allowlist suppresses any lowercase 64-hex value for the
generic API-key rule. That shape can be a real 256-bit credential, so the
exception must identify exact known evidence rather than a token class.

## Current-HEAD Validation

Confirmed reachable at the current branch head before remediation; the exact affected surface and source commit are recorded above.

## Remediation

Removed the broad generic-api-key allowlist for bare 64-hex strings in goal history.

Changed files:

- `.gitleaks.toml`

- Targeted package typechecks passed.
