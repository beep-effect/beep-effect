# Reflection: fleet-root-registry (2026-11-06, claude)

## Summary

The packet shipped as one PR. It adds a per-repository discovery-roots list
(`BEEP_FLEET_ROOTS`, then `roots.json`, else the derived root), read by the fleet
mirror, by residue reap through `FleetMirrorService.listCheckouts`, and by Yeet
economics. It also adds a schema-first registry overlay beside the session
ledger and the `fleet --join`, `describe` and `register` views, plus a runbook.

The `beep-effect0-worktrees` undercount was an origin-spelling mismatch. The
fleet compared `https://github.com/beep-effect/beep-effect.git` with
`git@github.com:beep-effect/beep-effect.git` as different origins, which
dropped `beep-effect0` and all 33 of its lanes. That is fixed in #2852. The
single attributed lane under that directory belongs to `beep-effect2`.

## Tooling experience

- **Worked:** the fixture fleet with fixed commit dates and `TestClock` gave a
  reproducible pre-change snapshot. Back-to-back `fleet --json | jq -S
  'del(.scannedAt)'` from the primary clone and the lane made workstation parity
  attributable row by row. `beep goals decisions add` and `decisions write` kept
  the SPEC block in sync without hand edits.
- **Didn't:** the Biome pre-commit hook rewrote the golden JSON. `yeet publish`
  stopped on an inherited red after creating the commit.
- **Frustrating:** the checker's `missingPipeableSignature` rule forced
  multi-argument exports into options objects. That was fine in the end, but it
  costs a pass per helper.
- **Wished existed:** a scan option deriving one checkout, so `describe` would
  not need the full mirror; a shared remote-URL canonicalizer.

## Implementation improvement opportunities

- `describe` and `register` run a full scan or listing; a narrowed derivation
  would make them fast.
- Economics falls back to the derived root with a warning on a bad
  `roots.json`, while the mirror fails. Revisit once the review-lane source can
  carry an error.
- Adoption never updates an existing row's `owningSeat`. If a lane is
  re-attached to another seat, only `register --owning-seat` corrects it.

## Goal & prompt critique

- GOAL.md should say "reproduce the undercount first" ahead of the schema
  work. The hypothesis was stated confidently and was wrong.
- SPEC lists ResidueReap.ts discovery as a target surface. Residue reap already
  delegates to `FleetMirrorService.listCheckouts`, so it needed no edit. The
  SPEC could have said that and saved an inspection pass.
- The byte-identity criterion should name the volatile fields up front (the
  scratch prefix and the `/proc` census) the way the workstation row names
  `scannedAt`.

## TODOs worth codifying

- GritQL rule: no point-free `Console.log` in `Effect.forEach`.
- Golden snapshots are kept out of the formatter.
- One remote canonicalizer module.

## Lessons (confidence-tiered)

- **HIGH (critical):** Reproduce a named symptom with the cheapest command
  before trusting a packet's hypothesis. Here, `git worktree list` succeeded and
  the origin spellings differed.
- **MEDIUM (best practice):** Capture a pre-change golden in its own commit
  before touching the code, and store it where no formatter rewrites it.
- **LOW (consideration):** Smoke-run every new CLI view on the real workstation.
  The stray-index bug in shipped plain output only showed on real data.
