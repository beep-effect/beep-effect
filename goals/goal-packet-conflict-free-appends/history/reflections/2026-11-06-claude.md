# Reflection — goal-packet-conflict-free-appends (2026-11-06, claude)

## Summary

The goal shipped in #2702 (merged 2026-11-06T00:10Z, merge 072748d024). Decisions are now
lane-owned `decisions/*.md` files. `beep goals decisions write` renders them into
marker-delimited blocks in SPEC.md and PLAN.md, and `goals doctor` blocks on
`decision-log-drift` / `decision-file-invalid`. The goal worked. Within a day 13 packets had
47 decision files across 13 commits on main, and no open PR is CONFLICTING. The 2026-11-04
incident, where eleven sibling PRs conflicted on SPEC tails, has not recurred. Closeout was the
weak part: the implementation PR merged with no proposal, so this docs-only re-final PR exists
only to carry it.

## Tooling experience

- **Worked:** `bun run beep goals decisions check` (`packets=272 decisions=47 invalid=0
  drift=0`), `goals doctor` (`blocking_new=0`), and `test/goals-decisions.test.ts` (6/6) all
  re-verified on current main without changes. The AGENTS.md Autonomy rule now points agents at
  `goals decisions add`, which explains why adoption was fast.
- **Didn't:** none of the tools flag a packet whose final PR has merged while its manifest
  still says every phase is `pending`.
- **Frustrating:** the closeout route (verify, publish verdict, until-ready, refresh, adoption)
  is long, and the required order is learned from memory notes, not from the tool.
- **Wished existed:** a `goals closeout plan <slug>` command that prints the next missing step
  from the manifest and PR state.

## Implementation improvement opportunities

- Report decision counts per slug in `decisions check` so adoption is measurable.
- The PLAN.md Checkpoints block was used here once ("Implementation landed"). Watch whether
  lanes actually use `kind: checkpoint` or keep editing PLAN.md prose.

## Goal & prompt critique

- GOAL.md Scope still contains the bootstrap placeholders (`<paths, packages, ...>`). Replace
  them at bootstrap with SPEC Target Surfaces and Non-Goals.
- The launcher's done condition predates #2703 and stops at `completion refresh`. AGENTS.md now
  requires the adoption PR as well, so the packet text should follow the current template.

## TODOs worth codifying

- Doctor advisory: completionGate PR merged but no `proposedCloseout`.
- Bootstrap projects scope into GOAL.md.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Put the proposal in the implementation PR and hold the merge for
  `merge-ready: yes`. A merge that outruns the proposal costs two extra PRs.
- **MEDIUM — Best practice:** Measure a process change by what happens downstream (conflicting
  PR count, adoption count), not only by its own tests passing.
- **LOW — Consideration:** Forward-only migration was right for 265 legacy packets. Revisit
  bulk conversion only if mixed legacy/generated logs confuse readers.
