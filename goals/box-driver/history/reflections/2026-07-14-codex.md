# Reflection — box-driver (2026-07-14, codex)

## Summary

The retained deliverable is the shipped `@beep/box` technical driver: generated
models and JSON operations, hand-written config/error/service/streaming
boundaries, tests, docs, and PR closure. The July reconciliation revealed that
implementation had finished long before the packet bookkeeping admitted it.

## Tooling experience

- **Worked:** The merge identifier, live generated artifact counts, and concrete
  shipped-path inventory made the historical completion claim auditable.
- **Didn't:** Phase metadata did not close alongside the implementation merge,
  so portfolio status understated already-delivered work.
- **Frustrating:** A stale packet can resemble an invitation to regenerate a
  large driver even when the generated and hand-written boundaries are present.
- **Wished existed:** A merge-time check linking completed packet phases to the
  retained implementation SHA and generated-surface summary.

## Implementation improvement opportunities

- Keep pragmatic schema fidelity at driver scope unless repeated driver evidence
  justifies an architecture-wide decision.
- Preserve OAuth2 and JWT as explicit deferrals until the client escape hatch is
  insufficient for a real integration.

## Goal & prompt critique

The goal should have separated implementation completion from optional auth
expansion and required the manifest reconciliation in the merge closeout. That
would have prevented both the stale active appearance and accidental re-scaffold
risk.

## TODOs worth codifying

- Record generator counts and the merge SHA when a generated driver closes.
- Make "do not re-run create-package" part of reconciliation for shipped
  scaffold-based packages.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Close packet bookkeeping with the implementation merge —
  shipped code should not remain operationally active by metadata accident.
- **MEDIUM — Best practice:** Preserve exact generated counts at closeout — they
  distinguish retained evidence from instructions for a new generation run.
- **LOW — Consideration:** Add auth modes from caller pressure — the pre-built
  client Layer already covers deferred SDK authentication paths.
