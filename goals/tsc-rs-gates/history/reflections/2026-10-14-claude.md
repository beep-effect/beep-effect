# Reflection — tsc-rs-gates (2026-10-14, claude)

## Summary

The typecheck and build gates run on tsc-rs 0.6.0. Hosted cache-cold
`Heavy / Check` dropped from 7m39s turbo time (tsgo, 2026-10-13) to 2m15s on the
same runner with identical diagnostics; the eleven upstream 7.1 fixes shipped
first (#1670), the swap shipped as #1675 with the catalog pin held beside
`@effect/tsgo` in syncpack and a policy test that fails a one-sided bump.

## Tooling experience

- **Worked:** the measurement harness (sequential per-project runs plus a full
  `turbo run check` under three compilers) attributed every diagnostic difference
  to upstream 7.1-dev before any code moved; `beep-heavy`, `yeet publish` with
  cheap gates, `yeet reply`, and the stacked-branch flow (swap on the fixes
  branch, main merged in once #1670 landed) all behaved.
- **Didn't:** `beep lint package-scripts --write` did not rewrite existing
  manifests when the defaults changed; `quality:cache-policy` reported only a
  digest mismatch with no subject list until a request was submitted; cross-session
  messages to the orchestrator were held for most of the night (permission-mode
  mismatch), so finals had to be relayed by the operator.
- **Frustrating:** GitHub GraphQL rate limits made `yeet ready` report "no open
  pull request was found" (the read failed, not the PR); a fresh lane without built
  dists reports thousands of TS2305/TS7031 under any compiler, so attribution
  needs `turbo run build --filter='<pkg>^...'` first.
- **Wished existed:** a `cache baseline --subjects-from-audit` form that names the
  changed subjects itself; a knip plugin hook for custom compiler binaries.

## Implementation improvement opportunities

- Point the remaining Effect-compiler lanes (`test-tsgo`, `tsgo-smoke`, docgen's
  example compile) at tsc-rs when ts-rust ports 0.52; keep `--fast` off until the
  test-project CPU cost is re-measured on the 8-vCPU runner.
- Replace the sed-based manifest rewrite with a `package-scripts` migration mode
  that applies a defaults change to package-owned impl scripts.

## Goal & prompt critique

- GOAL.md should say the swap PR stacks on the diagnostics PR until it merges and
  list the expected churn (manifests, knip config, cache baseline, the two script
  parsers, the policy test) so a reviewer sees them as the plan, not as surprises.
- The acceptance criterion "asserts the new version shapes" should name the exact
  assertions (version regex, no `+effect-tsgo` suffix, catalog coupling).

## TODOs worth codifying

- AGENTS.md Touch table: `@effect/tsgo` or `tsc-rs` bump → typescript-toolchain
  runbook (the two move together).
- `beep lint package-scripts`: drift report for impl scripts against defaults.
- yeet skill: cache-baseline re-record recipe for script-word changes.

## Lessons (confidence-tiered)

- **HIGH — Critical:** attribute every diagnostic difference with the stock
  upstream compiler before blaming the port — all eleven tsc-rs "failures" were
  TypeScript 7.1-dev behaviour, reproduced with `typescript@7.1.0-dev.20261008.1`.
- **HIGH — Critical:** a compiler-word change touches every cache-qualification
  subject; submit one reviewed baseline request over the full `Unreviewed:` list
  rather than the three subjects whose basis is their manifest.
- **MEDIUM — Best practice:** keep the Effect compiler for the rule-proof lanes
  and editors while the gates move; the split keeps `tsgo-rules` meaningful and
  made the one inherited red attributable in minutes.
- **LOW — Consideration:** bun blocking the tsc-rs postinstall costs about 22 ms
  per run; `trustedDependencies` is not worth an install script for that.
