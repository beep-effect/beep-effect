# Reflection — ship-velocity (2026-09-02, codex)

## Summary

The final cache repair closed the remaining semantic gap in ship-velocity. The infrastructure
credential had not drifted: every failing checkout pointed at an older credential that predated
the AWS cache, and the provisioning helper had preserved it because it treated any nonblank token
assignment as complete. An explicit replacement mode repaired the fleet without exposing a value.

The frozen six-root sample then separated configuration from behavior. All six roots carried the
canonical reference. Five exact wrappers resolved and returned 200 for a known hosted artifact;
four of those roots observed eight first-touch remote hits and one was authenticated-cold on a
different revision and lockfile. The remaining exact wrapper was skipped because an unrelated
reference in the same env file failed before HTTP; its separately labelled cache-only canary then
returned 200 and restored eight tasks remotely. No repaired root produced a cache authentication
failure.

## Tooling experience

- **Worked:** digest-only comparisons against both control-plane sources disproved the mirror-
  drift hypothesis without rendering a token. The authorization-only artifact GET made 403, 200,
  and cache-miss states independently observable.
- **Worked:** the cold/warm cache probe plus Turbo summary JSON made the C5 denominator concrete.
  Only the first cold lane was counted, so its remote restores were not diluted by the required
  local restoration pass.
- **Didn't:** the original helper's leave-nonblank-alone policy made stale references invisible to
  repeated provisioning. Resolving the reference was evidence of 1Password availability, not
  evidence that the cache would authorize the resolved value.
- **Didn't:** the recovery workflow queued without a heavy runner. Even with a runner, warming
  would have addressed namespace coverage rather than the reader's 403, so it was the wrong first
  repair for an authorization failure.
- **Frustrating:** the fleet JSON report exceeded its own output capture limit, requiring the
  already-documented bounded text path. A zsh read-only special parameter also broke a harmless
  inventory before any probe ran.
- **Wished existed:** one value-suppressed command that joins reference identity, source digest,
  exact-wrapper health, artifact authorization, and first-touch summary classification for every
  frozen root.

## Implementation improvement opportunities

- Keep replacement opt-in. Default idempotence protects intentional alternate configuration, while
  explicit replacement makes credential correction auditable and testable.
- Treat reference comparison as part of rotation. A resolving reference can still point at the
  wrong item, and item timestamps cannot establish value identity.
- Require an authorization-only GET before cache warming or interpreting an all-miss probe. A 403
  is a reader-credential problem; a 200 followed by misses is an authenticated namespace outcome.
- Split cache credential readiness from unrelated whole-env health. The exact wrapper should remain
  the sanctioned whole-environment proof, but subsystem lanes should pass only their required
  references or preflight each reference and name failures without values.

## Goal & prompt critique

The final prompt correctly distinguished reference coverage, authenticated resolution, and
observed remote hits, and it supplied a stop rule tied to the main checkout and explicit cache
authentication failures. That structure prevented a 200-plus-miss root from being mislabeled as
broken, kept the exact-wrapper skip visible, and allowed the separate cache-only hit to be counted
at the correct evidence level.

The packet should have required source-of-truth identity verification when C1 first provisioned
the fleet. The clearer acceptance text would be: compare the intended reference's value-suppressed
digest with the deployed read-token source, then require a known-artifact GET, then measure
first-touch hits. Metadata timestamps may motivate the comparison but never decide the diagnosis.

The liveness instruction could also name `worktree fleet` directly. Its existing 900-second,
positive-evidence rule was the rule used by the prior scan, while the prompt's 14-day Git fallback
describes a materially different population.

## Lessons (confidence-tiered)

- **HIGH — Critical:** a resolving secret reference proves nothing about service authorization;
  compare a value-suppressed digest against the source of truth before hypothesizing drift.
- **HIGH — Critical:** a provisioning helper that preserves every nonblank assignment needs an
  explicit compare-and-replace path, or it will preserve confidently wrong configuration.
- **HIGH — Critical:** authenticate the reader before warming the namespace; runner capacity and
  cache contents cannot repair a rejected credential.
- **MEDIUM — Best practice:** count only each task's first cold-lane touch when measuring remote
  reads, because restoration intentionally turns later observations into local hits.
- **LOW — Consideration:** whole-env wrappers are valuable runtime proofs but can make one
  subsystem's evidence depend on unrelated secret-reference hygiene.
