# Reflection: ship-velocity observation closeout

## Summary

This observation round tested the shipped system under a concentrated day of repository activity.
The sample contained 24 merged pull requests, eight main-push Check runs after the parity repair,
and eight pull requests opened and merged after the original ship-velocity anchor. The operator
accepted that volume as representative enough to replace the planned seven-day duration proxy.
Every outcome gate then in force still applied to that ruling. Operator PR #921 later and
separately superseded A4 by removing the published-PR ownership lease and automatic takeover;
this reflection does not relabel that removal as takeover success.

The exercise found one structural defect that synthetic tests had missed. The weighted scheduler
had capacity for overlapping full proofs, but Yeet still held the older same-origin v3 proof lock.
The first dual-worktree trial therefore queued one healthy proof behind another. The repair makes
the scheduler the current concurrency authority, installs a permanent v4 compatibility marker,
drains same-origin legacy work before migration, and retains a separate exclusive fallback lock
for machines below the scheduler's memory envelope.

The repaired protocol then admitted two independent same-origin full proofs concurrently. Their
admission intervals overlapped for 48 minutes 49.201 seconds; both completed every lane at exit 0,
with pre-push peaks of 17,966,264 and 18,001,708 KiB. Capacity contracted below the admitted token
total during pressure and recovered without a hard-floor event, dead lease, quarantine, or OOM.

## Tooling experience

- Live GitHub queries, the parity ledger, scheduler status, and the admission journal made the
  production claims checkable. The typed Yeet inbox also kept local failures attached to an
  explicit fix or disposition receipt.
- The first live dual trial spent 58 minutes behind valid admission work before revealing that a
  second mutex still made overlap impossible. The delay was legitimate, but a composition test
  should have exposed the contradiction before the fleet trial.
- The first reviewer round found a mixed-version queue deadlock and a filesystem error boundary
  that treated unreadable coordination files as absent. Both bugs survived focused steady-state
  tests because those tests did not model ticket order or non-NotFound read failures.
- Remote-cache configuration could be repaired without reading a secret. That was useful and
  safe. It was not remote-read proof. The 1Password MCP was unavailable and the local `op` CLI was
  signed out, so the probe correctly degraded to local-only caching.
- A single command that joins GitHub runs, inbox receipts, scheduler transitions, cache plans, and
  publish contention would have shortened this closeout and reduced manual reconciliation.
- The durable admission journal preserved both terminal transitions but omitted the coordination
  protocol and did not carry the peak RSS available in either Yeet verdict. The live status,
  journal, and verdicts had to be correlated manually.

## Implementation improvement opportunities

- Run independent subprocesses for current-first and legacy-first ticket order, two current
  clients, old-client fail-closed behavior, and fallback-holder interruption. Same-process fibers
  remain useful for deterministic unit tests, but they do not model process identity or version
  skew.
- Record `coordinationProtocol` in admission journal events. After tickets and leases disappear,
  the current journal requires timestamp correlation with the v4 marker to prove which protocol
  admitted a run.
- Preserve the original scheduler cause when Yeet translates a scheduler error into a command
  error. Also emit a bounded warning if fallback-lock cleanup fails while keeping finalization
  infallible.
- When a coordination primitive is retired, remove its service, ignored state, operational
  instructions, tests, and packet claims together. PR #921 removed the watcher implementation;
  the closeout branch still had to reconcile the historical A4 acceptance text afterward.

## Post-closeout integration addendum

While the final branch was being refreshed, PR #921 merged an explicit operator cleanup of the
published-PR lease. The merge resolution followed current `main`: it kept the lease module,
watcher scripts, service, and obsolete tests deleted; retained the unrelated cache-provisioning
test and scheduler-origin concurrency repair; and passed 170 focused Yeet, hook, watch, and setup
tests. The packet now records A4 as superseded. It preserves the earlier watcher timing as
historical evidence and makes no automatic takeover claim.

## Goal and prompt critique

The completion gate used seven elapsed days as its definition of a representative sample, but it
did not specify minimum event counts for merges, main runs, failures, takeovers, cache reads, or
publish conflicts. That made time the authority even when one busy day produced more useful
evidence than a quiet week. The operator's evidence-volume ruling was reasonable, but the packet
should have defined that alternative at ratification.

Two original latency targets depended on failure events. A healthy interval may contain no
hosted-watch failure or dead-owner takeover, so an empirical percentile cannot exist. Before A4
was superseded, the packet needed an implementation bound plus deterministic timing tests when
production produced no qualifying incident, while still requiring observed percentiles once
enough incidents occurred.

## TODOs worth codifying

- Add an event-volume option to the goal completion schema, including minimum counts per required
  evidence family and an explicit operator override field.
- Add a ship-velocity closeout command that emits one schema-validated report from the existing
  GitHub, inbox, scheduler, cache, and contention records.
- Add a migration rule for coordination protocols: constructor defaults identify new writers,
  decode defaults preserve old records, old binaries fail closed on the new marker, and removal
  requires a recorded fleet-generation floor.
- Separate cache configuration coverage from authenticated reference resolution and observed
  remote hits in every operator report.

## Lessons by confidence

- **HIGH, critical.** Adding a scheduler does not create concurrency if an older mutex still wraps
  the scheduled work. Review every acquisition layer as one composed protocol.
- **HIGH, critical.** Mixed-version coordination needs explicit old-client execution and both queue
  orders. Additive schemas alone do not prove liveness.
- **MEDIUM, best practice.** A secret reference proves configuration intent, not authentication or
  cache behavior. Keep those receipts separate.
- **LOW, consideration.** A fixed observation duration is a weak proxy in repositories whose daily
  traffic varies sharply. Event coverage is often the clearer completion rule.
