# Reflection — comment-law-gate (2026-11-22, claude)

## Summary

The goal shipped the comment law in three PRs: #3467, the shared grammar, the `beep/no-comments` oxlint rule and `beep laws comments` (growth check, pending-scope lock, census, explicit push mode), advisory and wired into cheap gates, Repo Sanity and lefthook; #3468, the package `decisions/` home with `beep decisions check` and `for`; and the final PR with the AST-proved strip, the `/delete-comment` skill, generator and law-text changes, the AGENTS line and the flip to blocking. Under blocking enforcement the final branch reports `introduced=0 removed=145 findings=0`.

## Tooling experience

- **Worked:** the out-of-repo census and prototypes made the grammar a port, not a design. The 100-commit replay (67 of 72 in-scope main commits would fail, no directive or exported-JSDoc false positive) was cheap and convincing. Yeet's inbox rows forced every red and thread to be answered with a SHA.
- **Didn't:** the first local `final-check` reported six reds at once; the operator's push-first ruling replaced it with targeted gates plus hosted CI, which was faster. A Claude weekly limit stopped one Opus child mid-wave and a host restart killed the Codex fallback lane; resuming the same Codex session kept its work.
- **Frustrating:** each push of the new module drew a fresh CodeRabbit round, and `yeet closeout` accepts one `--reply-thread` per call.
- **Wished existed:** an in-process oxlint rule harness with coverage, and a staged comment-law check that understands merge commits.

## Implementation improvement opportunities

See findings: parity first, new-file coverage in the first commit, explicit push mode, and merge-aware staged checks.

## Goal & prompt critique

The SPEC was precise and its evidence lanes answered almost every design question. Two gaps: the deletion acceptance criterion conflicted with the brief's no-deletion rule, and nothing said that the required Repo Sanity step makes the PR a workflow-edit PR with an operator hand merge, which changed how #3467 merged.

## Lessons

- **HIGH:** a shared classifier is only shared once both hosts agree on the whole tree; fixtures are not enough.
- **MEDIUM:** a new tooling file needs full in-process coverage from its first push.
- **MEDIUM:** a check placed in a required lane must say how it fails: on findings by policy, and closed on execution errors, with a command-level test of each.
- **LOW:** when one review round finds edge cases, expect the next push to find more; fix the class, not the instance.
