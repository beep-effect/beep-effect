## 3. Architecture Doctrine Relevant To The New Feature

- Binding doctrine: `standards/ARCHITECTURE.md` is the architecture constitution; proposals contradicting it must change or amend the document (`standards/ARCHITECTURE.md:1-12`).
- North star: product code uses hexagonal vertical slices; technical wrappers live in repo-level `drivers` (`standards/ARCHITECTURE.md:19-33`).
- Slice default roles: `domain`, `use-cases`, `config`, `server`, `client`, `tables`, and `ui`; boundaries are `domain <- config <- use-cases <- server`, `domain <- client <- ui`, and product ports in `use-cases` implemented by `server` via `drivers` (`standards/architecture/01-hexagonal-vertical-slices.md:30-57`).
- Smallest legal slice: three packages and about 15 files: `packages/<slice>/domain`, `packages/<slice>/use-cases`, and `packages/<slice>/server`; no `client`, `tables`, `config`, or `ui` until there is a real reason (`standards/architecture/13-onboarding-the-minimum-viable-slice.md:21-51`).
- Smallest slice rules: `domain` has no live Layer, `use-cases` defines ports but does not implement them, and `server` is the package that knows how the slice runs (`standards/architecture/13-onboarding-the-minimum-viable-slice.md:53-66`).
- External library wrappers belong in `packages/drivers/<driver>`; drivers are flat repo-level external boundary wrappers, and if a package needs slice language it does not belong in `drivers` (`standards/architecture/03-driver-boundaries.md:1-15`, `standards/architecture/03-driver-boundaries.md:28-37`).
- Driver import rules: `server` and `tables` may import drivers; `client` only browser-safe driver entrypoints; `domain`, `use-cases`, `config`, `ui`, and `shared/*` do not import drivers (`standards/architecture/03-driver-boundaries.md:75-85`).
- Product-agnostic UI primitives, themes, tokens, hooks, and composition helpers belong in `foundation/ui-system`; slice UI owns product screens and workflows (`standards/ARCHITECTURE.md:49-58`, `standards/architecture/07-non-slice-families.md:165-195`).
- Apps wire slices locally: apps are executable workspaces, not reusable public package surfaces, and framework apps should keep runtime modules app-local through `@/*` (`standards/ARCHITECTURE.md:60-66`).
- Shared kernel is deliberate cross-slice product language, not foundation, drivers, generic schema kits, UI primitives, or technical wrappers (`standards/architecture/02-shared-kernel.md:1-7`, `standards/architecture/02-shared-kernel.md:32-52`, `standards/architecture/02-shared-kernel.md:114-137`).
- Codegen/scaffolding command exists as `bun run beep architecture`; README shows an `add concept` dry-run example with `--domain-kind entities` and `--stage persistence` (`README.md:163-170`).
- Architecture CLI flags: `--stage` supports `core`, `persistence`, `protocol`, `client`, `full`; `--domain-kind` supports `aggregates`, `entities`, `values`; `--dry-run` emits a plan without writing files (`packages/tooling/tool/cli/src/commands/Architecture/Architecture.command.ts:34-62`, `packages/tooling/tool/cli/src/commands/Architecture/OperationPlan.ts:34-87`).
- Architecture CLI commands: `architecture plan`, `apply`, `check`, `create slice`, `create package`, `add concept`, and `add role` are wired under the `architecture` command group (`packages/tooling/tool/cli/src/commands/Architecture/Architecture.command.ts:154-193`, `packages/tooling/tool/cli/src/commands/Architecture/Architecture.command.ts:195-253`, `packages/tooling/tool/cli/src/commands/Architecture/Architecture.command.ts:269-291`).

## 6. Goal Packet Format And Exploration Flow

- `goals/` holds durable goal packets for initiatives, research, and agent execution; a goal packet is a docs-as-code contract with objective, source hierarchy, decisions, verification surface, stop conditions, and evidence trail (`goals/README.md:1-14`).
- Standard execution-capable goal shape is `README.md`, `SPEC.md`, `PLAN.md`, `GOAL.md`, `ops/manifest.json`, `research/`, and `history/` (`goals/README.md:16-31`).
- Goal file roles: `README.md` orients; `SPEC.md` is normative; `PLAN.md` is mutable execution plan; `GOAL.md` is compact launcher; manifest is machine-readable routing; `research/SOURCES.md` is provenance; `history/` holds evidence (`goals/README.md:33-48`).
- `GOAL.md` is required for future execution-capable packets, must stay a launcher rather than doctrine, and targets at most 3,500 chars with a hard max of 4,000 (`goals/README.md:49-65`).
- Live packet example `agent-pipeline-velocity` has status, mission, launch command, read order, current phase, latest evidence, and notes in `README.md` (`goals/agent-pipeline-velocity/README.md:1-70`).
- Its `SPEC.md` contains objective, non-goals, source hierarchy, target surfaces, constraints, acceptance criteria, verification matrix, stop conditions, and exception ledger (`goals/agent-pipeline-velocity/SPEC.md:1-107`).
- Its `PLAN.md` contains phase table, closeout checklist, execution notes, and verification commands (`goals/agent-pipeline-velocity/PLAN.md:1-55`).
- Its manifest records schema version, initiative status, packet anchor `SPEC.md`, provenance from an exploration, completion gate, current source of truth, research reports, launcher, phases, verification commands, and stop conditions (`goals/agent-pipeline-velocity/ops/manifest.json:1-117`).
- `explorations/` is the fuzzy front end before work is ready for `goals/`: brainstorming, research, alignment, shaping, and decomposition graduate into goals or product docs (`explorations/README.md:1-16`).
- Exploration pipeline stages are `capture`, `research`, `align`, `shape`, `decompose`, and `graduate`; packet anatomy includes `README.md`, `CAPTURE.md`, `RESEARCH.md`, `research/SOURCES.md`, `DECISIONS.md`, `BRIEF.md`, `MAP.md`, manifest, and assets (`explorations/README.md:23-80`, `explorations/README.md:81-99`).
- Exploration graduation requires complete brief, no unresolved blocking questions, a map naming candidate goal packets and first vertical slice, and a capability check; mechanics scaffold `goals/<slug>` from `goals/_template`, seed `SPEC.md` from `BRIEF.md`, back-link manifests, update `ATLAS.md`, and flip status (`explorations/README.md:139-165`).
- The `explore` skill states the same flow: capture → research → align → shape → decompose → graduate into `goals/` packets (`.claude/skills/explore/SKILL.md:1-19`).
- `explore` research requires both external cited landscape and in-repo capability inventory with package/path citations and explicit NOT FOUND gaps (`.claude/skills/explore/SKILL.md:49-60`).
- `explore` graduation scaffolds goals from `goals/_template`, seeds `SPEC.md` from brief/no-gos/rabbit holes/decisions, links manifests, carries `research/SOURCES.md`, registers source-of-truth entries, and flips exploration status (`.claude/skills/explore/SKILL.md:82-95`).
