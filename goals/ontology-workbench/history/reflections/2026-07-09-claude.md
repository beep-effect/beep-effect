# Reflection — ontology-workbench (2026-07-09, claude)

## Summary

Shipped the full ontology workbench across six phase PRs (#351, #354, #355, #357,
#358, #359, plus the P6 close): a new `ontology` vertical slice
(domain/use-cases/server/client/ui), four drivers (n3, cosmos, oxigraph, shacl),
and the professional-desktop workbench shell. Every phase landed through yeet
with hosted checks green, and every user-facing capability was proven in a live
runtime (browser against vite+sidecar; cosmos twice on real webkitgtk at 100k
elements / 60 FPS). Verdict: complete within scope, with one regression-guarded
deferral (competency t2/t3, DL reasoning explicitly out of scope per GOAL.md).

## Tooling experience

- **Worked:** `bun run beep architecture` scaffolding; the yeet
  repair→verify→publish pipeline as the quality gate; the codex-companion
  runtime for sustained implementation work (all substantive code was written by
  Codex sub-agents); the preview/browser tooling for live acceptance proofs;
  canonize fingerprints as round-trip truth.
- **Didn't:** the codex sandbox blocked network/git-writes/GUI, so every phase
  needed a host-side landing pass (install, tests, browser proofs, publish);
  Bun-backed vitest never started inside the sandbox (fork-worker timeouts).
- **Frustrating:** `yeet publish` pushes but does not open PRs while
  `yeet monitor` requires one; docgen constraints (per-export JSDoc on barrels,
  fixed @category vocabulary, compilable examples) are discoverable only by
  failing hosted lanes; `standards/dual-arity.inventory.jsonc` regenerates with
  unrelated churn on every repair.
- **Wished existed:** a single command to register a new package everywhere
  (workspaces, tsconfig refs, syncpack, boundaries); a headless webkitgtk probe
  harness (the spike page + screenshot loop was hand-rolled).

## Implementation improvement opportunities

- Preserve the empty (base) `@prefix :` binding through the Turtle codec —
  named prefixes survive save, the default prefix does not (subjects serialize
  long-form; still Protégé-parseable).
- Extend verified repairs beyond `sh:hasValue` addQuad proposals (minCount,
  datatype, class-range violations).
- Move large-ontology quality metrics fully behind the worker before scale
  testing beyond 100k (node-side 100k projection costs ~40s; webkitgtk worker
  path stays responsive but the cost is real).
- Sidecar file-path resolution follows process cwd; Tauri controls this in
  production but dev tooling should pin it explicitly.

## Goal & prompt critique

- GOAL.md's compact launcher + packet-as-contract structure worked well; the
  "smallest change that satisfies SPEC" rule kept phases honest.
- Propose adding to the PLAN P6 row: "t2/t3 depend on OWL 2 DL classification
  (out of scope; expect a scoped deferral unless a bounded extension is
  chosen)" — the exit criterion contradicted the scope list as written.
- The pre-approved cosmos→sigma fallback decision framing was excellent: the
  early spike gate resolved the riskiest unknown for the price of one dev-window
  run before any deep integration was spent.

## TODOs worth codifying

- Driver-authoring standard: at least one real-engine test per driver package
  (no fakes); registry-verified catalog pins; lazy engine imports.
- UI standard: no silent no-op guards; every action guard surfaces a state.
- Worker standard: DOM-free import-graph guard test + error/messageerror
  listeners for every worker entrypoint.
- Scaffold codegen: emit docgen-compliant barrels (per-export @category/@since
  from the validated vocabulary) and register packages in all config surfaces.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Prove every user-facing flow in a real runtime before
  declaring a phase done — sandbox-green is not done. Every phase from P2 to P5
  shipped at least one defect that only a live browser/webkitgtk run exposed
  (nested-button click loss, prefix loss, worker DOM crash, DAG tree-id hang,
  inert validate, engine factory bug).
- **HIGH — Critical:** Fakes must not be the only coverage for a driver; run
  the real engine at least once in tests.
- **MEDIUM — Best practice:** Carry a standing-lessons ledger forward into each
  phase prompt — P3 landed with zero CI remediation rounds and P5's fix rounds
  shrank steadily because each phase inherited the previous phases' failures as
  constraints.
- **MEDIUM — Best practice:** Stack phase branches and reconcile via rebase at
  landing time; generated files (inventories, boundary configs) conflict — take
  the validated side and regenerate rather than hand-merging.
- **LOW — Consideration:** Surfaced error states pay for themselves in
  diagnosis speed — the P5 factory bug was root-caused from the UI error text
  in a single probe after the no-silent-guards fix landed.
