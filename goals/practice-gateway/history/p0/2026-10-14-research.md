## Decisions taken in P0

1. **Box in slice 1 goes through Box Drive, not the Box API.** Box's OAuth
   token exchange needs a client secret; shipping one in a desktop binary is
   unsafe, and a hosted exchange broker is a no-go. The lawyer installs and
   signs in to Box Drive (a human step), and the gateway probes it and works
   on its local folder. Box API user auth moves to
   `practice-gateway-providers` as a recorded gap. Reverse by adding a
   Box OAuth provider once a secret-free path (PKCE public client, or an
   approved broker) is proven.
2. **Secrets: Credential Manager for small items, DPAPI for blobs.** A
   Windows credential blob is capped at 2,560 bytes, too small for an MSAL
   token cache. A new driver wraps `CredWriteW`/`CredReadW`/`CredDeleteW`
   (advapi32) and `CryptProtectData`/`CryptUnprotectData` (crypt32, user
   scope) through `bun:ffi`; the MSAL cache becomes a DPAPI-protected file
   behind a cache plugin. Reverse by adopting `@azure/msal-node-extensions`
   if its native module bundles cleanly into the compiled binary.
3. **M365 needs an Entra app registration** (a multi-tenant public client)
   under the operator's entity (D12). The scopes in use (`User.Read`,
   `Files.Read.All`, `Sites.Read.All`, `Mail.Read`, `Calendars.Read`,
   `offline_access`) are delegated; a tenant that blocks user consent becomes
   a `NeedsHuman` admin-consent step with plain instructions. Registration
   is free.
4. **practice-kg resource layers move out of the app** into a package so
   both `practice-kg-mcp` and the gateway mount the same toolkit; the
   existing app keeps its behavior.
5. **Package placement** (architecture standard, "How To Use"):
   `PracticeProfile` and `SetupRequirement` schemas in
   `packages/law-practice/domain`; the doctor service in the law-practice
   slice; the Windows secret store as a new `drivers/*` package; the gateway
   as `apps/practice-gateway`.
