# Reflection — repo-cli-gh-git-consolidation (2026-11-13, claude)

## Summary

The goal moved repo-cli and ai-metrics off hand-rolled `gh` and `git` spawning onto `@beep/git`, `@beep/github` and
`@beep/commands` in 18 merged PRs (W0 to the W7 runner retirement, D-07 to D-21). The closeout PR adds W8 (D-22) and
the site-list ledger. The closeout re-census found that a week of other work had already brought back 34 unrecorded
spawns. W8 migrated 9 of them, kept 26 with a named missing kit member, and labelled the compliant and already
censused rows. Verdict: the acceptance criteria hold at the closeout head, but they will drift again unless a guard
lands.

## Tooling experience

- **Worked:** `beep worktree new` produced a ready lane in one command. `goals decisions add` kept D-22 off the
  hand-edited SPEC tail. The W7 census method (literal argv search, then reading each raw spawn) was reproducible
  enough that the W8 re-census reused it unchanged. Golden suites caught all three false "exact" covers before
  commit.
- **Didn't:** a read-only Explore agent cannot write files, so the census came back inline.
  `package-verify @beep/ai-metrics` failed on the package name.
- **Frustrating:** two failing `package-verify` runs armed P0 inbox rows that cannot be acknowledged before a commit
  exists.
- **Wished existed:** a law that fails on an unrecorded spawn, which would have made W8 unnecessary.

## Implementation improvement opportunities

- The 26 KEEP (D-22) rows name a small set of kit gaps that recur across sites: a per-call environment on `Git`
  (HeadMove fetch, Cache.fingerprint, the evidence probes), `mergeTree` `--merge-base`, a commit parent list, an
  any-state `pullRequestForBranch`, an authenticated-login read and an issue-comment listing. If a later site needs
  one of these, add it as a kit member and move every KEEP row that names it in one PR.
- `ReadyGate` now reads through `gh api` but posts through `GithubRest` on the same gh login. Moving its reads too
  needs `base.repo.full_name` on the kit's pull record and a strict timeline reader.

## Goal & prompt critique

- `GOAL.md`'s acceptance is "repo-cli and ai-metrics contain no hand-rolled gh or git spawn outside the kits", and it
  only lists one-off verification commands. Proposed edit: add
  `bun run beep laws no-unrecorded-git-gh-spawn` (once it exists) to the Verification block, so every session
  re-proves the absence instead of relying on the last census.
- The PLAN "Waves" table ended at C with no guard wave. A guard row ("W-guard: the law that keeps the acceptance
  true") after the last site wave would have been the cheapest place to stop drift.

## TODOs worth codifying

- The `no-unrecorded-git-gh-spawn` law and its test-double twin (frontmatter `todos`).
- `package-verify` name suggestion.

## Lessons (confidence-tiered)

- **HIGH — Critical:** For an absence goal, ship the guard with the last migration wave. A census proves the absence
  only on the day it is taken: 32 spawns came back within seven days of #2753.
- **MEDIUM — Best practice:** "Exact kit cover" means the caller's whole contract (quoting, inherited stdio, text
  that reaches goldens or logs), not the argv. Run the site's goldens before you count it as migrated.
- **LOW — Consideration:** Keep a census subagent read-only, but give it a writable output path in the lane, so its
  evidence lands as a packet file without a hand copy.
