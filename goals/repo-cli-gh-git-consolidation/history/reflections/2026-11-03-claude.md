# Reflection — repo-cli-gh-git-consolidation (2026-11-03, claude)

## Summary

The goal moved repo-cli and its tests off hand-rolled `gh` and `git` spawning onto `@beep/git`, `@beep/github` and `@beep/commands`. It ran in eight waves (W0–W6 plus W2b; W6 added at closeout review for the six Yeet modules D-13 had deferred) with kit extensions, and every behaviour shift is recorded in SPEC D-02..D-15 with a differential of 0 unclassified rows. The goal is complete. What stays on `gh` or a hand-rolled double is a named KEEP. Closing took longer than the code, because of generated-surface churn and main-red episodes 24–26.

## Tooling experience

- **Worked:**
  - Differential ops scripts with frozen pre-wave bodies made each behaviour change visible and classifiable.
  - The scratchpad remerge script (merge main, take main's generated copies, regenerate, re-stamp, push) turned every inventory conflict into one command.
  - `yeet reply` handled review threads cleanly.
  - Replaying W6's own diff onto main, instead of merging after W5's squash, cut 27 conflicts to 6 with no force-push.
- **Didn't:**
  - Local full-package coverage writes under host memory pressure.
  - `yeet ready` without a local final-check receipt, so push-first PRs were flipped with `gh pr ready`.
- **Frustrating:**
  - Generated files conflicting on every main merge.
  - Fresh lanes needing `turbo run build` of dependencies before `check` stopped reporting TS6305.
  - earlyoom killing the 1Password desktop app, which broke commit signing until it was relaunched.
- **Wished existed:**
  - A per-file coverage row write from hosted output.
  - A guard against pushing to a merged PR.
  - A merge driver for generated standards files.

## Implementation improvement opportunities

- **Kit timeouts:** `Git` gets a per-mutation timeout option, so Yeet doesn't need its own `patientGit` 15-minute instance.
- **Kit gaps behind KEEP rows:** `gh pr view` of the current branch, a branch-in-any-state PR lookup, and `gh run view --log-failed` extraction. Each would retire a remaining KEEP.
- **`ScriptCompletion` defect outcome:** the 14 never-spawn guards that stay on their own doubles could then move.

## Goal & prompt critique

- **Deferral:** the packet should say a deferral becomes a later wave or a KEEP with a named reason. That would have surfaced W6 at W4, not at closeout.
- **Decision records:** stacked waves would conflict less if each wave's decision lived in its own file.

## TODOs worth codifying

- A merge driver, or regeneration on merge, for generated standards files.
- A yeet guard against pushing to a merged PR's head.
- A coverage ratchet write from the hosted-printed row.
- A lint or test-kit default: tests that record spawned processes use a private runtime root.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Copy every final SHA from `git rev-parse HEAD`; never retype or recall one. A guessed SHA in a `final` note stalls the merge gate, which arms only on the exact head (#2648).
- **HIGH — Critical:** Check `gh pr view <n> --json state` before pushing to a PR another session may be merging. A squash merge drops later pushes, so the fix never reaches main.
- **HIGH — Critical:** Keep merge and readiness gates fail-closed on malformed input when they move onto a new reader, and test the malformed case.
- **HIGH — Critical:** Never retry a non-idempotent write after an ambiguous transport failure. Only a rate limit proves GitHub didn't apply it.
- **MEDIUM — Best practice:** After any main merge, regenerate the JSDoc inventory, the catalogs and the cache baseline on the merge commit. Never hand-resolve them.
- **MEDIUM — Best practice:** Replay an unpushed stacked lane's own diff onto main after its base squash-merges, instead of merging.
- **LOW — Consideration:** When local compute is exhausted, record the hosted-printed coverage row verbatim instead of waiting for the machine.
