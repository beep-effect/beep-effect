# Reflection — citation-regex-worker-v3 (2026-11-14, claude)

## Summary

The goal met its main count: ten plain-text calls now start 10 regex child processes instead of
291, with the 291 evaluations and every other count column unchanged. Three slices merged: B1
#3336 (one native lane per invocation, limits policy v2), B2 #3352 (protocol v3 and
`CitationRegexSession`), B3 #3355 (protocol v2 deleted, law-practice shard plan re-recorded, eight
shards from about 564 s to about 364 s planned). The kill rules held throughout: a parent-owned
SIGKILL, confirmed dead before `evaluate` returns, and no respawn after a deadline, interruption or
protocol deviation. One red reached main (ep103, a test fixture race) and was fixed the same hour
by #3353.

## Tooling experience

- **Worked:** the A1 count fixture again made the goal measurable independent of host load. Real
  child process tests on both Bun and Node children caught defects that fake spawners would not.
  Independent review on separate sessions found a real defect in every round of B2.
- **Didn't:** `yeet open` mistitled three PRs. Hosted Coverage Regression cannot be rerun (attempt 2
  always fails), so a runner timeout on an unrelated shard cost a main merge to get a fresh run.
- **Frustrating:** a local cheap-gates race between the JSDoc inventory writer and the committed
  ratchet failed two final-checks (fixed on main by #3354 while this goal ran).
- **Wished existed:** a way to fence an authority check at the platform spawner's real birth point;
  Effect's `ChildProcessSpawner.spawn` returns an Effect that prepares `cwd` asynchronously first.

## Implementation improvement opportunities

- Work that never resolves keeps its private Scope and its quarantined lane capacity indefinitely;
  the guarantee is a bounded caller wait, not eventual settlement. Recorded as accepted.
- `invalid-runtime` now covers both a spawner/Clock mismatch and nested lane use; no caller depends
  on telling them apart today, but a distinct reason would be clearer.
- Selection hashing uses `@noble/hashes` because Effect's Digest service accepts one contiguous
  buffer; a multi-part Digest API upstream would remove the second implementation.

## Goal & prompt critique

- The binding design was right about the shape and wrong in two numbers (depth, engine placement);
  both were caught by an implementer stopping instead of improvising, which the brief required. Keep
  that rule; add the check against enforcing code before graduation.
- The B3 acceptance line bundles deletion, shard re-record, a hosted replay-time bound and a
  remote-worker run. The shard re-record needed a CI-driver ruling because of an unrelated
  measurement window. Proposed edit: list cross-goal approvals a slice needs in the SPEC up front.

## TODOs worth codifying

## Lessons (confidence-tiered)

- **HIGH — Critical:** For any check-then-act on a shared resource, list every yield between the
  check and the act, including inside library code — five review rounds each found one more.
- **HIGH — Critical:** Stop and record a decision when the design conflicts with the code — both
  stops in B2 produced rulings that kept every safety rule.
- **MEDIUM — Best practice:** Cancelling a waiter must not touch the resource the holder owns —
  CodeRabbit found a queued evaluation's interruption killing the active job.
- **MEDIUM — Best practice:** Delete code the moment nothing imports it, not a slice later — the
  dead v2 RPC client failed hosted coverage as soon as B2 stopped calling it.
- **LOW — Consideration:** Read every PR title right after `yeet open` on a stacked lane.
