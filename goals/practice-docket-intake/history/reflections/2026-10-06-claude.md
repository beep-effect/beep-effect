# Reflection — practice-docket-intake (2026-10-06, claude)

## Summary

The docket intake service shipped in eight PRs (#1455, #1456 with #1473 and #1501, #1458, #1475,
#1502, #1517, #1528): an app-only `@beep/m365` write lane, the classify, enter and adversarial
review pipeline, the service app with journal, undo and dry run, the live practice-KG matter
lookup and the docket-sheet cross-check. Two unattended live runs on 2026-10-06 wrote tentative
entries to the attorney calendar (10 messages, 1 entered, 2 to review, 0 failed, 3 events) with
nothing undone. Verdict: the goal is met; the open operational item is the attorney's spot-check of
those first entries, which is an operator step and not a code deliverable.

## Tooling experience

- **Worked:** `yeet publish` push-first with the draft PR and the detached readiness job; the
  orchestrator's merge-over-REST at the gate; `beep-heavy` for package-verify fan-out (four
  packages in parallel without touching the desktop app); `it.layer` blocks per journal fixture;
  the REST reply plus GraphQL `resolveReviewThread` pair for review threads.
- **Didn't:** merging `main` after the base PR's squash (12 identical-content conflicts);
  `beep quality test-tsgo` with package names; `beep lint effect-vitest` with file arguments.
- **Frustrating:** the `knowledge refs --check` gate is absent from every local lane the packet
  runs, so a runbook path form turned `main` red after the merge; an `op://` vault name that does
  not exist shipped in the README and only failed at the first live run.
- **Wished existed:** a `yeet` hint after a squash merge for lanes stacked on that branch; a
  journal shape check that fails a cycle which wrote nothing to the journal.

## Implementation improvement opportunities

- Treat the journal as a run ledger: `run-started` and `run-completed` lines bracket every cycle,
  and `runs` reports a cycle without both as torn.
- Temperature 0 and the per-round trace (D-46) landed in slice 4; the next pipeline of this shape
  should start with them.
- The docket-sheet cross-check reads a CSV export (D-44); reading the sheet itself needs an xlsx
  reader and waits for the cross-check to prove its value.
- Master categories are created and never undone (D-42); an `undo --categories` for a throwaway
  mailbox would make the IT-mailbox drill fully reversible.

## Goal & prompt critique

- Write D-41 as "attended by default; the operator may rule an unattended bounded run on a second
  mailbox first" so the ruling that actually happened is a packet decision rather than a message.
- Tick each SPEC acceptance box in the PR that satisfies it and cite the PR; the closeout then
  verifies rather than discovers.
- The brief's rule "ids, counts and hashes only, no client mail in the repo or transcripts" was
  clear and held through two live runs; keep it verbatim in future practice packets.

## TODOs worth codifying

- Stacked-lane rebase guidance after squash merges.
- `knowledge refs --check` inside the docs-touching cheap gates.
- `test-tsgo` package filter; `effect-vitest` file arguments.
- `op://` vault-name lint.

## Lessons (confidence-tiered)

- **HIGH — Critical:** journal every run from the first writing slice, including runs that write
  nothing — the first live run exposed the gap within minutes.
- **HIGH — Critical:** run `knowledge refs --check` on the commit before final whenever a PR
  touches a runbook; use `$HOME/...` or `${XDG_STATE_HOME:-...}` and never a `/home/...` literal.
- **MEDIUM — Best practice:** when a dependent lane merged the base branch by commits, rebase
  onto `main` after the base squash-merges instead of merging `main`.
- **MEDIUM — Best practice:** pin temperature 0 and keep a text-free trace for agentic review
  loops so a dry-run/live divergence can be attributed from the journal.
- **LOW — Consideration:** a two-mailbox first run (IT mailbox, then attorney) is a cheap safety
  net; it found the zero-write journal gap without touching the attorney calendar.
