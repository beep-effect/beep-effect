# CSF-012: Quoted JSON bypasses process\-ID corpus redaction

- Severity: Medium
- Codex ID: `e525f4ad4e5c81919f86da335e5db7c8`
- Source commit: `20ad99a87fccad63856f6fcb117d80fd270bf19f`
- Owner: Public corpus process identity redaction
- Status: implemented; merge and Codex closure pending

## Public Summary

Quoted JSON inside a message bypassed the corpus generator's PID redaction.
The same pattern in three generators allowed process identifiers into saved
public corpus records. The residue guard also missed the escaped form.

## Current-HEAD Validation

Confirmed vulnerable; remediate in lane `L9-corpus-redaction`. Synthetic tests
reproduced quoted-key, whitespace, and repeated-serialization bypasses. Twelve
raw files in each fleet corpus contained affected message values.

## Remediation

All three standalone generators now recognize quoted and escaped PID syntax.
The older generator also rejects residual PID text before publication. A staged
repair sanitizes saved string values and regenerates projections, byte counts,
and digests, then runs each generator's complete pin verifier before promotion.
It retains capture timestamps, event counts, source descriptors, and custody
references. The previous manifest digest records the security transformation;
running the repair again verifies the result without recapturing live sources.

The operator's all-findings instruction authorizes this security correction to
the otherwise immutable run-2 corpus. No ontology ratification is rerun.

Changed files:

- Corpus generators `etl_fleet_corpus.py`, `etl_run3_fleet_corpus.py`, and
  `etl_run3_checkout_identity.py`, plus `test_run3_generators.py`, under
  `explorations/beep-ci-operational-ontology/ontology/extraction/s4/beep-ci-ops/corpus/`.
- Saved `run2-fleet`, `run3-fleet`, and `run3-checkout-identity` pins in that directory.
- `research/scripts/resanitize-corpora.py` in this goal packet.

## Verification

- All 18 generator tests pass, including PID cases through four JSON depths,
  negative controls for unrelated identifiers, and residue rejection without
  echoing the identifier.
- The staged repair sanitizes 24 raw files; all three complete pin verifiers pass.
- A second repair run verifies all pins unchanged.
- Independent decoded-string scanning across 1,838 raw JSON/NDJSON files finds
  zero quoted PID residues.
- Commands are retained in `ops/triage.json`.
