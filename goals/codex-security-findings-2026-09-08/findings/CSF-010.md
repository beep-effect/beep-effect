# CSF-010: Lane\-proof cache ignores inherited environment changes

- Severity: Informational
- Codex ID: `87fa964ffcec81918d3518db0cc69a5d`
- Source commit: `52fcc8d1353db9481ef9edb6cc9619500f95568d`
- Owner: Local verification proof reuse
- Status: implemented; full repository proof pending

## Public Summary

Ordinary local verification commands inherit environment settings that can
change their behavior. Their cached proof identity omitted those settings,
allowing an earlier successful proof to skip a materially different execution.

## Current-HEAD Validation

Confirmed at the current source: `useLocalEnv` controls secret-session wrapping,
while ordinary commands still extend the ambient environment. Disposition:
`remediate`. The optional proof cache affects local verification reliability;
live vulnerability checks remain excluded from reuse.

## Remediation

Retain the upstream fix that hashes the complete ambient environment for lanes
that inherit it, including locally wrapped commands. Keep explicit overrides
hashed as well. A real Bun child records inherited
values so the regression proves both environment propagation and invalidation.

Changed files:

- `packages/tooling/tool/cli/src/commands/Quality/internal/LaneProofReuse.ts`
- `packages/tooling/tool/cli/test/quality-tasks.test.ts`

## Verification

- `bunx --bun vitest run test/quality-tasks.test.ts -t 'lane proof|lane-proof|ordinary lane'`:
  six tests passed. The new regression changes inherited `BEEP_FC_NUM_RUNS`,
  `GITHUB_ACTIONS`, and `TURBO_FORCE` without explicit lane overrides. Each
  unchanged repeat reuses proof; each changed value executes the child again.
