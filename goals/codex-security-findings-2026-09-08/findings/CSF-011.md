# CSF-011: Hard\-coded user path enables cross\-account module hijacking

- Severity: Low
- Codex ID: `20b2517dcb34819191140b7e040cc595`
- Source commit: `b8eb96213c897288025cd527c67601ced27764bf`
- Owner: Graft hook installation trust
- Status: implemented; full repository proof pending

## Public Summary

The generated hook and statusline loaders imported executable modules from an
initializing user account. A different account on a shared machine could select
that installation automatically, crossing the account boundary.

## Current-HEAD Validation

Confirmed in both tracked shims. Their baked installation path and
version-based selection did not validate ownership. Disposition: `remediate`.

## Remediation

Both shims use one repo-owned loader. It resolves the Graft executable on the
agent PATH, validates the canonical package name and entry layout, and permits
only current-user or root-owned paths protected against group/world writes.
Foreign installations, module links escaping the package, relative PATH entries,
and unsupported ownership checks leave the optional integration inactive.
No baked user path, project fallback, or version ranking remains.
