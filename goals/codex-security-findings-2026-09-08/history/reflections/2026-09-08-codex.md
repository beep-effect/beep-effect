# Reflection on the September security findings

## Summary

All nine captured findings have implementation changes and passing focused
regressions. The fixes cover destructive command permissions, private metadata,
cleanup boundaries, token rotation, process identity compatibility, and input
validation. Repository proof and post-merge closure remain tracked in the plan.

## Tooling experience

The signed-in CSV export and ingest command preserved exact finding identities
without putting raw reports in git. Existing filesystem and Effect helpers kept
the changes focused, but the private-file regression exposed an incorrect
assumption in one shared helper. Interrupted proof processes required separate
source fixes and environment investigation; passing focused tests did not prove
the full repository gates.

## Implementation improvement opportunities

Keep permission assertions next to the shared writer as well as its provenance
consumer. Destructive worktree operations now revalidate registration, canonical
containment, and Git ownership immediately before mutation. Those checks should
remain in the service even when callers already validate their arguments.

## Goal & prompt critique

The original launcher pointed at an older packet. The operator's clarification
made the intended outcome explicit: resolve all current findings in one PR.
Future launchers should refresh the live export first and use archived packets
as evidence rather than a fixed count or a new approval gate.

## TODOs worth codifying

- Test output permissions directly whenever a helper describes files as private.
- Keep durable logs for long-running verification commands across continuation.
- Separate embedded replay from optional historical corpus verification.

## Lessons

- High confidence: a regression must inspect the actual security boundary.
  Successful JSON writes alone would have missed the permissive file mode.
- High confidence: pair a destructive target with the authority that permits
  changing it. A plausible path string does not establish Git registration.
- Medium confidence: serial verification should reduce resource contention;
  a successful complete run is still required to establish acceptance.
