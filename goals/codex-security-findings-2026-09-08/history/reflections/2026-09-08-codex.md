# Reflection on the September security findings

## Summary

Eleven captured findings are addressed in PR #1026. Focused tests cover actual
filesystem modes, worktree registration and ownership, cleanup symlink swaps,
OAuth cancellation, inherited execution settings, input validation, redaction,
and hook installation trust. Full proof and external closeout evidence belong
in the verification ledger; focused tests alone do not establish completion.

## Tooling experience

CSV export and canonical refresh preserved exact identities while keeping raw
reports out of git. Early publication met the operator's request to push fixes
as soon as they were ready. The full CLI audit and docgen passed, and focused
coverage restored all six reported worktree metrics above unchanged floors.

GraphQL quota exhaustion interrupted PR lookup after a successful push. REST
provided current-head confirmation and a review-reply path until GraphQL
recovered. A queued or interrupted local proof never counted as acceptance.

Hosted Check caught five new test-file layer diagnostics that runtime tests and
source checks did not cover. Moving services to the Effect Vitest suite boundary
cleared the complete package test diagnostic pass. Two inherited scheduler tests
failed under hosted load because fixed sleeps preceded queue assertions. Both
failures reproduced with delayed starts; observable ticket synchronization
replaced those timing assumptions while keeping the original assertions.

## Implementation improvement opportunities

A cleanup candidate needs both a bound inode and its outer authority boundary.
Resolving the candidate and class root together is insufficient when both can
move outside the authorized repository. The Turbo regression now exercises
that exact transition.

Generated hook loaders should not trust an initializing account or package
version ranking. Windows needs its own ACL mechanism. The Linux-hosted tests
exercise Windows ACL evaluation with isolated fixtures; native Windows execution
remains a useful additional platform test.

## Goal & prompt critique

The operator's current objective settled the scope: resolve every current
finding in one PR. The archived launcher supplied history, while refreshed
capture supplied the actual finding set. Repeating approval or stale-count
gates would have delayed the requested remediation.

## TODOs worth codifying

- Assert output modes next to helpers that promise private files.
- Retain known PR identity when quota failures affect only a follow-up lookup.
- Exercise the Windows ACL probe on a native runner.
- Keep durable logs and distinguish package proof from full repository proof.

## Lessons

- High confidence: tests should cross the same boundary as the reported exploit.
- High confidence: reviewed fixes can be pushed early while full proof remains required.
- High confidence: inherited environment values are part of a reusable proof's identity.
- Medium confidence: native platform execution would strengthen the Windows ACL evidence.
