# Reflection — agent-execution-authority (2026-07-28, claude)

## Summary

The packet delivered what it promised: a default-deny authority boundary over the MCP
agent surface with a hash-chained, append-only record of every decision, shipped across
seven independently mergeable PRs. The verdict is positive with one large caveat — the
packet's own written mechanism claims were wrong twice, and adversarial review, not the
type system and not a green local suite, is what caught the two defects that would have
made the boundary exploitable.

## Tooling experience

- **Worked:** `bun run beep yeet` as a single quality path was the right shape — one
  command to repair, one to prove, one to publish, one to watch. The slice-package
  generator (`beep architecture create package`) saved real time on
  `@beep/epistemic-config`. Adversarial review earned its cost outright: three defects
  in PR 5, two in PR 6, every one of them a thing a green suite had already blessed.
- **Didn't:** The type system cannot express the constraint this packet most needed. A
  `Context.Reference` layer's output type is `never`, so "provide the governed `Fetch`
  here and nowhere else" is a comment, not a signature. Both PR 6 majors lived in that
  blind spot.
- **Frustrating:** `A.filterMap` takes `Result`, not `Option`, in this version; passing
  `O.some`/`O.none` silently produced a corrupted array that surfaced as
  `SchemaError: Missing key` in three tests nowhere near the call site. `it.effect`
  installs a TestClock, so an `Effect.sleep(5ms)` written to widen a race window hung
  for the full 30-second timeout with no indication why. `changeset status` reads from
  git, so an unstaged changeset is invisible to the check that exists to find it.
- **Wished existed:** A way to assert layer-graph identity in a test — "this `HttpClient`
  is not the same instance that one resolves." The bug that mattered most in this packet
  is a graph-shape property, and the only tool available for it was reading the code and
  reasoning carefully, which is precisely the method that had already failed.

## Implementation improvement opportunities

- **Egress decisions are not correlated to an MCP session.** Recorded, not hidden, and
  the reason is structural (no fiber inside `Fetch`), but time-correlation degrades under
  concurrency. Closing it needs new `mcp-kit` surface.
- **The `audience` axis is half-degenerate.** Only `external-network` is genuinely
  exercised; every governed MCP write is a local workspace file. The axis is modelled,
  not validated, and the packet says so — but a future contributor will read two
  populated literal members as two tested paths.
- **The exfiltration primitive is live.** `ontology_publish_provenance` is default-off
  and allowlist-gated, which is what makes it defensible. Anyone widening
  `EPISTEMIC_EGRESS_DESTINATION_ALLOWLIST` is authorizing an agent-chosen POST of
  workspace content to that origin and everything beneath it. That belongs in a
  CODEOWNERS rule, not only in a packet note.

## Goal & prompt critique

The `GOAL.md` launcher and `SPEC.md` split worked well — normative contract separate from
the compact launcher, with `PLAN.md` carrying dated corrections inline rather than being
rewritten. Three specific edits I would make:

1. **Mark unmeasured mechanism claims.** `PLAN.md` and `SPEC.md` stated how
   `provideContext` behaves and how a run should be keyed, in the same imperative voice
   as the requirements. Both were wrong. A convention as small as an `UNVERIFIED:` prefix
   would have flagged them as things to measure rather than things to implement.
2. **State what a spike actually covered.** The graduation record said two mechanisms were
   "proven" by the 2026-07-25 spike. The `Fetch` finding was proven for a
   *directly-provided effect*, not through a running server — a materially weaker claim
   than "proven," and PR 6's blocking check existed only because someone noticed the gap.
   A spike's scope limits belong next to its findings.
3. **Put the blocking check earlier.** PR 6's blocking check was correctly specified and
   correctly executed, and it falsified the packet's central assumption at PR 6 of 7. The
   same measurement could have run at PR 0 for the same cost and would have saved a wrong
   comment shipping in PR 5.

- The positive-sibling-assertion rule in `08-testing.md`.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Measure a mechanism before writing a plan in its imperative voice.
  This packet asserted two runtime behaviours as settled, shipped a code comment restating
  one of them, and spent two PRs correcting both. The falsifying measurement was cheap
  and available from the start.
- **HIGH — Critical:** A green suite is not evidence. PR 6 was green locally with two
  exploitable defects in it — a boundary that escaped its own branch and an audit record
  that named the allowlist entry instead of the request, leaving an exfiltration channel
  inside the control built to prevent exfiltration. Adversarial review found both.
- **MEDIUM — Best practice:** When a constraint cannot be expressed in a type, write the
  test that catches its violation *and* say in the code why no signature enforces it.
  `GovernedEgress.layer.ts` now carries that note; it is the only thing standing between
  a future reader and the same mistake.
- **MEDIUM — Best practice:** Pair every absence assertion with a positive control in the
  same test. Effect's defaults make silent vacuity the easy failure mode.
- **LOW — Consideration:** Attribute a CI failure before rerunning it. Three cheap checks
  — did the commit touch that package, did the job pass on an earlier run of this branch,
  what is the local runtime against the timeout — separate an environment-only flake from
  a real regression, and this repo has enough of the former to make blind reruns tempting.
