# Reflection — lint-policy-single-digit (2026-08-13, claude)

## Summary

The packet took the hosted Lint Policy required check from ~20 minutes to ~10.5 minutes
(PR #678: 4-wide deprecated-apis shards, LPT step ordering, empty-scope step omission) and
then disproved the oxlint-tsgolint engine swap with a gate-driven spike (NO-GO on program
coverage and existing-source parity) rather than shipping a silent coverage hole. The
closeout PR raises outer step concurrency 2→3, modelled to land the lane around 8.3
minutes; its own hosted run is the admission evidence. Single digits achieved; the deeper
engine swap stays disproven-until-P2b.

## Tooling experience

- **Worked:** the five-lane Codex exploration fan-out (each report survived into
  `research/` with file:line evidence); yeet's verdict/packet artifacts for failure
  attribution; the hosted job log's `[beep-cli] ... done in Xms` lines as a free per-step
  profiler; the spike's ordered hard gates (engagement first) catching a false-positive
  benchmark before it cost anything.
- **Didn't:** `yeet closeout` status decode (the PR #668 raw-Option residue) still forces
  reading `pr-closeout.json` by hand; the first publish's monitor raced GitHub check
  registration and reported a phantom failure.
- **Frustrating:** two publish-proof failures that had nothing to do with the change under
  test (corrupt oip-web Turbopack cache; upstream `--daemon=false`), each costing a full
  proof cycle.
- **Wished existed:** hosted per-step RSS telemetry for the lint-policy lane — the
  outer-concurrency admission decision leans on local RSS probes and a model instead of
  fleet numbers.

## Implementation improvement opportunities

- The LPT ordering is a static array sort; if step durations drift, nothing re-sorts. A
  periodic re-measure (or emitting per-step timings as a build artifact) would keep the
  order honest.
- `lint:docgen` (197→290s under contention) is the next long pole; the fold-into-Docgen
  design is fully specified in `research/03`/`research/05` and stays backlog.

## Goal & prompt critique

- SPEC P1's "hosted <= 9 min observed" should have been written as "hosted evidence
  recorded; accept/tune decision at closeout" — the number forced a redundant decision
  round when 10m39s arrived. Exit criteria that hinge on a modelled number should name the
  fallback explicitly.
- GOAL.md's phase-scoped launcher (P1-only, everything else out of scope) worked well and
  is worth repeating for multi-phase packets.

## TODOs worth codifying

- Turbo-flag-spelling guard for tooling-constructed turbo invocations (latent-break class:
  flags only exercised by affected-mode paths that the introducing PR structurally cannot
  run).
- Oxlint typed-rule experiments: dedicated config + `--disable-nested-config` +
  engagement canary as the mandatory first step (candidate for the tool-routing notes).

## Lessons (confidence-tiered)

- **HIGH — Critical:** Prove rule engagement before benchmarking a linter — a 0.55s
  "clean" typed scan meant the rule never ran, and only the seeded canary exposed it.
- **HIGH — Critical:** A finding is not coverage: audit program assignment
  (`OXC_LOG=debug`, unmatched-file count) before trusting any type-aware migration.
- **MEDIUM — Best practice:** When a parallelism change lands, re-derive the lane's
  binding constraint (long-pole vs sum-bound) before promising the next number; contention
  moved docgen +47% and semantic-delta +44% in the same run that cut the long pole 55%.
- **LOW — Consideration:** Sequential publish-proof failures with distinct environmental
  causes (stale cache, inherited flag break) are cheaper to absorb by running the failing
  sub-lane standalone before re-entering the full proof.
