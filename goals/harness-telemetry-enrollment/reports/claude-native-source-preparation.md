# Fixed Claude native canary source preparation

This is local source preparation for one owner-admitted Claude Code 2.1.318 child invocation, pinned to `claude-opus-5-5` with medium effort. It is an explicitly observed route, not an orchestrator fallback. No networked model invocation, login operation, service installation, deployment or backend call is part of this source proof. The existing frozen Codex candidate and its accepted runtime proof remain separate source identities.

The new standalone `ops/claude-native-canary.ts` accepts one private schema-validated admission file. There is no arbitrary prompt, argv, environment, session, resume or dispatch API. The fixed prompt asks only for `ENROLLMENT_CANARY_OK`. Existing `AiProviderCliHome` public helpers preserve the native HOME/config consumer without inspecting or copying credentials. The reviewed flags enable safe/restricted mode, empty built-in tools, strict empty MCP configuration, disabled custom commands/Chrome, no session persistence, explicit model/effort, and native stream JSON with verbose metadata. `--bare` is prohibited because its native auth contract bypasses OAuth.

The decoder requires exactly one matching initialization, one exact assistant response and one successful terminal result. Initialization binds native version, actual working directory, model and native non-API-key auth source, and requires empty executable tools/MCP/custom skills/commands and the exact offline-qualified built-in plugin/agent set. Unknown builtin/customization changes refuse. Bounded `ui_invalidate` bodies are discarded; typed `api_retry` notifications are counted with messages discarded. Native vendor retry notifications do not establish an API-request count, and never authorize source replay. Tool-bearing messages, hook events, unknown event kinds, duplicated/reordered terminal states, foreign sessions/models, pending turns and permission denials fail closed. Raw source, reasoning, result and error bodies remain bounded in memory and are discarded. Native stderr is ignored. The immutable source receipt contains only salted session identity, safe startup inventory assertions, measured aggregate timing and typed native usage categories. Missing/null counts remain unknown; input/cache creation/cache read/output stay separate, and thinking tokens are already included in output. No cost estimate or agent-turn count becomes a billing/API-request claim.

The Linux policy preflight reads only fixed managed settings, managed MCP, sorted JSON drop-ins and the selected native cached remote-policy file. It never reads native credentials or the top-level Claude configuration JSON in the user's home directory. It hashes stable owner/mode/inode metadata and bounded transient content, rejects active selected bootstrap/hooks/MCP/model/env overrides and unknown policy keys, and emits only hashes/counts. The owner admission pins that fingerprint. Immediate pre-model and post-model checks refuse changed policy. The executable is independently hashed and version checked. Managed policy fetched remotely is not frozen by these local checks; this is an explicit admission boundary, not a remote privacy guarantee.

The existing exclusive, fsynced attempt marker wins before any process, including the version probe. An interrupted or invalid attempt never launches again. Only a complete immutable source receipt permits metadata-only replay in its original host/namespace/epoch. Replaying delivery reruns neither the native source nor its probes. Public launch facts and managed-controller provenance are reused, as is the existing local collector route. Local acceptance remains separate from backend verification. Native token counters are retained as separate source evidence; the exported controller event still makes no model/token usage claim.

The finite config builder now accepts `codex-cli` or `claude-code`; constructor and decode defaults remain Codex. Existing Codex worker and deployment bytes are checked against explicit Codex selection. Claude selection changes only its declared launch route/harness; controller intake, privacy, resource bounds and paused initial deployment remain the existing policy.

Source proof includes 96 offline tests and the complete current `goals/tsconfig.ops.json` compiler gate. Tests cover wire privacy/counters, wrong inventory/model/version/cwd, failed/ambiguous terminal events, serialized private admission, policy drift, exact delivery replay, and default Codex compatibility. The initial mistaken `tsgo` replay reached the unchanged MemoryHigh reclaim boundary and was stopped; the canonical Repo Sanity `tsrs` replay passed. Failed and stopped receipts are preserved privately.

A pinned executable startup probe ran inside a fresh network-unshared bubblewrap profile with only synthetic API-key auth and no host credential mounts. It observed the exact native model/version, empty tools/MCP/skills/commands, three built-in plugins (`cc-plugin-agents-md`, `cc-plugin-privacy`, `cc-plugin-plugin-authoring`) and four built-in agents (`claude`, `Explore`, `general-purpose`, `Plan`). Native retries remained offline; the bounded probe was terminated without a terminal model success. Raw output was discarded. A shorter second probe timed out before initialization and is retained as incomplete evidence. This establishes no OAuth usability or successful model result.

Native HOME remains shared so the approved native OAuth consumer can operate. No-session-persistence suppresses session transcripts/resume; it does not prove that all ancillary cache/config writes cease. Startup metadata can only be qualified during a separately admitted actual native invocation. This preparation makes no zero-retention, remote-freeze, broad enrollment or population-coverage claim. Actual startup, intake, EventState, backend readback and cleanup still require owner admission and independent review.
