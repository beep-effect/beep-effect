# Claude failure diagnostics and process lifecycle

The original d88 source and failed controlled pilot remain immutable. Retained evidence showed Prepared and Started but no source receipt. That proves the owned native process was spawned; it does not distinguish native exit failure, protocol refusal, output bounds, or post-run policy refusal. The original model/API outcome remains Unknown. This revision does not reconstruct or relabel discarded output and does not authorize another model attempt.

The corrected producer writes finite metadata before each native version/source dispatch, then records observed spawn and final validation/refusal state. An unobserved spawn or exit stays unknown. Records contain only request binding, fixed purpose/stage, optional exit status, observed byte counts/completion, finite protocol counts and match booleans, fixed failure categories and policy digests/comparison. No response/reasoning, raw identifiers, error messages, paths, argv, native credentials or arbitrary configuration values are retained. Source-process nonzero, output refusal, protocol refusal, identity hashing, policy refusal, receipt persistence and timeout have separate typed phases.

Diagnostic records use an owned O_EXCL pending file, file fsync, atomic no-overwrite hardlink publication, directory fsync, unlink of only the pending inode created by that writer, and directory fsync again. Existing finals and failed/partial pending residue are preserved. Pending files never count as complete diagnostics. The shared helper is data-only and protocol-neutral; it exposes no process, prompt, session, dispatch or credential capability.

The protocol inspector does not promote output. It can count unsupported native metadata, including a documented rate-limit event, while the strict source decoder still refuses unsupported kinds. That is a possible refusal mode, not a diagnosis of the original failed pilot. Known bounded UI invalidations may trail the one successful terminal result and are discarded; a duplicate terminal or any non-UI trailing event still refuses. Exact tool/MCP/customization/model/version/cwd/auth contracts remain enforced.

Failure lifecycle is separate from task quality. For a known nonzero native exit, the producer records finite exit diagnostics and posts Finished failed. Exit0 with collection refusal posts Finished unknown while preserving the known process exit and the distinct collection failure. Uncertain ownership/exit stays unknown. A pending lifecycle intent is durable before the fact request; a failed or uncertain acknowledgment retains pending metadata. That secondary failure cannot mask the original source refusal or permit another model invocation. The original failed journal is not edited.

Offline regressions cover known native nonzero, unsupported metadata after exit0, post-run policy drift, output overflow, failed Finished delivery, pre-dispatch diagnostic visibility, no source replay, harmless trailing UI, and atomic publication collision/partial/symlink residue. The full existing native suites remain part of the source proof. The existing attempt fence and original-epoch/transport request binding remain intact; across-epoch re-admission is still a separate review boundary.
