# Fixed Muse proxy canary

This adapter prepares one fixed Muse source through the existing canonical
`claudem` consumer, requesting `muse-wonder-1.0(medium)`. It is a local dependent
implementation, not an actual Muse model or backend qualification.

The four function definitions in `muse-proxy-canonical-functions.zsh` are exact
extracts of the approved shell consumer: `beep_otel_attrs`, `claude`,
`_claude_proxy`, and `claudem`. The adapter pins their combined bytes and the
native shell. It sources only that file, never a full shell startup. The finite
host contract requires global zshenv files absent. Offline fixtures include a
user `.zshenv` that exits99; `zsh -f` skips it and still completes the fixed consumer. The owner must qualify any
future startup-file change instead of hiding or deleting policy. A private
command directory contains only `claude`, resolving to the separately pinned
native executable. No arbitrary prompt, args, environment or endpoint is accepted.

Authentication remains with the unmodified canonical `_claude_proxy` function.
The adapter never opens, copies or serializes its client token or provider
credentials. The owner supplies the existing consumer HOME and preserves the
existing proxy on `127.0.0.1:8317`. No new proxy, live discovery request, service
restart or production exporter configuration is part of preparation or cleanup.
The wrapper's lightweight model slot is retained exactly; zero tools and no
subagents are required, and unexpected model/agent behavior is refused.

An isolated native startup proof used a fresh fake HOME, dummy client token and
fake loopback proxy under a network namespace with no upstream or real credential
mounts. Native Claude 2.1.318 reported the requested Muse alias in init, assistant
and terminal model usage, `apiKeySource=none`, zero tools/MCP/skills/slash commands,
three exact built-in plugins and four exact built-in agents. These are synthetic
transport/protocol facts, not account health, upstream model attestation or paid
inference proof. The standalone decoder requires these finite forms. Native
reported usage is proxy-translated metadata; missing counters stay unknown and
actual HTTP request, title, auxiliary model and billing totals remain unknown.

The spawned shell/controller PID is never labeled native. The adapter locates a
single owned matching native descendant (or observes shell exec), checks actual
parent ancestry, executable inode, start ticks and CWD twice, and retains only
canonical salted process identifiers. The worker/root route is independently
admitted against the actual producer CWD. Proxy service ownership is separate.

One no-follow, exclusive fsynced attempt fence precedes all probes. An attempted
source without a complete immutable receipt never reruns. Exact request and epoch
binding plus evidence digest permit only metadata delivery replay. Safe source
metadata contains no response, reasoning, token, raw session/process/path, argv or
environment. Six content telemetry gates and all native exporters remain off;
this does not claim native or proxy content persistence suppression or ZDR.

Offline tests use a compiled synthetic executable, real private Unix socket and
the exact wrapper with an owned dummy token. They independently compare native
process identity, check fixed wrapper drift, source failure refusal and immutable
metadata replay. Actual Muse/model/service/backend execution remains root-owned
and must follow independent source and runtime admission review.

Finite diagnostics reuse the separately reviewed protocol-neutral native attempt
helper byte-for-byte. Completed metadata is fsynced then published atomically
without overwrite; owned pending residue is preserved on failure. Source records
mark native startup only after actual native executable/ancestry verification,
not shell spawn. Nonzero exit and decoder/policy refusal have distinct finite
phases, optional native exit observations and safe protocol counts. Failed
lifecycle delivery preserves pending intent and cannot hide the original source
failure. No failure grants a new wrapper invocation.

The data-only runtime config builder admits the existing `muse` harness identity.
An exact prior-d88 builder oracle preserves all four generated files for Codex
and Claude; separate current and frozen8029 runtimes prove config-schema,
controller DTO, metadata projection and protobuf export parity for fixed
synthetic Muse evidence. This is selected public-contract composition, not full
transitive equivalence, upstream model attestation or production qualification.
