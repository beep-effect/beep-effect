# Reflection — model-routing-sync (2026-09-25, codex)

## Summary

The acceptance repair exposed three package coverage failures outside Models.
The shared runner already documented package overrides, and isolated diagnostic
runs made the failures disappear. The operator approved three local configuration
exceptions through an interview, preserving shared defaults and test assertions.
Actual-config coverage then passed 47 wink, 182 utils, and 115 identity tests.

## Tooling experience

- **Worked:** reproducing the same failures with one worker separated runner
  isolation from Models behavior. Running without a CLI isolation override proved
  the committed configurations rather than a temporary invocation.
- **Didn't:** package quick verification alone did not check required release
  metadata. Hosted Repo Sanity rejected the missing changeset.
- **Frustrating:** hosted checks and local merged-preview proof finished on
  different schedules. Operator merges overtook the remaining packet work.
- **Wished existed:** one visible delivery handoff showing local proof, hosted
  readiness, and packet completion together before an operator merges.

## Implementation improvement opportunities

Keep the exception set explicit: wink, utils, and identity only. The comments
must describe unconditional isolation accurately, because coverage is the reason
for the override rather than a condition in its implementation. Preserve the
shared coverage default until separate evidence justifies a broader change.

## Goal & prompt critique

The approved scope decision was narrow enough to implement without changing
runtime behavior, APIs, thresholds, or dependencies. The intended open-PR
handoff needs coordination with operator merges: a green hosted monitor is not
proof that a still-running local publisher has finished or that lifecycle edits
have landed. Preserve each dated receipt and resolve the delivery boundary
explicitly when the operator merges first.

## TODOs worth codifying

- Include changeset status in publication preflight for configuration-only
  changes to versioned packages.
- Make final handoff evidence name the proven commit and the remaining gates.

## Lessons (confidence-tiered)

- **HIGH — Critical:** a diagnostic CLI override does not prove the package
  configuration; repeat the original failing runner conditions without it.
- **MEDIUM — Best practice:** retain live proof handles across interruptions and
  wait for their terminal outcomes instead of scheduling duplicate heavy work.
- **LOW — Consideration:** a consolidated delivery indicator could prevent an
  operator merge from racing packet closeout.
