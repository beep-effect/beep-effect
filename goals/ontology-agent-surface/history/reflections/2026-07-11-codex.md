# Reflection — ontology-agent-surface (2026-07-11, codex)

## Summary

The packet delivered a nine-tool stateless ontology MCP surface with real
engine layers, semantic CAS, fixed budgets, fail-closed mutation policy,
authenticated actor attribution, and typed visible refusals. The implementation
is locally closeout-ready; canonical host measurements, ROBOT interop, retained
live-socket proof, and P3 PR mergeability remain operator gates.

## Tooling experience

- **Worked:** The live-client proof loop crossed transport, auth, MCP session
  replay, toolkit dispatch, stateless file open, rdfc-1.0, and Oxigraph in one
  flow. It caught the empty-language literal defect and produced a precise
  real-service regression. The standing lesson ledger kept later fixes on
  Effect codecs, typed errors, terse helpers, and clean diffs.
- **Didn't:** Sandbox docgen could reuse proof manifests, so invalid categories
  passed locally and failed only in hosted lanes. Bun-backed Vitest and CI
  workers also hit environment-specific startup or default-timeout failures.
- **Frustrating:** Affected-scope selection looked authoritative while omitting
  hosted category and integration obligations. The packet paid for that blind
  spot across three separate docgen remediations involving `budgets`,
  `references`, and `context`.
- **Wished existed:** One live-source preflight that validates JSDoc categories,
  expands affected public-surface obligations, selects node-backed Vitest for
  real engines, and applies the explicit heavy-test timeout policy.

## Implementation improvement opportunities

- Make the single-writer assumption observable in operator UX. The semaphore
  closes in-process races, but an independent process can still reopen the
  cross-process CAS window.
- Keep canonicalization refusal visible in capacity planning. Each stateless
  read includes rdfc-1.0 with a configured 1,000 ms abort signal and a deep
  blank-node work cap. Neither is a strict end-to-end deadline, and scale work
  must not hide the measured cost with an undeclared cache.
- Keep all heavy real-engine tests on `{ timeout: 120_000 }` and prove them
  through `node .../vitest.mjs`, so hosted worker startup does not masquerade as
  a product failure.

## Goal & prompt critique

- The locked non-goals and the indivisible gate/actor/budget trio kept the
  packet focused. The explicit first live slice was especially valuable
  because it forced real transport and Oxigraph evidence before mutation.
- Revise the closeout contract to distinguish `implemented-local`,
  `host-evidence-complete`, and `mergeable`. A single phase status currently
  has to carry sandbox completion, host-only evidence, and GitHub state, which
  makes a local `completed-retained` preparation look stronger than it is.
- State the canonical benchmark runner directly. Direct Node cannot resolve
  this checkout's source `.js` specifiers to `.ts`; the working standalone
  TypeScript precedent is Bun with an Effect `NodeRuntime` adapter.

## TODOs worth codifying

- Docgen vocabulary: generator and lint feedback should list valid categories;
  sibling-export lookup should be part of the authoring template.
- Test policy: real N3, rdfc-1.0, Oxigraph, SHACL, browser, or socket tests use
  `{ timeout: 120_000 }` plus a node-backed proof command.
- Generator policy: external or generated inputs cross
  `S.decodeUnknownEffect`; no default synchronous decode shortcut.
- Quality policy: run terse-effect, typed-error checks, `git diff --check`, and
  `git diff --cached --check` before handing work to hosted lanes.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Keep the live proof loop end to end — the real MCP client
  found an Oxigraph literal defect that narrower green lanes did not exercise.
- **HIGH — Critical:** Choose `@category` only from the validated vocabulary —
  plausible labels are not valid labels, and reusable sandbox manifests can
  hide the mistake.
- **HIGH — Critical:** Give heavy real-engine tests an explicit 120-second
  timeout and retain node-backed Vitest proof — runner instability must not be
  confused with semantic failure.
- **MEDIUM — Best practice:** Treat affected-scope gates as a fast subset, then
  enumerate hosted-only public-surface and generated-config obligations.
- **MEDIUM — Best practice:** Carry and codify the lesson ledger — Effect
  decoding, terse helpers, typed errors, and clean staged/unstaged diffs
  prevented known failures from recurring.
- **LOW — Consideration:** Report local lifecycle preparation separately from
  achieved closeout whenever the operator still owns host evidence or GitHub
  mergeability.
