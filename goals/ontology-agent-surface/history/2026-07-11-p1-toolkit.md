## Summary

P1 defines and implements the curated nine-tool ontology agent surface under
the worker-safe `@beep/ontology-use-cases/tools` subpath. Thin handlers live at
`@beep/ontology-server/tools` and delegate to stateless use-case orchestration
wired to the real N3, Oxigraph, SHACL, rdfc-1.0, and filesystem layers. No HTTP
transport, session repository, cache, TierGate dispatch, or actor-auth redesign
was added.

## CAS Semantics Decision

P1 freezes the save precondition as semantic rdfc-1.0 fingerprint equality,
without an additional byte hash. This follows the normative SPEC language and
the shared canonicalization contract: formatting, prefix spelling, and blank
node labels may change without blocking an otherwise semantically current
agent write, while any RDF dataset change produces a stale-write conflict.

The mutation sequence is open from the real server-side file store, parse with
N3, fingerprint the current dataset with rdfc-1.0, compare the caller's
expected fingerprint, apply typed operations, reject empty deltas, serialize,
atomically replace the Turtle file, reopen, and return the new fingerprint.
A service-owned semaphore serializes the compare/apply/write section inside the
sidecar process; it is coordination, not a session repository or cache.

The current filesystem port has no cross-process conditional-rename primitive.
P2 must retain one sidecar write authority or add an OS-level conditional-write
port before claiming safety against an independent process writing the same
workspace during the compare-to-rename interval.

## Server-Owned Budgets

| Budget | Default | Enforcement point |
| --- | ---: | --- |
| Typed change operations per batch | 256 | Before apply, serialize, or write |
| SPARQL results | 200 | Handler-created safeguards; LIMIT injection and returned-result truncation |
| Search results | 100 | After deterministic snapshot search, before response construction |
| SHACL validation results | 100 | Handler-created validation input before real SHACL execution |
| Reasoner drift operations | 64 | Before mutation reasoning exposure; drifted inference results are refused |

Callers have no budget fields in tool requests. A batch above 256 receives a
budget refusal; a batch of 65-256 receives the narrower drift-cap refusal. V1
saved-file mutation accepts asserted-partition operations only. The shared
`classifySessionDatasetPartitions` function now owns base parse routing and
change-batch shape detection, so a proposed asserted quad that classifies into
SHACL shapes is visibly refused.

## Typed Recoverable Errors

- `OntologyCasConflict`: expected and current semantic fingerprints,
  `recoverable: true`, and refetch/rebuild/retry guidance.
- `OntologyBudgetRefusal`: budget kind, actual count, fixed limit,
  `recoverable: true`, and narrowing/splitting guidance.
- `OntologyReasonerDriftRefusal`: observed operation count, fixed cap,
  `recoverable: true`, and smaller-window guidance.
- `OntologyNoOpRefusal`: explicit recovery guidance for duplicate adds, absent
  removes, empty repairs, or another all-empty real delta.
- `OntologyToolExecutionError`: safe typed mapping for real file, Turtle,
  canonicalization, SPARQL, validation, unsupported-partition, and proposal
  lookup failures.

No tool returns early as a silent no-op. `propose-change-batch` and `repair`
return the real `SessionChangeDelta` containing added and removed quads.

## Real-Engine Proof Per Tool

`packages/ontology/server/test/OntologyTools.test.ts` builds
`OntologyToolsLive` without HTTP and therefore exercises the thin handlers plus
the real N3/Oxigraph/SHACL/rdfc-1.0/file-store graph.

| Tool | Real proof |
| --- | --- |
| `ontology_open_inspect` | Opens a temp Turtle file and returns rdfc-1.0 fingerprint, prefixes, and quad count. |
| `ontology_snapshot_describe` | Builds the actual ontology snapshot from the parsed session. |
| `ontology_search` | Searches 205 fixture resources and returns exactly 100 with `truncated: true`. |
| `ontology_sparql_query` | Oxigraph SELECT over more than 200 rows injects the fixed LIMIT and returns 200. |
| `ontology_propose_change_batch` | Applies an asserted quad, returns one real added delta, atomically saves, and changes the fingerprint. |
| `ontology_validate` | Real shacl-engine validation returns the expected violation and verified P0-registry repair. |
| `ontology_repair` | Revalidates the proposal, CAS-saves its operations, and proves the repaired file conforms. |
| `ontology_export_provenance` | CAS-checks the source and writes PROV-O plus dataset-description Turtle sidecars through the real file store. |
| `ontology_capability_metadata` | Returns all nine tools, immutable budgets, semantic CAS, statelessness, and the bounded reasoner profile from the real handler layer. |

Negative proof in the same suite covers stale CAS rejection with the new
fingerprint and refetch guidance, the 257-operation budget ceiling, and the

## P2 Risks And Entry Conditions

- Mount only authenticated, Origin-validated streamable HTTP `/mcp`; do not
  inherit wildcard RPC CORS and do not add stdio.
- Dispatch all three mutating tools through TierGate fail-closed. Tool hints
  are metadata and are not authorization.
- Derive authenticated caller identity and persist it per change before
  enabling mutation. The inherited journal still uses `agent:workbench` and a
  stateless reopen cannot reconstruct an earlier in-memory change log.
- Decide the durable per-change journal/sidecar contract without introducing a
  v1 session repository. Provenance export currently describes the saved
  dataset and the current stateless session only.
- Preserve one sidecar write authority or strengthen the file-store port for
  cross-process conditional writes.
- Fix or explicitly waive the repo-wide `tsconfig-sync` docgen regression
  before P2 closeout; never accept the 106-file blanking diff.
