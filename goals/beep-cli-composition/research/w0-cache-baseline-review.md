# Cache baseline review: W0 retirements (2026-10-31)

Reviewer: Claude Opus 5.5 (W0 lane, `refactor/beep-cli-w0-retirements`).

W0 retires finished or duplicate `beep` instruments after a zero-consumer
check (SPEC D11, D22; census in `w0-retirements.md`). The edits move three
cache subjects. No task is added or removed, no cache flag, output or
`passThroughEnv` changes, and no qualification is granted.

## `//` (root)

- `turbo.json`: `bun run beep lint policy-fingerprint --write` dropped the six
  `Quality/internal/JSDocMigrate*.ts` inputs from the
  `//#lint:policy-fingerprint:quality` seal. Four of those files were deleted;
  `JSDocMigrateRewrite.ts` and `JSDocMigrate.schemas.ts` stay (the effected port
  runner imports them) but no quality command reaches them any more. The
  `standards/policy-tools.fingerprint.json` closure changed the same way.
- `package.json`: the root script `codex:quality-review-fix-loop` and the root
  catalog entry `@openai/codex-sdk` were removed. Neither had a caller.
- `bun.lock` was regenerated by `bun install`: `@openai/codex-sdk` leaves the
  lockfile and repo-cli no longer lists `@beep/runpod`.

## `@beep/repo-cli`

`package.json` drops the `@beep/runpod` and `@openai/codex-sdk` dependencies
(their only importers were the deleted `docgen quality-worker-eval` modules).
`tsconfig-sync` pruned the `drivers/runpod` project reference from
`tsconfig.json` and `tsconfig.check.json`. The task graph loses the
`@beep/runpod#*` upstream edges of the repo-cli tasks; nothing else changes.
`@beep/runpod` itself is kept, with its own codegen lane.

## `@beep/repo-docgen`

The package-owned extra script `docs:aggregate` now runs
`beep-cli docgen aggregate --clean` instead of the retired
`beep-cli docs aggregate --clean`. The flags are identical and both call the
same `aggregateGeneratedDocs`. This is a script-word change only.
