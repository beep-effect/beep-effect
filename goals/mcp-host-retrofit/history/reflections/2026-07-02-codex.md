# Reflection — mcp-host-retrofit (2026-07-02, codex)

## Summary

Closed out `goals/mcp-host-retrofit`: implementation and verification were
already green from the 2026-07-01 session (sanitized-span adoption in both
hosts, four-hint annotation parity, tier-gate correctly recorded
not-applicable), so this pass recorded the packet's actual shipping path
(direct user merge to `origin/main`, no PR against the declared
PR-mergeable gate), updated all packet documents and the manifest
accordingly, wrote this reflection, and cross-checked the shared
`@beep/mcp-kit` README consumer table (found and fixed a stale `uspto-mcp`
row while closing out that sibling packet in the same session).

## Tooling experience

- **Worked:** The packet's own `PLAN.md` P0 finding
  (`NlpToolkit`'s stateful tools are gate-relevant but out of Target
  Surfaces) gave a precise, pre-verified handoff to `mcp-write-wall` — no
  rediscovery needed, just cross-linking.
- **Didn't:** Nothing blocked this closeout pass — pure documentation
  reconciliation.
- **Frustrating:** Same completion-gate honesty gap as the sibling
  `uspto-mcp` closeout: no first-class manifest field exists for "shipped,
  but not via the declared gate mechanism."
- **Wished existed:** A cross-packet "shared artifact ownership" note when
  two goals' closeout checklists both touch the same file (here,
  `@beep/mcp-kit/README.md`'s consumer table) — would have caught the stale
  `uspto-mcp` row without needing a second packet's closeout to notice it.

## Implementation improvement opportunities

- Before `mcp-write-wall` wires `TierGate` into `nlp-mcp`'s dispatch, it
  must annotate more than the four named stateful tools — `TierGate`'s
  fail-closed default (unannotated = destructive) means all 21 other
  `NlpToolkit` tools need an explicit non-destructive annotation too, or
  every read call gets refused once the gate is live. This wasn't wrong to
  leave undone here (out of Target Surfaces), but the follow-on goal's scope
  needs to be sized correctly for it.

## Goal & prompt critique

- The SPEC's conditional acceptance criterion ("`NlpToolkit`, if found
  unannotated at P0") was well-designed — it let P0 discover the real
  answer (yes, unannotated) without forcing an in-scope fix, and the
  criterion could still be marked satisfied at closeout by pointing at the
  correctly-scoped deferral.

## TODOs worth codifying

- `mcp-write-wall` P0: verify whether the fail-closed `TierGate` default
  requires annotating the full `NlpToolkit` tool set, not just the four
  stateful ones.

## Lessons (confidence-tiered)

- **HIGH — Critical:** A fail-closed gate whose default is "unannotated =
  blocked" turns "annotate the write tools" into "annotate every tool in
  the gated toolkit" the moment the gate is actually wired — judge the
  blast radius of a default, not just the named targets, before scoping a
  follow-on goal.
- **MEDIUM — Best practice:** When two goals share a branch and a mutable
  artifact (a README consumer table), don't trust one goal's "done" claim
  for a row owned by a sibling goal — re-verify with a grep at closeout.
- **LOW — Consideration:** Recording a completion-gate deviation costs one
  manifest field and two sentences of prose; the alternative (silence) costs
  a future reader's trust in every other "complete" status in the file.
