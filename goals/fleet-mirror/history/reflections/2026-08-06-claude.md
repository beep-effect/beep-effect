# Reflection — fleet-mirror (2026-08-06, claude)

## Summary

Rung 1 shipped end to end in one pass: schema family → `Context.Service`
contract → three signals → `beep worktree fleet`, with the #551-shape proof
test and the two unknown-path tests from `SPEC.md`. The first live scan of the
real 17-clone / 75-checkout fleet produced correct, self-consistent output —
including the subtle cases (a branch cut from newer `main` reads `unmoved`
while stale-based rows read `moved`; detached ancestors show empty branch
diffs because prediction runs against the ground-truth merge base, which
eliminates the stale-base inflation T5 warned about).

## Tooling experience

- **Worked:** the `worktree-command.test.ts` scratch-git pattern transplanted
  cleanly; `LiteralKit` + `S.Class` + `$I` made the schema family fast to
  author; `runCapturedStreams` had exactly the env/exit-code surface the
  scanner needed; the live fleet itself was an instant integration oracle —
  one command run validated more design decisions than any amount of desk
  checking.
- **Didn't:** local `bun run check` in the CLI package is pre-noised with
  upstream TS2353 errors (see findings); v4 renames bit exactly as the
  validate-before-writing law predicts (`Effect.either`→`Effect.result`,
  `Order.string`→`Order.String`, no `Order.reverse`, no `A.isNonEmpty`) —
  every API I checked against `node_modules/effect/dist` first was right,
  every one I wrote from prior instinct was wrong.
- **Frustrating:** cleanup-on-touch pulled a full legacy-carrier migration of
  `Worktree.command.ts` into a feature PR; correct policy, real tax. The
  harness Write NUL-byte incident cost a debugging loop.
- **Wished existed:** an import-graph check surfaced at design time (the
  cycle was only discovered by a runtime TDZ crash, not by any lint).

## Implementation improvement opportunities

- Memoize merge-tree by `(headSha, targetSha)` if cadence rises (rung 2).
- The contested-path index currently spans all checkouts and relies on the
  renderer joining liveness; a `--live-only` render filter would make the
  Mode A story crisper without touching the measured snapshot.
- `dormant` is unreachable on this machine (1285/1816 `/proc` entries are
  root-owned and unreadable, so the process scan is never complete) — this is
  the binding law behaving correctly, but the ledger records it because any
  future refinement needs a measurement that does not exist today.

## Goal & prompt critique

`SPEC.md` was the best-shaped packet contract I have executed in this repo:
the acceptance criteria translated one-to-one into the test list, the
constraints section pre-answered every sharp edge actually hit (`-uall`,
`FETCH_HEAD`, `-name .git -prune`, failed probe ⇒ unknown), and the stop
conditions never needed invoking. The single revision worth making: the P0
schema-home question should have included "which module registers the
subcommand, and in which direction do imports flow" — the answer would have
sited the schemas in a leaf file on day one.

## TODOs worth codifying

- The NUL-byte write verification (findings above).
- The import-direction question as a standard line in `_template` P0 phase
  descriptions for packets that add subcommands to existing families.

## Lessons (confidence-tiered)

- **HIGH — Critical:** validate every Effect v4 API against the installed
  `.d.ts` before writing it — in this packet the miss rate for
  prior-knowledge API names was effectively 100% on renamed surfaces.
- **HIGH — Critical:** run the real thing early. The live-fleet smoke run
  found the TDZ cycle and the dormant-unreachable fact minutes after the code
  compiled; tests alone would have found the first and hidden the second.
- **MEDIUM — Best practice:** encode ignorance distinctly from facts at the
  schema level (`null` = unknown, explicit fact booleans beside it) — every
  downstream decision (render, degraded accounting, tests) got simpler
  because the distinction was structural, not conventional.
