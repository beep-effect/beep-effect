# Reflection — patent-document-schema (2026-10-05, claude)

## Summary

The goal shipped: `@beep/law-practice-domain` owns the 13 ordered patent
application sections, the independent/dependent claim union with
preamble/transition/body and missing/self/forward/cycle diagnostics, and the
one-crossing Markdown heading normalizer, and the practice-KG claims batch
consumes `PatentApplicationDocument` directly. PR #867 merged on 2026-08-30
with all 16 review threads resolved. The packet was not closed at that time,
so this reflection and the lifecycle flip land in a corrective docs PR after
re-proving the suites on current `main`.

## Tooling experience

- **Worked:** The focused package suites were a reliable acceptance oracle;
  the review bots (Codex connector, Greptile, OpenClaw) found real claim-text
  defects that the graph-level tests could not see; Yeet drove the PR to
  merge-ready.
- **Didn't:** The repair loop kept running expensive docgen behind cheap-gate
  blockers, and the scheduler status command disagreed with its skill text
  about a required flag.
- **Frustrating:** Branch-sync guidance named a removed script, and the main
  clone's install was stale after a catalog bump, so the first re-proof
  attempt failed for reasons unrelated to the schema.
- **Wished existed:** A lint that catches a merged feature PR whose packet
  lifecycle never flipped.

## Implementation improvement opportunities

- Extend the Markdown fixture with claim-text edge shapes so the raw-text
  boundary is covered as thoroughly as the dependency graph.
- Keep DOCO at generic structure; the schema already stops short of ontology
  vocabulary, and the sibling goals should consume it rather than widen it.

## Goal & prompt critique

The launcher said to "publish through Yeet and close with a reflection", but
the close step had no gate attached, so it was skipped once the PR merged.
Proposed edit to `GOAL.md`: "The feature PR is not publishable until the
manifest lifecycle flip and `history/reflections/<date>-<agent>.md` are
committed on the branch." That makes the repo's same-PR packet-state law a
precondition instead of a trailing instruction.

## TODOs worth codifying

- A goals lint that fails a packet whose completion gate requires a merged PR,
  whose evidence names one, and whose lifecycle is still `active`.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Commit the lifecycle flip and reflection on the feature
  branch before Yeet publish; a merged PR without them leaves the portfolio
  wrong for weeks.
- **HIGH — Critical:** Test the raw-text boundary of a parser with fixtures
  shaped like real documents, not only the typed graph behind it.
- **MEDIUM — Best practice:** Reinstall the checkout after a catalog bump
  before reading a test failure as a regression.
- **LOW — Consideration:** Keep friction receipts contemporaneous in
  `research/OPPORTUNITIES.md`; they made this late reflection evidence-backed.
