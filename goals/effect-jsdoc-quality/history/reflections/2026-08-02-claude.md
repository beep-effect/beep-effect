# Reflection — effect-jsdoc-quality (2026-08-02, claude)

## Summary

Ported Effect v4's JSDoc section grammar into beep law, skill posture, and
machine-checked inventory rules; proved it on the pilot trio plus a 127-tag
carrier migration; captured before/after WebStorm hover evidence from an
isolated IDE instance. All four phases completed in one branch by a Fable
orchestrator delegating every heavy phase to Codex (Sol medium) runs.

## Tooling experience

- **Worked:** `codex exec` headless delegation (P0-P3, ~100k tokens per phase);
  the P0 baseline-verification pass caught real drift (532 vs 491 `@remarks`,
  line numbers) before any edit; docgen's dual-carrier harvest meant zero new
  harvesting code; btrfs reflink clones made an isolated WebStorm instance cheap.
- **Didn't:** the jsdoc-inventory CLI and `docgen:local` both die when any
  package's module evaluation throws — a teammate's in-flight edit blocked
  repo-level verification twice; per-package generator runs were the workaround.
- **Frustrating:** JetBrains launcher single-instance forwarding silently opened
  stray project windows on the user's desktop three times before the IDE-home
  clone + `bin/idea.properties` + `XToolkit` pinning combination isolated it;
  JCEF renders black under Xvfb and had to be disabled for doc popups.
- **Wished existed:** a headless hover-render harness (see findings); a
  first-class "ignore these dirty paths, they belong to a human" mode on
  changed-files quality gates.

## Implementation improvement opportunities

- The kind-aware presence rule scopes its universe via `git ls-files`; consider
  surfacing untracked-file exclusions in the inventory report so a future reader
  understands why a scratch file is invisible to the baseline.
- `empty-section`/`malformed-example` baseline totals (85/85) are legacy debt
  worth a follow-on burn-down list per package.

## Goal & prompt critique

- The packet was excellent: pre-grilled decisions plus P0 drift-verification made
  every phase mechanical. The one gap was branch-state interaction (see finding);
  a "Branch preconditions" section in GOAL.md would have surfaced the parked
  commit's 128-tag consequence before launch.

## TODOs worth codifying

- Per-package isolation for inventory/docgen CLI dispatch.
- Committed-diff vs dirty-path split in the cleanup-on-touch gate report.
- Headless hover-evidence renderer.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Verify cited baselines (P0) before implementing a
  pre-grilled packet — two of ten packet facts had drifted, and one (the live
  inventory not being clean) changed how P2 folded baselines.
- **MEDIUM — Best practice:** When a quality gate unions committed and dirty
  paths, attribute findings to their owner before repairing; 12 files of red
  belonged to the user's parallel session and were correctly left alone.
- **LOW — Consideration:** For IDE-evidence tasks, clone the IDE home and pin
  the AWT toolkit rather than fighting single-instance forwarding with env vars.
