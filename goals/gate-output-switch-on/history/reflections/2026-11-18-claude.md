# Reflection — gate-output-switch-on (2026-11-18, claude)

## Summary

The goal landed six fixes in three pull requests on the day it graduated. Each fix switched on
behaviour a tool already had. A green test run through Turbo under an agent fell from 14,238
characters to 820, a cached one replays no test log, a subcommand help page lost its global-flag
block, two envelopes and one JSON line left stdout, and a package check on an unbuilt tree prints
one line where the compiler printed 134,905 characters. Two thresholds were set too low in the spec
and were amended against measurement.

## Tooling experience

- **Worked:** The exploration's inventory named every site by file and symbol, so each slice
  started from a verified location. Three implementer runs on three lanes in parallel kept the
  slices apart in source. `bun run beep quality package-verify` gave a short verdict per package.
  `bun run beep goals decisions add` kept decisions as files, and regenerating the blocks resolved
  every packet conflict without hand merging.
- **Didn't:** The plan's claim that the slices touch disjoint files held for source and failed for
  generated files: the root cache baseline, the decision blocks and the manifest conflicted on each
  sibling merge.
- **Frustrating:** Re-recording cache baselines. One changed script meant 207 digests in a reviewed
  request and six secret-scanner fingerprints; each base merge that touched the root Turbo config
  needed another request.
- **Wished existed:** A detached final-check under the job runner. Two host restarts cancelled
  background proofs and implementer runs that had to start again.

## Implementation improvement opportunities

- The probe runs once per package check. A root `check` through Turbo runs it in every package
  task, about 0.14 seconds each; the census could probe once and pass the result down.
- The slim entry in `bin.ts` is a second hand-written fast path beside the lint one. A small table
  of fast paths would keep the next one from growing the file's branching.
- Fixes 1 and 2 leave Turbo's own lines and the step banner. They are the remaining characters in
  both measured runs and belong to the gate-report console.

## Goal & prompt critique

- Replace fixed character thresholds with measured ones. Proposed edit to the spec template for
  this kind of goal: "the threshold is recorded in P0 from a run on the lane, then fixed".
- Replace "P1, P2 and P3 touch disjoint files" in the plan with "disjoint source files; they share
  the root cache baseline and the packet's generated blocks, so each later slice merges the earlier
  ones before it publishes".
- The launcher did not say which pull request closes the goal. Naming the last slice as the
  closeout carrier up front would have saved deciding it mid-run.

## TODOs worth codifying

- A rule form for cache baseline requests and a rebase mode for base merges.
- A final-check preface that lists the gates a repo-wide diff leaves to hosted CI.
- A goals command that sets one phase status and validates the literal.
- Inherited-row marking in the coverage regression summary.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Measure before fixing a number in a criterion — two of ten criteria needed
  an amendment because their targets were estimates.
- **HIGH — Critical:** Treat generated files as shared surface when slicing a goal — every sibling
  merge in this goal conflicted in a generated file and never in source.
- **MEDIUM — Best practice:** Open the closeout pull request as a draft, record the closeout that
  names it, then run the final proof once — the record needs the number, and the proof needs the
  final head.
- **LOW — Consideration:** Keep a fast path for any command a generated script calls on every run —
  loading the whole CLI would have added about half a second to each package check.
