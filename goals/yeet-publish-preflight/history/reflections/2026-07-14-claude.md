# Reflection — yeet-publish-preflight (2026-07-14, claude)

## Summary

Shipped exactly the two-scoped fixes as PR #402 (squash `31bedfeac1`,
merged 2026-07-14): `publish:00-head-install-preflight` — a frozen-lockfile
install in a detached temp worktree of committed HEAD, wired into verify's
full tier and every publish push path with guaranteed, warning-on-failure
cleanup — and a fail-fast guard making `--start-pr-early` require `--pr`.
Codex (gpt-5.6-sol medium) implemented from the packet SPEC in one lane;
Fable reviewed, fixed two law violations the full proof caught, and drove
three full-proof publish cycles to green. The preflight's first live run
gated its own PR's push (~7s on a warm bun cache).

## Tooling experience

- **Worked:** the packet's P0 probe-first posture (incident partially
  stale; probe redirected the fix); centralized step dispatch made the
  preflight execute identically in verify and publish; per-lane
  `durationMs` landed as a free bonus; the stale-base gate caught a real
  INDEX conflict before push.
- **Didn't:** plain `git push` after a rebase — a green 20-minute proof
  followed by a non-fast-forward rejection, twice; manual
  force-with-lease was the fallback.
- **Frustrating:** repair hints misrouted on every failed proof (3/3);
  the failed-step log was the only reliable diagnosis surface.
- **Wished existed:** a fail-fast "this push will be non-fast-forward"
  check before the full proof starts.

## Implementation improvement opportunities

- Plan-mode guard parity sweep (P0 found PR validation skipped in plan
  mode).
- A unit test forcing `git worktree remove` failure to pin the cleanup
  warning path (Greptile's one finding; fixed but untested).
- Hint-selection fix in IssueClassification: prefer needles found in the
  failing step's own output (the module gained exactly such a needle for
  the preflight — the mechanism exists).

## Goal & prompt critique

SPEC was execution-grade and the scope guard held (canvas CI lane and
CauseTaggedError sweep stayed out despite adjacency). One addition for
next time: name the *generated-config* consequences of the fix surface in
SPEC (goals INDEX regen on rebase collided twice with concurrent packet
PRs; predictable, and the resolution — regenerate, never hand-merge — was
rediscovered rather than pre-declared).

## TODOs worth codifying

See frontmatter `todos`. Highest leverage: rebased-branch push support
(saves a full proof cycle per rebase), then hint-misrouting.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Probe before plumbing, again: the motivating
  incident's failure mode had already been half-fixed by an intervening
  change; only the P0 matrix kept the fix honest.
- **HIGH — Critical:** The repo-global lint is the real law surface —
  effect-fn and goals-doctor violations sailed through per-package checks
  and 77/77 tests; budget for a full-proof green-up pass after any codex
  lane, and read the failed-step log, not the hint.
- **MEDIUM — Best practice:** Generated files (goals/INDEX.md, fallow
  boundaries, tsconfig references) should never be hand-merged in a
  rebase — regenerate from the rebased tree and continue.
- **LOW — Consideration:** Dogfooding a gate on its own PR (the preflight
  gating its own push) is cheap, satisfying evidence — prefer landing
  operator gates via the path they guard.
