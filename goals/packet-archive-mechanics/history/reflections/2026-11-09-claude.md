# Reflection — packet-archive-mechanics (2026-11-09, claude)

## Summary

The sweep took terminal packets off `main` in six batches. The public archive holds 189 goals and 76 explorations, every batch's tree hashes verified on the remote, and `main` keeps tombstones for 186 goals and 76 explorations. Seven packets stay whole on `main` because this sweep's scans found live code reading them: four goals and three explorations. The archive also holds copies of three of them, from batch 4. The verdict is mixed: the outcome is sound, but too many batches depended on hosted CI to find what a better preflight would have found in minutes.

## Tooling experience

- **Worked:** `--plan` and `--expect` made each write reproducible. Hash verification against the remote gave a real guarantee. `knowledge:semantic-delta` showed the rewriter working, with 0 introduced in every batch from 3 on. Refusing to archive a packet with a `retentionReason` made retention simple to apply.
- **Didn't:** the literal consumer scan found paths but could not say whether anything opened them. It also skipped hidden paths until I added `--hidden`, and it could not see links wrapped across two lines. Worker `final-check` passed on heads that hosted CI later failed.
- **Frustrating:** heavy jobs queued for hours, so each mistake cost a long cycle. T3 repeatedly dropped PR watches on this host. `t3_thread_send` to the hub returned `thread_not_found`, so a decision I sent never arrived. `gh pr checks` shows cancelled jobs as `fail`, which I misread once.
- **Wished existed:** a single tombstone preflight, and a plan report that separates citations from live reads.

## Implementation improvement opportunities

The rewriter needed three fixes after first contact with real data: code spans in link text (#2979), tracked symlinks, and wrapped links (both in #2989). Each had a fixture gap that real documents exposed, so a plan-only run over the whole tree before merging #2979 would have found all three. Inbound rewrites are not atomic, which left two files changed when the symlink case stopped a write. The planner should also report document budgets.

## Goal & prompt critique

The batching and the archive-first invariant were right, and hash verification should stay. The GOAL understated retention: "every terminal packet is tombstoned" conflicts with packets that remain live, and I treated moving their files as the default for too long. Moving a file out of `goals/` loses exemptions from secret scanning, the IRI law and the shell law, so retention should have been my first answer. I also made mistakes the GOAL could not have prevented: I pushed batch 4's archive before running its gates, and a bug in my own memory guard reported a false pass, which I caught by reading the report.

## TODOs worth codifying

See `todos` above. The most valuable is the tombstone preflight, because it would have prevented most of the hosted red cycles in this sweep. This goal does not retire the three archived-and-retained copies; they are harmless, and the decision files record them.

## Lessons (confidence-tiered)

- **HIGH:** A terminal status says the work ended, not that nothing reads the files. Check for live readers first, and retain by default when something does.
- **HIGH:** Push public, append-only artifacts after every gate that could change what should be published.
- **HIGH:** Read the check that actually ran. An exit code from a pipe, a watcher on the wrong process and a cancelled job shown as `fail` each misled me here.
- **MEDIUM:** Secret scanning reads commits, so removing a file from the tree does not clear a finding. Recommit on a new branch rather than force-pushing.
- **MEDIUM:** Compare a finding against clean `main` before calling it inherited. That settled #2966's 13 findings with evidence.
- **LOW:** Before rewriting a citation in an active goal, consider a shorter pointer such as a tombstone README; it survives the budget and still leads to the archive.
