# Cache baseline review: 3-A6 (`TsconfigValidator` and docgen onto `@beep/repo-tsconfig`)

Reviewed 2026-10-28 for adoption PR 3-A6 of `goals/effected-promotion` (wave-3 plan 3-A6, wave-4 plan PR sequence;
map sites #160, #161, #242, #266).

`bun run beep quality cache-policy` is expected to report configuration drift on `@beep/repo-docgen` (`#build`,
`#check`, `#test`, `#test:property`, `#lint:deprecated-apis`), all introduced by this branch and all of one kind; the
`cache baseline --request` run (`research/cache-baseline-request-3-a6.json`) is the remaining step of this review: the
implementing session ended before the repo-wide lint pipeline released the checkout.

The cause is one manifest edit, `packages/tooling/tool/docgen/package.json`:

- `dependencies` gains `"@beep/repo-tsconfig": "workspace:^"` and `"@beep/tsconfig": "workspace:^"`. docgen
  `Configuration.readTSConfig` reads a named tsconfig through `TsconfigValidator.compilerOptions`,
  `CompilerOptionsShape` is `S.toEncoded(ClosedCompilerOptions)`, and `encodeExamplesTsconfig` renders the examples
  `tsconfig.json` through `TsconfigValidator.validate` and `StrictTsconfig`.
- `devDependencies` gains `"@beep/memfs": "workspace:^"`: the tsconfig-path tests in `test/Configuration.test.ts` seed
  a real virtual filesystem, since `TsconfigValidator.compilerOptions` walks the named file's `extends` chain.

The scripts block is unchanged. `bun run beep tsconfig-sync --write` added the matching project references to the
package's `tsconfig.json` and `tsconfig.check.json` and regenerated `standards/fallow.boundaries.generated.jsonc`;
`bun.lock` records the three workspace edges. No third-party dependency is added. `@beep/repo-utils` loses a module
(`src/schemas/TSConfig.ts`) and no dependency.

## Turbo coupling, measured against current main

Measured from the workspace `dependencies` closures at the lane base `931e52792e` (origin/main) and at this branch
head:

- `@beep/repo-docgen`: 20 workspaces before, 22 after; it gains `@beep/repo-tsconfig` and `@beep/tsconfig`
  (`@beep/walker`, `@beep/jsonc`, `@beep/identity` and `@beep/schema` it already reached through `@beep/config-file`
  and `@beep/repo-utils`). An edit to either package's `src/**` now invalidates docgen's `#build`, `#check` and
  `#test` entries.
- No other workspace gains a closure member: docgen's only workspace dependent is `@beep/repo-cli`, which already
  depends on both packages (3-2, 3-A5).

The coupling is accepted: `@beep/repo-tsconfig` is the one owner of tsconfig reading and of the strict model (D-09,
W3-c), and `@beep/tsconfig` is the pure document model docgen's compiler-option shape is now defined from.

The root subject moves: `bun run beep lint policy-fingerprint --write` adds `packages/foundation/modeling/tsconfig/**`
and `packages/tooling/library/repo-tsconfig/**` to the fingerprinted docgen closure (`standards/policy-tools.fingerprint.json`).
