**Steps:**

2. **`FsUtils.runGlob` becomes an adapter over walker + glob:**
   - Each include pattern is compiled with `GlobPatternOptions.make({ dot })` and expanded with `descend(p, { cwd: path.resolve(cwd ?? "."), prune, followSymlinks: false, onUnreadable })`.
   - Ignores are compiled with dot true as `p` OR `p/**`.
   - Results are concatenated, deduplicated, sorted with `Order.String`, and absolutized when `absolute: true`.
   - `prune` is derived from ignores shaped `**/<literal>/**` and is otherwise `[]`, because the walker default prunes `node_modules`/`.git`.
   - Errors map to `DomainError`.
   - The `SharedGlobLayer` merge is dropped and the `FsUtilsShape` signatures are unchanged.
3. **`Workspaces.ts:159`** stops relying on directory results: it calls `globFiles(\`${ws}/package.json\`)` and then takes `dirname`, with `followSymlinks: true` so symlinked workspace dirs survive. Directories without a manifest were already skipped (:185-190). `FsUtils.glob` keeps `nodir: false` only if walker gains directory emission; otherwise mark it deprecated in favour of `globFiles` in the same PR.
4. **Utils tests:** move the `Glob.test.ts` assertions that still apply (GlobError, GlobOptions and the matching cases) to their new owner in `@beep/glob`/`@beep/walker` tests, unweakened, before deleting the file (SPEC: promoted tests are retargeted, never deleted). ### Colour precedence ruling (new decision, next free D-number; refines D-14)

`@beep/runtime-env` `ColorLevel.fromEnv` is the only colour-level decision in the repo. Order:

1. `FORCE_COLOR` present decides alone and exactly: `''`/`1`/`true` give basic, `2` gives 256, `3` gives truecolor, anything else (`0`, `false`, `4`, `" 2 "`) gives none. It beats `NO_COLOR`, argv flags and TTY.
2. Argv flags, consulted only by `@beep/chalk` (`sniffFlags`) and `@beep/colors` (`--no-color`), and only when `FORCE_COLOR` is unset. Each maps to a FORCE_COLOR-equivalent exact level (`--no-color` family gives none, `--color=16m` truecolor, `--color=256` 256, `--color` basic).
3. `NO_COLOR` / `NODE_DISABLE_COLORS` (non-empty, per no-color.org) or `TERM=dumb` give none.
4. A stream that is not a TTY gives none. CI alone never enables colour.
5. The Node table: `OS=Windows_NT` gives truecolor; `TMUX` truecolor; Azure basic; CI vendor rows (GitHub/Gitea/CircleCI truecolor, others 256, generic CI none); TeamCity; `TERM_PROGRAM`; `COLORTERM`; `TERM` table/regex.
