# Cache baseline review: roadmap PR R2a

Reviewed 2026-10-28 for roadmap PR R2a of `goals/effected-promotion` (the root `vitest.setup.ts` Bun.Glob
shim onto `@beep/glob`, with `toml` and `picomatch` leaving the root; W4-p).

`bun run beep quality cache-policy` reports 0 blocking findings on this branch, before and after the edits.
The baseline is recorded anyway because the PR changes two inputs the policy does not surface as drift: the
root manifest (`//`) and `vitest.setup.ts`, a global test input.

## The root manifest

`package.json` loses three entries from `devDependencies` and the same three from the root catalog:
`toml` (`^5.0.1`), `picomatch` (`^4.0.7`) and `@types/picomatch` (`^4.0.3`). Their only consumer was the
Bun shim in `vitest.setup.ts` (`Bun.TOML.parse` over `toml`, `GlobShim.match` over `picomatch`); nothing
under `packages/`, `apps/` or `scratchpad/` imported either. `devDependencies` gains `@beep/glob`
(`workspace:^`) beside `@beep/utils`, because the shim now compiles its patterns with `GlobPattern` and the
root `tsconfig.configs.json` project types the file. No scripts block changes (`bun run beep lint
package-scripts` is untouched), no third-party dependency is added, and `bun run beep quality catalog-usage`
reports no orphaned catalog entry. `bun.lock` was regenerated by `bun install`: `toml@5.0.1` and
`@types/picomatch@4.0.3` leave it; `picomatch@4.0.7` stays as a transitive of `vite`, `tinyglobby` and
`fdir`; and Bun 1.4.4 re-serialized the `systeminformation@5.33.14` entry's `os` field (the #2341 pin) in its
own spelling. `bun run beep lint policy-fingerprint --check` is unaffected: the root is not a fingerprinted
closure.

## The global test input

`vitest.setup.ts` is listed under `$TURBO_ROOT$` in every `turbo.json` test, coverage and doctest task
(global test input), so this edit moves the `#test`, `#test:property`, `#coverage` and `#doctest` cache keys
of every workspace once. That is the point of carrying the `toml` removal and the `picomatch` swap in one PR
(plan Blocker 6: "R2a carries toml and picomatch together, once"). The file's observable behaviour for Node
runs changes in two places, both pinned by `packages/tooling/tool/cli/test/vitest-bun-glob-shim.test.ts`
on Bun and Node: the matcher (identical over the census in `research/glob-shim-census-r2a.json`, closer to
`Bun.Glob.match` on trailing `/**`) and the `scanSync` `onlyFiles` default, now `true` like Bun's.

The new import also has a per-file cost: `@beep/glob/GlobPattern` brings `@beep/schema` and `@beep/identity`
into the setup graph that every test file evaluates. Measured on repo-cli `test/foundation-topology.test.ts`
(four warm runs each, alternating `main` at `2c1ff256c1` and this lane, vitest's own setup share of the
reported duration): Node 190-233 ms before against 210-240 ms after, about +25 ms of setup per test file;
Bun 140-160 ms before against 140-170 ms after, within the run-to-run noise. Over the repo's ~5,800 test
files that is a few minutes of aggregate worker time on the Node lane of a full proof and nothing measurable
on the Bun lane; it is recorded here as part of the global-test-input review and is not a reason to hold
the one-time key move.

## Turbo coupling

Measured on this branch at `f77a32de6d` (the lane's base, current `origin/main`) by walking the workspace
dependency closure (dependencies, devDependencies, peer and optional, `workspace:` specifiers only) of every
manifest:

- The root (`//`) closure grows from 11 to 12 workspace packages: `@beep/glob` is the one addition. Its
  own dependencies (`@beep/identity`, `@beep/schema`, `@beep/utils`, and `@beep/fc-runs` as a
  devDependency) were already in the root closure through `@beep/repo-configs` and `@beep/utils`.
- No workspace depends on the root, so no other closure changes. `@beep/glob`'s dependents are unchanged.

Recording the root subject accepts the dependency-only edit of the root manifest and the one-time key move
of the global test input. No qualification is granted, and no other subject changes.
