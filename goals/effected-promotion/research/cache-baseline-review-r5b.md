# Cache baseline review: roadmap PR R5b

Reviewed 2026-10-31 for roadmap PR R5b of `goals/effected-promotion` (the
slugger and table-of-contents builder in `@beep/markdown`, `@effect/markdown-toc`
out of docgen, repo-cli and the root catalog; SPEC W4-h and W4-i, R5b parts).

`bun run beep quality cache-policy` reported 9 blocking findings, all
introduced by this branch and all of one kind: configuration drift on
`@beep/repo-docgen` task tuples (`#build`, `#check`, `#lint:deprecated-apis`,
`#test`, `#test:property`) and on `@beep/effect-drizzle` task tuples (`#build`,
`#check`, `#lint:deprecated-apis`, `#test`).

The manifest edits are two workspace edges and one removal:

- `@beep/repo-docgen` gains `@beep/markdown` (`workspace:^`) as a runtime
  dependency and drops `@effect/markdown-toc` (`catalog:`), because
  `Core.getModuleMarkdownFiles` renders the module page TOC through
  `MarkdownToc.render` instead of the npm package.
- `@beep/effect-drizzle` gains `@beep/markdown` (`workspace:^`) as a
  devDependency only (ecosystem polarity: no `@beep` runtime edge), because
  `packages/ecosystem/effect-drizzle/scripts/assemble-readme.ts` strips docgen
  frontmatter through `FrontmatterSource.split`.
- The root catalog drops `@effect/markdown-toc`; no package consumes it any
  more. `bun.lock` loses 51 entries (the package, its dependency tree such as
  `remarkable`, `gray-matter`, `diacritics-map` and `lazy-cache`, and the
  nested version keys it pinned) and re-keys three (`fill-range`, `is-number`,
  `systeminformation`) at their already-resolved versions, from a plain
  `bun install`; no third-party package enters.

The scripts blocks are unchanged (`bun run beep lint package-scripts` reports 0
drifting manifests), and so are both packages' `turbo.json` files. The generated
`tsconfig.json` and `tsconfig.check.json` references of both packages and
`standards/fallow.boundaries.generated.jsonc` were regenerated by
`bun run beep tsconfig-sync`.

Turbo coupling, measured over the workspace manifests:

- `@beep/repo-docgen`: no closure grows. `@beep/markdown` was already upstream
  through `@beep/md` (a repo-docgen runtime dependency that lists
  `@beep/markdown` among its own runtime dependencies); the edge becomes
  direct, so the recorded repo-docgen task tuples now name `@beep/markdown`'s
  tasks among their direct dependencies, and no package enters any closure
  that did not already reach it.
- `@beep/effect-drizzle`: the dev closure grows by `@beep/markdown` and its two
  runtime dependencies that effect-drizzle did not already reach,
  `@beep/toml` and `@beep/yaml` (`@beep/identity`, `@beep/jsonc`,
  `@beep/schema` and `@beep/utils` were already upstream through
  `@beep/repo-utils`). The edge is a devDependency, so the published package
  and its runtime graph are unchanged; the recorded effect-drizzle task tuples
  gain the three packages' `#build` and `#transit` tasks.

`@beep/markdown` itself gains two source modules and no dependency, so its
own tuples do not drift. No other workspace's dependencies change, and
`bun run beep lint policy-fingerprint` reports the fingerprint current.

Recording these two subjects accepts the existing posture for
`@beep/repo-docgen` with its one new direct dependency and for
`@beep/effect-drizzle` with its one new dev dependency. No qualification is
granted, and no other subject changes.
