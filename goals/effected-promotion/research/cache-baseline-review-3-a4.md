# Cache baseline review: 3-A4 (package.json readers onto `@beep/package-json`)

Reviewed 2026-10-24 for adoption PR 3-A4 of `goals/effected-promotion` (wave-3 plan 3-A4, wave-4 plan PR sequence;
map sites #130-#135, #143, #277, #307).

`bun run beep quality cache-policy` reported 11 blocking findings, all introduced by this branch and all of one kind:
configuration drift on `@beep/repo-cli` (`#build`, `#check`, `#doctest`, `#lint:deprecated-apis`, `#test`,
`#test:property`) and on `@beep/repo-docgen` (`#build`, `#check`, `#lint:deprecated-apis`, `#test`, `#test:property`).

The cause is two manifest edits, one regular dependency line each:

- `packages/tooling/tool/cli/package.json` gains `"@beep/package-json": "workspace:^"`. repo-cli's projection readers
  (ChangesetGraph, ChangesetStatus, PackageVerify, QualityArtifactSupport, Tasks, CatalogUsage, BunResolver,
  RootCatalog, PackageTestTypecheck, EffectSchemaInventoryModules) now read through `LenientManifest`, and the
  VersionSync updaters edit through `PackageJsonFormat`.
- `packages/tooling/tool/docgen/package.json` gains the same line. docgen `Configuration.ts` and `Version.ts` read
  through `PackageJsonFile`.

The scripts blocks are unchanged. `bun run beep tsconfig-sync` added the matching project references to both packages'
`tsconfig.json` and `tsconfig.check.json` and regenerated `standards/fallow.boundaries.generated.jsonc`; `bun.lock`
records the two workspace edges. No third-party dependency is added.

## Turbo coupling, measured against current main

Measured from the workspace `dependencies` closures at `origin/main` bda2713db8 and at this branch head:

- `@beep/repo-cli`: 62 workspaces before and after. repo-cli already reached `@beep/package-json` and its whole
  closure through `@beep/observability` (3-A9), so the new direct edge adds no task and no closure member.
- `@beep/repo-docgen`: 16 workspaces before, 20 after; it gains `@beep/package-json`, `@beep/npm-spec`,
  `@beep/semver` and `@beep/spdx` (`@beep/identity` and `@beep/jsonc` it already reached through `@beep/config-file`).
  An edit to one of those four packages' `src/**` now invalidates docgen's `#build`, `#check` and `#test` entries.
- No other workspace gains `@beep/package-json` in its closure: docgen's only workspace dependents are repo-cli, which
  already had it.

The coupling is accepted: `@beep/package-json` is the one owner of package.json reading (W3-f), and the four modeling
packages were promoted as stable, low-churn kits.

The root subject is untouched: `bun run beep lint policy-fingerprint --write` reports no change, because repo-cli's
policy-tool closure already contained all four packages.
