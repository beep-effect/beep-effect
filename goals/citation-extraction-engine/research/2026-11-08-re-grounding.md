## Diagnosis

The algorithm was informed by official eyecite, two TypeScript donors and
source-derived fixtures. The strategy expanded to exhaustive cross-runtime
observable compatibility and accounting before a matched product comparison
established which behavior and implementation the product actually needed.
Python object/hash/debug semantics, arbitrary callbacks and HTML reconstruction
could consume effort without a measured improvement in the six citation forms.

The old completed-event count measures accounting closure, not accuracy, recall
or the proportion of useful functionality delivered. Test-suite duration and raw
source line counts are cost signals, not comparable throughput or correctness
measurements. Do not infer implementation absence from a stale phase table, or
goal runtime from the age of the design packet.

Owning domain schemas does not require owning the parsing algorithm. An
Effect-native boundary can capture an existing parser while retaining typed
schemas, errors, resource ceilings and source verification. Check the available
Effect modules and configuration levers before introducing custom machinery. A
dependency and a vendored copy of the same synchronous regex require the same
real interruption boundary.

The [nine-case operability
screen](../history/evidence/2026-11-08-six-form-smoke/README.md) used existing

- Official eyecite 2.7.6: Pin: 04d82c032ad5fd0f9ab72a61c87110c46ee8f52e

- eyecite-ts 0.34.2: Pin: 34133d03143ea65861f48a5ed0eb32c931581666

- eyecite-js 2.7.6-alpha.28: Pin: 53a49f2412da668aaf262e5f92584c2c3781043b

All three recognized the anticipated broad families on one example of each
six-form input, emitted nothing on a simple negative, handled an astral-prefix
range after Python offset conversion, and emitted two mentions on a full-case
and Id. context pair. All normalized ranges were bounded valid UTF-16 slices.
These are import/basic-recognition results, not accuracy, metadata correctness,
local linking, deployment-runtime, resource or performance proof. The current
native Beep Layer was not measured in this screen. One-pass timings must not
rank candidates.

Actual mapping differences justify defining the contract before comparison:

- Python's supra span excludes the preceding name; both TypeScript spans include
  it. This is not automatically an extraction error.
- Python and eyecite-js distinguish core Id. token text from the pin-inclusive
  citation span. A donor text field is not automatically the verified quote.
- C.F.R. fields use different layouts. Joining or mapping part/section fields
  incorrectly can turn section 1.56 into section 56.

## Adversarial corrections

Claude and Grok independently reviewed the completed reports and the screen.
Kimi's report was available, but quota prevented its debate reply. These are
expert judgments and concessions, not independent experimental proof.

1. Grok withdrew vendoring as an inherent safety advantage. A whole pinned
   dependency can run in a killable boundary; copying a pattern does not make it
   linear or interruptible. Vendoring needs a concrete maintenance reason.
2. Grok withdrew full-case-only extraction as fulfillment of six-form v1. A
   small full-case screen cannot replace short/Id./supra/U.S.C./C.F.R.
3. Claude withdrew expansion into a check-report product, authority lookup, paid
   CourtListener access, claim-support gates and citation-residue heuristics.
   Extraction was always a component of the larger grounding program.
4. Claude withdrew invented latency/accuracy/timebox thresholds and the large
   corpus program as immediate acceptance gates. Retain real resource ceilings;
   calibrate consumer needs from evidence rather than another large checklist.
5. Version labels, stars and suite counts do not establish a TypeScript donor's
   failure. Build, artifact provenance, data attribution and maintenance remain
   real integration concerns to inspect on the selected artifact.
6. Kimi's TypeScript-first preference does not justify discarding the existing
   native path unmeasured. Test its actual public Layer before requiring
   pruning. Candidate-only span verification is not automatic citation
   discovery.

current implementation and history until that choice is supported. Do not start
