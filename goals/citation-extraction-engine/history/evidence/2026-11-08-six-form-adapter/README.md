## Proposed implementation direction

Implement the TypeScript recognizer behind the existing domain and proof model.
Keep the existing resolver and physical process owner, addressing its substring
party matching before claiming the strict profile rule. Do not add another
citation hierarchy, identity scheme, scheduler or general resolver. Production
dependency adoption still needs an explicit recorded decision and attribution.
The existing engine has been measured and is preserved; no API is retired here.

The Effect 4.1.2 source audit identifies RpcServer.layerProtocolStdio and
RpcSerialization.layerSchemaBinary as supplied transport/codec machinery.
RpcClient.Protocol.make provides the narrow parent process-stream adapter point.
ChildProcess killSignal and forceKillAfter configure shutdown; the existing
owner supplies separate physical-exit observation and quarantined permits.
NodeWorker/BunWorker have a hardcoded five-second graceful policy in this version.
The archived audit cites installed source and records the concrete gaps. Reuse
these provided facilities; the historical custom framing is not the starting
point. Actual transport and resource-control acceptance remains open.
