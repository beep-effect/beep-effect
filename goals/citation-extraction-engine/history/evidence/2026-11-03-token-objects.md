# Native token objects and actual mixed assembly host

The private token store represents all nine built-in source token classes with
native data/groups, source-point spans, edition handles and short-cite state.
The first-capture constructor accepts normalized group-one data/span and the
complete named group dictionary, then applies the source offset. Raw regex
result selection and extra-argument normalization remain a separate binding
obligation; this is not a claim of a complete custom TokenExtractor adapter.

Source group equality ignores key insertion order while preserving missing
versus null keys and scalar versus literal-surrogate words. Schema-derived
record equivalence uses upstream Effect Bytes equivalence over canonical native
storage; Effect Bytes also provides owned buffer copies. Effect HashMap owns
local identities and Semaphore serializes compound mutations. Candidate and
retained data/group UTF-16 budgets are cumulative across the store. Native byte
copy size is checked before snapshotting, and failed construction does not
publish an identity. Caller mutations and snapshot mutations cannot alter state.
Captured deadlines wrap permit acquisition as well as operation execution.

Base merge compares start/end, exact built-in class and groups while ignoring
data equality. It returns the left identity even if that token is empty; this
is distinct from None. Citation merge additionally evaluates the base token's
truth, checks short state and updates exact/variation sets through the existing
edition adapter. The assembly-facing truth method retains the source's separate
return-identity and truth behavior, including closed failure for invalid None
truth. General custom subclasses, field mutation and arbitrary group values
remain outside this current private profile and are unfinished goal duties.

## Independent proof

The producer verifies the exact clean oracle commit/tree and Python 3.11.15.
Actual source from_match runs for each of nine classes, eleven match witnesses
and offsets zero, seven and minus three: 297 cases. These include unmatched and
empty group one, group-one versus full-match selection, null named groups,
astral and literal-surrogate input, NUL, Unicode names and __proto__ keys.
Target normalized first-capture construction matches every resulting field.

Actual source merge runs in 216 cases across all nine classes, nonempty/empty/
None data, unequal data, reordered groups, changed native words, missing versus
null keys, changed spans/classes and short-cite controls. Target return identity,
None/error outcomes and separate truth results all match.

The existing 407 mixed assembly cases now create eight actual target token
objects per case and use their read/merge/nominative methods. Their 1,247 source
host decisions are expected results, no longer replayed returns. Exact mixed
items and special-token indices still match. Edition facts are bound to the
existing captured runtime profile; the prior 89 source set-order and 42 choice
controls remain required. Text gaps use the real target text planner. This does
not claim general native gap ownership from the ASCII assembly witnesses.

Ten focused object/assembly/edition/text tests pass, retaining all 1,561 text
cases. Ownership, snapshot independence, cumulative ceilings, failed-publication
and captured-clock controls pass. Quick server lint/type checks, scoped Oxlint
and zero-finding new-only Fallow pass. Both token-object and expanded assembly
fixture regeneration are byte-identical after formatting. Latest-head hosted
proof remains pending; full source extraction is not inferred from these cases.
