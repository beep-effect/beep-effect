# Issued default branch observations and ambiguity data

Date: 2026-10-29. Private default callbacks now capture the branch that actually
returned None, and document projection consumes that issued evidence. Public
engine integration and exhaustive resolver proof remain unfinished.

## Observation ownership

CallbackObservations binds an immutable schema-encoded observation to the exact
callback result object in a private WeakMap. The result retains its existing
resource-only shape; no function or diagnostic selector enters request data. A
copied result does not carry issuance. Reusing it for another occurrence does
not transfer its evidence. Custom callback results without issued evidence
retain callback-unresolved. A wrapper that replaces None with a chosen resource
does not attach the old None observation to its chosen result.

The dispatcher captures the observation before structurally copying the result.
It includes the evidence in the sealed session image and validates occurrence
coherence, None-only evidence and registry-origin closure for candidate
resources. Final presentation refreshes use the existing pure view operation;
there is no added native truth/hash/equality call. Candidate arrays preserve
matched prior-full order rather than inventing a chosen result or membership.

Default callbacks record missing-antecedent for absent supra/name fields,
no-matching-authority for zero candidate resources, no-previous-authority when
Id. receives a falsy prior result, and invalid-pin-cite when its actual pin
check rejects. Source unknown/no-callback results remain unsupported-citation.
These reasons describe observed branches; no cause text or confidence is
invented.

Ambiguity records the distinct resource count from the candidate set already
executed by matching and the matched resource references. It never reruns that
set to explain a None return. The short-case first-set/refinement sequencing
remains unchanged. Candidate evidence is neither a successful decision nor a
successful append destination.

## Projection and current boundary

A supported ambiguity becomes CitationAmbiguous with distinct authority labels,
absent confidence and no assignment. The projector interns candidate labels into
the same catalog, while bindings keep their chosen decisions and group
memberships separate. Candidate-label order follows first matched occurrence;
Python's hidden helper set iteration order is not exposed as an output law.
Receipts and trusted bindings restore all tested ambiguous documents. Candidate
positions are explicit out-of-band resource-binding expectations, separate from
chosen decisions and final group membership. Legacy bindings may omit this field
only when they expect no candidate positions. Restoration checks exact
occurrence/position ownership and rejects reordered candidates or missing
expectations with stale-authority. This does not reexecute matching. Candidate
references also share the graph edge budget with member-list edges; the
persistent receipt boundary includes them in its hard maximum. A two-full,
two-candidate control rejects a ceiling of three and accepts exactly four.

Native distinctness at callback time cannot certify that final pure descriptors
still distinguish those resources. A control deliberately supplies one label for
every candidate and proves the projector rejects identity-failed rather than
claiming a valid two-authority ambiguity. Likewise, candidate None values or
unavailable host descriptors cannot manufacture authority labels. General
historical candidate identity, later semantic mutation and arbitrary host
normalization remain open. This conditional boundary is not a semantic waiver or
a completed public behavior claim.
