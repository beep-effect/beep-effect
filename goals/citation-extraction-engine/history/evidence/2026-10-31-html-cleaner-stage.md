# Native HTML stage and intermediate input bounds

Date: 2026-10-31. Scope: captured Unicode-text HTML composition with the private
cleaner ledger, before complete live registry ownership or global admission.

## Intermediate preparation and framing

Raw HTML input preparation and the supervisor's raw clean method retain their
original source allowance. The new internal preparation method accepts already
owned intermediate text up to the frozen eight-million-unit produced-text
maximum. It scans cooperatively to determine the pinned Python representation,
wrapper classification and exact native byte length before allocating bytes.

A schema-owned layout carries only encoding, wrapper mode and byte count. A
captured server callback uses that layout to check the complete worker job before
the preparation allocates its native payload buffer. It encodes the small header
with the actual job codec, adds exact padded base64 length and the terminal LF,
and rejects excess processMessageBytes. The ordinary job encoder repeats the
same check before base64/JSON allocation and verifies the final encoded length.
No callback becomes a request field. The raw standalone preparation helper
continues to enforce its original payload-only contract.

An exact request ceiling succeeds and one byte less fails. A valid intermediate
of 7,999,998 ASCII units plus one supplementary character has eight million
UTF-16 units and 31,999,996 native bytes. The metadata preflight rejects its
complete frame against the frozen 32,000,000-byte channel ceiling before payload
allocation. This is an explicit existing safety failure, not invalid input or
silent truncation. Existing cooperative scans and captured clean timing remain.

## Shared capacity and process retirement

The supervisor's internal stage method borrows the cleaner ledger's remaining
output capacity exclusively. It sends that natural-number allowance, including
zero, in the native job. The kernel checks selected UTF-16 text before allocating
its result. The parent validates the complete bounded reply and acknowledges
child exit before returning text to the ledger for exact charge settlement.
A schema-owned stage result preserves original live charge tickets; creating
or decoding matching ticket data does not issue spending authority.

The composed test starts with a one-unit source allowance, reserves a legitimate
1,000,003-unit intermediate, and returns the exact same full text from HTML.
Cumulative production is exactly 2,000,006 units. This input uses 4,000,008 native
UTF-32 bytes and therefore exercises the widened native path. An independent
signal-zero check confirms that its child exited. A 1,000,028-unit script-only
intermediate consumes the complete production budget and still cleans to empty
at zero remaining capacity. A one-unit visible intermediate under the same zero
allowance fails explicitly without a partial result. Raw input still observes
the original source allowance.

A separate composed cancellation test waits until an injected process worker is
actively busy, interrupts the enclosing pipeline, and checks interruption,
closed work, zero worker ownership/admission and an independent child PID probe.
The busy fixture exercises process ownership; existing worker tests separately
cover infinite WASM execution. The retirement/quarantine supervisor remains the
owner of unresolved native work;
this ledger adapter does not claim that a logical allowance proves process exit.
