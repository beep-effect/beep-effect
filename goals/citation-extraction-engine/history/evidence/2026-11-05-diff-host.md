# Shared restricted WASM host and exact default-diff adapter

Historical host checkpoint: the subsequent [owned-worker receipt](2026-11-05-diff-worker.md)
records transport integration, an emission-bound ABI addition and the current
binary digest. This receipt retains the original host proof and its limitations.

The private Effect host authenticates a copied asset before compilation and
captures Digest during installation. Its run method has R=never and accepts
only schema-decoded native data and effective count limits. The method borrows
immutable child-owned inputs; it does not establish source ownership itself.
The existing native Unicode validator checks canonical widths, alignment,
valid point values and the combined effective UTF-16 ceiling before allocating
native inputs. Source-point copying preserves NULs and literal surrogate points.
Returned operation/count pairs are schema-decoded, and the existing span-step
fold verifies complete consumed/emitted lengths. A fresh instance and Effect
Scope own both input allocations and the result; no native views escape.

NativeWasm.ts moves the existing HTML ABI declarations and closed WASI callbacks
into one shared module. It also shares copied-asset authentication, compilation
and fresh restricted instance creation. HTML and diff use the same live-memory validation,
empty environment, fixed clock and descriptor/path refusal behavior. The old
HTML-specific helper export is retired and its callers migrate. There is no
second environment shim or new worker scheduler/transport. Native evaluation
still belongs only in an independently stoppable child, not on the parent.

## Runtime finding and build correction

The original core in commit 567ec4b77e passed the Node-only portable replay.
The first Bun Effect-host test rejected that binary at compilation:
"Module uses both legacy exceptions and try_table". The failed receipt remains
in .beep/diff-and-html-host-tests.log; a direct Bun compile reproduced it.
The unchanged upstream header was not at fault. The WASI SDK's current runtime
libraries and default compiler output mixed exception instruction models.

The build recipe now explicitly selects -wasm-use-legacy-eh=false alongside
-fwasm-exceptions and libunwind. Both Bun 1.4.4 and Node 24.22.1 compile the new
binary. Two independently extracted clean builds and their receipts agree
byte-for-byte. Current WASM size is 874,110 bytes and SHA-256 is
186b72b1410982b2b384e74c84fc448bddc16aa479fdcf85c01f493a5d8359ec.
The original source archive and all expected source steps are unchanged.
This supersedes the original binary digest in the earlier diff-core receipt;
it does not approximate the algorithm or waive any fidelity requirement.

This is an authenticated private host, not an owned worker or live engine.
Complete framing/pre-allocation accounting, shared admission, interruption,
captured deadlines, independently acknowledged retirement, quarantine and
whole-operation accounting still require integration with the existing Effect
RPC/native process owner. The synchronous kernel cannot be made interruptible
by a parent-thread Effect timeout. Builtin difflib, placeholder/emphasis
discovery, HTML names, complete engine parity and every remaining accounting
and lifecycle acceptance requirement remain open.
