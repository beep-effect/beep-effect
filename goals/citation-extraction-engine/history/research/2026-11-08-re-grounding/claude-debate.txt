## 1. Vendoring versus a pinned dependency in a killable worker

**Claim challenged.** Grok recommends vendoring a bounded slice and calls dependency adoption "the loser", keeping the runtime ban "for the safety reason" (`decisioncritique.md:93,98`).

**My position: that safety reason does not discriminate.** A vendored copy of a catastrophic regex backtracks exactly like the original. Grok's own gate 3 says what makes it safe: a proved linear-time subset, or a boundary a supervisor can kill from outside the matching thread (`:138-141`). Packaging appears in neither branch.

| Packaging | Same regex? | External kill? | Gate 3 result |
| --- | --- | --- | --- |
| Dependency in the host thread | Yes | No | Fail |
| Vendored in the host thread | Yes | No | **Fail** |
| Dependency in a killable process | Yes | Yes | Passes the boundary branch |
| Vendored in a killable process | Yes | Yes | Passes the same branch |
| Vendored, patterns proved linear | No | Either | Passes the proof branch, but no such proof exists (`:151`) |

The old ban doesn't help either. `SPEC.md:157,470` state the ban, but those lines give no safety rationale. Grok supplies that rationale itself, and the argument fails on the table above.

Grok's gate 4 (`:142`) says the "host runtime" must not load a donor. A dependency running in a separate process would pass that wording, but it still violates `SPEC.md:157`. I won't use that gap: this needs an explicit ruling.

**So the real question is maintenance.** This table is my judgment, and none of it is measured.

| | Pinned whole dependency | Vendored whole snapshot | Vendored slice |
| --- | --- | --- | --- |
| Code matches what the smoke ran | Yes | Yes | **No, slicing makes new code** |
| Cost to edit one pattern | Patch or fork; the memory index records bun patches silently dropping on dependency bumps | Low | Low |
| Registry and publisher exposure | Yes, reduced by an exact pin and lockfile | None | None |
| Upstream fixes | A cheap bump, then re-run | Manual | Manual, and diffs stop mapping |
| Reviewable surface | Whole package | Whole package | Smallest (size not measured, `:102`) |
| Repo lint and law gates on the code | Outside them | Possibly inside; unchecked | Possibly inside; unchecked |

**Strongest opposing case.** Both donors are quiet (eyecite-ts since 2026-07-04, eyecite-js since 2025-08-21), so a dependency's cheap-upgrade advantage is mostly theoretical. A small slice is the only surface anyone could fully review. A catastrophic pattern needs an edit eventually, and the kill boundary only converts a hang into a failed document, so it protects availability but doesn't fix the pattern. Those arguments are good, and they could make vendoring right later.

**Resolution.** Default to the pinned whole package in a killable process, because the running code stays identical to what was screened. Vendor only on a named trigger: a pattern that must be edited, a rejected registry risk, or an import-surface finding. Slice only after that, and re-run selection on the slice.

**Correcting the blanket BSD claim.** Grok's rule says "BSD-2-Clause attribution stays with the vendored text" and allows vendored source "with the retained BSD copyright" (`:100,142`). That doesn't fit eyecite-ts. Grok also says licensing was not re-verified (`:129`).

| Candidate | Code license | Data | What must travel with it |
| --- | --- | --- | --- |
| eyecite (Python) | BSD-2 | reporters-db and courts-db, both BSD-2 | BSD-2 notices |
| **eyecite-ts** | **MIT**; the LICENSE file names only its author | Bundled reporters-db-shaped data, embedded by a generator (`kimi/report.md:88`) | **MIT, plus the FLP BSD-2 notice for the data.** Its README says "ported from" eyecite, so check whether ported patterns also carry BSD duties |
| eyecite-js | BSD-2; the LICENSE names FLP and the port author (`kimi/report.md:96`) | Provenance not checked | BSD-2 notices; check the data |

This is a provenance checklist, not a legal opinion.

**Concessions to Grok.** Pre-1.0 and alpha labels don't show a donor is inferior (`:35`). An Effect timeout around synchronous `RegExp` is not safety (`:43`). "Native child" as a default is unproved until executed (`:45`). The non-expansion gate (`:143`) is correct, and my report broke it.

**Falsifiers.** A kill trial on the deployment runtime leaves the caller blocked past the limit: both packagings fail equally. Importing the package has effects outside the worker: the dependency default fails. A candidate cannot be packaged as a separate process at all: vendoring gains a real reason.

## 2. Kimi's TypeScript-first order, with native outside the evaluation

**Claim challenged.** Kimi evaluates only eyecite-ts. It treats reduced native as "do not choose by default" (`kimi/report.md:118`), and if adoption fails it stops automatic extraction instead of testing native (`:17,281,295`). Kimi's own uncertainty section says it ran nothing (`:285`). The smoke says "No current native Beep engine timing was measured here."

**My position: Kimi's evidence condemns the parity program, not a six-form native extractor.** The 100-minute lane replays the exhaustive program. The Python-shaped inputs and results Kimi cites (`:51`) are real defects in the current public contract, and an adapter can stop them at the boundary. Neither fact measures whether native extracts six forms correctly.

There is also an asymmetry. Kimi requires a bounded worker for eyecite-ts (`:216`), which has not been built or tested, while native already has process-isolation evidence in its packet (`README.md:18-24`; I have not re-verified it here). And Kimi's fallback could leave extraction shut off while a passing engine sits on `main`.

**Strongest opposing case.** Native is 39,187 lines in four directories, with Python emulation of unknown entanglement. Sunk cost is not a reason to keep it, as Kimi says (`:21`). Native's fixtures were derived from the same oracle, so a pass there shows little. Testing it invites the old program back through the side door. And if a donor passes, the ownership cost favors the donor regardless of native's score.

**Resolution.** I accept the last point in part: **among candidates that pass, ownership cost can legitimately favor a donor. That justifies a preference after measurement. It does not justify excluding native before measurement.** The side-door risk is real, so native enters under strict terms: run `extract` as it exists on `main`, through the same harness, with no new native features or parity work.

**Concessions to Kimi.** Its contract instincts are good: plain text, six forms, no confidence fields, non-partial failure, and a reduced failure union. It is right that the public shape is a poor boundary, and right to treat official eyecite as a process-boundary option only under a separate decision. Its reading of 182 complete events against 15,316 unfinished rows (`:57`), with its own caveat that totals vary, supports stopping the ledger.

**One rejection.** Kimi ships `verifyCandidate` first (`:142`). That belongs to the completed verified-span prerequisite, so it isn't a new engine operation.

**Falsifiers.** Native is eliminated by a contract row, by the kill trial, or by being unable to emit the contract without leaking Python-shaped data. Dependency mapping shows that keeping any native extraction means keeping nearly all 35,123 lines of `internal/Citation`. Then a passing donor wins on cost, and Kimi's preference holds in effect.

## 6. What the smoke shows about spans

One mention produced three different strings across implementations. **This is why donor text fields can't be the verified quote.**

| Case | Python `span()` | TS span | JS span | Python `matched_text()` | TS `matchedText` | JS `token.data` |
| --- | --- | --- | --- | --- | --- | --- |
| `Id. at 120.` | [0,10) | [0,10) | [0,10) | `Id.` | `Id. at 120` | `Id.` |
| `Smith, supra, at 3.` | **[7,18)** | **[0,18)** | **[0,18)** | `supra,` | `Smith, supra, at 3` | `Smith, supra,` |
| `Roe v. Wade, 410 U.S. 113, 120 (1973).` | [13,25) | [13,25) | [13,25) | `410 U.S. 113` | `410 U.S. 113` | `410 U.S. 113` |
| `See 410 U.S. at 120.` | [4,19) | [4,19) | [4,19) | `410 U.S. at 120` | `410 U.S. at 120` | not inspected |

- **Id.** All three spans agree and include the pin. The lexical core `Id.` is [0,3). `span()` and lexical matched text are different facts. The JS token range [0,3) shows this directly.
- **Supra.** Implementations disagree about the span itself: Python starts at `supra`, while TS and JS include the antecedent name. JS self-reports 2.7.6 parity but differs from the pinned Python here. It is one row and a design difference, not an extraction failure.
- **Span policy varies by form.** Full-case spans exclude the pin, whose location is [27,30) in TS, while short-form and Id. spans include it. TS and JS also expose a wider region [0,37) for the full case.
- **Consequence for Grok's oracle.** Its "agree or diverge" tuple includes span start and end against pinned Python. On a supra row, both donors diverge. Grok avoids this by testing full case only (`:62`), but that can't carry over to six forms. **The contract must define the span; no implementation can.**
- **Fields differ too.** On `37 C.F.R. § 1.56`, TS returns `title: 37, section: "1.56"`. JS returns `chapter: "37", part: "1", section: "56"`. An adapter reading only JS's `section` would state § 56. That is a mapping trap, not an error, since `part` is present. The Python screen didn't capture groups.
- **Python offsets need conversion:** code points [6,18) become UTF-16 [7,19).

## 7. Reduced engine contract

A conceptual shape, not Effect code. Reuse the existing schemas where they fit. The two methods keep the `CitationEngine` names; the old shapes do not carry over.

```text
extract(request) : Effect<ExtractionResult, CitationEngineFailure, never>
resolve(source, mentions) : Effect<LinkResult, CitationEngineFailure, never>

Request = { source: { id, version, text /* plain text only */ }, limits }

ExtractionResult = { mentions: Mention[], rejected: Rejected[], report: Report }

Mention = { id, form, anchor: Anchor, components: Component[] }
Anchor  = { start, end /* half-open UTF-16 */, rawText /* = source.slice(start, end) */ }

form =
  | FullCase  { volume, reporter, page }
  | ShortCase { volume, reporter }
  | Id        {}
  | Supra     { antecedentText? }
  | Usc       { title, section }          // FullLawCitation family
  | Cfr       { title, section }          // section "1.56", never "56"

Component = { role: pin | lexicalCore | antecedent | volume | reporter | page | title | section,
              anchor: Anchor }

Rejected = { reason: SpanNotVerified | OutOfScopeForm | Unparsed, anchor?: Anchor }

LinkResult = { links: { mention, link: Resolved{authority} | Ambiguous{candidates} | Unresolved{reason} }[] }

Report = { counts, engineArtifact, vocabularyVersion, limitDecisions, timing /* separate from semantics */ }
```

### Anchor definition per form

These are **contract decisions, not findings**. Examples use the smoke's text.

| Form | `anchor` | Components |
| --- | --- | --- |
| Full case | Locator only: `410 U.S. 113` [13,25) | pin `120` [27,30), if present |
| Short case | Through the pin: `410 U.S. at 120` [4,19) | pin `120` |
| Id. | Through the pin: `Id. at 120` [0,10) | **lexicalCore `Id.` [0,3)**; pin `120` [7,10) |
| Supra | From `supra` through the pin: `supra, at 3` [7,18) | lexicalCore `supra` [7,12); pin `3` [17,18); **antecedent `Smith` [0,5)** |
| 35 U.S.C. | `35 U.S.C. § 101` [0,15) | title, section |
| 37 C.F.R. | `37 C.F.R. § 1.56` [0,16) | title, section |

**Why the narrow supra anchor,** despite two of three implementations going wider: finding the name is a heuristic, and `supra` is a literal. If the name is mis-scoped, as in `Smith & Jones, supra`, a wide anchor is wrong at its start, while a narrow anchor stays correct and the error stays in one component. Anyone wanting the wide region takes the hull of antecedent and anchor; the reverse would need parsing. **Falsifier:** a named consumer needs a single mention range and the hull is wrong on labelled rows.

### Laws

1. `rawText` always equals `source.slice(start, end)`, checked through the existing `VerifiedSpan` contract, for anchors and components alike. Donor `matchedText`, `matched_text()` and `token.data` are never used as `rawText`.
2. Offsets are half-open UTF-16 on the raw source. Any internal cleaning maps back and re-verifies. A span that fails becomes `Rejected{SpanNotVerified}`.
3. Plain text only: no HTML, no cleaning operation, no callable cleaners or tokenizers.
4. No donor type crosses the boundary. No confidence score, Python storage, cleaner container or callback handle.
5. Recognized citations of other forms become `Rejected{OutOfScopeForm}` with counts, so they aren't silently dropped and aren't contract-gated.
6. Identical source and engine artifact produce identical semantic output (`SPEC.md:198-204`). Timing stays out of semantic comparison.

### Local ambiguity

The link rules belong to this contract, not to any donor. Grok's fact report says eyecite's resolver drops unresolved citations with no ambiguous state (`decisioncritique.md:70`). Kimi says eyecite-ts defaults to fuzzy party matching and warns about `antecedentId` fallback chaining (`kimi/report.md:85-86`). **The smoke tested no linking.**

| Mention | `Resolved` when | `Ambiguous` when | `Unresolved` when |
| --- | --- | --- | --- |
| Id. | Exactly one authority in the preceding citation unit | Preceding unit has more than one authority | No antecedent |
| Supra | Antecedent text exactly matches one earlier authority's party text | Matches more than one | No match, or no antecedent text |
| Short case | Volume and reporter match exactly one earlier authority | Match more than one | No match |

Rules: no fuzzy matching, no similarity scores, and never the first or nearest candidate as a tiebreak. Links are local only, with no external authority. "Preceding citation unit" and party-text normalization need one precise definition when this is specified. **Falsifier:** labelled rows show these rules produce mostly `Ambiguous` or `Unresolved` where a careful reader sees one answer. That is a reason to refine the rule, not a reason to guess.

### Resource bounds

- Execute matching in a boundary a supervisor can kill from outside the matching thread, with the caller staying responsive. **I prefer a separate process** because an OS kill doesn't depend on engine cooperation. A worker thread qualifies only if demonstrated on the deployment runtime. A same-thread timeout fails.
- A kill or limit hit gives `CitationSafetyLimitExceeded` with no partial result, carrying no source text.
- Reuse the existing schema-owned ceilings, reduced to the fields this contract needs: source units, mentions, wall clock and concurrency. No new numeric targets.
- Failure union: `CitationInputError`, `CitationPrerequisiteError`, `CitationSafetyLimitExceeded`. `CitationAnnotationError` goes away with annotation. `CitationOperationUnsupported` is unnecessary once modes are gone.

### Explicitly outside

Authority existence, quote verification as an engine operation, support, good law, Bluebook expansion, journals, general statutes, MPEP, annotation, HTML, confidence, parity claims, and any statement that the engine is a hallucination guard.

## 8. Finite selection, not a benchmark project

This run **selects or eliminates. It does not certify accuracy**, and nobody may quote its results as precision or recall.

| Item | Bound |
| --- | --- |
| Fixture | One frozen file: the nine smoke rows plus public excerpts, labelled against section 7 **before any candidate runs on it** |
| Ceiling | About 24 rows per form, plus ambiguity, orphan, duplicate, astral and negative rows. A cap, and my judgment. Grow it only if a named row class turns out to be missing |
| Candidates | Native at `main`, eyecite-ts and eyecite-js at their pinned commits, all through one adapter harness on the deployment runtime |
| Python eyecite | Diagnostic only. Disagreements get reviewed against the label; it is neither gold nor a runtime option |
| Kill trial | A seeded catastrophic pattern to prove the boundary, then the existing `regex-adversarial-corpus.json` through each candidate's real patterns |
| Output | One row-level table with no rollup percentages, timing reported with a repeat count fixed in advance, and one decision file |
| Remediation | One adapter-mapping round. No upstream pattern work and no new native features |

Donor runs need the authorization `GOAL.md:30` requires. Python stays outside the repo (`goals/python-free-repo/SPEC.md:71`).

**Elimination:** an unverified anchor emitted as verified; a forced link on an ambiguous or orphan row; a miss on a contract row that the label stands behind after review; a failed kill trial; exceeding existing ceilings; or inability to emit the contract at the boundary.

**Among survivors,** write down the ownership cost: retained lines, dependencies, license notices and upstream exposure. My current lean is the smallest owned surface, which likely favors a donor in a worker if one passes. That lean rests on upkeep, so the operator may reasonably weigh it differently.

**If nothing survives:** fix specific measured errors, or stop. Parity doesn't come back, and a Python process needs a new decision.

**If no consumer is named** once the contract lands, stop there.

## 11. Where I may still be wrong

- **The narrow supra anchor** goes against two of three implementations on purely design grounds.
- **Human labels on so small a fixture** can miss real failure classes. The reflection's missing-page defect came from replaying original inputs (`reflections/2026-11-07-integrated-parity-feedback.md:35`), which argues for including hard original rows in the fixture.
- **Selection can't see what the fixture lacks.** A candidate could pass here and fail badly on real documents, and this run explicitly won't tell you.
- **Whether a separate process is practical** on the deployment target is unchecked, and I haven't identified that target.
- **The link rules are untested** by any evidence here.
- **Native may be cheaper or costlier to reduce than I assume.** Dependency mapping has not been done.
- **The smoke used Bun and source imports.** Node and published artifacts could differ.
- **Licensing** of eyecite-ts's ported patterns and eyecite-js's data is unresolved.
