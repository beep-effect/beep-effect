# Reflection — effect-child-process-hardening (2026-07-30, codex)

## Summary

The goal converted implicit process behavior into explicit ownership: stdio is
declared, opened streams are drained concurrently, nonzero exits are observed,
timeouts escalate, and compatible repo CLI commands route through `StepExec`.
The result follows the upstream Effect lifecycle instead of wrapping it in a new
facade.

## Tooling experience

- **Worked:** The pinned Effect docs, source, adapters, and tests gave exact
  lifecycle semantics. The AST inventory, focused package checks, real
  large-output regression, and Yeet artifacts made the result auditable.
- **Didn't:** The first isolated install used `--ignore-scripts`, so the
  repository's Effect `tsgo` patch was absent and its policy test failed for an
  environmental reason. A normal frozen install restored the expected compiler.
- **Frustrating:** `--staged-only` safely parks unstaged residue, but it cannot
  select this goal out of an index that already contains unrelated staged work.
- **Wished existed:** A documented Yeet handoff that exports an explicit path
  set into a clean worktree and verifies the reconstructed patch before publish.

## Implementation improvement opportunities

- Codify explicit stdio options with an AST lint. Stream-consumption ownership
  still needs tests and review because a syntax-only rule cannot prove a pipe is
  drained.
- Keep the `StepExec` API limited to the modes that have current callers. The
  Codex streamed-input command remains a deliberate direct-process exception.
- Do not adopt `string`, `lines`, pipelines, prefixing, custom descriptors, or
  manual process control until a caller needs their exact semantics.

## Goal & prompt critique

Add one launch instruction: "If the current branch or index belongs to another
initiative, implement and publish from an isolated worktree based on the latest
`origin/main`; do not rely on staged-only publication to separate an existing
mixed index." This would make the preservation rule operational from the start.

## TODOs worth codifying

- Add an Effect child-process stdio ownership lint under the existing policy
  tooling.
- Add the isolated-worktree publication pattern to the Yeet skill.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Drain every configured output pipe concurrently or mark
  it ignored/inherited — an unread pipe can prevent the child from exiting.
- **MEDIUM — Best practice:** Treat the existing package boundary as the first
  reuse point — `StepExec` belongs in repo CLI, while driver result folds remain
  local.
- **LOW — Consideration:** Adopt more unstable process exports only when a real
  caller benefits without losing exit-status or diagnostic ownership.
