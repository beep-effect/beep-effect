# Alchemy beta.64–beta.66

Catalog of official release notes. Facts below are only what those three posts state.

## beta.64 — 2.0.0-beta.64 - Full AWS Coverage

- URL: https://alchemy.run/blog/2026-07-22-beta-64/
- Date: 2026-07-22T06:00:00.000Z
- Version: 2.0.0-beta.64

beta.64 is the AWS release. Alchemy covers **206 AWS services**, with every resource and binding live-tested against the real cloud. It also adds first-class containers on ECS and EKS, Durable Lambda Functions, and Helm charts on EKS. (https://alchemy.run/blog/2026-07-22-beta-64/)

### New or changed resources

Coverage, from one PR ([#797](https://github.com/alchemy-run/alchemy/pull/797)), using the same resource factory that built the Cloudflare provider. Agents cataloged all **428 generated SDK modules**, then implemented and live-tested them in waves: serverless first, then ECS/Fargate, EKS, EC2, and the long tail. (https://alchemy.run/blog/2026-07-22-beta-64/)

- **206 AWS services**, **683 resources**, and **2,842 bindings** (plus event sources and sinks). The post names the span as “from DynamoDB and S3 all the way out to MediaLive, IoT SiteWise, Bedrock, and SageMaker.” It does not list all 206 services. (https://alchemy.run/blog/2026-07-22-beta-64/)
- “Everything left over is documented as out of scope (deprecated APIs, data-only endpoints, billing objects).” (https://alchemy.run/blog/2026-07-22-beta-64/)
- All of it is documented in the API reference, with usage examples on every resource and binding. (https://alchemy.run/blog/2026-07-22-beta-64/)

Bindings shown in the ECS `Service` sample (each binding grants one IAM action on one ARN): (https://alchemy.run/blog/2026-07-22-beta-64/)

- `AWS.DynamoDB.GetItem(table)` — call shape `getItem({ Key: { pk: { S: "user#1" } } })`; HTTP layer `AWS.DynamoDB.GetItemHttp`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.DynamoDB.PutItem(table)` — call shape `putItem({ Item: { pk: { S: order.orderId } } })`; HTTP layer `AWS.DynamoDB.PutItemHttp`. Used again from `AWS.EKS.Deployment` and `AWS.EKS.Job`, where the binding lands as pod-identity IAM. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.SQS.SendMessage(queue)` — call shape `send({ MessageBody: JSON.stringify(item.Item) })`; HTTP layer `AWS.SQS.SendMessageHttp`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.S3.GetObject(bucket)` — HTTP layer `AWS.S3.GetObjectHttp`. Sample comment: “pull the video from S3, shell out to ffmpeg, then exit.” (https://alchemy.run/blog/2026-07-22-beta-64/)

ECS, full platform treatment ([#867](https://github.com/alchemy-run/alchemy/pull/867)). `Task` is run-to-completion; `Service` is long-running servers. Both are authored the same three ways as Workers and Lambda: an external image, an inline effect, or a tagged class. (https://alchemy.run/blog/2026-07-22-beta-64/)

- `AWS.ECS.Cluster` — sample `AWS.ECS.Cluster("AppCluster", {})`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.ECS.Service` — sample id `"Edge"` with `{ cluster, image: "public.ecr.aws/nginx/nginx:1.27", port: 80, desiredCount: 2, loadBalancer: true }`. Output `nginx.url` is `http://<alb-dns-name>`. `loadBalancer: true` provisions an Application Load Balancer. An Effect-program `Service` (`"Api"`, `{ cluster, main: import.meta.url, port: 3000, desiredCount: 2 }`) returns `{ fetch }`, and bindings grant IAM to the task role. Fetch handler reads `HttpServerRequest` / `request.json` and returns `HttpServerResponse.json`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.ECS.Task` — one-shot; the impl returns `{ run }`, and the container exits when the effect completes. Sample `"Thumbnailer"` props: `main: import.meta.url`, `dockerfile: Dockerfile.inline` (see below), `cpu: 1024`, `memory: 2048`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.ECS.RunTask` — binding `AWS.ECS.RunTask(cluster, thumbnailer)` grants `ecs:RunTask` and `iam:PassRole` automatically. Sample launches from `AWS.Lambda.Function` with `runTask({ launchType: "FARGATE", networkConfiguration: { awsvpcConfiguration: { subnets: [subnetId] } } })` and returns `response.tasks?.[0]?.taskArn`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.Lambda.Function` — sample `"Api"` with `{ main: import.meta.url, url: true }` whose `fetch` calls `RunTask`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.ECS.every` — `AWS.ECS.every("NightlyJob", "cron(0 3 * * ? *)", { cluster, task: nightlyTask, subnets: [privateSubnet.subnetId] })` provisions the EventBridge rule and invoke role. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `Service` props past `loadBalancer: true`: multiple services can share one load balancer; custom domains; auto-scaling on CPU or request count; Fargate Spot capacity; EFS volumes; secrets; health checks. (https://alchemy.run/blog/2026-07-22-beta-64/)

Every container platform takes one image source, flat on props: (https://alchemy.run/blog/2026-07-22-beta-64/)

- `{ main }` — bundle this Effect program. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `{ main, image }` — bundle FROM your base image. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `{ context, dockerfile? }` — build your own Dockerfile. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `{ dockerfile: Dockerfile.inline\`...\` }` — inline Dockerfile content. `import { Dockerfile } from "alchemy/Docker"`. Sample layers `FROM oven/bun:1` plus `RUN apt-get update && apt-get install -y ffmpeg`; “the inline content builds the environment, and the bundled program is layered on top.” (https://alchemy.run/blog/2026-07-22-beta-64/)
- `{ image }` — registry ref, mirrored into ECR. (https://alchemy.run/blog/2026-07-22-beta-64/)

EKS. “Kubernetes workloads live in the same TypeScript program as the cluster itself — no YAML, no `kubectl`.” (https://alchemy.run/blog/2026-07-22-beta-64/)

- `AWS.EC2.Network` — `AWS.EC2.Network("Network", { cidrBlock: "10.42.0.0/16", availabilityZones: 2, nat: "single" })`. Output used: `network.privateSubnetIds`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.EKS.Cluster` — `AWS.EKS.Cluster("Cluster", { compute: "auto", resourcesVpcConfig: { subnetIds: network.privateSubnetIds } })`. `compute: "auto"` stands up an EKS Auto Mode cluster where AWS manages the nodes. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.EKS.Deployment` — replaces `AWS.EKS.ServerHost` (breaking; see below). Sample `"Api"` props `{ cluster, main: import.meta.url, port: 3000, replicas: 2, serviceType: "LoadBalancer" }`. Synthesizes a Kubernetes `Deployment`, `Service`, and `ServiceAccount`, with bindings landing as pod-identity IAM. Effect impl returns `{ fetch }`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.EKS.Job` — run-to-completion counterpart; same image sources; impl returns `{ run }`. Sample `"SeedData"` with `{ cluster, main: import.meta.url }`. Add `schedule` and a Job becomes a Kubernetes CronJob. External form: `AWS.EKS.Job("NightlyBackfill", { cluster, image: "ghcr.io/acme/backfill:v3", schedule: "0 3 * * *" })`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.EKS.Manifest` — replaces removed `alchemy/Kubernetes`. Applies any raw Kubernetes object via server-side apply, CRDs included. The manifest is a literal object. No kubeconfig required. Sample `"Cache"` manifest: `apiVersion: "apps/v1"`, `kind: "StatefulSet"`, `metadata: { name: "cache", namespace: "apps" }`, `spec: { replicas: 3 }`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.EKS.HelmChart` ([#891](https://github.com/alchemy-run/alchemy/pull/891)) — installs Helm charts. Renders the chart locally with `helm template` and applies the objects, so Alchemy owns the lifecycle: drift is corrected on every deploy, dropped objects are pruned, and destroy deletes everything. Sample `"IngressNginx"`: `chart: "ingress-nginx"`, `repo: "https://kubernetes.github.io/ingress-nginx"`, `version: "4.11.2"`, `namespace: "ingress-nginx"`, `createNamespace: true`, `values: { controller: { replicaCount: 2 } }`. (https://alchemy.run/blog/2026-07-22-beta-64/)

Durable Lambda ([#797](https://github.com/alchemy-run/alchemy/pull/797)): (https://alchemy.run/blog/2026-07-22-beta-64/)

- `AWS.Lambda.DurableFunction` — long-running orchestrations as plain code, on AWS Lambda’s durable execution model. It **is** a Lambda Function, with the same props and bindings, but its body is checkpointed. (https://alchemy.run/blog/2026-07-22-beta-64/)
- Tagged class: `export class OrderFlow extends AWS.Lambda.DurableFunction<OrderFlow>()("OrderFlow") {}` then `OrderFlow.make({ main: import.meta.url, executionTimeout: "1 hour" }, ...)`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.Lambda.Durable.step` — records each result so it isn’t re-run on replay. Sample: `AWS.Lambda.Durable.step("reserve", putItem(...).pipe(Effect.orDie), { retry: { limit: 3, delay: "5 seconds" } })`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.Lambda.Durable.sleep` — suspends the execution entirely; Lambda re-invokes the function to resume it. Sample: `AWS.Lambda.Durable.sleep("cooldown", "10 minutes")`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.Lambda.Durable.waitForCallback` — pauses on an external signal for up to a year. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `yield* OrderFlow` returns a typed handle to start, inspect, and stop executions, and to complete callbacks from the outside. `orders.start({ name: "order-123", params: { orderId: "123" } })` — comment: “idempotent start”. `orders.get(ref.executionArn!)`. `execution.Status: "RUNNING" | "SUCCEEDED" | "FAILED" | ...`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- The run body is `Effect.fn(function* (input: { orderId: string }) { ... })`. (https://alchemy.run/blog/2026-07-22-beta-64/)

- `Cloudflare.D1.Database` — `Cloudflare.D1.Database("app-db", { migrationsDir: schema.out })`. Passing `schema.out` as `migrationsDir` makes the database apply the SQL: “generate first, apply second, in one deploy.” (https://alchemy.run/blog/2026-07-22-beta-64/)
- `Cloudflare.D1.QueryDatabase` — runtime Worker binding. Layer `Cloudflare.D1.QueryDatabaseBinding`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `Drizzle.D1` — `Drizzle.D1(d1, { relations })`. Sample query `db.query.Users.findMany({ with: { posts: true } })`. Every query is an Effect with `SqlError` in the typed error channel. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `Cloudflare.Worker` tagged class wrapping that stack: `export default class Api extends Cloudflare.Worker<Api>()("Api", { main: import.meta.url }, ...) {}`. (https://alchemy.run/blog/2026-07-22-beta-64/)

### Effect concepts

Bindings: (https://alchemy.run/blog/2026-07-22-beta-64/)

- Bindings are 1:1 with IAM actions. Each binding the code uses becomes a least-privilege policy statement on exactly the resources it touches, whether the code runs on Lambda, ECS, or EKS. (https://alchemy.run/blog/2026-07-22-beta-64/)
- “You never write an IAM policy, and every error is typed — the compiler tells you what can fail and you handle it like any other Effect error.” (https://alchemy.run/blog/2026-07-22-beta-64/)
- Init comment in the `Service` sample: “init: each binding grants one IAM action on one ARN.” The handler closes over clients resolved in init (`getItem`, `send`, `putItem`, `getObject`, `runTask`). (https://alchemy.run/blog/2026-07-22-beta-64/)
- HTTP binding layers passed to `Effect.provide`: `AWS.DynamoDB.GetItemHttp`, `AWS.SQS.SendMessageHttp`, `AWS.DynamoDB.PutItemHttp`, `AWS.S3.GetObjectHttp`, `Cloudflare.D1.QueryDatabaseBinding`. The first sample provides two layers as an array: `Effect.provide([AWS.DynamoDB.GetItemHttp, AWS.SQS.SendMessageHttp])`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- On EKS, the same `AWS.DynamoDB.PutItem` binding lands as pod-identity IAM. On ECS, bindings grant IAM to the task role. Durable Function init comment: “IAM lands on this role.” (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.ECS.RunTask` grants `ecs:RunTask` and `iam:PassRole` automatically. (https://alchemy.run/blog/2026-07-22-beta-64/)
- Actions get local bindings and Output accessors ([#807](https://github.com/alchemy-run/alchemy/pull/807)). (https://alchemy.run/blog/2026-07-22-beta-64/)
- Binding diffs are stable across runs ([#898](https://github.com/alchemy-run/alchemy/pull/898)). (https://alchemy.run/blog/2026-07-22-beta-64/)
- The coverage count includes “event sources and sinks” in addition to the 2,842 bindings. No individual sink or event-source identifier is named. (https://alchemy.run/blog/2026-07-22-beta-64/)
- Effect-valued env bindings converge in plans ([#890](https://github.com/alchemy-run/alchemy/pull/890)). (https://alchemy.run/blog/2026-07-22-beta-64/)

Phases and handler shapes: (https://alchemy.run/blog/2026-07-22-beta-64/)

- Container and Worker/Lambda impls split init (bindings) from the returned handler: `{ fetch }` for `AWS.ECS.Service`, `AWS.EKS.Deployment`, `AWS.Lambda.Function`, and `Cloudflare.Worker`; `{ run }` for `AWS.ECS.Task` and `AWS.EKS.Job`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- One-shot ECS Task impls return `{ run }` instead of `{ fetch }` (breaking; [#867](https://github.com/alchemy-run/alchemy/pull/867)). (https://alchemy.run/blog/2026-07-22-beta-64/)
- Durable Function init resolves binding clients; the returned value is `Effect.fn(function* (input) { ... })`. `Durable.step` / `Durable.sleep` / `Durable.waitForCallback` are the checkpoint and suspend operations inside that body. (https://alchemy.run/blog/2026-07-22-beta-64/)
- SQL client lifecycle: “nothing connects at plan or deploy time, the client is built lazily on the first query, and it’s torn down when the request settles.” (https://alchemy.run/blog/2026-07-22-beta-64/)
- Drizzle: generate migration SQL at deploy time, apply via `migrationsDir` in the same deploy. (https://alchemy.run/blog/2026-07-22-beta-64/)

References, handles, and errors: (https://alchemy.run/blog/2026-07-22-beta-64/)

- `yield* OrderFlow` is a typed handle: `start`, `get`, inspect, stop, and complete callbacks from the outside. `start({ name })` is an idempotent start. `execution.Status` is `"RUNNING" | "SUCCEEDED" | "FAILED" | ...`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `SqlError` is in the typed error channel of every Drizzle/D1 query. (https://alchemy.run/blog/2026-07-22-beta-64/)
- “Every error is typed.” The post does not name other error tags in this release. (https://alchemy.run/blog/2026-07-22-beta-64/)
- Unresolved Outputs are never persisted into state ([#835](https://github.com/alchemy-run/alchemy/pull/835)). (https://alchemy.run/blog/2026-07-22-beta-64/)

Layers and data types: (https://alchemy.run/blog/2026-07-22-beta-64/)

- Duration props take `Duration.Input` (`"1 hour"`, `Duration.hours(1)`) ([#797](https://github.com/alchemy-run/alchemy/pull/797)). Samples also pass `"5 seconds"`, `"10 minutes"`, and `"1 hour"`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- Sensitive props (passwords, secrets, keys) are `Redacted.Redacted<string>` ([#797](https://github.com/alchemy-run/alchemy/pull/797)). (https://alchemy.run/blog/2026-07-22-beta-64/)
- Replay requires the Durable Function body to be deterministic, and the type system enforces it: “the run body has no access to cloud credentials, so the only way to do I/O is through a binding client resolved in init and called inside a `Durable.step`.” (https://alchemy.run/blog/2026-07-22-beta-64/)
- The vocabulary mirrors Cloudflare Workflows, “so orchestration code reads the same on both clouds.” (https://alchemy.run/blog/2026-07-22-beta-64/)
- Layers, Bindings, and Runtime concept pages are rewritten. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `Effect.orDie` wraps the `putItem` effect passed into `Durable.step`. (https://alchemy.run/blog/2026-07-22-beta-64/)

Telemetry: none in this post. (https://alchemy.run/blog/2026-07-22-beta-64/)

### Tips and tricks

- “You never write an IAM policy.” Least privilege falls out of the bindings the program actually uses, on Lambda, ECS, or EKS. (https://alchemy.run/blog/2026-07-22-beta-64/)
- Every error is typed; handle it like any other Effect error. (https://alchemy.run/blog/2026-07-22-beta-64/)
- Author containers the same three ways as Workers and Lambda: external image, inline effect, or tagged class. (https://alchemy.run/blog/2026-07-22-beta-64/)
- One image source, flat on props — do not nest a `docker: { base }` object (that shape was removed). `{ image }` is a registry ref mirrored into ECR. `{ main, image }` bundles FROM your base image. `Dockerfile.inline` builds the environment and the bundled program is layered on top. (https://alchemy.run/blog/2026-07-22-beta-64/)
- A registry-image `Service` with `loadBalancer: true` is the shortest path to an ALB URL (`nginx.url`). Several services can share one load balancer. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.ECS.RunTask` grants `ecs:RunTask` and `iam:PassRole` automatically; a Lambda with `url: true` can launch a Fargate task per request. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.ECS.every` provisions the EventBridge rule and invoke role; you pass cluster, task, and subnets. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `compute: "auto"` is EKS Auto Mode: AWS manages the nodes. No YAML and no `kubectl`. `AWS.EKS.Manifest` needs no kubeconfig. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `AWS.EKS.HelmChart` uses local `helm template` plus apply, not a live Helm release you operate separately: drift is corrected on every deploy, dropped objects are pruned, and destroy deletes everything. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `schedule` on `AWS.EKS.Job` turns it into a Kubernetes CronJob; the external form can run a pre-built image with no Effect impl. (https://alchemy.run/blog/2026-07-22-beta-64/)
- Durable replay is deterministic because the run body cannot see cloud credentials. Do I/O only through a binding client resolved in init and called inside `Durable.step`. `Durable.sleep` suspends entirely (Lambda re-invokes to resume). `Durable.waitForCallback` can pause up to a year. `start({ name })` is idempotent. (https://alchemy.run/blog/2026-07-22-beta-64/)
- Durable code is meant to read like Cloudflare Workflows. (https://alchemy.run/blog/2026-07-22-beta-64/)
- Drizzle on D1: `Drizzle.Schema` writes SQL, `migrationsDir: schema.out` applies it, generate-then-apply in one deploy. Dialect in the sample is `"sqlite"`. (https://alchemy.run/blog/2026-07-22-beta-64/)
- effect-sql / Drizzle clients do not connect at plan or deploy time; the client is built lazily on the first query and torn down when the request settles. (https://alchemy.run/blog/2026-07-22-beta-64/)
- A passing test that leaks a cloud resource is a provider bug. 375 live tests stay gated because they are slow, expensive, or need special account entitlements. (https://alchemy.run/blog/2026-07-22-beta-64/)
- Out of scope, as documented: deprecated APIs, data-only endpoints, billing objects. (https://alchemy.run/blog/2026-07-22-beta-64/)
- Set `AWS_REGION` to override the SSO profile’s stored region ([#895](https://github.com/alchemy-run/alchemy/pull/895)). (https://alchemy.run/blog/2026-07-22-beta-64/)
- RDS: fingerprinting stops `MasterUserPassword` being re-sent on every reconcile. Set `skipFinalSnapshot: false` to take a final snapshot on deliberate teardown. (https://alchemy.run/blog/2026-07-22-beta-64/)
- Python Workers: point `main` at a `.py` file; dependencies are vendored from `pyproject.toml` via uv. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `alchemy login` does not need an `alchemy.run.ts`, and it accepts a GHES or data-residency enterprise host. (https://alchemy.run/blog/2026-07-22-beta-64/)
- `--force` is how you refresh stale bound attributes. (https://alchemy.run/blog/2026-07-22-beta-64/)
- Destroy will not silently orphan zombie rows; it aggregates GC failures. (https://alchemy.run/blog/2026-07-22-beta-64/)

beta.65 brings SageMaker HyperPod to the AWS provider: persistent ML training fleets, Slurm or EKS orchestrated, with task governance and typed workloads. ### New or changed resources

`AWS.SageMaker.Cluster` ([#924](https://github.com/alchemy-run/alchemy/pull/924)) provisions the fleet. HyperPod is “AWS’s persistent fleet for ML training and inference: accelerated instances with automatic health checks and faulty-node replacement, staying up between jobs. Where ECS and EKS run application containers, HyperPod runs distributed training.” (https://alchemy.run/blog/2026-07-27-beta-65/)

- Default orchestrator is Slurm — “an S3 lifecycle script, an execution role, and instance groups.” Sample `AWS.SageMaker.Cluster("TrainingCluster", { instanceGroups: { controller: { InstanceType: "ml.t3.medium", InstanceCount: 1, ExecutionRole: role.roleArn, LifeCycleConfig: { SourceS3Uri: script.sourceS3Uri, OnCreate: script.onCreate } } } })`. (https://alchemy.run/blog/2026-07-27-beta-65/)
- Instance groups reconcile in place: change a count or add a group and the cluster updates; remove one and it is deleted from the cluster. (https://alchemy.run/blog/2026-07-27-beta-65/)
- Jobs are submitted with `sbatch` over SSM — every node is an SSM target. (https://alchemy.run/blog/2026-07-27-beta-65/)
- `orchestrator: { Eks }` — the fleet’s nodes join an EKS cluster you provide. From there, workloads are ordinary Kubernetes objects. (https://alchemy.run/blog/2026-07-27-beta-65/)
- `AWS.EKS.Job` and `Deployment` opt onto HyperPod nodes with the `hyperpod` prop. Sample `AWS.EKS.Job("Train", { cluster: eks, main: import.meta.url, hyperpod: { instanceGroup: hyperpod.instanceGroups.workers } }, ...)` returning `{ run }`. “bindings land IAM on pod identity.” (https://alchemy.run/blog/2026-07-27-beta-65/)
- Instance-group keys carry through the cluster’s attributes as types, so a typo’d group name is a compile error. (https://alchemy.run/blog/2026-07-27-beta-65/)
- `ClusterSchedulerConfig` sets priority classes. (https://alchemy.run/blog/2026-07-27-beta-65/)
- `ComputeQuota` reserves per-team capacity (Kueue under the hood). A workload submits through governance by passing the quota resource: `hyperpod: { instanceGroup: hyperpod.instanceGroups.workers, quota, priorityClass: "training" }`. Comment on `quota`: “→ hyperpod-ns-research + queue label”. (https://alchemy.run/blog/2026-07-27-beta-65/)
- The full working stack (both orchestrators, governance, every workload tier) is `examples/aws-hyperpod`. (https://alchemy.run/blog/2026-07-27-beta-65/)

Worker bundling (behavior of `Cloudflare.Worker` builds, not a new resource): (https://alchemy.run/blog/2026-07-27-beta-65/)

- Hono/Express-style route registrations are no longer stripped ([#952](https://github.com/alchemy-run/alchemy/pull/952)). `purePlugin` had annotated top-level calls like `app.get("/", handler)` as pure, and under minification that annotation is a deletion instruction, so every request 404’d. Statement-position calls are now only annotated in packages that explicitly declare `sideEffects: false`, and never in entry modules. (https://alchemy.run/blog/2026-07-27-beta-65/)
- Cross-chunk evaluation order ([#940](https://github.com/alchemy-run/alchemy/pull/940)). Rolldown could split top-level initializers (e.g. Drizzle `pgTable` schemas) into a chunk that ran before its dependencies, failing Cloudflare startup validation with ``Cannot access 'a' before initialization``. `strictExecutionOrder` is now on by default, preserving ESM semantics across chunk boundaries. (https://alchemy.run/blog/2026-07-27-beta-65/)
- The same PR opens per-Worker control of chunking: `build` forwards rolldown output options and `preserveEntrySignatures`. Sample: `Cloudflare.Worker("Api", { main, build: { output: { codeSplitting: { groups: [{ name: "auth", test: "packages/(schema|auth)/" }] } } } })`. (https://alchemy.run/blog/2026-07-27-beta-65/)

Destroy / nuke behavior (engine, see also state-store and CLI): (https://alchemy.run/blog/2026-07-27-beta-65/)

- VPC-attached Lambda destroy no longer strands subnets and security groups on `DependencyViolation` ([#937](https://github.com/alchemy-run/alchemy/pull/937)). Lambda’s Hyperplane ENIs linger in the VPC for many minutes after the function is deleted, and AWS’s own reaper can take 20+ minutes. Subnet and security-group deletes now identify detached Lambda ENIs and delete them directly, so one `destroy` removes everything. (https://alchemy.run/blog/2026-07-27-beta-65/)
- `alchemy unsafe nuke` ([#950](https://github.com/alchemy-run/alchemy/pull/950)): `--independent` retries each delete on its own capped backoff instead of a shared barrier, so one hanging delete only ever stalls itself. Providers declare which resource types their cloud-side teardown consumes (a HyperPod cluster deletes its ENIs by assuming its IAM role inside its VPC), and nuke deletes in topologically-ordered waves so a role is never deleted out from under an in-flight cluster teardown. (https://alchemy.run/blog/2026-07-27-beta-65/)

### Breaking changes

- The `alchemy/SQL` barrel is removed ([#951](https://github.com/alchemy-run/alchemy/pull/951)). It eagerly loaded every backend, so projects without the optional `@effect/sql-pg` peer crashed on import. (https://alchemy.run/blog/2026-07-27-beta-65/)

The caution block calls this the breaking change. The bundling fixes change runtime behavior of already-deployed Workers (routes 404’d; startup `Cannot access 'a' before initialization`) but are not listed in the caution block. (https://alchemy.run/blog/2026-07-27-beta-65/)

### Migration notes

Replace the barrel import. The post’s diff is: (https://alchemy.run/blog/2026-07-27-beta-65/)

```diff
import * as SQL from "alchemy/SQL";
import * as SQL from "alchemy/SQL/D1";
import * as SQL from "alchemy/SQL/Postgres";
```

“Import each client from its own subpath instead.” Only `alchemy/SQL/D1` and `alchemy/SQL/Postgres` are shown. (https://alchemy.run/blog/2026-07-27-beta-65/)

### Tips and tricks

- Slurm is the default HyperPod orchestrator. Pass `orchestrator: { Eks }` to join an EKS cluster you provide. (https://alchemy.run/blog/2026-07-27-beta-65/)
- Instance groups reconcile in place: change a count or add a group to update; remove a group to delete it from the cluster. You do not replace the cluster for a count change. (https://alchemy.run/blog/2026-07-27-beta-65/)
- Submit Slurm jobs with `sbatch` over SSM; every node is an SSM target. (https://alchemy.run/blog/2026-07-27-beta-65/)
- A typo’d HyperPod instance-group name is a compile error because group keys are carried as types on `hyperpod.instanceGroups`. (https://alchemy.run/blog/2026-07-27-beta-65/)
- Task governance is opt-in by passing `quota` and `priorityClass` on the `hyperpod` prop. `ComputeQuota` is Kueue under the hood. The post’s comment says `quota` maps to `hyperpod-ns-research` plus a queue label. (https://alchemy.run/blog/2026-07-27-beta-65/)
- Do not mark entry-module statements as pure. Statement-position calls are annotated only in packages that explicitly declare `sideEffects: false`, and never in entry modules. Otherwise minification deletes `app.get("/", handler)` and every request 404s. (https://alchemy.run/blog/2026-07-27-beta-65/)
- `strictExecutionOrder` is now on by default. Leave it on if Drizzle `pgTable` (or any top-level initializer) is split across chunks; the failure mode is Cloudflare startup validation ``Cannot access 'a' before initialization``. (https://alchemy.run/blog/2026-07-27-beta-65/)
- Per-Worker chunking is available: `build` forwards rolldown output options and `preserveEntrySignatures`, including `output.codeSplitting.groups` with a `name` and a `test` regex. The sample groups `packages/(schema|auth)/` as `"auth"`. (https://alchemy.run/blog/2026-07-27-beta-65/)
- One `destroy` is enough for a VPC-attached Lambda. Hyperplane ENIs linger many minutes and AWS’s reaper can take 20+ minutes; Alchemy now deletes detached ENIs itself. (https://alchemy.run/blog/2026-07-27-beta-65/)
- `alchemy unsafe nuke --independent` so one hanging delete only stalls itself, on a capped backoff, instead of a shared barrier. (https://alchemy.run/blog/2026-07-27-beta-65/)
- Nuke will not delete a role out from under in-flight cloud-side teardown. Providers declare which types that teardown consumes. (https://alchemy.run/blog/2026-07-27-beta-65/)
- `_redirects` and `_headers` used to be hashed and then silently dropped. They now apply on deploys, no-op redeploys, and `alchemy dev`. (https://alchemy.run/blog/2026-07-27-beta-65/)
- Pausing a workflow in `alchemy dev` is not an error. Workflow classes export correctly in vite dev. (https://alchemy.run/blog/2026-07-27-beta-65/)
- `Docker.Container` `labels` and `stopTimeout` are what enable Traefik-managed routing in a remote Docker context. (https://alchemy.run/blog/2026-07-27-beta-65/)
- Import SQL from `alchemy/SQL/D1` or `alchemy/SQL/Postgres`, not `alchemy/SQL`. The barrel crashed projects that did not have optional peer `@effect/sql-pg`. (https://alchemy.run/blog/2026-07-27-beta-65/)
- Fragment helpers work on wrapped clients: `` sql`INSERT INTO users ${sql.insert(row)}` `` and nested `sql.and` / `sql.or` replay against the resolved client. (https://alchemy.run/blog/2026-07-27-beta-65/)
- Keep branded strings branded: an Action output of `string & Brand<"UserId">` is `Output<UserId>`, not an `ObjectExpr` of string methods. (https://alchemy.run/blog/2026-07-27-beta-65/)
- If you depended on the public vitest harness from beta.63, `alchemy/Test/Vitest` is back. (https://alchemy.run/blog/2026-07-27-beta-65/)

### Do not roll your own

- HyperPod fleet definition: Slurm lifecycle script from S3, execution role, in-place instance-group reconcile, or EKS orchestrator with typed instance-group names. (https://alchemy.run/blog/2026-07-27-beta-65/)

- Worker bundler footguns: pure-annotation of entry-module calls, and cross-chunk initializer order (`strictExecutionOrder` default), plus per-Worker rolldown `codeSplitting` groups. (https://alchemy.run/blog/2026-07-27-beta-65/)
- VPC destroy retries caused by Lambda Hyperplane ENIs. Alchemy deletes detached ENIs itself instead of waiting out a 20+ minute AWS reaper. (https://alchemy.run/blog/2026-07-27-beta-65/)
- Nuke scheduling: per-resource capped backoff (`--independent`) and provider-declared teardown dependencies so roles survive in-flight cluster ENI cleanup. (https://alchemy.run/blog/2026-07-27-beta-65/)
- Cloudflare `_redirects` / `_headers` upload (previously hashed and dropped). (https://alchemy.run/blog/2026-07-27-beta-65/)
- SQL fragment composition on wrapped clients (`sql.insert`, `sql.and`, `sql.or`) and per-backend subpath imports that do not pull `@effect/sql-pg`. (https://alchemy.run/blog/2026-07-27-beta-65/)
- Preserving branded primitive Outputs instead of expanding them into string-method object expressions. (https://alchemy.run/blog/2026-07-27-beta-65/)

## beta.66 — 2.0.0-beta.66 - Local Emulation & Gradual Deployments

- URL: https://alchemy.run/blog/2026-07-30-beta-66/
- Date: 2026-07-30T20:00:00.000Z
- Version: 2.0.0-beta.66

Frontmatter title is HTML-escaped as `Local Emulation &amp; Gradual Deployments`. The body states: beta.66 makes `alchemy dev` fully local by default: KV, R2, D1, and Queues are emulated on your machine, and `Alchemy.remote()` opts any resource back onto the real cloud. Workers gain versions, gradual deployments, and sticky sessions. The release also redesigns how Worker URLs and domains are modeled, and adds OpenTelemetry export, a Prisma provider, and a Bedrock `LanguageModel` binding. (https://alchemy.run/blog/2026-07-30-beta-66/)

### New or changed resources

Local emulation ([#963](https://github.com/alchemy-run/alchemy/pull/963)). Provider mode (local vs live) is a first-class engine concept. (https://alchemy.run/blog/2026-07-30-beta-66/)

- KV Namespaces, R2 Buckets, D1 Databases, and Queues are emulated locally during `alchemy dev`. They fabricate `dev:`-prefixed ids with no cloud calls, and Worker bindings lower onto local workerd simulators. (https://alchemy.run/blog/2026-07-30-beta-66/)
- D1 applies `migrationsDir` and `importFiles` against the local database. (https://alchemy.run/blog/2026-07-30-beta-66/)
- `Alchemy.remote()` opts a resource (or a whole scope) back onto the real cloud during dev. Sample: emulated `Cloudflare.D1.Database("DB", {})`; live `Cloudflare.Queues.Queue("Jobs", {}).pipe(Alchemy.remote())`. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Remote queues work in both directions: a local Worker can produce to a live queue, and a local `queue()` handler drains a live queue through an `http_pull` consumer. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Node-side capability clients (e.g. in Actions) reach the same local simulators the Workers see, so a seed script writes to the same local KV the Worker reads. (https://alchemy.run/blog/2026-07-30-beta-66/)

Worker versions and gradual deployments ([#948](https://github.com/alchemy-run/alchemy/pull/948)). The `version` prop maps Cloudflare’s versions and gradual deployments onto alchemy stages. (https://alchemy.run/blog/2026-07-30-beta-66/)

- `Cloudflare.Worker.ref("Api", { stage: "staging" })` — parent reference. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Zero-traffic version of another stage’s Worker (PR-preview workflow): `Cloudflare.Worker("Api", { main: "./src/api.ts", version: { parent, message: \`PR #${process.env.PR_NUMBER}\` } })`. The version’s `url` is a stable aliased preview URL that re-points at each newly uploaded version. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Canary: `version: { parent, traffic: 10 }` — “canary: 10% of staging's traffic”. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Self-rollout: `version: { traffic: 25 }` — “self-rollout: new version at 25%”. (https://alchemy.run/blog/2026-07-30-beta-66/)
- `version.affinity` pins each user to one version for the duration of a rollout ([#985](https://github.com/alchemy-run/alchemy/pull/985)). Sample: `version: { traffic: 10, affinity: { cookie: "session_id", ip: true } }` — “sticky by session cookie, falling back to sticky IP”. (https://alchemy.run/blog/2026-07-30-beta-66/)

Worker URLs ([#977](https://github.com/alchemy-run/alchemy/pull/977)), on `Cloudflare.Worker` and `Cloudflare.Website.*`: (https://alchemy.run/blog/2026-07-30-beta-66/)

- `workersDev` controls the `workers.dev` surface and is actually reconciled. The old `subdomain` prop was silently ignored. Object form in the caution snippet: `workersDev: { enabled: false, previewsEnabled: true }`. Boolean form later: `workersDev: false`. Mapping: `url: true` (the default) becomes `workersDev: true` — omit it. (https://alchemy.run/blog/2026-07-30-beta-66/)
- `domain` object: `{ name: "example.com", aliases: ["www.example.com"], redirects: ["old.example.com"] }`. Aliases “also serve the Worker”. Redirects are `301 → https://example.com`. `domain: "example.com"` still works as a string. `domain: []` (explicit detach-all) becomes `domain: null`. An omitted `domain` leaves attachments unmanaged. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Each redirect hostname gets managed DNS and an edge certificate, plus a zone redirect rule that 301s (path and query preserved) before Workers run — redirected requests never invoke the Worker. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Outputs: `urls` lists every URL that serves the Worker, most significant first, and `url` is always `urls[0]`. `domain` output is `{ name, aliases, redirects } | undefined`. Old output `domains` (`string[]`) is replaced. (https://alchemy.run/blog/2026-07-30-beta-66/)

  - custom domain — outranks workers.dev: `["https://example.com", "https://api.my-team.workers.dev"]`. (https://alchemy.run/blog/2026-07-30-beta-66/)
  - domain with aliases, `workersDev: false`: `["https://example.com", "https://www.example.com"]`. (https://alchemy.run/blog/2026-07-30-beta-66/)
  - version worker (`version.parent`) — stable aliased preview URL first, then this upload’s per-version URL: `["https://pr-42-api.my-team.workers.dev", "https://a1b2c3d4-api.my-team.workers.dev"]`. (https://alchemy.run/blog/2026-07-30-beta-66/)
  - gradual rollout (`version: { traffic }`) — the uploaded version’s preview URL trails: `["https://example.com", "https://api.my-team.workers.dev", "https://a1b2c3d4-api.my-team.workers.dev"]`. (https://alchemy.run/blog/2026-07-30-beta-66/)
  - `alchemy dev` — the dev server’s actual surface: `["http://localhost:5173", "http://192.168.1.23:5173"]`. (https://alchemy.run/blog/2026-07-30-beta-66/)

- The State Store records whether each resource is local or live. ### Breaking changes

Worker URL configuration is redesigned ([#977](https://github.com/alchemy-run/alchemy/pull/977)). The caution block says: (https://alchemy.run/blog/2026-07-30-beta-66/)

- The `url` and `subdomain` props are replaced by `workersDev`. (https://alchemy.run/blog/2026-07-30-beta-66/)
- `domain` takes an object form. (https://alchemy.run/blog/2026-07-30-beta-66/)
- The `domains` output is replaced by `urls` + `domain`. (https://alchemy.run/blog/2026-07-30-beta-66/)
- This applies to `Cloudflare.Worker` and `Cloudflare.Website.*`. (https://alchemy.run/blog/2026-07-30-beta-66/)

The caution’s code sample places old and new fields in one object (duplicate `domain` keys). Read it as a before/after, not as a single valid props object. Old side shown: `url: false`, `subdomain: { previewsEnabled: true }`, `domain: ["example.com", "www.example.com"]`, `worker.domains` as `string[]`. New side shown: `workersDev: { enabled: false, previewsEnabled: true }`, `domain: { name: "example.com", aliases: ["www.example.com"] }`, `worker.url` (“https://example.com” — always `urls[0]`), `worker.urls` (every URL serving the Worker, most significant first), `worker.domain` (`{ name, aliases, redirects } | undefined`). (https://alchemy.run/blog/2026-07-30-beta-66/)

The caution then states: (https://alchemy.run/blog/2026-07-30-beta-66/)

- `url: true` (the default) becomes `workersDev: true` — omit it. (https://alchemy.run/blog/2026-07-30-beta-66/)
- `domain: "example.com"` still works as a string. (https://alchemy.run/blog/2026-07-30-beta-66/)
- `domain: []` (explicit detach-all) becomes `domain: null`; an omitted `domain` leaves attachments unmanaged. (https://alchemy.run/blog/2026-07-30-beta-66/)

Not in the caution block, but a default change: plain Workers default to `nodejs_compat`. “The default previously reached only Effect-native Workers.” ([#796](https://github.com/alchemy-run/alchemy/pull/796)). (https://alchemy.run/blog/2026-07-30-beta-66/)

### Migration notes

- Persisted Worker URL state migrates automatically on the first redeploy ([#977](https://github.com/alchemy-run/alchemy/pull/977)). (https://alchemy.run/blog/2026-07-30-beta-66/)
- Drop `url: true`; it is now the `workersDev: true` default, so omit it. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Replace `url: false` / `subdomain: { previewsEnabled: true }` with `workersDev: { enabled: false, previewsEnabled: true }` (the caution’s object) or `workersDev: false` (the later boolean example, which does not show `previewsEnabled`). (https://alchemy.run/blog/2026-07-30-beta-66/)
- `domain: ["example.com", "www.example.com"]` becomes `domain: { name: "example.com", aliases: ["www.example.com"] }`. A single string `domain: "example.com"` still works. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Explicit detach-all changes from `domain: []` to `domain: null`. Omitting `domain` does not detach; attachments stay unmanaged. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Stop reading `worker.domains`. Read `worker.urls` (most significant first), `worker.url` (always `urls[0]`), and `worker.domain`. (https://alchemy.run/blog/2026-07-30-beta-66/)
- The old `subdomain` prop was silently ignored; `workersDev` is actually reconciled. Quote: “`workersDev` controls the `workers.dev` surface (and is actually reconciled — the old `subdomain` prop was silently ignored).” (https://alchemy.run/blog/2026-07-30-beta-66/)
- After a local `alchemy dev`, the next `alchemy deploy` plans replacements of `dev:`-prefixed resources rather than updates ([#963](https://github.com/alchemy-run/alchemy/pull/963)). (https://alchemy.run/blog/2026-07-30-beta-66/)

### Tips and tricks

- `alchemy dev` does not call the cloud for KV, R2, D1, or Queues unless you opt back in. Ids are `dev:`-prefixed. Bindings hit local workerd simulators. D1 still applies `migrationsDir` and `importFiles` locally. (https://alchemy.run/blog/2026-07-30-beta-66/)
- `Alchemy.remote()` is per resource or per scope. A local Worker can produce to a live queue, and a local `queue()` handler can drain a live queue through an `http_pull` consumer. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Seed scripts and Actions see the same local simulators as the Worker, so a seed writes the KV the Worker reads. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Do not `alchemy deploy` immediately after `alchemy dev` and expect an in-place update. The State Store recorded local vs live, and the switch plans a replacement. (https://alchemy.run/blog/2026-07-30-beta-66/)
- PR previews: `version: { parent, message }` uploads one stage’s code as a zero-traffic version of another stage’s Worker. `url` on that version is a stable aliased preview URL that re-points at each new upload. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Canary with `version: { parent, traffic: 10 }` (10% of the parent’s traffic) or self-rollout with `version: { traffic: 25 }`. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Sticky sessions during a rollout: `affinity: { cookie: "session_id", ip: true }` — cookie first, IP fallback. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Omit `workersDev` to keep the default `workers.dev` surface (`url: true` used to mean that). Set `workersDev: false` to turn it off. The old `subdomain` prop did nothing. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Redirects are edge 301s with managed DNS and an edge certificate, path and query preserved, and they never invoke the Worker and never appear in `urls`. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Use `urls`, not a hand-built origin list, as the CORS allow-list. In production that is the custom domain, aliases, and `workers.dev` URL. Under `alchemy dev` it is the Vite dev server’s Local and Network URLs — `localhost` plus the LAN address (`http://192.168…`) — “so a phone on your Wi-Fi can load the site and call the API.” (https://alchemy.run/blog/2026-07-30-beta-66/)
- Custom domains outrank `workers.dev` in `urls`. `url` is always `urls[0]`. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Telemetry is optional. No layer means Effect’s no-op tracer and instrumentation stays free. Merge several OTLP layers to fan out with agreeing trace ids. `Axiom.Telemetry` is only sugar over `Alchemy.Telemetry.layerOtlp`. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Prisma: `createDatabase: false` on `Prisma.Project` when you create `Prisma.Postgres` yourself. Effect-style `Prisma.Compute` takes `main` plus a body; path/build form takes `path`, `build.command`, `build.outdir`, and `env`. Credentials are not persisted as plaintext. Interrupted deployments recover. Reconcile uses observed API state. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Bedrock model ids are an IAM allow-list fixed at deploy (`AWS.Bedrock.LanguageModel([...])`). Change model parameters per call with `AWS.Bedrock.withModelParameters`, not by widening the binding. The adapter speaks the Converse API directly, so `generateText`, `streamText`, toolkits, and `Chat` stay the same. (https://alchemy.run/blog/2026-07-30-beta-66/)
- An assets-only Worker (only an `assets` directory, no script) makes static requests free — they never invoke a Worker. The class form needs no impl. (https://alchemy.run/blog/2026-07-30-beta-66/)
- `alchemy login` over SSH or in a container uses a hosted relay page; paste the code when the browser cannot reach the CLI. Prompt cancellation works ([#968](https://github.com/alchemy-run/alchemy/pull/968)). (https://alchemy.run/blog/2026-07-30-beta-66/)
- The version-update warning prints before interactive prompts, so it does not land mid-prompt ([#959](https://github.com/alchemy-run/alchemy/pull/959)). (https://alchemy.run/blog/2026-07-30-beta-66/)
- Non-Cloudflare stacks do not need rolldown’s native binding; it loads lazily ([#955](https://github.com/alchemy-run/alchemy/pull/955)). (https://alchemy.run/blog/2026-07-30-beta-66/)
- `Worker.URL` is how a Worker learns its own public URL, and it follows `alchemy dev` to the local URL. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Dev `send_email` does not deliver. Log locally, or `Alchemy.remote()` the binding to send for real. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Plain (non-Effect) Workers now get `nodejs_compat` by default, matching Effect-native Workers. (https://alchemy.run/blog/2026-07-30-beta-66/)
- `Output<Redacted>` env values upload encrypted as `secret_text`, not readable text. `InferEnv` still sees the type. (https://alchemy.run/blog/2026-07-30-beta-66/)
- A dev session that outlives the access token re-resolves OAuth credentials. That is the “dev breaks after machine sleep” hang. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Accounts with many zones: subdomain lookups are memoized and route discovery is scoped to known zones, which is what was producing 429s. Unmanaged custom domains plan as `noop`. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Slow `alchemy dev` restarts (container image prep) no longer 503: the old workerd serves until the new one starts. (https://alchemy.run/blog/2026-07-30-beta-66/)
- A Worker that consumes a queue with a dead-letter queue starts again in local dev ([#1000](https://github.com/alchemy-run/alchemy/pull/1000)). `Container` env bindings no longer break Vite builds ([#999](https://github.com/alchemy-run/alchemy/pull/999)). (https://alchemy.run/blog/2026-07-30-beta-66/)
- Destroy does not stop at the first failure. You get one `DestroyError` covering failures and the resources those failures blocked. (https://alchemy.run/blog/2026-07-30-beta-66/)
- After destroy, do not expect a hollow stack output. Cross-stack refs fail with `InvalidReferenceError`. (https://alchemy.run/blog/2026-07-30-beta-66/)
- ECS `Service` updates wait until rollout, drain, and ALB targets are healthy. Attach extra IAM with `taskRoleManagedPolicyArns` on the `Service` form. `environmentFiles` is on the shared task-definition surface. (https://alchemy.run/blog/2026-07-30-beta-66/)
- PlanetScale: a metadata-only update does not replace roles. (https://alchemy.run/blog/2026-07-30-beta-66/)
- CloudFront: props that don’t express a member no longer `IllegalUpdate`; observed config is merged. (https://alchemy.run/blog/2026-07-30-beta-66/)
- Host `@cloudflare/sandbox`’s `Sandbox` as `DurableObject("Sandbox", { container })` on async Workers instead of reimplementing a container-backed DO. (https://alchemy.run/blog/2026-07-30-beta-66/)
