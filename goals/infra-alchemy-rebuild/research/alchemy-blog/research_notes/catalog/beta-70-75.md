# Alchemy beta.70–beta.75 catalog

Verbatim extracts only. Each bullet cites the post it comes from. beta.70's notes cover beta.67 through beta.70. beta.75's notes cover beta.72 through beta.75. beta.71 is a single release.

## beta.70 — Web Frameworks & Full Local Dev

- URL: https://alchemy.run/blog/2026-08-06-beta-70/
- Date: 2026-08-06T09:00:00.000Z
- Version: `2.0.0-beta.70`. "This post covers beta.67 through beta.70 — beta.67 was a small fix release that didn’t get its own notes, and beta.68/beta.69 are superseded by beta.70." (https://alchemy.run/blog/2026-08-06-beta-70/)

### New or changed resources

- `Cloudflare.Website` grows from Vite and StaticSite to a framework family that deploys **Next.js, Astro, Nuxt, SvelteKit, Waku, and Octane** to Cloudflare Workers. Programmatic builds: no wrangler binary, no `wrangler.json`, no adapter packages. Each resource deploys a Worker (server bundle plus static assets) and returns a plain `Worker`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- `Cloudflare.Website.Nextjs` ([#923](https://github.com/alchemy-run/alchemy/pull/923)). Docs path `/cloudflare/frontend/nextjs`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- `Cloudflare.Website.Astro`. Docs path `/cloudflare/frontend/astro`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- `Cloudflare.Website.Nuxt`. Docs path `/cloudflare/frontend/nuxt`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- `Cloudflare.Website.SvelteKit`. Docs path `/cloudflare/frontend/sveltekit`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- `Cloudflare.Website.Waku` ([#1086](https://github.com/alchemy-run/alchemy/pull/1086)). Docs path `/cloudflare/frontend/waku`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- `Cloudflare.Website.Octane` ([#1093](https://github.com/alchemy-run/alchemy/pull/1093)). Deploys [OctaneJS](https://octanejs.dev) through Octane’s own Cloudflare adapter. Docs path `/cloudflare/frontend/octane`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Worker vocabulary on every website resource: `env` takes any binding (KV, R2, Durable Objects, secrets), plus `domain`, `compatibility`, and asset routing. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Framework config files load natively: `astro.config.*`, `vite.config.ts`, `nuxt.config.ts`, and the post's "…". Alchemy merges its Cloudflare config over that file. (https://alchemy.run/blog/2026-08-06-beta-70/)
- **Next.js** builds through the OpenNext pipeline. Writable ISR needs a KV incremental cache and a Durable Object queue: time-based regeneration and on-demand `revalidatePath`. Sample bindings: `NEXT_INC_CACHE_KV`, `NEXT_TAG_CACHE_KV`, `NEXT_CACHE_DO_QUEUE: Cloudflare.DurableObject("NEXT_CACHE_DO_QUEUE", { className: "DOQueueHandler" })`. `DOQueueHandler` "ships in the OpenNext bundle". (https://alchemy.run/blog/2026-08-06-beta-70/)
- **Astro** defaults to server output and auto-provisions a KV namespace for zero-config sessions, bound as `SESSION`. Bindings are read via `Astro.locals.runtime.env`. Sample: `env: { CACHE: kv, UPLOADS: bucket }`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- **Nuxt** builds through nitro’s `cloudflare_module` preset and natively loads `nuxt.config.ts`. The `nuxt` prop merges over it. Sample: `nuxt: { routeRules: { "/about": { prerender: true } } }`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- **SvelteKit** uses an in-memory Cloudflare adapter — no `svelte.config.js` changes, no `@sveltejs/adapter-cloudflare`. Bindings via `platform.env`. Sample: `env: { API_KEY: Alchemy.secret("API_KEY") }`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- **Waku** serves RSC SSR at request time and prerenders SSG pages at build time inside workerd. Optional custom entry `main: "src/worker-entry.ts"` can host Durable Objects alongside waku’s fetch handler. Sample: `env: { COUNTER: Cloudflare.DurableObject("Counter") }`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- **Octane** sample: `env: { CACHE: cache }` via `context.platform.env`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- `Cloudflare.Website.Nextjs` dev: `nextjs: { devMode: "hmr" }` for Turbopack HMR, or the default preview parity under workerd. (https://alchemy.run/blog/2026-08-06-beta-70/)
- `alchemy dev` local surface added in this campaign ([#1039](https://github.com/alchemy-run/alchemy/pull/1039)), on top of beta.66's KV, R2, D1, and Queues: cron triggers, Browser Rendering, Images, email (both directions), Secrets Store, `secret_key` CryptoKey, Stream, tail consumers, Workflows, Hyperdrive. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Cron triggers: `crons` schedule real timers. Manual trigger route `/cdn-cgi/handler/scheduled` (miniflare-compatible). Previously `scheduled()` never ran under `alchemy dev`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Browser Rendering: `env.BROWSER` drives a real local Chrome over CDP. `@cloudflare/puppeteer` works unchanged. Sample resource: `Cloudflare.Browser("BROWSER")`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Images: `env.IMAGES` transforms run through sharp locally. Sample resource: `Cloudflare.Images.Images("IMAGES")`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Email, both directions: `send_email` validates and persists sent mail as `.eml` files. `POST` to `/cdn-cgi/handler/email` drives the `email()` handler with accept, reject, and reply semantics. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Secrets Store: a Worker binding a `secrets_store_secret` boots in dev, with the real (Redacted-sourced) value seeded into the simulator. `secret_key` CryptoKey bindings boot too. New user-facing resource: `Cloudflare.Workers.SecretKey`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Stream: `Cloudflare.Stream.Stream("STREAM")` is a new binding surface ("alchemy previously had none"), live and against a local video-store simulator in dev. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Tail consumers: new `tailConsumers` prop uploads as `tail_consumers` metadata live. A local producer’s trace events reach a local tail Worker in dev. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Workflows and Hyperdrive are now first-class dual providers. (https://alchemy.run/blog/2026-08-06-beta-70/)
- `Alchemy.remote()` ([#1065](https://github.com/alchemy-run/alchemy/pull/1065)) opts a binding onto the real cloud during dev. Worker-only bindings gained `pipe()`, so the same aspect works on plain binding values in an async Worker’s `env`. Samples: `Cloudflare.Browser("BROWSER").pipe(Alchemy.remote())` and `Cloudflare.Images.Images("IMAGES").pipe(Alchemy.remote())`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Hybrid local/live queues. Sample: `Cloudflare.Queues.Queue("Jobs").pipe(Alchemy.remote())` with `Cloudflare.Worker("Processor", { main: import.meta.url }, Effect.gen(...))` and `Cloudflare.Queues.consumeQueueMessages(jobs, (stream) => Stream.runForEach(stream, (msg) => processJob(msg.body)))`. Local producer writes the real queue; local consumer drains it through a pull loop with batching, retry, and dead-letter semantics. (https://alchemy.run/blog/2026-08-06-beta-70/)
- `Alchemy.renamedFrom` ([#1108](https://github.com/alchemy-run/alchemy/pull/1108)). Sample: `Cloudflare.R2.Bucket("Assets").pipe(Alchemy.renamedFrom("Bucket"))`. A bare string resolves against the ambient namespace like the `id` argument. `{ fqn: "..." }` addresses a move between namespaces. Listing several former ids covers rename chains. Plan text shown: `Plan: 1 to update` / `[Assets] update (renamed from Bucket)`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- `Cloudflare.Website.StaticSite` ([#1053](https://github.com/alchemy-run/alchemy/pull/1053)): no longer duplicates `env` resources into its own namespace. A shared KV namespace passed as `env` used to register a second physical copy at `<site-id>/…`. The site’s Worker moves from the `<id>/Worker` FQN to `<id>`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Every `Binding.Service` gains `execute(...)` ([#1037](https://github.com/alchemy-run/alchemy/pull/1037)): invoke a capability at plan/deploy time and get an `Output`. First data source: `AWS.EC2.getAmi`. Sample: `AWS.EC2.Instance("web", { imageId: AWS.EC2.getAmi({ owners: ["amazon"], name: ["al2023-ami-2023.*"] }).ImageId.as<string>(), instanceType: "t3.micro", subnetId: subnet.subnetId })`. The same capability as a runtime binding is `yield* AWS.EC2.GetAmi(opts)`, which grants `ec2:DescribeImages`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- `Cloudflare.VpcService.lookup({ name })` ([#821](https://github.com/alchemy-run/alchemy/pull/821)) resolves a service managed outside the stack. Binding it, or a managed `VpcService`, to a Worker’s `env` yields a `Fetcher` that tunnels into the private network. Sample: `env: { VPC: Cloudflare.VpcService.lookup({ name: "my-vpc-service" }) }`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Kubernetes workloads move out of `AWS.EKS.*` into `alchemy/Kubernetes` ([#986](https://github.com/alchemy-run/alchemy/pull/986)): `Deployment`, `Job`, `Manifest`, and `HelmChart`. They reference a cluster instead of being EKS resources. Pass an `AWS.EKS.Cluster` and auth (SigV4), the image registry (ECR), and workload identity (Pod Identity) resolve through its adapter. Sample: `Kubernetes.KubeConfig({ context: "kind-dev" })` and `Kubernetes.Deployment("Api", { cluster: local, image: "ghcr.io/acme/api:v3" })`. Exec credential plugins honored: `aws eks get-token`, `kubelogin`, `gke-gcloud-auth-plugin` (EKS today, AKS/GKE via kubeconfig). Add `Kubernetes.providers()` to the stack. (https://alchemy.run/blog/2026-08-06-beta-70/)
- `SQL.MySQL` and `Drizzle.MySQL` ([#1063](https://github.com/alchemy-run/alchemy/pull/1063)), siblings of the Postgres and D1 clients. Import `import * as SQL from "alchemy/SQL/MySQL"`. Sample: `Cloudflare.Hyperdrive.Connect(Hyperdrive)` then `SQL.MySQL({ url: hd.connectionString })` and `` sql`SELECT * FROM users` ``. (https://alchemy.run/blog/2026-08-06-beta-70/)
- `Cloudflare.WorkerEntrypoint` ([#1097](https://github.com/alchemy-run/alchemy/pull/1097)) binds a specific `WorkerEntrypoint` class exported by another Worker, with optional `ctx.props`. Samples: `Cloudflare.WorkerEntrypoint(target, "Api")` and `Cloudflare.WorkerEntrypoint(vendor, { entrypoint: "Vendor", props: { baseUrl: site.url } })`. `alchemy dev` delivers `ctx.props` to the local target. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Bundler pure-annotation config ([#1021](https://github.com/alchemy-run/alchemy/pull/1021)): `build: { pure: { packages: ["my-lib", "@my-scope/*"] } }` or `pure: false`. `effect`, `@effect/*`, and alchemy’s own packages stay annotated by default. (https://alchemy.run/blog/2026-08-06-beta-70/)

### Provider packages

- [distilled](https://github.com/alchemy-run/distilled) v1 ([#823](https://github.com/alchemy-run/alchemy/pull/823)) replaces per-provider hand-rolled generators with one compiler. Native spec formats converted into a standard [Smithy](https://smithy.io) model, then one Smithy-to-SDK codegen. Formats named: OpenAPI (shared by 13 providers — the 13 are not named), Cloudflare’s API docs, AWS’s official Smithy models, Google Discovery, Azure ARM, GraphQL introspection. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Each provider package is data: a spec converter config, a trait/pagination/protocol vocabulary (Cloudflare’s is ~115 lines), and a thin runtime protocol seam. SigV4 for AWS. A generic bearer-REST protocol shared by 12 providers (the 12 are not named). (https://alchemy.run/blog/2026-08-06-beta-70/)
- Result: 20 packages and ~45k operations — 429 AWS services, all of Azure and GCP, Cloudflare, Kubernetes, Stripe, PostHog, and "the long tail" (not enumerated). Adding a provider is a spec config. A mistyped error or wrong response schema is one JSON Patch against a Smithy model. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Migration verified name-for-name against the v0 surfaces and by alchemy’s full live test tree — nearly 6,000 tests against real cloud APIs — with zero SDK regressions. (https://alchemy.run/blog/2026-08-06-beta-70/)
- SQL client import path: `alchemy/SQL/MySQL`. Kubernetes namespace: `alchemy/Kubernetes` (workloads leave `AWS.EKS.*`). (https://alchemy.run/blog/2026-08-06-beta-70/)
- `pg`, `mysql2`, `mongodb`, and `@vercel/nft` are optional peer dependencies ([#1069](https://github.com/alchemy-run/alchemy/pull/1069), [#1071](https://github.com/alchemy-run/alchemy/pull/1071)). (https://alchemy.run/blog/2026-08-06-beta-70/)
- `@sveltejs/adapter-cloudflare` is no longer required for `Cloudflare.Website.SvelteKit`. `@cloudflare/puppeteer` is the Browser Rendering client that works unchanged. (https://alchemy.run/blog/2026-08-06-beta-70/)

### CLI commands

- `alchemy dev`: framework dev servers for all six website resources; full local Cloudflare surface; Vite servers in child processes; delivers `WorkerEntrypoint` `ctx.props`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- `alchemy state export` ([#1043](https://github.com/alchemy-run/alchemy/pull/1043)): every state record across stacks and stages as one JSON document, deterministically ordered so exports diff cleanly. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Not a CLI command, but dev HTTP routes named in this post: `POST` is not specified for cron — the miniflare-compatible `/cdn-cgi/handler/scheduled` route triggers crons manually; `POST` to `/cdn-cgi/handler/email` drives `email()`. (https://alchemy.run/blog/2026-08-06-beta-70/)

### State-store features

- `Alchemy.renamedFrom` migrates the persisted state row instead of planning a replacement. Same instance ID, same physical name, nothing created or deleted in the cloud. Types must match. Ambiguous claims and rename cycles fail the plan. A leftover row from an interrupted move is dropped state-only, never touching the cloud. (https://alchemy.run/blog/2026-08-06-beta-70/)
- StaticSite Worker FQN `<id>/Worker` → `<id>` migrates in place via `renamedFrom()`: "same physical name, same `workers.dev` subdomain, nothing recreated." (https://alchemy.run/blog/2026-08-06-beta-70/)
- Kubernetes: existing state migrates in place when moving off `AWS.EKS.Deployment`-style resources. (https://alchemy.run/blog/2026-08-06-beta-70/)
- `alchemy state export`: one deterministically ordered JSON document of every state record across stacks and stages. (https://alchemy.run/blog/2026-08-06-beta-70/)
- An interrupted first deploy no longer bricks later plans with a `SchemaError` ([#1005](https://github.com/alchemy-run/alchemy/pull/1005)). (https://alchemy.run/blog/2026-08-06-beta-70/)
- Cyclic props and class instances no longer send the engine’s prop walkers into infinite recursion ([#1094](https://github.com/alchemy-run/alchemy/pull/1094)). (https://alchemy.run/blog/2026-08-06-beta-70/)
- Whole-resource references are re-resolved at apply so downstream resources see fresh upstream attributes ([#1068](https://github.com/alchemy-run/alchemy/pull/1068), [#1070](https://github.com/alchemy-run/alchemy/pull/1070)). (https://alchemy.run/blog/2026-08-06-beta-70/)

### Testing features

- distilled v1 verified by "nearly 6,000 tests against real cloud APIs" with zero SDK regressions. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Pure-annotation caveat: auto-detection could delete top-level registrations such as `app.get("/", handler)` under minification — "the deploy succeeds, unbundled unit tests stay green, and every request 404s." Auto-detection is removed. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Local D1 migrations fixed ([#1009](https://github.com/alchemy-run/alchemy/pull/1009)). No further test API is described. (https://alchemy.run/blog/2026-08-06-beta-70/)

### Effect concepts

- Bindings: `Binding.Service` gains `execute(...)` returning an `Output` at plan/deploy time. The same contract still works as a runtime binding (`yield* AWS.EC2.GetAmi(opts)` grants `ec2:DescribeImages`). "One capability, two execution times." (https://alchemy.run/blog/2026-08-06-beta-70/)
- Bindings: `Alchemy.remote()` plus `pipe()` on Worker-only bindings and on plain binding values in an async Worker’s `env`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Bindings: `Cloudflare.Queues.consumeQueueMessages` with `Stream.runForEach` inside `Effect.gen` on `Cloudflare.Worker`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Bindings: `Alchemy.secret("API_KEY")`; Secrets Store values are Redacted-sourced. (https://alchemy.run/blog/2026-08-06-beta-70/)
- References: whole-resource references re-resolved at apply ([#1068](https://github.com/alchemy-run/alchemy/pull/1068), [#1070](https://github.com/alchemy-run/alchemy/pull/1070)). `Alchemy.renamedFrom` with a bare string, `{ fqn: "..." }`, or several former ids. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Phases: Workflows and Hyperdrive as dual providers make switching between dev and deploy "an engine-orchestrated replacement instead of ad-hoc branching." (https://alchemy.run/blog/2026-08-06-beta-70/)
- Layers: `Kubernetes.providers()` must be added to the stack. The post does not show a `Layer` value for it. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Errors: distilled clients put every error in the type-level union. A failed handler’s `HttpServerResponse` is preserved instead of a bare 500. Interrupted first deploy no longer raises `SchemaError` on later plans. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Telemetry: tail consumers — local producer trace events reach a local tail Worker. The post does not name OpenTelemetry, sinks, or a telemetry API. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Sinks: none named. (https://alchemy.run/blog/2026-08-06-beta-70/)

### Breaking changes

- Caution box, labeled **Behavior change** (not "breaking"): `Cloudflare.Website.StaticSite` no longer duplicates `env` resources into its own namespace ([#1053](https://github.com/alchemy-run/alchemy/pull/1053)). A shared KV namespace passed as `env` used to register a second physical copy at `<site-id>/…`. The site’s Worker moves from `<id>/Worker` to `<id>`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Pure-annotation auto-detection is removed entirely ([#1021](https://github.com/alchemy-run/alchemy/pull/1021)). A package with `sideEffects: false` is no longer auto-annotated. `effect`, `@effect/*`, and alchemy’s own packages stay annotated by default. Any other package is touched only when listed in `build.pure.packages`, or annotation is disabled with `pure: false`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Kubernetes workloads leave `AWS.EKS.*`. Old `AWS.EKS.Deployment`-style exports keep compiling for one release as deprecated aliases. (https://alchemy.run/blog/2026-08-06-beta-70/)

### Migration notes

- StaticSite Worker FQN change migrates in place on the next deploy via `renamedFrom()`: "same physical name, same `workers.dev` subdomain, nothing recreated." (https://alchemy.run/blog/2026-08-06-beta-70/)
- To rename any resource, declare former ids with `Alchemy.renamedFrom`. The next deploy plans a single re-branding update. Docs: `/infrastructure-as-code/renaming`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Kubernetes: add `Kubernetes.providers()`. Point `Deployment` / `Job` / `Manifest` / `HelmChart` at a cluster (`AWS.EKS.Cluster` or `Kubernetes.KubeConfig`). Existing state migrates in place. Deprecated `AWS.EKS.Deployment`-style aliases last one release. (https://alchemy.run/blog/2026-08-06-beta-70/)
- distilled v1 is a name-for-name migration of SDK surfaces. The post does not list caller-facing renames. (https://alchemy.run/blog/2026-08-06-beta-70/)
- If your own package relied on `sideEffects: false` to get pure annotations, list it explicitly: `pure: { packages: ["my-lib", "@my-scope/*"] }`. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Optional peers: install `pg`, `mysql2`, `mongodb`, or `@vercel/nft` only if you use them. (https://alchemy.run/blog/2026-08-06-beta-70/)

### Tips and tricks

- Builds are memoized by content-hashing the input files, so an unchanged project skips the build and deploy entirely. (https://alchemy.run/blog/2026-08-06-beta-70/)
- You do not install a wrangler binary, write `wrangler.json`, or install adapter packages for the six framework resources. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Astro sessions are zero-config: Alchemy auto-provisions the KV namespace and binds it as `SESSION`. Default output is server. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Next.js dev default is preview parity under workerd; Turbopack HMR is opt-in with `nextjs: { devMode: "hmr" }`. The other five use Vite HMR. Real bindings resolve in-process. (https://alchemy.run/blog/2026-08-06-beta-70/)
- `Alchemy.remote()` is "now the single way to opt a binding onto the real cloud during dev." (https://alchemy.run/blog/2026-08-06-beta-70/)
- Hybrid topology: pin a queue live and keep the Worker local. "Your dev session sees the same traffic as staging — messages produced by deployed services or a teammate’s session land in your local handler, and your local edits process them instantly." (https://alchemy.run/blog/2026-08-06-beta-70/)
- Vite child processes exist because plugin ecosystems resolve paths against `process.cwd()`. Config loaders, framework plugins, and tailwind broke when the stack ran from a different directory. Each server’s cwd is its project root, and multiple sites in one stack no longer interfere. Logs are prefixed with the worker name. (https://alchemy.run/blog/2026-08-06-beta-70/)
- `renamedFrom` is deliberately conservative: types must match; ambiguous claims and rename cycles fail the plan; an interrupted move’s leftover row is dropped state-only and never touches the cloud. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Changing a logical ID without `renamedFrom` still plans a replacement: new resource created, old one and its data deleted. (https://alchemy.run/blog/2026-08-06-beta-70/)
- On workerd, `SQL.MySQL` automatically switches to MySQL’s text protocol because "Hyperdrive’s proxy has no prepared statements", and uses eval-free row parsers. Lambda and containers keep prepared statements. Same lazy per-request pool lifecycle as Postgres. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Do not rely on `sideEffects: false` for tree-shaking. That auto-detection could delete `app.get("/", handler)` while unit tests stayed green. (https://alchemy.run/blog/2026-08-06-beta-70/)
- `AWS.Lambda.Version` and `Alias` are retain-by-default "for production-safe Durable Function deployments." (https://alchemy.run/blog/2026-08-06-beta-70/)
- Lambda `build.install` resolves the installed dependency graph against the lockfile (npm, pnpm, bun, yarn) via generated `overrides`, "so deployed artifacts can’t drift." (https://alchemy.run/blog/2026-08-06-beta-70/)
- `alchemy state export` is deterministically ordered so exports diff cleanly. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Asset-only website changes deploy because the assets directory is hashed during plan diff. Relative `rootDir`s hash stably. Dev child ports are allocated ephemerally. (https://alchemy.run/blog/2026-08-06-beta-70/)
- Writable ISR "fully works" only with both the KV incremental cache and the Durable Object queue (`DOQueueHandler`). (https://alchemy.run/blog/2026-08-06-beta-70/)

### Relevance

- **Cloudflare Workers.** The release is a Workers release. Six `Cloudflare.Website.*` resources deploy as Workers; `env` takes KV, R2, Durable Objects, and secrets; `alchemy dev` finishes local emulation past KV, R2, D1, and Queues; `WorkerEntrypoint`, `tailConsumers`, `Cloudflare.Workers.SecretKey`, `Cloudflare.Stream.Stream`, `Cloudflare.VpcService.lookup`, Access `oauthConfiguration` / `IdentityProvider` / `getIdentityProvider`, cron, email, Browser, Images, Workflows, and Hyperdrive are all Worker-adjacent. ### Tips and tricks

- Pin drizzle to the exact version `1.0.0-rc.5-ab785fc`. A caret range can resolve back to rc.4. (https://alchemy.run/blog/2026-08-12-beta-71/)
- Importing the Postgres or MySQL Drizzle client no longer requires `@effect/sql-mysql2` / `@effect/sql-pg` unless you actually connect. (https://alchemy.run/blog/2026-08-12-beta-71/)
- Swap auth databases by swapping the Layer. Neon needs no Hyperdrive and no `pg`. `AuroraDataApi` needs no VPC attachment (SQL over HTTPS with IAM). PlanetScale, RDS, or any connection string use the generic `Postgres` or `MySQL` TCP fallbacks. (https://alchemy.run/blog/2026-08-12-beta-71/)
- Use `SQLite` for local dev and `Memory` for tests. (https://alchemy.run/blog/2026-08-12-beta-71/)
- Better Auth migrations are an alchemy Action: input-hash diffed, and tree-shaken out of runtime bundles. You do not call them from the request path. (https://alchemy.run/blog/2026-08-12-beta-71/)
- `auth.fetch` is the same on Workers and Lambda. Direct `auth.api.*` calls keep set-cookie and typed `BetterAuthApiError` (`e.statusCode`, `e.body.code`). (https://alchemy.run/blog/2026-08-12-beta-71/)
- Dev proxy used to bind only `127.0.0.1` while browsers prefer `::1`, so a framework dev server could squat `[::1]:3000` and `http://localhost:3000` hit the wrong app. The proxy now owns the port on both address families. A restart no longer increments every configured port. (https://alchemy.run/blog/2026-08-12-beta-71/)
- Production framework builds are isolated child processes with `NODE_ENV=production` so user config and plugins can `chdir`, mutate `process.env`, or crash without taking the engine with them. (https://alchemy.run/blog/2026-08-12-beta-71/)
- `send()` to a local queue with no running consumer resolves instead of hanging. `batchSize` / `maxWaitTimeMs` are honored locally; they used to be silently ignored. (https://alchemy.run/blog/2026-08-12-beta-71/)
- Asset-first dev is the new default and matches production. Opt into worker-first only if the worker must intercept asset paths. (https://alchemy.run/blog/2026-08-12-beta-71/)
- Expect one full asset re-upload on the next deploy after this upgrade, because hashes now include the extension. (https://alchemy.run/blog/2026-08-12-beta-71/)
- Do not name stacks `aws-*` if physical names flow to Resource Groups, S3 Tables, or S3 Vectors. Colliding prefixes are escaped; other names stay byte-for-byte unchanged. (https://alchemy.run/blog/2026-08-12-beta-71/)
- InternetGateway destroy now waits 5–20 minutes for Fargate and Lambda ENIs instead of leaving an IGW+VPC residue. (https://alchemy.run/blog/2026-08-12-beta-71/)
- Docker `environment` is actually injected. Empty env was breaking PostgreSQL bootstrap. (https://alchemy.run/blog/2026-08-12-beta-71/)
- A `Date` prop that updated on every plan was the `{}` serialization bug, not a real diff. (https://alchemy.run/blog/2026-08-12-beta-71/)
- Stale `Alchemy.remote()` 400s on KV/R2/D1 (up to 50 minutes) were destroyed-resource sessions, not your binding code. (https://alchemy.run/blog/2026-08-12-beta-71/)

### Relevance

- **Cloudflare Workers.** Better Auth’s sample is a `Cloudflare.Worker` class served with `auth.fetch`. `CloudflareD1` and `CloudflareHyperdrive` are first-party auth databases. `@alchemy.run/cloudflare-runtime` and `@alchemy.run/cloudflare-frameworks` land in the monorepo. `Website.Vite` queue consumers, `assets.runWorkerFirst`, and the dev proxy/port fixes are Workers-dev behavior. "Worker props can now be an Effect". (https://alchemy.run/blog/2026-08-12-beta-71/)
- **R2.** No new R2 resource. The remote-binding fix covers R2 explicitly: edge preview was "400ing every proxied KV/R2/D1 call for up to 50 minutes." Asset MIME/hash changes affect Worker static assets, not R2. (https://alchemy.run/blog/2026-08-12-beta-71/)
- **AWS EC2 autoscaling runner fleet.** None. (https://alchemy.run/blog/2026-08-12-beta-71/)
- **Lambda.** Better Auth routes "on Workers and Lambda unchanged". InternetGateway detach waits out "Fargate and Lambda ENIs" that hold public IPs for 5–20 minutes. No Lambda resource API is added in this post. (https://alchemy.run/blog/2026-08-12-beta-71/)
- **S3.** No bucket resource. Name generation: stacks named `aws-*` "produced physical names that Resource Groups, S3 Tables, and S3 Vectors reject; colliding prefixes are now escaped, and non-colliding names are byte-for-byte unchanged." (https://alchemy.run/blog/2026-08-12-beta-71/)
- **IAM.** No IAM resource. `AuroraDataApi` is "SQL over HTTPS with IAM — no VPC attachment." (https://alchemy.run/blog/2026-08-12-beta-71/)
- **KMS.** None. (https://alchemy.run/blog/2026-08-12-beta-71/)
- **Budgets.** None. (https://alchemy.run/blog/2026-08-12-beta-71/)
- **GitHub repository settings.** None. (https://alchemy.run/blog/2026-08-12-beta-71/)
- **Custom Vercel provider.** None. (https://alchemy.run/blog/2026-08-12-beta-71/)
- **Docker over SSH.** None. Docker change that does exist: "`environment` entries resolved empty inside the container, breaking e.g. PostgreSQL bootstrap" and now arrive. That is env injection, not SSH transport. (https://alchemy.run/blog/2026-08-12-beta-71/)
- **AWS S3 BucketState store.** None. Date persistence is described for "durable state stores" generally: "a `Date`-typed prop used to serialize as `{}` in durable state stores, churning a phantom update on every subsequent plan." (https://alchemy.run/blog/2026-08-12-beta-71/)

### Do not roll your own

- An effectful Better Auth handle (`BetterAuth`, `auth.fetch`, typed `auth.api.*`, `BetterAuthApiError`) plus a Layer per database: `CloudflareD1`, `Neon`, `AuroraDataApi`, `CloudflareHyperdrive`, `Postgres`, `MySQL`, `SQLite`, `Memory`, `Drizzle`. (https://alchemy.run/blog/2026-08-12-beta-71/)
- Deploy-time auth schema migrations as an input-hashed alchemy Action that is tree-shaken out of the runtime bundle. (https://alchemy.run/blog/2026-08-12-beta-71/)
- Automatic repair of pre-beta.66 dev/deploy state, including queue consumer script mismatches, instead of hand-deleting Cloudflare consumers. (https://alchemy.run/blog/2026-08-12-beta-71/)
- Dual-stack localhost ownership so a configured dev port cannot be squatted on `::1`, and stable ports across dev restarts. (https://alchemy.run/blog/2026-08-12-beta-71/)
- Local queue semantics: Vite boot-order consumer wiring, `send()` that resolves with no consumer, and `batchSize` / `maxWaitTimeMs` actually applied. (https://alchemy.run/blog/2026-08-12-beta-71/)
- Disposable `NODE_ENV=production` framework build processes so a plugin `chdir` or crash cannot take down the engine. (https://alchemy.run/blog/2026-08-12-beta-71/)
- IGW detach that waits out Fargate/Lambda ENIs instead of leaking an IGW+VPC. (https://alchemy.run/blog/2026-08-12-beta-71/)
- Physical-name escaping for `aws-*` stacks so Resource Groups, S3 Tables, and S3 Vectors accept generated names. (https://alchemy.run/blog/2026-08-12-beta-71/)
- `Date` round-trip in durable state so plans do not phantom-update. (https://alchemy.run/blog/2026-08-12-beta-71/)

### State-store features

- `RemovalPolicy.retain()` is persisted on the noop apply path ([#1253](https://github.com/alchemy-run/alchemy/pull/1253)). A deploy that flips a policy prints a note. Because the policy now persists, a `retain()` removed from code takes effect: the next removal deletes the resource for real. (https://alchemy.run/blog/2026-08-25-beta-75/)
- SQL history lives in `__alchemy_migrations`. `migrationsDir` / `migrationsTable` are gone. A database previously migrated with drizzle-kit, Prisma, or wrangler is adopted by a one-way conversion: the old tool’s applied history is copied into Alchemy’s table once, validated against local migration files, and the old table is left frozen — never written, never dropped. Nothing replays. (https://alchemy.run/blog/2026-08-25-beta-75/)
- History validation is strict: a recorded migration with no matching local file fails the deploy instead of passing silently. (https://alchemy.run/blog/2026-08-25-beta-75/)
- `Worker.workerId` old state "heals itself on the next deploy." (https://alchemy.run/blog/2026-08-25-beta-75/)
- DynamoDB secondary-index state "upgrades without a replacement." (https://alchemy.run/blog/2026-08-25-beta-75/)
- Switching a resource between local and live "plans a **replacement**, so dev state never silently becomes cloud state." (https://alchemy.run/blog/2026-08-25-beta-75/)
- Prisma `State/PostgresState`: a state backend with per-stack advisory locks ([#1061](https://github.com/alchemy-run/alchemy/pull/1061)). This is Postgres, not S3. (https://alchemy.run/blog/2026-08-25-beta-75/)
- `alchemy unsafe nuke --local` wipes emulator state (floci-emulated account and Cloudflare local runtime) without cloud credentials. (https://alchemy.run/blog/2026-08-25-beta-75/)

Provided with `Effect.provide` (array form when more than one). (https://alchemy.run/blog/2026-08-25-beta-75/)
- Bindings (capability model, same shape as AWS and Cloudflare): Railway `ConnectPostgres`, `ReadWriteRedis`, `PutObject`; Hetzner `MountVolume`, `Hetzner.Ssh` (`exec`/`scp`), `ReadDns` / `WriteDns` / `ReadWriteDns`; Fly `ConnectPostgres`, `ReadRedis` / `WriteRedis` / `ReadWriteRedis`, `PutObject` / `GetObject`, `GetSecret` / `WriteSecret`, `Encrypt` / `Decrypt` / `Sign` / `Verify`, `MountVolume`; AWS local `AWS.S3.PutObject`, `AWS.SQS.SendMessage`; Prisma `ReadBucket` / `WriteBucket` / `ReadWriteBucket`; Cloudflare `Access.Context` / `getIdentity`; pipelines stream in `env`. - Layers: circular Worker layers typecheck ([#1199](https://github.com/alchemy-run/alchemy/pull/1199)) — `Worker.make` no longer leaks the other Worker’s tag into `Layer.mergeAll` requirements. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Phases: local ↔ live is a planned replacement. `Deployment.triggers` forces a Prisma redeploy when an opaque key/value changes. Hetzner `userData` changes plan a replacement because cloud-init only runs on first boot. Removal policy flips print a note on deploy. (https://alchemy.run/blog/2026-08-25-beta-75/)
- References: `Worker` bound to an already-yielded Worker no longer perpetual-`update`. Whole-resource `migrations: schema` orders Drizzle generation before apply. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Telemetry: `edgeDeployment` on `Axiom.Dataset`; "OTLP endpoints derive from Axiom’s regional URL." Tail/pipeline bindings are separate (pipelines stream in `env`). (https://alchemy.run/blog/2026-08-25-beta-75/)
- Sinks: the word is not used. Closest stream primitive is a pipelines stream placed in `env`, which becomes a pipelines binding instead of JSON. (https://alchemy.run/blog/2026-08-25-beta-75/)

### Tips and tricks

- "Change the namespace to change the cloud." `astro.config.*` still loads natively. Stage-varying values go in the `astro:` bag, not in a cloud-specific server bag. (https://alchemy.run/blog/2026-08-25-beta-75/)
- `alchemy dev` on every cloud "is the framework’s own server" — "native HMR, no cloud resources." (https://alchemy.run/blog/2026-08-25-beta-75/)
- An AWS Vite SPA is assets-only: no Lambda. Next.js on Fly, Hetzner, and Railway is `next build` plus a Node server; Cloudflare and AWS stay on OpenNext. (https://alchemy.run/blog/2026-08-25-beta-75/)
- React Router, SolidStart, and TanStack Start are not five-cloud website resources. They stay on Cloudflare `Website.Vite` and AWS dedicated composites. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Railway has no private registry. Push to GHCR or Docker Hub (`registry: "ghcr.io/acme"`). Public images use `image` (`hashicorp/http-echo`); GitHub source uses `repo`. (https://alchemy.run/blog/2026-08-25-beta-75/)
- `Railway.Function` cap is 96KB, Bun, no Docker, no registry. Use `Railway.Service` when you need `main` plus a registry. (https://alchemy.run/blog/2026-08-25-beta-75/)
- `Railway.healthcheck` / `cronSchedule` match Railway IaC. `api.url` is `https://{name}.up.railway.app`. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Hetzner `userData` is merged with alchemy’s bootstrap, not a replacement. Changing it replaces the server because cloud-init only runs on first boot. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Hetzner DNS clients are split least-privilege: `ReadDns` / `WriteDns` / `ReadWriteDns`. `Hetzner.Ssh(Box)` is the typed `exec`/`scp` client. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Fly `count` is how Anycast spreads replicas. Extra VMs of an existing image are extra `Fly.Machine` resources ("yield another to add capacity"), not a count field on Machine. (https://alchemy.run/blog/2026-08-25-beta-75/)
- `Fly.Sprite` has no parent App and no Docker image. It wakes on demand, hibernates when idle, and keeps its filesystem. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Fly Postgres `migrations` accepts a `Drizzle.Schema`, a directory, or `{ dir, table }`. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Local AWS: same program as production. Save the file and the Function serves new code in **~100–500ms**. `putObject` lands in the local bucket; queue consumers fire; websites run their own dev servers. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Do not expect dev state to become cloud state in place. Local ↔ `Alchemy.remote()` plans a replacement. A remote resource’s binding clients hit the real cloud, not just its lifecycle. (https://alchemy.run/blog/2026-08-25-beta-75/)
- `alchemy dev` needs no AWS account and no credentials. `alchemy unsafe nuke --local` wipes the emulator with no cloud credentials in reach. (https://alchemy.run/blog/2026-08-25-beta-75/)
- ECS tasks, Lambda MicroVMs, and EC2 instances that host an Effect program reload on save the same way as Functions. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Pass a `Drizzle.Schema` resource as `migrations` so generation is ordered before application in one deploy. Do not hand-sequence those steps. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Strict migration history: restore squashed files before upgrading or the deploy fails. The old drizzle-kit / Prisma / wrangler table is never written and never dropped. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Access enrollment goes through the binding contract, so removing `access` or the Worker un-enrolls on the next reconcile. `AllWorkers` covers every current and future Worker in the account. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Non-empty R2 buckets are protected by default. `forceDestroy: true` is the explicit opt-in. The incident that motivated this deleted 60k objects. (https://alchemy.run/blog/2026-08-25-beta-75/)
- A `retain()` you delete from source now deletes the cloud resource. Put it back before deploying if something still depends on it. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Lambda packaging is zip XOR image. Mixing `main` with `image` is a compile error. `image.uri` can point at an existing tag or digest; otherwise Alchemy builds the Dockerfile into a managed ECR repo. `architecture: "arm64"` is in the sample. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Nested `zipCode` archives are byte-deterministic across builds. Installed packages keep file modes and symlinks. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Process env wins over dotenv defaults ([#1355](https://github.com/alchemy-run/alchemy/pull/1355)). (https://alchemy.run/blog/2026-08-25-beta-75/)
- The CLI honors `STAGE`. The version check never suggests a downgrade. (https://alchemy.run/blog/2026-08-25-beta-75/)
- `Docker.Container` `ports: [{ external: 0 }]` reports the assigned host port. It will not detach Docker’s default `bridge`; only networks alchemy attached. `extraHosts` becomes `--add-host`. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Cloudflare container dev: loopback URLs are rewritten to the docker host; Linux reaches host databases via a unix-socket tunnel rather than the bridge IP; images hot-reload when context, Dockerfile, or props change. A `docker build` failure fails the deploy (with a buildx `--load` hint) instead of looping on "Container exited while waiting for port". (https://alchemy.run/blog/2026-08-25-beta-75/)
- A mid-edit syntax/eval error no longer kills `alchemy dev`; it logs and waits for the next save. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Queue names and other env-bound strings deploy bare, not JSON-quoted, so the dashboard and hand-written env reads see the real value. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Pin `Worker.domain` with `zoneId` / `zone` / `zoneName`. Unpinned hostnames resolve by name, not "the first page of an account-wide zone list." (https://alchemy.run/blog/2026-08-25-beta-75/)

- A pipelines stream in `env` must be a real binding; it used to fall through to JSON. (https://alchemy.run/blog/2026-08-25-beta-75/)
- GSI keys: up to 4 attributes on partition and on sort, diffs preserve order. (https://alchemy.run/blog/2026-08-25-beta-75/)
- RDS `DBParameterGroup.parameters` reconciles against live user-modified values, not only the last desired document. (https://alchemy.run/blog/2026-08-25-beta-75/)
- App Runner delete reaps auto-created log groups. (https://alchemy.run/blog/2026-08-25-beta-75/)

- DNS adoption no longer clobbers the first record that shares `(name, type)`; it disambiguates by content/priority. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Installing alchemy no longer pulls `@effect/vitest` (and its esbuild peer conflicts). (https://alchemy.run/blog/2026-08-25-beta-75/)
- A missing `.make` Layer names itself via `MissingImplementationError` instead of a deep `TypeError`. (https://alchemy.run/blog/2026-08-25-beta-75/)

### Relevance

- **Cloudflare Workers.** Websites stay on `Cloudflare.Website.*` (including `Vocs` and `Foldkit`) and now share props with the other four clouds. Access can be inline (`access.policies`), a shared `Cloudflare.Access.Application`, or account-wide `AllWorkers`, with `Cloudflare.Access.Context` / `getIdentity()` and a dev identity stub. Inbound mail is `Cloudflare.email({ zone }).subscribe`. `Worker.workerId` is the hex script tag Access destinations key on. `Worker.domain` takes `zoneId` / `zone` / `zoneName`. Preview versions carry static assets. Pipelines streams in `env` are real bindings. `limits: { steps }` caps workflow steps. SvelteKit 3 (`@sveltejs/kit@3.0.0-next.21+`) and Astro `prerenderEnvironment` are forwarded. Nested Worker env plans converge. Env strings deploy unquoted. (https://alchemy.run/blog/2026-08-25-beta-75/)
- **R2.** "Destroying a non-empty R2 bucket now fails instead of silently deleting every object" with `BucketNotEmpty`. Opt in: `Cloudflare.R2.Bucket("Cache", { forceDestroy: true })`. "`r2.dev` managed domain — enable it on `Cloudflare.R2.Bucket`." The 60k-object incident is the stated reason for the default flip. (https://alchemy.run/blog/2026-08-25-beta-75/)
- **AWS EC2.** Local dev reloads EC2 instances that host an Effect program: "EC2 instances that host an Effect program do too." No autoscaling group, launch template, runner fleet, or scaling policy is named. (https://alchemy.run/blog/2026-08-25-beta-75/)
- **Lambda.** Local: `AWS.Lambda.Function` with `functionUrl: true`, URL shape `http://b71ff5c0….lambda-url.us-east-1.localhost:4566/`, reload in ~100–500ms. `AWS.Lambda.MicrovmImage` runs in dev. Container functions: `image: { context, dockerfile }` or `image.uri`, managed ECR, `architecture: "arm64"`, zip XOR image. Breaking rename: Lambda’s `url` is `functionUrl`. Packaging keeps file modes and symlinks; nested `zipCode` is byte-deterministic. (https://alchemy.run/blog/2026-08-25-beta-75/)
- **S3.** Local only in this post: `yield* AWS.S3.Bucket("Files")`, `AWS.S3.PutObject`, `AWS.S3.PutObjectHttp`, output `Files.bucketName files-dev-x7k2`, endpoint host `localhost:4566`. "putObject lands in the local bucket." No live S3 bucket resource is introduced here. Fly’s object store is Tigris (`Fly.Bucket` + `PutObject`/`GetObject`), not AWS S3. Railway’s `Bucket` is "S3-style". Prisma’s `Prisma.Bucket` is Prisma object storage. (https://alchemy.run/blog/2026-08-25-beta-75/)
- **IAM.** None. (https://alchemy.run/blog/2026-08-25-beta-75/)
- **KMS.** "Cognito email OTP, CustomEmailSender, and KMS — on `UserPool`" ([#1323](https://github.com/alchemy-run/alchemy/pull/1323)). No key resource, alias, or grant API is shown. Fly `SecretKey` has `Encrypt` / `Decrypt` / `Sign` / `Verify`, which is Fly, not AWS KMS. (https://alchemy.run/blog/2026-08-25-beta-75/)
- **Budgets.** None. (https://alchemy.run/blog/2026-08-25-beta-75/)
- **GitHub repository settings.** None. Railway accepts `repo` for GitHub as a service source, and the sample registry is `ghcr.io/acme`. That is a deploy source, not repository settings. (https://alchemy.run/blog/2026-08-25-beta-75/)
- **Custom Vercel provider over `@distilled.cloud/vercel`.** None. (https://alchemy.run/blog/2026-08-25-beta-75/)
- **Docker over SSH.** Not described. Closest mechanisms, quoted: Hetzner "`Hetzner.Ssh(Box)` is a typed `exec`/`scp` client for a Server" and the Service "ships it to the server, and runs it under systemd". Railway and Fly "build a Docker image" and push to a registry. `Docker.Container` gains `ports: [{ external: 0 }]`, `extraHosts` as `--add-host`, and narrower network disconnect. Cloudflare Containers rewrite loopback to the docker host and tunnel Linux loopback over a unix socket. None of these say Docker is transported over SSH. (https://alchemy.run/blog/2026-08-25-beta-75/)
- **AWS S3 BucketState store.** None. State backends named here are `__alchemy_migrations` on D1/Neon/PlanetScale, removal-policy persistence on the resource row, and Prisma `State/PostgresState` "with per-stack advisory locks." Local S3 is an emulated bucket (`localhost:4566`), not a state store. (https://alchemy.run/blog/2026-08-25-beta-75/)

### Do not roll your own

- One website props vocabulary across Cloudflare, AWS, Hetzner, Railway, and Fly for `Vite`, `Foldkit`, `Astro`, `Nextjs`, `Nuxt`, `SvelteKit`, `Waku`, `Octane`, `StaticSite`, plus `Cloudflare.Website.Vocs` on Fly, Hetzner, and Railway. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Railway: Project, Service, Function (96KB Bun canvas), Postgres, MySQL, Mongo, Redis, Bucket, Volume, Variable, CustomDomain, TcpProxy, PrivateNetwork, image build/push, `ConnectPostgres`, `ReadWriteRedis`, `PutObject`. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Hetzner: Server, SshKey, Volume, VolumeAttachment, Network, Firewall, PlacementGroup, PrimaryIp, FloatingIp, FloatingIpAssignment, Certificate, LoadBalancer, Image, DNS Zone + RecordSet, systemd Service with readiness, `MountVolume`, typed `Ssh` exec/scp, split DNS clients, multipart `userData` that does not clobber bootstrap. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Fly: App, Machine, Service (Anycast `count`), Sprite (hibernate, persistent disk, no Docker), Volume + VolumeSnapshot, IpAssignment, Certificate, Secret, SecretKey (`Encrypt`/`Decrypt`/`Sign`/`Verify`), Postgres, Upstash Redis, Tigris. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Credential-free local AWS for Lambda, S3, DynamoDB, SQS, ECS, EC2, and websites, including MicroVMs, ~100–500ms reload, and `Alchemy.remote()` that plans a replacement rather than promoting dev state. (https://alchemy.run/blog/2026-08-25-beta-75/)

- Prisma object storage (`Prisma.Bucket`, `BucketAccessKey`, read/write bindings), a Postgres state backend with per-stack advisory locks, and `Deployment.triggers` for opaque secret rotation. (https://alchemy.run/blog/2026-08-25-beta-75/)
- Axiom dataset edge deployment with regional OTLP endpoints. (https://alchemy.run/blog/2026-08-25-beta-75/)
