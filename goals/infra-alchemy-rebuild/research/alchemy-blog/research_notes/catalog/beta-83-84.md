### New or changed resources

- `Cloudflare.Container` with `schedulingPolicy: "durable_object"` declares one container per image (`image`, or `dockerfile` plus `context`). PRs #1905 and #2223. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Example ids in the post: `Node` with `image: "node:24-slim"`; `Python` with `dockerfile: "./python/Dockerfile"` and `context: "./python"`; async-worker examples also use `python:3.13-slim` and `rust:1.90-slim`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- A Durable Object binds each container and calls `start()` with the instance size and entrypoint it chooses. The post’s example: `node.start({ instance: "lite", entrypoint: ["sleep", "infinity"], enableInternet: false })`, then `(yield* node.exec(cmd)).output()`, inside `Effect.scoped`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- “A Durable Object runs one container at a time, so start one image and `destroy()` it before you switch.” (https://alchemy.run/blog/2026-10-12-beta-83/)
- A plain async Durable Object lists containers on the binding: `Cloudflare.DurableObject("Agent", { containers: [Node, Python] })`. One container can back several classes (`Node` on both `Agent` and `Reviewer`, `Rust` only on `Reviewer`). (https://alchemy.run/blog/2026-10-12-beta-83/)
- The async class reads `this.ctx.container`. Images are `ctx.container.images` under the Container id (`container.images.Node`). `container.running`, `container.start({ image, entrypoint, enableInternet })`, `container.exec(cmd).output()`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- “Snapshots, SSH, and stdin streaming are supported, and the same code runs under `alchemy dev`.” Credit: Dan van der Merwe. Docs linked: `/cloudflare/compute/containers`, `/cloudflare/compute/container-lifecycle`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- `Cloudflare.K2.Stream` is “a durable event stream stored in R2” (#2010). Example: `Cloudflare.K2.Stream("Orders", { retention: "7 days" })`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- A Worker writes through `Cloudflare.K2.WriteStream(Orders)` and `orders.send([{ content }])`, provided with `Cloudflare.K2.WriteStreamBinding`. The sample returns HTTP 202 via `HttpServerResponse.empty`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Long-running hosts consume with `Cloudflare.K2.consumeStreamRecords(Orders, { startAt: "earliest", concurrency: 4 }, ...)`. The sample filters `order.amountCents > 100_000`. The post’s host example is a Fly Service. (https://alchemy.run/blog/2026-10-12-beta-83/)
- K2 caveat, quoted: “Workers can’t consume K2 streams yet. Cloudflare can’t push records to a Worker, so produce from Workers and consume from a long-running host such as a Fly, ECS, EC2, Railway, Hetzner, or Docker service. Alchemy will add a Worker consumer once Cloudflare supports one.” Docs: `/cloudflare/messaging/k2`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Cloudflare renamed its data platform **Basin**: “Pipelines, the R2 Data Catalog, and SQL.” The same resources are also exported as `Cloudflare.Basin.*` (#2010). (https://alchemy.run/blog/2026-10-12-beta-83/)
- Basin sample resources: `Cloudflare.R2.Bucket("Lake")`; `Cloudflare.Basin.Catalog("Catalog", { bucket: lake })`; `Cloudflare.Basin.Stream("PageViews", { schema: PageView })`; `Cloudflare.Basin.Sink("PageViewTable", { type: "basin_catalog", catalog, table: { namespace: "web", name: "page_views" }, token: yield* Config.Redacted("CATALOG_TOKEN") })`; `Cloudflare.Basin.Pipeline("PageViewEtl", { sql })` using `Output.interpolate` to `INSERT INTO ${table.name} SELECT ... FROM ${views.name}`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- “Alchemy checks the SQL with Cloudflare during plan, so a bad statement fails before anything changes.” (https://alchemy.run/blog/2026-10-12-beta-83/)
- `Cloudflare.Basin.Table` creates an Iceberg table directly, columns from an Effect Schema. Sample: `{ catalog, namespace: "sales", schema: Order, partitionBy: ["day(at)"] }`. Docs: `/cloudflare/data/pipelines`, `/cloudflare/data/iceberg-tables`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- `Cloudflare.KV.InstantNamespace` creates a namespace in Instant mode, “for small configuration that is read often” (#2027). Existing KV capabilities accept it. `alchemy dev` emulates it. Sample: `Cloudflare.KV.ReadNamespace(config)` then `kv.get("feature-enabled")`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- “Switching a namespace between classic and Instant replaces it and does not copy its data.” Credit: BlankParticle. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Workers Issues (#1992): `Cloudflare.Worker` `observability: { issues: { enabled: true } }`. “Version uploads and gradual rollouts keep the setting.” (https://alchemy.run/blog/2026-10-12-beta-83/)
- `Website.Vinext` supports vinext 1.0, including hybrid App and Pages Router builds (#2025). Credit: BlankParticle. (https://alchemy.run/blog/2026-10-12-beta-83/)

Origin uses `serviceId`: `{ scheme: "postgres", serviceId: service.serviceId, database: "app", user: "app", password: password.text }`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- “The guide connects a Worker to Aurora in private AWS subnets through a Cloudflare Tunnel, and `examples/cloudflare-hyperdrive-aws-vpc` deploys the whole thing.” Docs: `/cloudflare/data/hyperdrive-private-database`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- `entrypoints` sets Workers Cache per entrypoint (#2216). Sample: `default: { cache: { enabled: false } }`, `Public: { cache: { enabled: true } }`. “An entrypoint you don’t list uses the Worker’s `cache` setting.” (https://alchemy.run/blog/2026-10-12-beta-83/)

### Effect concepts

- **Bindings.** `yield* Sandbox` binds a container and does not start it. `Cloudflare.K2.WriteStream` plus `Cloudflare.K2.WriteStreamBinding`. `Cloudflare.KV.ReadNamespace`. `Git.BlobStoreR2` needs `Cloudflare.R2.ReadWriteBucketBinding` or `ReadWriteBucketHttp` on the Worker (#2102). DynamoDB HTTP bindings from Cloudflare Workers (#1782). An `MtlsCertificate` in `env` is an mTLS binding typed as a `Fetcher`, not a JSON binding (#2051). `MtlsCertificate.Fetch` from an Effect Worker. `Cloudflare.WorkerEntrypoint<Api>("Api")` without a Worker targets the declaring Worker. Effect Workers call themselves through `ctx.exports`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- **Sinks.** `Cloudflare.Basin.Sink` with `type: "basin_catalog"`, a catalog, `table: { namespace, name }`, and `token: yield* Config.Redacted("CATALOG_TOKEN")`. `QueueSink` drains an Effect `Stream` into a Queue, in batches Cloudflare accepts (#1781). (https://alchemy.run/blog/2026-10-12-beta-83/)
- **Phases.** Basin SQL is checked with Cloudflare during plan. DSQL rejects SQL it can’t run before the cluster is touched. Durable Object `exports` cutover: the first deploy after upgrading must go out at 100% traffic; if you use gradual deployments, remove `version.traffic` for that one deploy or it fails with `WorkerVersionConfigError`. Previews still use `migrations`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- **Telemetry.** Lambda timeouts (#1494): “the root span ends and telemetry flushes `timeoutMargin` before the timeout.” Workers AI reports billed neurons on finish parts (#1724). (https://alchemy.run/blog/2026-10-12-beta-83/)
- **References.** `InstanceId` is replaced by `ResourceContext` (#2160): `const { instanceId } = yield* ResourceContext`. Async containers are referenced as `ctx.container.images.<ContainerId>`. Durable Object bindings carry `containers: [...]`. Removing a Durable Object binding no longer deletes its namespace while the class is still exported; remove the class from code to delete it. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Other Effect surface used in samples, not new APIs by themselves: `Effect.gen`, `Effect.provide`, `Effect.scoped`, `Effect.andThen`, `Effect.succeed`, `Stream.map`, `Stream.filter`, `Stream.runForEach`, `HttpServerRequest`, `HttpServerResponse`, `Config.Redacted`, `Redacted.make`, `Output.interpolate`, and an Effect Schema as `Basin.Table`’s `schema`. (https://alchemy.run/blog/2026-10-12-beta-83/)

### Breaking changes

- **Containers start explicitly, and one Container is one image** (#1905, #2223). `Cloudflare.Containers.layer` is removed. (https://alchemy.run/blog/2026-10-12-beta-83/)
- `yield* Sandbox` binds the container without starting it. The caution fence shows the old use, then the required start. Old: `const sandbox = yield* Sandbox; return { ping: () => sandbox.ping() };`. New: `const start = sandbox.start({ enableInternet: true }); return { ping: () => start.pipe(Effect.andThen(sandbox.ping())) };`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- A Durable Object-managed Container declares a single `image` or `dockerfile`. “The `images` map from beta.82 is removed.” (https://alchemy.run/blog/2026-10-12-beta-83/)
- On an async Worker, the Container’s `className` is replaced by the Durable Object binding’s `containers`. A Durable Object-managed Container placed directly in `env` fails with `DurableObjectContainerBindingError`. The replacement shape shown: `env: { AGENT: Cloudflare.DurableObject("Agent", { containers: [Node, Python] }) }`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- A container’s RPC shape can no longer declare members the handle already has. The post lists `start`, `exec`, `image`, `getTcpPort`, and “…”. RPC on a stopped container fails with `ContainerNotRunningError`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- **`Pipelines.Stream` is private by default** (#2010). Declared without `http`, it no longer gets a public unauthenticated ingest endpoint. To keep one: `http: { enabled: true, authentication: false }`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- **Durable Objects deploy with `exports`, and you can’t go back** (#2135). “After a Worker with Durable Objects deploys on beta.82, older Alchemy releases can no longer deploy it.” “Once a Worker deploys with `exports`, a release before beta.82 can’t deploy it again.” (https://alchemy.run/blog/2026-10-12-beta-83/)
- **`InstanceId` is now `ResourceContext`** (#2160). Old: `import { InstanceId } from "alchemy"; const instanceId = yield* InstanceId;`. New: `import { ResourceContext } from "alchemy"; const { instanceId } = yield* ResourceContext;`. The fence also imports `effect/Effect` on the old side. (https://alchemy.run/blog/2026-10-12-beta-83/)
- **CLI runtime** (#2151): Node 24.11.1+ or Bun. Node 22 and 23 are no longer supported. (https://alchemy.run/blog/2026-10-12-beta-83/)
- **Bundle directory** (#2133): bundles are written to `.alchemy/bundles`, not `dist/`. “Workers and Lambdas redeploy once after you upgrade because their sourcemap paths change.” `build.output.dir` chooses a location. (https://alchemy.run/blog/2026-10-12-beta-83/)
- **`Git.BlobStoreR2`** (#2102) needs a `ReadWriteBucket` implementation: `Cloudflare.R2.ReadWriteBucketBinding` or `ReadWriteBucketHttp` on the Worker. (https://alchemy.run/blog/2026-10-12-beta-83/)
- **Removed GCP resources** (#2159, #2024): `GCP.WorkspaceEvents.TasksPushNotificationConfig` and the `GCP.Dataplex` data taxonomy resources. Google removed the APIs behind them. (https://alchemy.run/blog/2026-10-12-beta-83/)
- **`MtlsCertificate` in `env`** (#2051) is an mTLS binding typed as a `Fetcher`, instead of a JSON binding. (https://alchemy.run/blog/2026-10-12-beta-83/)

### Tips and tricks

- One container at a time per Durable Object; `destroy()` before switching images. (https://alchemy.run/blog/2026-10-12-beta-83/)
- K2: produce on Workers, consume on a long-running host (Fly, ECS, EC2, Railway, Hetzner, or Docker). Workers cannot consume yet. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Basin SQL is checked during plan, before anything changes. (https://alchemy.run/blog/2026-10-12-beta-83/)
- `Basin.Table` takes columns from an Effect Schema, with `partitionBy` (sample `["day(at)"]`). (https://alchemy.run/blog/2026-10-12-beta-83/)
- KV Instant is “for small configuration that is read often.” Classic ↔ Instant replaces the namespace and does not copy data. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Workers Issues stays on through version uploads and gradual rollouts. (https://alchemy.run/blog/2026-10-12-beta-83/)
- An entrypoint omitted from `entrypoints` uses the Worker’s `cache` setting. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Pin `alchemy@2.0.0-beta.82` or later on every laptop, CI job, and preview job before the exports deploy, and do not roll back past it. First deploy at 100% traffic. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Access `applicationId` keeps `id` and `aud`, so existing JWT validation keeps working. (https://alchemy.run/blog/2026-10-12-beta-83/)
- DSQL: one transaction per statement; `CREATE INDEX` is rewritten to `CREATE INDEX ASYNC`; illegal SQL never touches the cluster. (https://alchemy.run/blog/2026-10-12-beta-83/)
- “Every Neon role has owner-level access to the branch’s databases.” Password is stable. `noLogin: true` is supported. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Kubernetes secrets: plans and state stay wrapped; the cluster gets the real value; errors and Helm output are scrubbed, including base64 and JSON-escaped forms. Destroy on 403 or 5xx fails instead of reporting success. Unreachable API servers time out. (https://alchemy.run/blog/2026-10-12-beta-83/)
- `R2.S3Credentials` tokens are scoped to their bucket, not every bucket in the account. `locks` is the R2 bucket-lock prop. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Secrets Manager `recoveryWindowInDays` is opt-in. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Lambda delete no longer waits about 40 seconds for the log group (#2174). (https://alchemy.run/blog/2026-10-12-beta-83/)
- `Railway.Service` delete only removes that environment’s instance. (https://alchemy.run/blog/2026-10-12-beta-83/)
- AWS console login uses AWS CLI 2.32+ and no long-lived keys; refresh with `alchemy profile refresh`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Set `build.output.dir` if `.alchemy/bundles` is the wrong bundle directory. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Where to go next, as linked: `/cloudflare/compute/containers`, `/cloudflare/compute/container-lifecycle`, `/cloudflare/messaging/k2`, `/cloudflare/data/pipelines`, `/cloudflare/data/iceberg-tables`, `/cloudflare/data/hyperdrive-private-database`, `/cloudflare/networking/federated-apis`, `/cloudflare/compute/durable-objects`, `/cloudflare/compute/workers`, `/cloudflare/security/access`, `/kubernetes`, `/turso`, `/aws/setup`, `/aws/data/drizzle-dsql`, `/neon/data/roles`, changelog `#v200-beta83`, compare `v2.0.0-beta.81...v2.0.0-beta.83`. ### Do not roll your own

- Do not hand-start containers outside the new handle. `Cloudflare.Containers.layer` is removed; `start()` / `destroy()` and one image per `Cloudflare.Container` are the lifecycle. Snapshots, SSH, and stdin streaming are already on that handle. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Do not build an R2-backed event log or a Worker-side K2 consumer. Produce with `K2.WriteStream`; consume with `consumeStreamRecords` from a long-running host until Cloudflare can push to a Worker. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Do not hand-apply Pipeline SQL or hand-create Iceberg tables. `Basin.Pipeline` checks SQL during plan; `Basin.Table` builds columns from an Effect Schema. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Do not invent a second public ingest on `Pipelines.Stream`. The default is private; the public unauthenticated opt-in is `http: { enabled: true, authentication: false }`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Do not copy KV keys yourself when switching to Instant. The namespace is replaced and data is not copied. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Do not keep a parallel migrations journal for Durable Objects. Alchemy uploads `exports`. Do not roll a deployer back past beta.82 after that, and do not delete a namespace by only removing the binding. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Do not front a private Aurora with a public endpoint if Hyperdrive `serviceId` plus the Workers VPC / Cloudflare Tunnel path in `examples/cloudflare-hyperdrive-aws-vpc` is the intended shape. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Do not recreate a Cloudflare Access app to adopt it. Pass `applicationId` so `id` and `aud` stay put. A missing id must fail (`DeclaredApplicationNotFound`), not create. Clear a setting with `[]` or `false`; omission keeps the live value. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Do not wrap the Turso API, Drizzle connection, or per-tenant create. The post ships `Turso.Group`, `Turso.Database` (`migrations`), `Turso.Connect`, `Drizzle.LibSQL` / `SQL.LibSQL`, and `Turso.ManageDatabases`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Do not store long-lived AWS keys for the console path. The post’s path is `aws login` (CLI 2.32+) plus `alchemy profile edit --add AWS --method console-login` and `alchemy profile refresh`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Do not rewrite DSQL `CREATE INDEX` or run illegal DSQL yourself. `AWS.DSQL.Cluster` `migrations` runs each statement in its own transaction, rewrites `CREATE INDEX` to `CREATE INDEX ASYNC`, and rejects illegal SQL before the cluster is touched. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Do not hand-issue Neon role passwords. `Neon.Role` keeps a stable password. The post’s caveat is that every Neon role has owner-level access to the branch’s databases. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Do not substitute `<redacted>` into Kubernetes. `Redacted.make` now reaches the cluster as the secret; plans and state stay wrapped; errors are scrubbed including base64 and JSON-escaped forms. Do not treat a 403 or 5xx delete as success. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Do not batch a Cloudflare Queue by hand if `QueueSink` already drains an Effect `Stream` “in batches Cloudflare accepts.” (https://alchemy.run/blog/2026-10-12-beta-83/)
- Do not mint account-wide R2 S3 credentials. `R2.S3Credentials` is scoped to its bucket. Bucket locks are `locks` on `R2.Bucket`. (https://alchemy.run/blog/2026-10-12-beta-83/)
- Do not flush Lambda telemetry yourself at the timeout edge. The root span ends and telemetry flushes `timeoutMargin` before the timeout. (https://alchemy.run/blog/2026-10-12-beta-83/)

### Effect concepts

- **Bindings.** Every binding works on any host: ~2,850 AWS bindings / 205 services, 192 GCP bindings / 57 services, every Cloudflare `*Http` binding. Provide the `*Http` layer (`AWS.SQS.SendMessageHttp`, `AWS.S3.PutObjectHttp`, `Cloudflare.R2.WriteBucketHttp`). On an AWS host the binding grants the host role. On a Worker or Cloud Run, Alchemy creates a least-privilege IAM user and role and signs each call. GCP uses a service account and key. Role or service-account hosts omit that signing code from the bundle. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Bindings removed.** `AWS.Lambda.isBindingHost` is removed (#2260, #2347). “Custom AWS bindings use `AWSBindings.Bind` and `AWSBindings.withCredentials`.” (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Bindings, workflows.** `Workflows.layer` takes an Effect that resolves bindings (`Cloudflare.R2.WriteBucket`) and returns the handler. The Worker provides `Cloudflare.R2.WriteBucketBinding` plus an engine. `Workflows.RunWorkflow` is the start/read handle. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Bindings, dev.** `Website.Vite` dev covers Durable Objects from other Workers, Workflows, Containers, WebSockets, `ctx.access`, and Node.js polyfills. Asset routing follows `htmlHandling`, `notFoundHandling`, and `runWorkerFirst`. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Sinks.** This post does not name a new sink type. Beta.83’s `Basin.Sink` and `QueueSink` are unchanged here. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Phases.** Plan and apply were proportional to the square of the resource count: “Apply rebuilt every resource’s outputs once per resource, and plan scanned every node to find each node’s dependents. Both are now linear” (#2419). CI fails a missing or outdated state store unless `--yes`. Web Function `canary.weight` shifts traffic on deploy; edit the weight to promote or roll back. Existing `AWS.Website` sites “roll forward on the next deploy,” creating a `WebServer` Web Function and deleting the old server Lambda. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Telemetry.** This post does not name a new telemetry API. The CPU cuts are measurements of runtime bindings, not a telemetry feature. Beta.83’s Lambda `timeoutMargin` flush is not restated. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **References.** `WorkerEntrypoint` targets a cross-stack `Worker.ref` (#2414). `ctx.props` and `ctx.exports` in Effect Workers and Durable Objects (#2251). `ctx.access` works in Vite dev. Domain: `DomainCloudflare.DurableObjects` gives every aggregate, view key, and policy its own Durable Object. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Workflows (`effect/workflow`).** `Workflow.make` payload, success, and `idempotencyKey`. `Activity.make`. `DurableClock.sleep` suspends “and costs nothing while it waits.” Engines: `Cloudflare.Workflows.DurableObjectEngine`, `Cloudflare.Workflows.NativeEngine`, `AWS.Lambda.WorkflowFunction`, `AWS.Lambda.DurableFunctionEngine`. Run status tags: `NotStarted`, `Running`, `Completed`, `Failed`, `Interrupted`, `Died`. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Redacted wire format.** Prisma and Neon env values use the runtime wire format (#2244). `Prisma.Connect` and the Neon clients are unchanged. Direct `process.env` reads see `{"_tag":"Redacted","value":"…"}`. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Effect version.** “Bump `effect` and `@effect/*` to `^4.0.5`” (#2372). (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Distilled and Effect Schema.** Distilled error classes are no longer Effect Schemas (#2345). The rebuilt SDK “replaces Effect Schema with a lighter schema tree.” (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Other runtime Effect behavior.** SQL cursors allocate only what you use (#2281). RPC streams whose values arrive after the method returns now deliver every value (#2273). Durable callbacks that keep failing back off and park after eight attempts instead of waking forever (#1908). (https://alchemy.run/blog/2026-10-22-beta-84/)

### Tips and tricks

- Worker bundles dropped 346 KB → 216 KB because the stack builder and CLI auth code are no longer in the bundle (#2240). A Lambda that imports the Cloudflare barrel dropped 3.26 MB → 0.84 MB (#2267). (https://alchemy.run/blog/2026-10-22-beta-84/)
- Intro claim: rebuilt distilled SDKs “add 5–100× less overhead per call than the official AWS, Cloudflare and GCP SDKs, in bundles a third smaller than before.” (https://alchemy.run/blog/2026-10-22-beta-84/)
- Later claim, against official SDKs: “Distilled adds 5–100× less overhead per call, ships bundles 2–6× smaller, and imports with 3–22× less memory.” “Its first cold call is faster too, except on Cloudflare, where it takes 3.4 ms against the official SDK’s 1.9 ms.” (https://alchemy.run/blog/2026-10-22-beta-84/)
- Service counts printed for “importing a whole provider”: AWS 438 services, GCP 318, Cloudflare 129. Official comparison clients named: AWS SDK v3, the Stainless-built `cloudflare` package, and `@google-cloud/storage`. “Each official program imports one client. Each distilled program imports the whole provider and is still smaller.” Medians are over 98 one-auth, one-call programs. Table cells are not in the extract. (https://alchemy.run/blog/2026-10-22-beta-84/)
- R2 presigned URLs use `@distilled.cloud/aws4signer`, so the Cloudflare package no longer depends on the AWS SDK (#2370). (https://alchemy.run/blog/2026-10-22-beta-84/)
- Plan and apply are linear in resource count. They used to be proportional to the square. Timings are engine overhead only, no-op providers (#2419). Credit: gpu004. Timing numbers are not in the extract. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Account API Token Provisioning is off by default. Reconfigure with All Scopes, then enable it under Sensitive scopes, or alchemy cannot mint scoped API tokens. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Cross-cloud default: AWS host → grant the host role; any other host → least-privilege IAM user and role, sign each call; GCP → service account and key. Hosts that already run as a role or service account leave that code out of the bundle. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Web Functions: up to 128 in-flight requests per environment, streaming responses, an HTTPS endpoint, `canary.weight` to promote or roll back. `regions: ["us-east-1", "eu-west-1"]` is commented “one global domain.” Listen address for a custom server is `AWS_LAMBDA_HTTP_ENDPOINT`. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Next.js on AWS no longer needs OpenNext, SQS, or DynamoDB; it is a standalone server with an S3 cache. (https://alchemy.run/blog/2026-10-22-beta-84/)
- `DurableClock.sleep` “suspends for a week and costs nothing while it waits” (sample `duration: "7 days"`). (https://alchemy.run/blog/2026-10-22-beta-84/)
- Domain views are security boundaries. Clients can watch them live over WebSockets. An `alchemy-domain` skill ships in the package. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Vite dev, quoted behavior change: “dev before: `/api/some-file.txt` → the file on disk” / “dev now: `/api/some-file.txt` → the Worker, as deployed” when `runWorkerFirst: ["/api/*"]`. (https://alchemy.run/blog/2026-10-22-beta-84/)
- A Vite config that keeps `cloudflare()` from `@cloudflare/vite-plugin` now runs, “so RedwoodSDK, Flue and the Agents SDK build as documented.” (https://alchemy.run/blog/2026-10-22-beta-84/)
- Runtime: SQL cursors allocate only what you use. Late RPC stream values are delivered. Durable callbacks park after eight failed attempts. Dan van der Merwe measured CPU on deployed Workers and Durable Objects; the bar-chart numbers are not in the extract. The intro says “the runtime bindings use a lot less CPU.” (https://alchemy.run/blog/2026-10-22-beta-84/)
- Fly remote builds are the default. “Deploys no longer upload the whole ~86 MB `node:26-slim` image for every Service, which made them slow on home and CI connections.” Opt back to local Docker with `build: { remote: false }`. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Private RDS migrations run from a Lambda in the VPC (`AWS.RDS.MigrationRunner`). Public databases connect directly. Aurora uses the Data API. (https://alchemy.run/blog/2026-10-22-beta-84/)
- `GitHub.consumeRepositoryEvents` generates a webhook secret when you omit one, and checks every delivery’s signature. (https://alchemy.run/blog/2026-10-22-beta-84/)
- `GitHub.Ruleset` can adopt an existing ruleset by name. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Log redaction no longer leaks the tail of a secret that extends a shorter one (#2418). (https://alchemy.run/blog/2026-10-22-beta-84/)
- A logical id already used by another type fails with `DuplicateLogicalIdError` (#2063). (https://alchemy.run/blog/2026-10-22-beta-84/)
- Prisma Compute upload cap is 768 MiB (#2257). (https://alchemy.run/blog/2026-10-22-beta-84/)
- Where to go next, as linked: `/getting-started`, `/cloudflare/setup`, `/aws/setup`, `/gcp/setup`, `/domain`, `/domain/tutorial/part-1`, `/cloudflare/frontend/foldkit`, `/aws/compute/web-functions`, `/aws/frontend/nextjs`, `/aws/data/rds`, `/cloudflare/compute/effect-workflows`, `/aws/compute/effect-workflows`, `/cloudflare/frontend/vite`, changelog `#v200-beta84`, compare `v2.0.0-beta.83...v2.0.0-beta.84`. (https://alchemy.run/blog/2026-10-22-beta-84/)

### Relevance

Same monorepo target as beta.83. Mechanisms below are only what this post states.

- **Package split (install this, not `alchemy/AWS`).** `alchemy` stays the engine, CLI, and local/in-memory state. Providers move out. For this monorepo the printed mappings that matter are `alchemy/AWS` → `@alchemy.run/aws`, `alchemy/Cloudflare` → `@alchemy.run/cloudflare`, and the named packages `github`, `docker`, `git`, `domain`. Also printed: `@alchemy.run/aws/S3` and `@alchemy.run/aws/S3/Bucket` both resolve. `ServerHost` stays inside `alchemy` but moves `alchemy/Server` → `alchemy/Runtime/Process`. `alchemy/Workflows` is still the workflows import in the samples. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **AWS S3 state (`bucketName` vs `name`) and locking.** “`AWS.state({ name })` is now a short logical name. Use `bucketName` to pass a full bucket name.” “`AWS.state()` now locks each stack and stage too, so two concurrent deploys of one stage can no longer mix their state” (#2145). The post never uses the identifier `BucketState`. It does not print `alchemy state bootstrap --backend aws`. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Cloudflare state store.** Old `alchemy provider cloudflare bootstrap` prints the new command and exits 1. New: `alchemy state bootstrap --backend cloudflare`. Named: `Cloudflare.state({ name: "team-a" })` and `alchemy state bootstrap --backend cloudflare --name team-a`. The post does not say the backend is R2 or KV. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **GCP state store.** `GCP.state()` “keeps deploy state in a Cloud Storage bucket in your project”, with `GCP.providers()`, bootstrapped by `alchemy state bootstrap --backend gcp` (#2379). (https://alchemy.run/blog/2026-10-22-beta-84/)
- **CI state.** “In CI, a missing or outdated state store fails unless you pass `--yes`.” (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Workers calling AWS.** A Worker uses the same SQS binding as a Lambda: `yield* AWS.SQS.SendMessage(queue)` and `Effect.provide(AWS.SQS.SendMessageHttp)`. “On any other host, such as a Worker or Cloud Run, Alchemy creates a least-privilege IAM user and role for it and signs each call with that role.” Beta.83 only had S3, Lambda, and DynamoDB bindings working outside AWS. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Lambda writing R2.** “a Lambda writes to R2 through `Cloudflare.R2.WriteBucketHttp`, which binds a scoped Cloudflare API token.” OAuth can mint those tokens only after Account API Token Provisioning is turned on (off by default): `alchemy profile edit --reconfigure Cloudflare`, All Scopes, Sensitive scopes. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **R2, other.** `localUploads` on `Cloudflare.R2.Bucket` (#2424). Presigned URLs use `@distilled.cloud/aws4signer` and drop the AWS SDK dependency (#2370). The workflow sample writes profile JSON with `Cloudflare.R2.WriteBucket` / `WriteBucketBinding`. A Lambda that imports the Cloudflare barrel is 0.84 MB instead of 3.26 MB. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Workers, dev and deploy.** `alchemy dev` for Vite matches `@cloudflare/vite-plugin` (other Workers’ Durable Objects, Workflows, Containers, WebSockets, `ctx.access`, Node polyfills, HTTPS, Wrangler `/cdn-cgi/local/*`, `runWorkerFirst`). The dev server refuses `.env`, `.dev.vars`, and `.alchemy/`. Website builds receive `env` so `NEXT_PUBLIC_*` and `VITE_*` reach the client bundle. A full deploy returns `versionId` and `deploymentId`. `Worker.ref` is the cross-stack entrypoint target. Each Worker gets its own Cache store in dev (#2383). Node 26 deploys use HTTP/1.1 “avoiding stream resets.” Worker bundle 346 KB → 216 KB. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **EC2 / LaunchTemplate (no autoscaling resource).** `metadataOptions` on `AWS.EC2.Instance` and `LaunchTemplate` (#2426). `Redacted` `userData` on `Instance` (#2421). “EC2, LaunchTemplate, AppRunner and Batch hosts now get IAM grants, so they plan new IAM resources on the next deploy.” `Lambda.KafkaEventSource` “grants the EC2 permissions MSK mappings need” (#2401). An interrupted VPC create is recovered instead of leaked (#2416). No autoscaling group, fleet, or runner-pool resource is named. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Lambda.** `AWS.Lambda.WebFunction`: 128 requests per environment, streaming, HTTPS, `authType: "ApplicationManaged"`, canary `weight`, multi-region “one global domain,” custom servers on `AWS_LAMBDA_HTTP_ENDPOINT`. Default for server-rendered `AWS.Website` (Nuxt, SvelteKit, Astro, React Router, SolidStart, TanStack Start, Waku, Octane, Vinext). Next deploy creates `WebServer` and deletes the old server Lambda, keeping CloudFront and the domain. `server: "function"` keeps a Function URL. `AWS.Lambda.WorkflowFunction` plus `AWS.Lambda.DurableFunctionEngine`. Private RDS migrations run from a Lambda in the VPC via `AWS.RDS.MigrationRunner`. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **S3 (application, not state).** Web Function sample: `AWS.S3.Bucket("Uploads")`, `AWS.S3.PutObject`, `AWS.S3.PutObjectHttp`. Next.js “standalone server with an S3 cache, without OpenNext, SQS or DynamoDB.” (https://alchemy.run/blog/2026-10-22-beta-84/)
- **IAM.** Non-AWS hosts get a least-privilege IAM user and role; AWS hosts get grants on the host role; custom bindings use `AWSBindings.Bind` and `AWSBindings.withCredentials`; EC2, LaunchTemplate, AppRunner, and Batch plan new IAM on the next deploy. GCP resources named: `GCP.IAM.ServiceAccount` and `ServiceAccountKey` (#2347), plus a service account and key for non-GCP hosts calling GCP. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **KMS.** The only mention: `AWS.RDS.Aurora` accepts Outputs for `kmsKeyId` and `migrations` (#2364). No KMS key resource is introduced. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Budgets.** Not mentioned. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **GitHub repository settings.** `GitHub.Ruleset` gains `allowedMergeMethods` and `requireExtraApprovalForUnattributedChanges` (#2397) and adopts an existing ruleset by name (#2129). `GitHub.BranchProtection` deploys with `requiredStatusChecks.checks` (#2076). `GitHub.consumeRepositoryEvents` generates a webhook secret when omitted and checks every signature (#1932). Import move: `GitHub.Cloudflare.RepositoryEventSourceLive` → `GitHub.RepositoryEventSourceLive`. The package name `github` is in the split list. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Vercel / `@distilled.cloud/vercel`.** Not named. The distilled breaking change that a custom distilled provider would hit: error classes are no longer Effect Schemas (`TooManyRequests.is(error)`, not `Schema.is(TooManyRequests)(error)`); generated request and response schemas are not exported (`putDispatchNamespaceScript.input.ast`, not `PutDispatchNamespaceScriptRequest.ast`). The only `@distilled.cloud/*` package named is `@distilled.cloud/aws4signer`. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Docker.** The package name `docker` is in the split list. `Docker.Context` missing from a fresh CI runner is re-created (#2187). Fly’s opt-out `build: { remote: false }` “build and push with your local Docker engine instead.” This post does not describe Docker over SSH. (https://alchemy.run/blog/2026-10-22-beta-84/)
- **Effect pin.** `effect` and `@effect/*` must be `^4.0.5` (#2372). (https://alchemy.run/blog/2026-10-22-beta-84/)

### Do not roll your own

- Do not keep `alchemy/AWS`, `alchemy/Cloudflare`, or the other `alchemy/<Provider>` imports. Install the provider package and use the `@alchemy.run/...` path. Do not invent a second engine: `alchemy` still holds the CLI and the local and in-memory state stores. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Do not keep calling `alchemy provider cloudflare bootstrap` or `alchemy prisma generate`. They print the replacement and exit 1. Use `alchemy state bootstrap --backend cloudflare` and `alchemy provider prisma generate`. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Do not pass a full S3 bucket name as `AWS.state({ name })`. `name` is a short logical name; `bucketName` is the full name. Do not hand-lock a stage: `AWS.state()` locks each stack and stage so two deploys cannot mix that stage’s state. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Do not hand-build a GCP state bucket. `GCP.state()` stores state in a Cloud Storage bucket in the project; bootstrap with `alchemy state bootstrap --backend gcp`. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Do not hand-build a Cloudflare state backend under the old `alchemy provider cloudflare bootstrap` command. Use `Cloudflare.state({ name })` and `alchemy state bootstrap --backend cloudflare --name <name>`. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Do not sign AWS calls from a Worker yourself. Provide `AWS.SQS.SendMessageHttp` (or the other `*Http` layer). Alchemy creates the least-privilege IAM user and role and signs each call. On an AWS host, do not also hand-grant what the binding grants to the host role — and do expect EC2, LaunchTemplate, AppRunner, and Batch to plan new IAM after `isBindingHost` was removed. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Do not mint a broad Cloudflare token for Lambda → R2. `Cloudflare.R2.WriteBucketHttp` binds a scoped API token. Turn on Account API Token Provisioning (Sensitive scopes, off by default) so OAuth can mint it. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Do not treat distilled errors as Effect Schemas, and do not import generated `*Request` / `*Response` schemas. Use `TooManyRequests.is(error)` and `putDispatchNamespaceScript.input.ast`. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Do not parse Prisma or Neon secrets out of `process.env`. That view is the Redacted wire format. Use `Prisma.Connect` or the Neon clients. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Do not stand up OpenNext, SQS, and DynamoDB for Next.js on AWS. The post’s server is a standalone Web Function with an S3 cache. Do not hand-roll canaries: `canary: { weight }` promotes or rolls back. Set `server: "function"` only if the old Lambda Function URL server must stay. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Do not write a second workflow engine. `alchemy/Workflows` already runs `effect/workflow` on `DurableObjectEngine`, `NativeEngine`, and `AWS.Lambda.WorkflowFunction` / `DurableFunctionEngine`. `DurableClock.sleep` is the suspend path that “costs nothing while it waits.” (https://alchemy.run/blog/2026-10-22-beta-84/)
- Do not hand-build Durable Object event sourcing if `@alchemy.run/domain` is the model. Commands, aggregates, events, views, policies, sagas, and projections run in memory for tests and on `DomainCloudflare.DurableObjects` in production. Views are the security boundary. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Do not put a migration runner in the VPC by hand for private RDS. `AWS.RDS.MigrationRunner` is that Lambda; Aurora runs migrations over the Data API; a public database connects directly. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Do not upload the ~86 MB `node:26-slim` image on every Fly deploy. Remote builders are the default; `build: { remote: false }` is the local-Docker opt-out. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Do not invent a GitHub webhook secret, or hand-adopt a ruleset, if `GitHub.consumeRepositoryEvents` (secret generated when omitted, signature checked) and `GitHub.Ruleset` adopt-by-name are enough. Branch protection status checks are `requiredStatusChecks.checks`. (https://alchemy.run/blog/2026-10-22-beta-84/)
- Do not bind a Hyperdrive you do not want Alchemy to manage. `Cloudflare.Hyperdrive.lookup` binds an existing configuration without managing it. (https://alchemy.run/blog/2026-10-22-beta-84/)
