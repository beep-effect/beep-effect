### New or changed resources

- `Domain.Model("Bank", { aggregates: [Account] })`, then a later deploy adds `views: [AccountSummary]`. Adding a view is one line; the deploy brings consumers up to date from history with no script to write (`#2725`, `#2875`). https://alchemy.run/blog/2026-11-01-beta-85/
- `Domain.View("AccountSummary", { from: [Account], key: Account, state: Schema.Struct({ net: Schema.Number }), initial: { net: 0 }, evolve: { MoneyDeposited, MoneyWithdrawn }, version: 1 })`. Changing what a view computes is a version bump. The new `MoneyWithdrawn` evolve is "applied to every past withdrawal". https://alchemy.run/blog/2026-11-01-beta-85/
- Deploy strategy: a view keyed by the one aggregate it reads is rebuilt in place (each key re-reads its own aggregate's events the first time it is touched; the deploy waits for nothing). Any other view, "such as a total across every account", is rebuilt from the history in new storage, and the deploy waits and reports progress. https://alchemy.run/blog/2026-11-01-beta-85/
- Progress identifiers printed: `[DomainBackfillRun] Backfilling view:Deposits reading history 41% (1,690/4,096 subtrees, 410,211 instances) (48s) ...` and `[DomainBackfillRun] Backfilled view:Deposits (112.4s)`. https://alchemy.run/blog/2026-11-01-beta-85/
- `history.complete` tells a screen when a view has caught up. Reads stay correct while new code rolls out. A deploy interrupted halfway picks up where it stopped. https://alchemy.run/blog/2026-11-01-beta-85/
- Cloudflare replay shape (not a new resource name, but the mechanism under backfill): replay runs as Durable Objects, not on the deploying machine. Every aggregate instance lists itself in a directory on its first commit: a tree where each node holds up to 256 instances and splits into 16 children when it fills. A backfill's root splits that directory into a few hundred subtrees and hands them to relays. A relay given more than six items splits them among six child relays. https://alchemy.run/blog/2026-11-01-beta-85/
- View application at the leaves: a view keyed by its aggregate reads its own instance's events and applies them. A view that many instances feed, "like a timeline", gets a scanner per instance that pushes each key its share; once every scanner has pushed, each key applies its events in the order they were recorded. Every part of the run is a class only the new code has, so nothing starts on the old code while Cloudflare rolls the deploy out. https://alchemy.run/blog/2026-11-01-beta-85/
- Docs for replay: `/domain/model#consumers-added-later-receive-the-history`, `/domain/model#change-a-view-bump-its-version`, `/domain/model#fill-a-view-lazily`, `/domain/backfill#width`. https://alchemy.run/blog/2026-11-01-beta-85/
- Domain layout upgrade (`#2560`): on Cloudflare a Domain model is a set of Durable Object classes holding every aggregate, view row and running saga. The deployed layout is versioned. Every Worker that hosts a model records the Domain version it was deployed with. The Worker's reconciler upgrades older layouts on the next deploy, renaming classes in place in the same upload, so no data is copied or lost. Future layout changes ship as new upgrade steps in Alchemy. https://alchemy.run/blog/2026-11-01-beta-85/

### Tips and tricks

- Release size: 249 pull requests, 39 contributors, 84 features, 95 bug fixes. Domain alone is 30 features, mostly by Taras Kornichuk (`artile`). "Most of this release is fixes, many found by new test suites rather than by users." https://alchemy.run/blog/2026-11-01-beta-85/
- 270×: the heading and the intro say AWS state "plans 270× faster". The body does not show the benchmark. What it does state is one on-demand DynamoDB table per account and region, and one `Query` to load the stage. https://alchemy.run/blog/2026-11-01-beta-85/

- Cheapest backfill: a view keyed by the one aggregate it reads rebuilds in place and the deploy waits for nothing. Any other view rebuilds in new storage and the deploy waits and reports progress. https://alchemy.run/blog/2026-11-01-beta-85/
- Reads stay correct while new code rolls out. `history.complete` tells a screen when a view has caught up. An interrupted deploy resumes. https://alchemy.run/blog/2026-11-01-beta-85/
- Replay does not run on the deploying machine. It runs as Durable Objects. Directory nodes hold up to 256 instances and split into 16 children. Relays fan out at most six ways because "a Cloudflare Worker invocation runs at most six outgoing calls at a time, so a seventh would only wait in line." Depth is about log base 6 of the instance count: 6 levels for 10,000 instances, 8 for a million. https://alchemy.run/blog/2026-11-01-beta-85/
- Measured on Cloudflare, rebuilding a view over accounts with 10 deposits each. Past about 100,000 accounts the limit is Cloudflare's cap on how fast one account can create and call Durable Objects, not the tree. The run paces itself "the way TCP does": it sends more while the account keeps up, halves when Cloudflare refuses calls, and resends the refused work. The million-account run held about 2,000 keys a second. https://alchemy.run/blog/2026-11-01-beta-85/
- Backfill classes exist only on the new code, so old isolates do not start the new replay while Cloudflare rolls out. https://alchemy.run/blog/2026-11-01-beta-85/
- Layout upgrades rename classes in place (`renamed_classes`); "no data is copied or lost." A newer Alchemy's Worker is never moved back. https://alchemy.run/blog/2026-11-01-beta-85/

### Do not roll your own

- Domain history replay: "Change the model, and the deploy brings every consumer up to date from the history, with no script to write" (`#2725`, `#2875`). Adding a view is one line. Changing the computation is a `version` bump. Do not write a backfill script, a lazy-vs-eager selector, or a progress reporter: in-place rebuild vs new-storage rebuild, `DomainBackfillRun` progress, `history.complete`, and resume-after-interrupt are the deploy. https://alchemy.run/blog/2026-11-01-beta-85/
- Do not hand-roll the Cloudflare relay tree either: directory nodes of 256 splitting into 16, six-wide relays because a Worker invocation allows six outgoing calls, log₆ depth, scanners for cross-instance views, TCP-style pacing against the account's Durable Object create/call cap (~2,000 keys/s at a million accounts in their measurement). The post presents that as how Alchemy's backfill runs, not as a recipe to copy. https://alchemy.run/blog/2026-11-01-beta-85/
- Durable Object layout migrations: "Changing how those classes are laid out would normally mean a hand-written migration and a careful cutover. In Alchemy it's part of the deploy." Renames are `renamed_classes` in the same upload (`#2560`). Future layout changes "ship as new upgrade steps in Alchemy, and your deploy applies them." Do not copy class storage yourself. Do not deploy an older Alchemy onto an upgraded Worker (`DomainVersionTooNew`). If two models shared one aggregate class, set `legacyData: true` on the model that keeps it instead of splitting the data by hand. https://alchemy.run/blog/2026-11-01-beta-85/
- One `Domain.Api` is the client surface. Do not build a second HTTP API, MCP server, CLI and Foldkit binding that can drift apart: `DomainHttp.toHttpApi`, `DomainAi.toMcp`, the generated CLI, and Foldkit commands/subscriptions (`#2700`) share middleware and rejections. The aggregate, policy, projection and external system stay inside the model. https://alchemy.run/blog/2026-11-01-beta-85/
- Optimistic UI: use `Aggregate.predict` and `View.snapshot` (`#2568`, `#2567`) instead of re-implementing command rules on the client or inventing a cursor. `watch` already streams `{ state, cursor }`; `events` ends with `CaughtUp` (`#2579`). Cancel a scheduled command with `unschedule` (`#2547`). https://alchemy.run/blog/2026-11-01-beta-85/
- Story doubles: do not keep a fully scripted fake of every external system. `stub` chooses the fakes; other systems run through the adapter Layer (`#2477`, `#2481`). `Story.call` plus `Story.succeed` or `Story.returned` is the assertion. Do not ignore side-effect events: unasserted commits fail the story (`#2551`). Do not accept a stub value the schema rejects (`#2548`). https://alchemy.run/blog/2026-11-01-beta-85/
- Test harness: do not write an Effect test runner, a per-test output demuxer, or an agent log scraper. `@alchemy.run/test` runs tests as Effects, buffers each test's stdout/stderr, prints failures in one piece, writes `.alchemy/log/test/...` including passes, and after 10s of silence names the tests still running (`#2452`). `Test.make` deploys a stack for a test file and works with `bun test` and Vitest. `--stage <name>` separates git worktrees on one cloud account (`#2613`). https://alchemy.run/blog/2026-11-01-beta-85/
- CLI wrapping: "The `alchemy` CLI is now a thin layer over `alchemy/Alchemist`." Plan, apply, drift, nuke, logs and state are calls (`Alchemist.plan`, `Alchemist.apply`, `Alchemist.Drift.scan`, `Alchemist.Drift.execute`, `Alchemist.onEvent`, `Alchemist.layer`). Do not scrape CLI text. The NDJSON log under `.alchemy/log/` already includes child processes and sidecars (`#2765`). `--log-ansi` is gone; telemetry no longer exports log records. https://alchemy.run/blog/2026-11-01-beta-85/
- Cloudflare state store: do not keep managing the `CloudflareStateStore` stack, and do not rotate the auth token or encryption key from a deploy. v8 deploys the store with direct API calls (`#2385`), only creates a secret that is missing, and will not mint a new key for a store that lost one unless you confirm. Losing that key "nothing can recover." Pin `accountId` instead of inventing a guard against the wrong Cloudflare login. Use `domain` instead of a private tunnel just to avoid `workers.dev`. Use `workerName` for the full Worker name; do not reimplement the old `alchemy-state-store-` prefix. https://alchemy.run/blog/2026-11-01-beta-85/
- AWS state: do not build a new state backend beside these two. `AWS.state()` is one on-demand DynamoDB table per account and region, loaded with one `Query` (`#2683`, `#2691`). Move stages with `alchemy state migrate`. Keep the old store only via `AWS.state({ backend: "s3" })`. Do not delete the S3 copy yourself; the post says nothing in S3 is deleted, and older Alchemy is fenced out of that copy. Roll back only with `alchemy state migrate --rollback` before downgrading. The post does not name `BucketState`. https://alchemy.run/blog/2026-11-01-beta-85/
- Custom-domain DNS: do not hand-publish certificate validation records, ACME challenges, verification TXTs or aliases. Set `domain.dns` to an adapter (`#1888`). Shipping adapters: `Cloudflare.DNS.Adapter`, `AWS.Route53.Adapter`, `Hetzner.DNS.Adapter`. A new provider "is three functions", not a new publisher. https://alchemy.run/blog/2026-11-01-beta-85/
- Keyless AWS–GCP: do not create a service account key for a GCP binding on Lambda, ECS, EC2 or App Runner (`#2648`), and do not create an IAM user or access key for Cloud Run or Cloud Functions to call AWS (`#2645`). Use the binding / workload identity the deploy now creates. For CI, use `WorkloadIdentityPool` and `WorkloadIdentityProvider` (`#2130`) rather than a long-lived key. The post's diagram still prints `WorkerServiceAccountKey`; the prose says a key is no longer created. Do not add a key "to match the diagram" without reading that tension as unresolved in this post. https://alchemy.run/blog/2026-11-01-beta-85/
- Cloud Run sidecars and RPC: do not hand-order container startup or hand-roll localhost clients. List containers on an image service; `bindPort` / `bindContainer` on a program. `InvokeService` signs with the caller's ID token. Do not expose RPC by turning the invoker check off; that deploy fails (`#2653`, `#2654`). https://alchemy.run/blog/2026-11-01-beta-85/
- GCP SQL migrations: do not write a separate migrator for Cloud SQL, AlloyDB or Spanner. `migrations` on `GCP.SQL.Database` matches D1, Neon, PlanetScale, Turso, RDS and DSQL (`#2651`). Default path is the Cloud SQL data API (no network route). Spanner already resumes at the failed statement. https://alchemy.run/blog/2026-11-01-beta-85/
- Lambda rollout: do not point event sources at `$LATEST` and do not build a second rollback pointer if `alias` fits. `alias` publishes a version and routes event sources, the URL and integrations (`#2504`). Do not fail a whole SQS/Kinesis/DynamoDB Streams batch when the handler can return `batchItemFailures` (`#2508`). Do not buffer a `RESPONSE_STREAM` body (`#2502`). Do not invent a pre-kill flush: `timeout` interrupts the handler so finalizers run and telemetry flushes, with `timeoutMargin` on the Lambda side (`#2682`). https://alchemy.run/blog/2026-11-01-beta-85/
- Workflow engines: do not assume one engine's semantics. The same 28-case suite covers the Durable Object engine, Cloudflare Workflows and Lambda durable functions (`#2916`). `Activity.raceAll` is unsupported on two of them and now fails at once, pointing at the Durable Object engine. Do not paper over that with a hang timeout. https://alchemy.run/blog/2026-11-01-beta-85/
- Ownership and destroy: do not add a takeover/adopt path that overwrites a Worker or Lambda, replaces a name someone else owns, or deletes a same-named resource while recovering an interrupted create (`#2195`, `#2620`, `#2200`, `#2199`, `#2534`). Do not run the program just to plan a destroy; `alchemy destroy` plans from state without cloud credentials (`#2491`). `--repair` recreates deleted resources in dependency order (`#2495`). EC2 create retries must not launch a second instance; Alchemy now treats them as idempotent (`#2598`). https://alchemy.run/blog/2026-11-01-beta-85/
- Drizzle: do not answer rename-or-create outside the plan. Drizzle 1.0 rc.5 asks those questions during plan (`#2433`). https://alchemy.run/blog/2026-11-01-beta-85/
- R2 destroy: do not manually abort multipart uploads before `forceDestroy`; that flag now deletes a bucket holding unfinished multipart uploads (`#2537`). https://alchemy.run/blog/2026-11-01-beta-85/
- What this post does not hand you, so do not treat it as coverage: KMS, budgets, Vercel / `@distilled.cloud/vercel`, Docker over SSH, and a type named `BucketState`. S3 state remains only as `AWS.state({ backend: "s3" })`, the un-deleted S3 copy, and `alchemy state migrate --rollback`. https://alchemy.run/blog/2026-11-01-beta-85/
