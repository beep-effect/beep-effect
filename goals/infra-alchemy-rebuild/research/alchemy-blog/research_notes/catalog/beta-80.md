## beta.80 — 2.0.0-beta.80 - GCP, Neon & Secret Providers

- URL: https://alchemy.run/blog/2026-09-29-beta-80/
- Date (from frontmatter): 2026-09-29T09:00:00.000Z
- Version: v2.0.0-beta.80 (`beta.80`). Frontmatter title is `2.0.0-beta.80 - GCP, Neon &amp; Secret Providers`. Compare link is `v2.0.0-beta.79...v2.0.0-beta.80`. Changelog anchor is `#v200-beta80`. (https://alchemy.run/blog/2026-09-29-beta-80/)

Headline, as written: Google Cloud (~1,050 resources across 190 services; Effect-native runtimes on Cloud Run, Cloud Functions, and GKE; bindings that grant each host the narrowest IAM role GCP allows); Neon as a full backend (Functions, object storage, managed Auth, the Data API, AI Gateway, and 13 `Neon.Website` frameworks); secret providers (dotenv, Doppler, Infisical, per stage, browser login locally, OIDC in CI). Also: Effect 4.0 stable is the baseline; Prisma ORM v8 with an Effect-native Postgres runtime; `Fly.Service` is its own App (public URL, typed calls to other Services, blue/green deploys, multi-container Machines); `--include` / `--exclude` deploy a slice of a stack; on Cloudflare: durable callbacks, hibernating WebSocket RPC, presigned R2 URLs under `alchemy dev`, and Queue subscriptions from any resource. (https://alchemy.run/blog/2026-09-29-beta-80/)

### Tips and tricks

Secrets precedence ([#1728](https://github.com/alchemy-run/alchemy/pull/1728)): (https://alchemy.run/blog/2026-09-29-beta-80/)

- "Later entries override earlier ones." (https://alchemy.run/blog/2026-09-29-beta-80/)
- "A missing key falls through to the next source, and an empty string counts as a value." (https://alchemy.run/blog/2026-09-29-beta-80/)
- "The process environment is always the implicit last entry, so a one-off `DATABASE_URL=… alchemy deploy` or a CI runner’s exported variables still win." (https://alchemy.run/blog/2026-09-29-beta-80/)
- "List `Alchemy.Secrets.ProcessEnv()` yourself to rank it elsewhere, or pass `{ disabled: true }` to leave the shell out." (https://alchemy.run/blog/2026-09-29-beta-80/)
- "`secrets` and every provider’s options also accept a callback that receives the stage, so one stack serves `dev`, `pr-42`, and `prod` from different places." (https://alchemy.run/blog/2026-09-29-beta-80/)
- "Nothing is written to `process.env` or to disk." (https://alchemy.run/blog/2026-09-29-beta-80/)
- "`--log-level debug` prints which variable names each source loaded, never their values." (https://alchemy.run/blog/2026-09-29-beta-80/)
- A changed `Config` value read during a Worker’s Init plans an update, so rotating the value in Doppler and running `alchemy deploy` ships it ([#1837](https://github.com/alchemy-run/alchemy/pull/1837)). (https://alchemy.run/blog/2026-09-29-beta-80/)

GCP: (https://alchemy.run/blog/2026-09-29-beta-80/)

- "The default region comes from your profile (else `us-central1`)," and `GCP.Region("europe-west1")` overrides it for a stack. (https://alchemy.run/blog/2026-09-29-beta-80/)
- "Reconciles wait until GCP reports a resource ready, deletes wait until it is gone." (https://alchemy.run/blog/2026-09-29-beta-80/)
- Fulfillment "has no public URL. Pub/Sub signs each push with an OIDC token for the service’s own account, which gets `run.invoker` on the service, and every request’s token is verified before the handler runs." (https://alchemy.run/blog/2026-09-29-beta-80/)
- "A failure answers the push with a 500, so Pub/Sub redelivers." (https://alchemy.run/blog/2026-09-29-beta-80/)
- Jobs and WorkerPools pull with `GCP.Run.TopicPullEventSource` instead of the push path. (https://alchemy.run/blog/2026-09-29-beta-80/)
- Firestore `ReadWriteDatabase` is `datastore.user` "under an IAM Condition naming only this database." Pub/Sub `WriteTopic` is `pubsub.publisher` "on this topic only." (https://alchemy.run/blog/2026-09-29-beta-80/)

Neon and Prisma: (https://alchemy.run/blog/2026-09-29-beta-80/)

- Neon bindings do not pass "your deployment API key to the application." (https://alchemy.run/blog/2026-09-29-beta-80/)
- "`alchemy dev` runs each website’s native framework server and a local Fetch runtime for Functions; `.pipe(Alchemy.remote())` deploys one for real." (https://alchemy.run/blog/2026-09-29-beta-80/)
- `QueryDataApi` "forwards the caller’s JWT so row-level security applies." (https://alchemy.run/blog/2026-09-29-beta-80/)
- Neon organization governance (API keys, member roles, spending limits, VPC endpoints) is "experimental." (https://alchemy.run/blog/2026-09-29-beta-80/)
- Prisma "stays an optional peer." TypeScript and PSL "use the same runtime." "Queries, prepared statements, streams, and transactions are Effects with typed errors and per-execution connection cleanup." (https://alchemy.run/blog/2026-09-29-beta-80/)
- Prisma dev commands default to `NODE_ENV=development` ([#1703](https://github.com/alchemy-run/alchemy/pull/1703)). (https://alchemy.run/blog/2026-09-29-beta-80/)
- `alchemy/Prisma`, Fly, Hetzner, Railway, and Neon import without `@alchemy.run/frontend-frameworks` installed ([#1815](https://github.com/alchemy-run/alchemy/pull/1815)). (https://alchemy.run/blog/2026-09-29-beta-80/)

Fly: (https://alchemy.run/blog/2026-09-29-beta-80/)

- `public: false` keeps a Service off the internet. (https://alchemy.run/blog/2026-09-29-beta-80/)
- `network: yield* Fly.stackNetwork` isolates Services "on a private network per stack and stage." (https://alchemy.run/blog/2026-09-29-beta-80/)
- `region: ["iad", "lhr"]` runs `count` Machines in each region "behind one hostname." (https://alchemy.run/blog/2026-09-29-beta-80/)
- Blue/green ([#1706](https://github.com/alchemy-run/alchemy/pull/1706)): checked replacement before stopping the running version. `shutdown` "gives in-flight responses time to finish" (example `"60 seconds"`). "An interrupted rollout resumes on the next deploy, and a failed readiness check leaves the old version serving." (https://alchemy.run/blog/2026-09-29-beta-80/)
- "Rolling updates stay the default and remain the only option for volume-backed Services." (https://alchemy.run/blog/2026-09-29-beta-80/)
- Rolling updates wait for service checks before the next replica ([#1670](https://github.com/alchemy-run/alchemy/pull/1670)). (https://alchemy.run/blog/2026-09-29-beta-80/)
- Multi-container `dependsOn` condition shown: `"healthy"`. (https://alchemy.run/blog/2026-09-29-beta-80/)

Partial deploy ([#1757](https://github.com/alchemy-run/alchemy/pull/1757)): (https://alchemy.run/blog/2026-09-29-beta-80/)

- "Dependencies of included resources come along automatically." (https://alchemy.run/blog/2026-09-29-beta-80/)
- "Excluding one fails the plan with its dependency chain." (https://alchemy.run/blog/2026-09-29-beta-80/)
- "Excluded state is left untouched." (https://alchemy.run/blog/2026-09-29-beta-80/)
- Flags accept an FQN, a logical ID, or a glob, and can repeat. `Test.make` `deploy` takes the same filters. (https://alchemy.run/blog/2026-09-29-beta-80/)

Durable Objects, RPC, attachments: (https://alchemy.run/blog/2026-09-29-beta-80/)

- Callback scheduling "joins the storage transaction, so the write and the job commit together." (https://alchemy.run/blog/2026-09-29-beta-80/)
- "Delivery is at least once with retries." (https://alchemy.run/blog/2026-09-29-beta-80/)
- Existing `scheduleEvent` jobs "keep running beside callbacks on the object’s single alarm." (https://alchemy.run/blog/2026-09-29-beta-80/)
- "Alarm updates are now batched once per transaction" ([#1701](https://github.com/alchemy-run/alchemy/pull/1701)). (https://alchemy.run/blog/2026-09-29-beta-80/)
- Hibernating WebSocket RPC: "The request picks the transport; your code doesn’t change." (https://alchemy.run/blog/2026-09-29-beta-80/)
- "Every call on that socket goes to the `"alice"` object. While the connection is idle the Durable Object can hibernate; the next call wakes it and is answered on the same socket. Alchemy handles the heartbeats and restores the connection after a wake." (https://alchemy.run/blog/2026-09-29-beta-80/)
- "In-flight calls are not replayed: if the object restarts mid-call, the socket closes with code `1012`." (https://alchemy.run/blog/2026-09-29-beta-80/)
- `RpcWebSocketClient` "imports only Effect modules, so it is safe to bundle." (https://alchemy.run/blog/2026-09-29-beta-80/)
- Typed attachments: a session read back after hibernation "comes back decoded and typed, where `deserializeAttachment` used to return an unchecked value." (https://alchemy.run/blog/2026-09-29-beta-80/)

### Relevance

Target: Cloudflare Workers + R2. The post ships several mechanisms that apply directly. (https://alchemy.run/blog/2026-09-29-beta-80/)

- Workers default: "JavaScript Workers default to `new_module_registry` in deploys, `alchemy dev`, and Vite preview." Opt out with `compatibility: { flags: ["legacy_module_registry"] }`. "Python Workers are unchanged." Prebuilt Workers "keep explicit compatibility flags." (https://alchemy.run/blog/2026-09-29-beta-80/)
- Presigned R2: "The same code signs against the Worker’s local dev URL in dev and against `r2.cloudflarestorage.com` when deployed." Binding is `Cloudflare.R2.PresignPutObject` plus Layer `Cloudflare.R2.PresignPutObjectToken`. "No extra configuration." (https://alchemy.run/blog/2026-09-29-beta-80/)
- S3-compatible access from Async Workers: `Cloudflare.R2.S3Credentials(bucket, { access: "write" })` "delivers an endpoint and scoped keys for any S3 client." "The local S3 endpoint runs inside the Worker’s existing workerd process," and the dev proxy answers `Expect: 100-continue` (3 MB AWS SDK `PutObject` from ~6 s to ~130 ms). (https://alchemy.run/blog/2026-09-29-beta-80/)
- Cross-stack R2 events: `Cloudflare.R2.Bucket.ref("Uploads", { stack: "storage", stage: "prod" })` as `source` of `Cloudflare.Queues.Subscription`, events `bucket.created` and `bucket.deleted`. Sources also include Images, KV, Vectorize, Workers, Workflows, `AI.Model`, and `R2.SuperSlurperJob`. (https://alchemy.run/blog/2026-09-29-beta-80/)
- "`R2.SuperSlurperJob`, a one-off migration into R2 from S3 or another bucket." (https://alchemy.run/blog/2026-09-29-beta-80/)
- Local Workers without a Cloudflare profile: "a stack of local Workers, KV, R2, and D1 runs without a profile" because "Cloudflare authentication is deferred until a cloud call needs it." (https://alchemy.run/blog/2026-09-29-beta-80/)
- Secrets land in Workers: `Config.Redacted` "captured by a Worker or Lambda" resolves from `secrets`, and a changed value read during Worker Init plans an update. (https://alchemy.run/blog/2026-09-29-beta-80/)
- Durable Object work that survives the request: `Alchemy.makeCallback`, SQLite plus native alarms, at-least-once, joins `storage.transaction`. Stricter transactions: sibling-fiber storage access inside `storage.transaction`, and writes after `txn.rollback()`, fail. (https://alchemy.run/blog/2026-09-29-beta-80/)
- `Cloudflare.RpcDurableObject` serves Effect RPC over hibernating WebSockets and HTTP. Browser client is `alchemy/Cloudflare/RpcWebSocketClient`. Close code `1012` if the object restarts mid-call. (https://alchemy.run/blog/2026-09-29-beta-80/)
- Plain DO sockets: `socket.setAttachment` / `getAttachment` with an Effect Schema; failure is `WebSocketAttachmentError`. (https://alchemy.run/blog/2026-09-29-beta-80/)
- `Cloudflare.Workflows.task` keeps typed errors across retry and replay. Account-global `workflowName`. `Cloudflare.Workflow.ref` for another stack. (https://alchemy.run/blog/2026-09-29-beta-80/)
- `Cloudflare.SqlMigrations("./drizzle")` at DO construction, atomic with the history row. (https://alchemy.run/blog/2026-09-29-beta-80/)
- `build.input` passes Rolldown options such as `resolve.alias`. Full deploys keep `version.tag` and `version.message`. Workers-for-Platforms uploads keep `_headers` and `_redirects`. (https://alchemy.run/blog/2026-09-29-beta-80/)
- `Cloudflare.Container.ref` and `publish: { repository: "web" }` (images and layers reused across stages; builds cached by default). (https://alchemy.run/blog/2026-09-29-beta-80/)
- `Cloudflare.Access.McpServer` registers upstream MCP servers with Access. (https://alchemy.run/blog/2026-09-29-beta-80/)
- Websites on Workers: Vinext "deploys a Worker with KV caching and prerender seeding, without Wrangler or OpenNext." Next.js ISR is the `isr` prop plus KV namespaces and a `DOQueueHandler` Durable Object, without `open-next.config.ts`. Private Websites for SvelteKit, Nuxt, Octane, Next.js, Astro, Waku, and Vocs "answer service-binding calls in dev." (https://alchemy.run/blog/2026-09-29-beta-80/)
- Partial apply against a Worker stack: `alchemy deploy --include`, `alchemy dev --exclude`, and `Test.make` `deploy({ include })`. (https://alchemy.run/blog/2026-09-29-beta-80/)
- DNS: "DNS records only treat a missing record as gone." ACME DNS-01 is `Cloudflare.DNS.AcmeSolver({ zoneId })`. (https://alchemy.run/blog/2026-09-29-beta-80/)

### Do not roll your own

The post says these already ship. Each is a capability a team would otherwise build. (https://alchemy.run/blog/2026-09-29-beta-80/)

- Secret loading: `Alchemy.Stack` `secrets` resolves every `Config.Redacted` in the stack, in a resource provider, or captured by a Worker or Lambda, from dotenv (`Alchemy.Secrets.DotEnv`), Doppler (`Doppler.Secrets`), and Infisical (`Infisical.Secrets`), or "any Effect Layer that provides a `ConfigProvider`." Nothing is written to `process.env` or disk. Precedence, stage callbacks, browser login (`alchemy profile edit --add`), CI tokens, and OIDC on GitHub Actions, GitLab CI, Vercel, and Google Cloud are included ([#1728](https://github.com/alchemy-run/alchemy/pull/1728)). (https://alchemy.run/blog/2026-09-29-beta-80/)
- Partial stack deploy: `--include` / `--exclude` on `alchemy deploy`, `alchemy dev`, and `alchemy plan`, plus `Test.make` `deploy({ include })`. Dependencies of included resources come along; excluded state is left untouched ([#1757](https://github.com/alchemy-run/alchemy/pull/1757)). (https://alchemy.run/blog/2026-09-29-beta-80/)
- Presigned R2: `Cloudflare.R2.PresignPutObject` under `alchemy dev` and against `r2.cloudflarestorage.com` when deployed, with no extra configuration ([#1793](https://github.com/alchemy-run/alchemy/pull/1793)). Neon storage also has "presigned GET/PUT URLs." (https://alchemy.run/blog/2026-09-29-beta-80/)
- Scoped S3 credentials for R2: `Cloudflare.R2.S3Credentials(bucket, { access: "write" })`. (https://alchemy.run/blog/2026-09-29-beta-80/)
- ACME: `alchemy/ACME` "issues and renews certificates from Let’s Encrypt or any ACME CA," with `Cloudflare.DNS.AcmeSolver` for DNS-01, `ACME.IssueCertificate` for runtime issuance, and `Fly.WriteCertificates` / `Fly.Certificate` to install them ([#1702](https://github.com/alchemy-run/alchemy/pull/1702)). (https://alchemy.run/blog/2026-09-29-beta-80/)
- Queue subscriptions from any resource: `Cloudflare.Queues.Subscription` `source` is a resource or `.ref(...)`, including another stack. Named sources: Images, KV, R2, Vectorize, Workers, Workflows, `AI.Model`, `R2.SuperSlurperJob` ([#1722](https://github.com/alchemy-run/alchemy/pull/1722), [#1505](https://github.com/alchemy-run/alchemy/pull/1505)). (https://alchemy.run/blog/2026-09-29-beta-80/)
- Kubernetes: `Kubernetes.LocalCluster` (kind plus local registry) and `Kubernetes.KubeConfig` with a named registry, for workloads from `main` or a Docker context onto GKE, AKS, k3s, or a laptop ([#1779](https://github.com/alchemy-run/alchemy/pull/1779)). (https://alchemy.run/blog/2026-09-29-beta-80/)
- Prisma: Effect-native Postgres runtime for queries, prepared statements, streams, and transactions; TypeScript `defineContract` or PSL via `alchemy prisma generate`; deploy-time migrations through `Prisma.Contract` and `Prisma.Migrate` ([#1198](https://github.com/alchemy-run/alchemy/pull/1198)). (https://alchemy.run/blog/2026-09-29-beta-80/)
- Neon backend in one stack: `Neon.Function` (Node 24), `Neon.Project`, `Neon.Bucket`, `Neon.Connect`, Auth (`AuthOAuthProvider`, `AuthTrustedDomain`, `ConnectAuth`), `DataApi` / `QueryDataApi`, `QueryAIGateway`, `CronEventSource`, `BucketEventSource`, `Credential`, `CustomDomain`, and 13 `Neon.Website` frameworks ([#1695](https://github.com/alchemy-run/alchemy/pull/1695)).
