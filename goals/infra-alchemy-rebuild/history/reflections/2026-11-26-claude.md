# Reflection — infra-alchemy-rebuild (2026-11-26, claude)

## Summary

The goal replaced every Pulumi program with Alchemy stacks:
- Storybook, the turbo cache, cost controls and GitHub in P3;
- OIP web and AI metrics in P4;
- the runner fleet in P5.

It then destroyed the last Pulumi stack (`beep-ci-runners`, 353 resources, export archived). The final PR, #3567, deletes `infra/` and Pulumi from the repository. The verdict is done, apart from two operator steps after the merge that touch no repository file: `pulumi stack rm` and the step 6 (f) choices.

## Tooling experience

- **Worked:**
  - The pinned destroy checkout at the last commit that still held the program let the destroy run while the deletion PR was already prepared.
  - A small mode script (`export | preview | destroy | remaining`) gave every live step the same receipt shape.
  - `beep cache baseline --request` made re-recording drifted subjects after each main merge mechanical.
- **Didn't:** the bucket pre-read. It reported zero objects for a bucket holding 6111, so the first destroy stopped part way.
- **Frustrating:** every merge of main conflicted on generated files: tsconfig paths, the fallow boundaries, the schema-first inventory and cache-baseline shards. Each needed take-theirs, re-apply and regenerate.
- **Wished existed:** a single `beep merge-main --regenerate` that re-runs every generator touched by the conflicted paths.

## Implementation improvement opportunities

- The cutover decision kept inventory rows that named files by tracked path. Once a file is deleted those rows become broken-path findings. Inventories of things a PR deletes should use prose names.
- The `@beep/infra-github` census needed hand edits for credentials that only a destroyed stack used. An `unmanaged` entry could carry an owning-stack field, so a stack destroy lists the entries it retires.

## Goal & prompt critique

- Add to PLAN.md's P6 row: "Merges only after the step 6 (d) destroy receipt is posted from a checkout at or before the last program commit. It is an operator hand merge when it touches `.github/`." That ordering was the gating fact for P6 and lived only in rulings.
- The P7/P8 split adds little when P6 is the last repository change. Say that P6's PR is the final PR unless a later phase changes files.

## TODOs worth codifying

- A bucket-content read in the Pulumi destroy runbook (see findings).
- A hold-thread marker for `yeet monitor`.
- A fresh-base knowledge delta in final-check.

## Lessons (confidence-tiered)

- **HIGH — Critical:** read the S3 contents with a non-paginated KeyCount, plus versions, before any stack destroy that owns a bucket. A null KeyCount is not zero.
- **MEDIUM — Best practice:** stop on the first destroy error and report a partial receipt. The second run then took 5 seconds and left a clean two-run record.
- **LOW — Consideration:** fold the closeout into the last code PR when the remaining steps are operator actions with no repository change. It saves a review window and a merge slot.
