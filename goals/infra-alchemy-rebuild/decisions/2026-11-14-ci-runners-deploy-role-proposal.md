Role `beep-alchemy-ci-runners-deploy`: trusted by the existing provider `token.actions.githubusercontent.com`, audience `sts.amazonaws.com`, subject exactly `repo:beep-effect/beep-effect:environment:ci-runners-prod`, one-hour sessions. Inline policy `ci-runners-deploy`. Since the gate ruling of 2026-11-14 every name the stack and the composite choose in `prod` is pinned under `beep-fleet-prod-` (physical-names decision), so the policy is scoped by those names; EC2 network objects, launch templates and KMS keys have AWS-assigned ids and stay scoped by the ownership tags Alchemy stamps (`alchemy::stack = CiRunners`, `alchemy::stage = prod`). The one generated-name exception is the nine Lambda execution roles, which `Lambda.Function` names `CiRunners-<logical id>-prod-<suffix>` with no prop to pin them:

- State: `s3:ListBucket`, `s3:GetBucketLocation`, `s3:GetBucketVersioning`, `s3:GetBucketOwnershipControls`, `s3:GetBucketPublicAccessBlock`, `s3:GetEncryptionConfiguration` on `arn:aws:s3:::alchemy-state-832907639880-us-east-1-an`; `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject` on `arn:aws:s3:::alchemy-state-832907639880-us-east-1-an/CiRunners/*` only.
- EC2 reads: `ec2:Describe*` on `*`.
- EC2 creates (VPC, subnet, internet gateway, route table, security group `beep-fleet-prod-runner`, flow log, launch templates `beep-fleet-prod-{heavy,overflow}`): `ec2:CreateVpc`, `ec2:CreateSubnet`, `ec2:CreateInternetGateway`, `ec2:CreateRouteTable`, `ec2:CreateSecurityGroup`, `ec2:CreateFlowLogs`, `ec2:CreateLaunchTemplate` with `aws:RequestTag/alchemy::stack = CiRunners` and `aws:RequestTag/alchemy::stage = prod`. `ec2:CreateTags` in two statements only (amended 2026-11-18): tag-on-create, with `ec2:CreateAction` in exactly those seven create actions plus the same two request tags (Alchemy's EC2 providers tag through `TagSpecifications` on create); and direct `CreateTags` only on a resource that already carries `aws:ResourceTag/alchemy::stack = CiRunners` and `aws:ResourceTag/alchemy::stage = prod` (tag updates of the stack's own resources). A request tag alone never grants `CreateTags`: otherwise the role could stamp `alchemy::stack = CiRunners` on a live-fleet resource and gain every tag-scoped mutation and delete below on it.
- EC2 mutations and deletes on resources tagged `alchemy::stack = CiRunners` and `alchemy::stage = prod`: `ec2:ModifyVpcAttribute`, `ec2:AttachInternetGateway`, `ec2:DetachInternetGateway`, `ec2:CreateRoute`, `ec2:ReplaceRoute`, `ec2:DeleteRoute`, `ec2:AssociateRouteTable`, `ec2:DisassociateRouteTable`, `ec2:ModifySubnetAttribute`, `ec2:AuthorizeSecurityGroupEgress`, `ec2:RevokeSecurityGroupEgress`, `ec2:CreateLaunchTemplateVersion`, `ec2:ModifyLaunchTemplate`, `ec2:DeleteLaunchTemplateVersions`, `ec2:DeleteLaunchTemplate`, `ec2:DeleteFlowLogs`, `ec2:DeleteSecurityGroup`, `ec2:DeleteSubnet`, `ec2:DeleteRouteTable`, `ec2:DeleteInternetGateway`, `ec2:DeleteVpc`, `ec2:DeleteTags`. The new VPC's default security group carries no Alchemy tag: AWS creates it with the VPC, and `DefaultSecurityGroup` only empties its rules. Its two revokes are therefore granted positively, scoped to the new fleet VPC, in a second policy version (amended 2026-11-18, #3386 review). v1, created at step 0, has no default-group grant. v2 adds `ec2:RevokeSecurityGroupIngress` and `ec2:RevokeSecurityGroupEgress` on `security-group/*` with `ArnEquals ec2:Vpc` = the new fleet VPC's ARN. That ARN exists only once cutover step 1a has deployed the VPC, so the gate writes v2 after 1a (one `describe-vpcs` filtered on `tag:alchemy::stack=CiRunners`), re-runs the simulations below and only then dispatches the full deploy (step 1b). No grant reaches a security group in any other VPC. The sweep on destroy: `ec2:TerminateInstances` on instances whose `ghr:environment` starts with `beep-fleet-prod-` (`StringLike`).
- IAM: `iam:CreateRole`, `iam:DeleteRole`, `iam:GetRole`, `iam:UpdateRole`, `iam:UpdateAssumeRolePolicy`, `iam:TagRole`, `iam:UntagRole`, `iam:PutRolePolicy`, `iam:DeleteRolePolicy`, `iam:GetRolePolicy`, `iam:ListRolePolicies`, `iam:AttachRolePolicy`, `iam:DetachRolePolicy`, `iam:ListAttachedRolePolicies`, `iam:PutRolePermissionsBoundary` on `arn:aws:iam::832907639880:role/beep-fleet-prod-*` (runner roles `beep-fleet-prod-{heavy,overflow}-runner`, flow-logs role `beep-fleet-prod-flow-logs`) and, for the Lambda execution roles only, `arn:aws:iam::832907639880:role/CiRunners-*-prod-*`; policy CRUD and versions on `arn:aws:iam::832907639880:policy/beep-fleet/prod/*`; instance-profile CRUD and `iam:AddRoleToInstanceProfile`/`RemoveRoleFromInstanceProfile` on `arn:aws:iam::832907639880:instance-profile/beep-fleet-prod-*`; `iam:PassRole` on those roles with `iam:PassedToService` in `lambda.amazonaws.com`, `ec2.amazonaws.com`, `vpc-flow-logs.amazonaws.com`. Role creation requires the boundary condition only for runner roles (the composite sets it there).
- Lambda: function CRUD, configuration, code, URL config, concurrency, tags, permissions and event-source mappings on `arn:aws:lambda:us-east-1:832907639880:function:beep-fleet-prod-*` only (eleven functions: `beep-fleet-prod-webhook`, `-ssm-housekeeper`, `-binaries-syncer`, `-termination-watcher`, `-reaper`, and per pool `-{heavy,overflow}-scale-up`, `-job-retry`, `-scale-down`); `lambda:CreateEventSourceMapping`/`List`/`Get` on `*` (no resource ARN), update/delete on mappings tagged `alchemy::stack = CiRunners`.
- SQS: queue CRUD, attributes and tags on `arn:aws:sqs:us-east-1:832907639880:beep-fleet-prod-*` (ten queues: per pool `-build`, `-build-dlq`, `-job-retry`, `-job-retry-dlq`; fleet `-deregister-retry`, `-deregister-retry-dlq`).
- SSM: parameter put/get/delete/describe/tags on `arn:aws:ssm:us-east-1:832907639880:parameter/beep-fleet/prod/*`; `ssm:DescribeParameters` on `*`.
- KMS: `kms:CreateKey` with `aws:RequestTag/alchemy::stack = CiRunners`; key policy, rotation, describe, schedule deletion, tags, `kms:Encrypt`/`Decrypt`/`GenerateDataKey` (SecureString writes) on keys tagged `alchemy::stack = CiRunners`; `kms:CreateAlias`, `kms:UpdateAlias`, `kms:DeleteAlias` on `alias/beep-fleet-prod-*` plus the tagged key.
- S3 binaries bucket: bucket CRUD, public-access block, tags and object put/delete on `arn:aws:s3:::beep-fleet-prod-binaries-832907639880` and its objects only.
- EventBridge: rule and target CRUD and tags on `arn:aws:events:us-east-1:832907639880:rule/beep-fleet-prod-*` (seven rules: per pool `-scale-down`; `-ssm-housekeeper`, `-binaries-syncer`, `-spot-interruption`, `-instance-state-change`, `-reaper`).

- STS: `sts:GetCallerIdentity`.

No assets bucket: the provider layer registers no `Assets` service, so each bundle uploads inline with `CreateFunction`/`UpdateFunctionCode` and the role needs no access to an `alchemy::assets-bucket`. No `ec2:RunInstances`/`CreateFleet`: the deploy never launches a runner; scale-up's own role does.

Policy JSON: generated from this list outside the repository (`~/.cache/beep/ci-runners-deploy-role/`: `gen.ts <new vpc arn>` writes `policy-v1.json` and `policy-v2.json`; `chunk.ts` splits each into documents under the 2,000-character limit of `simulate-custom-policy`, and since the policy only allows, the split documents evaluate together exactly as the whole policy does). Simulations against the generated JSON (`aws iam simulate-custom-policy`), listed with their expected decisions in that directory's `SIMULATIONS.md`. Placeholder ARNs stand in for the new VPC. Before arming, the gate re-runs them against the generated policy, and again against v2 with the real VPC ARN between steps 1a and 1b: (1) v2, default-group revokes in the new VPC: allowed; (2) v2, the same in an unrelated VPC: implicitDeny; (3) v1, default-group revokes in the new VPC: implicitDeny (why step 1a excludes `DefaultSecurityGroup`); (4) `ec2:CreateTags` on the live VPC with both `alchemy::` request tags and no `ec2:CreateAction`: implicitDeny; (5) `ec2:CreateTags` with `ec2:CreateAction=CreateVpc` and both request tags: allowed; (6) `ec2:DeleteVpc` on a VPC tagged `alchemy::stack=CiRunners`, `alchemy::stage=prod`: allowed; (7) `ec2:DeleteVpc` on the live VPC: implicitDeny; (8) `lambda:UpdateFunctionCode` on `beep-ci-scale-up`: implicitDeny.
