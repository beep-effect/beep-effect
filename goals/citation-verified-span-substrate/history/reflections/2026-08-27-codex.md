# Reflection - citation-verified-span-substrate (2026-08-27, codex)

## Summary

The goal adds a durable, same-matter history around the existing exact UTF-16
locator and verified-anchor contracts. Each attempt retains its candidates,
source identities, engine and normalization versions, typed outcome, and link
to the prior attempt. Source drift cannot replace an old anchor. An explicit
re-anchor must prove the retained drift source and exact slice again. Source
proof is reusable across a batch, runtime-immutable, and tied to one digest.

## Tooling experience

- **Worked:** The P0 hostile-text fixture fixed the offset contract before this
  work began. The schema-first and Effect-first guidance kept persistence and
  failure behavior in schemas and typed Effects. Package audits, property
  coverage, and direct docgen exposed boundary defects early.
- **Didn't:** merge-base attribution correctly identified an inherited Docgen
  defect, but the hosted required check still blocked this PR until the
  downstream category was repaired here.
- **Frustrating:** `tsgo` accepted the first attempt-record schema, but `tsc`
  could not emit its inferred declaration. The working explicit class pattern
  existed in one unrelated package and was not documented in the schema skill.
- **Wished existed:** A schema-first example for large checked classes and a
  docgen report that separates inherited downstream findings from changed
  package failures.

## Implementation improvement opportunities

- Keep any current-anchor or display projection derived from the terminal
  successful attempt. A second persisted pointer would create another mutable
  source of authority.
- If future consumers need recovery after a non-stale re-anchor failure, add a
  named retry transition with its own acceptance rule. Do not loosen the
  current stale-source prerequisite.

## Goal & prompt critique

The packet should state the persistence state machine directly: an initial
verification may be followed by another verification only after success, and
a re-anchor may follow only a retained stale-source failure. It should also say
whether the previously merged coordinated consumer proof satisfies this goal
or must be changed again. This PR resolves the ambiguity with a focused
workspace-resolver-to-verified-source integration assertion.

## TODOs worth codifying

- Add the explicit checked-class declaration pattern to the schema-first skill.
- Add merge-base attribution to downstream failures in `docgen:local`.

## Lessons

- **HIGH - Critical:** Prove source identity before interpreting an empty
  candidate batch. Otherwise source drift can masquerade as a valid negative
  extraction result.
- **HIGH - Critical:** Put history transitions in the decoder as well as the
  command API. Persistence is an input boundary, not a trusted replay log.
- **HIGH - Critical:** A branded proof that exposes mutable nested values is
  not opaque authority; snapshot and freeze its complete runtime state.
- **MEDIUM - Best practice:** Persist raw candidates beside each outcome. They
  make failures and later re-anchor decisions reproducible after restart.
- **LOW - Consideration:** Add a derived current-anchor helper only when a real
  consumer needs it. The append-only history is already the authority.
