# P0e acceptance checklist

P0a-P0d are complete. P0e remains unaccepted until every applicable group below
has direct evidence from the final source. A draft, mocked registration result,
compile pass or successful lane exit alone does not establish this gate.

## Charters and grounding

- Shared contract and all four lens charters include mission, D-number rules,
  judgment beyond mechanical detectors, evidence sources, the existing finding
  schema and worked before/after examples.
- All APIs use the pinned Effect tag/commit or verified installed Vitest 4.1.11
  public exports. The seven existing-API worked snippets have supporting compile
  proof; the instrumented import and final edited charters still need final proof.
- Preserve no-findings completeness rows, literal D9 scope, four-lens coverage,
  Node timing evidence, D12 order, D13 waves and all human phase/merge gates.
- No MemoryFileSystem import/promotion/adoption is implied before its own gate.

## Public runner equivalence

- Callable plain it and every supported effect/live tester method retain their
  types, options, conditional behavior and runtime semantics.
- Each keeps original case data, one-case callback arity, formatting/indexed
  name/fullName/fullTestName, tuple/object interpolation, duplicate values and
  concurrency behavior through one real collection. Check actual task option
  fields rather than the nonexistent task.options.
- Properties keep record/tuple Schema/FastCheck inputs, seed/shrinking/fcRuns
  behavior and the correct actual TestContext.
- Named, unnamed and nested layer callbacks remain instrumented while preserving
  acquisition counts, nested memo maps, allowed method/options surface,
  TestClock/TestConsole sharing and upstream per-test Scope identity.
- No private upstream runner import/copy, global TestEnv/config mutation,
  silent fallback to uninstrumented tests or root-barrel runtime side effect.

## Watchdog and lifecycle

- The watchdog uses the live clock without advancing/replacing the body's
  TestClock and works with live, default and excludeTestServices environments.
- It uses the actual test identity and resolved finite-positive task timeout.
  Zero/Infinity-disabled semantics and small positive budgets are explicit.
  Property state resets for each retry/repeat while trials/shrinking share one
  execution budget; errors report a meaningful configured watchdog limit.
- Many short property trials cannot reset the whole test budget; lifecycle
  start/end/outcome represents the test run across trials and shrinking.
- TestHang captures the last body log at expiration, after later logs actually
  execute. Independent concurrent names/logs/timeouts remain isolated.
- Start/body/end run under the intended logger provision. Trace-off,
  BEEP_TEST_TRACE=1 and CI behavior are proven, with existing loggers and
  TestConsole preserved. Lifecycle messages do not erase the diagnostic body log.
- Success, typed failure, defect, interruption and watchdog outcomes preserve
  causes, finalizers and loser cancellation. Logger plumbing does not add an
  unnecessary body Scope or make resource cleanup disappear.
- Real failing/hanging fixtures are isolated from ordinary discovery. Assertions
  verify the expected named failure, rather than accepting any nonzero exit.

## Detector integration

Paired probes confirm a new integration gap: changing only the it import from
@effect/vitest to @beep/test-utils/Vitest currently hides EV001/EV004/EV008.
The separate repo-cli lane owns only Syntax recognition and detector tests.
It must prove equivalent findings for the actual it export, aliases,
namespace.it and nested layer bindings, while retaining shadowing and negative
cases for non-tester exports/unrelated modules. No blanket expect/vi/beforeEach
support, algorithm rewrite or generated-artifact edit is authorized in that lane.

The historical P0d proof remains a completed phase receipt. This deliberate
P0e entry-point extension requires fresh final repo-cli package verification,
canonical membership attribution and scanner proof before P0e acceptance.

## Final verification and ownership

- Both source lanes exit successfully and their actual processes are absent
  before orchestrator package verification. Preserve interrupted/failed receipts.
- The orchestrator has moved the existing @effect/vitest catalog pin to test-utils
  runtime dependencies and regenerated/reviewed the lockfile under Bun 1.4.1.
  Do not change versions or include unrelated dependency churn.
- Actual Bun-native package-script and Node Vitest proofs cover the full new
  integration matrix; record executable/version, commands, exits and test counts.
- Full package-verify passes for @beep/test-utils and @beep/repo-cli, with stable
  source/package/lockfile snapshots and no concurrent writer.
- Exact scanner writer/determinism/default-ratchet proof and final census/row
  comparison attribute every new path/finding without changing old semantics.
- All final charter examples compile against the final implementation; remove
  provisional claims only once those proofs exist.
- Packet doctor/index, launcher length and whitespace checks pass after the
  phase flip. P0.5 starts only after this gate is established.
