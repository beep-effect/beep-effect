# OpenClaw registered properties and acceptance witnesses

The CLI union round trip now uses one registered it.prop with named validation
and reload inputs. Both exact schema generators, codecs, equivalences, the
fifty-run floor and the original single test deadline remain. Explicit labels
identify the union whose equivalence failed. The adapter owns shrink/replay.

A new fifty-run property starts with the valid acceptance fixture and changes
one component at a time: hosted provider, requested local model, skill sentinel,
reload warning count, or Telegram probe. Every generated trial checks all five
exact failed steps; the original valid-input and wrong-skill checks remain.
Suffixes use NonEmptyString; warning counts retain the branded NonNegativeInt
schema refined to the inclusive range one through one hundred. No provider,
credential, network request or production implementation is added.

Neutralizing each of the five invalid components makes its witness fail.
Inverting CLI validation equivalence also fails. All six controls report replay
information and restore the exact source bytes. The full package audit and
passing documentation check cover the final sources. The elevated command uses
BEEP_FC_NUM_RUNS=400 and BEEP_FC_SEED=20260708: all 54 tests in the five
property-bearing files pass. That mode intentionally filters other files; it
is not a claim that all package tests ran under the elevated property mode.

Native integration deadlines, redacted acquisition-stage context and runner
integration remain outstanding. Existing ledgers are not marked complete yet.
