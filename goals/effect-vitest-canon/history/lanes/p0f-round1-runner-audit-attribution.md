### Exact path through the failure

1. `test/fixtures/vitest-instrumentation/runtime.test.ts.txt:96–106` registers the property with the existing TraceSink layer, seed 4242, `fcRuns(4)`, 60ms body promises and 180ms task timeout. The named layer is acquired by rc.112's beforeAll, outside the test-handler timer; do not charge that entire acquisition to the inner/outer timer skew. Per-trial cached context provision, scope and callback scheduling still occur inside the handler.
2. `node_modules/@vitest/runner/dist/chunk-artifact.js:1782–1787` creates the registration sentinel and gives it to withTimeout. At `2261–2319`, the handler arms its own 180ms timer before calling the returned promise. Timer firing calls rejectTimeoutError. The successful-resolution branch also checks elapsed time; the rejection branch forwards an error without that extra elapsed check. The retained report cannot distinguish those branches solely from duration.
3. Exact rc.112 `packages/vitest/src/internal/internal.ts:96–102,131–154` runs the callback through Effect.suspend, mapEffect and runPromise(ctx), inside fc.asyncProperty/fc.assert. `:24–36` binds the Effect run to the public TestContext abort signal. `:257–273` provisions cached layer context and a fresh trial scope. Installed index/internal files are byte-identical to the pinned snapshot.
4. `src/internal/VitestInstrumentation.ts:72–85` computes `180 − max(25, 180×0.05) = 155`. `:141–150` records the first trial's monotonic start and shared deadline. `:153–181` builds logger scope/emits start/sets the completion callback. `:201–221` later calculates `deadline − earlierSample` and arms relative Effect.sleep. If arming occurs δ after that sample, the timer's nominal due time is `deadline + δ`, before callback scheduling delay. This applies again on later trials; it is not a reset to a new full budget.
5. Exact rc.112 `packages/effect/src/internal/effect.ts:6033–6064,6114–6115` implements the live clock sleep through setTimeout; `:1535–1579` makes raceFirst wait for loser interruption, and therefore relevant scope finalization. After a failed trial reaches fast-check, `node_modules/fast-check/lib/fast-check.js:1215–1222,2178–2183,2512–2537` records the failure and runs shrinks. Only afterward do `:2402–2405,2460–2475,2540–2543` construct/reject the seed/path/counterexample/Shrunk error. No fast-check deadline option is set by this fixture or current setup; the explicit task timeout belongs to Vitest. fcRuns preserves the env-max floor, and fast-check merges explicit options after global configuration.
6. If the outer timeout wins that race, `chunk-artifact.js:2404–2410` creates the timeout message but assigns `stackTraceError.stack.replace(error.message, stackTraceError.message)`. The timeout message is not present in the old sentinel stack, so this expression cannot insert it. `node_modules/@vitest/utils/dist/error.js:9–39` and `serialize.js:92–119` serialize the error; the JSON reporter at `node_modules/vitest/dist/chunks/index.UpGiHP7g.js:3567–3574` selects `e.stack || e.message`. Thus the passed negative substring assertion is not a reliable check for absence of an outer timeout. The exact reason this runtime's first stack line is bare “Error” rather than the sentinel text remains unproved; the stack-copy/report-preference defect is enough to establish the information-loss path without guessing that formatting detail.
7. `VitestInstrumentation.ts:225–228,262–276` updates the property outcome after the raced Effect returns and emits one lifecycle end when the enclosing test execution finishes. Original package assertions after the missing seed were never evaluated, and its cleanup trace was not retained in the failed log. Do not infer whether its watchdog fired, shrinking began, or finalization completed. An external abort can interrupt before the outcome update; inspecting the original abort/outcome relationship requires new structured diagnostics.

The 204.090641ms child result is not a direct stopwatch for the 180ms handler: the runner starts result timing before per-test hooks (`chunk-artifact.js:2921–2956`) and assigns duration after cleanup (`:3052`). It supports the timeout hypothesis but cannot quantify the overshoot of a particular callback.

This identifies origin skew, timer lateness and completion delay separately. Do not subtract aggregate host PSI or scanner timing from the test duration. **Smallest independently justified implementation correction:** recompute `deadline − now` immediately before arming the watchdog sleep, inside the composed Effect, and fail immediately when that value is nonpositive. Preserve the stored deadline, its 155ms budget derived from the unchanged 180ms task timeout, property reference identity, per-execution lifetime, inner scopes and finalization. Do not reset the budget during shrinking. This removes the confirmed sample/arming gap but is not a proof that the original package failure is fixed; it cannot bound event-loop delay or finalization cost. A late body-success outcome versus an already-expired absolute deadline also needs explicit characterization before changing winner policy, rather than silently changing raceFirst semantics.

**Defensible deterministic test seam:** separate the existing watchdog's monotonic-read/sleep capabilities from the adapter that binds them to liveClock. A small internal timing dependency can be supplied with the current live implementation in production and a controlled implementation in a deliberately authorized test harness. Keep the body TestEnv and TestClock unchanged; control only the watchdog clock. Use the real fast-check property registration and the same seed/floor to drive multiple trials, consume the same logical absolute budget, force expiry, and let actual shrinking/reporting finish. Retain every lifecycle, last-log, seed, counterexample and Shrunk assertion. The fixture's logical trial delay must be controlled by that harness rather than fabricated TestHang failures or monkey-patched platform state. Keep existing real-clock watchdog/finalizer tests as integration evidence, with the current timeout values. Root must choose the internal test access route explicitly; this proposal does not authorize a public option, an internal export leak, or a hidden environment switch.

No finite margin on two cooperative event-loop timers can unconditionally guarantee that inner failure, loser cancellation, scoped finalization, all shrinks and report serialization finish before the outer 180ms timer. The source offers no bound on those operations. Under sufficiently long event-loop starvation, no callback can run on time; uninterruptible finalization can also exceed the margin independently of host load. The deterministic seam tests the absolute-deadline/lifecycle/seed+shrink semantics without depending on a 25ms scheduling race. The real adapter remains subject to Vitest's hard timeout. If unconditional pre-timeout metadata is a required product guarantee even under arbitrary starvation, that contract is infeasible in this single-threaded adapter and needs an explicit Root decision; raising timeouts or relaxing the seed/Shrunk assertions is not a fix proposed here.
