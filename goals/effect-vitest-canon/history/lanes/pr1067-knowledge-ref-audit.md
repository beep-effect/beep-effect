The extraction chain is in `packages/tooling/tool/cli/src/commands/Knowledge/Knowledge.refs.ts`:

- `extractKnowledgeHostAnchors` (line 1711) finds `/home/`, `~/`, `/tmp/` and bare machine-tree anchors over every non-whitespace run. `trimHostToken` (1659) trims punctuation, not JSON escape layers; a token may therefore include `O.some(` or trailing serialized fields. This is expected under the current lexical grammar, not a reason to rewrite detector evidence.
- `extractDocumentRefs` (2503) calls `hostCandidates` (2265) for every elected file type and every line, including JSONC/JSONL and fenced text. Markdown prose restrictions apply only to the other reference buses.
- `hostCandidates` supplies `knowledgeRefPatternContext(line.text)` (1809). That predicate recognizes table delimiters, regex groups/classes, `--glob`, and `rg`/`grep`; it does not recognize a serialized source literal.
- `classifyHostAnchor` (1865) already maps pattern data to `audit-pattern-literal`, before archival handling. Otherwise an ordinary `/tmp` anchor is actionable: only `/tmp/portless` is a registered temp convention. The existing remediation for audit literals explicitly says the anchor is rule or inventory data rather than guidance.

Do **not** add these fixture names to `TEMP_CONVENTIONS`, normalize away escaping, blanket-exclude inventory directories, mark the live inventory archival, or add a generic “quoted path is safe” rule. Do not widen the existing line-wide pattern predicate with a JSON-quote regex: one evidence literal and one genuine host reference can share a minified JSONL line, and exempting the whole line would hide both. `KnowledgeHostPathRef` and the existing `audit-pattern-literal` classification already provide the necessary representation; no new class, gate-set change, version change or suppression marker is needed.

The smallest change I can recommend **while preserving the genuine-host gate** is an anchor-specific, source-bound generated-evidence recognizer, reused through the existing `patternContext` input:

1. Recognize the exact producer formats, not directory membership alone. Decode canonical JSONC with existing `decodeJsoncTextAs` from `@beep/schema/Jsonc` and `EffectVitestInventoryDocument`; decode package rows with existing `decodeEffectVitestFindingJson`/`EffectVitestFinding`. These schemas/decoders already live in `Lint.schemas.ts` and are used by `EffectVitestStore.ts`. The canonical file has a generated comment header, so plain JSON parsing of the entire file is insufficient. Use the pure decoder, **not** the filesystem-backed `readArtifact`, inside the tree evaluator.
2. Identify the original serialized **evidence-value span** belonging to that validated row, preserving original document line/column and escape offsets. A host occurrence outside that field remains subject to existing rules, including a `reason`, prose, command field or another property on the same line. Malformed/ambiguous data must fall back to the existing gate.
3. Bind the evidence to the row's declared test-source range through the existing `KnowledgeTreeOracle.readBytes` and tracked-entry index (scan entry at 2642). Read only regular source blobs from that same requested tree; never substitute live filesystem bytes. Verify the producer's normalized/truncated evidence against the declared source range, then establish that this particular anchor lies in the source string-literal data represented by the evidence. The eight requested literals are complete and closed after outer JSON decoding. If source provenance, span mapping or quoting cannot be established, retain the gate. Cache per-document decoding and per-source reads; do not launch the Effect Vitest detector.
4. For that anchor only, set pattern context true and emit the existing `audit-pattern-literal` observation. Preserve extraction counts, raw token, anchor, occurrence, location and reference identity. Classification is not in the identity preimage, so this does not require changing normalization or detector rows. Other anchors on the line must be classified independently.

A format/schema check alone is insufficient: a fabricated JSON object with a plausible `evidence` field would otherwise become a way to hide a real host reference. Source binding avoids adding that escape hatch. If Root chooses a cheaper lexical exception instead, its residual laundering risk needs an explicit policy decision; I do not recommend such a shortcut. No current marker or waiver offers equivalent provenance without changing the immutable payload.
