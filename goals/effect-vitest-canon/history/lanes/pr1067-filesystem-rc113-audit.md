## Coverage boundary and ownership proposal

`test/MemoryFileSystem/Conformance.test.ts` calls the shared `testLayer(MemoryFileSystem.layer)`, so it inherits the current 21-case coverage gap. Existing Node/Bun conformance fixtures likewise cannot gain the new cases solely from main's type migration. `ConformanceLedger.test.ts` uses filesystem access for ledger fixture infrastructure; this is not evidence of the new filesystem contract. `FileSystemWriteCompatibility.test.ts` supplies meaningful numeric IO coverage for the Node platform implementation under its runtimes, not a substitute for running the same cases against every subject.

The root barrel and explicit MemoryFileSystem package export were checked. No helper, public fixture API, or source-role addition is needed. The smallest proposed implementation lane owns **only `src/FileSystemConformance.ts`**: port the 15 new registrations and the two strengthened assertions, using the existing subject-local 27-byte `lorem ipsum dolar sit amet\n` fixture and private setup operations. Preserve the full MIT notice, both optional flags/defaults, dual API, per-test subject provision under D14, existing cleanup scopes, flags and error-path assertions. Existing platform and Memory adoption files can remain unchanged and register the enlarged suite automatically. Root can then run those adapters and assign a disjoint core repair only if an executed case reveals a defect. This audit does not authorize or perform that implementation.
