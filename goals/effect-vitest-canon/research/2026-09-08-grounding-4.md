## Findings

### 1. Named vs unnamed build (verified)

`layer` starts at snapshot `packages/vitest/src/internal/internal.ts:213`. At call time it always:

1. Merges `TestEnv` unless `excludeTestServices` (`237-240`).
2. Allocates a **root** `MemoMap` (`241`: `options?.memoMap ?? Effect.runSync(Layer.makeMemoMap)`).
3. Allocates **one outer** `Scope` (`242`: `Effect.runSync(Scope.make())`).
4. Wraps `Layer.buildWithMemoMap(withTestEnv, memoMap, scope)` in `Effect.orDie` then `Effect.cached`, then `Effect.runSync` (`243-247`).

`Effect.cached` at rc.112 is `Effect<Effect<A,E,R>>` (`packages/effect/src/Effect.ts:7110`, impl `packages/effect/src/internal/effect.ts:4291-4292` = `cachedWithTTL(..., Duration.infinity)`). The `runSync` therefore **creates the cache cell**; it does **not** acquire the layer. The first run of the inner cached effect performs the build.

**Named form** (`args.length === 2`, `317-327`): `V.describe(name, …)` + `V.beforeAll(() => runPromise(Effect.asVoid(contextEffect)), hookTimeout(options?.timeout))` + `V.afterAll(() => closeScope(), …)`. Build runs inside `beforeAll`. Finalizers run in `afterAll` via `Scope.close(scope, Exit.void)` (`249-255`).

**Unnamed form** (`args.length === 1`, `281-314`): no `describe`. After the callback registers tests, it diffs `getCurrentSuite().tasks` (`282-289`). Then:

- `V.beforeEach` (`298-312`) no-ops unless `ctx.task` is in the collected block set; for matching tests it registers `ctx.onTestFinished` to decrement a remaining counter and close when it hits 0, then `return runPromise(Effect.asVoid(contextEffect), ctx)`.
- `V.afterAll(() => closeScope(), …)` (`313`) is a second close path. `closed` makes close idempotent (`249-253`).

Packet §1.2 "builds lazily on the block's first test and closes after its last test (298-305)" is **mostly verified**. Nuances:

- Acquisition is lazy because of `Effect.cached`; `beforeEach` still *runs* the cached effect on **every** matching test (`309`).
- Last-test close is `303-307`; `afterAll` (`313`) is an extra safety net (needed if `remaining--` races under concurrency — **inference**).
- Empty unnamed blocks only register `afterAll` (`290-292`).
- Unnamed `beforeEach` is suite-scoped and filters by task identity (`300-302`) so it will fire for sibling tests in the same suite and no-op. **Pitfall:** two unnamed `it.layer` blocks in one `describe` share the suite's hook list.

PR that introduced unnamed isolation + forked memo maps: [Effect-TS/effect-smol#2177](https://github.com/Effect-TS/effect-smol/pull/2177) (merged 2026-05-17 as `0c9d3ab`). Summary verified from the PR page: isolate unnamed blocks via the runner collector; fork memo maps; proxy `it` instead of mutating the Vitest API.

### 2. Shared TestClock / TestConsole state (verified)

`TestEnv = Layer.mergeAll(TestConsole.layer, TestClock.layer())` is a **module-level constant** (`internal.ts:44`). Default `it.layer` does `Layer.provideMerge(layer_, TestEnv)` (`238-240`), then builds that **once** into the outer scope.

Consequences, all from source:

- One `TestClock` instance for the whole block. `TestClock.adjust` / `setTime` persist into later tests. Packet §1.2 is verified.
- `it.effect` outside `it.layer` is the opposite: `makeMethods` uses `flow(Effect.scoped, Effect.provide(TestEnv))` (`356`) — a **fresh** `TestEnv` per test.
- `it.live` is `makeTester(Effect.scoped)` (`357`) — no `TestEnv`.
- Nested `it.layer` passes the same `excludeTestServices` flag and `Layer.forkMemoMapUnsafe(memoMap)` (`270-277`). Because `TestEnv` is already memoized in the **parent** map, nested siblings **reuse the parent TestClock** (see §5). Nested resource layers are isolated; the clock is not.
- `TestClock.make` captures `liveClock` at construction (`packages/effect/src/testing/TestClock.ts:254`) and registers `warningDone` on the **layer** scope (`388`). Warning delay default is `"1 second"` (`197-199`) and the warning fiber itself uses `withLive` (`286-291`). That warning state lives on the shared TestClock, not per test.

Upstream proof that `it.layer` + TestEnv yields TestClock: `packages/vitest/test/index.test.ts:175-184` (`layer(Sleeper.layer)("test services")` forks `sleeper.sleep(100_000)` then `TestClock.adjust(100_000)`). `Sleeper.layer` captures `Clock.Clock` at **layer build** (`94-105`), so the captured clock is the shared TestClock.

Community/docs corroboration (dated):

- [Effect-TS/effect#3718](https://github.com/Effect-TS/effect/issues/3718) (opened 2024-10-02, closed): historically `it.layer` did **not** provide TestContext, so `TestClock.adjust` could not drive schedules. rc.112 inverts that: TestEnv is default-on. The live pitfall is sharing, not absence.
- Official TestClock guide (fetched 2026-09-08): [effect.website/docs/v4/testing/testclock](https://effect.website/docs/v4/testing/testclock) — clock does not move unless `adjust`/`setTime`; `Effect.sleep` semantically blocks until then; fork-then-adjust is the documented pattern.
- README at the tag (`packages/vitest/README.md:45-48,108-112,257-259`) documents per-test `it.effect` TestClock + fresh Scope. It has **no** `it.layer` section and does **not** mention shared clock, named vs unnamed, hook timeout, or `excludeTestServices`. That gap is verified by reading the 311-line README.

**Inference (not executed):** `TestClock.sleep` pushes onto a module-local `sleeps` array (`TestClock.ts:327-339`) with no `onInterrupt` removal. An interrupted sleep inside a shared `it.layer` clock can leave a latch that a later `adjust` in the same block opens.

**Inference:** services that `yield* Clock.Clock` during **layer** construction (Sleeper pattern) freeze whichever clock was active at build. `TestClock.withLive` on a later `Effect.sleep` does not rewrite that captured clock.

### 3. Separate inner scoped body vs outer finalizer ownership (verified)

Inner tester (`internal.ts:259-266`):

```ts
Effect.flatMap(contextEffect, (context) =>
  effect.pipe(Effect.scoped, Effect.provide(context)))
```

`Effect.scoped` (`packages/effect/src/internal/effect.ts:3938-3946`) allocates a **new** scope, `Context.add`s it as `Scope.Scope`, and `onExit` closes it and restores the previous fiber context.

`Effect.provide(context)` here is `provideContext` (`packages/effect/src/internal/layer.ts:85-87`) — it does **not** rebuild the layer. Pipe order is scoped-then-provide, so provide is outer: layer services are in fiber context, then scoped installs the **inner** `Scope`. Test-body `acquireRelease` / `makeTempDirectoryScoped` therefore attach to the inner scope.

Outer ownership (`internal.ts:242,249-255,313,322-324`): the `Scope.make()` from `layer()` is the observer scope passed to `buildWithMemoMap`. `closeScope` is the only closer for that scope (`Scope.close(scope, Exit.void)`). Named: `afterAll`. Unnamed: last `onTestFinished` and/or `afterAll`.

Memo-map finalizers (`packages/effect/src/Layer.ts:396-418,241-249`): each memoized layer has its own `layerScope`; observers decrement on observer-scope close; at 0 the entry is deleted and `layerScope` is closed. Nested child scopes `memoMapReuse` parent entries (increment observers, add a child-scope finalizer). Closing a nested block releases **child-only** layers and decrements parent observers without releasing parent layers while the outer block still holds them. Verified by `packages/vitest/test/nested-isolation.test.ts:29-62` (child 1 released before sibling 2 runs; both released by parent `afterAll`).

README law (`README.md:257-259`): "Do not wrap the test body in `Effect.scoped`, because the test runner already manages its scope." That refers to the **inner** runner scope, not the outer `it.layer` scope.

Per-test `Effect.provide(layer)` (D14 contrast) is `scopedWith` + `buildWithScope` (`packages/effect/src/internal/layer.ts:8-22`). `buildWithScope` (`Layer.ts:762-774`) forks a memo map from the fiber and builds into **that** fresh scope. N tests = N acquisitions / N releases. Verified at the tag (packet's HEAD caveat is unnecessary for this file: the snapshot copy matches).

### 4. Nested memo maps (verified)

Nested `it.layer` (`internal.ts:270-277`):

```ts
return layer(Layer.provideMerge(nestedLayer, withTestEnv), {
  ...options,
  memoMap: Layer.forkMemoMapUnsafe(memoMap),
  excludeTestServices
})
```

`forkMemoMapUnsafe` (`Layer.ts:511`) is `new MemoMapImpl(parent)`. Child `get` checks local map then `parent.get` (`434-442`). New builds write to the **child** map (`411`). JSDoc (`494-503`): child sees parent memoized layers; new allocations stay out of the parent.

Types: nested `MethodsNonLive.layer` options are **only** `{ timeout? }` (`packages/vitest/src/index.ts:107-114`). Nested calls **reject** `excludeTestServices` and `memoMap` (`packages/vitest/typetest/index.tst.ts:41-54`). Runtime still *copies* the outer `excludeTestServices` boolean (`276`).

**Pitfall (verified structure, inference on identity):** when `excludeTestServices` is false, the inner `layer()` **again** does `Layer.provideMerge(alreadyMerged, TestEnv)` (`237-240`). `TestEnv` is the same module identity, so the inner build hits the parent memo and reuses the same TestClock. Nested sibling isolation tests (`nested-isolation.test.ts`) prove Child/State isolation, **not** clock isolation.

**Pitfall:** same Layer identity in two nested siblings is two builds (separate child memo maps). Same Layer identity in two tests of **one** `it.layer` is one build. `isolation.test.ts:19-105` proves **top-level** unnamed `it.layer(inMemoryLayer)` blocks do **not** share: three blocks → ids `[1,2,3]`.

Concurrent nested siblings (`nested-isolation.test.ts:65-120`, `describe.concurrent`) allocate isolated children (ids 1 and 2, order undefined). **Inference:** they still share the parent TestClock; concurrent `TestClock.adjust` in nested siblings would race. Upstream does not test that.

Changelog (`packages/vitest/CHANGELOG.md:337`): "Add forked memo maps so nested layer scopes can reuse parent allocations without leaking sibling-local layers."

### 5. Default hook timeout (verified locally; official page body empty)

`hookTimeout` helper (`internal.ts:54-55`):

```ts
timeout === undefined ? undefined : Duration.toMillis(Duration.fromInputUnsafe(timeout))
```

If the caller omits `options.timeout`, vitest receives `undefined` and uses its **config default**.

Installed vitest `4.1.11`:

- Types JSDoc `node_modules/vitest/dist/chunks/reporters.d.DtoKVV2s.d.ts:2891-2900`: `testTimeout` default `5000`; `hookTimeout` default `10000`.
- Resolver `node_modules/vitest/dist/chunks/coverage.DM_a_rWm.js:538-539`: `testTimeout ??= browser.enabled ? 15e3 : 5e3`; `hookTimeout ??= browser.enabled ? 3e4 : 1e4`.
- CLI help `node_modules/vitest/dist/chunks/cac.uFydS1Z4.js:996-1002`: test timeout default `5000`; hook timeout default `10000`.

**Verified pitfall:** container `it.layer` without `{ timeout: "30 seconds" }` is bounded by the **hook** default (10s Node), not the test default (5s). Named build is `beforeAll`; unnamed first acquisition is `beforeEach`. Both use `hookTimeout(options?.timeout)` (`311, 313, 318-324`). README syntax still advertises `it.effect` timeout default `5_000` (`README.md:45`) — a different knob.

Upstream container canon uses the option: `packages/sql/pg/test/Client.integration.test.ts:17` and `Persistence.integration.test.ts:26,109` (`{ timeout: "30 seconds" }`); `packages/sql/mysql2/test/Persistence.integration.test.ts:11` uses `"90 seconds"`; `packages/platform/node/test/NodeRedis.integration.test.ts:64` uses `"30 seconds"`. Cheap layers (`NodePath.test.ts`) omit it.

Official vitest page [vitest.dev/config/hooktimeout](https://vitest.dev/config/hooktimeout) was fetched 2026-09-08 and returned an empty JS shell. Search snippet (same URL, indexed) stated default `10_000` Node / `30_000` if `browser.enabled`. That matches installed resolver. Treated as **verified from installed vitest 4.1.11**, not from the live HTML body.

Build failures are `Effect.orDie` (`244`). Failed exits are cached (`cachedWithTTL` stores `exit`, `internal/effect.ts:4257-4262`). **Inference:** a failed `beforeAll`/`beforeEach` build poisons the rest of the block with the same defect.

### 6. `excludeTestServices` (verified)

Default `false` (`237`). When `true`, `withTestEnv = layer_` — no TestClock/TestConsole merge (`238-239`). Nested copies the flag and cannot override it (types + runtime).

Canon: `packages/vitest/test/index.test.ts:201-207` — `layer(Sleeper.layer, { excludeTestServices: true })("live services")` then `sleeper.sleep(1)`. Because Sleeper captured live `Clock` at build, that sleep is **wall-clock**.

Top-level options include `memoMap`, `timeout`, `excludeTestServices` (`index.ts:217-222`). Changelog (`CHANGELOG.md:728`, PR [effect-smol#1442](https://github.com/Effect-TS/effect-smol/pull/1442), merged 2026-02-23 as `f0c6ee5`): nested remains timeout-only.

`Clock.Clock` is a `Context.Reference` with default `ClockImpl` (`packages/effect/src/internal/effect.ts:6033-6053`). `TestClock.layer` is `Layer.effect(Clock.Clock)(make)` (`TestClock.ts:436-439`). `make` requires `Scope` (API: `Effect<…, never, Scope>` at [docs v4 TestClock.make](https://effect.website/docs/v4/api/effect/testing/TestClock#make), source `TestClock.ts:244` + `addFinalizer` at `388`). Under `excludeTestServices` / `it.live`, the fiber's Clock ref is `ClockImpl`, which has **no** `withLive`.

`TestClock.withLive` (`580-581`) is `testClockWith((testClock) => testClock.withLive(effect))`. `testClockWith` (`469-471`) is `fiber.getRef(Clock.Clock) as TestClock` — an unchecked cast. **Inference (not executed):** calling `TestClock.withLive` under `it.live` or `excludeTestServices` throws because `ClockImpl.withLive` is not a function.

### 7. D14 stress-test (provide rule vs scopes)

D14 (packet, locked): `it.layer` required for scoped/effectful layers (`Layer.effect`, `Layer.scoped`, `Layer.unwrap`, `acquireRelease`, containers, filesystems, servers, every `withXyz`). Per-test `Effect.provide` only for `Layer.succeed` / `Layer.mock`.

**What source supports**

- Per-test `Effect.provide(layer)` rebuilds into a fresh `scopedWith` scope (`layer.ts:8-22`). That is the N-acquire problem D14 targets.
- `it.layer` builds once into an outer scope and `provide(context)` per test (`internal.ts:243-247,259-265`). Matches D14 for expensive resources.
- Nested `it.layer` + forked memo map is the supported way to share a parent (container) while isolating a child (connection, volume). Matches Resource-Authoritarian nested shape.
- `{ timeout: "30 seconds" }` on container layers is required by hook-timeout facts (EV014). Source-backed.
- TestClock persistence across a D14 `it.layer` block is real (EV015). Reset per test or `excludeTestServices: true` + explicit clock. `excludeTestServices` also drops TestConsole and breaks `TestClock.withLive` (**inference**).

**Contradictions / over-claims**

1. **Inner `Effect.scoped` is not always wrong.** README forbids wrapping the *whole test body*. Upstream still uses *nested* `Effect.scoped` for a lifetime shorter than the test, e.g. `packages/sql/pg/test/Persistence.integration.test.ts:47` (`yield* Effect.scoped(… store1.take … Effect.never)` inside `it.effect` inside `it.layer`). A blanket EV004 "delete, runner owns the scope" would flag this canon. **Verified** usage vs **inference** that EV004 as written is too coarse.

2. **Per-test provide of the layer-under-test is canon.** `packages/effect/test/FileSystem.test-utils.ts:16-18` uses plain `it` + `Effect.provide(self, layer)` per case (and extra inner `Effect.scoped` for temp dirs, lines 33-51). Packet P0.5 already records this as a D14 exception. `packages/platform/node-shared/test/NodeFileSystem.test.ts:61-63` does `it.effect(…).pipe(Effect.provide(NodeFileSystem.layer))` plus `TestClock.withLive` in `startWatch` (`31-32`). D14 would migrate the cheap platform layer to `it.layer`; that changes Clock-capture-at-build semantics (Sleeper lesson).

3. **`Layer.unwrap` / `Layer.effect` that only wrap `Layer.succeed` internals** still count as effectful constructors. D14 as stated sends them to `it.layer` even when acquisition is trivial. Judgment residue is required (packet already says so).

4. **D14 does not by itself fix TestClock sharing.** Moving `Effect.provide(TestClock.layer())` (fresh per test) into `it.layer` *introduces* shared time. That is the opposite of `it.effect`'s per-test TestEnv. Resource sharing and clock isolation are different axes.

5. **Outer vs inner scope is two owners, not one.** "The runner owns the scope" is true for the inner `Effect.scoped`. Layer resources are owned by `it.layer`'s outer `Scope.make()` / memo `layerScope`. Detectors that treat every `Scope` mention as EV004 will mis-attribute.

### 8. Watchdog design stress-test (D7)

D7 sketch: wrap testers so the body is `Effect.raceFirst(body, watchdog)` with

`watchdog = Effect.sleep(limit).pipe(TestClock.withLive, Effect.andThen(Effect.die(new TestHang({ testName, lastLog }))))`.

**What source supports**

- A TestClock `Effect.sleep` without `adjust` does not complete. Official guide + `TestClock.ts:36-41,327-339`. A watchdog that is *not* live never fires under `it.effect` / default `it.layer`. D7's live-clock requirement is verified.
- `TestClock.withLive` under a provided TestClock swaps `Clock.Clock` to the live clock captured at `make` (`278-280,580-581`). That is the correct operator **when TestClock is the Clock ref**.
- `Effect.raceFirst` is `raceAllFirst` (`internal/effect.ts:1623-1659,1535-1558`): first exit wins; remaining fibers are interrupted. If the race is **inside** the tester's `Effect.scoped`, inner-scope `onExit` still runs on watchdog die (`3938-3946`). Outer `it.layer` scope is not closed by a test-body interrupt. **Verified structure.**
- `TestClock.withLive` does not call `adjust`. A correctly implemented watchdog does **not** pollute shared block time. **Inference** from API.

**Contradictions / design holes**

1. **`it.live` wrap is unsafe as written.** `it.live` has no TestClock (`internal.ts:357`). `TestClock.withLive` casts `Clock.Clock` to `TestClock` (`471`). **Inference:** TypeError on `ClockImpl`. The live tester should use plain `Effect.sleep(limit)` (already live). Same hole for `excludeTestServices: true`.

2. **Wrap order must put the race inside `mapEffect`.** Public-API wrapping of the `TestFunction` (D7: wrap testers via `makeMethods`) yields `mapEffect(raceFirst(body, watchdog))`, i.e. race inside `Effect.scoped` + `Effect.provide(TestEnv|context)`. That is the order that (a) gives `withLive` a TestClock under `it.effect`/`it.layer`, and (b) still closes the inner scope on die. Racing *outside* provide loses TestClock for `withLive`.

3. **Hooks are not in the race.** Named build is `beforeAll`; unnamed first build is `beforeEach`. Watchdog cannot name "last log line" during container startup. Those hangs hit **hookTimeout** (default 10s) with a vitest hook failure, not `TestHang`. EV014 (`timeout: "30 seconds"`) and D7 watchdog are complementary, not substitutes. D7 "under the vitest timeout" refers to **testTimeout** (default 5s), a different budget than hookTimeout.

4. **Shared TestClock + watchdog is OK; shared TestClock + mistaken `adjust` is not.** If an implementer "fixes" a hang by `TestClock.adjust(limit)` instead of `withLive`, they would release every sleep scheduled on the shared clock (**inference** from `run`/`sleeps` in `TestClock.ts:343-375`).

5. **Captured clocks ignore `withLive`.** A service that stored `Clock` at `it.layer` build (Sleeper) still TestClock-sleeps while the watchdog live-sleeps. `raceFirst` still interrupts the body fiber (`raceAllFirst` `fiberInterruptAll`). Hang *detection* works; hang *attribution* ("waiting on TestClock") is not automatic.

6. **Watchdog limit vs vitest `testTimeout`.** README/`it.effect` third-arg default is 5s (`README.md:45`). If watchdog `limit` ≥ testTimeout, vitest may fire first and the `TestHang` defect never surfaces. D7 says "under the vitest timeout" — implement **strictly less than** the effective test timeout. Not verified by running races.

7. **Wrapping `it.layer` only instruments the callback `it`.** Outer `closeScope` in `afterAll` can still hang on layer finalizers (container stop). That is again hookTimeout, not watchdog.

8. **Concurrent unnamed `it.layer` + remaining counter.** Close-on-last-test uses non-atomic `remaining--` (`303-307`). `afterAll` saves resource leaks. Watchdog interruption of a test still runs `onTestFinished`. No extra contradiction found; close remains outer-owned.

### 10. Practical pitfall list (for later phases; not implementing)

1. `it.layer` TestClock is block-scoped state; `adjust` leaks. Reset or isolate.
2. Nested `it.layer` isolates *new* layers, not parent `TestEnv`.
3. Named vs unnamed: named isolates hooks in `describe`; unnamed registers suite-level `beforeEach`/`afterAll`.
4. Omit `timeout` on slow layers → 10s hook kill, not 5s test kill, not watchdog.
5. `excludeTestServices` is all-or-nothing and sticky in nested blocks; it also breaks `TestClock.withLive`.
6. Do not wrap the whole `it.effect` body in `Effect.scoped`; nested scoped for a shorter lifetime is used upstream.
7. `Effect.provide(layer)` inside `it.effect` rebuilds; `Effect.provide(context)` (what `it.layer` does) does not.
8. Clock captured at layer build ≠ Clock at call time.
9. README at rc.112 does not document 1–5; do not treat README as the `it.layer` spec.
10. HEAD `@effect/vitest` README (search snippet 2026-09-08) mentions `{ concurrent: true/false }` on `layer` — **not present** at rc.112. Do not copy HEAD docs.
