## 2. `it.layer` mechanics the SQL/platform suites actually use

Primary tag anchors (`packages/vitest/src/internal/internal.ts`):

| Behavior | Anchor | Verified fact |
| --- | --- | --- |
| `TestEnv` = `TestConsole.layer` + `TestClock.layer()` | 44 | merged into the shared build unless `excludeTestServices: true` (237–240) |
| One scope per block | 242 | `Scope.make()` once |
| Build once, cached | 243–247 | `Layer.buildWithMemoMap` + `Effect.cached` + `Effect.runSync` of that cached effect |
| Build dies the block | 244 | `Effect.orDie` |
| Inner tests get Context, not Layer | 259–265 | `Effect.flatMap(contextEffect, (context) => effect.pipe(Effect.scoped, Effect.provide(context)))` |
| Nested fork of memo map | 270–277 | child `memoMap: Layer.forkMemoMapUnsafe(memoMap)` |
| Named form = `describe` + `beforeAll`/`afterAll` | 317–327 | hook timeout from `options.timeout` via `hookTimeout` (54–55, 319–325) |
| Unnamed form = lazy first-test / last-test close | 281–314 | `beforeEach` runs `contextEffect`; last matching test closes the scope |
| Nested options | 270–271 + typetest | nested `it.layer` accepts `timeout` only; `excludeTestServices` / `memoMap` are rejected (`packages/vitest/typetest/index.tst.ts` 33–51) |

Public docs at tag (`packages/vitest/src/index.ts` 176–178): “Share a `Layer` between multiple tests”. README line 32: same one-liner. README “Resource Safety and Scope” 257–258: `it.effect` / `it.live` already own a fresh `Scope`; do not wrap the body in `Effect.scoped`.

`Layer.forkMemoMapUnsafe` (`packages/effect/src/Layer.ts` 495–511): child memo map **reuses parent allocations** and **does not write newly built layers back to the parent**. Changelog at tag (`packages/vitest/CHANGELOG.md` 337, beta.67 / PR effect-smol#2177): nested `it.layer` forks memo maps “isolating sibling setup while preserving parent sharing”.

**Inference:** that is why a nested SQL suite can reuse a parent Postgres container while two sibling nested layers each get their own store/schema.

Per-test `Effect.provide(layer)` is the opposite (`packages/effect/src/internal/layer.ts` 8–22): `scopedWith` opens a **fresh scope per run** and `buildWithScope` rebuilds the layer into it. N tests = N acquisitions / N releases. **Verified (snapshot).**

## 3. Container services: the shared-fixture shape

Canonical constructor (verified snapshot `packages/sql/pg/test/utils.ts`, 58 lines; GitHub blob at the pin also reports 58 lines):

1. `Context.Service` (`"test/PgContainer"`) whose `make` is `Effect.acquireRelease(PostgreSqlContainer("postgres:alpine").start(), container.stop)`.
2. `static layer = Layer.effect(this)(this.make)` — the expensive acquire.
3. `static layerClient = Layer.unwrap(Effect.gen(function*() { const container = yield* PgContainer; return PgClient.layer({ url: Redacted.make(container.getConnectionUri()) }) })).pipe(Layer.provide(this.layer))`.

`Layer.unwrap` (`packages/effect/src/Layer.ts` 1174–1178) turns `Effect<Layer<A, E1, R1>, E, R>` into a `Layer`. The client Layer is therefore built **from the already-acquired container**, not by starting a second container.

Variants on the same container:

- `layerMakeClient` — `PgClient.layerFrom(PgClient.makeClient({ url }))`
- `layerClientWithTransforms` — camel/snake name transforms
- `layerClientSingleConnection` — `maxConnections: 1` (LISTEN/NOTIFY tests)

## 4. Nested reuse vs sibling isolation vs top-level restart

### 4.1 Nested `it.layer` reuses the parent allocation

`packages/vitest/test/index.test.ts` 109–124: outer `layer(Foo.layer)`, inner `it.layer(Bar.layer)` — `Bar` is `Layer.effect` of `Foo`. Inner test yields both.

`packages/sql/mysql2/test/Persistence.integration.test.ts` 11–16 is the SQL form of that:

```ts
it.layer(MysqlContainer.layerClient, { timeout: "90 seconds" })("Persistence", (it) => {
  PersistedCacheTest.suiteWith("sql-mysql2-multi", Persistence.layerSqlMultiTable, it)
  PersistedCacheTest.suiteWith("sql-mysql2-single", Persistence.layerSql, it)
  PersistedQueueTest.suiteWith("sql-mysql2", PersistedQueue.layerStoreSql(), it)
  it.effect("deletes expired entries in batches", …)
})
```

`suiteWith` calls `testApi.layer(layer, { timeout })` — i.e. **nested** `it.layer`. The MySQL container is acquired once; inner persistence/queue layers are built against that parent Context via the forked memo map.

The cleanup test in the same block (`Persistence.integration.test.ts` 25–26) `DROP TABLE IF EXISTS` because the single-table cache suite left schema on the **shared** database. **Verified (snapshot).** That comment is direct evidence that inner suites share the outer container.

### 4.2 Sibling nested layers do not share child allocations

`packages/vitest/test/nested-isolation.test.ts` 29–62: parent `layer(Parent.layer)`, two sibling `it.layer(Child.layer)` — child ids 1 then 2; first child released before the second `beforeAll`. Concurrent siblings (65–119) also get distinct children. Provided-state graph (122–212) mutates isolated `Ref`s per sibling.

**Inference for SQL:** nested `suiteWith` under one container is the intended share; two top-level `it.layer(PgContainer.layerClient)` calls are **not** the same container.

### 4.3 Separate top-level `it.layer` = separate memo map = another container

Each `layer()` call does `options?.memoMap ?? Effect.runSync(Layer.makeMemoMap)` (`internal.ts` 241). Top-level blocks do not share memo maps.

`packages/sql/pg/test/Persistence.integration.test.ts` therefore starts **multiple** Postgres containers:

- `PersistedCacheTest.suite("sql-pg-multi", Persistence.layerSqlMultiTable.pipe(Layer.provide(PgContainer.layerClient)))` — top-level `it.layer`
- `PersistedCacheTest.suite("sql-pg-single", …)` — another
- `PersistedQueueTest.suite("sql-pg", …)` — another
- `it.layer(PgContainer.layerClient, { timeout: "30 seconds" })("PersistedQueue SQL locks", …)` — another
- `it.layer(PgContainer.layerClient, …)("Persistence SQL cleanup", …)` — another

Same for `packages/sql/pg/test/KeyValueStore.integration.test.ts` (two `KeyValueStoreTest.suite` calls, each `Layer.provide(PgContainer.layerClient)`), `packages/sql/mssql/test/Persistence.integration.test.ts` (two top-level suites), `packages/sql/mysql2/test/KeyValueStore.integration.test.ts` (two top-level suites, **not** nested under the Persistence file’s 90s layer).

**Verified (snapshot + GitHub suite helpers).** Packet §1.5’s “nine `packages/sql/pg/test/*.test.ts` files (`it.layer(PgContainer.layer, { timeout: "30 seconds" })`)” is **too coarse**: there are nine `*.test.ts` files, but only some wrap a container, and several files open **more than one** container because they use top-level `suite()` instead of nested `suiteWith`.

`packages/vitest/test/isolation.test.ts` 56–90: three top-level `it.layer(inMemoryLayer)` blocks each get a fresh state id. **Verified.**

### 4.4 A third sharing pattern: vitest `globalSetup` (not `it.layer`)

`packages/platform/node/test/cluster-integration/globalSetup.ts` 27–37 starts Postgres + MySQL once for the **project**, `project.provide("clusterDatabases", { mysql, pg })`, stops both on teardown. This is process-wide, not a memo-map. Out of scope for `it.layer` canon, but it is how the cluster-integration lane shares containers. **Verified (snapshot).**

## 5. Inner per-test state (connections, tables, temp dirs)

The shared fixture is the container / client / in-process engine. Isolation inside the block is **not** a second container. Observed inner-state recipes:

### 5.1 Per-test connection from the shared pool

`packages/sql/pg/test/Client.integration.test.ts` 362–372 (`"interruption"`):

```ts
const conn = yield* sql.reserve
yield* conn.executeRaw("select pg_sleep(1000)", []).pipe(
  Effect.timeoutOption("50 millis"),
  TestClock.withLive
)
```

`sql.reserve` is taken inside `it.effect`, so the reserved connection is scoped to **that test’s** `Effect.scoped` (runner-owned). The pool itself is the shared layer. **Verified.**

LISTEN tests in the same file (393–446) share `layerClientSingleConnection` (`maxConnections: 1`) and fork `sql.listen(channel)` with `Effect.forkScoped` — again the extra connection/fiber is per-test scoped.

### 5.2 Per-test tables / namespaces on the shared database

- `CREATE TEMP TABLE nested_transactions (value TEXT) ON COMMIT DROP` — `Client.integration.test.ts` 265. Temp table dies with the transaction. **Verified.**
- `CREATE TABLE test_multi …` inside one transforms test (350–354) — lives on the shared DB for that test only; no drop. **Inference:** later tests in that block must not assume a clean `test_multi`.
- Pglite `setup(table)` (`packages/sql/pglite/test/Transaction.test.ts` 7–14): `CREATE TABLE IF NOT EXISTS ${table}` + `TRUNCATE … RESTART IDENTITY`. Shared in-process engine (`PgliteClient.layer({})` at 5, provided once via `layer(ClientLayer)` at 17); **per-test table name**.
- Pglite `Migrations` (`packages/sql/pglite/test/Client.test.ts` 8–15, 27): `Layer.effectDiscard` DROP/CREATE `test`, then `Effect.provide(Migrations)` **inside** the test body. Shared engine, per-test schema reset.
- Libsql `Migrations` (`packages/sql/libsql/test/Client.integration.test.ts` 6–16, 63): `CREATE TABLE test` acquire / `DROP TABLE test` release, provided per test. Extra `Effect.addFinalizer(() => sql\`DROP TABLE test2\`)` at 70 for a second table.
- Event-log unique names (`SqlEventLogServerUnencryptedStorageTest.ts` 9–21, GitHub raw): `uniqueNamespace` increments a module counter so `entryTablePrefix` / `remoteIdTable` differ per test on the shared SQL client.
- Persistence store ids (`packages/sql/sqlite-node/test/Persistence.test.ts` 31, 43, 61, …): `"test_store"`, `"test_store_2"`, … on one shared sqlite file.
- KeyValueStore tests start with `kv.clear` (`KeyValueStoreTest.ts` 11, 27, 39, …) because the store Layer is shared.

### 5.3 Per-test temp directories (cheap FS, or sqlite file)

Sqlite-node **shared-DB** form (`Persistence.test.ts` 12–21, `KeyValueStore.test.ts` 8–17):

```ts
const ClientLayer = Effect.gen(function*() {
  const fs = yield* FileSystem.FileSystem
  const dir = yield* fs.makeTempDirectoryScoped()
  return SqliteClient.layer({ filename: dir + "/test.db" })
}).pipe(Layer.unwrap, Layer.provide([NodeFileSystem.layer, Reactivity.layer]))
```

`makeTempDirectoryScoped` runs when **the layer is built** (once per `it.layer` block). The temp dir is the **outer** fixture; tests share `test.db`. Isolation is store/table names, not files.

Sqlite-node **per-test DB** form (`packages/sql/sqlite-node/test/Client.test.ts` 6–13): `makeClient` itself does `makeTempDirectoryScoped` + `SqliteClient.make`. Because that effect runs inside `it.effect`, the temp dir is the **inner** fixture (fresh file per test). Same helper, different lifetime.

`makeTempDirectoryScoped` contract (`packages/effect/src/FileSystem.ts` 180–191): “Functionally equivalent to `makeTempDirectory`, but the directory will be automatically deleted when the scope is closed.” Node implementation (`packages/platform/node-shared/src/NodeFileSystem.ts` 183–191): `Effect.acquireRelease(mkdtemp, rm recursive)`. Unscoped `makeTempDirectory` (163, 29–40 of the conformance helper) **survives** the inner scope — that is a test of the unscoped API, not a leak of the shared layer.

Platform KeyValueStore FS test (`packages/platform/node/test/KeyValueStore.test.ts` 12–49): outer `it.effect` provides `NodeFileSystem.layer` once for the test; inner `makeTempDirectoryScoped` is the root; `KeyValueStore.layerFileSystem(directory)` is provided only around the store operations. Cheap platform layer + per-test directory.

### 5.4 What is **not** inner state

`packages/sql/mysql2/test/Model.integration.test.ts` 38–40 (and the rest of that file): each `it.effect` does `Effect.provide(MysqlContainer.layerClient)` with `{ timeout: 60_000 }`. That **rebuilds the container per test** (`internal/layer.ts` 8–22). Same for `packages/sql/mysql2/test/Client.integration.test.ts` 29–31, `packages/sql/d1/test/Client.test.ts` 42 (and siblings): `Effect.provide(D1Miniflare.layerClient)` per test.

Those are the expensive-layer anti-pattern the packet’s D14 is written against. Upstream itself is inconsistent: Persistence uses `it.layer`; Model/D1 often do not.

## 6. `TestClock.withLive` waits

### 6.1 What it does (tag + official API)

Implementation (`packages/effect/src/testing/TestClock.ts` 278–280):

```ts
function withLive<A, E, R>(effect: Effect.Effect<A, E, R>) {
  return Effect.provideService(effect, Clock.Clock, liveClock)
}
```

`liveClock` is captured at `TestClock.make` (254) via `Clock.clockWith`. The exported helper (547–581) is `testClockWith((testClock) => testClock.withLive(effect))`.

Official API page **verified (web, 2026-09-08)** `https://effect.website/docs/v4/api/effect/testing/TestClock` `#withLive`, source link pinned to the same SHA `…/TestClock.ts#L580`. Example: `Clock.currentTimeMillis` under TestClock is `0`; `TestClock.withLive(Clock.currentTimeMillis)` is wall time.

The **guide** `https://effect.website/docs/v4/testing/testclock` (fetched 2026-09-08) documents `adjust` / `setTime` / fork-then-adjust. It does **not** mention `withLive`. `https://effect.website/docs/guides/testing/testclock` returned **404**. Use the v4 API page + tag source for `withLive`, not the older guide URL from packet §1.2’s README link.

Warning-fiber scheduling inside TestClock also uses `withLive` (`TestClock.ts` 289–291) so the “you forgot to adjust” warning can fire on real time. **Verified.**

Because `it.layer` merges `TestClock.layer()` into the **shared** block Context (`internal.ts` 44, 238–240), `TestClock.adjust` in test 1 persists into test 2. Packet §1.2 / EV015. `it.effect` outside a layer block gets a fresh `TestEnv` per test (`internal.ts` 356). **Verified.**

### 6.2 Why SQL/platform tests wrap waits

Under TestClock, `Effect.sleep`, `Effect.timeout`, `Schedule.spaced`, and `pg_sleep` **do not advance** unless something calls `TestClock.adjust` or the sleep is switched to the live clock.

## 7. Expensive shared fixture vs inner per-test state (decision table)

| Resource | Cost | Share with `it.layer`? | Inner per-test state | Tag evidence |
| --- | --- | --- | --- | --- |
| Docker Postgres/MySQL/MSSQL/Redis/libsql | seconds–tens of seconds | **Yes.** One acquire/release per block. Pass `{ timeout: "30 seconds" }` (MySQL Persistence uses 90s). | New table / TEMP TABLE / unique namespace / `kv.clear` / `sql.reserve` | §3–§5 |
