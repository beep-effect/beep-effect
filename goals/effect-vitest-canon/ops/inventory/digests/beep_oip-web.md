## Layer topology and native boundaries

The main suite explicitly disables concurrency. React Testing Library renders actual components in configured jsdom, with mocked Next image/headers/server seams. OipAtomProvider builds a RegistryProvider with defaultIdleTTL=1000 and mounts the browser runtime. HeroVideo owns idle and interval cancellation through Atom finalizers; the interval remains 7000ms and tests invoke its captured callback rather than waiting seven seconds. This proves controlled callback behavior, not real media playback or browser event timing. DOM cleanup and media/global restoration must retain their lifetimes during P2.

The two ConfigProvider wrappers build scoped pure configuration layers with synthetic values. They are mechanical wrapper candidates, not evidence of an expensive network allocation. submitContact itself scopes HubSpot.makeLayer with FetchHttpClient when spam checks and configuration succeed. The provider-success/error cases intercept global fetch. The HttpApi handler builds a local Web handler with injected submit; Request/Response/FormData are the actual public subjects, with no HTTP server opened. Its production helper returns only handler rather than the toWebHandler lifetime object; this audit has not established an acquired socket or runtime leak and makes no such finding.

Home reads runtime Sanity configuration and may fetch content; the final valid form POST uses ambient HubSpot configuration. These call paths are not universally isolated by the test's separate configuration wrappers. A future repair must control the actual runPromise boundary, not assume context crosses a Promise. No environment values, tokens or provider services were accessed. MemoryFileSystem cannot replace DOM, media callbacks or Web-standard request behavior and is not indicated here.

setup.dom.ts is support code installed by package Vitest configuration. It conditionally supplies storage, fixed-false matchMedia, inert observers and a one-millisecond native idle fallback with cancellation. Those are limited jsdom capabilities, not full browser conformance. The setup file has no independent timing registration and is neither an omitted test nor skipped test. There is no isolated rebuild measurement or credible savings estimate from this audit.

## Findings and preservation

- **L-PROP-04 negative-seo-presence-gap**, `apps/oip-web/test/oip-seo.test.ts:43-96`: sameAsUrls returns [] when LegalService is absent; inactive and Discord cases accept that empty result. Preserve all negative containment and length assertions and the active positive controls. Require the LegalService node to exist for each input before inspecting sameAs. A graph that drops that node only for inactive/Discord input satisfies the current negative oracle. Do not replace the absent sameAs field contract with a mandatory empty property.
- **L-RES-02 restoration-not-armed-before-render**, `apps/oip-web/test/oip-web.test.tsx:443-501`: Media prototypes and idle callbacks are patched before render and two synchronous assertions; finally is attached afterward. Install restoration immediately with try/finally or an equivalent scoped acquisition covering render and all synchronous assertions as well as the returned Promise. If render or an early assertion throws, current finally is never attached. Preserve serial registration, DOM cleanup, original descriptors, idle handles and all existing assertions. Apply the same ownership review to neighboring browser patches; do not claim an observed leak.
- **L-FLAKE-01 live-spam-threshold-window**, `apps/oip-web/test/oip-web.test.tsx:784-795`: The too-fast payload samples live now minus 1000ms; submitContact later compares another live now against a 3000ms minimum. Use one controlled Effect clock for payload construction and submitContact, preserving the 1000ms age, 3000ms production threshold and rejected assertion. More than 2000ms of scheduling delay can move the case out of its intended branch. Preserve separate browser/native timer subjects; do not blanket-freeze DOM polling or raise timeouts. This is a source-derived timing sensitivity, not a proven historical flake.
- **L-FLAKE-04 ambient-provider-path**, `apps/oip-web/test/oip-web.test.tsx:884-890`: The final POST(formContactRequest()) expects rejected without an empty ConfigProvider or fetch stub; Home calls also use runtime content. Make the intended no-provider configuration explicit at the actual runtime boundary or use the existing injected submit/content seams. POST and getOipSiteContent create their own runtimes, so merely wrapping the outer Promise in Effect.provide does not establish propagation. Keep Web Request/FormData/redirect and page assertions. Ambient HubSpot settings can permit a write; Sanity settings can make Home fetch content. No credential values were read and no provider call was executed.
- **L-PROP-04 provider-normalization-oracle**, `apps/oip-web/test/oip-web.test.tsx:743-753`: The normalization test stubs fetch but only asserts response.status accepted; it never inspects the outgoing provider payload. Keep the accepted-status assertion and all existing FormData normalization checks. Also inspect the captured public fetch request body for normalized email/name and unchanged message, using the actual HubSpot wire contract. A submission that forwards untrimmed input can pass this local oracle because the stub accepts any request. Do not recreate private provider state or alter the production schema.
- **L-OBS-01 unasserted-rejection-log**, `apps/oip-web/test/oip-web.test.tsx:797-804`: The test named logs and rejects on provider failure checks only rejected; production emits sanitized warning annotations. Retain rejected status and the 503 provider stub, and capture the public Effect logger for operation=oip.contact.submit, outcome=rejected and provider reason/status. Check that submitted personal fields and credential material are absent from captured records using synthetic fixture values only. The current case cannot distinguish a missing or misattributed log. No production logging change is authorized.
