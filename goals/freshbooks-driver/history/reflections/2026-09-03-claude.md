# Reflection — freshbooks-driver (2026-09-03, claude)

## Summary

Shipped `@beep/freshbooks` on the `@beep/hubspot` pattern: a schema-first Effect
driver with an auth-code token helper whose single-use refresh-token rotation is
serialized behind one refresh owner, and schema-decoded read verbs for identity,
clients, invoices, and payments across the distinct `account_id` / `business_id`
namespaces. The rotation guarantee is proven by a concurrent-refresh test. The
invoice-PDF retrieval verb is deferred: its P0 live validation requires a
one-time operator OAuth grant an agent cannot perform, so the verb stays out of
the surface (SPEC: "dropped without shame" until proven) and the harness to
finish the verdict is prepared.

## Tooling experience

- **Worked:** `bun run beep create-package --family drivers` scaffolded the
  package and auto-registered `$FreshbooksId`, the workspace, aliases, and
  tsconfig references in one shot. The `@beep/hubspot` exemplar transferred
  almost verbatim (FetchHttpClient + Schema decode + LiteralKit errors +
  `S.Redacted`). Browser-pane + `gh search code` together settled the
  documentation half of the P0 spike fast.
- **Didn't:** `S.fromKey` and `S.merge` (v3 reflexes) do not exist in v4;
  `S.isPositive()` is `S.isGreaterThan(0)`. Each cost a compile round-trip.
- **Frustrating:** the shared-layer capture log under `@effect/vitest`
  accumulates across concurrently-scheduled `it.effect` tests, which produced a
  confusing cross-test URL mismatch until the mock was made a stateless router.
- **Wished existed:** a per-field wire-key rename on schema fields (there is
  only the struct-level `encodeKeys`).
- **Didn't (closeout day):** three attributions of hosted red were wrong in a row —
  an "inherited" Lint Policy red that was really `lint:effect-fn` on the new package,
  an "environmental" all-lanes red that was really the unregistered package tripping
  the CI lane partition gate, and "foreign" edits in the checkout that were really this
  session's own Codex companion doing the registration. Each was resolved by reading
  the primary evidence (the runner's failure summary, one lane's log, a live shell's
  environment) instead of the pattern that looked like it.

## Implementation improvement opportunities

- When the live grant is completed, `getInvoicePdf` is a small addition:
  `GET …/invoices/invoices/{id}/pdf` with `Accept: application/pdf`, returning
  bytes; the error path and account-base builder already exist.
- A generic paginated-list follow (page/pages loop) could sit on top of the
  list verbs for full reconciliation once a consumer needs it.

## Goal & prompt critique

- The packet's P0 "decide the PDF verb against the dev app" is structurally
  operator-gated (interactive OAuth). The GOAL/SPEC should state that the live
  half needs an operator Authorize + redirect-URI registration and treat the
  agent-deliverable as: docs verdict + limits + webhook schedule + ready
  harness, with the live verdict as an operator hand-off.

## TODOs worth codifying

- Operator step: run `goals/freshbooks-driver/research/live-spike-harness.md`

## Lessons (confidence-tiered)

- **HIGH — Critical:** Attribute hosted red from primary evidence before repairing:
  grep the lane runner's `[beep-cli] <lane>: failed N step(s)` summary for the real
  step, and check whether a tiny unrelated PR is green on the same lane (if so the red
  is introduced, not inherited). Pattern-matching on the last-printed step cost a
  whole no-op PR.
- **HIGH — Critical:** A new workspace package must be placed in `CiLanePartitions.ts`
  (lightest bin) with `ci-lane.test.ts` fixtures updated, or every partitioned lane
  fails with `no deterministic placement`; there is no generator despite the hint.
- **HIGH — Critical:** Serialize single-use token rotation with a one-permit
  Semaphore whose critical section re-reads persisted state — atomic persistence
  alone does not prevent replay of a consumed refresh token.
- **MEDIUM — Best practice:** Validate every v4 Schema API against the reference
  checkout before writing it; v3 muscle memory (`fromKey`, `merge`,
  `isPositive`) silently misfires.
- **LOW — Consideration:** For boundary DTOs that rename many snake_case wire
  keys, `S.Struct(...).pipe(S.encodeKeys({...}))` is cleaner than fighting to
  keep an `S.Class`.
