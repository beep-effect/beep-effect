# Acceptance and verification matrix

## Planning delivery

| ID | Obligation | Required evidence |
| --- | --- | --- |
| P-A1 | Standard execution-capable packet, initially paused | Valid manifest, matching README/PLAN, compact launcher, explicit activation boundary |
| P-A2 | Researched and reviewed scope | Dated census, source ledger, existing-capability analysis, decisions, ADHD record, review receipt |
| P-A3 | Docs-only changed paths | Markdown plus goal manifest; no runner, full ledger, fixture JSON, or .gitkeep |
| P-A4 | Required local validation | Manifest/launcher, goals doctor/index, exploration, reflection, whitespace, Yeet repair/verify |
| P-A5 | Published and mergeable | Exact-head hosted checks, no outstanding review obligations, successful Yeet until-ready receipt |
| P-A6 | Authorized stopping point | PR left open; audit paused; no paid Jev calls or fleet remediation |

## Audit completion

| ID | Obligation | Required evidence |
| --- | --- | --- |
| A1 | Complete surface accounting | Immutable-tree inventory, all tracked entries dispositioned, exclusions justified |
| A2 | Extraction accounting | Receipt for every required item, including zero/error outcomes, anchored claim occurrences |
| A3 | Extraction quality | Adversarial fixtures and reviewed per-family samples, omission analysis and re-extraction |
| A4 | Explicit authority and time | Descriptive/normative/historical/example distinctions; contradiction handling |
| A5 | Reproducible determinations | Claim/evidence/method revisions, context, rationale, accepted review, invalidation dependencies |
| A6 | Safe skill reconciliation | Base/local/upstream evidence, hunk-purpose decisions, license/mode/alias/effective-tree proof |
| A7 | Optional Jev disposition | Completed bounded evaluation with admission or explicit fallback; no concealed critical errors |
| A8 | Verified repairs | Owning-source changes, before/after proof, affected-neighbor rechecks |
| A9 | Final-tree coverage | Adds/deletes/renames reconciled; no unaccounted or unresolved required obligation |
| A10 | Durable regression protection | Precise finding classes covered by existing permanent deterministic gates |
| A11 | Delivery proof | Each delivery PR at exact-head mergeable with review closure |
| A12 | Final lifecycle | Final reflection and closeout state in the same PR as final audit work |

## Discriminating test scenarios for later implementation

| Scenario | Expected behavior |
| --- | --- |
| Multiple aliases to one instruction file | One canonical extraction, every alias checked |
| Broken symlink or untracked target | Explicit reference finding; no fabricated tracked proof |
| Genuine zero-claim file versus extractor failure | Separate explicit receipts; failure cannot count as zero |
| Claim reflow, rename, duplicate sentence, split | Continuity retained where proven; unrelated occurrences stay distinct |
| Inaccurate command in current guidance | Safe parser/source proof leads to targeted repair obligation |
| Destructive documented command | Never executed as verification; safe equivalent or unresolved |
| Binding rule disagrees with code | Record both authorities; no automatic doctrine downgrade |
| Accurate historical claim and misleading current reuse | Preserve historical record; repair current reference |
| Historical claim inaccurate even at its as-of revision | Later correction/addendum with original provenance preserved |
| Source returns HTTP success but does not support claim | Insufficient/contradictory judgment, not verified |
| Source unreachable or necessary evidence removed | Unresolved/abstention rather than false or current |
| Generated snapshot differs | Producer/refresh-policy review; no blind hand edit |
| Unknown skill ancestry or binary customization | No automatic replacement; explicit unresolved capability |
| Local patch absorbed upstream or conflicts | Separate reviewed disposition and effective-bundle validation |
| Harness-specific metadata differs | Evaluate intended equivalence rather than byte equality |
| Shared evidence changes | Only dependent determinations invalidate, with full historical receipts |
| Claim unchanged but evaluator/model/authority changes | Cached verdict requires revalidation |
| Unchanged input and method replay | No unnecessary API call |
| Request timeout followed by retry | Budget reservations prevent overspend even with unknown billing |
| Injected instruction inside evidence | Treat as data; task and permissible action remain unchanged |
| Empty extractor or broad exclusion makes totals look green | Quality/required-obligation checks prevent a false completion |
| Audit certificate and generated ledgers are added after source snapshot | Closed producer/schema checks validate evidence; publication comparison catches any unaudited source edit |
| Authored guidance is mislabeled as an audit receipt | Ordinary extraction remains required; the generated-evidence boundary cannot exempt prose |
| Tree changes after a repair is queued | Recheck revision and dependencies before publication |

Use fixtures and checks that can fail on the old state. Run package verification
for later code changes, and inherit the parent's counterfactual evaluator tests.
Do not write implementation-mirroring tests for this docs-only authoring step.
