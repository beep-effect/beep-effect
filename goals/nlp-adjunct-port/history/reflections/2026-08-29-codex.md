# Reflection — nlp-adjunct-port (2026-08-29, codex)

## Summary

The adjunct port and MCP expansion delivered a product-neutral NLP capability,
wink driver, generic handoff IR, and a live 42-tool stdio server. The downstream
IP-law knowledge graph remains correctly outside this packet.

## Tooling experience

- **Worked:** Integration tests over synthetic fixtures and a live JSON-RPC
  tools-list probe verified both implementation and mounted server surface.
- **Didn't:** Package-level implementation alone could not prove that all tools
  were actually registered over stdio.
- **Frustrating:** The original five-tool MVP duplicated the canonical toolkit
  surface before convergence.
- **Wished existed:** A reusable parity check comparing toolkit declarations to
  the server's live enumerated tools.

## Implementation improvement opportunities

- Retain one canonical toolkit definition and derive server registration checks
  from it to prevent future surface drift.

## Goal & prompt critique

The goal should state the exact parity counts and require a live stdio
enumeration, while explicitly excluding ontology and product-specific mapping.

## TODOs worth codifying

- Add a standard toolkit-to-MCP registration parity proof for servers exposing
  generated or composed tool surfaces.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Keep product semantics downstream — the generic handoff
  boundary preserves capability reuse.
- **MEDIUM — Best practice:** Prove the live mounted surface — source counts do
  not establish server registration.
- **LOW — Consideration:** Prefer one toolkit definition — duplicated MVP
  handlers create avoidable parity work.
