# Reflection — identity-iri-core (2026-07-02, claude)

## Summary

Rewrote `@beep/identity` in place as a literal-preserving IRI/CURIE composer
(vocab registry + Curie/Predicate/Expand types, CURIE + PN_LOCAL codecs,
bound composer with exact-literal `.iri`/`.curie`/`.slug`, projection-only
`rebase`, owned-channel annotation fields) with zero call-site changes,
proven by a shape-stable harness written before the rewrite. Landed as
[PR #289](https://github.com/beep-effect/beep-effect/pull/289), merged same
day. Verdict: the exploration→prototype→port pipeline worked exactly as
designed — every module was a port of an already-proven scratchpad file, so
implementation risk concentrated where expected (Id.ts generics threading)
and nowhere else.

## Tooling experience

- **Worked:** the effect-only scratchpad prototype as port donor (27/27 tests
  carried straight into package tests); the P0 shape-stable harness as
  rewrite tripwire; turbo-filtered gates for fast package-scoped proof;
  exploration packet back-links giving every sub-agent self-contained
  context.
- **Didn't:** codex-companion foreground timeouts (10 min) killed or detached
  long tasks; resume paths never recovered a stalled Codex thread — only
  fresh relaunches worked; `bunx --bun vitest` worker startup failed on this
  host in two independent runs.
- **Frustrating:** local `yeet verify` structurally blocked by inherited
  main-red (five distinct pre-existing failure classes), forcing manual
  attribution + `--no-verify`; the permission classifier allowed one direct
  main push and denied the next identical pattern, splitting the flow.
- **Wished existed:** verify-against-attributed-baseline (introduced-only
  failures); a sub-agent contract primitive for "deliverable = file at exact
  path, verify before finishing" instead of restating it per prompt.

## Implementation improvement opportunities

- The unbound-composer `.iri`/`.curie` returning typed `undefined` is safe
  but worth revisiting when `identity-iri-fold` lands — a `Predicate`-style
  branded "unbound" marker might catch misuse earlier at type level.
- `SlugFromIdentifier` is runtime-mirrored at type level for static strings
  only; acceptable now, but the fold packet's Markdown projection should
  assert parity property-based.
- The vocab registry and `@beep/rdf` Vocab constants are now dual-maintained
  under a drift test; consider generating one from the other when the fold
  packet touches both.

## Goal & prompt critique

- GOAL.md's workflow ordering (authority ruling → harness → port → measure)
  was right and the launcher stayed under budget. Two edits would have saved
  review cycles: name the house test idiom explicitly (@effect/vitest,
  no node:*), and pre-assign homes for cross-package guard tests (drift test
  in the downstream package; template assertions in the template's package).
- SPEC's Exception Ledger for inherited main-red proved load-bearing — the
  PR body cited it verbatim. Keep that section in future packet SPECs cut
  from red mains.

## TODOs worth codifying

## Lessons (confidence-tiered)

- **HIGH — Critical:** Pin the entire existing surface with a harness before
  rewriting a foundation package — the audit-B inventory turned "trust me,
  zero call-site changes" into a test result.
- **HIGH — Critical:** For codex fleets, the only reliable contract is a
  deliverable file at an exact path plus a filesystem watcher; wrapper
  completion notifications and thread resumes are both unreliable.
- **MEDIUM — Best practice:** Prototype in an import-restricted sandbox
  (effect-only scratchpad with a purity test) before touching the real
  package — the packaging decision was settled by construction, not debate.
- **LOW — Consideration:** Measure compile blast radius even when you expect
  it to be fine; the +6%-in-package/noise-downstream numbers preempted an
  entire review thread about template-literal type cost.
