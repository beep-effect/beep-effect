# Reflection — semantic-foundation (2026-08-27, codex)

## Summary

M1 now has an auditable path from a checksum-pinned FOLIO API slice to a
repo-owned SKOS alignment and from that seed to the librarian's concept,
document class, and local-vault/Box filing paths. The closeout also reconciles
the already-complete R1-R4 research while preserving the explicit M2-M4 gates.

## Tooling experience

- **Worked:** CodeGraph located the live package surfaces, the local Effect
  reference settled v4 API details, the asset fetcher reproduced all vendor
  bytes, and package tests plus scoped docgen closed the implementation loop.
- **Didn't:** Packet checkboxes and status prose did not expose that the real
  asset manifest was incompatible with the loader or that librarian output
  dropped alignment metadata.
- **Frustrating:** The prior fixture-only proof looked complete while bypassing
  the exact integration boundary named by the acceptance criteria.
- **Wished existed:** One typed asset-manifest validator reusable by the shell
  fetch lane and package loader without coupling portable ontology code to Bun.

## Implementation improvement opportunities

- Add a new tagged load directive only after a vetted use case exists; keep
  unreferenced research assets inert.
- Consider runtime checksum verification only if the threat model requires
  protection after the canonical fetch script has verified the vendor pack.

## Goal & prompt critique

The goal should require a proof invocation against the real asset manifest, not
only package-local fixtures. Its completion checklist should also require the
sample output to assert the actual alignment collection rather than treating a
concept IRI alone as evidence of external alignment.

## TODOs worth codifying

- Add a shared manifest validator if another loader kind makes the current
  fetch/load schema boundary materially harder to maintain.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Test the named integration artifact directly — fixture
  compatibility does not prove compatibility with the retained manifest.
- **MEDIUM — Best practice:** Separate verification from admission — a fetched,
  licensed asset is not loadable until a specific runtime directive is VETTED.
- **LOW — Consideration:** Defer portable runtime hashing — the current fetch
  lane proves bytes, and adding platform crypto without a concrete threat model
  would widen this focused M1 surface.
