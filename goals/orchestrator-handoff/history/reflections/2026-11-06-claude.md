# Reflection — orchestrator-handoff (2026-11-06, claude)

## Summary

P1 (register, role, merge gate, skill procedures) had merged earlier. This lane shipped P2:
`yeet gate-table` (the `gate.sh` port), `session handoff`, `session ruling add|list` and
`session register convert`. It dropped the Codex-lane PR-comment helper, which the T3-only
messaging doctrine retired. P3 ran as a read-only take-over drill by a fresh child session
that had only the files. It correctly refused the take-over because the holder was live, and
its findings were fixed in the same PR. The goal's purpose holds: a successor can now
reconstruct the role from files. The remaining gaps are data hygiene in the live files, not
missing tools.

## Tooling experience

- **Worked:** the recorded-GitHub test harness (`recordedGithub` and `legacyGhAnswer`) let the
  gate table reuse the 2026-10-06 merge-gate fixtures. `goals decisions add` kept decisions off
  the SPEC tail. Running the new commands against live GitHub and a scratch copy of the live
  HANDOFF.md found the Vercel-status and carry-over problems before tests encoded the wrong
  behaviour.
- **Didn't:** `quality package-verify` ended with the unit-test step terminated (exit 143) and
  no failing test. The admission line reported every token held by other runs. A direct re-run
  was needed to tell an environmental kill from a regression.
- **Frustrating:** the 2026-10-06 pull fixture lacks REST keys (`node_id`, `body`, `merged_at`,
  `labels`, and others). Each new REST consumer re-learns this, as the merge-gate test's
  `restPull` helper shows.
- **Wished existed:** a register field for a unit's T3 thread link that is separate from its
  address, and a ledger heartbeat. The drill could not tell a live holder from a stale one by
  the ledger row's age alone.

## Implementation improvement opportunities

- `gate-table` reads threads once per ready PR. If the queue grows past roughly 30 ready PRs,
  move to one batched GraphQL page per 25 PRs that reuses ReviewThread's wire projection.
- The renderer recognises sections by heading prefix. A heading renamed by hand stops being
  matched and is kept as an extra section, which is safe but silent.

## Goal & prompt critique

- PLAN P2 said `yeet merge-gate --table`. Name the deliverable by behaviour ("a read-only gate
  table command") so the shape is decided with the existing command's contract in view.
- P3's "perform one real take-over" conflicts with "Ownership before take-over" whenever the
  holder is healthy. Proposed edit: "A fresh session performs the take-over procedure from
  files alone, as far as it is read-only while a holder is live, and records every step it
  could not complete."

## TODOs worth codifying

- A journal writer for STATE.md with real instants.
- Seed the rulings store from the live HANDOFF table, then delete the carried block.
- Register PR owners at take-over.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Run any new renderer or gate against a copy of the real artifact before
  writing its tests. Both the carry-over loss and the Vercel over-strictness were invisible on
  synthetic fixtures.
- **MEDIUM — Best practice:** Use a fresh child that has only the files to prove "from files
  alone". The author of the files cannot see what they assume.
- **LOW — Consideration:** Keep wrappers such as `gate.sh` for one cycle after a port, so
  pollers armed by a live holder keep working.
