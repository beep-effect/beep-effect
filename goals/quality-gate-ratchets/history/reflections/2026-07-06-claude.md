# Reflection — quality-gate-ratchets (2026-07-06, claude)

## Summary

Shipped all five ratchet gates (coverage, knip, jsdoc totals, doctrine-pinned
boundaries, commitlint-in-CI) as PR #305 plus the live main ruleset with a
proven direct-push refusal — the repo's declared gates are now blocking,
baseline-ratcheted, and enforced at the trunk. Verdict: the goal succeeded and
its own gates were the toughest reviewers it had — twelve CI rounds, every red
a real defect with no lane to catch it before this PR created one.

## Tooling experience

- **Worked:** the ratchet pattern itself (the knip gate caught five real
  regressions in this PR's own integration before CI ever saw them); direct
  `codex exec` from orchestrator Bash with worktree cwd (after the wrapper
  path failed three ways); `beep worktree new/remove` for lane isolation;
  deliverable-on-disk + file watchers for codex fleets; per-lane
  `.lane-summary.md` proof packs.
- **Didn't:** the codex-rescue wrapper chain (sandbox rooted at the wrong cwd,
  cannot git-commit in worktrees, silent instant-death on auth revocation with
  stale job state); yeet publish's state machine for committed-work publishing
  (staged-only expectations, stale-base + lock interactions).
- **Frustrating:** verdict repair-hint misattribution (three rounds); the
  pre-push composite racing its own steps in one tree; gh pr checks surfacing
  cancelled-duplicate rows as failures.
- **Wished existed:** a single "why did this lane fail, verbatim" surface —
  every diagnosis required exhuming raw logs from envelopes, ANSI-mangled
  turbo streams, or expired log blobs.

## Implementation improvement opportunities

- Extract the shared ratchet skeleton (crispen-debt ledger) so the three
  modules stop tripping duplication audits.
- Coverage lane: consider sharding the full-repo coverage run or reusing
  turbo-cached per-package summaries; the lane is the slowest new gate.
- The Bun-API shim in vitest.setup.ts is deliberate but dense (eight
  complexity suppressions); revisit if Bun ships istanbul-compatible coverage.

## Goal & prompt critique

The GOAL/SPEC held up well — the two-way-proof acceptance criterion and the
"no gate weakened" constraint drove correct behavior under pressure. Two
revisions worth making for successor goals: (1) the Ship phase should name
concurrent-trunk churn as a first-class risk with a rebase/coordination
protocol, not discover it live; (2) "single PR" scope decisions should
pre-authorize the follow-up-fix commits that hosted-only failures inevitably
require, so rounds 4-12 are expected mechanics rather than scope anxiety.

## TODOs worth codifying

See frontmatter `todos`: rqt-015 step isolation, RatchetSupport extraction,
verdict label fix, PR-title length preflight.

## Lessons

- **HIGH:** A gate that has never executed in its enforcing lane is not a
  gate; audit enforcement surfaces as complete sets, not per-failure.
- **HIGH:** Key environment-mode behavior on process-local signals (argv),
  not on env vars crossing spawn chains.
- **HIGH:** When local and CI disagree, suspect the runtime matrix first
  (node version, instrumentation overhead, skipped-on-CI tests) — every
  local/CI divergence in this goal reduced to one of those three.
- **MEDIUM:** Two operators in one checkout works only with commit-level
  interleaving discipline and gets expensive under proof locks; worktrees are
  cheaper than coordination.
- **MEDIUM:** Duplicate CI runs from one push surface as phantom failures;
  check run conclusions before debugging content.
- **LOW:** Suppression comments shift line numbers and invalidate
  line-keyed inventories — regenerate inventories last, after the tree is
  otherwise stable.
