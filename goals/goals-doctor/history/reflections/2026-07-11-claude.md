# Reflection — goals-doctor (2026-07-11, claude)

## Summary

Shipped the full goals-lifecycle machine-truth stack in one packet: canonical
`GoalManifest` v2 with the 5-state domain, a census-locked idempotent
migration (62 manifest edits, 5 backfills, 10 README rewrites, 0 parked, 83/83
decoding), the generated `goals/INDEX.md` with drift check, the single-writer
`set-status`, and a baseline-ratcheted `goals doctor` — all blocking inside
`yeet verify` (PR #373). The P0 census-first discipline paid off: zero
surprises during migration; every surprise came from the repo's own quality
lanes instead.

## Tooling experience

- **Worked:** jsonc-parser surgical edits via the shared
  `applyJsoncModification` kept 62 manifest rewrites byte-minimal and
  reviewable; `diffMembership`/fallow ratchet pattern dropped straight in;
  the P0 jq census script converged with the audit exactly; turbo caching made
  verify reruns cheap enough to iterate.
- **Didn't:** `yeet publish` on a fully-committed tree (requires staged
  changes; needed the `--push-only --reuse-verified` path after a fresh
  verify).
- **Frustrating:** quality lanes surfacing one at a time across verify rounds
  (tests profile, three effect-law lanes, dual-arity inventory) instead of in
  one sweep; a `goals/*/ops/...` glob inside a JSDoc block comment terminating
  the comment (`*/`) cost a round of pure syntax errors.
- **Wished existed:** a single `beep laws --check --scope <dir>` sweep that
  runs every source-law lane over just the files being authored.

## Implementation improvement opportunities

- Record shipping PR numbers in manifests at closeout so the completion-gate
  advisory can verify by PR number rather than commit-subject grep.
- The doctor could emit its findings as a JSON packet (like the reflection
  lint's `[reflection:issue]` lines) for downstream automation —
  portfolio-heartbeat will want machine-readable output.

## Goal & prompt critique

The packet was exceptionally executable: locked decisions D1-D8, oracles
authored at shaping time, and the census-first P0 meant the migration table
was ground truth before any code existed. Two proposed edits: (1) SPEC should
have prescribed the consequence rule for packets newly gated by D7 (the
reflection opt-out was invented mid-flight); (2) PLAN's "Land through yeet"
step should name the fully-committed publish sequence, since phase-per-commit
execution guarantees a clean tree at publish time.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Census before code — committing the full token census
  and mapping table as P0 ground truth made the migration mechanical and
  argument-free; every later decision cited it.
- **HIGH — Critical:** In this repo, run the stricter proof surfaces
  (`quality test-tsgo`, the laws lanes, `lint schema-first`) locally before
  the first verify; the package-level typecheck is necessary but nowhere near
  sufficient.
- **MEDIUM — Best practice:** Baseline ratchets (inherited advisory, new
  blocking, shrink-only) are the right way to land a new blocking gate over a
  drifted population — 36 findings were inherited without blocking anyone
  while new drift blocks immediately.
- **LOW — Consideration:** Keep `lifecycle` mirrors validated-equal rather
  than deleted during migrations; wire-shape compatibility cost nothing and
  the doctor guards the equality.
