## F13: why it is dropped, and the sites P5 fixes by hand

The census regex (`\): [A-Za-z_$][\w$]* is `) counts every type predicate.
On the P4 scan scope it matches 253 predicates in 165 files. Most have no
schema behind them: dynamic-import module-shape guards, WeakSet brand guards,
`instanceof` checks on runtime classes, ts-morph node guards, and
`Readonly<Record<string, unknown>>` shape checks. A rule broad enough to reach
100 files would ship far under 0.70 precision.

The precise rule flagged a hand-written `x is T` guard only when `T` resolves
to a schema value (a class extending a schema factory, or a const built from
`S.*`, `LiteralKit` or `MappedLiteralKit`), or when a `number` guard
re-implements `S.Finite`. It skipped bodies that already derive from the schema
(`S.is`, `.guards`, `.isAnyOf`, `.is.*`, a class's static `is`) and a
schema's own refinement (`S.declare(isFoo)`). That rule found 10 occurrences in
10 files: 9 true positives and 1 borderline, so precision is about 0.90 and
reach is below the floor. SPEC goal-time row 2026-09-29 drops it.

## Occurrence identity

Every parity finding carries a content anchor
`<lexical path>::<export>@<hash>` (`SchemaFirstOccurrenceAnchor`); the
membership key is `file::ruleId::anchor` (`makeSchemaFirstEntryKey`, anchored
branch).

- **Lexical path (display):** the names of the enclosing declarations and
  property keys, outermost first, for example `Widget.title`; `<module>` when
  nothing encloses the reference. It tells a reviewer where the occurrence is.
- **Export:** the wrapper's export name (`withNoneDefault`, `Defect`).
- **Hash (identity):** the first 12 hex digits of the SHA-256 of the
  wrapper's call. The call is the member/call chain that starts at the
  wrapper (`SchemaUtils.withKeyDefaults(0)`, `Defect({ includeStack: true })`),
  widened to the call that receives it as an argument
  (`S.OptionFromOptionalKey(S.String).pipe(SchemaUtils.withNoneDefault)`), so
  it covers the schema being defaulted. The hashed text is the TypeScript
  scanner's token stream without trivia: whitespace and comments are skipped,
  a trailing comma before a closing token is dropped, and string literals
  count by value, not quote style.
- **Residual ordinal:** only calls that are byte-identical after that
  normalization and sit on the same lexical path share a hash. The second and
  later of those get `#2`, `#3` in document order. Removing or inserting one
  of a set of byte-identical twins can therefore still move an ordinal between
  them. The committed backlog at this capture has none.

Consequences, each covered by `packages/tooling/tool/cli/test/schema-first-parity.test.ts`:

- Line shifts and a formatter pass (re-wrapped arguments, comments, trailing
  commas, quote style) change no anchor.
- Removing the earlier of two wrappers on one path resolves exactly that
  anchor; the survivor keeps its identity.
- Inserting a wrapper above an existing one introduces exactly the new
  anchor.
- A parameter, local or other shadowing binding that merely shares the
  wrapper's name is not flagged; element access, parenthesized receivers,
  namespace imports of the Opaque module and barrel re-exports are flagged.

This keeps the effect-vitest membership shape (line kept out of identity,
content anchor inside), anchored on the wrapper's own call rather than on the
enclosing statement. A schema class is a single statement, so a statement
digest would re-key every occurrence in a class whenever any field changed.

## Storage and ratchet

- **Storage:** backlog rows group anchors per file and rule
  (`SchemaFirstBacklogRow { ruleId, file, occurrences }`), sorted by file then
  rule, with anchors sorted lexically. One object per occurrence would have
  been about 900 KB for 2,744 occurrences; grouped, the committed file is about
  316 KB.
- **Check:** `diffSchemaFirstParity` reduces both sides to membership keys and
  classifies them with the shared `diffMembership`. Enforcement goes through
  `enforceRatchet`. An anchor missing from the backlog is a regression and
  fails the check. Its `[schema-first:issue]` line carries the anchor as
  `occurrence`, and Yeet keys the issue id by that anchor instead of the line.
  An anchor the scan no longer finds only prints a `tighten-baseline` hint.
- **Write:** `--write` only shrinks the backlog: it drops resolved anchors,
  never admits a new one, and still fails while one is present. That keeps
  Yeet's staleness repair (`bun run beep lint schema-first --write`) from
  absorbing growth. `--write --admit-parity-backlog` admitted this initial
  capture and is not a routine repair.
- **Removing a rule:** removing a rule id from the `SchemaFirstPolicyRuleId`
  kit makes committed rows for that id undecodable. The PR that removes a rule
  must delete its backlog rows before `--write` can run, as this lane did for
  `SFV4-derived-guard`. Changing the anchor grammar has the same effect: the
  old rows are cleared, then re-captured with `--admit-parity-backlog`.
