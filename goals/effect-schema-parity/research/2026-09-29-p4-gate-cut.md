## F13: why it is dropped, and the sites P5 fixes by hand

The census regex (`\): [A-Za-z_$][\w$]* is `) counts every type predicate.
On the P4 scan scope it matches 253 predicates in 165 files. Most have no
schema behind them: dynamic-import module-shape guards, WeakSet brand guards,
`instanceof` checks on runtime classes, ts-morph node guards, and
`Readonly<Record<string, unknown>>` shape checks. A rule broad enough to reach
100 files would ship far under 0.70 precision.

The precise rule flagged a hand-written `x is T` guard only when `T` resolves
to a schema value (a class extending a schema factory, or a const built from
`S.*`, `LiteralKit` or `MappedLiteralKit`), or when a `number` guard
re-implements `S.Finite`. It skipped bodies that already derive from the schema
(`S.is`, `.guards`, `.isAnyOf`, `.is.*`, a class's static `is`) and a
schema's own refinement (`S.declare(isFoo)`). That rule found 10 occurrences in
10 files: 9 true positives and 1 borderline, so precision is about 0.90 and
reach is below the floor. SPEC goal-time row 2026-09-29 drops it.

## Occurrence identity

Every parity finding carries an anchor `<lexical path>::<evidence>#<ordinal>`
(`SchemaFirstOccurrenceAnchor`):

- **Lexical path:** the names of the enclosing declarations and property
  keys, outermost first. Classes, functions, variables, methods, properties,
  parameters, namespaces, and `default` for an export assignment count;
  property-access chains do not. An example is `Widget.title` for a field
  initializer inside `class Widget extends S.Class<Widget>(...)({ title: ... })`.
  A path with no enclosing names is `<module>`.
- **Evidence:** the flagged export name (`withNoneDefault`, `Defect`).
- **Ordinal:** counts identical path/evidence pairs per rule in document
  order, so two wrappers inside one field are `#1` and `#2`.

The membership key is `file::ruleId::anchor`
(`makeSchemaFirstEntryKey`, anchored branch). No line number takes part. Lines
still travel on the live entry for diagnostics and Yeet issue lines. Inserting
or deleting lines, or reordering sibling declarations, leaves membership
unchanged. Renaming the enclosing declaration or adding another identical
occurrence changes it. Entries of the older rules have no anchor and keep
their historical line-inclusive key.

This follows the effect-vitest membership shape (rule, file, symbol,
evidence, occurrence, ordinal; line kept out) with one deliberate difference.
effect-vitest anchors on a SHA-256 of the enclosing statement's tokens. A
schema class is a single statement, so a token digest would re-key every
occurrence in a class whenever any field of that class changed. The lexical
path keeps an unrelated field edit out of membership.

## Storage and ratchet

- **Storage:** backlog rows group anchors per file and rule
  (`SchemaFirstBacklogRow { ruleId, file, occurrences }`), sorted by file then
  rule, with anchors sorted lexically. One object per occurrence would have
  been about 900 KB for 2,744 occurrences; grouped, the committed backlog is a
  243 KB diff.
- **Check:** `diffSchemaFirstParity` reduces both sides to membership keys and
  classifies them with the shared `diffMembership`. Enforcement goes through
  `enforceRatchet`. An anchor that is missing from the backlog is a regression
  and fails the check; its issue line carries the rule id as the Yeet
  sub-category. An anchor that is no longer found only prints a
  `tighten-baseline` hint.
- **Write:** `--write` rewrites the backlog to the live membership.
- **Removing a rule:** removing a rule id from the `SchemaFirstPolicyRuleId`
  kit makes committed rows for that id undecodable. The PR that removes a rule
  must delete its backlog rows before `--write` can run, as this lane did for
  `SFV4-derived-guard`.
