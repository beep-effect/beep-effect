## Method

`goals/effect-schema-parity/research/tools/facet-census.ts` parses every
`.ts`/`.tsx` file under `packages` and `apps` that mentions `@beep/schema`, plus
every file under `packages/foundation/modeling/schema/src`, with the TypeScript
parser (syntax only, no checker). It resolves three import forms to the
concept member they bind: root `@beep/schema` named or namespace imports, the
concept subpath (`@beep/schema/Number` and so on), and relative imports inside
the schema package. It then counts every reference outside the concept's own
file. Sibling concept files count as consumers, so `Int.ts` reading Number's
checks is attributed to `Number`.

Columns in the census tables:

- **Lines / Files**: distinct source lines and files with at least one
  reference, all buckets.
- **Prod**: the same, excluding test trees (`test/`, `tests/`, `__tests__/`,
  `dtslint/`, `*.test.*`, `*.spec.*`) and the schema package's own `src`.
- **Value / Type refs**: references in expression position versus
  `TypeReference`, `typeof` and import-type position.
- **Static members**: property access on the member (`NonNegativeInt.make`).
- **SPEC rg**: the SPEC command shape
  `rg -c -e '\.<member>\b' packages apps --glob '!node_modules' --glob '!**/<Concept>/**' --glob '*.ts' --glob '*.tsx'`,
  with one extra `--glob '!**/schema/src/<Concept>.ts'` because all four
  concepts are single files, which the directory glob does not exclude.
- **Doc comments**: comment lines that mention the bare member name
  (`(?<![.\w])<member>\b`), a textual count of JSDoc example lines the
  retirement PR also rewrites. It collides with prose for generic names
  (`Int`, `Unknown`).

The import-anchored count is the deciding count. Two cross-checks agree with
it: `NonNegativeInt.make(` appears on 1,223 non-comment lines by `rg` against
1,227 property accesses in the census, and `PosInt.make(` on 335 against 336.
The raw `rg` totals (1,891 and 477) are higher only because they include
JSDoc examples. `graft callers` has no cross-file reference edges for these
symbols and was not usable as a third check.

The opaque facet is the always-true schema equivalence that `Opaque.ts`
attaches through a `toEquivalence` annotation. `facet-probe.ts` measures it:

| Field schema | `S.toEquivalence` on a struct, different causes | `S.toEquivalence` on a `TaggedError`, different causes | `Equal.equals` on `TaggedError`, different causes | `Equal.equals`, same cause |
| --- | --- | --- | --- | --- |
| `@beep/schema` `Defect()` | true | true | false | true |
| `S.Defect()` | false | false | false | true |
| `S.Defect().pipe(S.overrideToEquivalence(() => () => true))` | true | true | false | true |
| `@beep/schema` `OpaqueUnknown` | true | true | false | true |
| `S.Unknown` | false | false | false | true |

The override reproduces today's behaviour in every column, so the facet is
covered by a public symbol. Bare `S.Defect()` would make two values that
differ only in that field compare unequal under `S.toEquivalence`, in the
schemas of 105 production files. `Equal.equals`
on tagged errors ignores the annotation in every variant, so the retirement
cannot change `Equal.equals` results either way.

### Doctrine sums and verdicts

The P0 rule, landing in `standards/architecture/11-evolution-and-deprecation.md`,
compares two sums per concept: (a) lines that read an uncovered facet, and
(b) lines that use a covered facet, schema-value use sites included.
A larger uncovered sum flips the row to ADAPT; otherwise RETIRE holds and the
consumers of minor uncovered facets adapt. LiteralKit read 2,054 uncovered
against 2,048 covered.

`facet-census.ts` prints the sums in its "Doctrine sums" section. Lines are
distinct `file:line` pairs of code (doc comments excluded); one line can land
in both sums. The classification:

- **Uncovered**: type-position references to a member that carries a nominal
  brand (`S.brand` in its definition). Upstream has no pre-branded
  `S.Natural` or positive-integer schema, so these lines lose the brand.
- **Covered**: every schema-value reference (the member passed or piped as a
  schema, called as a constructor, used as a struct field), every static
  member (`.make`, `.pipe`, `.annotateKey`, `.is`, the codec statics), and
  type positions of unbranded members. Each has a public upstream form.

| Concept | (a) Uncovered lines | (b) Covered lines | Covered breakdown | Both | Verdict |
| --- | ---: | ---: | --- | ---: | --- |
| `Number` | 112 (`NonNegativeInt` in type position) | 2,079 | `.make` 1,199, schema value 663, `.pipe` 107, `.annotateKey` 100, `.check` 12, `.annotate` 4, `.ast` 4, `.is` 2, `.decodeEffect` 1 | 8 | RETIRE holds |
| `Int` | 67 (`PosInt` and `Int` in type position) | 478 | `.make` 326, schema value 114, `.annotateKey` 29, `.pipe` 16, `.check` 2, `.decodeEffect` 1 | 1 | RETIRE holds |
| `Unknown` | 0 | 175 | codec statics 160 (`encodeUnknownEffect` 43, `encodeUnknownSync` 39, `decodeUnknownEffect` 22, `decodeUnknownResult` 13, `encodeUnknownResult` 12, `decodeEffect` 10, `encodeEffect` 9, others 12), schema value 15 | 0 | RETIRE holds; target corrected from the internal `S.UnknownFromJsonString` |
| `Opaque` | 0 | 154 | schema value 153 (`Defect(...)`, `OpaqueUnknown`), `.annotateKey` 1 | 0 | RETIRE holds; recipe must carry `S.overrideToEquivalence` |
| PR 3b defaults | 0 | 2,513 | `withNoneDefault` 1,933, `withKeyDefaults` 446, `withConstantDefault` 88, `withEmptyArrayDefaults` 46 | 0 | RETIRE holds |

The sums add back to the census totals (`Number` 112 + 2,079 - 8 = 2,183;
`Int` 67 + 478 - 1 = 544).

**Ruling on `.make` (2026-09-29).** `.make` on a branded member counts as
covered, so RETIRE holds for `Number` and `Int`. The case-brand ruling
(`explorations/effect-schema-parity/DECISIONS.md:297`, "Case-string brands
retire; rejection uses a check") holds that a brand carrying an invariant in
the type is not a kept facet: a check carries it in the schema, which is where
the repo's laws put invariants. `S.Natural.make(n)` and
`S.Int.check(S.isGreaterThan(0)).make(n)` validate and throw exactly as
`NonNegativeInt.make(n)` and `PosInt.make(n)` do, so the member is served by
public upstream API. Only the brand on the return type is lost, and the census
counts that separately as the uncovered facet (branded type positions:
`Number` 112, `Int` 67).

Rejected: counting `.make` as a brand read. It would re-litigate the
case-brand ruling for numeric brands. The counts under that reading:

| Concept | Uncovered with `.make` | Covered without `.make` |
| --- | ---: | ---: |
| `Number` | 1,305 | 895 |
| `Int` | 392 | 162 |

- Upstream is data-last only, so the 13 data-first `withKeyDefaults(schema, v)`

It reads only the tagged-string member of today's input union, which is the
only form today's encoder writes.

Notes that bound the probe:

- `ISOStr` decodes through `S.Trim`, so the byte-identical replacement keeps
  `S.Trim` and `S.isNonEmpty` beside the parse check; the probe's padded
  input is trimmed the same way by both.
- `S.DateTimeUtcFromString` matches today's bytes only for `formatIso`
  output (the form both known writers produce, `JudgeContract.ts:44` and
  `Worktree.service.ts:883`). Stored files or fixtures written by hand or by
  older code can hold other accepted forms, which is why the string wire is
  the persisted choice.
- The HashSet probe compares encoded values. It does not re-derive the
  drizzle column type that `toPgTable` builds from the new field schema; the
  group E PR diffs the generated table and expects no migration. The
  converter note at `ActFrame.converters.ts:97-100` already warns that bare
  `S.HashSet` cannot survive a row trip, which the 0 / 3 row confirms.
- Upstream `Duration.Unit` is a type only (`Duration.d.ts:87`), so a string
  timeout keeps its unit list consumer-local.
- `"Factory"` is in the `@beep/data` timezone dataset and not a valid IANA
  zone on the probe runtime; with no consumer, nothing stored can hold it.

## Divergences from the audit

- `Unknown`: the audit target `S.UnknownFromJsonString` is internal at every
  sha the packet has used; the target is `S.fromJsonString(S.Unknown)`.
- Consumer counts: the census counts import-anchored files including tests
  (`Number` 394 files, 270 in production; `Int` 132, 91; `Unknown` 135, 62;
  `Opaque` 110, 105). The audit's direct-importer counts (361, 143, 128, 103)
  used a different attribution; neither is the PR closure, which each PR
  sizes with `graft callers --depth all` and a type check.
- JSDoc examples are part of the rewrite: `NonNegativeInt` appears on 943
  doc-comment lines in 128 files and `PosInt` on 201 in 29. Docgen compiles
  those examples.
- Timestamp persisted rows: the SPEC suggested `S.DateTimeUtcFromString` or
  `S.DateTimeUtcFromMillis`. Neither is byte-identical for `ISOStr` fields, and
  `ISOStr` is the only Timestamp member that crosses a boundary.
