# Reflection — spar-document-annotation-wire (2026-10-09, codex)

## Summary

The implementation adds immutable, attributed acquisition of four SPAR vocabularies,
a revision-scoped Md source address, a deterministic DOCO section fold, and a typed
OA/PROV annotation profile. The same synthetic fixture connects the fold output to
an annotation selector and tests encode/decode equivalence. The handoff records
terminal proof results and distinguishes local evidence from hosted readiness.

## Tooling experience

- **Worked:** the existing generator target boundary supports hash-pinned acquisition,
  deterministic term projection, identity registry output, and RDF provenance sidecars.
  Package verification gives separate audit and docgen outcomes.
- **Didn't:** root-level focused Vitest selected no package fixtures. Report-only coverage
  still exited zero, so a command exit alone was insufficient evidence.
- **Frustrating:** the heavy wrapper needs the user-session bus environment. It queues
  behind shared slots; captured package-audit output appears only after completion.
- **Wished existed:** a focused-test helper that resolves package cwd and rejects an empty
  test selection even when coverage is report-only.

## Implementation improvement opportunities

The fold deliberately addresses nodes within an immutable revision, rather than promising
ids across edits. A future parser position/id contract can replace the adapter if its
migration preserves revision selectors. The pinned TTL extractor is deliberately limited
to curated declared classes/properties; a future broader inventory should use an explicit
parser and retain hash and semantic-digest verification. Those changes are follow-ups,
not implicit reasoning in this profile.
