# Reflection — history-message-overlay (2026-11-06, claude)

## Summary

The goal shipped the no-rewrite answer to beep-effect's noisy pre-July
history. The reviewed July message map is tracked at `docs/history/` (940
rows). `beep history notes --check | --write | sync` projects it into
`refs/notes/history`, every new lane and cloud VM is configured to display it,
and a post-merge workflow is the only publisher. The exploration's July
cutover folder is archived. All four slices went into the final PR #2785. The
first publication and the check against origin's ref happen after it merges.

## Tooling experience

- **Worked:** `beep explore graduate --plan/--write` scaffolded the goal from
  the exploration cleanly. `beep goals decisions add` kept every decision a
  separate file with no append conflicts. `git fast-import` gave a fully
  deterministic notes commit (the same id from any prior ref state). The
  scoped vitest coverage run (`--coverage.include='src/commands/History/**'`)
  proved 100% quickly.
- **Didn't:** the knowledge gates under `lint policy` failed on a full `/tmp`,
  and turbo strips `TMPDIR`. Readiness monitors died three times on the shared
  GitHub rate limit.
- **Frustrating:** `goals decisions add --title "--write ..."` parses a title
  that starts with `--` as a flag and prints help with no error. Inherited reds
  from #2777, #2780 and #2799 hit this lane in sequence. One (`#2807`) had to be
  fixed on main mid-goal.
- **Wished existed:** a one-shot "is this red inherited" command that runs the
  failing gate on `origin/main` in a throwaway checkout. I did it by hand in a
  second lane.

## Implementation improvement opportunities

- `Git.replaceNotes` still re-checks name and email for `<`, `>` and newlines
  at runtime. Now that `GitIdentEmail` encodes the email rule, a matching
  `GitIdentName` would let that check live entirely in the schema.
- `beep history notes sync` could report when `notes.displayRef` already lists
  other refs, so a user who configured `refs/notes/*` sees the overlap.

## Goal & prompt critique

- The SPEC's acceptance list mixes in-PR and post-merge criteria. Proposed
  edit: move "The post-merge workflow published `refs/notes/history` to origin"
  and the `--check` against origin's ref under a "Post-merge acceptance"
  heading that the adoption PR verifies.
- The brief's canonical note body ("value + `\n`") was wrong for 939 of 940
  rows, which already ended in a newline. Specifying the intent instead
  ("byte-identical to what `git notes add -m` stores") would have avoided the
  mid-slice correction.

## TODOs worth codifying

- Forward `TMPDIR` through turbo for the knowledge gates, or keep their
  archives under the repo cache.
- Make the readiness monitor rate-limit aware.
- Document the external-protocol email schema pattern next to
  `@beep/schema` `Email`.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Attribute a red before acknowledging it, and re-check
  the attribution when someone else touched the tree. I first acknowledged the
  repo-cli audit row as "did not reproduce" because my rerun passed after the
  child had already regenerated the policy fingerprint; the failure was
  introduced, and the row was re-acknowledged against the fix commit.
- **MEDIUM — Best practice:** A schema-first finding on a protocol field is a
  prompt to write a precise local schema, not to reach for the closest shared
  one. The redacted `Email` would have broken fast-import.
- **LOW — Consideration:** Deterministic projections (fixed identity, fixed
  time, parentless commit) make "publish" idempotent, so the workflow can
  force-push safely and an unchanged map is a no-op.
