Slice 7 lands PERIL-09 (ruling D12) on `feat/local-proof-review-window-anchor`. A push that only merges the synchronized base into the pull request keeps the review-window anchor where it was when #3130's head-move classifier proves the PR's own patch unchanged: the new head is one two-parent commit whose first parent is the old head and whose push row moved the branch from it, the merged commit is on `base.sha`, the pushed tree is git's clean automatic merge, and the three-dot patch has the same identity before and after. `ReviewWindow.ts` walks the anchor back across every such merge to the first push that changed the patch, so the monitor and its inbox rows, `yeet status --remote`, `yeet merge-gate`, `yeet gate-table` and the REST gate (`yeet gh pr status`) all read one anchor; a carried window prints `carried across N base merge(s) from <sha>`. A conflict resolution, an edit inside the merge, a base change next to a PR hunk, a force push, a shallow history, a failed read and any unknown verdict re-arm. The window length stays 20 minutes. The AGENTS.md mergeable definition, the yeet skill (`references/merge-loop.md`) and the orchestrate skill state the rule in the same change. Decision files `peril-09-base-merge-proof-on-head-move-classifier`, `peril-09-merge-probe-gates-github-reads` and `peril-09-conservative-carry-limits` record the design.

Gate evidence: `test/yeet-review-window-base-merge.test.ts` (21 cases, Node and Bun, no checkout, no network, TestClock) replays git 2.56.1 output recorded from a scratch repository (`test/support/YeetBaseMergeReplay.ts`) through the real classifier over `Git.layerTest` and a scripted spawner, and recorded GitHub reads through the real REST client. Clean merge keeps (the window elapses from the PR's earlier push); conflict touching PR lines re-arms; unknown identity re-arms (shallow history, a failed activity read, a push that did not move the branch from the merge's first parent, a force-pushed merge). The suite also covers the edited merge, the moved hunk context, a base that absorbed the whole patch, a merged commit off the base, a two-merge chain, a carried root without a check suite, the read gate that spends no GitHub call on an elapsed window or a plain commit, the carry schema's legacy decode, and the REST gate and gh-login status read agreeing on the anchor. Mutating the carry to accept every merge fails four of its cases. The existing review-window, head-move, merge-gate, ready-gate, gate-table and monitor suites pass unchanged apart from the carry record's new `merges: 0`.
