`readyMonitorArgvKey` (`ProofJob.ts`) is the reuse key for `monitor --until-ready` jobs. It starts from the words the job replays (`stripProofJobSubmitFlags` already drops `--detach` and `--job-max-runtime`), drops `--json` and `--summary` (output only; the until-ready loop reads neither) and `--poll-interval` (how often the loop reads, not what it decides), reads `--flag=value` as `--flag value`, and sorts the entries. Every other flag stays with its value, including one the list does not know, so a future requirement flag keys apart without a code change. A live job is reused only when its key equals the request's. A stricter request (an extra or different flag, such as a longer `--settle-timeout`) submits a new job, and so does a looser one: handing back a stricter job could hold the caller's `job wait` on a requirement it never asked for. Publish now keys its reuse the same way, on `MONITOR_READY_SUBMIT_ARGV` (`Planner.ts`), so it no longer hands back a monitor an agent started with other readiness flags; before, any live monitor on the pull request was reused. A job's runtime ceiling is not part of the key. Rejected: subset matching (a stricter job satisfies a looser request); keeping publish's any-monitor rule (one rule for both paths, and a monitor with another `--state-root` or settle timeout reports somewhere else or on another schedule); keying on the raw argv (publish's `--json` would never match an agent's plain `--detach`).
