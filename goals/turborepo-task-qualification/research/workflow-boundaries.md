# Workflow and action boundaries

Observed 2026-09-09. The [source snapshot](./workflow-sources.json) retains all
nine local workflows and the composite setup action, including complete
conditions, environments, inputs, matrices, permissions, shell bodies and
action references. Its 28 job definitions and 171 step definitions are source
templates, not expanded jobs or executions. The referenced remote action code,
resolved reusable-workflow revision and deployed runner state remain separate
evidence boundaries.

The [recipe](./refresh-workflow-sources.ts) uses `@beep/schema/Yaml`, strict
UTF-8 decoding and SHA-256 of original source bytes. It preserves complete
parsed documents rather than the version resolver's smaller Node-only model.
The output regenerated byte-identically, and its paths match the current
workflow/action inventory. Reproduce from the checkout root:

```sh
env -i PATH="$PATH" HOME=/nonexistent \
  bun --no-env-file goals/turborepo-task-qualification/research/refresh-workflow-sources.ts
```

## Execution and reuse boundaries

| Source boundary | Inputs and effects that the census must retain |
| --- | --- |
| Composite setup: baked image | Reads checkout lockfile/Bun pins, image marker files, installed binary/archive hashes, owner/mode bits and a Bunx symlink. It removes the inherited writable Bun store and restores the image archive only after the checks match; missing or mismatched markers select ordinary setup. This is provisioning and archive restoration, not task-result proof. |
| Composite setup: ordinary install | Installs pinned Bun and optionally Node, restores the Bun dependency archive, and runs `bun install --frozen-lockfile`. Network, package-store state, lifecycle scripts and generated dependency files are inputs/effects outside a task's output comparison. Timing writes to GitHub environment/summary files are additional effects. |
| Composite setup: Actions cache | Restore/save keys include OS, fleet/shared runner partition, job/suffix and selected file hashes. Broad restore prefixes can return earlier archives. The Turbo fallback in this action is conditional on an incomplete token/team pair; action inputs separately control writes. Archive restoration does not prove any enclosed task artifact eligible. |
| Check and Heavy wrappers | Event, base Git ref, changed paths, matrix row, runner class and explicit environment select execution and affected/full modes. `ci-change-profile.sh` skips matrices only for a narrow set of convention-owned goal documents; research scripts and arbitrary goal data remain code-bearing changes. Fetches, disk cleanup, process-group cleanup, install steps, reports and cache saves remain separate from the lane body. |
| Post-lane fallback saves | Check/Heavy contain separate successful-push cache-save steps. Their conditions differ from the composite action's token/team fallback condition. Record the actual `if` and key at each call site rather than assume one global fallback rule. |
| Lint/Test Unit aggregate checks | The final jobs use `always()` and fail unless the shard job's aggregate result is success. They consume hosted job state; the empty package-task population of an aggregate is not proof that no computation occurs. |
| Secret Scanning and Security | Secret scanning selects a Git range, writes a base-reviewed scanner configuration/ignore file for PRs, and runs a digest-pinned container. Vulnerability/dependency-review actions read external verdicts. Their current hosted results retain existing proof ownership and cannot be replaced by a task-cache hit. |
| Cache Warm | A scheduled/manual job checks out main, selects a protected write environment, runs `cache warm`, and uploads receipts/run summaries. Main resolution, credentials, endpoint and upload are external inputs/effects. The source schedule and flags do not prove a warm run or signed artifact occurred. |
| Property Laws Nightly | Validates the requested run count and derives the seed from the workflow run ID. It invokes the full property lane and can open an issue or append a comment on failure. The seed/run count are semantic test inputs; issue updates are distinct remote writes. This job declares token/team fields without Check's complete API/mode expression, so its remaining effective posture must be resolved separately. |
| Official Data Sync | Reads authenticated datasets, writes generated source and reports, runs a named package subset, builds a PR body with a random delimiter, and can create/update a branch and PR. Network freshness and source/publication mutation preclude treating the whole workflow as a pure cached computation. Its focused checks remain separately assessable. |
| Storybook | Provisions Chromium/system dependencies, builds the static site, runs browser tests, checks the output file and uploads the tree. Browser/runtime/platform inputs and output/capture obligations remain separate from the archive-upload step. |
| Fleet Lane Probe | Manual inputs select the runner label and lane. It reports hardware identity and runs that lane with an explicit local-cache posture. These are actual-run measurements only when executed; source input defaults are not measured capacity or qualification evidence. |
| Fleet Shadow Check | Declares live runner, container, network, IMDS, IAM/STS, JIT-replay and access-denial probes. These require the fleet owner's authorized runtime and external verdicts. Their workflow name does not make them task-qualification shadow decisions, and this review executes none of them. |
| Desktop Release | Validates a release tag, uses signing/protected-environment inputs, builds platform bundles and sidecars, stages manifests/assets and checks target completeness before staging a draft release. Runtime/platform matrices, signatures, hosted artifact transfer and release mutation have distinct authorities. Pure build prerequisites require their own contracts; release readiness stays fresh. |

The setup action's displayed cache-key text omits the fleet/shared partition
present in its actual restore/save keys. Reconstruct archive identity from the
`with` blocks, not the shorter human-readable summary. This is an observed
source discrepancy, not a claim about a particular hosted execution.

The [checkpoint](./workflow-sources-checkpoint.json) binds the snapshot,
recipe, YAML decoder and directly reviewed change-profile script. No workflow
was dispatched, no action downloaded, no secret resolved and no runner or
remote resource modified. Integrating these records with operational census
keys and nested lane/handler records remains required. Remote action internals
and the exact hosted resolved revisions are not established by local YAML.
