# CSF-003: Extensible proof objects allow verified provenance forgery

- Severity: Informational
- Codex ID: `31937b1d88088191a99249e49086b3f7`
- Source commit: `72932dfe02fda598449c7b3ccc0fe9a3b2ac1efa`

- Status: remediated in PR #949; repository and hosted proof complete; Codex
  finding closed as `Already fixed`.

## Public Summary

Verified provenance values exposed forgeable structural state. A caller able
to recover the constructor could create or extend an object that passed the
verification guard without running source or anchor verification.

## Current-HEAD Validation

- Verdict: confirmed at the packet's initial HEAD.
- Disposition: `remediate`.
- Lane: `L3-provenance-capabilities`.
- Owner: provenance modeling.
- Rationale: authority was represented by inspectable object structure rather
  than private issuance membership.

## Remediation

Status: implemented with CSF-009. Module-private `WeakMap` registries now hold
immutable source and anchor snapshots. Only verification functions issue
members; guards require registry membership, instances are frozen, and getters
return copies.

- `packages/foundation/modeling/provenance/src/VerifiedTextAnchor.ts`
- `packages/foundation/modeling/provenance/test/VerifiedTextAnchor.test.ts`
