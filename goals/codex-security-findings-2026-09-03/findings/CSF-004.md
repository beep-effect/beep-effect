# CSF-004: PST output ceiling retains over\-limit data

- Severity: Informational
- Codex ID: `34129b90da2881919145836d5bb422c5`
- Source commit: `a09d001ed7f8d652fb5d9f6663e79a5acca17652`
- Owner: libpff PST export
- Status: remediated; repository proof in progress

## Public Summary

The PST output watchdog polled after writes had already reached the host and
retained over-limit trees on failure. Fast expansion or many small entries
could exceed the approved data and metadata budget before termination.

## Current-HEAD Validation

- Verdict: confirmed at the packet's initial HEAD.
- Disposition: `remediate`.
- Lane: `L4-sandbox-quotas`.
- Owner: libpff PST export.
- Rationale: recursive polling was advisory; it neither enforced a write-time
  quota nor prevented failure output from becoming durable host state.

## Remediation

Status: implemented. A configured ceiling now requires bubblewrap. The worker
writes to a size-limited tmpfs inside a bounded systemd user scope; entry count
and file types are checked after the writer stops. A tar stream enters a scoped
host staging directory, is revalidated, and only expected trees are atomically
published. Quota failures retain no export tree.
