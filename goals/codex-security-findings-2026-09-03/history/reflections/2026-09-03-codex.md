# Reflection — codex-security-findings-2026-09-03 (2026-09-03, codex)

## Summary

The packet is complete and retained. PR #949 merged all 12 shared-root security
remediations after 23 repository jobs passed, seven review threads were
resolved, and Greptile reported 5/5 with zero issues. Every captured Codex ID
was then manually closed as `Already fixed` and independently verified in the
Closed view.

## Tooling experience

- **Worked:** Stable Codex IDs, the ingested triage ledger, package-scoped
  coverage, and exact-head hosted checks made remediation and closure evidence
  attributable despite multiple repair pushes.
- **Didn't:** Aggregate test success did not imply changed-file coverage-ratchet
  success, and suite-level serialization did not constrain Effect-aware tests.
- **Frustrating:** Yeet could not emit strict closeout after GitHub auto-merged
  the PR, and the Codex sidebar briefly lagged authoritative detail state after
  a manual closure.
- **Wished existed:** A resumable packet closeout operation that consumes the
  captured allowlist, drives the signed-in browser UI, and writes only sanitized
  closure evidence.

## Implementation improvement opportunities

- Audit input enumeration, intermediate staging, aggregate expansion, output
  retention, and wire framing separately whenever adding a resource limit.
- Exercise every fail-closed arm, including late revalidation and injected I/O
  failure callbacks, before relying on the package ratchet.
- Give child-process pipeline tests a repeated-operation case so a pending
  transfer fiber remains observable after a successful destination exit.

## Goal & prompt critique

The packet correctly required post-merge scanner closure, but P9 described the
lifecycle flip as part of the same closeout PR state without distinguishing the
remediation PR from the inevitable post-merge evidence PR. The template should
name these as two publishable states: remediation merged, then scanner closure
recorded. The operator's instruction to use hosted CI as proof was clear and is
recorded as the bounded P5 exception instead of being presented as local proof.

## TODOs worth codifying

- Extend Yeet closeout to inspect an exact-head PR that auto-merged moments
  before the command ran.
- Add a packet-aware browser closeout helper that refuses IDs outside the
  captured allowlist and re-audits the Closed view before producing a ledger.
- Make stale-base overlap analysis stream or bound its path set separately from
  generic command-output capture.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Security bounds must cover work performed before the
  final count or byte check; otherwise an attacker can exhaust resources before
  rejection.
- **HIGH — Best practice:** A green aggregate table is not coverage proof;
  inspect every changed-file ratchet row for each touched package.
- **HIGH — Best practice:** Scanner closure proof is an exact-ID detail audit,
  not a submission count or transient list total.
- **MEDIUM — Consideration:** Keep server-side auto-merge in mind when a
  post-success tool still needs an open-PR state to emit its receipt.
