# Reflection — epistemic-bitemporal-edge-core (2026-07-25, claude)

## Summary

The packet shipped end-to-end in one session on top of a P0 spike that had
already de-risked every storage decision. The Postgres bitemporal claim/edge
authority core landed exactly on the ratified design: schema-first domain
(LogicalEdgeIdentity digest, bounded EdgeEndpoint union, EdgeVersion with
half-open BIGINT-millis axes, ClaimDisposition), one-liner table projections
with mechanical DDL-parity tests, typed EdgeAuthority/ClaimDisposition ports
with a required-`validFrom` command contract, a transactional repository whose
supersession is one READ COMMITTED FOR UPDATE close-and-insert, the
hand-authored btree_gist migration registered three-place plus manifest, and
`resolveClaimGateOutcome` closing the rejected-verdict no-op by composition
with shared `ClaimLifecycle` untouched. Verification went beyond the spike:
real-Postgres races (4/4, six consecutive runs) found and fixed a genuine
error-mapping gap, and the restart proof reads history off disk with no
re-migration. Provenance duties (notices, vendored donor LICENSE bytes, three
derivation headers) and the Graphiti retirement doctrine record landed in the
same PR. Verdict: the P0-gate-then-execute structure worked; the slice needed
zero design reversals, only refinements the tests themselves surfaced.

## Tooling experience

- **Worked:** the P0→P1 handoff as an execution contract; `beep yeet
  repair`/`verify` failure packets with named repair commands; the
  AcceptedProofManifest byte-equality proof (rejected the spike's misplaced
  files in CI, accepted hand-authored + registered files first try); the new
  test-utils `inProcess.extensions` seam; `S.toArbitrary` with annotated
  arbitraries (Sha256Hex generated cheaply); five-lane agent fan-out over an
  on-disk design contract.
- **Didn't:** vitest as a type gate (it isn't one — two real type errors
  survived green runs); `changeset status --since` on untracked changesets;
  piped exit codes around yeet.
- **Frustrating:** whole-repo generated artifacts (schema-catalog,
  jsdoc-inventory) stale at HEAD, so any honest regeneration drowns a branch
  in unrelated churn; the db-admin test-typecheck blind spot surviving even
  after three sibling packages fixed theirs.
- **Wished existed:** a per-package "test-typecheck coverage" lint; a
  changed-files-scoped jsdoc-inventory refresh.

## Implementation improvement opportunities

- `epistemic_edge_version.public_id` is derived
  (`..._a<logicalKey>v<version>`), inheriting uniqueness from the
  logical-version constraint — fine for the authority core, but revisit if
  public ids ever need to be opaque handles.
- `EpistemicServerLive` keeps `RIn = never` with in-memory dispositions while
  `EpistemicServerDrizzleLive` adds persistence — inverted naming relative to
  the workspace slice; harmonize when a third consumer appears.
- Head disambiguation (prefer both-axes-open, fall back to highest version) is
  proven by tests 4 and 8 but deserves a named fixture when the
  contradiction-triage goal builds on supersession.
- entity/observation endpoint refs stay opaque until those tables exist
  (handoff item 5) — the FK columns are a mechanical follow-up.

## Goal and prompt critique

  packet was dead weight.
- The single misleading sentence was handoff item 10's codegen phrasing (see

- The SPEC's verbatim Decision 7 quote earned its length: three separate lanes

## Lessons

- **HIGH — Critical:** PGlite-only concurrency proofs are structurally unable
  to order-check DB backstops; the real-Postgres race lane found a
  contract-level mapping bug (`logical_version_unique` → conflict, not
  malformed-write) that every cheaper lane missed. Budget the container lane
  for any concurrency contract.
- **HIGH — Critical:** a green test run is not a type gate; packages without
  `tsconfig.test.json` coverage ship latent type errors to the repo gate.
- **MEDIUM — Best practice:** pin every name (tables, columns, constraints,
  error statics) in an on-disk design contract before fanning out lanes;
  the only cross-lane API breakage this goal (positional resolver factory)
  came from the one surface the contract had left as prose.
- **MEDIUM — Best practice:** when a schema gains a cross-field check, audit
  its `S.toArbitrary` consumers and its filter `message` annotations in the
  same commit.
- **LOW — Consideration:** fallow's CRAP metric flags exhaustive column-walk
  test arrows whose branch count equals the table width; the sanctioned
  inline suppression with a rationale reads better than restructuring
  assertions into helpers that hide what is asserted.
