# Reflection — scripts-to-beep-cli (2026-11-07, claude)

## Summary

Retired `./scripts` into beep commands across three PRs plus one main unblocker. PR 1
(#2860) replaced the leaf scripts with `beep toolchain`, `beep git merge-driver`,
`beep github app mint`, repo-configs policy data, the changeset formatter, systemd unit
rendering and a vitest port of the Python gitleaks test, and added a slim compiled
`bin-ci` entry plus a main-only release publisher. #2902 then gave its ten new files
in-process coverage (ep40). PR 2 (#2906) pins the published binary, switches the hosted
workflows to `beep ci ...`, ports the #2850 cache-pilot scripts, folds `fetch.sh` into
`bootstrap.sh` and adds the `tracked-shell-allowlist` law. Because `check.yml` calls
`heavy.yml@main`, #2906 had to keep the seven scripts main's heavy.yml still ran; PR 3
(#2921) deletes them once #2906's heavy.yml is the `@main` copy. Verdict: the design held;
most of the elapsed time went to inherited main reds, merge-driven baseline churn and
an exhausted workstation, not to the code.

## Tooling experience

- **Worked:** Effect CLI command topology and lazy dispatch made new groups cheap;
  `bun build --compile` on a slim entry; parity fixtures (shell vs TS over synthetic
  repos) proved byte-identical change-profile output before deletion; `yeet reply`,
  `yeet inbox ack` and `final-check --skip` kept the loop auditable.
- **Didn't:** the full CLI cannot be compiled (eager DuckDB); local full proofs were
  repeatedly SIGKILLed by earlyoom; GitHub REST/GraphQL quotas shared across sessions
  ran out several times and stalled monitors.
- **Frustrating:** four cache-baseline re-records for one PR; a main-wide cache-policy
  red from #2856 that looked like this PR's fault until a pristine-main probe proved
  otherwise; heavy runners queued for over two hours at the end.
- **Wished existed:** a baseline rebase command, a cheap "is this red already on main"
  query, and a runner-queue readout in `yeet monitor`.

## Implementation improvement opportunities

- Guard `bin-ci.ts` bundle contents with a test (see findings).
- `beep ci runner-resources` exits 130 on SIGTERM where the shell exited 143; callers
  only test non-zero, but aligning the code would remove a parity footnote.
- The pin in `.github/actions/fetch-beep-ci/action.yml` is manual; a bot PR that bumps
  tag and sha256 after each `beep-ci-binary.yml` release would remove the hand step.

## Goal & prompt critique

- Add to GOAL.md: "Two PRs: PR 1 lands commands and the publisher; PR 2 pins the first
  published binary and switches workflows." The supply-chain constraint forces it.
- Replace the SPEC's "no wildcards, hooks plus bootstrap only" with the decided
  allowlist (hooks, `goals/`, `explorations/`, `infra/`, bootstrap, two fixtures);
  as written it would fail on main.
- Name `beep quality cache-policy` and `knowledge semantic-delta` in the Verification
  Matrix; both were hosted reds this packet caused.

## Lessons (confidence-tiered)

- **HIGH — Critical:** after any main merge that conflicts on
  `standards/cache-qualification-baseline.json`, take main's side and re-stamp only your
  own subjects before pushing — a merge that keeps main's file silently drops your
  re-record and reds `quality:cache-policy`.
- **HIGH — Critical:** before blaming your PR for a repo-wide gate red, run the gate on a
  pristine `origin/main` worktree and bisect; #2856's drift was 1683 findings on main.
- **MEDIUM — Best practice:** compile CI binaries from a slim entry and pin them by
  checksum from a main release; never build the gating binary from the PR head.
- **MEDIUM — Best practice:** when deleting files, rewrite every live packet doc that
  names them in the same PR, and recheck GOAL.md length afterwards.
- **LOW — Consideration:** under swap exhaustion, skip memory-heavy `final-check` gates
  with the measured reason instead of retrying; hosted CI is the proof.
