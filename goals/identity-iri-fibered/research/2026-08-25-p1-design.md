# P1 design — discrete Fibered, exact IdentityRegistry, SHACL projection (2026-08-25)

Design authority order: `explorations/identity-as-iri/assets/identity-iri-fibration-handoff.md` §6 (D8)
→ `explorations/identity-as-iri/DECISIONS.md` (2026-07-02 packaging seam, registry name, 2026-07-31
split surface) → `SPEC.md`. Everything below is the discrete case only: base = a finite set of
string literals, fibers = one schema per point, section = one schema-validated record per point.
No version fibers, no cartesian lifts, no 2-cells, no fuzzy retrieval, no production store.

Order of work is schema → `Context.Service` contract → implementation, per repo law.

## 1. `Fibered` kit — `@beep/identity/src/Fibered.ts` (effect-only)

`@beep/identity` depends on `effect` only. The kit therefore uses `S.Literals` (not `LiteralKit`),
plain `S.TaggedError`, and `effect/HashMap` for its case map. Validate every API against
`.repos/effect/packages/effect/src/Schema.ts` (effect `4.0.0-rc.111`).

### 1.1 Schemas / types

```ts
// B is the discrete base: a finite union of string literals carried by an S.Literals schema.
export interface FiberedInput<
  const Points extends ReadonlyArray<string>,
  Fibers extends { readonly [K in Points[number]]: S.Top },
  Section extends S.Top
> {
  readonly base: S.Literals<Points>                    // discrete base B; `.literals` are the points
  readonly fibers: Fibers                              // F : B → Schema (varies per point)
  readonly section: {
    readonly schema: Section                           // M's codomain — validated once per point
    readonly values: { readonly [K in Points[number]]: Section["Encoded"] }  // total by type
  }
  readonly annotationKey?: string                      // default "fiberedSection"
  readonly member?: <K extends Points[number]>(point: K, fiber: Fibers[K]) => S.Top
  //   default thin member: S.Struct({ _tag: S.tag(point), value: fiber })
  //   (JSDoc migration may supply JSDocTagDefinition.mapFields(...) here ONLY if the golden
  //    harness proves the default differs byte-for-byte — prefer no hook)
}

export interface Fibered<Points, Fibers, Section> {
  readonly points: Points                              // base points in declaration order
  readonly base: S.Literals<Points>
  readonly members: { readonly [K in Points[number]]: Member<K> }   // O(1) case map, built once
  readonly member: <K extends Points[number]>(point: K) => Member<K>
  readonly union: S.Union<...>                         // Σ(t) F(t), tagged union on "_tag"
  readonly meta: <K extends Points[number]>(point: K) => Section["Type"]        // M(t), decoded once
  readonly fiberOf: (value: { readonly _tag: Points[number] }) => Section["Type"] // display map ∘ section
  readonly project: <K extends Points[number], Keys extends keyof Section["Type"]>(
    point: K, keys: ReadonlyArray<Keys>
  ) => Pick<Section["Type"], Keys>                     // task-indexed sub-section (policy = key list)
  readonly pullback: <const Sub extends ReadonlyArray<Points[number]>>(points: Sub) => Fibered<Sub, ...>
  //   change of base along the inclusion Sub ⊆ Points; fibers and section come along; members are
  //   reused by reference (no re-decode), base = S.Literals(points)
}
```

Member schema = `S.Struct({ _tag: S.tag(point), value: fiber }).annotate({ [annotationKey]: meta(point) })`.
Section values are decoded with `section.schema` at construction; a failure is a programmer error and
throws (`Result.getOrThrow(S.decodeResult(...))`) exactly like today's `JSDocTagDefinition.make`.
Section totality is enforced at the type level (`values` keyed by every point) and at runtime the
constructor iterates `base.literals`, so a missing point is a compile error and a decode error.

`annotationKey` is a string key on `S.Annotations.Annotations` — the JSDoc consumer keeps
`"jsDocTagMetadata"` and its existing module augmentation; the kit adds a `fiberedSection` augmentation
for the default key only.

### 1.2 Laws (tests in `packages/foundation/modeling/identity/test/Fibered.test.ts`)

- Totality: for every point `p`, `member(p)` and `meta(p)` are defined; `points` equals `base.literals`.
- Section: `meta(p)` deep-equals `S.decodeSync(section.schema)(section.values[p])`, and is the same
  reference on repeated calls (decoded once).
- Display map: for `v = S.decodeSync(member(p))({ _tag: p, value })`, `fiberOf(v) === meta(p)`.
- Union: `S.decodeUnknownSync(union)` accepts exactly the members' encoded forms; wrong `_tag` fails.
- Project: `project(p, keys)` equals `Pick` of `meta(p)`; `project(p, [])` is `{}`.
- Pullback (property-based over random subsets of the points, `@effect/vitest` `it.prop` or fast-check
  via the schema's arbitrary): `pullback(points)` behaves identically to the original;
  `pullback(sub).member(p) === member(p)` by reference; `pullback(sub).pullback(subsub)` equals
  `pullback(subsub)` (restriction composes); `pullback(sub).points` preserves declaration order.
- Type-level: `expectTypeOf`-style assertions that `member("x")` is not assignable to `member("y")`,
  `pullback(["x"]).meta` rejects `"y"`, and `section.values` missing a point is a compile error
  (`@ts-expect-error`).

## 2. `IdentityRegistry` — `@beep/identity/src/IdentityRegistry.ts` (effect-only)

Name locked by DECISIONS 2026-07-02. Exact dereference in all three encodings; no discovery.

### 2.1 Schemas

```ts
export const IdentityRef = S.Union([
  S.Struct({ _tag: S.tag("identity"), value: S.String }),  // "@beep/<pkg>/<path>"
  S.Struct({ _tag: S.tag("iri"),      value: S.String }),  // "https://ns.beep.sh/<pkg>/<path>"
  S.Struct({ _tag: S.tag("curie"),    value: S.String }),  // "beep:<pkg>/<path>"
]).pipe(S.toTaggedUnion("_tag"))
export type IdentityRef = typeof IdentityRef.Type

export class IdentityEntry extends S.Class<IdentityEntry>("@beep/identity/IdentityRegistry/IdentityEntry")({
  identity: S.String,                       // canonical identifier — the base point
  iri:      S.String,                       // literal projection from the bound composer
  curie:    S.String,                       // literal projection from the bound composer
  fibers:   S.Record(S.String, S.String),   // v1 fiber parts: named string sections (see §5)
}) {}

export class IdentityNotFoundError extends S.TaggedError<IdentityNotFoundError>(
  "@beep/identity/IdentityRegistry/IdentityNotFoundError")("IdentityNotFoundError", { ref: IdentityRef }) {}
export class IdentityRegistryConflictError extends S.TaggedError<IdentityRegistryConflictError>(
  "@beep/identity/IdentityRegistry/IdentityRegistryConflictError")("IdentityRegistryConflictError",
  { encoding: S.Literals(["identity", "iri", "curie"]), key: S.String }) {}
```

`IdentityEntry.fromComposer(composer, fibers)` builds an entry from a **bound** composer's
`identifier` / `iri` / `curie` literal projections (see `IdentityComposer` in `Id.ts`; the fold requires
a bound composer at its entrypoint — do the same, and make the unbound case a type error, not a
runtime `undefined`). No string interpolation anywhere: IRIs and CURIEs are read from the composer.

### 2.2 Service contract

```ts
export interface IdentityRegistryShape {
  readonly resolve: (ref: IdentityRef) => Effect.Effect<IdentityEntry, IdentityNotFoundError>
}
export class IdentityRegistry extends Context.Service<IdentityRegistry, IdentityRegistryShape>()(
  "@beep/identity/IdentityRegistry/IdentityRegistry") {}
```

### 2.3 Local layer

`IdentityRegistry.layerLocal(entries: ReadonlyArray<IdentityEntry>)` →
`Layer.Layer<IdentityRegistry, IdentityRegistryConflictError>`. Builds three `effect/HashMap`
indexes (identity → entry, iri → entry, curie → entry) once; duplicate keys in any index fail the layer
with `IdentityRegistryConflictError`. `resolve` is a single HashMap lookup on `ref._tag`; a miss is
`IdentityNotFoundError`. Never `Set`/`Map`; `Effect.fn`/`Effect.fnUntraced` for generator functions.

Tests (`test/IdentityRegistry.test.ts`): resolve by each encoding hits the same entry; unknown ref →
`IdentityNotFoundError` carrying the ref; duplicate identity/iri/curie → conflict error at layer
build; `fromComposer` matches `composer.identifier/iri/curie` literally; a `Fibered` section can be
flattened into `fibers` (bridging test: register an entry whose fibers are `project(p, keys)` values).

## 3. `JSDocTagDefinition.make` migration — `@beep/repo-utils` (byte-identical)

`make(_tag, meta)` keeps its exact signature and all 60+ call sites in `JSDoc/JSDoc.ts` untouched.
Its body becomes a single-point `Fibered`:

```ts
Fibered.make({
  base: S.Literals([_tag]),
  fibers: { [_tag]: TagValue.cases[_tag] },
  section: { schema: JSDocTagDefinition, values: { [_tag]: { _tag, ...meta } } },
  annotationKey: "jsDocTagMetadata",
}).member(_tag)
```

Proof harness, **written and green BEFORE the migration edit**, in
`packages/tooling/library/repo-utils/test/JSDocTagDefinition.golden.test.ts`:

1. A verbatim copy of today's `make` body as `legacyMake` inside the test.
2. For every member of the exported `JSDocTag` union (iterate `JSDocTag.members`, or the exported
   per-tag schemas) compute a fingerprint: `String(schema.ast)`, the encoded annotation payload
   `S.encodeSync(JSDocTagDefinition)(getJSDocTagMetadata(schema))`, the member field keys, and a
   decode→encode round trip of a sample value from `TagValue.cases[_tag]`'s arbitrary.
3. Assert fingerprint(`make(tag, meta)`) deep-equals fingerprint(`legacyMake(tag, meta)`) for at least
   the tags `param`, `returns`, `deprecated`, `example`, plus the whole-union fingerprint snapshot
   stored as a committed golden JSON under `test/__golden__/jsdoc-tag-fingerprints.json` generated from
   the pre-migration code and NOT regenerated afterwards.

If the default thin member differs from `JSDocTagDefinition.mapFields(...)` in any fingerprint field,
pass the `member` hook from §1.1 — the golden must pass unchanged either way.

## 4. `@beep/semantic-web` — SHACL projection + dataset-backed test/dev Layer

Layer direction: semantic-web depends on `@beep/identity`, `@beep/rdf`, `@beep/schema`. It may NOT
depend on `@beep/epistemic-*`. Target contract: `src/services/shacl-validation.ts` (post-move).

### 4.1 Schemas — `src/identity/IdentityRdfBinding.ts`

```ts
export class IdentityRdfBinding extends S.Class<IdentityRdfBinding>($I`IdentityRdfBinding`)({
  identifierPath: NamedNode,                 // predicate carrying entry.identity as a plain literal
  curiePath:      NamedNode,                 // predicate carrying entry.curie as a plain literal
  fiberPaths:     S.Record(S.String, NamedNode),  // fiber key → predicate; EXPLICIT, never derived
}) {}
export const DefaultIdentityRdfBinding: IdentityRdfBinding   // identifier/curie predicates minted from
//   $SemanticWebId.create("identity/...").iri literal projections (no interpolation); fiberPaths: {}
export class IdentityFiberPathError extends S.TaggedError<...>(...)("IdentityFiberPathError", { fiber: S.String }) {}
export class IdentityDatasetDecodeError extends S.TaggedError<...>(...)("IdentityDatasetDecodeError", { subject: S.String, message: S.String }) {}
```

Subject of every entry = `NamedNode(entry.iri)`. Codec (pure, exact, round-trip tested):
`entriesToDataset(binding)(entries): Effect<Dataset, IdentityFiberPathError>` and
`datasetToEntries(binding)(dataset): Effect<ReadonlyArray<IdentityEntry>, IdentityDatasetDecodeError>`.
A fiber key with no `fiberPaths` entry is `IdentityFiberPathError` — projection never invents IRIs.

### 4.2 Layers — `src/identity/IdentityRegistryDataset.ts`

`layerDataset(binding, dataset)` → `Layer<IdentityRegistry, IdentityDatasetDecodeError | IdentityRegistryConflictError>`
= decode entries, then delegate to `IdentityRegistry.layerLocal`. This is the dev/test store-backed
example; no Oxigraph/SPARQL store commitment (that stays behind `SparqlQueryService`, untouched).

### 4.3 SHACL projection — `src/identity/IdentityShaclProjection.ts`

```ts
export class IdentityShapePolicy extends S.Class<IdentityShapePolicy>($I`IdentityShapePolicy`)({
  requiredFibers: S.Array(S.String),         // policy as data: which fiber parts must be present
}) {}
export const projectShapes = (binding, policy) =>
  (entries: ReadonlyArray<IdentityEntry>): Effect<ReadonlyArray<ShaclNodeShape>, IdentityFiberPathError>
```

Per entry: `ShaclNodeShape { targetNode: NamedNode(entry.iri), properties: [
  { path: identifierPath, minCount 1, maxCount 1, hasValue: Literal(entry.identity) },
  { path: curiePath,      minCount 1, maxCount 1, hasValue: Literal(entry.curie) },
  ...requiredFibers.map(k => { path: fiberPaths[k], minCount 1 }) ] }`.
Every field uses the contract's own schemas (`ShaclNodeShape.make`, `ShaclPropertyShape.make`); the
result is placed straight into `ShaclValidationRequest.shapes`.

### 4.4 Proof

- semantic-web tests: codec round trip (entries → dataset → entries deep-equal, property-based over
  generated entries); `layerDataset` resolves all three encodings; `projectShapes` output decodes with
  `ShaclValidationRequest`; a mock `ShaclValidationService` receives the projected shapes.
- End-to-end in `packages/epistemic/server/test/` (epistemic-server already depends on semantic-web and
  hosts `BoundedShaclValidatorLive`): validate `entriesToDataset(entries)` against `projectShapes(entries)`
  → `conforms: true`; remove one required fiber quad → a `violation` on that path. If the bounded
  validator cannot evaluate `targetNode`+`hasValue` literals, record the exact gap in the lane report
  and keep the mock-service proof; do not widen the validator in this goal.

## 5. Deliberate narrowings (record in the reflection)

- Registry fibers are `Record<string, string>` in v1 so the RDF codec is exact with plain literals.
  Widening to `S.Json` fiber parts (rdf:JSON literals) is a follow-up, not this slice.
- One `IdentityRegistry` method (`resolve`); enumeration/search surfaces live elsewhere by SPEC.
- `pullback` restricts along subset inclusions only (the discrete change of base).
