# Reflection — harness-hygiene-mechanical (2026-07-14, claude)

## Summary

All three outcomes shipped mechanically and evidence-cited: the four
zero-signal ponytail skills are deleted through the skill registry (entries,
lock, codex config, dirs), AGENTS.md dropped from 5,840 to 5,354 bytes with
volatile memory/Graphiti operational state evicted to the new
`standards/memory-architecture/06-agent-memory-operations.md` runbook, and the
three agent-requested laws (same-PR packet-state flips, verification-failure
attribution, durable on-disk handoffs) landed in one batched cache-prefix
edit. Full verification matrix green on first run.

## Tooling experience

- **Worked:** Two codex lanes (gpt-5.6-sol, medium effort) with one on-disk
  deliverable each — the P0 research artifact
  (`research/2026-07-14-eviction-and-laws.md`) answered every design question
  (destination file, byte budget, updater prune semantics, reference
  classification) accurately; the P1 lane applied the pinned edits
  byte-exactly. The skills updater's design (installed dirs drive the lock and
  codex config) made pruning automatic once dirs and registry entries were
  removed.
- **Didn't:** The codex sandbox could not run the network-dependent skills
  updater and could not write `.codex/config.toml`; the main session had to
  rerun the sync and verify by fresh reads.
- **Frustrating:** rg skipping hidden directories by default nearly produced a
  false-clean reference scan; the agent-config surface of this repo is almost
  entirely dot-directories.
- **Wished existed:** A prune-only updater mode; skill deletion should not
  imply refreshing every surviving remote skill from upstream HEAD.

## Implementation improvement opportunities

- Prune-only mode for `bun run beep skills update` (see findings).
- The stop-condition language for skill-deletion packets should name the
  provisioning-surface vs consumer-reference distinction explicitly.

## Goal & prompt critique

The packet was well-formed: GOAL/SPEC/PLAN agreed, evidence was pre-staged
with reflection counts and H4/H9 verdicts, and the byte-ceiling constraint
made the cache-prefix edit self-verifying. Two concrete edits would have made
it friction-free: (1) add `--hidden` to the SPEC verification-matrix rg
command; (2) qualify the "referenced by tooling" stop condition as
consumer-references-only, since the provisioning surfaces are necessarily part
of the change.

## TODOs worth codifying

- Prune-only updater flag (tracked in frontmatter todos).
- `--hidden` in reference-scan command templates for future SPECs.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Scan agent-config surfaces with `rg --hidden` — the
  default skip of dot-directories silently drops most of the harness surface
  (.claude, .codex, .agents) and can false-pass a deletion's reference check.
- **MEDIUM — Best practice:** Treat codex-lane failures on network or
  protected-file operations as routing signals, not blockers: rerun the
  canonical command from the main session and verify with fresh reads instead
  of trusting lane self-reports.
- **LOW — Consideration:** Side effects of canonical sync commands (upstream
  drift-repair riding along in a deletion PR) are acceptable when small and
  documented in packet evidence; hand-splitting generated files to avoid them
  risks an inconsistent lock state.
