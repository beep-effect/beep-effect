# Reflection — ciops-ontology-pipeline (2026-10-06, claude)

## Summary

The packet took the CI operational ontology from a research exploration to a lab-backed pipeline: a frozen
fleet capture and ledgers (W3+W4), a byte-deterministic S7 projection with differential replay and a typed
CQ-009 verdict (W5–W7, #1490, #1524), auditor run 4 ratified at its pin with eight accepts and six
withdrawals under a capped review loop, and a KPI reading under a written law (W8, #1532) beside a
hand-written verdict (W9, this PR). The reading is a lawful failing report: 165 of 473 admission requests
in the window wait beyond the declared 120000 ms bound, TierCiMergeGreen is unmeasured, and the
M1-replica agrees with time-to-certainty's M1 to the millisecond on P50 and P95. Every ruling was made
under the 2026-10-06 autonomy charter and listed for the operator's asynchronous review.

## Tooling experience

- **Worked:** the Workflow seat pattern (brief on disk, structured result, orchestrator commits);
  `chain_digest.py` and sha256 pins for every input; the auditor engine's gate before and after the
  scribe; `yeet publish` once the cache baseline was re-recorded; `beep session note` as the hand-off
  ledger across a session restart; the schema-first order (schema, service, fold) that let the contract
  type-check and land a day before the fold.
- **Didn't:** a Workflow seat does not survive the orchestrator's session restart and leaves no result
  record; `yeet ready` gates on green checks, so the content-final flip the operator ruled is `gh pr
  ready`; `git stash pop` is blocked by a permission rule, so a stash is restored with a three-way patch.
- **Frustrating:** every bun command through `zsh -ic` with gitstatus and zle noise; `beep-heavy` queue
  waits on sub-minute checks; a `dual` wrapper to export a two-argument helper; commitlint's 100-column
  body limit discovered at commit time; the yeet PR title from the oldest commit.
- **Wished existed:** a scoped effect-vitest inventory write; a `beep cache baseline` request printed by
  the gate that fails; a lane-side friction ledger append the lane is allowed to make; a progress file
  convention for long seats.

## Implementation improvement opportunities

  (the seat-request clock would have been caught at the contract lane).
- A compact encoding and a reproducibility class on committed generated tables (the adoption table).
- Survivorship by reason once a pin carries compaction receipts; the contract has one field today.
- The run-4 follow-ups already tracked in the exploration's `research/run4-lanes/p3-run4-report.md`
  (foundational minors, lane-execution wording, the S5 gate gap for `later_ratifications`, the run-3
  projection gap for rat-067/068 flags).

## Goal & prompt critique

- The completion gate pins the law at v1.1 and asks for an operator-ratified window; both had to be
  read through decision-log entries. Point gates at "the law's current version" and "the ratifying
  authority named in the decision log".
- The W8 lane brief limited edits to listed files, which kept it from filing receipts; name the ledger and
  allow appends. It also left the output encoding open; name it.
- PLAN's sequencing line named one verdict PR; the launch sitting split it into PR-A and PR-B, which was
  right (one PR carrying the ETL, the verdict and the close would not have been reviewable). Write the
  split into the plan when the phase is planned, not when it opens.

## Lessons (confidence-tiered)

- **HIGH — Critical:** attribute a hosted red before claiming it — a fresh local run on the branch head
  against the `pull/<n>/merge` ref CI used; #1524's JSDoc ratchet red was inherited from main and was
  first called introduced.
- **HIGH — Critical:** a written measurement rule can be vacuous on the data it was written for; the
  first reading must say which rules fired, and a vacuous rule gets a ruling, never a silent zero.
- **MEDIUM — Best practice:** keep every seat's brief on disk and commit from the orchestrator; a seat
  that edits only, returns a structured result and never commits survives restarts in its files even
  when its result is lost.
- **MEDIUM — Best practice:** flip a PR ready at content-final with the 20-minute window, batch pushes
  per wave, and let the orchestrator merge at the gate; the P3 PRs landed with one push each, and PR-A
  needed a second wave for two reds its first hosted run found (a formatter touching a byte-exact
  generated file, and a design-system lint reading a JSON string in a test as a class site).
- **LOW — Consideration:** a 1 MB committed table is acceptable when it is data read by sha256, but say
  so in the PR and choose the encoding before the lane runs.
