Extends the declared-prune rule in 2026-11-17-absent-subject-skipped-present-strict.md, which stays in force with its present-strict, subject-keying and one-helper rules, and extends the ProductLeaves catalog that #3379 shipped with a second source of declarations. The review of #3379 showed that a skip keyed on absence turns a stale or misspelled name into a silent skip, and #3379 now skips only for subjects listed in @beep/repo-cli-kit/ProductLeaves whose directory is gone. A code catalog has a limit: a trimmed checkout or fork can drop only what that kept file lists, and it cannot add its own drops without editing a kept package. Agent call: a checkout may carry one optional tracked declaration at checkout-prune.jsonc under standards/. This repository ships none, so every assertion here stays as strict as #3379 left it. Its schema is CheckoutPruneDeclaration, in a new @beep/repo-cli-kit/CheckoutPrune module: { version: 1, prune: [CheckoutPruneEntry], keep: [CheckoutPruneEntry], owned: [CheckoutPruneEntry] }, where CheckoutPruneEntry is { path, why, packageName? }, and path is a repository-relative git :(glob) pathspec (** crosses segments, * does not). An entry resolves to a subject this way: a workspace subject is declared by an entry whose packageName names it, and that entry's path is the workspace's last-known directory, the one "its directory is gone" checks, just as ProductLeaves lists workspaces by name and directory; a packet subject is declared by an entry whose path matches its packet root; and a repository path outside every packet and workspace, normally an always-present subject, becomes a subject of its own when a prune or owned entry matches it: seam 1b adds a RepositoryPathSubject { path } variant to CheckoutSubject for it. A prune entry makes it pruned once the file is gone; an owned entry skips its upstream checks whether or not the file exists, as owned does everywhere. That last case is the one exception to the subject-keying rule, just as owned is the one exception to the present-strict rule. A prune entry names a path the checkout removed. An owned entry names a path the checkout replaced with its own content, so upstream checks of that path do not apply to it. A keep entry carves a path out of a broader prune or owned glob. A path is declared pruned when it matches a prune or owned entry and no keep entry. loadCheckoutInventory reads the declaration. A subject skips when it is in productLeaves, or declared pruned by a prune entry, and its directory is gone; or when it is declared pruned by an owned entry. A keep entry therefore protects a subject from both. Owned is the one exception to the present-strict rule: an owned subject skips although its directory exists, because the checkout replaced what upstream checks assert. An absent subject that is not declared still fails. A prune entry that matches a live path outside every keep entry is a finding, so a declaration cannot hide a live path; owned and keep entries match live paths by design. Each tolerant surface class gets these tests: absent and declared skips with the note; absent and undeclared fails; a live owned subject skips while the same path without an owned entry stays strict; a subject carved out by keep stays strict.
