# Reflection: research-library-routes (2026-11-07, claude)

## Summary

The library now acquires web, docs and registry sources natively through a new
`@beep/firecrawl` driver, downloads Box selections with one receipt per file, imports
VidBee and alphaXiv results, records hop-1 and hop-2 derivation edges at inventory,
and gates hop-2 acquisition on routed findings with per-domain caps. Live probes
verified the Firecrawl and Box routes, and October's imported web captures still
replay byte for byte.

## What went well

- Reusing the `firecrawl` method name kept native and imported captures under one
  `webResponseValid` contract with no validator change.
- Modelling the Box version id as the source revision made resume and new-version
  handling fall out of the existing acquire selection.
- The live Firecrawl probe exercised hop extraction on a real page (155 hop-2
  identities) and exposed a Markdown adjacent-link URL bug, fixed in this PR.

## What was hard

- Cheap gates were far stricter than tests and typecheck: complexity, schema-first,
  effect-vitest, span and schema catalogs, and the reviewed cache baseline each needed
  their own fix.
- The base moved under the branch twice; generated alias files conflicted and were
  regenerated rather than hand-merged.

## Next time

Run fallow and schema-first per module while writing, keep cache-baseline basis files
immutable, and probe credentials from a checkout that has the operator's `.env`.
