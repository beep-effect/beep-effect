ROUT-05 slice 2b (PLAN slice 11b), the producer slice 11 left open. `beep ci task-outcomes` (`packages/tooling/tool/cli/src/commands/Ci/CiTaskOutcomes.ts`) reads every Turbo run summary in the job's `.turbo/runs/` and writes one `task-outcomes/v1` record: the job's name as GitHub lists it and one `{task, outcome}` row (`HostedTaskOutcome`) per Turbo task. Exit code 0, a run or a cache replay, is `pass`; any other exit code is `fail`; a task with no exit code is `not-run`; a task Turbo wrote with `exitCode: null` (killed, or failed with no code) is `unknown`; a task several invocations list keeps `fail` over `pass` over `not-run`.

- Steps. Every lane job that runs Turbo gains two steps after its Turbo summary: `Record Turbo task outcomes` (`continue-on-error: true`, so it never decides the job) and `Upload Turbo task outcomes` (artifact `task-outcomes-<run>-<attempt>-<job>-<partition or lane>`, 30 days). The jobs are the verification-step anchor (Repo Sanity, Ecosystem Contracts, Codegen Drift; the job name comes from `BEEP_CI_LANE_NAME`), Labs, `Lint (<partition>)`, `Test Unit (<partition>)`, `Test Integration (<partition>)` and `Property Laws (<partition>)`, plus `shard-overflow.yml`'s Test Unit job, which `ci-shard-overflow.test.ts` holds identical to the hosted shard. Heavy lanes run from `heavy.yml@main` and are not touched, so their failed jobs keep `tasks` absent. No job name, `needs`, `runs-on`, job `if`, matrix or required context changes.
- Retention. Thirty days rather than the seven of the other per-run artifacts, because the corpus is captured by hand, by date range, days after the runs.
- Capture. For a finished run with a failed job, the capture lists the run's artifacts once and downloads each unexpired `task-outcomes-<run>-<attempt>-` archive (fflate unzips it), then fills `tasks` on the failed jobs whose name equals a record's job, or starts with `<job> / ` (a job reached through a reusable workflow). Only failed jobs keep tasks, as only they keep steps. A run with no failed job costs no extra read.
- REST budget. These reads go through the same rate-limit wait as every other capture call, and the receipt's new optional `taskOutcomeReads` counts them (one request per listing page, one per download), summed across the captures that built the corpus. Receipts written before it decode with the key absent.
- Classification is unchanged: `hostedJobRedOrigin` already reads `tasks`. With records present, a failed task is a `task` red, a job whose recorded tasks all passed is `harness`, and a job that died in setup before it could write a record is judged by its steps (`setup`). `packages/tooling/tool/cli/test/ci-task-outcomes.test.ts` seeds one of each through a capture and `load`, so the rows decode under `route-corpus/v1`.
- Cache baseline. `bun run beep cache audit` reports 0 blocking findings: the baseline covers Turbo configuration, which these workflow steps and CLI files do not touch, so no baseline is re-recorded (as in decision `unit-timings-every-event`).
