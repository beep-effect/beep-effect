A post-merge review of #3118 found three scoring defects in `Certainty.ts`; all three change reported numbers that sibling goals read.

1. Supersession. A non-green head was censored when the next push started before its last job of any kind finished, so a red head with a slow non-required job was censored rather than counted as a miss. That broke D5, and flipping a counted green head red could lower p95: with counted values 5, 8, 30 and 40 min, the 40-minute head turned red was censored and p95 fell from 40 to 30. A non-green head is now judged against the instant its verdict was decided: the first red or cancelled required context's completion, else the latest required job's completion. Jobs outside the required set never move it. On the baseline fixture, red head f6c4a648 moves from superseded to counted: n 17 to 18, misses 6 to 7, superseded 14 to 13, and p50 stays 63.35. A synthetic fixture (required-green at 40, a non-required job to 55, the next push at 45) pins the flip.
2. Admission to Heavy. The row took the earliest non-skipped `Heavy / ` job of check.yml runs. Since #3030 that is mostly the hosted `Heavy / Test Integration` aggregate, which starts after every integration shard, so the row measured shard time, not heavy-pool pickup. Each producer run of a code head, check.yml or heavy-admit.yml, now pairs its own Heavy Admission start with its first executed job on the heavy pool (beep-ec2-heavy runner labels). The planned fixture p50 goes from 6.45 to 1.22 min (n 15); the baseline goes from 1.35 (n 31) to 1.32 (n 32). heavy-pool-diet's gate (p50 at least 0.5 min faster) reads this row.
3. Runner-minutes. Per-run figures counted check.yml and heavy-admit.yml runs separately, all-skipped heavy-admit runs included. The green code-run percentiles left out a label-admitted head's beep-ec2-heavy minutes, which ran in heavy-admit.yml. The population is now head attempts: each check.yml run (all of its run_attempts, so a rerun is part of the same head attempt) plus the admitted heavy-admit.yml runs of its head. A heavy-admit run joins the latest check.yml run created at or before it, and one whose Heavy Admission was skipped is dropped. Baseline: 40 runs averaging 219.7 become 35 attempts averaging 251.08, and green code p50/p95 go from 271.63/385.35 to 278.85/385.35. Planned: 45 runs averaging 97.49 become 29 attempts averaging 151.28, and green code p50/p95 go from 208.88/334.23 to 222.62/351.75. The superseded runner-minute share on the baseline goes from 0.4083 to 0.3737, because f6c4a648 is no longer superseded. hosted-setup-tax reads greenCodeRunP50 and greenCodeRunP95. main-verdict-every-commit reads the SLO counts.

Field names are unchanged (`ci-certainty-report/v1`); the schema descriptions and the Markdown labels now say "head attempts" and "heavy pool". Decision `fixture-corpus-real-captures` is restated, because two of its three anchors are not reproduced. The baseline test now asserts one code head under ten minutes instead of adding the docs heads to it.
