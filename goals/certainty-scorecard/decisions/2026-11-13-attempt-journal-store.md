Every removal through the worktree removal service (`yeet sweep --retire`, `worktree remove` with or without `--archive`, `worktree reap`) now files the checkout's `.beep/yeet/runs/<runId>/attempts.ndjson` journals under `<yeet state>/attempts/<host__owner__name>/runs/<runId>/attempts.ndjson` before it deletes anything, through the `AttemptJournalStore` service in `packages/tooling/tool/cli/src/commands/Yeet/internal/AttemptJournalStore.ts`. The yeet state root is `BEEP_YEET_STATE_ROOT`, else `$XDG_STATE_HOME/beep/yeet`, else `~/.local/state/beep/yeet` (the PR session registry's root), which residue-reap never cleans. The partition key is the GitHub repository the owning clone's `origin` names, the key the session ledger and the fleet roots use. In an archive retirement the export runs inside the fence, after the head authority check and before any capture, so a failed export leaves the fenced copy as it was and the existing restore puts the lane back whole.

- Format: the checkout's own run layout and rows, byte for byte, so economics reads the store with the reader it uses for a live checkout. Each export appends, in one write that starts with a newline (the SCHE-09 archive rule), only the rows the stored journal does not already hold, so a repeated export, or a restored lane's grown journal, stores each row once.
- Failure: an unreadable runs directory or journal, an unresolvable state root, or a store directory or file that cannot be created, read or appended refuses the removal with preservation step `export-attempt-journals` and deletes nothing (D18: a copy failure blocks deletion). A runs path that is missing or crosses a file holds no journal and exports nothing. A clone whose origin names no GitHub repository has no partition and no fleet reader; its journals are reported `unpartitioned` and not copied.
- Visibility: `WorktreeRemovalReceipt.attemptJournals` (an optional key, absent when the checkout held no journal) and one summary line in the `worktree remove` and `yeet sweep --retire` output.
- Economics: `yeet economics --fleet` also reads the partition for the clone's repository, as checkout `(retained)`. Rows of a retained attempt that a live journal of the same run also holds are dropped before the fold and counted in `duplicateStartedRowsDeduplicated` and `duplicateFinishedRowsDeduplicated` (the A1 loader's live-overwrites rule), so each (runId, attemptId) is counted once.
- Admission gate: `packages/tooling/tool/cli/test/yeet-attempt-journal-store.test.ts` retires a scratch lane with a file planted where the store belongs (refused; lane, journal, material and branch kept), retires it, restores it from the archive ref with its old rows and one new attempt, retires it again (only the new attempt's rows appended), runs residue-reap with `maxAgeDays: 0`, and checks after every step that the fleet census holds each (runId, attemptId) exactly once.
- Size: the workstation's 371 live journals total 8.9 MB (p50 13 KB, p95 73 KB, max 206 KB), so the store has no prune in this slice; a prune would censor the fleet census the store exists to complete.

Rejected: copying `.beep/yeet` into the archive's `beep-material` (the residue root is a cache, and a restore would move the journals back into a live lane); SCHE-09 day segments (terminal rows carry no run id, so a segment loses the run a terminal row belongs to, and economics folds per run journal); exporting only on archive retirement (a plain `worktree remove` deletes the same journals); counting a live-and-retained attempt from the retained copy (a restored lane's live journal can hold a newer terminal row).

Not in this slice: the T3 `roots.json` row and the monitor-time split (slice 8), host and seat fields and read-only fleet-host reads (slice 9). A residue-reap `checkout-jobs` archive-move of a merged lane's `.beep/yeet` under a terminal-lane authority still moves its journals into `.beep/residue-reap/<run>/archive/`, where economics does not read them; the export covers removals only.
