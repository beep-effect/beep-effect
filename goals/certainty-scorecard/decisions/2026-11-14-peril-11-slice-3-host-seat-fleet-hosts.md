PERIL-11 slice 3 (PLAN slice 9). Two parts: attempt-started rows say where an attempt ran, and `yeet economics --fleet-hosts` reads other machines' journals read-only over the SSH wrappers they already have.

Host and seat. `YeetAttemptStarted` in `packages/tooling/tool/cli/src/commands/Yeet/internal/AttemptJournal.ts` gains two optional keys. `host` is the writer's short host label (`hostLabelOf`, the GitHub ledger's `HostLabel`). `seat` is the agent harness in the PR provenance footer's vocabulary (`PrProvenanceHarness`), as the merged-lever skeptic asked: `codex` when `CODEX_THREAD_ID` is set (a Codex shell, even one a Claude Code session launched, the footer's fallback order), else `claude-code` when `CLAUDE_CODE_SESSION_ID` is set, else `unknown`. Session ids are read only to tell harnesses apart and are never stored. Both writers (`makeYeetAttempt` in `Handler.ts` and the final-check start row in `FinalCheck.ts`) stamp them through `currentYeetAttemptOrigin`. SPEC D18 says "attempt rows"; the PLAN row and this slice put them on the start row only, because every terminal row joins its start by attempt id. The entrypoint half of the footer vocabulary is not recorded: it needs transcript reads on the start path.

Mixed revisions. Rows written before the keys decode with both absent, and readers that predate them drop them as excess keys. `test/fixtures/yeet-attempt-journal/mixed-revision.ndjson` holds two rows encoded by origin/main's encoder at 9d2ce0c0ea0 and two by this revision's; `test/yeet-attempt-journal-host-seat.test.ts` decodes both with the new decoder, re-encodes each byte for byte, decodes the new rows with origin/main's started-row field set (frozen in the test), runs the journal's own retention reader over the file (the new rows' bytes stay), and folds it. The economics projection reads both keys as plain strings, so a value a newer writer adds never invalidates a row. Each attempt mix gains `hostMix` and `seatMix`, where a row without the key counts as `unrecorded`; the report stays `yeet-economics/v4` because nothing changes meaning (the slice-8 rule: new fields are additive).

Fleet hosts. `--fleet-hosts` (implies `--fleet`) reads the hosts listed in `<state>/beep/fleet/<repo-key>/hosts.json` (`fleet-hosts/v1`, beside `roots.json`). `FleetHostRoute` is a closed domain of the five ordinary workstation wrappers the host profiles name (`ssh-beep-worker-yubi`, `ssh-tbk-worker`, `ssh-dankserver-worker`, `ssh-tom-pc-1-wsl`, `ssh-grok-bot`), never `--admin`, so a `hosts.json` cannot name a new route or credential. Roots are home-relative paths of plain segments with no `.` or `..`. Each host runs one command, every token single-quoted: `find <roots> -maxdepth 8 ( -name node_modules -o -name .git ) -prune -o -type f -path */runs/*/attempts.ndjson -exec tail -v -c +1 -- {} +`. It only lists and prints journals; nothing is created on the host. Read-only is enforced three ways: the command is built only from fixed tokens and schema-validated roots (`fleetHostReadCommand`), `FleetHostReadCommand` is a branded schema whose filter accepts only that shape, and the live `FleetHostShell` re-checks it and refuses anything else before it starts the wrapper (standard input closed). Hosts are read one at a time, since every route may ask for a touch of the same YubiKey, with two minutes each. The output is split into files in memory (exact bytes, torn tails and `find` batch boundaries included), classified as a live checkout (`<checkout>/.beep/yeet/runs/<runId>/attempts.ndjson`) or the host's store partition for this fleet's key, and folded with the local fold: labels `<host>:<checkout>` and `<host>:(retained)`, a retained attempt a live journal of the same run holds counted once. The report gets one `FleetHostReadReceipt` per host in `scope.hosts` (status, reason, exit code, journal, attempt and skipped-file counts); no row, path or error text from a host is kept.

Unreachable hosts. `read` is exit 0; `partial` is exit 1 (`find` met a missing or unreadable root and still printed the rest); `unreachable` carries `timeout`, `connection-failed` (ssh exit 255), `route-failed` (any other status, such as a wrapper's own 78), `spawn-failed` (wrapper not installed), `output-truncated` (past 64 MiB, nothing folded) or `refused-command`. One host's failure never fails the read; a clone without a GitHub origin, a missing `hosts.json` or one that does not decode logs a warning and reads no host.

Tests use a fake SSH executor only: `test/yeet-economics-fleet-hosts.test.ts` gives the source a `FleetHostShell` that answers only the exact read command for each configured host and dies on any other command line, and drives the live shell over a scripted spawner (refusal before spawn, spawn failure, the timeout under the test clock). No test or verification step opened a connection to a fleet host; the workstation has no `hosts.json` yet, so `--fleet-hosts` reads nothing until one is written.

Rejected: reading hosts on every `--fleet` run (each read can ask for a YubiKey touch, so it is opt-in); running `beep yeet economics` remotely and merging reports (a remote command beyond reading journals, which may write caches); reading remote `.git/config` to apply the origin rule (a read beyond the journals: remote checkouts are admitted by root, and `hosts.json` should list only directories holding this repository's checkouts); the T3 environment route (D18 names the SSH routes); copying remote journals into the local attempt-journal store (raw rows would then leave the fold); remote `verdict.json` orphans (not journals; a remote attempt without a terminal row counts only through its rows).
