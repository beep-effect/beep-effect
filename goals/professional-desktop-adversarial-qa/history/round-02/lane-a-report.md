## Clean areas

- Hard reload succeeded in a newly created Chrome tab; no pre-existing user tab was touched.
- Stop followed immediately by a new prompt answered the new prompt (`NEWPROMPT`), not the abandoned long request.
- Once refreshed, a stopped turn persisted across subsequent transcript updates.
- Built a three-exchange thread, rewrote the middle user turn, rewrote that edited turn again, and reloaded. Only the current branch (`A1/A1`, `C2/C2`) remained; the discarded `A2/A2`, `A3/A3`, and first rewrite `B2/B2` did not return.
- Seven rapid **+ New thread** actions created seven distinct new rows, all dated `Jul 12`.
- First-message title derivation worked for normal and oversized messages; titles were truncated in the sidebar.
- A 50,000-character send did not silently disappear: it persisted and survived reload (the absence of a bound is reported above).
- Reload after the oversized send left the composer usable and showed the completed assistant response.
- Two-tab testing preserved both user prompts across reload; the assistant-response association was the failing portion reported above.

## Not fully proven clean

- Pixel-precise scroll pinning/resume behavior could not be conclusively measured in the allotted live campaign window.
- No forced transport rejection occurred, so failure-toast plus draft-restoration behavior was not re-proven through a real failing send.
