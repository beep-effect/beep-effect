# Reflection — ingestion-secret-scrub (2026-10-09, codex)

## Summary

One pure, versioned schema bank now supplies credential matching to both existing
consumers and the file-processing scrub. The scrub returns masked proof with
coverage and residue states, retention decisions and a prompt-admissible brand.
FilingDecisionLlm rejects blocked or unknown excerpts before model invocation.
The slice uses synthetic inputs and reads no corpus or client document.

## Tooling experience

- **Worked:** Graft located the existing consumers and wiring; schema-first and
  Effect-first guidance kept contracts and runtime composition aligned. Signed
  commits, Yeet inbox attribution and exact-canary scans provided checkable repair
  receipts. Single-file tests gave fast feedback while heavy checks waited.
- **Didn't:** A direct schema encoder violated the compiler's Effect policy;
  constructors passed directly to Array.map received an index as MakeOptions.
  Explicit effectful encoders and a constructor callback repaired those failures.
- **Frustrating:** Shared heavy admission used independent polling, delaying an
  owned consumer job despite continued machine activity. A queued unit is not
  evidence that a proof ran.
- **Wished existed:** FIFO admission with estimated wait and result provenance
  tied to source fingerprints would make dependency rechecks easier to assess.

## Implementation improvement opportunities

- Keep original-input counts separate from rendering. Mask overlapping value
  extents before header and assignment formatting so an expanded match cannot
  consume another original bank's credential coverage.
- Keep partial-residue admission stricter than existing consumer rendering.
  Complete legacy matches retain their contract; ingestion additionally masks
  partial findings and rejects the excerpt.
- Retention enforcement remains a schema and pure eligibility decision. Storage
  deletion belongs to a later packet with its own storage surface and proof.

## Goal and prompt critique

- The brief's rulings resolved bank ownership, union semantics, real boundary,
  support-evidence surfaces and hosted quality mapping before implementation.
- Include quoted multiline and nested assignment/header examples in the initial
  fixture requirements. Those overlaps caused most of the implementation repair.
- Check module export projection consequences during P0; the namespace barrel
  avoided a shared-root change and kept the repair inside ownership.
- Align release-note deliverables with package manifests; private-package notes
  belong in the handoff and PR body under main #1566.
- Distinguish a content-final worker PR from standard merge readiness when the
  orchestrator owns consolidated inherited-red repair under S11.

## TODOs worth codifying

- Track fair heavy admission without raising caps or bypassing the shared budget.
- Add a compiler-policy recipe explaining why Array.map cannot receive schema
  constructors that take optional MakeOptions as their second argument.
- Maintain the no-raw-value scanner as the regression boundary for packet evidence,
  test output, logs, telemetry and posted review replies.

## Lessons

- **HIGH — Critical:** Consolidation must preserve the union of original match
  coverage across overlaps, not only the isolated regex match shapes.
- **HIGH — Critical:** Only independently validated, known-coverage, clear-residue
  results mint prompt text. Prompt admission grants no action or egress permission.
- **MEDIUM — Best practice:** Attribute every failed proof before remediation;
  inherited out-of-scope policy and coverage reds require the orchestrator's repair.
- **LOW — Consideration:** Report exact source/proof provenance when code changes
  while detached verification is running.
