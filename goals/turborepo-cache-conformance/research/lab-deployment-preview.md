# Disposable AWS lab: deployment preview (P2)

Status: prepared 2026-10-23, **not applied**. Applying it spends money in the
operator's AWS account, so it waits for an explicit operator decision on the
ceiling below (AGENTS.md autonomy charter: money escalates). Everything that
does not spend money runs first in the local container lab
(`infra/lambda/turbo-cache/lab/`).

## What the local lab cannot prove

The local lab reproduces routes, the REQUEST authorizer, the writer HMAC gate,
the two-function shim split and object storage. It cannot reproduce, and the
deployed lab exists to measure:

- API Gateway HTTP API and synchronous Lambda payload ceilings (RC-027);
- concurrency, throttling (`100 rps / 200 burst` stage limits) and cold starts
  (RC-028);
- IAM: reader role cannot write S3, writer cannot be invoked directly
  outside the gateway (RC-012 storage half, RC-013);
- lifecycle expiry and namespace cleanup on a real bucket (RC-029);
- CloudWatch log redaction and request correlation (RC-030, RC-031);
- endpoint/epoch cutback with no mixed writes (RC-032).

## Load measurement

No local Turbo cache artifacts exist to size (all local caches were empty on
2026-10-23). The representative envelope therefore needs a read-only size
census of the production bucket: `s3api list-objects-v2` over
`beep-turbo-cache-832907639880`, recording only object sizes and last-modified
dates (no keys, no content), plus peak concurrent PUT/GET from existing API
Gateway access metrics. This is read-only, costs well under one cent, and runs
under the same operator AWS profile as the lab.

## Apply, verify, tear down

1. `bun run beep cache conformance-corpus --check` and the local lab run pass.
2. Build the incumbent ZIP with `infra/lambda/turbo-cache/build.sh` and record
   its SHA-256; record Ducktors/Bruno digests from `pins-2026-10-23.json`.
3. `infra/turbo-cache-lab/lab-aws.sh bootstrap <epoch>` then `lab-aws.sh preview <epoch>` (diff retained, secrets masked);
   proceed only if every resource carries the lab prefix and tags and no
   production resource appears.
4. `lab-aws.sh up <epoch>` with `BEEP_TCL_APPROVED_CEILING_USD` set to the approved ceiling; run the corpus per topology with the
   same target descriptors as the local run, profile `aws-lab`.
5. Teardown owner: the goal executor. Command: `lab-aws.sh destroy <epoch>`
   (empties the bucket, destroys and removes the stack, deletes the lab
   parameters, schedules the lab key's deletion), then `lab-aws.sh inventory
   <epoch>`, which must report nothing tagged for the epoch. Record actual cost from Cost Explorer
   after 24 hours. A teardown failure keeps the lab open and is reported.
