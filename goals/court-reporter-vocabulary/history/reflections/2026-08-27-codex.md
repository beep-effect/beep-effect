# Reflection: court-reporter-vocabulary (2026-08-27, codex)

## Summary

The packet is complete and retained. It delivers deterministic pinned-source
generation, 2,809 stable court identities, 1,262 stable reporter identities,
public schema-decoded vocabulary and lookups, exact artifact versioning, and a
reviewable compatibility classifier while keeping raw data private.

## Tooling experience

- **Worked:** Schema-first and Effect-first checks kept the public contract
  typed, CodeGraph located the live citation boundary, and Yeet exercised the
  complete package and repository proof path.
- **Didn't:** Config sync updated the root TypeScript alias without updating
  the generated Vitest alias map in the same transaction.
- **Frustrating:** A direct package audit initially read stale dependency
  declarations and obscured whether the failure belonged to this change.
- **Wished existed:** One dependency-aware package-audit command that builds
  prerequisite declarations and reports provenance for stale output.

## Implementation improvement opportunities

- Add fixture history when a future upstream release first tombstones or
  supersedes an issued identity; the current pinned release contains only
  active records, so lifecycle history is proved with typed transition fixtures.
- Keep citation parsing pinned to the exact artifact version even when a future
  vocabulary refresh is classified as additive-compatible.

## Goal and prompt critique

The packet's launcher and spec preserved the 2026-07-25 P1a-only boundary after
the request expanded delivery to the full goal. A clearer launcher would say:
"Complete P1a through P3 in one PR; preserve the existing non-goals and raw-data
privacy boundary."

## TODOs worth codifying

- Make config sync update `vitest.aliases.generated.json` whenever it changes
  root `compilerOptions.paths`.
- Teach package audit guidance to distinguish stale dependency declarations
  from source regressions.

## Lessons by confidence

- **HIGH, critical:** Treat artifact identity as a public parser dependency.
  An additive data change can be review-compatible while still requiring an
  exact parser rebuild.
- **HIGH, best practice:** Prove deterministic generation with a second
  canonical check and archive both the zero-diff report and checked-in hashes.
- **MEDIUM, consideration:** Keep lifecycle transition fixtures even before the
  pinned source contains tombstones; they prevent the first real deletion from
  defining policy accidentally.
