# Reflection — patent-citation-candor-gate (2026-08-05, claude)

## Summary

Landed the derived, fail-closed candor gate: two new law-practice entities plus an
information-disclosure fact record, a `CandorPolicy` `Context.Service` proven by 19
failing-then-green scenarios over in-memory layers, durable append-and-read-only ports with
a Drizzle repository, and the law-practice slice's first db-admin migration with append-only
triggers proven against PGlite. Two findings that the packet had not anticipated were
surfaced and deferred with evidence rather than worked around.

## Tooling experience

- **Worked:** The schema-first stack carried a lot. `BaseEntity.Class` plus
  `EntitySchema.persist.*` meant the migration SQL was *generated* from the domain model —
  three entities became three correct tables with one `drizzle-kit generate`. Adding the new
  entities to the existing arbitrary-driven round-trip test in `LawPracticeDomain.test.ts`
  validated every field of every value object for the cost of three identifiers.
  `verifyTextAnchor` being an opaque from-self declare is a genuinely good piece of design:
  it is structurally impossible to pass a persisted receipt off as live proof, which is
  exactly the invariant the SPEC needed and it needed no enforcement of my own.
- **Didn't:** `A.isArrayNonEmpty` is mutable-only; the readonly form is
  `isReadonlyArrayNonEmpty`, and the error surfaces as a confusing `TS4104` about
  assignability rather than "wrong helper". `Result` is not yieldable in an Effect v4
  generator — the table converters return `Result`, and yielding one fails at *runtime*
  with `Fiber.runLoop: Not a valid effect`, not at compile time. `Effect.fromResult` is the
  bridge. Both cost a debug cycle.
- **Frustrating:** Three separate JSDoc examples compiled fine in my head and failed the
  docgen gate for the same underlying reason — a `Fn`-declared service method carries its
  requirement channel in the schema type, so `Effect.runPromise(shape.method(x))` never
  typechecks even when the fixture implementation needs nothing. The full docgen run is the
  only place this surfaces, it takes ~90s, and `docgen:local` refused to run the bounded
  version at all because `bun.lock` had changed — which it necessarily had, since the goal
  requires new workspace dependencies. So every JSDoc example iteration cost a full repo
  docgen.
- **Wished existed:** A crypto test layer in `@beep/test-utils`. Every proof that touches
  `verifyTextAnchor` needs `Crypto.Crypto`, and the only in-repo answer is
  `@effect/platform-bun/BunCrypto`, which a use-cases package has no business depending on.
  I hand-rolled a Web Crypto layer to avoid adding a dependency for a test; that layer will
  be re-hand-rolled by the next person with the same problem.

## Implementation improvement opportunities

- The predicate evaluates coverage per source group and gives every AI-discovered event in
  the group the head's answer. When the head is an examiner-observed event that superseded
  an AI-discovered one, the AI event blocks forever, because an examiner event is never in
  the quantified set and so can never be dispositioned. That is fail-closed and therefore
  safe, but it is an unreachable state a human cannot clear, and it is untested. It deserves
  either a test pinning the behaviour or an align question about whether an examiner
  observation should be dispositionable.
- `CitingApplicationIdentity` has no conversion between its two representations, because
  translating an eight-digit USPTO number to ST.13 needs USPTO's series-code-to-year table
  and inventing one would fabricate legal identity. The consequence is that reads are keyed
  by one exact representation and a filing recorded both ways would gate twice. The
  reference-reconciliation follow-on already owns this, but the gate is where it will first
  hurt.
- The Drizzle repository filters by jsonb equality on the encoded citing application. That
  is correct and index-free; a filing with many events will table-scan. A generated column
  or an expression index is the obvious answer when volume justifies it.

## Goal & prompt critique

- `GOAL.md` was well-shaped: compact, correctly pointed at SPEC as normative, and its stop
  conditions were the reason the two P0 findings got surfaced instead of absorbed. I would
  not shrink it.
- I *would* change one line. The Workflow section says P0 makes "the final gate-shape pick
  (emitted events preferred vs a promoted `shared/use-cases` contract — SPEC decision 7)".
  Naming the two candidates inline framed the task as *choosing between them* rather than
  *checking whether either is available*. The better phrasing is "make the final gate-shape
  pick by re-deriving the lawful options from `standards/architecture/`, then recording the
  pick" — same length, and it does not pre-commit the agent to a stale enumeration.
- The rung-2 acceptance criterion "a blocked predicate blocks a real filing candidate" was
  unachievable from the day it was written: the promotion path has one in-memory fixture
  implementation consumed by a single test, and no app composes both slices. A SPEC that
  names a consuming surface should require P0 to verify that surface is *runnable*, not just
  that it exists on disk. The packet did verify existence; existence was not enough.

## TODOs worth codifying

- The `Result`-returning converter contract (`to<Entity>Insert`) is now the repo pattern in
  two slices, and both call sites need `Effect.fromResult`. That is worth a line in the
  effect-first skill, because the failure mode is a runtime error with no type-level warning.
- `docgen:local` escalating to full-repo docgen whenever `bun.lock` moves makes it useless

  surprise mid-loop.
- A note that a `Fn`-declared service method's requirement channel travels in its schema
  type, so JSDoc examples must compose rather than run them.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Re-derive a deferred decision's option set from the standards at the
  moment you make it, even when the SPEC enumerates it. A correctly-quoted stale source is
  the hardest kind to catch, because the citation checks out.
- **HIGH — Critical:** When a domain has no ordering signal, do not invent one. Deriving
  currency purely from declared links turned three adversarial test cases into
  consequences of the design instead of special cases, and it fails closed by construction.
- **MEDIUM — Best practice:** Prove an append-only guarantee at the database, and prove it
  in both directions. The PGlite test pins the exact constraint and trigger names before
  asserting the denials, so a silent rename cannot leave the tables writable while the
  proof still passes.
- **MEDIUM — Best practice:** Split a blocked goal along the axis of the blocker rather
  than stopping at it. Rung 2's durability half needed no cross-slice decision at all, so
  the migration lane — the actual risk retirement — landed while the gate-shape question
  went to its own packet with the evidence already written.
- **LOW — Consideration:** A test-only capability layer (crypto here) is worth promoting to
  the shared test kit the second time someone hand-rolls it.
