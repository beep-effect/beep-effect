# CSF-018: Coverage ratchet can miss offset test regressions

- Severity: Informational
- Codex ID: `bdaf5007ae688191a499967b959b5a86`
- Source commit: `3082ae31d10320b8dd49a68b7a2112b8ce169758`
- Owner: Repo CLI coverage architecture
- Status: confirmed; defer-p2

## Public Summary

Package-level coverage percentage and uncovered totals cannot distinguish a
loss of tested units from an exactly offsetting deletion of uncovered units.

## Current-HEAD Validation

Verdict: `defer-p2`. Current code explicitly documents the ambiguity. A local
predicate change would either retain the blind spot or restore false positives
for deletion-only changes.

## Remediation

Deferred to a per-file coverage baseline design, which can preserve provenance
for the offsetting changes that package aggregates erase.

## Verification

- Add an offsetting per-file regression fixture with the baseline redesign.
