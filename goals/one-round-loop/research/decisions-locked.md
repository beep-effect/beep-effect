## Decisions

| # | Question | Ruling |
|---|----------|--------|
| D1 | Packaging | **One packet, tiered DoD.** All ~10 improvement items in one packet. Core tier (6 items) is required for the Definition of Done; stretch tier (4 items) may close as won't-fix with a ledgered rationale. Mirrors the crispening's exception-ledger discipline. |
| D2 | CI replay architecture | **Invert lane ownership into the CLI, with a three-class lane taxonomy** (adversarial-review amendment, 2026-07-07). Every lane is classified `cli-runnable` (pure command body moves into `beep ci lane <id>`; check.yml dispatches it), `workflow-gated` (command body moves to the CLI but GitHub-context orchestration — docgen lane-gate modes, desktop-IPC path filter, fallow envelope-validation/artifact upload, commitlint range computation, base-pinned gitleaks config — stays in YAML and passes results as flags like `--base`/`--mode`), or `ci-native` (Docker/actions-only: dependency-review, OSV action, gitleaks image; never simulated locally). `beep ci lane --list` emits the classification machine-readably. CI-only concerns (turbo cache env, typos install) stay workflow-side. Reuses the Quality/Tasks.ts step-group runner. |
| D3 | Property-law cadence | **PR affected + nightly full, ratcheting to required.** A per-PR lane runs property suites at ~400 runs for `--affected` packages only; a nightly run (schedule + workflow_dispatch, `issues: write` permission) covers ALL suites at 1000+ runs and opens/updates a single tracking issue (stable title key, label `property-laws-nightly`; triage owner = packet operator until P4, then repo default). Required-check status mirrors the repo's advisory→blocking ratchet: the PR lane lands NON-required with a frozen context name, and flipping it to required (ruleset 10240248 addition via gh api, an admin step) is a P4 close criterion once it has a stable green history over the packet's own PRs. |
| D4 | Definition of Done | **Mechanisms + self-dogfood** (adversarial-review amendment, 2026-07-07). Each core item ships with its own fixture-level verification, PLUS the dogfood rule: **every packet PR — including P0's own PRs — must pass `beep ci local` as built from that PR's branch before push** (the command exists in the worktree before the first push, so there is no bootstrap exemption). A packet PR needing >1 CI round is a failed dogfood proof, not merely a noted event: it requires a root-cause note AND a demonstrated fix — the exposed failure class must be shown caught locally (fixture or the next PR's pre-push run) before the packet may close. Latency budget (D8): full `beep ci local` for code PRs (may run in background during final review); `beep ci local --fast --affected` suffices for docs-only / packet-file-only PRs. |
| D5 | Authoring path | **Direct goals/ packet.** No explorations/ round; the crispening closeout reflection + three research briefs are the evidence base. |
| D6 | Stretch tier contents | **All four kept**: fallow envelope file/line, yeet publish committed-branch mode, worktree deps story, CI cancel-rerun + required-check quarantine. |
| D7 | cwd-independence mechanism | **chdir at startup + escape hatch.** A lightweight sync root-walk + `process.chdir()` in bin.ts BEFORE the bin-main import (findRepoRoot semantics: `.git` or `bun.lock` marker; matches the `.git` FILE so linked worktrees stay in-worktree). The invocation cwd is stashed (`BEEP_INVOCATION_CWD`) defensively, though the audit found NO command that genuinely consumes it today (Worktree re-derives from `git worktree list --porcelain`; Yeet runs git with explicit cwd). Plus a `beep` shim so the command resolves from any directory (the CLI package already declares `bin: {"beep-cli": "./src/bin.ts"}`). ORDER MATTERS twice: (a) ship chdir before or with the shim — a shim alone exposes the ~8 cwd==root-assuming command files harder; (b) the chdir goes at the VERY TOP of bin.ts, before the fast lint-fix no-op path that runs BEFORE the bin-main import (bin.ts:17-46) — "before bin-main" is too late. Fact base: 38 `process.cwd()` textual sites (RepoRun.executor's 5 are comment examples, not runtime consumers); cwd==root assumers include SchemaFirst, DualArity, TerseEffect:581, EffectImports:125, SchemaTopology:437, PackageTestImports:279, Lint.command:242/343, Tasks:1339/1651. |
| D8 | Dogfood latency budget | Full `beep ci local` before push for code PRs (background execution during final review is fine); `--fast --affected` suffices for docs-only / packet-file-only PRs; a full-battery local run that exceeds ~40 minutes on a dev machine is itself a defect to fix (lane parallelism/caching), not a reason to skip the gate. |
| D9 | P0 parity-proof method | **Shadow workflow on the same SHA.** Before thinning merges, the P0 PR adds a temporary workflow_dispatch "shadow" workflow that dispatches every cli-runnable/workflow-gated lane via `beep ci lane <id>`; it is run against the SAME head SHA as the unmodified check.yml run on that PR, and lane set + commands (CLI-echoed) + verdicts must match, with run IDs recorded in the packet history. Only then does the thinning commit replace check.yml's bodies. "One unchanged commit pre/post" is satisfied by this same-SHA shadow comparison, not by re-running across the merge. |

## Research-settled decisions (no user fork; rationale recorded)

| # | Question | Ruling |
|---|----------|--------|
| R1 | Coverage denominators | **Baseline schema v2 with raw counts.** `standards/coverage.regression-baseline.jsonc` currently stores percentages only (schema_version 1); v2 adds covered/total counts per metric so the ratchet can report denominator deltas ("branches: 41 was 66") alongside percentage drops. The file regenerates by command (`coverage:baseline:write`), so the schema bump is cheap. Missing-package warnings (e.g. @beep/pacer) become auto-add on baseline write. |
| R2 | numRuns override mechanism | **Shared helper + mechanical sweep.** Inline `{ numRuns: N }` overrides `fc.configureGlobal`, so a global config alone cannot work. A shared test-kit helper (e.g. `fcRuns(n)` returning `{ numRuns: max(n, BEEP_FC_NUM_RUNS) }`) replaces inline options via a ts-morph codemod; existing per-suite values become floors. Sweep scope (live inventory 2026-07-07, regenerate from `rg` at execution time): 287 `numRuns:` lines / 161 files, 264 `fc.assert` sites, 53 `assertSchemaArbitraryDecodesToSelf` calls, PLUS `it.prop`/`test.prop` sites (e.g. drivers/pacer) whose `{ fastCheck: ... }` params also override globals. Turbo: `BEEP_FC_NUM_RUNS` goes in the property task's `env` (deliberate separate cache key — passThroughEnv would let low-run cached results satisfy the 400-run lane), and the lane is its OWN turbo task so it never hijacks the regular `test` cache. |
| R3 | Generated-file merge strategy | **Regen command over merge drivers.** gitattributes merge drivers require non-versionable local git config, so the portable fix is a `beep quality regen-generated` command + a documented conflict recipe (checkout --ours on generated paths, regen, continue). Scope (audit-confirmed regen commands): jsdoc-documentation.inventory.{jsonc,md} (`quality jsdoc-inventory` — one command, two files), schema-catalog.generated.jsonc (`lint schema-catalog --write`), fallow.boundaries.generated.jsonc (`fallow:boundaries:write`), coverage.regression-baseline.jsonc (`coverage:baseline:write`), schema-first.inventory.jsonc (`lint schema-first --write`, preserves exception entries), dual-arity.inventory.jsonc (`laws dual-arity --write`), plus knip/fallow.dead-code/jsdoc-totals baselines. EXCLUDED: effect-laws.allowlist.jsonc is HAND-maintained (validate-only, no --write). The command is an ORDERED per-artifact manifest (each entry: artifact path(s), exact regen command, idempotency check), not a generic wrapper — the write mechanisms differ (jsdoc-inventory writes directly; jsdoc-ratchet and knip use `--write-baseline` flags; coverage baseline is a root script; fallow dead-code baseline is a fallow subcommand). Optional enhancement: a bootstrap step writing the local `[merge "<driver>"]` config that reruns the matching command per path. |
| R4 | Fixed-point combinator home | **`SchemaUtils.withNormalizedCheck(normalizer, options)`** in `packages/foundation/modeling/schema/src/SchemaUtils/` (foundation substrate — domain-agnostic schema machinery; new file + alphabetized barrel entry; style reference: withConstructorDefaults.ts, which houses withConstantDefault/withNoneDefault). Constrains a codec's Type domain to normalization fixed points so `S.toArbitrary` only generates round-trippable values. Options bag carries caller-supplied `{identifier, title, description, message}` (each check needs a unique identity) + optional `equivalence` (default from the schema) for non-string Types. Migration targets (audit-corrected): venice-ai `VeniceAIBaseUrlNormalizedCheck` (VeniceAI.service.ts:75-95), phoenix `Phoenix.config.ts:16-36`, m365 `M365.config.ts:139-159` (byte-identical hand-rolls); uspto `Uspto.config.ts:30-41` OPTIONALLY (it lacks the check today — migrating ADDS the guard, a behavior tightening needing its own parity note). NOT a target: repo-utils `TSConfigJsonKey` (a `__proto__` guard, not a fixed-point check — shape sibling only). |
