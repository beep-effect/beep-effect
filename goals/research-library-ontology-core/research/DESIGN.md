# Design: research library ontology core

P0 output. Order: schema, then the `Context.Service` contract, then the
implementation. `SPEC.md` stays normative; this file records the concrete
contracts the implementation lanes build against.

## Facts established in P0

- `Library.schemas.ts` has 15 exports, all `S.Opaque` wrapping anonymous
  `S.Struct`, annotated with `$I.annoteSchema` only. There are no `Finding`,
  `Derivation`, `ModelRun` or `AccessClass` models yet.
- `Library.service.ts` is 41 lines and only resolves the library root. Its
  fallback is a home-relative path, which `SPEC.md` forbids in repo files
  (the same string appears in `Library.command.ts` flag help and the runbook).
- `@beep/ontology` `fold(composer, { label, schemas, triples })` takes schema
  handles that carry `$I.class(...)` annotations, plus field keys annotated
  with `$I.key(...)`. Triple predicates are typed `Predicate<CoreVocab>`. Objects may
  be absolute IRIs, so PROV, CiTO, FaBiO and DCAT alignments are written as
  `rdfs:subClassOf` / `rdfs:subPropertyOf` triples whose objects are absolute
  IRIs. `toTurtle` projects the T-Box. There is no SHACL projection in
  `@beep/ontology`.
- `$RepoCliId` mints `https://beep-effect.com/ns/repo-cli/<path>` IRIs and is
  bound to CoreVocab (`vocabRegistry` undefined).
- `@beep/semantic-web` holds the `ShaclValidationService` and
  `SparqlQueryService` contracts. `@beep/shacl` (`ShaclValidationServiceLive`),
  `@beep/oxigraph` (`OxigraphSparqlQueryServiceLive`) and `@beep/n3`
  (`N3TurtleCodec`) are the live drivers. Datasets are `@beep/rdf` `Rdf.Dataset`.
  `@beep/repo-cli` depends only on `@beep/identity` and `@beep/rdf` today.
- The vocab term files in `@beep/rdf/Vocab/generated` are produced by
  `bun run beep sync-data-to-ts --target vocab-terms` from the identity
  `CoreVocab` registry. `VocabDrift.test.ts` pins each module against that registry.
- Live library census (catalog `library.json`, 9.5 MB): 144 reports, 1203
  sources, 5418 occurrences, 1577 captures, 14 qualifications, 5 intake
  records under two intake dates (`2026-10-06`, `2026-10-14`).
- There is no dedicated command-topology lint. The role check is
  `standards/architecture/07-non-slice-families.md` §Repo CLI Command Topology,
  applied by review and by `bun run beep architecture plan`/`check`.

## Schema layer (`Library.schemas.ts`)

The table below already includes the corrections from [FOUNDATIONAL-AUDIT.md](./FOUNDATIONAL-AUDIT.md).

Export names keep the `Library*` prefix because `@beep/repo-cli/commands/Research`
already re-exports them. Ontology class names are the bare SPEC names, so the
class IRI is `$I` + `/Source` and so on.

| Export | Ontology class | Alignment (`rdfs:subClassOf`) |
| --- | --- | --- |
| `LibrarySource` | `Source` | `prov:Entity`; kind maps to `fabio:Expression` / `schema:CreativeWork` facts |
| `LibrarySourceVersion` (was `LibraryVersion`) | `SourceVersion` | `prov:Entity`, `fabio:Manifestation`; linked by `prov:specializationOf` |
| `LibraryCapture` | `Capture` | `prov:Entity` (generated by an acquisition `prov:Activity`) |
| `LibraryArtifact` | `Artifact` | `prov:Entity` (DCAT alignment rejected by the audit) |
| `LibraryDocument` | `Report` | `prov:Entity`, `fabio:Report` |
| `LibraryOccurrence` | `Occurrence` | `cito:Citation` |
| `LibraryFinding` (new) | `Finding` | `prov:Entity`; `cito:*` typed edge; `skos:related` to a topic concept |
| `LibraryDerivation` (new) | `Derivation` | `prov:Derivation` (qualified `prov:wasDerivedFrom`) with `hopDepth` measured from `intakeId` |
| `LibraryModelRun` (new) | `ModelRun` | `prov:Activity`, `prov:wasAssociatedWith` a projected `prov:SoftwareAgent` model-pin node |
| `LibraryCatalog` | `Catalog` | `dcat:Dataset` |
| `LibraryAccessClass` (new `LiteralKit`) | — (scheme) | `skos:ConceptScheme` members `public`, `private` |

Rules:

- Every model is `class X extends S.Class<X>($I\`X\`)(fields, $I.class(...))`.
  No anonymous exported `S.Struct` remains in the catalog contract.
- Every field that has an external meaning names it with
  `$I.key("<curie>")` when the CURIE is in CoreVocab (`skos:*`, `dcterms:*`,
  `rdfs:*`). It is otherwise an owned predicate whose `rdfs:subPropertyOf`
  alignment to a PROV/CiTO/DCAT IRI is a fold triple.
- `accessClass: LibraryAccessClass` on `LibrarySource` and `LibraryArtifact`,
  with a decoding default of `public` so v1 catalogs decode.
- Capture dispositions and `LibraryCaptureStatus` stay `LiteralKit` phases
  (`skos:Concept` members of a phase scheme), not classes. `hopDepth` is a
  non-negative integer field of `LibraryDerivation`, not a class.
- `LibraryCatalog.schema` accepts `beep.research.library/v1` and `/v2`.
  New catalogs and the `migrate` command write `/v2`. v2 adds `findings`,
  `derivations` and `modelRuns`, each defaulting to `[]` on decode.

## Service layer

- `Library.paths.ts` (earned role): `resolveLibraryRoot(flag)` resolves the flag
  first, then `BEEP_RESEARCH_LIBRARY`, then `$XDG_DATA_HOME/beep/research-library`,
  then `HOME` + `.local/share/beep/research-library`. No operator-specific
  directory string appears in repo files; the operator sets
  `BEEP_RESEARCH_LIBRARY`. Layout constants (`ontology/` file names and the
  migration receipt directory) also live here.
- `Library.service.ts`: `class ResearchLibrary extends Context.Service<...>()`.
  It has one method per subcommand: `inventory`, `qualify`, `acquire`,
  `importResult`, `verify`, `render`, `status`, `renderOntology`, `migrate`.
  `ResearchLibrary.layer` is the default live layer and wires
  `ShaclValidationServiceLive`, `OxigraphSparqlQueryServiceLive` and
  `N3TurtleCodecLive`.
- `Library.command.ts` calls the service only. `index.ts` exports named
  models, `LibraryError` and the `ResearchLibrary` contract, and has no `export *`.

## Ontology layer

- `Library.ontology.ts`: `libraryOntologyInput` (schemas plus alignment
  triples), `assembleLibraryOntology = fold($I, input)`, `libraryTBoxTurtle`
  (`toTurtle`), and `libraryShapes(assembled)`. The shapes function derives one
  `sh:NodeShape` per assembled class (`sh:targetClass`) and one `sh:property`
  per assembled predicate. Required fields get `sh:minCount 1`, scalars get
  `sh:maxCount 1`, datatype predicates get `sh:datatype`, object predicates get
  `sh:class`, and `LiteralKit` fields get `sh:in`. It emits `@beep/semantic-web`
  `ShaclNodeShape` values plus a Turtle serialization through `N3TurtleCodec`.
- `ontology render` subcommand: writes `ontology/research-library.ttl` and
  `ontology/research-library.shacl.ttl`, then re-parses both with
  `N3TurtleCodec` and fails if either does not parse.
- `Library.projection.ts`: `catalogDataset(catalog, topics)` maps a v2 catalog
  to an A-Box `Rdf.Dataset`. Instance IRIs are the class IRI plus `/` plus the
  `encodeURIComponent` of the record id. SKOS topic concepts come from
  `goals/*/ops/manifest.json` and `explorations/*/ops/manifest.json`
  (`initiative.id`/`title`), one `skos:Concept` per packet in one
  `skos:ConceptScheme`.
- `verify` keeps its integrity gate and adds SHACL: it loads the generated
  shapes (regenerating them in memory when the files are absent), validates
  `catalogDataset` with `ShaclValidationService`, and reports violation count
  and the first violations.

## Views

`Library.views.ts` holds the named SPARQL SELECT queries. Each one projects
the rows a view prints:

- `statusCounts`: capture attempt counts by status, qualification counts, and
  source/version effective categories. Effective categories need
  file-system evidence (`libraryEffectiveCaptures`), so the projection carries
  them as an `effectiveCategory` literal per source-version claim and SPARQL
  aggregates them.
- `reportIndex`, `sourceIndex`, `qualificationIndex`: the `index.md` sections,
  ordered by catalog position (`catalogIndex` literal) so the output stays
  byte-stable.
- `reportOccurrences(documentId)` and `sourceBacklinks(sourceId)`: per-report and
  per-source pages.

`render` and `status` format the rows; the `A.filter` view code over
`catalog.*` is deleted. `render` and `status` exclude `accessClass = private`
by default, and `status` prints the private partition count separately.

## Migration

`beep research library migrate` decodes the current catalog (v1 or v2) and
builds the v2 catalog. It renders `index.md` to memory through the SPARQL path
and compares that hash with the on-disk `index.md`. When the two hashes match,
it writes `catalog/history/<sha>.json` (a backup of the pre-migration catalog),
the v2 `catalog/library.json`, and
`ops/migrations/<timestamp>-v2.json`. The receipt is a `LibraryMigrationReceipt`
model with the validator contract version `research-library-shapes/1`, the
before and after catalog SHA-256, the `index.md` SHA-256, both intake dates and
the SHACL violation count. When the hashes differ, it writes nothing and
reports the diff hash. Reversal: restore the backed-up catalog.

Replay tests (`test/research-library-ontology.test.ts`) build fixture
catalogs shaped like intakes `2026-10-06` and `2026-10-14`. They assert v1
decodes into v2, the SPARQL `index.md` is byte-equal to the legacy renderer's
output (captured as a golden string before the legacy code is removed), the
generated shapes produce zero SHACL violations, and both Turtle files parse.
