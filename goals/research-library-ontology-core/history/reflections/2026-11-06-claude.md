# Reflection: research-library-ontology-core (2026-11-06, claude)

## Summary

The research library is now ontology-first. Its named, annotated S.Opaque
models fold into a PROV-O/CiTO/DCAT T-Box with generated SHACL shapes. `verify`
SHACL-validates the catalog projection. `render` and `status` read their lists
from SPARQL over oxigraph, with a schema-level private partition. A hash-gated
v2 `migrate` command proved, in a real-library dry run, `shacl: conforms=true
violations=0` and an in-memory `index.md` equal to the on-disk pre-migration
render. The real migration and ontology render run after merge, so `main`'s
v1-only reader never sees a v2 catalog. Verdict: SPEC met. Two open audit issues
are recorded.

## Tooling experience

- **Worked:** Codex lanes (`gpt-6.1-sol` medium) on disjoint files, run in
  sequence: A (DCAT), B1 (schemas and service), B2 (fold, shapes, projection),
  B3 (views and migration), C (gates). Each lane wrote a report into `history/`. The
  golden-first replay design for B3 (capture legacy output, then delete the
  legacy view code) made byte-equality a test, not a hope. The independent
  adversary seat found real defects: the hop-depth anchor, finding byte binding,
  and private documents.
- **Didn't:** the Codex sandbox scrubbed `BEEP_RESEARCH_LIBRARY`, so B2 skipped its
  real-library check, and the sandbox blocked commits in lane C.
- **Frustrating:** `yeet inbox ack --observed` refuses local-shard rows, and the
  stop hook loops while a fix lane is still running.
- **Wished existed:** a `beep research library verify --diff-against <ref>`
  that compares failure classes between two checkouts.

## Implementation improvement opportunities

- The projection still assembles quads imperatively behind named helpers. A
  schema-driven A-Box encoder (S.Class AST to triples) would remove the
  per-field projection code.
- Cross-field Capture coherence (`readable` with `complete=false`) belongs in a
  SHACL-SPARQL rule, once the census of the 1577 existing captures shows it would
  not reclassify valid October captures.

## Goal & prompt critique

- Replace "named `S.Class` models" in SPEC Objective and Acceptance with "named
  branded `S.Opaque` classes with `$I.class` ontology annotations (schema-first D1)".
- The SPEC's acceptance line "no anonymous exported S.Struct" was the real intent
  and is worth keeping. The model form should defer to the schema-first law.
- State in GOAL.md that the real-library migration is a post-merge step. The
  persisted contract cannot move ahead of the reader on `main`.

## TODOs worth codifying

- Hash-binding rule: schema encoder only, never S.Unknown, for any hashed record.
- `toShacl` in `@beep/ontology`; `sh:in` in the typed shape contract.
- LibrarySourceKind split; expectedOccurrences provenance.

## Lessons (confidence-tiered)

- **HIGH (critical):** After changing a persisted model, diff verify failure
  classes against `main` on real data. Green package tests prove nothing about
  hash-bound legacy bytes.
- **MEDIUM (best practice):** Run cheap gates after the first implementation lane.
  Gate families compound, and one late fix lane cost about as much as the whole
  B2 lane.
- **MEDIUM (best practice):** Run the foundational adversary as a separate Codex
  seat. Its FAIL produced three schema changes the primary seat missed.
- **LOW (consideration):** Let the orchestrator own all inbox acknowledgements.
  Lanes acknowledge rows with the wrong form.
