# CSF-001: PR code now runs on self\-hosted EC2 CI lanes

- Severity: High
- Codex ID: `08ee74d0eb18819187fd02f570b4d57c`
- Source commit: `7e730d757312e56ccfbbc87b1e2adfe18e562820`
- Owner: CI runner admission architecture
- Status: confirmed; remediate; architecture/deployment-blocked

## Public Summary

Pull-request code is still checked out and executed on persistent self-hosted EC2 runners. A contributor who can modify repository scripts or lifecycle hooks can therefore run code inside the runner trust boundary before the change is approved.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`; disposition: `remediate`.

The standalone JSDoc ratchet now uses a hosted runner, but the Lint Policy, Check, Integration, Coverage, and Docgen jobs remain assigned to `beep-ec2-heavy`. Each job checks out the pull request and invokes repository-controlled setup or task code. The current workflow therefore still admits untrusted pull-request code to the persistent EC2 fleet.

Evidence:

- `.github/workflows/check.yml:3` enables the workflow for pull requests.
- `.github/workflows/check.yml:64`, `.github/workflows/check.yml:76`, `.github/workflows/check.yml:88`, and `.github/workflows/check.yml:100` assign pull-request jobs to the self-hosted runner label.
- `.github/workflows/check.yml:223` checks out repository content, and `.github/workflows/check.yml:227` runs the repository-owned setup action before repository commands execute.

## Remediation

Blocked on a runner-admission architecture enforced outside pull-request-
editable workflow content and external GitHub organization runner-group plus
AWS deployment proof. The finding remains dispositioned `remediate`; no
workflow or fleet change in this PR closes the admission boundary.

## Verification

- After the architecture and deployment land, prove from GitHub organization
  runner-group policy and a hostile pull request that untrusted code cannot
  acquire an owned production runner even after editing workflow content.
- The receiving arc must record exact-ID dashboard closure after the deployed
  evidence passes. This packet claims neither result.
