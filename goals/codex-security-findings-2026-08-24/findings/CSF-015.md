# CSF-015: Ack receipts follow symlinks out of the checkout

- Severity: Informational
- Codex ID: `0b32ed8f84008191b07c25996336ef96`
- Source commit: `d2885e5b95e8fa873d3931dee5266697d13a7543`
- Owner: repository CLI safe writes
- Status: confirmed; remediate; repo-side remediated

## Public Summary

Yeet acknowledgment files are written to predictable paths without rejecting symbolic links. A crafted acknowledgment entry or parent can redirect the write outside the intended inbox and can also be read as if it were a legitimate acknowledgment.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`; disposition: `remediate`.

The acknowledgment path is derived beneath the inbox, but the writer creates its parent and calls the ordinary write API without inspecting link state. The read path also accepts an existing symlink through the normal existence and read operations, so the link is not rejected on either side of the workflow.

Evidence:

- `packages/tooling/tool/cli/src/commands/Yeet/internal/Inbox.ts:371` constructs the acknowledgment path.
- `packages/tooling/tool/cli/src/commands/Yeet/internal/Ack.ts:300` checks and reads acknowledgment state without a symlink guard.
- `packages/tooling/tool/cli/src/commands/Yeet/internal/Ack.ts:353` creates the parent and `packages/tooling/tool/cli/src/commands/Yeet/internal/Ack.ts:365` writes directly to the final path.

## Remediation

Acknowledgment writes now use the shared contained atomic overwrite helper.
Reads reject a symlink at the target or any parent and treat the path as
unacknowledged rather than consuming external content.

Changed files:

- `packages/tooling/tool/cli/src/internal/cli/FsGuards.ts`
- `packages/tooling/tool/cli/src/commands/Yeet/internal/Ack.ts`
- `packages/tooling/tool/cli/test/yeet-ack.test.ts`
- `packages/tooling/tool/cli/test/yeet-inbox-view.test.ts`

## Verification

  safe-write run: 5 files, 73/73 tests passed with the threads pool.

Residual risk: Effect's portable filesystem API has no directory-handle-
relative rename. The immediate recheck narrows but cannot eliminate a
concurrent parent-rename race; filesystem permissions remain that boundary.
