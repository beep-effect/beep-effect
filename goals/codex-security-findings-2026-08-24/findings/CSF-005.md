# CSF-005: Shadow runner exposes AWS role creds to job code

- Severity: High
- Codex ID: `c799c2269d748191997ff176ce4bfd48`
- Source commit: `37f289a025b5072e7099a24d195103ab8b2ea4f1`
- Owner: CI runner workload identity
- Status: confirmed; remediate; architecture/deployment-blocked

## Public Summary

EC2 instance metadata remains enabled on the self-hosted runners, and the job process shares the host account with the runner agent. A UID-scoped firewall hook reduces direct access for the normal job process, but privileged job paths can bypass that boundary and reach the instance role.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`; disposition: `remediate`.

Current HEAD contains a mitigation that blocks metadata access for the runner user's UID, but the runner agent and job both execute as `ec2-user`, the instance metadata service remains enabled, and the design does not establish a root-resistant workload boundary. Repository code with a privileged execution path can therefore escape the UID-only rule and obtain the host role.

Evidence:

- `infra/src/CiFleetController.ts:39` defines both the agent and job account as `ec2-user`.
- `infra/src/CiFleetController.ts:65` installs an owner-UID firewall rule, and `infra/src/CiFleetController.ts:344` documents that the protection is UID-scoped.
- `infra/src/CiFleetController.ts:578` attaches the runner instance role, while `infra/src/CiFleetController.ts:590` keeps instance metadata enabled with required tokens.
- `.github/workflows/fleet-shadow-check.yml:87` tests only the non-root runner user and treats credential unavailability there as success.

## Remediation

A root-resistant workload-identity boundary must remove usable instance-role
credentials from job execution. The finding remains dispositioned `remediate`
and is handed to the runner-admission/workload-identity arc for deployed AWS
proof against ordinary and privileged host probes. The repo-side Gate E and
bootstrap changes do not close this identity boundary.

## Verification

- Prove on the deployed fleet that ordinary and privileged hostile job probes
  receive no usable metadata credential and that the effective permissions
  boundary remains attached and enforced.
- Record the deployed identity, metadata, teardown, and exact-ID dashboard
  evidence in the receiving arc. This packet claims none of it.
