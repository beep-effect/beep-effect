# CSF-006: Red\-team gate misses sudo IMDS credential path

- Severity: Medium
- Codex ID: `33cd94a12d788191afbec1edc25c433f`
- Source commit: `e65b2ff6d8655921a0dec7635bd990eab11a5c28`
- Owner: CI runner workload identity
- Status: confirmed; remediate; architecture/deployment-blocked

## Public Summary

The fleet red-team workflow verifies that the ordinary runner user cannot read instance-role credentials, but it does not test privileged/root access or permissions-boundary drift. The test can therefore pass while a pull-request job still has a path to usable AWS credentials.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`; disposition: `remediate`.

The shadow check accepts AWS CLI credential failures as proof for the non-root account and separately tests container metadata access. It has no privileged-host probe and no assertion that the attached permissions boundary still constrains the effective role. The companion red-team script expects four gates only, so these missing assertions are not enforced elsewhere.

Evidence:

- `.github/workflows/fleet-shadow-check.yml:87` begins the non-root host credential probe, and `.github/workflows/fleet-shadow-check.yml:103` treats expected credential errors as a passing result.
- `.github/workflows/fleet-shadow-check.yml:185` tests metadata from a container but does not test privileged host access.
- `.github/workflows/fleet-shadow-check.yml:206` summarizes only the existing four gates.
- `goals/ci-fleet-endgame/ops/redteam-verify.sh:99` requires exactly those four gates and has no permissions-boundary assertion.

## Remediation

The fleet workflow and verifier now name and count Gate E, but that local
assertion cannot prevent a privileged job from reaching host metadata. This
finding remains dispositioned `remediate` and is handed to the runner-
admission/workload-identity arc until a root-resistant identity boundary and
deployed AWS proof land.

## Verification

- After the identity boundary is deployed, run
  `goals/ci-fleet-endgame/ops/redteam-verify.sh <deployed-ref>` and require
  exactly one PASS for Gates A, B, C, D, and `E_RUNNER_IMDS_HOOK`.
- Prove that a privileged probe obtains no usable credential, the effective
  permissions boundary remains enforced, and runner deregistration plus EC2
  teardown complete. Exact-ID dashboard closure remains with the receiving arc.
