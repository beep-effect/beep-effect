# CSF-007: Yeet publish writes generated index through symlinks

- Severity: Medium
- Codex ID: `87e92cedfe34819189e2747d988cd0bb`
- Source commit: `450d11b32f55e8a62049e1c7de8279914fe07e44`
- Owner: repository CLI safe writes
- Status: confirmed; remediate; repo-side remediated

## Public Summary

The Yeet portfolio-index repair writes directly to the expected index pathname without rejecting symbolic links. In a writable checkout, a crafted index symlink can redirect the repair outside the intended file while the command still stages the apparent repository path.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`; disposition: `remediate`.

The repair computes the index path by joining the repository root and configured relative path, then writes to it with the ordinary filesystem API. There is no `lstat`, resolved-path containment check, or no-follow operation before the write, and the resulting repository path is passed to `git add`.

Evidence:

- `packages/tooling/tool/cli/src/commands/Yeet/internal/PortfolioIndexGuard.ts:203` constructs the target pathname and reads it directly.
- `packages/tooling/tool/cli/src/commands/Yeet/internal/PortfolioIndexGuard.ts:230` writes regenerated content to that path without a symlink check.
- `packages/tooling/tool/cli/src/commands/Yeet/internal/PortfolioIndexGuard.ts:232` stages the apparent repository-relative path after the write.

## Remediation

Portfolio-index regeneration now writes through a shared contained-write helper
that rejects lexical escapes and symlinked targets or parent components,
rechecks canonical containment immediately before mutation, and atomically
renames a private temporary file. Git staging runs only after the guarded write
succeeds.

Changed files:

- `packages/tooling/tool/cli/src/internal/cli/FsGuards.ts`
- `packages/tooling/tool/cli/src/commands/Yeet/internal/PortfolioIndexGuard.ts`
- `packages/tooling/tool/cli/test/yeet-portfolio-index-guard.test.ts`

## Verification

- `packages/tooling/tool/cli/test/yeet-portfolio-index-guard.test.ts` is part of
  the focused safe-write run: 5 files, 73/73 tests passed with the threads pool.
- Command: `cd packages/tooling/tool/cli && zsh -ic 'bunx --bun vitest run test/yeet-portfolio-index-guard.test.ts test/yeet-inbox.test.ts test/yeet-remediation.test.ts test/yeet-ack.test.ts test/yeet-inbox-view.test.ts --pool=threads'`.
- The test proves final-file and parent-directory symlink rejection, no external
  destination change, and no staged Git path after refusal.

Residual risk: Effect's portable filesystem API has no directory-handle-
relative rename. The helper rechecks immediately before mutation, but a
principal that can concurrently rename checkout parents retains a narrow
time-of-check/time-of-use race; filesystem permissions remain that boundary.
