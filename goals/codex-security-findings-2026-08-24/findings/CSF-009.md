# CSF-009: IMDS hook can silently remain unarmed

- Severity: Medium
- Codex ID: `d1f026deb21881919d853e63780734fe`
- Source commit: `4c952edb18dad422e3fa5f95305fc3b0e15c392f`
- Owner: CI runner workload identity
- Status: confirmed; remediate; repo-side remediated; deployment proof pending

## Public Summary

The runner bootstrap treats a missing runner work directory as a successful metadata-firewall setup. The host can therefore register and accept jobs without installing the intended UID-scoped instance-metadata block.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`; disposition: `remediate`.

The bootstrap hook logs that the metadata guard was not armed when it cannot locate the runner directory, but it does not exit unsuccessfully. The fleet verification workflow and red-team script also do not include the documented deployment gate that would prove the hook was installed before registration.

Evidence:

- `infra/src/CiFleetController.ts:103` handles a missing runner directory, and `infra/src/CiFleetController.ts:111` records the condition without terminating bootstrap.
- `infra/src/CiFleetController.ts:344` documents the deployment-time metadata gate as a separate requirement.
- `.github/workflows/fleet-shadow-check.yml:206` reports only four gates and omits that deployment assertion.
- `goals/ci-fleet-endgame/ops/redteam-verify.sh:99` also accepts a four-gate report.

## Remediation

Runner bootstrap now exits unsuccessfully before registration when it cannot
arm the job-start metadata hook. The shadow workflow promotes the runner-user
IMDSv2 token PUT probe to named Gate E, and the red-team verifier requires
exactly one PASS for every named Gate A through Gate E.

Changed files:

- `infra/src/CiFleetController.ts`
- `.github/workflows/fleet-shadow-check.yml`
- `goals/ci-fleet-endgame/ops/redteam-verify.sh`
- `infra/test/CiFleetController.test.ts`
