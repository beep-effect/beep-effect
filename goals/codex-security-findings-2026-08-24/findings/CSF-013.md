# CSF-013: Watch inbox follows repo symlinks for failure writes

- Severity: Low
- Codex ID: `6cb93ab3587c81918330133bba28926a`
- Source commit: `2817f286d3236a935259f9465a9a2ba1bca61988`
- Owner: repository CLI safe writes
- Status: confirmed; remediate; repo-side remediated

## Public Summary

Yeet appends failure entries and writes remediation dispatches to predictable paths without rejecting symbolic links. A crafted checkout can redirect either write to another writable location when an operator runs the command.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`; disposition: `remediate`.

Both paths are assembled beneath the repository root and written with ordinary filesystem operations after creating parent directories. Neither implementation inspects existing parents or the final entry with `lstat`, verifies the resolved destination remains contained, or uses a no-follow write.

Evidence:

- `packages/tooling/tool/cli/src/commands/Yeet/internal/Inbox.ts:335` constructs the inbox paths.
- `packages/tooling/tool/cli/src/commands/Yeet/internal/Inbox.ts:483` creates the failures parent and `packages/tooling/tool/cli/src/commands/Yeet/internal/Inbox.ts:491` appends directly to the target.
- `packages/tooling/tool/cli/src/commands/Yeet/internal/Remediation.ts:413` constructs the dispatch path.
- `packages/tooling/tool/cli/src/commands/Yeet/internal/Remediation.ts:473` writes the dispatch directly after creating its parent.

## Remediation

Inbox failure appends and remediation dispatch writes now use the shared
contained no-follow helpers. They reject lexical escapes plus symlinked targets
and parents. Dispatch replacement uses a private temporary file and atomic
rename; existing-file append uses a verified private hard-link alias so the
predictable target pathname is never opened for writing.

Changed files:

- `packages/tooling/tool/cli/src/internal/cli/FsGuards.ts`
- `packages/tooling/tool/cli/src/commands/Yeet/internal/Inbox.ts`
- `packages/tooling/tool/cli/src/commands/Yeet/internal/Remediation.ts`
- `packages/tooling/tool/cli/test/yeet-inbox.test.ts`
- `packages/tooling/tool/cli/test/yeet-remediation.test.ts`

## Verification

- `yeet-inbox.test.ts` and `yeet-remediation.test.ts` are part of the focused
  safe-write run: 5 files, 73/73 tests passed with the threads pool.
- Command: `cd packages/tooling/tool/cli && zsh -ic 'bunx --bun vitest run test/yeet-portfolio-index-guard.test.ts test/yeet-inbox.test.ts test/yeet-remediation.test.ts test/yeet-ack.test.ts test/yeet-inbox-view.test.ts --pool=threads'`.
- The tests cover symlinked final files and parent directories and prove the
  external destinations remain unchanged.

Residual risk: Effect's portable filesystem API lacks directory-handle-relative
link and rename operations. Immediate rechecks narrow but cannot eliminate a
concurrent parent-rename race. Existing-file append also requires hard-link
support and fails with a typed guard error if the filesystem refuses it.
