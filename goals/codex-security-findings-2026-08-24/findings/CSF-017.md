# CSF-017: Check flake quarantine rerun no longer filters packages

- Severity: Informational
- Codex ID: `57be126aec5481918f04d9d0df882b6f`
- Source commit: `6418482c7f275d5343a6b6d8d6d7a367cdf7c392`
- Owner: flake-quarantine scoping
- Status: confirmed; remediate; repo-side remediated

## Public Summary

Flake quarantine appends Turbo filters after a `--` separator for nested quality commands. For the `bun run beep ci lane check` shape, that filter is forwarded to the CLI rather than the underlying Turbo invocation, so the retry may run a broader scope than the quarantined package.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`; disposition: `remediate`.

The filter helper recognizes only a direct Turbo command. All other commands receive `-- --filter=...`. The quality check task is a nested Beep CLI lane command, and the GitHub-check retry attaches quarantine to that shape. A direct probe produces `bun run beep ci lane check --affected -- --filter=@beep/schema`, confirming the misplaced filter.

Evidence:

- `packages/tooling/tool/cli/src/commands/Quality/internal/FlakeQuarantine.ts` defines filter insertion and previously used the passthrough form for every non-Turbo command.
- `packages/tooling/tool/cli/src/commands/Ci/CiLane.ts` defines the nested `ci lane check` command.
- `packages/tooling/tool/cli/src/commands/Quality/internal/GithubChecks.ts` attaches quarantine scoping to that quality-check command.

## Remediation

Flake quarantine now recognizes nested `bun run beep ci lane` steps and appends
the package filter to that command rather than to its child passthrough. The CI
lane parser accepts `--filter` and forwards it into the underlying Turbo
arguments.

Changed files:

- `packages/tooling/tool/cli/src/commands/Quality/internal/FlakeQuarantine.ts`
- `packages/tooling/tool/cli/src/commands/Ci/CiLane.ts`
- `packages/tooling/tool/cli/test/flake-quarantine.test.ts`
- `packages/tooling/tool/cli/test/quality-tasks.test.ts`
