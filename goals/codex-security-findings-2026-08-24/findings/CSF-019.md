# CSF-019: delete\-package can recursively remove workspace container trees

- Severity: Informational
- Codex ID: `e3026e33c5448191bdb579132e2c6864`
- Source commit: `e97f73be4467e2d1899219cf9c3ac80fd148fb9d`
- Owner: delete-package safety
- Status: confirmed; remediate; repo-side remediated

## Public Summary

Delete-package accepts any workspace returned by the workspace inventory and later removes its directory recursively. It does not reject a workspace root or a workspace directory that contains other registered workspaces, so one request can erase unrelated packages while dependency scanning omits the descendants from its safety analysis.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`; disposition: `remediate`.

Target resolution records the selected workspace path without checking whether it is the repository root or an ancestor of another workspace. The registration probe skips every file under that target, and apply performs a forced recursive removal. This remains exploitable by a branch that changes workspace registration before an operator runs the command, even if the present workspace graph happens to contain leaf packages only.

Evidence:

- `packages/tooling/tool/cli/src/commands/DeletePackage/DeletePackage.command.ts:154` resolves the selected workspace and `packages/tooling/tool/cli/src/commands/DeletePackage/DeletePackage.command.ts:184` stores its relative directory without an ancestor guard.
- `packages/tooling/tool/cli/src/internal/cli/RegistrationGeometry/RegistrationGeometry.probes.ts` excludes the target subtree from ordinary dependency scanning.
- `packages/tooling/tool/cli/src/commands/DeletePackage/DeletePackage.policy.ts:46` contains no root-or-ancestor refusal in the policy checks.
- `packages/tooling/tool/cli/src/commands/DeletePackage/DeletePackage.command.ts:719` removes the target recursively and forcibly.

## Remediation

Target resolution now carries the complete resolved workspace-path inventory.
DeletePackage refuses the repository root and any workspace that contains
another resolved workspace before planning, repeats the topology guard
immediately before apply mutations, and reports descendant workspaces as hard
file-path dependents in registration geometry.

Changed files:

- `packages/tooling/tool/cli/src/commands/DeletePackage/DeletePackage.command.ts`
- `packages/tooling/tool/cli/src/commands/DeletePackage/DeletePackage.policy.ts`
- `packages/tooling/tool/cli/src/internal/cli/RegistrationGeometry/RegistrationGeometry.probes.ts`
- `packages/tooling/tool/cli/test/delete-package.test.ts`

Residual risk: tests use dry-run command paths and direct geometry calls rather
than a real recursive deletion. The apply boundary re-resolves workspace paths
immediately before mutation, but a concurrent external workspace rewrite
between that check and removal remains outside the command's control.
