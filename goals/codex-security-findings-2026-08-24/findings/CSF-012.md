# CSF-012: Docgen watchdog logs system process command lines

- Severity: Low
- Codex ID: `574797607d308191935c448d70f7c1d9`
- Source commit: `0f224c9a3a8a091a6f835a07786071a94462178c`
- Owner: docgen process diagnostics
- Status: confirmed; remediate; repo-side remediated

## Public Summary

The docgen stall watchdog enumerates command-line arguments for every process on the host and can print matching rows into CI logs. Unrelated processes may carry credentials or other sensitive values in their arguments, so repository code can cause those values to be disclosed.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`; disposition: `remediate`.

The watchdog runs a host-wide `ps` command with the full arguments column and filters the resulting text after collection. It does not restrict inspection to the docgen child tree or sanitize argument values before logging diagnostics.

Evidence:

- `packages/tooling/tool/cli/src/commands/Docgen/internal/Local.ts:512` defines the stall-diagnostic process snapshot.
- `packages/tooling/tool/cli/src/commands/Docgen/internal/Local.ts:520` invokes `ps` with the full `args` column for all processes.
- `packages/tooling/tool/cli/src/commands/Docgen/internal/Local.ts:527` filters and returns raw matching rows for diagnostic output.

## Remediation

The watchdog retains the spawned child PID, queries only that PID and recursively
discovered direct children, caps the snapshot at 40 rows, and logs only PID,
PPID, executable identity, state, and elapsed time. It no longer enumerates the
host process table or requests the `args` column.

Changed files:

- `packages/tooling/tool/cli/src/commands/Docgen/internal/Local.ts`
- `packages/tooling/tool/cli/test/docgen-stall-watchdog.test.ts`

## Verification

- `packages/tooling/tool/cli/test/docgen-stall-watchdog.test.ts`: 1 file, 6/6
  tests passed with the threads pool.
- Command: `cd packages/tooling/tool/cli && zsh -ic 'bun run beep:test test/docgen-stall-watchdog.test.ts --pool=threads'`.
- The live fixture proves an unrelated sibling PID and an argv canary never
  enter diagnostics while executable identity and state remain present.

Residual risk: the bounded collector depends on Linux/procps `ps` support for
`-p`, `--ppid`, `etimes`, `stat`, and `comm`. Process trees can change during a
snapshot, so exiting or reparented descendants may be absent; the collector
never widens to a host-wide query. The default fork pool failed to start in the
sandbox, and direct `bun test` timed out through its Vitest compatibility path.
