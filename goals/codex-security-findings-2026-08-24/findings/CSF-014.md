# CSF-014: POSIX path redaction bypass after punctuation

- Severity: Low
- Codex ID: `8f79050754fc8191b3e7675886f6059a`
- Source commit: `81ffcb13e3e09d0440c0be83fa80e9365bcee953`
- Owner: knowledge diagnostic redaction
- Status: confirmed; remediate; repo-side remediated

## Public Summary

Knowledge-command path redaction recognizes absolute POSIX paths only after a narrow set of delimiters. Paths adjacent to other punctuation, such as angle brackets or semicolons, remain intact and can disclose checkout or user names in committed diagnostic artifacts.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`; disposition: `remediate`.

The sanitizer's lookbehind permits only the beginning of the string, whitespace, or a small opener set before `/`. Direct probes against the exported sanitizer confirm that a whitespace-prefixed path is redacted while the same path after `<` or `;` is returned unchanged.

Evidence:

- `packages/tooling/tool/cli/src/commands/Knowledge/Knowledge.service.ts:106` defines the restricted POSIX boundary expression.
- `packages/tooling/tool/cli/src/commands/Knowledge/Knowledge.service.ts:135` applies that expression to diagnostic text.
- `packages/tooling/tool/cli/src/commands/Knowledge/Knowledge.service.ts:146` returns the sanitized result without a broader fallback for punctuation-delimited paths.

## Remediation

The sanitizer now blocks only Unicode word and slash adjacency before an
absolute POSIX path. Punctuation-delimited paths are redacted, while URLs and
ASCII or Unicode word-adjacent slash fragments remain intact.

- `packages/tooling/tool/cli/src/commands/Knowledge/Knowledge.service.ts`
