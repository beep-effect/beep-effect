# Reflection: codex-security-findings-2026-08-24 (2026-08-24, codex)

## Summary

The packet is complete and retained. All 19 findings were validated, PR #783
contains 15 repository remediations, and 13 dashboard IDs closed as Already
fixed on 2026-08-24. Two repo-fixed IDs remain open for a fresh deployment
proof, and four runner findings moved to `goals/runner-trust-boundary` with
their exact identities and evidence requirements intact.

## Tooling experience

- **Worked:** The sanitized triage ledger preserved Codex IDs, which made it
  possible to match recurring runner findings across three captures even when
  their CSF ordinals changed.
- **Didn't:** Packet-local disposition and `codexStatus` fields could not express
  the difference between a repo-side fix held for deployment proof and a
  finding transferred for new architecture work.
- **Frustrating:** The phrase "remediated repo-side" was easy to mistake for
  deployed proof or dashboard closure, although those are separate states.
- **Wished existed:** A goal command that groups repeated Codex IDs across
  packets and prints current owner, required proof, and dashboard state.

## Implementation improvement opportunities

- Extend the triage schema with typed receiving-goal and external-proof fields.
- Generate the transfer table from Codex IDs so packet-local ordinal changes
  cannot break identity continuity.
- Keep dashboard closure metadata separate from repository disposition.

## Goal and prompt critique

The original zero-open completion rule conflated source-packet completion with
the completion of external security work. A clearer rule would allow
`completed-retained` after repository work is terminal when every remaining ID
has a named receiving goal, a current dashboard state, and an explicit proof
gate. It should still forbid accepted risk and unowned deferral.

## TODOs worth codifying

- Add typed Codex handoffs and held-proof states to the triage model.
- Add exact-ID reconciliation across retained findings packets.
- Teach goal doctor to reject a completed security packet whose open IDs lack a
  receiving goal and proof requirement.

## Lessons by confidence

- **HIGH, critical:** Match findings by Codex ID. CSF ordinals changed across
  captures, while four runner identities stayed the same.
- **HIGH, best practice:** Record repository, deployment, and dashboard state
  separately. PR #783 proves code state but does not supply the fresh fleet
  proof required for CSF-003 and CSF-009.
- **MEDIUM, consideration:** A source packet can close without hiding risk when
  every open identity has an explicit receiving packet and evidence boundary.
