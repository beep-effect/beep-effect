# Protected producer workflow preparation

The manual main-only caller selects only stable or canary, then routes the fixed
producer command through the already admitted Heavy workflow. The mode defaults
off, excludes the other two operational modes and leaves every ordinary quality
context intact. The existing `turbo-cache-write` environment remains the branch
protection boundary. No new environment or cloud resource is created.

The caller forwards eleven named fields. GitHub documents that environment
secrets also need named forwarding or inheritance in reusable calls; this route
uses explicit names. Per-channel approval/runtime/issuer records are delivered
only to `producer-install --from-environment`. The execution step gets only its
trial signing, storage and role capabilities. The separate publication step gets
only storage credentials and cannot rerun producer execution. Verifier ownership
stays off the runner.

Before issuer delivery, the workflow requires an explicit enable, exact source
SHA and independently selected candidate run/artifact/binary identities. It
verifies the downloaded executable and current policy input hashes. Its closed
preparation builds only the identity-lint activation preview, dependency receipt,
two registered same-source sibling worktrees and the full pilot request. The
canary archive and executable are checked against the accepted pins; no caller
can supply a command, source override, summary, upload report or signing payload.

The budget is one concurrent existing runner for at most sixty minutes, with a
fifty-minute outer producer limit. Existing comparison/protocol/upload limits
remain twenty/fifteen/ten minutes respectively, so the outer timeout permits
their complete worst-case sum. Trial storage/operation limits are unchanged and
must be accounted for in the concrete activation preview. Only the bounded
64-KiB digest report is uploaded to Actions for one day. The complete issued
observation goes through the existing private R2 publisher. Cleanup selects only
the frozen private directory, owned input path and exact worktrees, without force.

This source preparation has not been activated or executed. Syntax and targeted
formatting were checked; security assertions and seven real selection-shell
cases are authored for hosted CI. No local package/verify/publish proof or test
suite ran. Current hosted proof, independent source/tool/profile approval, real
secret delivery, signed R2 execution/import, rollout and all observation windows
remain required. Every trust-goal acceptance criterion remains unproven.
