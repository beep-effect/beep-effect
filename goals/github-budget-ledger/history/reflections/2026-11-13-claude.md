# Reflection: github-budget-ledger (2026-11-13, claude)

## Summary

The goal shipped the host-scoped GitHub budget ledger (#3068) and two accounting corrections found from live data
(#3200 credential buckets, #3247 GraphQL windows as reset-scoped instances). This closeout adds the 24 h hub
baseline and the T3 share threshold. The baseline resolved the 430 vs 720-1,440 GraphQL/h conflict: a monitor
spends about 94 points per process-hour, so the old per-monitor estimate was 8-15 times too high. The fleet's
GraphQL load comes from running 15-26 monitors at once. The T3 bound (median 46%, p90 66%) stays below the 60% and
1,500 points/h gate.

## Tooling experience

- **Worked:** `beep github ledger report --json` gave per-hour, per-key, per-command data that needed no
  re-derivation. `calibrate` was cheap (6 points) and its median rule handled the second-window outliers. The
  `github-headroom` parcel was already in the SessionStart output. The ordinary worker SSH wrappers ran the report
  on tbk-worker and dankserver without touches.
- **Didn't:** calibration had not run after the implementation merged (see findings). zsh does not word-split
  `$var`, which broke a quick loop that worked in bash.
- **Frustrating:** the text report's all-zero resource lines.
- **Wished existed:** a fleet aggregation mode for the A19 bound.

## Implementation improvement opportunities

- A `--fleet` report mode that computes the A19 residual and share statistics.
- Per-command gh-spawn cost estimates above one point. `gh pr view --json` with many fields costs more than one
  GraphQL point, so the residual partly holds understated gh spend from attributed commands.
- Count monitor process-hours (distinct PIDs per command per hour) in rollups, so per-process rates come from the
  report instead of raw rows that age out after 72 h.

## Goal & prompt critique

- GOAL.md was clear, and its done condition (`closeout.status == initiative.status` on `origin/main`) is mechanical.
- The "Baseline recorded" criterion should name which fleet hosts must report. "Every fleet host with repo tooling"
  left the choice to the closer. tom-pc-1 had no ledger, and beep-worker and grok-bot were not reached. The bound
  stays conservative either way, but the criterion should say so.
- A16's "two-PR closeout" citation is stale against the current one-PR law.

## TODOs worth codifying

- Fleet mode for `ledger report`; a calibration-missing warning; retire stale two-PR closeout wording.

## Lessons (confidence-tiered)

- **HIGH (critical):** Re-measure a quota estimate from live headers before planning a reduction around it. The
  720-1,440 GraphQL/h per-monitor figure would have sized github-state-worker's savings 8-15 times too large.
- **MEDIUM (best practice):** Give every "after merge, run X once" step in a design a check that can fail.
  Calibration was a prose instruction and was missed.
- **LOW (consideration):** A share threshold needs an absolute floor once a sibling goal is set to shrink the
  denominator. Otherwise removing Yeet spend would fire the T3 gate without T3 changing.
