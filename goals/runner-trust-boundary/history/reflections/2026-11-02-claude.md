# Reflection — runner-trust-boundary (2026-11-02, claude)

## Summary

P8 closed on an operator decision rather than on proof. A fresh A-through-L
red team re-proved that the runner class has no usable ambient instance-role
credentials. Probe N then showed that a leaked one-use JIT configuration is
refused from the original and a second host after an orderly listener stop,
but accepted after a SIGKILL stop until the original job ends. A 12-minute
held replay session started no job. The operator accepted that bounded
residual as E1.

## Tooling experience

- **Worked:** aws-vault for read-only fleet audits and for the disposable
  second host; the EC2 serial console as an AWS-private channel for verdicts
  and the RSA-OAEP-wrapped configuration; CloudWatch logs of the termination
  and deregistration Lambdas, which reconstructed run 1's timeline exactly;
  `yeet reply` for review threads.
- **Didn't:** the first probe run lost both verdicts to two classifier and
  ordering bugs; the red-team verifier's deregistration gate had been
  vacuous since August.
- **Frustrating:** every probe change needed a full merge cycle because the
  runner group admits the workflow only from `main`; Vercel rate-limit rows
  arrived on every push.
- **Wished existed:** a sanctioned way to run a fleet probe from a branch on a
  dedicated, non-admitting runner group, so probe iterations do not ride
  through `main`.

## Implementation improvement opportunities

- Make Probe M and Probe N share one replay classifier file instead of three
  copies of the marker list (workflow M, workflow N, second-host user-data).
- Record the matched listener line for every verdict, accepted included, so a
  verdict can be audited without a rerun.

## Goal & prompt critique

- E1's removal condition should have named the SIGKILL stop explicitly; the
  orderly stop alone is the runner's normal path, not the attacker's.
- The session brief's done condition ("no recoverable handoff credential and
  no server-side replay") cannot hold on this fleet: with sudo in job code the
  credential is always recoverable, and replay after a SIGKILL is accepted
  until the job ends. The packet closed on the operator's acceptance of that
  residual, which the brief did not anticipate as an exit.

## TODOs worth codifying

- A shared, source-cited runner replay classifier.
- A lint for pkill -f with relative launches.
- Organization-roster defaults in runner tooling.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Check a surprising security verdict against the
  upstream source before escalating it. — Run 1's "accepted" came from a
  marker printed before any session request; run 3 later confirmed the
  finding with the correct marker.
- **HIGH — Critical:** A deregistration gate must first see the runner on the
  roster it watches. — The repository-roster read made P4's lifecycle proof
  vacuous for two months.
- **MEDIUM — Best practice:** Keep a credential that must leave a VM inside
  AWS-private channels (serial console, user-data) and wrap it to a one-time
  key; never route it through job logs. — Both runs moved the value without it
  touching a log or the operator workstation.
- **LOW — Consideration:** Stopping a process tree from the inside needs
  ordering care; disarm the parent's side effects before killing children.
