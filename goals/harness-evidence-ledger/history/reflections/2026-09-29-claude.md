# Reflection — harness-evidence-ledger (2026-09-29, claude)

## Summary

The packet built a typed, append-only ledger for harness edits, evidence that
expires by config fingerprint, and pruning proposals scoped to the current
harness regime. It reran the parked SkillOpt pilot twice. The second run, on a
scorer that measures only the agent's edit, showed that the earlier baselines
measured a broken sandbox and that the corpus has no headroom at this model
strength. No trained skill is adopted.

## Tooling experience

- **Worked:** Workflows with briefs written to files and one implementer per
  slice with a strict file ownership list. Three agents edited one worktree at
  the same time without a conflict. The reproduce-before-report review
  returned twelve findings that all held. `systemd-run --user` kept the rerun
  alive and out of the session. The rerun preflight caught nothing this time,
  which is what it is for.
- **Didn't:** The Agent tool could not pin the model id the repo law
  requires. The settings edit for the `SessionStart` hook was denied, so the
  feature ships inert until a human adds one entry.
- **Frustrating:** The inventory refresh rewrote the whole file. The first
  baseline rollouts finishing in 30 seconds with perfect scores looked like a
  fault and cost a verification pass, because every earlier run had taught that
  this scorer returns about 0.5.
- **Wished existed:** A scorer self-test. A scoped inventory write. A way to
  run a target agent with the corpus mounted read-only.

## Implementation improvement opportunities

- The screen's term list is tuned on two known-bad diffs. It passed a
  candidate whose added text speaks of what "the inventory lint flags" and what
  "the precision audit checks". A rule for checker-directed language would have
  flagged it for a human.
- The shell mirror of the config snapshot walks the whole repository to depth
  eight for nested agent docs and takes about one second. The TypeScript
  snapshot takes about six. Narrowing the walk in both would make the stamp
  close to free.
- The config snapshot does not include `.mcp.json`, although D3 names the
  enabled MCP set as part of the fingerprint. Enabling or removing a server
  does not expire evidence today.
- Codex and Cursor sessions are not stamped, so they never count toward a
  pruning window.
- Declaration files written by an agent are penalised, not type-checked.

## Goal & prompt critique

The launcher was clear about rules and stop conditions, and those held under
pressure: the settings denial matched "never apply a harness edit without
human admission" exactly. Two edits would have saved time. First, `GOAL.md`
should have said "measure the scorer before measuring the skill"; the packet
inherited the pilot's scorer as trusted. Second, the two-PR split in the
routine calls priced review convenience above runner cost. One PR with
reviewed commits was cheaper and no harder to read, and the operator had to
say so.

## TODOs worth codifying

- Scorer self-test as a preflight step for any eval-driven loop.
- Baseline noise band printed beside every gate verdict.
- Human admission step written into any packet that changes hook wiring.
- Workflow route named as the way to pin a child model id.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Validate the instrument before reading it — two
  packets and one week of conclusions rested on a scorer floor that three
  fixture copies and four seconds each would have exposed.
- **HIGH — Critical:** Green checks are not a review — twelve reproduced
  defects sat under passing tests, types, and lints, one of them a complete
  bypass of the scoring laws.
- **MEDIUM — Best practice:** Record a rejection as evidence and an
  acceptance as a proposal — the machine wrote four `rejected` rows and left
  four `proposed`, which keeps negative evidence without taking a decision
  that belongs to a human.
- **MEDIUM — Best practice:** Prefer a missing stamp to a wrong one — the
  shell mirror drops the stamp whenever parity is in doubt, so the worst case
  is a session that does not count.
- **LOW — Consideration:** An annealed budget may still help on a corpus with
  headroom — this run could not test it, so the question stays open rather
  than answered.
