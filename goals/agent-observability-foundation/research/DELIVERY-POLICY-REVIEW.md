# Delivery policy remediation — 2026-10-29

The current-main delivery gates exposed 306 inline schema compiler constructions (294 in the first targeted scan plus 12 in the CLI synthetic fixture) and 541 new Effect Vitest review candidates. The gates were not waived. Static schema compiler calls moved to module scope, reusing their parser identity while retaining exact schema/options. Runtime validation remains unchanged. Per-test setup/cleanup budgets are explicit; terminal whole-test scopes were removed because the installed Effect Vitest runners already scope their bodies. Terminal platform provisions became separate layer registrations per existing test, preserving SQLite/temporary-file/process ownership. Shorter scopes that close a resource before assertions remain.

Exact optional-value comparisons use Effect Vitest assertion helpers. Partial object assertions were split into their actual known fields; absent fields remain unknown. Mocked runtime scheduling now advances TestClock instead of sleeping or polling. Each adjusting Git probe/managed session test owns its own clock. Pure native trace/export tests use Crypto only. CLI rendering/inventory fixtures use an in-memory filesystem and a spawner that defects on any attempted process launch. Real crash tests retain native resources.

The independent Astra panel reviewed the original candidates and current detector semantics. It accepted narrowly recorded native-resource and shorter-lifetime exceptions, rejected generic filesystem exceptions for pure projections/rendering, required explicit clock isolation, and accepted the separate cache-input basis. Exceptions must name the observed semantic dependency and exit condition; full baseline regeneration is only after all remaining rows are adjudicated. No blanket acceptance is authorized.

Intermediate evidence: the initial codec/lifetime repair passed full ai-metrics audit (120.9 seconds) and docgen (11.4 seconds), with 5.1 GiB peak and zero additional swap. After the mock-clock and assertion repairs, the full audit passed again (124.7 seconds), with docgen passing in 11.5 seconds. Phoenix audit/docgen passed in 13.8/6.8 seconds and provider CLI in 25.5/6.7 seconds. Focused runtime-clock and CLI fixture tests also passed. The final 12 synthetic CLI fixture codecs require their own refreshed test pass. Earlier failed checks remain in their logs; they are not counted as passing evidence.

The first clock conversion exposed two test construction problems: regression fixtures used negative time from TestClock's zero epoch, and moving the synthetic epoch past a test-body timeout fired that timer. Tests now start at a positive synthetic epoch and rely on the test runner's real timeout for containment, while exercising the runtime's own controlled deadline explicitly. This changes test mechanics, not production time or recovery semantics.

Recovery hold and historical archives remain intact. No production collector enrollment or service deployment occurred in this repair wave.

The independent follow-up accepted all 31 semantic exceptions after four descriptions were corrected to distinguish independent file-backed launch authority from optional collector SQLite facts. It also verified the generated cache projection: no commands, cache flags, output contracts or qualification changed; the additional three uncached task dependency graphs follow the reviewed manifest additions.
