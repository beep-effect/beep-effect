# Reflection — canonical-digest-owner (2026-11-13, claude)

## Summary

The goal did what it set out to do. RFC 8785 through `JsoncFingerprint` is the
one encoder behind every canonical digest this repository mints, the four
hand-rolled encoders are gone, `sha256:` has one grammar in `@beep/schema`,
and a lint rule rejects the shape those encoders were built in. No stored
digest changed: all 76 stored packet events, the 13 fixture events, the four
golden execution seals and the W1 corpus hash recompute through the owner.
It took six pull requests where four were planned (3129, 3173, 3193, 3204,
3209, after the graduation in 3096), because slice C merged before its review
finished and the fix had to follow it onto `main`.

## Tooling experience

- **Worked:** the slice A order. A census, a differential property test and a
  replay of stored digests, all landed before any encoder was touched, meant
  each swap in slice C was a body replacement with the proof already green.
  One commit per encoder kept each swap separately revertable. Fallow's
  duplication audit caught a copied helper that review had passed.
  `quality package-verify --quick` per touched package was fast enough to run
  before every push.
- **Didn't:** the merge path. Two of the four slices merged before their
  owner called them final (3173 as a draft; 3193 at a head under review).
  The cache-policy audit is local only, so a new workspace dependency went
  through green hosted checks and then blocked every lane's cheap gates.
- **Frustrating:** `yeet final-check` re-measures the whole repository's
  coverage when a diff touches `@beep/schema`, so slices B and C skipped that
  gate by name and leaned on hosted coverage, which was itself red on `main`
  for an unrelated `@beep/repo-cli` episode during slice B. A lane switched
  to a new branch kept a stale install, and the check gate failed in a
  package the diff did not touch.
- **Wished existed:** a record of who marks a pull request ready, and a merge
  gate that reads the owning session's `final` post instead of the ready
  flag alone.

## Implementation improvement opportunities

- The refusal-to-`SchemaError` mapping should live once on the owner; today
  the epistemics twin and the PacketCore twin each write it.
- Free-text fields that feed a digest still accept an unpaired surrogate at
  decode and refuse it only at seal time. A well-formed-text schema would
  move the failure to the boundary and give the callers without a typed
  channel (the execution-record seals, `retentionPayloadBytes`) nothing left
  to throw on.
- The guard's diagnostic names a path inside this packet.
- `routeFootprintCanonicalJson` and the other rows under "Seen while reading,
  outside this goal" in the census are still as found.

## Goal & prompt critique

The packet was the right size and its acceptance criteria were checkable.
One sentence was missing. Under "Exports stay", `SPEC.md` should have said:
"A refusal is thrown only where the caller has no typed channel; a helper
that returns `Result` or an Effect with a `SchemaError` channel reports it
there, and a schema guard answers false." The census had the call sites on
2026-11-12. I carried the question into the slice C brief as "list each
site" instead of ruling on it, and that is where the extra pull request came
from.

The slice B wording "a pre-pass that drops undefined members" was also a
design decision made too early; it became an option on the owner's walk once
the walk's hardening was in view. Describing the contract (which values are
left out, which are still refused) without naming the mechanism would have
been enough.

## TODOs worth codifying

- A hosted check for the cache-policy audit.
- A well-formed-text schema for digest-feeding free text.
- One `SchemaError`-returning canonicalize function on `JsoncFingerprint`.
- A ledger record of which process marks a pull request ready.

## Lessons (confidence-tiered)

- **HIGH — Critical:** rule on how a new refusal surfaces before the slice
  that introduces it — the census named the call sites a day earlier, and
  deferring the ruling to review put three regressions on `main`.
- **HIGH — Critical:** tell the merging session to hold a pull request by
  number and head while a review round is open, and confirm it was read —
  a message that says "not final" did not stop a hand-merge of 3193.
- **MEDIUM — Best practice:** land the proof before the change. The
  differential test and the stored-digest replay from slice A made every
  later slice a question of "is the replay still green".
- **MEDIUM — Best practice:** after switching a lane to a new branch, run
  `bun install --frozen-lockfile` before any gate.
- **LOW — Consideration:** a syntactic guard covers the shape that was
  actually used, not every way to write the thing; say which in the rule's
  own documentation and keep the census as the list of exceptions.
