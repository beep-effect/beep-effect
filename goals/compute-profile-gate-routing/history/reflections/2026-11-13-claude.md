# Reflection — compute-profile-gate-routing (2026-11-13, claude)

## Summary

The goal gave every `beep` process a typed `workstation | worker` compute profile, read from the live cgroup, and made worker hosts defer hosted-only gates, catalog hooks and local proof to hosted CI. All seven acceptance criteria are met, with the worker ones shown on dankserver and beep-worker rather than only in tests. The design held; the cost was in finding its gaps late, on the real host.

## Tooling experience

- **Worked:** the cgroup probe (`bun run beep compute profile`, `--is worker` in under a second); the scheduler refusing hosted-only gates with the `yeet open` route printed; the Catalog Regeneration workflow pushing the regenerated shards with the knowledge-mint App token; `delegate_task` to the fleet hosts for the acceptance runs, with the write-up committed as a research file by the host lane itself.
- **Didn't:** forced gates before #3281. They ran at the workstation's width inside a 7 GiB slice and were killed by the pressure watchdog. Routing decisions taken without a ticket left no journal row until #3276.
- **Frustrating:** host drift. Stale local `main`, Bun 1.4.2 against a 1.4.4 pin, no git identity and a leftover `lefthook-local.yml` each interrupted an acceptance run. The draft-to-ready step was taken by the shared login twice before the lane could prove it.
- **Wished existed:** a type-check a worker may run on the test files it touched; a receipt field for the largest process of a run.

## Implementation improvement opportunities

- A subset `final-check` run now keeps its own receipt (this PR). Before, it replaced the head's.
- `forceLocal` is recorded on the journal row as requested and on the receipt as performed. That split is right but is explained only in the forced-gate research note; the runbook now carries it.
- The 1.5 GB RSS bound is checked by hand from scope peaks. The scheduler already samples the scope and could assert it.

## Goal & prompt critique

- Criterion 2 should have said from the start that refusing is a correct outcome on a small slice, and which measurement decides. The 2026-11-13 amendment is the wording it should have had.
- Criterion 3 chains six steps on a real host. The packet should have scheduled that run as its own phase before P2 merged, with the command list in SPEC, instead of leaving it to P2 Verify.
- "No local process above 1.5 GB RSS" needs a stated method (systemd scope peak plus the largest process sample), or two readers measure different things.

## TODOs worth codifying

- Worker bootstrap: pinned Bun, git identity, GitHub token reference; `beep worktree new` prints the base it used.
- A touched-tests type-check allowed under the worker profile.
- Host owner: remove the interim `lefthook-local.yml` on dankserver and fast-forward beep-worker's local `main`.

## Lessons (confidence-tiered)

- **HIGH — Critical:** run the host acceptance before calling a host-dependent slice implemented — three follow-up PRs and three host runs came from gaps no workstation test could show.
- **HIGH — Critical:** a gate that cannot fit a host must refuse with its measurement — a forced run that the watchdog kills leaves neither a proof nor a reason.
- **MEDIUM — Best practice:** have the host lane commit its own evidence file and open its own PR — the write-up then carries the real commands and output, and the PR itself is the proof of the `yeet open` to `yeet ready` path.
- **LOW — Consideration:** keep the routing table's measured rows per host in the runbook current when a host's slice size changes — the refusal reasons quote them.
