# Reflection — lexical-playground-capability-atlas (2026-08-25, claude)

## Summary

Goal A delivered the ratified capability contract and proved it end to end:
`@beep/editor/capability` (LiteralKit domains, descriptor/profile/resolved
schemas, typed `ProfileResolutionError`s, a deterministic resolver, one
resolved command registry projected into toolbar, slash picker, shortcut
help, and a guarded keybinding plugin), the compatibility profile that keeps
`EditorComposer` and `editorNodes` byte-identical, two production-kind
reference profiles proven in Storybook (15/15 Chromium) and in a
closed-by-default Professional Desktop shell panel, and a recorded browser QA
loop that closed on round 4 with `CAPTURE-GREEN` (82/82 assertions, zero app
console errors) and a `gpt-5.6-sol` inventory of zero findings. The atlas
gained five codec-backed compatibility corrections and retired the
`interchange.canonical-json` waiver on live evidence. Verdict: the goal's
acceptance is satisfied pending the hosted Yeet completion gate.

## Tooling experience

- **Worked:** the schema-first design brief
  (`research/P1-CAPABILITY-CONTRACT.md`) let two sequential Codex `codex exec`
  lanes implement ~5k lines with two review edits worth of deviation; the
  strict atlas reconciliation test caught every vocabulary drift (`lossy` vs
  `unsupported`, `node.tab`) immediately; `beep qa record → extract →
  judge-pack → codex judge → judge-ingest` produced a schema-validated
  inventory with correlated frames (beacon clock, 10 ms residual) and the
  round-3 judge found three real accessibility defects that no unit test
  expressed; `bun run beep quality changeset-status` and `goals doctor` gave
  exact, actionable failures.
- **Didn't:** the Codex sandbox cannot start vitest fork workers, so both
  lanes could only prove through a single-thread diagnostic lane; the
  Claude-in-Chrome extension was not connected, so visual verification ran
  through Playwright screenshots instead; `Data.tuple` written from v4
  priors did not exist.
- **Frustrating:** the Bash tool's working directory persists across calls,
  and four commands (a desktop test run, two `docgen:local` runs, a harness
  launch) silently ran in the wrong package until re-issued with absolute
  `cd`s; `jq` reflowing the biome-formatted atlas; `qa extract` taking
  `--session` where its siblings take `--round`; the witness collector's CORS
  noise on an https origin; `react-grab` arming on an editing chord.
- **Wished existed:** a `beep goals atlas set` row editor; a `QA_ROUND_DIR`
  contract for harnesses that live beside their app; a `qa doctor` probe for
  https origins; a `test:sandbox` lane for delegated agents.

## Implementation improvement opportunities

- Exhaustive `commandHandlers` over branded `CommandId` keys via an
  assertion-free branded-record constructor.
- A responsive single-pane upper dock at narrow widths is a shell redesign
  outside this goal; the narrow QA scenario exercises the panel maximized
  and the session notice now wraps, but the three fixed ontology columns at
  480 px remain a desktop-shell finding to route.
- `ShortcutHelp` could offer a collapsed state on very short boxes; today it
  is capped at `max-h-32` with its own scroll.
- The keybinding plugin swallows guarded chords silently; a development-only
  diagnostic that lists swallowed chords would make D3 behavior observable.

## Goal & prompt critique

- Add the P2 proof commands (Storybook Chromium lane, the `beep qa` chain
  from the checkout root, `VITE_REACT_GRAB=0`) to `GOAL.md`/`PLAN.md`
  verification so the next execution does not reconstruct them from skills
  and receipts.
- State in `GOAL.md` that `minimal` is an app-chosen subset (no atlas entry
  carries `minimal` eligibility) — the design had to derive this from a
  count.
- The touch-table row "new concept/role file → `beep architecture`" should
  be scoped to slices; it sent the design to a scaffold that only emits
  bounded-context layouts.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Validate every Effect v4 API in `.repos/effect` before
  writing it, even inside a one-line edit — `Data.tuple` cost a check
  failure and a runtime test failure that a 5-second grep would have
  avoided.
- **HIGH — Critical:** Under recording load, settle after every Lexical
  selection change before dispatching a command; a keystroke that passes
  standalone can land on a collapsed selection when video encoding slows
  the update loop.
- **HIGH — Critical:** Gate dev-only overlays off for recorded QA; a
  pointer-capturing overlay armed by an editing chord invalidates every
  later click.
- **MEDIUM — Best practice:** Make each harness scenario crash-tolerant so a
  thrown Playwright error becomes a failed assertion and the manifest still
  lands for every later scenario.
- **MEDIUM — Best practice:** Keep the vision judge's console ledger to app
  errors by classifying recorder traffic separately; otherwise the CORS
  noise reads as an app defect.
- **LOW — Consideration:** When the loop surfaces a pre-existing shell
  defect outside the goal, fix the contained half (text wrapping) and make
  the scenario realistic (maximize the group) rather than expanding scope
  into a redesign.
