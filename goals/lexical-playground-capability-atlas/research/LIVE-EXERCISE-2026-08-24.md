# Lexical Playground live exercise, 2026-08-24

## Method

This Goal A P0 re-judge used Lexical Playground 0.49.0 at pinned commit `a933222c489e7025d87b9217c2489d309fc8a3cf`. Vite served the detached Playground checkout on port 5199. The dedicated collaboration runner used the same Playground and the local Yjs relay.

PR #793 review found that the first evidence set was not hermetic. The old `authoring.undo` export contained the `authoring.redo` document, `document.clear` contained a 5x5 table, and `document.html-source` contained the `document.export-lexical-json` text. Parallel entry reruns shared the system clipboard. The old copy, caret, Enter, and paste tail also trusted keypress completion while Lexical still held a document-wide selection.

The probe reproduced the selection-cadence artifact: `Control+A -> End -> Enter` within about 50 ms erased the document. A 100 ms delay preserved it, and explicit DOM selection collapse plus a 100 ms delay produced two copies. The repaired lifecycle clears the clipboard, selects the whole document with two `Control+A` presses, collapses the DOM range, waits 150 ms, and verifies the settled result. This is a harness timing artifact, not a Playground defect.

The committed sweep came from one sequential `bun run ops/exercise/runner.ts --all` process. Before each scripted entry, the runner cleared and recreated only that entry directory. The sweep reported 154 PASS, 3 FAIL, and 5 SKIP across 162 entries. The five SKIP results wrote no observations; `collaboration.realtime` was then regenerated by its dedicated runner and passed.

The final evidence has 158 directories: 157 scripted entries plus collaboration. It contains 5,068 passing and 9 failing observation rows, 528 screenshots, and 44 `04-surface-roundtrip.png` screenshots. The verification actions recorded 44 passing `clipboard-verify` rows, 44 passing `paste-verify` rows, 42 passing and 2 failing `export-verify` rows. The two export failures follow blocked Export clicks in the comment scenarios and are product failures.

The runner classifies requests to `fonts.googleapis.com`, `fonts.gstatic.com`, and `va.vercel-scripts.com` as passing `baseline-egress` rows under D9/D14. The `network-summary` capability count excludes those requests. Both runners redact absolute home prefixes before writing observations. The regenerated observations contain no `/home/<user>` or `/@fs/home/<user>` prefix.

An entry is `verified-live` only when every non-baseline row passes and no defect appears on an exercised path. Responsive and keyboard-route defects remain blocking. A passing presence assertion is not enough when a screenshot shows the wrong structure, which is why `transformer.table` remains unverified.
