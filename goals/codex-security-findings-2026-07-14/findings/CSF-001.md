## Public Summary

Client-safe ProviderInstance commands accept a `binaryPath` validated only as a non-empty string; the probe path forwards it into a child-process executable sink without server-side canonicalization, provider-kind binding, or a trust-boundary check. Detailed report text, evidence paths, and source-commit context are kept in gitignored raw evidence.

## Validation

- Validation status: complete
- Disposition: remediate
- Verdict: real
- Rationale: `binaryPath` flows Add/Update command → stored → Probe → ProviderProbe adapter → `AiProviderCli` executable override → `ChildProcess.make`. No server-side allowlist ties the executable to the provider kind; no canonical-path validation. Maintained code, not `.repos`.
- Owner area: `packages/agents/**`, `packages/drivers/ai-provider-cli/**`
- Affected files: `packages/agents/use-cases/src/entities/ProviderInstance/ProviderInstance.rpc.ts`, `packages/agents/server/src/ProviderInstance/ProviderInstance.probe.ts`, `packages/agents/domain/src/entities/ProviderInstance/ProviderInstance.values.ts`, `packages/drivers/ai-provider-cli/src/AiProviderCli.service.ts`
- Close action: Close after merge as Already fixed.

## Remediation

- Remediation status: complete
- Remediation summary: The ai-provider-cli probe now enforces the server-configured `AiProviderCliPaths` allowlist via `Effect.filterOrFail` — any client executable override must equal the provider kind's configured binary (after tilde expansion) or the probe fails with a typed `AiProviderCliError` before `ChildProcess.make`. Regression tests assert an off-allowlist executable is rejected.
- Changed files: `packages/drivers/ai-provider-cli/src/AiProviderCli.service.ts`, `packages/drivers/ai-provider-cli/test/AiProviderCli.snapshot.test.ts`, `packages/agents/server/test/ProviderInstance.integration.test.ts`
