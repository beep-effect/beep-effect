## Public Summary

Untrusted PDF/DOCX bytes reaching document intake are fully parsed before any excerpt truncation, with no materialized-bytes cap or timeout, so a crafted or oversized document can exhaust CPU/memory and hang the local sidecar.

## Validation

- Validation status: complete
- Disposition: remediate
- Verdict: real
- Rationale: `FilingTextExtraction` copies the whole upload into an in-memory operation and calls `fileProcessing.process` without `maxMaterializedBytes`/timeout; the doc-text driver parses the full document before truncating to `maxExcerptChars`. Wired into the default packaged runtime. Maintained code.
- Owner area: `packages/documents/server/src/aggregates/Document/**`, `packages/drivers/doc-text/**`, `apps/professional-desktop/src/runtime/Layer.ts`
- Affected files: `packages/documents/server/src/aggregates/Document/FilingTextExtraction.ts`, `packages/documents/server/src/aggregates/Document/DocumentIntake.service.ts`, `packages/drivers/doc-text/src/DocText.service.ts`, `apps/professional-desktop/src/runtime/Layer.ts`
- Close action: Close after merge as Already fixed.

## Remediation

- Remediation status: complete
- Remediation summary: Filing extraction rejects inputs over a 32 MiB cap before copying/parsing, propagates the cap through `ProcessFileOperation`, and applies a typed 15s timeout; the doc-text driver independently enforces the cap before invoking PDF/DOCX parsers. Both values are configurable via `DOCUMENTS_FILING_TEXT_EXTRACTION_MAX_BYTES` / `_TIMEOUT` and threaded through existing desktop config wiring.
- Changed files: `packages/documents/server/src/aggregates/Document/FilingTextExtraction.ts`, `packages/documents/server/src/aggregates/Document/FilingDecisionLlm.config.ts`, `packages/documents/server/test/FilingDecisionLlm.test.ts`, `packages/drivers/doc-text/src/DocText.service.ts`, `packages/drivers/doc-text/src/DocText.errors.ts`, `packages/drivers/doc-text/test/DocText.service.test.ts`
