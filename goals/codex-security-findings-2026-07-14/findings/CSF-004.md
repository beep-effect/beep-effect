## Public Summary

The `ontology_export_provenance` tool CAS-checks only the source ontology while accepting independent caller-controlled `provPath`/`datasetPath` destinations, so a caller can overwrite an unrelated workspace `.ttl` file without any destination integrity check.

## Validation

- Validation status: complete
- Disposition: remediate
- Verdict: real
- Rationale: the handler validates `expectedFingerprint` only for `request.path`; `provPath`/`datasetPath` are forwarded unchecked and written unconditionally (bounded to workspace-root lower-case `.ttl` by path validation). No destination CAS/no-overwrite/per-target authz. Maintained server/toolkit code.
- Owner area: `packages/ontology/{server,use-cases}/**`
- Affected files: `packages/ontology/use-cases/src/tools/OntologyToolService.ts`, `packages/ontology/use-cases/src/tools/OntologyToolkit.ts`, `packages/ontology/server/src/tools/OntologyToolHandlers.ts`, `packages/ontology/use-cases/src/aggregates/Session/Session.validation.ts`
- Close action: Close after merge as Already fixed.

## Remediation

- Remediation status: complete
- Remediation summary: Provenance export now rejects source/output aliasing and preflights both destinations under the existing mutation semaphore; any existing target produces a typed `OntologyToolExecutionError` before either write, preserving unrelated TTL content (no-overwrite preflight relying on the documented single-process write authority).
- Changed files: `packages/ontology/use-cases/src/tools/OntologyToolService.ts`, `packages/ontology/use-cases/src/aggregates/Session/Session.validation.ts`, `packages/ontology/server/test/OntologyTools.test.ts`
- Verification commands: `bunx --bun vitest run --root packages/ontology/server test/OntologyTools.test.ts` (6/6)
- Close action: after PR merge, close in Codex as Already fixed.
