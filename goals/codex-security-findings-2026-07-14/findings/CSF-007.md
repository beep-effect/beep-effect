## Public Summary

The goals doctor passes a manifest-supplied `provenance.exploration` path straight to a filesystem existence check, so an attacker-controlled manifest in a PR can turn CI logs into an existence oracle for paths outside the repository.

## Validation

- Validation status: complete
- Disposition: remediate
- Verdict: real
- Rationale: `Doctor.ts` reads `provenance.exploration` and calls `fs.exists()` without normalizing to a repo-relative path; wired into the root lint policy that runs on `pull_request`. Advisory-only oracle (no read/exec). Maintained tooling code.
- Owner area: `packages/tooling/tool/cli/src/commands/Goals/**`, `.../Quality/**`
- Affected files: `packages/tooling/tool/cli/src/commands/Goals/Doctor.ts`, `packages/tooling/tool/cli/src/commands/Quality/Tasks.ts`
- Close action: Close after merge as Already fixed.

## Remediation

- Remediation status: complete
- Remediation summary: `Doctor.ts` resolves the repo root with `findRepoRoot` and rejects absolute, UNC, and repo-escaping exploration paths using the existing `@beep/file-processing/PathSafety` `isPathWithinRoot` helper (reused, not reinvented), emitting an "invalid path" advisory instead of probing the unsafe path. `Tasks.ts` already runs the guarded doctor from the repo root. Regression added.
