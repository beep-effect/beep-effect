## Public Summary

The repository auto-enables a Grafana MCP server that launches an unpinned Docker image with host networking, letting a repo-provisioned container reach loopback-only developer services. This contradicts the repo's own doctrine that MCP configuration is operator-level and not provisioned by repo config.

## Validation

- Validation status: complete
- Disposition: remediate
- Verdict: real
- Rationale: `.mcp.json` defines a `grafana` stdio server running `docker run --rm -i --network=host ... mcp/grafana` (no tag/digest); `.claude/settings.json` lists `grafana` in `enabledMcpjsonServers`; `.codex/config.toml` repeats the host-networked Docker launch. Confirmed present at current HEAD.
- Owner area: `.mcp.json`, `.codex/config.toml`, `.claude/settings.json`
- Affected files: `.mcp.json`, `.codex/config.toml`, `.claude/settings.json`
- Close action: Close after merge as Already fixed.

## Remediation

- Remediation status: complete
- Remediation summary: Removed the Grafana MCP from repo config — deleted the `grafana` server from `.mcp.json` and the `[mcp_servers.grafana]` block (and its describing comments) from `.codex/config.toml`, and set `.claude/settings.json` `enabledMcpjsonServers` to `[]`. Aligns the repo with operator-level-MCP doctrine and closes the supply-chain/host-network path. Operator re-adds grafana to user-level config to retain the tools.
- Changed files: `.mcp.json`, `.claude/settings.json`, `.codex/config.toml`
