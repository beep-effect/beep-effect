## Public Summary

The vault sync scanner and queued-upload reader check-then-use file paths without a no-follow invariant, so a symlink swapped into the vault can cause reads outside the vault whose bytes are uploaded to the configured Box mirror. Detailed evidence is in gitignored raw evidence.

## Validation

- Validation status: complete
- Disposition: remediate
- Verdict: real
- Rationale: `VaultSyncEngine` uses `readLink` then `stat`/`readFile` on the same path (non-atomic, both follow symlinks); `readVaultFileBytes` re-reads persisted relative paths without re-validating they remain a regular non-symlink file under the vault. Bytes flow to DMS mirror upload. Maintained code.
- Owner area: `packages/documents/server/src/aggregates/Sync/**`
- Affected files: `packages/documents/server/src/aggregates/Sync/VaultSyncEngine.service.ts`, `packages/documents/server/src/aggregates/Sync/DmsMirrorBox.ts`
- Close action: Close after merge as Already fixed.

## Remediation

- Remediation status: complete
- Remediation summary: Vault scanning and queued uploads now canonicalize the vault root, reject symlinks/non-regular files, open via a scoped handle whose fd is validated to remain contained (Linux `/proc/self/fd` canonicalization, since the Effect FS API exposes neither `lstat` nor `O_NOFOLLOW`), and read bytes through the validated handle. Regression asserts an escaping queued-upload symlink is never mirrored.
- Changed files: `packages/documents/server/src/aggregates/Sync/VaultSyncEngine.service.ts`, `packages/documents/server/test/VaultSyncEngine.test.ts`
- Verification commands: `bunx --bun vitest run --root packages/documents/server test/VaultSyncEngine.test.ts` (13/13)
- Close action: after PR merge, close in Codex as Already fixed.
