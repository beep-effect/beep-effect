## Public Summary

A newly registered SHACL datatype-repair candidate calls the IRI constructor on the violation focus node without accounting for blank nodes, so a datatype violation on a blank-node resource throws and crashes the validation request instead of yielding no repair proposal.

## Validation

- Validation status: complete
- Disposition: remediate
- Verdict: real
- Rationale: the adapter stores the focus node as a plain string, losing NamedNode/BlankNode kind; `datatypeCandidate` calls `makeNamedNode(violation.focusNode)`, which throws for blank-node labels (invalid IRIs) via `Result.getOrThrow`. Maintained driver/foundation code.
- Owner area: `packages/drivers/shacl/**`, `packages/foundation/{capability/semantic-web,modeling/rdf}/**`, `packages/ontology/use-cases/**`
- Affected files: `packages/drivers/shacl/src/Shacl.validation.ts`, `packages/foundation/capability/semantic-web/src/services/shacl-validation.ts`, `packages/foundation/modeling/rdf/src/Rdf.ts`, `packages/ontology/use-cases/src/aggregates/Session/Session.validation.ts`
- Close action: Close after merge as Already fixed.

## Remediation

- Remediation status: complete
- Remediation summary: Datatype repair now safely decodes the flattened focus node as a `NamedNode`; blank-node labels fail decoding and produce no repair candidate, preventing the throwing `makeNamedNode` path without changing other repair strategies. Regression asserts a blank-node datatype violation returns a validation result (no crashed fiber).
- Changed files: `packages/ontology/use-cases/src/aggregates/Session/Session.validation.ts`, `packages/ontology/use-cases/test/Session.validation.test.ts`
