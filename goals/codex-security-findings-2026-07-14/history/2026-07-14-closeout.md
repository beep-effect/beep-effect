## Hardening follow-up (PR #413)

PR #410 was merged by the operator while the Greptile-review follow-up commit
was still proving locally, so #410 shipped the base remediations only. The base
`main` briefly contained a Linux-only `/proc/self/fd` vault descriptor check
(CSF-003) that would fail closed on macOS/containers. PR #413 corrected this and
addressed the full Greptile P1 set:

- **CSF-003**: portable descriptor verification — the strong `/proc/self/fd`
  path is retained behind a capability probe; on non-procfs platforms a fallback
  verifies canonical vault containment + regular-file type + device/inode
  identity, **failing closed** when inode identity cannot be established.
- **CSF-004**: the provenance alias check now canonicalizes the workspace root
  via `realPath` and resolves source/prov/dataset paths against it before
  comparison, collapsing relative / `./` / absolute aliases (a lexical
  `Path.normalize` alone was insufficient).
- **CSF-004 no-overwrite** stays preflight-based under single-writer authority
  and the mutation semaphore; the ontology file store exposes only an
  overwriting write, so atomic destination no-overwrite was out of scope.
- **CSF-005** timeout: no code change — the 32 MiB materialized-bytes cap is
  enforced before the parser runs and is the primary bound on synchronous
  parse work; the fiber timeout is best-effort for async stalls.
