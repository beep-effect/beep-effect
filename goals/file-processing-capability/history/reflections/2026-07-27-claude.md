# Reflection — file-processing-capability (2026-07-27, claude)

## Summary

The packet shipped a complete product-neutral file-processing capability:
schema-first operation contracts, two real driver engines (Tika Server/App,
pffexport), and a repo CLI proof that writes the full schema-encoded manifest
tree. P5 closed with live calibration against Apache Tika 3.3.1 (including
runtime-generated legacy `.doc` and `.docx` binaries), a real-PST end-to-end
CLI run covering every V1 family, and a late RFC 5322 correctness fix
(conditional base64 body encoding, PR #478) decided through an adversarial
design panel. Verdict: the capability is ready for legal-document-intake P4.

## Tooling experience

- **Worked:** the yeet repair → verify → publish → monitor spine held for all
  closing PRs; worktree-isolated implementation agents kept three PR lanes
  moving in parallel without checkout contention; the P4 CLI's real-engine
  composition worked first try against live Tika + real pffexport.
- **Didn't:** `yeet publish` could not resume after being killed between
  commit and push (fresh full verify required); `yeet closeout` hard-blocks
  on Greptile score/issues when the bot never responds.
- **Frustrating:** proof-state fingerprints are recorded against the exact
  tree + HEAD, so a publish interrupted post-commit invalidates an otherwise
  valid 16-minute proof.
- **Wished existed:** a sanctioned thread-resolution path for merged PRs
  (`yeet closeout --resolve-threads` requires an open PR, so #470's resolved
  review threads could not be marked resolved from the CLI).

## Implementation improvement opportunities

- `FileProcessingWarningRecord` (capability schema) — the one structural gap
  every layer works around.
- Streaming digests for very large non-PST files.
- The doc/docx generators' ASCII-only text caveat (POI decodes cp1252, the
  generators encode UTF-8) is fine for the pinned marker but should be fixed
  before any non-ASCII calibration text is introduced.

## Goal & prompt critique

- The packet was strong: phase gates, design contracts with adversarial
  review rounds, and explicit non-goals kept scope tight. Two edits would
  have helped: (1) deferred obligations should appear in the receiving
  phase's PLAN section (the P2→P5 calibration deferral lived only in the P2
  status note); (2) the session prompt that drove closeout stated
  `currentTargetPhase` was P4 when main already had P4 complete and the
  manifest at P5 — grounding in the packet before writing code caught it, but
  the prompt should have been regenerated from live HEAD.

## TODOs worth codifying

- Yeet publish crash-recovery lane (committed-but-unpushed state).
- Closeout Greptile gates: bounded-wait degradation to a recorded warning.
- Office-binary fixture generators as shared test-kit substrate (on second
  consumer).

## Lessons (confidence-tiered)

- **HIGH — Critical:** Ground every closeout session in `ops/manifest.json`
  and live git history before acting on the prompt's phase claims — this
  session's prompt was one merged PR stale, and acting on it would have
  redone a landed phase.
- **HIGH — Critical:** Attribute CI failures before repairing: the only red
  hosted check in the closing PRs was a runner-cancelled verification lane
  (#478 Lint Policy), fixed by a re-run, not a code change.
- **MEDIUM — Best practice:** For binary-format fixtures, buy determinism
  with runtime generation plus an ablation pass that proves which bytes are
  load-bearing; the ablation notes made the port reviewable and the fragility
  explicit.
- **LOW — Consideration:** When an external review bot goes quiet, record the
  retrigger and the silence window in the PR/closeout evidence so the gate
  waiver is auditable.
