title: "resolve holds a write again when its node moved to another text since the hold"
date: 2026-11-13
lane: "agent-memory-store-p2"
reversal: "Restore writing theirs and merged on the current heads whatever the node holds, by decision file citing a resolver surface that shows the current text at resolve time"
---

A hold records the head revision its write was judged against, and the read model shows the text at that revision as ours. A theirs or merged resolution used to be written on the node's current heads whatever they held, so a writer that landed on the node after the hold opened (or the first of two holds on one node, once resolved) was overwritten by text the resolver never saw. resolve now compares the node's current text with the text at the hold's recorded head (none for a hold whose node had not reached the log). When they differ, the resolution is not applied: in one journal transaction the hold is closed with a HoldResolved that carries no revision and the same operation is held again as a new WriteHeld on the current head, with staleExpectedRevision (deleteVersusEdit for a delete) and the current text as ours; resolve returns held with the new hold id, which the resolver settles against the text it is now shown. A theirs resolution of a held status move is exempt: it rewrites only the status token of the current text under the lifecycle guard, so it drops no other writer's text. resolve also reads the log after the cursor its hold fold saw the hold open at, inside its transaction, and fails with HoldNotOpenError when a HoldResolved for the hold committed meanwhile, so a re-judgment that appends nothing (held again on the same head, or refused) never answers for a hold another resolver closed. Amends resolutions-are-written-under-a-fixed-resolver-lineage and admission-judges-each-operation-in-one-transaction. Code: packages/tooling/library/agent-memory-store/src/Admission.layer.ts and src/internal/AdmissionLog.ts; tests: the held and resolve cases of test/Admission.layer.test.ts. Rejected: keeping the hold open and re-judging against the recorded head on every resolve (a hold whose node moved could then never be settled with theirs or merged), and showing the current text in the read model while judging against the recorded one (the resolver would be judged against a text it is not shown).
