S14b: status cells, counters and pointers leave the held path as typed last-writer fields, and the lifecycle guard must reject backward moves (12 of 14 regress without it). Decision status-values-are-manifest-data makes the lifecycles runtime data, so the admission layer takes them as StatusFields (one StatusLifecycle per field) when it is built. A node is a typed status field for a field when its text holds exactly one value of that field's lifecycle as a whole token, a token being bounded by the text's ends or by characters that are not letters, digits, underscore or hyphen (so progress is not read inside in-progress); a value may span several words, and an occurrence inside a longer value's occurrence is not counted (decision status-values-may-span-words-and-the-longest-occurrence-wins). Only the setStatus operation takes the status path; a replace of the same node stays on the text path. setStatus is judged against the value the log head text holds, never the writer's base revision or the transition's from: an equal value lands at the head with no event (idempotent), a later value is written on the current head as a NodeStatusChanged whose transition records the head value as from and whose text changes only that token, and an earlier value is rejected with backwardStatusMove. Concurrent moves are therefore never held: in every interleaving the furthest value wins and the others are rejected or idempotent. A field with no lifecycle, a value outside it and a node text with no single value are rejected with statusOutsideLifecycle. The only held status move is one on a retired node (deleteVersusEdit). Code: packages/tooling/library/agent-memory-store/src/StatusField.models.ts and src/Admission.layer.ts; tests: the typed status field cases in test/Admission.layer.test.ts. Rejected: a status node kind (needs a partition change and a re-import) and trusting the transition's from (lets a stale writer move a field backward).
