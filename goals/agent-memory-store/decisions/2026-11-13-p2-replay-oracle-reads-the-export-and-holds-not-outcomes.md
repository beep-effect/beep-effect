title: "The AC-2 replay oracle reads the export and the holds, never admission's outcomes"
date: 2026-11-13
lane: "agent-memory-store-p2"
reversal: "Supersede by decision file naming the outcome-derived check that replaces an export- or hold-derived one, with the mutation that shows it still fails"
---

Review found that the replay oracle behind AC-2 excused a writer's text through a later write that admission itself reported landed, never checked deletes or where a node lands, and counted the delete-versus-edit holds from admission's outcome codes, while SPEC.md said it never read admission's judgment. The oracle in test/admission-replay.ts now reads only the base, the submitted batches, the final export and Admission.held for losses. Every writer of a replay edits the one imported base, so no write can supersede another and the supersession clause is gone. A delete is kept when its node is gone from the export or when Admission.held returns a delete hold of that writer on that node; a node gone while every delete of it is held is a loss. Each file's exported node sequence must equal the one the oracle builds from the base order and the submitted inserts (each after its predecessor in its own file, newest first among one predecessor's successors, then only the exported nodes), and no node may be exported twice. Delete-versus-edit holds are counted from Admission.held. Status moves and the AC-3 counts still read admission's outcomes, as scoring and measurement, and the header and SPEC.md now say so. The acceptance test also feeds the oracle doctored copies of one run (two nodes swapped, a node exported twice, a held delete's node dropped, a delete hold removed) and requires each to be reported. Measured unchanged: 0 losses in 100 adversarial runs and in all four history replay orders, 600 delete-versus-edit holds per 100 runs. Code: packages/tooling/library/agent-memory-store/test/admission-replay.ts and test/Admission.acceptance.test.ts.
