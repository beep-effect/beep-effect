---
title: "Op capture submits a status token swap as a typed setStatus"
date: 2026-11-13
lane: "agent-memory-store-p2"
reversal: "Drop typeStatusMoves by decision file citing a replay where typed status moves resolve worse than the text merge"
---

Text capture sees a status cell edit as a replace of the whole table row, and admission judges a replace with the whole-node three-way merge, so two concurrent moves of one status cell would be held as a staleExpectedRevision conflict even though S14b measured typed status fields resolving 10 of 10 such conflicts with 0 of 14 wrong. The admission lane flagged that capture never emitted setStatus. After capture, typeStatusMoves rewrites a replace into a setStatus when the base text the batch exported for the node holds exactly one whole-token value of a lifecycle, the new text is the base text with exactly that token replaced by another whole token (a run of letters, digits, underscore and hyphen) or by a value of the lifecycle, which may span several words, and every other byte unchanged, and exactly one of the layer's StatusFields reads it so (statusMoveBetween in StatusField.models.ts). The new token need not be a lifecycle value: a move to a token outside the lifecycle still reads as a move, so admission refuses it with statusOutsideLifecycle instead of landing it as free text. Any replace that changes more than the token stays a replace. The setStatus names the replace's node and expected revision; transition.from is the base value, which admission ignores in favour of the head value (decision typed-status-fields-are-whole-token-values). The step is pure over the batch, runs after captureBatch and before admit, and is part of the write path composition admitEdits. Code: packages/tooling/library/agent-memory-store/src/OperationCapture.status.ts and statusMoveBetween in src/StatusField.models.ts; tests: test/OperationCapture.status.test.ts, the status case of test/AgentWrite.test.ts and the status strata of the AC-3 replay. Rejected: typing inside admission (admission would have to diff texts it was handed as a replace, and a replace is a free-text claim the agent made) and requiring agents to submit setStatus by hand (the P5 loop captures edits of files, not typed commands).
