---
title: "Admission judges and appends each operation inside one SQL transaction and re-judges a stale append"
date: 2026-11-12
lane: "agent-memory-store-p2"
reversal: "Drop the per-operation transaction and rely on the log's compare-and-set alone by decision file if a non-SQLite journal cannot nest the journal write in a caller transaction"
---

The task bar is that an operation's check and its append cannot be separated by another writer. The log's compare-and-set covers only the node's own parents: an insert whose predecessor is retired between the judgment and the append would still land, unflagged as insertUnderDeletedAnchor. The live Admission layer therefore runs each operation's judgment (it reads the node's history from MemoryLog) and its append inside sql.withTransaction on the SqlClient the log writes through. On SQLite that is BEGIN IMMEDIATE, so the write lock is held from the read to the commit, and the journal's own writer transaction nests as a savepoint (the P1 fact that EventLog.write runs on the caller's fiber and connection). It is not a second lock: it is the database's write lock the log already uses. The log's compare-and-set still runs and is still the authority: a StaleParentsError from the append makes the layer judge the same operation again against the new heads, up to two more times, and any other log failure is an AdmissionError. resolve runs its re-judgment and its append in one transaction the same way; inside it, resolve reads the log after the cursor its hold fold read the hold open at and fails with HoldNotOpenError when a HoldResolved for the hold committed since, so a re-judgment that appends nothing (held again, or refused) never answers for a hold another resolver closed; the log's own check still refuses a HoldResolved for a closed hold, so of two resolvers exactly one settles a hold and the other gets HoldNotOpenError. Each operation is its own transaction, so one contested node never blocks or rolls back the batch's other operations. Measured by the race tests in test/Admission.layer.test.ts, which run the other writer inside the first one's transaction between its read and its append on the shared connection: two revisions of one node end with one landed and one held, and two concurrent status moves end at the furthest state with no hold. Code: packages/tooling/library/agent-memory-store/src/Admission.layer.ts. Rejected: a store-level lock file (a second locking scheme beside SQLite's) and checking the predecessor inside the log handler (a schema change to NodeCreated's admission that P2 does not need).
