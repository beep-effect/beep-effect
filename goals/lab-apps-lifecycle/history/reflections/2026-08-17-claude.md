# Reflection — lab-apps-lifecycle (2026-08-17, claude)

## Summary

The packet shipped both tracks: `beep delete-package` with a doctor residue
probe on a schema-first registration-geometry substrate, and `apps/labs/*` lab
apps in four AppKinds that mint law-abiding and delete without residue. The
First Vertical Slice passed end to end. The verdict I would put on it is that
the substrate was sound from P1 onward and every subsequent phase failed in the
same way instead: not in the design, but in the gap between what the gates
measured and what the artifact actually did.

## Tooling experience

- **Worked:** the reconstructive spine. `tsconfig-sync` as the inverse of
  create-package meant delete never needed a hand-maintained checklist, and the
  geometry model's `owned-tree` surface swept 1.1 GB of gitignored `target/`
  without anyone declaring it. `yeet verify` caught real problems repeatedly and
  its lane envelope made attribution mechanical. `create-package --lab` genuinely
  delivered D5: three separate mints across P3 and P4 each touched nothing
  outside `bun.lock` and the fenced identity segment.
- **Didn't:** `yeet verify` never runs `coverage`, so the ratchet is
  structurally invisible until CI. Twice a Coverage Regression arrived as a
  surprise on a file the branch had not edited. Attribution took hours the first
  time and was only cheap the second time because the first had taught me to run
  clean `main` before theorising.
- **Frustrating:** the failure modes that look like content but are not.
  Lint Policy emits 479 `broken-tracked-path` lines of which one was mine.
  `Build And Test` went red on a GitHub 429 during a platform outage. A coverage
  ratchet failed because my workstation has turbo credentials. In each case the
  log's tail was actively misleading and the answer came from grepping for
  the introduced item or reproducing on a clean tree.
- **Wished existed:** a `beep verify --like-ci` that reproduces CI's environment
  rather than my workstation's — pinned env, coverage included. Most of the
  session's lost time was local-vs-CI divergence, not defects.

## Implementation improvement opportunities

- `create-package` now has a verbatim asset path (`StaticAssetSpec` →
  `PlannedAsset` → `copy-asset`). The next binary artifact — favicons, fonts,
  seed fixtures — should reuse it rather than rediscover that templates are
  text-only.
- The tauri `devUrl` bug existed because the host was derived twice: once by
  `portlessLabel` for the dev script, once by `{{kebabCase name}}` in the config
  template. Any value derived twice will eventually disagree; the fix was to
  delete the second derivation, and that pattern is worth looking for elsewhere.
- `delete-package`'s baseline write should be scoped and atomic (see findings).

## Goal & prompt critique

`GOAL.md` was unusually good — the phase ordering held, the stop conditions were
real, and "Preserve unrelated worktree changes" prevented at least one mistake.
Two edits I would make:

1. **Acceptance criteria should name outcomes, not commands.** Track B's
   "passes `beep:check`, `beep:lint`, `beep:test`" is precise and was fully
   satisfiable by a package that could not build. Phrase it as "the variant's
   own build and run path works", and the tauri defect is caught at P2 rather
   than surviving into P3.
2. **The workflow should say to execute the gates per variant.** It says to
   follow the PLAN phases; it does not say that a criterion covering N variants
   requires N measurements. That inference failed once and cost a review cycle.

## TODOs worth codifying

- A repo law: when a criterion covers multiple variants, evidence must exist per
  variant. "Measured one, asserted the rest" is the single most repeated error
  in this packet.
- A lint or skill note that `yeet verify` excludes `coverage`, with the local
  reproduction recipe, so the next agent does not learn it from a red PR.
- Record that `gate staleness` in `yeet monitor` is mtime-based and local-only,
  and is not one of the three merge criteria — it reads like a blocker and is not.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Attribute a verification failure against a clean tree
  before changing code. Three separate red signals this session — a coverage
  ratchet, a lint-policy failure, a CI job — had causes outside the diff, and
  in every case reproducing on clean `main` or reading the introduced-vs-inherited
  split answered it in minutes.
- **HIGH — Critical:** The gates a spec enumerates become the definition of
  correctness, and anything outside them is invisible regardless of how central
  it is. Ask what the standard gate list *cannot* see for this artifact.
- **MEDIUM — Best practice:** Prefer a pinned invariant plus a test over a
  defensive branch. Unreachable branches are uncoverable lines, and a coverage
  ratchet reads those as regressions later, in a file whose author has moved on.
- **MEDIUM — Best practice:** Assert bytes, not existence, when proving a
  generated binary artifact. A PNG mangled by a string round-trip still exists.
- **LOW — Consideration:** A default that every caller overrides is not a
  default; it is a trap with a well-known workaround, and the workaround is what
  keeps it from being fixed. `--skip-baselines` hid a ten-minute defect for
  four phases.
