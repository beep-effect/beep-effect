# Reflection — harness-otel-adoption (2026-07-25, claude)

## Summary

Both harnesses export native OTLP through the dankserver collector with the
beep attribution schema and content capture off; P2 proved it with a one-day
ground-truth comparison (98.5% Claude session coverage by session-id join
across native/claudex/claudeg modes, per-model token totals within a named
±10% tolerance on bounded lanes with five heavy lanes recorded as explicit
out-of-tolerance exceptions, and clean payload inspection of both
harnesses' exported spans — 560 codex + 110 claude — plus the claude
metric-label surface) and P3 closed the packet in the same docs-only PR.
Verdict: shipped as specified, with codex metric limits honestly recorded
rather than papered over.

## Tooling experience

- **Worked:** Prometheus HTTP API via `docker exec` over the pre-warmed
  `ssh dankserver-yubi` control master (no YubiKey touch needed mid-session);
  Phoenix REST span API via unfiltered recent-page reads; the session-id
  join between
  `claude_code_session_count_total` labels and `~/.claude/projects` transcript
  filenames — it turns a fuzzy "coverage" question into an exact set
  difference.
- **Didn't:** Phoenix GraphQL span queries (timeouts at 585k traces);
  time-filtered Phoenix REST reads (`start_time`/`end_time` hangs >4 min on
  historical windows); `increase()` over codex counters (delta-reset collapse
  makes it useless for counting).
- **Frustrating:** `claude_code_session_count_total` emits one sample per
  session, so instant queries and short-range sums read as "no data" until
  you switch to `last_over_time`/series-API lookbacks — the first hour of
  P2 analysis chased a phantom outage caused by staleness semantics.
- **Wished existed:** a per-session final "flush" export on harness exit
  (would close the long-session undercount), and any per-repo label on codex
  metrics.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Dedupe transcript usage by `message.id` before any
  token comparison — streamed chunks repeat usage and overcount ~2.2×,
  enough to invert the conclusion about exporter health.
- **HIGH — Critical:** Session-scoped OTel counters (one sample per event)
  need `last_over_time`/series-API queries; instant reads mislead via
  staleness and look like outages.
- **MEDIUM — Best practice:** For fleet-style processes (codex), trust
  durable artifacts (rollouts) for counting and use metrics for rates;
  collector-side accumulation across identical label sets silently swallows
  process restarts.
- **LOW — Consideration:** Keep an eye on Phoenix ingestion lag as span
  volume grows; REST querying hides it because results look complete.
