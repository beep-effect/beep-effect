# Authority Context Spec

## Objective

Build authority as the first four-package slice: Invocation and grant-check language, grants, narrowing delegation, accountability, admission and re-admission, on Effect Cluster.

The design is in `explorations/model-first-slices/BRIEF.md` ("Authority") and `explorations/model-first-slices/DECISIONS.md`: D4, D7, D18, D24 to D27, D30, D32, D36
and D39, with D63 and D64 for why it is first and how it relates to the grants the repo already
has. The prototype's `authority` context proves the model in memory and on a two-runner swarm.

## Non-Goals

- Moving `packages/execution-authority` code. `goals/execution-authority-slice` finishes as planned, and `authority-absorbs-execution-authority` is a gated candidate in the exploration's `MAP.md` (D64).
- `AgentRun`, the budget ledger and run lineage. They belong to the gated `runs-context` (D28, D29).
- A `web` package. Authority has no screen in this goal; the first one comes with the first product slice.
- Law-practice's stricter supervision rules, which sit in their own context on top of the Accountability relation (D18).
- Gateway tokens between pools. One pool, whose contexts trust each other (D39).
- Changing existing slices to call authority. Each gets that with its own migration.

## Constraints

- Only authority builds an `Invocation`. A trusted boundary admits the caller; events store provenance alone (the root, on whose behalf, the causal chain, grant ids), never grant terms (D4, D24).
- At each hop a policy or saga asks authority, through a port it declares, to re-admit the chain from live grants. Re-admission never adds a grant, passes those still in force, and a command that needs a lapsed one is refused and the refusal recorded (D24, D30).
- Delegation only narrows: named operations, a resource scope and an expiry. It carries no budget (D26, D29).
- Every agent-rooted action names an accountable human (D18).
- The kernel holds the `Invocation` schema, ids and the pure grant-check language, with no Layer, aggregate or credential handling (D7, D27).
- Root forgery in process is controlled by a source scan whose known gaps are listed in the proof inventory, until upstream offers a request context only middleware may provide (D25).
- Command ids are bound to org, operation and request fingerprint (D36). A reused command id is answered from the stored receipt before the grant is checked; a test pins that.
- Reuse the `Principal` union and the branded ids in `packages/shared/domain`; do not recreate them. Grant terms keep the vocabulary of `ExecutionGrant` (principal, operation, resource, expiry) so the later move is a move and not a redesign (D64).
- Stored bytes are never rewritten; schemas convert on read (D22).
- The prototype (`scratchpad/model-first-slices/authority/`, `shared/kernel/`, `shared/contract-kit/`) is a porting source, never a dependency.

## Acceptance Criteria

- [ ] `packages/authority/{contract,model,host}` exist, generated by the scaffolder, and pass `check`, `lint` and the slice checkers with no baseline entry.
- [ ] Stories on `Domain.InMemory` prove admission at the Session boundary, a grant, a delegation that only narrows, accountability for an agent-rooted action, re-admission that adds nothing, revocation seen at the next hop, and the recorded refusal.
- [ ] The proof inventory has entries for root construction, no grant terms in events, re-admission adding nothing and contract parity, and every declared command outcome is executed.
- [ ] The first vertical slice passes on the two-runner swarm through the conformance package: a human delegates a narrowed grant to an agent, a command in the test model is decided under the Invocation authority builds, the grant is revoked, and the next hop is refused and recorded.
- [ ] The app pool's descriptors include authority and the generated entry module loads it.
- [ ] `bun run beep quality package-verify` passes for each new package.
- [ ] No unrelated refactors or formatting churn.
