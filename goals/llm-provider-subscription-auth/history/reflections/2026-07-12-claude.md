# Reflection — llm-provider-subscription-auth (2026-07-12, claude)

## Summary

Shipped the full CLI-delegation subscription-auth vertical: rich redacted auth-probe snapshots
with per-call executable/env/shadow-home isolation in `@beep/ai-provider-cli`, and the
ProviderInstance concept across all five agents-slice packages (domain entity, use-cases
commands/ports/RPC, net-new tables package with a no-tokens-at-rest row-shape proof, server
port implementations with PGLite integration coverage, thin client atoms). PR #392 carries the
work on a clean branch off `origin/main` after full local proof went green. Verdict: the
architecture held up exactly as mapped in SPEC; the execution cost was dominated by
orchestration failures and repo-global-vs-package-local verification gaps, not by design work.

## Tooling experience

- **Worked:** `bun run beep architecture` scaffolds; the SPEC architecture-mapping table plus
  binding P0 rulings made lane prompts nearly mechanical; codex-companion background lanes with
  XML operator prompts converged fast when they survived; `yeet` verdict artifacts and repair
  hints routed every failure; `EntityTable.pgTableFrom` made the tables package almost free.
- **Didn't:** the codex-companion record layer — jobs reported dead while their task-workers
  and brokers kept running, and vice versa; two duplicate lanes ended up racing in one
  worktree, and an orphaned broker's queued `yeet verify` sabotaged four subsequent proof runs.
- **Frustrating:** per-package `bun run check` passing while the repo-global
  `check:tsgo:tests` fails on effect-LSP rules; the JSDoc inventory rejecting inline-tag
  one-liner headers that every human reads as compliant.
- **Wished existed:** a package-scoped runner for the global LSP rule set; a companion-lane
  liveness sweep; worktree-isolated codex lanes by default so parallel sessions' sweep commits
  ("preping to sync") can't interleave with lane state.

## Implementation improvement opportunities

- Direct two-instance isolation test at the driver level (see finding).
- The client's `providerInstanceTransportLayerAtom` + `RpcTest.makeClient` stub pattern is
  reusable — worth extracting as the canonical AtomRpc test harness when a second consumer
  appears.
- UI composition (add-instance wizard, status banner) deliberately deferred; the dockview app
  is the natural home.

## Goal & prompt critique

- The packet was well-shaped: P1's inward-out order matched dependency reality, and
  "stop when tempted to build a registry/resolver" successfully fenced scope.
- Revise future SPECs to pin cross-layer data seams for acceptance criteria (see finding) and
  to name the repo-global gates (`yeet verify`, jsdoc-ratchet with fresh inventory) as the
  lane-exit bar rather than package-scoped checks.

## TODOs worth codifying

- Global-only effect-LSP rule list into testing-patterns guidance.
- Scoped `test-tsgo` entry point.
- Companion-lane liveness sweep helper.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Treat `bun run beep yeet verify` as the only "green" that counts —
  every lane that self-certified on package-scoped checks failed the global gate on first
  contact (effect-LSP rules, fresh jsdoc inventory, knip, fallow attribution).
- **HIGH — Critical:** Never relaunch a "dead" companion lane without a process sweep; the
  record layer lies, and duplicate writers in one tree cost more than the lane's work was
  worth.
- **MEDIUM — Best practice:** Assemble PR branches surgically off `origin/main` when the
  working branch carries parallel in-flight packets — path-scoped `git checkout` plus
  hunk-level root-config surgery kept PR #392 free of dockview/pretext contamination.
- **LOW — Consideration:** Sandboxed lanes cannot run git-writing proofs (`FETCH_HEAD`
  refusal) — plan for the operator to run the final verify/publish outside the sandbox.
