# Reflection — complexity-ceiling-burn-down (2026-09-03, codex)

## Summary

The goal was refreshed from historical calibration to current repository truth,
all 49 Fallow 3.22.0 tail verdicts were executed, and the unwaived
cognitive-over-15 tail was reduced to zero. The health baseline now compares
cleanly, the strict diff audit reports zero introduced findings, and the health
lane has been promoted after three consecutive clean runs.

The final comparator, refreshed after synchronizing to `origin/main` at
`53193e5a5e93a3231282eaead455f7d06a85ac4d`, analyzed 4,411 files and 67,646
functions, matched all 189
baseline entries with zero stale or moved entries, and retained zero unwaived
functions above cognitive complexity 15.

## Tooling experience

- **Worked:** Fallow's complexity breakdown exposed exact decision-point
  contributions; the new-only audit prevented helper extraction from merely
  redistributing complexity; package-local `tsgo` and focused Vitest runs found
  type and behavior regressions quickly.
- **Didn't:** the original packet counts and baseline no longer represented the
  live repository, and the old suppression evidence did not preserve a complete
  tool inventory.
- **Frustrating:** `fallow:health:baseline:write` wrote the intended artifact
  while exiting 1 and emitted a huge JSON document under `--quiet`, which made
  a successful wave boundary look like a failed command.
- **Wished existed:** one repository command that writes the baseline, verifies
  it, records the digest and summary, and fails only when the resulting
  comparator is invalid or regressed.

## Implementation improvement opportunities

- Keep the review-dated overrides observable and remove or lower them when
  public component contracts or parser state machines naturally shrink.
- Revisit the nested tooltip-label resolver now measured at cognitive 12 during
  the next chart behavior change; it is below the campaign ceiling and frozen
  by the baseline, so touching it here would expand scope.
- Preserve the direct diff-audit loop for future waves. It caught complexity in
  new helpers that the inherited-tail objective alone would have missed.

## Goal & prompt critique

The launcher should state at its top that all inventories and count-based gates
are refreshed from the current pinned/latest tool before work begins, and that
historical values are provenance unless a committed comparator proves they are
still current. That edit would have prevented the stale packet from being read
as a terminal blocker and would align the prompt with the user's invariant:
burn down complexity in the repository that exists now.

## TODOs worth codifying

- Add a schema-versioned suppression snapshot to count-ratchet packet templates.
- Add a bounded baseline write-and-verify wrapper to the repo CLI.
- Document that a clean inherited-tail result is insufficient until the
  new-only audit also reports zero introduced complexity and duplication.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Refresh inventory before enforcing a historical goal —
  live Fallow 3.22.0 state changed both target identities and suppression totals.
- **HIGH — Critical:** Pair inherited-tail health with a new-only diff audit —
  the first pass cleared the old tail but briefly created 18 new-code findings.
- **MEDIUM — Best practice:** Record three promotion runs against identical
  artifact bytes — the shared SHA-256 makes the clean-run evidence comparable.
- **LOW — Consideration:** Revisit the cognitive ceiling of 6 only after the
  review-dated override pressure at 8 has been observed; this campaign provides
  no evidence that lowering it now would improve design.
