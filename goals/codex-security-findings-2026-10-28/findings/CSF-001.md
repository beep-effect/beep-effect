# CSF-001: Named\-pipe replacement can expose the hub bearer token

- Severity: Low
- Codex ID: `commit:59dd726af40c8191ba736e49b5e42496`
- Source commit: `6bc6201825dd6d186551e85eca29015eddf8e50b`
- Owner: Windows token provisioning
- Status: validated; implemented; qualification and closure pending

## Public Summary

The sender writes its input to a named pipe without authenticating the owner of the connected endpoint. A different local account can replace the name after receiver expiry.

## Current-HEAD Validation

Disposition: remediate. Baseline source at `2c59e073c8` contains the defect. The branch implements the control described below; external closure remains pending.

### Cloud Validation, Evidence and Attack-path analysis

Cloud validation traces the plaintext sink and timeout race; Windows execution was unavailable. The attack-path analysis requires a distinct local account, a stale readiness check and an allowed device identity. No remote unauthenticated compromise is established.

Full report sections were read in the authenticated Cloud UI on 2026-10-28. Captured severity and identity remain unchanged. Cloud suppression is not evidence that the defect is false positive.

## Remediation

Authenticate the owner SID of the connected pipe using the handle security descriptor before stdin is opened. Explicitly set the receiver owner, limit client impersonation, request ReadPermissions, and dispose on refusal. Windows runtime qualification is pending.
