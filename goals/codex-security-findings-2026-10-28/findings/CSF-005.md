# CSF-005: Post\-capture settling can delete unarchived worktree changes

- Severity: Informational
- Codex ID: `commit:8f3863d64f848191896127654ffb856c`
- Source commit: `d3fe073a81fbdcd7b83621deb2b840285d3aa7c0`
- Owner: Worktree archive retirement
- Status: Fixed; merged and verified on 2026-10-31

## Public Summary

The final quiescence check waits for directory walkers to disappear after archive capture. A walker can write and close between scans, allowing uncaptured changes to be removed.

## Current-HEAD Validation

Disposition: remediate. Baseline source at `2c59e073c8` contains the defect. The branch implements the control described below; external closure was verified on 2026-10-31.

### Cloud Validation, Evidence and Attack-path analysis

Cloud validation reproduces watch/rename/openat primitives and source-traces deletion without recapture; the actual CLI reproduction was blocked. The attack-path analysis classifies this as a same-user data-preservation defect, without a demonstrated privilege escalation.

Full report sections were read in the authenticated Cloud UI on 2026-10-28. Captured severity and identity remain unchanged. Cloud suppression is not evidence that the defect is false positive.

## Remediation

Settle walkers only before capture. After capture, refuse on the first observed walker and preserve the fenced directory. The process-table integration check injects a late write at the post-capture observation and verifies its survival.
