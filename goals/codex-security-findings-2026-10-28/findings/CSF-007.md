# CSF-007: Bridge clients send bearer tokens over non\-loopback plaintext

- Severity: Informational
- Codex ID: `commit:e5e09e9134588191b573324f5328d292`
- Source commit: `faba4396bd628eb2efa09ef2e1b1aa46ff7723b2`
- Owner: Codex bridge transport
- Status: Fixed; merged and verified on 2026-10-31

## Public Summary

Both bridge entrypoints attach a bearer header to operator-selected non-loopback plaintext WebSocket URLs; reconnect repeats the same transport.

## Current-HEAD Validation

Disposition: remediate. Baseline source at `2c59e073c8` contains the defect. The branch implements the control described below; external closure was verified on 2026-10-31.

### Cloud Validation, Evidence and Attack-path analysis

Cloud validation exercises both unchanged CLI entrypoints against a synthetic local peer, including reconnect and interruption, and observes plaintext headers and messages. The attack-path analysis distinguishes this unsafe override from the qualified loopback-over-SSH workflow and does not establish listener replay or SSH bypass.

Full report sections were read in the authenticated Cloud UI on 2026-10-28. Captured severity and identity remain unchanged. Cloud suppression is not evidence that the defect is false positive.

## Remediation

Share one URL policy across both entrypoints. Accept remote TLS or loopback plaintext, reject credentials/fragments and deceptive hosts, and validate before reading the token environment. Reconnect reuses the already validated immutable URL.
