# CSF-012: Coverage ratchet can miss offset test regressions

- Severity: Informational
- Codex ID: `bdaf5007ae688191a499967b959b5a86`
- Source commit: `3082ae31d10320b8dd49a68b7a2112b8ce169758`
- Owner: Repo CLI coverage architecture
- Status: confirmed; remediate; fixed locally

## Public Summary

Package-level coverage percentages and uncovered totals cannot distinguish test
loss in one file from an offsetting deletion of unrelated uncovered units.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`. The committed package aggregate permits this
offset because both histories can produce identical package totals.

## Remediation

Coverage snapshots now use strict schema v2 with required normalized
repo-relative per-file provenance. Comparison fails closed on same-file and
new-path offsets. Any package percentage drop accompanied by any file-set change
also fails closed, so deletion-only ambiguity is not waived. A focused temporary-
repository regression proves scoped schema-v1 writes are refused while a full
writer run performs the one-way v1-to-v2 migration. The regenerated schema-2
baseline contains `files` keys for all 127 packages. Baseline reads reuse shared
read/decode error mappers so the Fallow duplication gate remains clean.
