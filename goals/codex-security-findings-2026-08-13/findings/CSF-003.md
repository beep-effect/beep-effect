# CSF-003: PR code now runs on owned EC2 CI runners

- Severity: High
- Codex ID: `a3a281b2a3d881919fdcbf68ee2364f0`
- Source commit: `69045830e2c3acca1ec771e23a5e4be3a9fc0e3c`
- Owner: CI runner admission architecture
- Status: confirmed; remediate; architecture/deployment-blocked

## Public Summary

Multiple pull-request verification lanes execute untrusted repository code on
owned EC2 runners. One-job VM lifecycle does not by itself create a trusted
event-admission boundary.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`. The affected lanes still target the production
runner label for pull-request events, so the reported trust-boundary expansion
is present on current HEAD.

## Remediation

Pull-request jobs must move to a non-privileged execution class or be admitted
by a control outside repository-editable YAML. P2/P3 have landed, but complete
repair still requires external GitHub organization runner-group plus AWS
deployment proof; this finding remains dispositioned `remediate`.

## Verification

- After reconciliation, prove from the deployed organization policy and a
  hostile pull request that all pull-request lanes are denied owned production
  runners by a control the pull request cannot edit.
