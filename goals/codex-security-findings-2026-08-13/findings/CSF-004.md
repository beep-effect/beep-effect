# CSF-004: Shadow runner exposes AWS role creds to job code

- Severity: High
- Codex ID: `c799c2269d748191997ff176ce4bfd48`
- Source commit: `37f289a025b5072e7099a24d195103ab8b2ea4f1`
- Owner: CI runner workload identity
- Status: confirmed; remediate; architecture/deployment-blocked

## Public Summary

Runner job steps execute as host processes while instance metadata remains
enabled. The metadata hop limit constrains ordinary containers but not job code
running directly on the host.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`. The worker boots with an instance role and the
job-start path does not remove or isolate metadata access before repository code
runs.

## Remediation

The fleet needs a bootstrap identity that is absent or unreachable during job
execution. That boundary spans external fleet admission and workload-identity
design, so the finding remains dispositioned `remediate` pending active-CI
landing and deployed AWS proof.

## Verification

- Against the deployed AWS runner, run a hostile host-process probe and prove
  no usable cloud credential is available while a runner job executes.
