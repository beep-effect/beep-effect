# CSF-006: PR code can steal EC2 runner IAM credentials

- Severity: High
- Codex ID: `e841bb5393c08191a74ff574c0108bd8`
- Source commit: `8df3aa7244e0ebeb764010cc3a9a2e728d54864a`
- Owner: CI runner admission architecture
- Status: confirmed; remediate; architecture/deployment-blocked

## Public Summary

Production pull-request lanes combine untrusted repository code with owned
workers whose host can reach the instance role. Ephemeral teardown does not
prevent credential use within the current job.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`. Both halves of the reported path remain:
pull-request admission to production runners and host-process reachability of
the worker identity.

## Remediation

Complete repair requires trusted-event admission and removal of usable cloud
identity during jobs. Those decisions cross the admission and workload-
identity lanes; this remains `remediate` pending external GitHub organization
runner-group and AWS deployment proof.

## Verification

- Against the deployed GitHub organization and AWS fleet, prove a hostile pull
  request cannot obtain a production runner and no runner job, including a
  privileged one, can retrieve usable cloud identity.
