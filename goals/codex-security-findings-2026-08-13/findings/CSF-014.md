# CSF-014: PR CI exposes Turbo cache token to checked\-out code

- Severity: Medium
- Codex ID: `83aaa20c361c819190399e1c6b155ce3`
- Source commit: `f883e2b16a83ad9d7a65f2269807dc09a99d7d7b`
- Owner: CI/GitHub Actions
- Status: confirmed; remediate; PR #696 open and unmerged under hosted monitoring

## Public Summary

Pull-request-capable CI jobs receive a reusable Turbo cache credential before
they execute checked-out repository code, allowing that code to access the
credential during the job.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`. At source commit
`f883e2b16a83ad9d7a65f2269807dc09a99d7d7b`, pull-request-capable jobs receive
the reusable Turbo credential while running repository-controlled steps.

## Remediation

Pull-request-capable lanes now use local-only Turbo caching and receive no
reusable Turbo token. The trusted push build retains remote read/write caching.
Full Yeet verify passed 21/21 on the exact current base. The branch is pushed
and PR #696 is open and unmerged under hosted monitoring; hosted green is not
yet claimed.
