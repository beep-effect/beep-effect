# CSF-015: Unauthenticated extraction can traverse local storage paths

- Severity: Informational
- Codex ID: `2543806b513081919d2463b171bebc1f`
- Source commit: `bdf4d34d971fe44a32b33aea936aba247855317a`
- Owner: scratchpad/effect-ontology storage boundary
- Status: confirmed; remediate; fixed locally on a prepared branch

## Public Summary

Unauthenticated local-storage keys can reach filesystem operations without
canonical confinement beneath the configured storage root, allowing traversal
or symlink resolution outside that boundary.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`. At source commit
`bdf4d34d971fe44a32b33aea936aba247855317a`, local-storage keys are not
consistently confined and re-resolved beneath the configured root before
filesystem operations.

## Remediation

Every key-bearing and root-wide operation now uses canonical PathSafety
confinement and re-resolution. The focused regressions cover traversal and
absolute keys, symlink escapes, prefix-directory replacement during creation,
configured-root replacement, and clear-time symlink children. The fix is
prepared but not merged.
