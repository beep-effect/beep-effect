# CSF-009: Semantic-delta probes execute untrusted archive code

- Severity: Medium
- Codex ID: `98d316271ef08191a2b6939597ae8fec`
- Source commit: `774d118c0645ebe46d4a43690efd388562e1c72f`
- Owner: Repo CLI knowledge architecture
- Status: confirmed; remediate; fixed locally

## Public Summary

Local and same-repository semantic-delta comparisons import executable command
and index modules from archived revisions. The fork-pull-request skip does not
protect those invocation modes.

## Captured-Baseline Validation

Verdict: `confirmed-vulnerable`. The probe policy is partially mitigated for
forks, but allowed comparisons still execute archive-local modules.

Post-remediation verdict: `fixed-locally`. Allowed comparisons execute only
current-checkout modules against archive data; archive-local modules are not
loaded.

## Remediation

The probes now load their executable command and index logic from the current
checkout while retaining the archived revision as the comparison data root and
working directory. A hostile archive regression proves archived modules are not
imported. The public Knowledge facade excludes the archive-oracle constructor;
tests access it only through the source-only Knowledge test kit. Probe-facing
documentation and diagnostics now describe current-checkout code operating on
archive data.

Round 2 found four additional fail-closed and sanitation gaps: successful
truncated streams, bare carriage returns/short absolute paths, archive-derived
public control text, and base-only commands outside the HEAD preflight union.
Repairs are present and focused proof is green. Exact aggregate proof and the
fix commit remain pending before publication.
