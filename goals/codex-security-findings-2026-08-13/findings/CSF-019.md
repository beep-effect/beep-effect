# CSF-019: Migration re\-baseline breaks existing databases

- Severity: Informational
- Codex ID: `f5918d64f4708191a9e2c11a66b0bce2`
- Source commit: `ec3bc91e63db2c3df716401fb1244c7d267b8045`
- Owner: Postgres migration compatibility
- Status: remediated locally; combined publication pending

## Public Summary

Professional Desktop replaced historical migration names with new baseline and
renamed entries containing non-idempotent SQL. Because the bundled migrator
selects pending work by journal name, existing databases attempted to apply the
new names and could fail during application startup.

## Current-HEAD Validation

Verdict: confirmed vulnerable. Disposition: remediate. Existing journal rows
prove old migration names, not the new canonical names, so the current bundle
cannot distinguish an upgraded database from a new database.

## Remediation

The bundled migrator now accepts complete legacy-name proof sets. It skips a
re-baselined migration only when every required legacy name is journaled,
rejects partial histories, and preserves Drizzle version-zero journal upgrades.
Professional Desktop declares the exact historical names corresponding to both
baselines and the renamed ST13 migration.
