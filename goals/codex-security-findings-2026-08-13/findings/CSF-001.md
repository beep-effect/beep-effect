# CSF-001: PR code now runs on self-hosted EC2 CI lanes

- Severity: High
- Codex ID: `08ee74d0eb18819187fd02f570b4d57c`
- Source commit: `7e730d757312e56ccfbbc87b1e2adfe18e562820`
- Owner: CI runner admission architecture
- Status: confirmed; remediate; architecture/deployment-blocked

## Public Summary

Five pull-request matrix lanes execute repository-controlled setup and package
code on owned EC2 workers. Ephemeral teardown limits persistence but does not
protect the current owned-worker boundary from untrusted job code.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`. The production label remains assigned to
pull-request jobs. Repository workflow conditions cannot provide durable
admission because the pull request can edit the same workflow content.

## Remediation

Blocked on a runner-admission architecture enforced outside pull-request-
editable YAML, active-CI landing, and external GitHub organization runner-group
plus AWS deployment proof. The finding remains dispositioned `remediate`; no
workflow or fleet files were changed.

## Verification

- After the architecture and deployment land, prove from GitHub organization
  runner-group policy and a hostile pull request that untrusted code cannot
  acquire an owned production runner even after editing workflow content.
