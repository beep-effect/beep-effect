# CSF-005: CI runner IMDS firewall rollback exposes AWS role creds

- Severity: High
- Codex ID: `ca9a4a0353e481919011a7d8380f5068`
- Source commit: `9b74f0013b6d0a08d4c10bbad3e2333fe70dc119`
- Owner: CI runner workload identity
- Status: confirmed; remediate; architecture/deployment-blocked

## Public Summary

The host-level metadata firewall was rolled back while instance metadata and
the shared runner host user remain in service, leaving no replacement job-time
identity isolation boundary.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`. Current bootstrap behavior no longer installs
the host metadata drop and does not remove the instance role or introduce an
equivalent root-resistant control before job code runs.

## Remediation

A root-resistant workload-identity design must replace the rolled-back firewall
approach and be reconciled with the active CI fleet changes. The finding remains
dispositioned `remediate` pending deployed AWS proof.

## Verification

- Against the deployed AWS runner, prove both ordinary and privileged job
  probes cannot obtain a usable instance credential during execution.
