# CSF-007: Yeet PR footer leaks local paths and AI session IDs

- Severity: Medium
- Codex ID: `14981c9702288191a821494c38525185`
- Source commit: `4ec4cd15cd0002530066780efe6e47328a8df6d4`
- Owner: Repo CLI Yeet provenance
- Status: confirmed; remediate; fixed locally

## Public Summary

The public Yeet footer and its machine block expose local clone and worktree
structure, an agent resume command, and an AI session identifier. Home-prefix
tokenization alone does not make those fields public-safe.

## Current-HEAD Validation

Verdict: `confirmed-vulnerable`. Both the visible footer and embedded JSON
include local-only resume provenance on the captured baseline.

## Remediation

Rendering now projects local provenance into a schema-backed public model that
contains only schema version, branch, and harness. Local paths, resume commands,
and session identifiers remain available only to local resume detection. The
remaining public branch value is escaped independently for visible Markdown and
the hidden JSON comment, including Git-valid backticks and comment terminators.

- `packages/tooling/tool/cli/src/commands/Yeet/internal/Provenance.ts`
- `packages/tooling/tool/cli/test/yeet-pr-provenance.test.ts`

## 2026-09-03 follow-up

Verdict: `false-positive` for the revived schema-version 2 footer.

The renderer now accepts only `PublicPrProvenance`; `toPublicPrProvenance` is the
single projection from workstation-local registry rows, and `renderResumeFence`
accepts a positive `PrNumber` rather than any path, branch, or session value. The
public command is exactly `bun run beep yeet resume <n>`. Session identifiers,
filesystem paths, harness resume commands, host identifiers, and Codex names remain
only in the append-only local registry.

A UUID or long hexadecimal run in the branch is not treated as a footer leak
because the head ref is already public on the PR page; boundary checks remove
the branch value before applying identifier-shape exclusions to every other field.

Optional Claude display labels cross the boundary only through the positive
`PrProvenanceLabel` slug schema. It rejects path syntax, `..`, `.lock`, UUID shapes,
and hexadecimal runs of 16 or more characters; Codex names are never projected.

`test/yeet-pr-provenance-boundary.test.ts` supplies the regression evidence over
arbitrary local identifier values. It asserts that rendered output has no rooted
path or environment path template, no `cd` or native harness resume command, no
UUID or long hexadecimal run, none of the local record's identifier values, no
comment terminator inside the JSON twin, and exactly one positive-number resume
fence when the PR number is present.
