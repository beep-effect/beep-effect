# CSF-011: Symlinked tmp entry deletes worktrees outside TMPDIR

- Severity: Informational
- Codex ID: `fa191f71f5d48191aa9f31d544cee2e7`
- Source commit: `fdf03d344df6f46452bc7a740d5b46ebc6a024a7`
- Owner: repo-cli tmpfs reaper
- Status: remediated; focused regression proof green

## Public Summary

Top-level temporary discovery followed symbolic links while classification and
Git worktree removal retained the lexical path under the temporary root.

## Current-HEAD Validation

Confirmed on the current head before remediation. A symlinked entry could
classify an external linked worktree and pass its temporary-root alias to Git
for forced removal.

## Remediation

Discovery rejects symlink entries, requires canonical containment, records the
discovery root, and revalidates the path immediately before apply. Explicit
worktree inputs receive the same checks.

Changed files:

- `packages/tooling/tool/cli/src/internal/repo-run/TmpfsReap.ts`
- `packages/tooling/tool/cli/test/tmpfs-reap.test.ts`

## Verification

- The focused tmpfs suite proves a symlinked entry cannot remove or deregister
  an external worktree.
- `@beep/repo-cli` package verification.
