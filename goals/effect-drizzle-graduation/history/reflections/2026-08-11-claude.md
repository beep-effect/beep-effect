# Reflection — effect-drizzle-graduation (2026-08-11, claude)

## Summary

The packet graduated a proven scratchpad experiment into `@beep/effect-drizzle`, the first
member of a newly chartered `ecosystem` family, across three phases and four merged PRs
(#658 doctrine, #664 package creation, #667 review remediation, plus this closeout PR). The
architecture survived contact with every repo gate; almost all friction came from governance
scope changes, not from the code itself.

## Tooling experience

- **Worked:** the yeet pipeline end to end (verify's authoritative full proof, publish's
  proof-reuse push paths, reply drafts, the sweep's tip-matched branch deletion contract);
  codex delegation for bounded jobs with non-overlapping write surfaces; detached
  setsid-plus-sentinel execution for every long run; the dossier-first grounding pattern.
- **Didn't:** new-only attribution on moved code (see findings); local proof manifests
  excusing checks CI later failed; Bun.build as a bundle oracle.
- **Frustrating:** the `--check` lane forms enforcing blocking findings that the plain
  command spellings report as advisory — every reproduction has to use the exact lane
  command or it proves nothing; `changeset add --empty` emitting frontmatter its own CLI
  cannot parse.
- **Wished existed:** move-aware gates; a single tool-loaded-roots inventory consumed by
  both knip and fallow instead of two hand-synchronized lists.

## Implementation improvement opportunities

- The tstyche matrix covers TypeScript 5.9.3 and 6.0.3; add a stable 7.x target the moment
  tstyche supports one, since the native compiler already proves 7.0.2 compilation only.
- The bundle ratchet measures one consumer entrypoint; a second probe over the sqlite
  subpath would catch cross-dialect regressions symmetrically.
- PGlite enum-array parameter serialization and literal relation-name preservation remain
  the two known open boundaries carried from the experiment.

## Goal & prompt critique

`GOAL.md` was accurate but silent on the governance-scope shift being the phase's real
risk. A P1 sentence like "expect every repo law to see this code for the first time —
enumerate the gates before moving files" would have converted a week of gate archaeology
into a planning step. The completion-gate subject convention (slug in the squash subject)
also deserves a line in the launcher, not just doctor's advisory.

## TODOs worth codifying

- Family-onboarding checklist (see frontmatter todos).
- Runtime-capability detection helper for the bun/node shim boundary.
- Bundle assertions must include presence floors — candidate lint or review-checklist item.

## Lessons (confidence-tiered)

- **HIGH — Critical:** reproduce gate failures with the exact lane command (`--check`
  forms, CI inventory paths) — the plain spellings can be green while the lane is red.
- **HIGH — Critical:** a whole-package move is a governance event, not a refactor; plan the
  gate deltas before `git mv`.
- **MEDIUM — Best practice:** treat merged-at-which-head as part of phase-done; resolve the
  full reviewer set on the head that merges.
- **LOW — Consideration:** background agent runs die with their process group; setsid plus
  a sentinel log plus a Monitor is the resilient shape on this machine.
