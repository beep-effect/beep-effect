# Reflection — lejeune-demo-corpus-and-ontology (2026-08-27, codex)

## Summary

The goal produced one lab-local, replay-first corpus capability with two synthetic Office
layouts, exact spans, a 12-class ontology, three cited rules, three deterministic projection
engines, and one sanitized live Anthropic recording. The acceptance surface is locally green,
and the replay remains complete with provider and network access disabled.

## Tooling experience

- **Worked:** The package generator, schema-first and Effect-first guidance, `@effect/vitest`,
  source-level XLSX/PDF generation, PGlite, DuckDB, Oxigraph, and package audit formed a tight
  implementation and proof loop.
- **Didn't:** The 1Password MCP authorization bridge returned an IPC failure even after the
  desktop app was unlocked.
- **Frustrating:** Desktop availability, desktop unlock, MCP authorization, and CLI sign-in are
  separate states but do not have one secret-safe diagnostic surface.
- **Wished existed:** A standard command that reports only those four booleans and can perform
  the approved CLI handshake without exposing account metadata.

## Implementation improvement opportunities

- Promote the deterministic Office-fixture generator shape only after a second lab proves the
  same need; the current schemas and operations should remain lab-local.
- If the corpus grows, split projection acceptance by durable-store adapter while retaining one
  end-to-end bundle identity test.
- Treat the checked-in provider recording as immutable input. A refresh should be an explicit
  reviewable event because its timestamp and response hash affect bundle identity.

## Goal & prompt critique

Add this sentence to the provider posture: "Commit the first successful sanitized recording as
a frozen synthetic fixture; refresh it only through an explicit reviewed change." This would
make the intended relationship between live proof and deterministic replay unambiguous.

The one-PR operator constraint was compatible with the packet, but it should be stated in the
goal launcher when it is required so publication tooling can reject accidental additional PRs.

## TODOs worth codifying

- Add a secret-safe 1Password Developer Environment preflight to the secret-reference skill.
- Document the generated-binary fixture pattern: source generator, parser exercise, frozen
  SHA-256 manifest, exact extraction anchors, and ignored durable artifacts.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Separate source-authored generators from produced binary artifacts —
  this proves real parsers without weakening a public repository's data boundary.
- **MEDIUM — Best practice:** Freeze the sanitized provider response once — reproducible replay
  begins at the recorded boundary, not at a live model call.
- **LOW — Consideration:** Promote the bundle machinery only after demonstrated reuse — keeping
  the first slice lab-local avoids prematurely defining a general ingestion platform.
