# Reflection — skillopt-training-pilot (2026-07-06, claude)

## Summary

One exploration graduated into one goal and one merged PR (#309): flake+uv
provisioning, a 12-task law-derived corpus, a deterministic law-scorer CLI,
a custom beeplaw SkillOpt environment, and a full training run of
schema-first-development with the repo's own quality machinery as the reward.
The loop-runs success bar was met at every scale (1-item smokes through the
8-step full run); the validation gate rejected all six candidate edits, so
the measured lift is zero and the recorded verdict is PARK with findings —
the harness stays one config edit away from the next experiment.

## Tooling experience

- **Worked:** the P0-finding pivot to SkillOpt's native codex_exec backend
  (instead of building a bespoke runner) eliminated an entire subsystem;
  _ENV_REGISTRY injection gave a custom env with no fork; the p23 cross-lane
  contract made three parallel codex lanes compose first-try; the ratchet
  gates from the predecessor goal caught every real defect in codex-written
  code (knip, terse-effect, jsdoc, cspell) before CI did.
- **Didn't:** yeet publish under parallel-session concurrency (three failure
  modes in sequence, ending in the documented direct-push recovery);
  --no-verify commits meeting the commitlint CI gate; duplicate workflow
  runs stamping canceled-job failures on required contexts (rerun clears).
- **Frustrating:** the first verify round red-ing on a stale-dist build
  artifact (types resolve as unknown) that a warm rebuild dissolved.
- **Wished existed:** a scorer daemon mode amortizing tsgo startup across
  the 12-plus invocations a single training step performs.

## Implementation improvement opportunities

- Gate evaluation dominates cost; workers were serialized per SPEC caution
  but the adapter already supports concurrency knobs worth measuring.
- The corpus scores baseline 0.146-0.25 from planted naive-form defects, but
  rollout variance (agent execution noise) is a large score component;
  a variance study (same skill, N repeated rollouts) would sharpen future
  lift claims.
- benchmark-cases.json seeds are static; wiring --record into the beeplaw
  reward path would put every training rollout into ai-metrics DuckDB.

## Goal & prompt critique

The phase order (P1 n=1 before volume, corpus before scorer before adapter)
was load-bearing: the P1 gate probes produced the analyst-declines-unpatchable
finding that shaped corpus design, and the stub-scorer escape hatch let the
adapter prove itself before the scorer existed. Revision I'd make: the SPEC
should have named training-run hyperparameters as an explicit experiment
matrix (edit budget, update mode, optimizer) instead of a single run, so a
zero-lift outcome would flow into the next configured attempt rather than a
park decision.
