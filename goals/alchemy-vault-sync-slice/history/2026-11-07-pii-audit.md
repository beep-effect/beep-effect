# D17 PII audit: vault-sync events, Api payloads and telemetry (2026-11-07)

Decision D17 (`explorations/alchemy-domain-adoption/DECISIONS.md:146-152`) requires the
event payload attributes to be audited for PII before the first deploy. This audit covers
the repository's own schemas and code only. It read no corpus or client documents.

No event, command or rejection declares `attributes`, so the kernel records **no payload
field** as a span attribute or span-event attribute: `Telemetry.attributesOf` returns `{}`
when `attributes` is undefined (`Telemetry.ts:117-123`). That covers command input
(`Kernel.ts:1059`, `Model.ts:611`), rejections (`Kernel.ts:1094-1097`), committed events
(`Kernel.ts:1126-1129`) and policy deliveries (`Kernel.ts:1422`). Every leak above comes
through **identifiers built from payload values**: aggregate ids, View keys, command ids
and saga keys. The kernel always records those (see the next section).

**Standing redaction rules** (both plan documents apply them):

- R1. Paths, file and folder names, destination names, remote names and evidence are
  never span attributes, log annotations, span names, aggregate ids, View keys, saga
  keys, command ids or activity names. Use `ItemId`, `OperationId`, `ConflictId` or
  `DestinationId`, all opaque, or `sha256hex` of the normalized value.
- R2. Every value that reaches `domain.id`, `domain.key`, `domain.stream`,
  `domain.command_id`, `domain.correlation_id` or a URL path segment must have a schema
  that admits only opaque tokens. A brand on `NonEmptyString` is not enough.
- R3. Never declare `attributes` on a vault-sync Event, Command or Rejection, unless the
  function returns only identifiers and literals. A review must reject any `attributes`
  that touch `path`, `name`, `previousName`, `evidence`, `remoteName`, `digest`, `cursor`
  or `cursorError`.
- R4. Content digests (`digest`) are not span attributes either. A content hash confirms
  whether a known document is present; the `ItemId` path hash is enough for tracing.
- R5. Caller-supplied strings (`requestId`, `x-correlation-id`) are validated as bounded
  tokens before they become identifiers.
- R6. Logs carry failure tags, positions and opaque ids, never a raw `Cause`, vendor
  message text or a decoded payload, unless the tier is `dev-verbose`.
- R7. The desktop host mounts `layerCatalogEnrichment` with `StrictDesktop`. Its
  `shape-only` ceiling drops every undeclared attribute key and every span event
  (`Catalog.enrichment.ts:117-160`, `Catalog.behavior.ts:153-161`). No app mounts it yet;
  `git grep layerCatalogEnrichment` outside the observability package finds nothing.

## BoxMirror error messages

The 3c adapter maps every Box failure to `BoxMirrorUnavailable { retryable,
disconnectReason, operation }` with a fixed operation literal and discards the vendor
error (`BoxMirror.ts:31-36`, `:111-113`, `:133`, `:140`, `:232-239`). No Box message text
reaches events, Views, spans or logs through the new path. The remaining exposure is the
legacy availability probe that `BoxMirror.probe` reuses (`BoxMirror.ts:159`): it logs
`documents.sync.failure = "Box <method> failed: <reason> (status) [code]"`
(`DmsMirrorBox.ts:910-914`, `:249-263`, `:868-869`). `reason` is vendor text from
