# Reflection: alchemy-vault-sync-slice (2026-11-08, claude)

## Summary

The `documents` vault-sync slice now runs on `@alchemy.run/domain` 2.0.0-beta.85. The work landed in this order:

- **PR 1, #2810:** foundations, doctrine and the entity-kit freeze.
- **Postgres Platform driver:** #2825 (aggregates and policies) and #2863 (views, projections, streams, Backfill, Cluster engine).
- **PR 3a, #2886:** the domain.
- **PR 3b part 1, #2894:** the saga, the Box mirror adapter and the legacy projections.
- **PR 3c, #2899:** the Api behind Session middleware, with a views-only MCP.
- **PR 3b part 2, #2903:** genesis import, replay-and-diff, single-writer cutover with an epoch fence, and reversal.
- **#2914:** the D17 PII audit and the observability plan.
- **PR 4, #2916:** the optimistic and offline-intents client.
- **This final PR:** the boundary spans registered in the catalog, with the kernel spans nested under them.

Three reds that reached `main` were fixed at root the same day:
- ep41 (#2907), an unregistered migration in the architecture proof manifest;
- ep44 (#2911), the delivery lease outliving a dead host;
- ep47 (in this PR), a test race between two Views.

Verdict: the acceptance criteria hold, and every merge-blocking red was root-caused rather than retried.

## Tooling experience

- **Worked:**
  - Yeet's `final-check`, attributed `--skip` and inbox acks kept each final honest on a host that kills full docgen for memory.
  - The concurrency stress loop root-caused both flaky reds.
  - The `goals decisions add` projection avoided append conflicts.
  - `git apply --3way` of a lane's own diff (stack tip to lane head) re-cut PR 4 cleanly onto a `main` that had squashed the PR 3 stack.
- **Didn't:**
  - The merge gate classified #2903's own red as inherited.
  - `lint effect-vitest --write` rekeyed hundreds of unrelated exceptions when only two rows needed removing, so the rows were removed by hand.
  - `worktree new` reported "Cannot install projection merge driver" yet still created the worktree.
- **Frustrating:**
  - Generated files conflicted on every merge of `main`: the manifest, the coverage baseline, fallow boundaries and the effect-vitest inventory.
  - Vercel rate-limit rows had to be acked on every push.
- **Wished existed:**
  - A gate that names deleted-file coverage rows.
  - Manifest coverage for new migrations.
  - An "is every plan step landed" check.

## Implementation improvement opportunities

- Mount `layerCatalogEnrichment` on the desktop sidecar and server hosts. The `shape-only` and `standard` tiers declared here only take effect at export once that is done. It is host composition in `apps/professional-desktop`.
- Give the `POST /vault-sync/rpc` HTTP server span a route-aware `SpanNameGenerator` in the app.
- Gate an `Outbox.claim` span on a non-empty claim, so idle polls do not emit spans.

## Goal & prompt critique

- In `PLAN.md`, name the final implementation PR once the PR sequence is fixed. Make "acceptance items remaining" an explicit field in the orchestrator's merge notices, so "nothing further owed" cannot be said while items are open.
- The SPEC acceptance line for observability should name the spans it expects, or point at the plan's span table. Then the PRs that own those spans carry them, instead of a plan written after they were content-final.

## Lessons (confidence-tiered)

- **HIGH (critical):** A cross-host wait must outlast the lease that recovers it. A crash-recovery test needs a short, configured lease so it exercises the real recovery path within its own budget (ep44).
- **HIGH (critical):** Attribute every red before fixing it. Of the five reds investigated here (ep41, ep44, ep47, the #2911 coverage rows, the #2903 Repo Sanity red), all were ours. Each looked environmental or inherited at first.
- **MEDIUM (best practice):** For a test that is green solo but red hosted, stress it at 16 concurrent runs before calling it flaky. Then fix the wait condition or the timing bound it exposes, never the timeout alone.
- **LOW (consideration):** Re-cutting a lane built on an unsquashed stack, by applying its own diff onto `main`, is cheaper than merging `main` into it once the stack has landed squashed.
