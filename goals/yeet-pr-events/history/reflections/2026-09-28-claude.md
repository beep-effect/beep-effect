# Reflection — yeet-pr-events (2026-09-28, claude)

## Summary

The goal shipped its producer (slice 1, PR #1270) and then closed in one more PR:
the W7 probe failed for every detached sender, so the session-owned tail (W8) was cut
without writing a line of tail code; the dead-owner notifier (W9) and the Status-chain
collapse (W10) landed with tests, and the packet flips to `completed-retained` in the
same PR. Verdict: the durable bad-news path exists and is measured; idle wake stays
hook injection, dead-owner wake is now a desktop + ntfy notification.

## Tooling experience

- **Worked:** the probe-gate discipline (D20) — a twenty-minute measurement decided a
  slice; `graft skeleton` for orientation; `worktree new` for a clean lane; focused
  `vitest` + `turbo run check --filter` as the fast local proof; Opus 5 implementers
  with disjoint file ownership finishing in parallel in one worktree.
- **Didn't:** `tsgo -p tsconfig.check.json` in a fresh worktree (TS6305 until a turbo
  build); the manifest phase domain has no way to say "cut".
- **Frustrating:** the messaging socket writes nothing back, so hold vs drop is only
  observable from the receiving transcript; the Bash tool's shell lingers after a call,
  which made "child of a live invocation" hard to reason about until measured.
- **Wished existed:** a `--debug` peer-message log per session, and a `yeet` fake-gh
  harness shared across the Status tests instead of a per-test recorder.
