# Reflection — domain-kernel-hardening (2026-10-09, codex)

## Summary

The merged kernel now has one canonical audit pack with nullable, Principal-typed
soft-delete fields and a public EntityRef error role module. P0 reconciled the
retired entity stack, P1 delivered the additive migration and compatible external
bundle parity, and P2 recorded the proof and source-bound inherited reds. PRs
#1577, #1593 and #1599 are merged; this P3 wave closes the retained packet.

## Tooling experience

- **Worked:** The adopt plan exposed the missing sources ledger without rewriting
  the manifest's unmodeled keys. Owner commands generated the migration, desktop
  bundle, packet events and trace. Default package verification and the PGlite
  suites supplied concrete proof rather than inferring runtime health from types.
- **Didn't:** A full inventory refresh could not isolate one existing exception
  anchor; D20 records 22 outside-scope identities and the correct byte-for-byte
  revert. D21 assigns reconciliation to the owner instead of relaxing the gate.
- **Frustrating:** Shared heavy admission, missing tool-shell bus variables and
  sequential Git mutations lengthened qualification. The immediate receipts are
  in research/OPPORTUNITIES.md; no caps, locks or other lanes were changed.
- **Wished existed:** A source-bound affected property/docgen census and a reviewed
  occurrence re-anchor would have reduced repeated publication waves.

## Implementation improvement opportunities

GeneratedByApp with constructor and missing-key defaults preserves constructors
and legacy decode inputs while encoding absence as null. Explicit insert
projections and exact selected-row subjects still need the two columns: the final
89 mechanical sites demonstrate why a compiler-only compatibility count is too
narrow. Future kernel migrations should measure those contracts before bounding
scope. No slice model or behavior edits were required.

The external physical-column marker preserves the shipped practice-kg shape;
legacy bundle load, serve and carry proof passed. Remove that marker only with a
separately qualified bundle migration. The nullable pair models deletion metadata;
paired-nullness, repository filtering and cascade remain later consuming work.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Preserve external physical schemas until their owner ships
  a qualified upgrade. Canonical kit growth cannot silently change bundle DDL.
- **HIGH — Critical:** Read stream findings, not just the exit code of explore
  --check; doctor validates lifecycle but does not prove event/trace integrity.
- **MEDIUM — Best practice:** Count docgen and exact-wire fixtures alongside
  compiler failures, and qualify the complete dependent property set early.
- **MEDIUM — Best practice:** Attribute inherited reds to unchanged source and
  retain proof limits. P2 passes four default package proofs, six-server tests,
  coverage, test-tsgo, knowledge refs and Fallow while recording UI, Accounts and
  JSDoc failures separately; completion does not rename those failures green.
- **LOW — Consideration:** A periodic FIFO admission receipt could make shared
  qualification waits easier to estimate without altering resource policy.
