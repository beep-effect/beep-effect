Commit 15 (PR C) realises design section 7 and section 14, item 15 against the live tree. Commit 14 kept the composer deriving its IRI (decision `2026-11-20-p1-composer-stays-registry-free`), so this commit adds the term-stability gate to the CLI and the lint only. No module that a CI runner handler loads changes.

1. **Base-ref comparison.** `beep lint identity-registry` takes `--base <ref>`. Without it, the base is `git merge-base HEAD origin/main`. The lint reads the base snapshot with `git show <base>:<snapshot>` and runs `snapshotViolations(base, head)` on the snapshot regenerated from the head's shards. That catches a change that edits the shards and the committed snapshot together, which `--check` alone cannot see. A base without a snapshot counts as the empty snapshot, as the design says. A checkout with no default base (not a git work tree, no `origin/main`, or a disjoint history) also gets the empty snapshot and logs a line saying so. An explicit `--base` that git cannot resolve fails loudly.
2. **Kinds.** The design's `term-removed-without-deprecation` (also used for `NamespaceDropped`), `namespace-prefix-changed`, `deprecation-changed` (removed or changed) and `term-revived` are added to both `IdentityRegistryIssueKind` and the lint's violation kind. The design left the binding cases unnamed, so `binding-changed` is added for `SinceRewritten`, `BindingReassigned` and `BindingAmbiguous`. Every `SnapshotViolation` case now has a kind.
3. **`beep identity rebind <from> <to>`** rewrites only the shards whose bindings move. Before writing, it checks the move with `RegistryTable.rebind`, so a move onto a code that is already bound is refused. A move that finds no binding is also refused. It then regenerates the artifacts. The snapshot rows list bindings by code, so a rebind changes the snapshot's binding rows and bumps the minor release. The design's "term-snapshot.json is byte-equal" therefore holds only for the snapshot's terms, namespaces and deprecations. The end-to-end test and L0-3 test 2 assert those collections, not the whole file.
4. **`beep identity deprecate <curie> [--replacement <curie>]`** is the only writer of a deprecation row, as section 7 requires. It removes the local from its shard and appends the row. Its `since` is the release the regenerated snapshot will carry, the next major, which it computes with `RegistryTable.snapshot` rather than a second copy of the release rule. A `ShardDeprecation` replacement is a local of the shard's own namespace, so a replacement in another namespace is refused, and `<prefix>:` names the namespace itself. A term that is still bound is refused: a binding must name a live term, so the binding is removed or rebound first.
5. **Left for later, with reasons:**
   - `binding-dangling`, the ts-morph scan for an annotation call site of each bound code, is not added. Annotations do not read bindings (commit 14), and the fold already refuses an unbound class (`unboundClass`, commit 13), which the research-library tests exercise.
   - `term-local-multi-segment` is not added. The kept values of section 5.2 declare multi-segment locals such as `qa:receipts/accepted/v2` on purpose. Against `origin/main`, which has no snapshot, every one of them is new on P1's own PR, so the check would refuse the design's own data.
   - `registry-since-mismatch` is not added. `deprecate` now computes `since`, and binding `since` values are already guarded by `SinceRewritten` against the base.
   - The `delete-package` guard (`--deprecate-terms`) is not added. No package that owns bindings is a deletion candidate in P1.
6. **L0-3 tests.** `identity/test/TermStability.test.ts` gains two tests on module-derived IRIs. In the first, the module-derived IRI of every bound code (`$BeepId.create(<module path>).iri`) is never in the published set, and where it left the process before P1, its deprecation names the bound term. In the second, a property test rebinds the research-library module to generated paths: the published terms and deprecations are unchanged, there are no violations, and no new module-derived IRI is published.
