# Reflection — text-knowledge-stack-rebuild (2026-11-25, claude)

## Summary

The foundation text-knowledge stack is now eight lawful layers in a dependency DAG:
- One occurrence identity (`@beep/text`).
- One annotation model with content and attribution apart (`@beep/annotation`).
- Typed signals with no algebra, and scoped admission (L4 claim cores, logs and admission).
- Declared term IRIs (registry snapshot 2.4.0).
- RDF datasets as quad sets with an RDFC-1.0 canonical digest.
- One `Operation` arrow with attributed PROV activities.
- A matter-walled agent surface.

`@beep/provenance`, `@beep/nlp` and `@beep/schema-org` are retired through `delete-package`. All 32 law-test ledger rows are green under their ledger titles. The work shipped as P0 #3420, P1 #3429/#3439/#3449, P2 #3511, P3 #3516, P4 #3540 and P5 #3550, followed by P6 #3558 and the final P7/P8 PR. Two rows are held on the corpus, money or operator configuration, with issues #3554 and #3555.

Verdict: the design held. The dependency order L0, L1, L2, L4, L3+L6, L5+L7, cut-over never needed reordering, and no ledger row was deleted. What did not hold was the delivery mechanics. Stacking, regenerated inventories and hosted-only gates cost more commits and wall time than the design work.

## Tooling experience

- **Worked:**
  - The law-test ledger, with test titles prefixed by row id. It made the completion proof mechanical (rg finds every row), and a late row (L5-4) took one decision.
  - Decision files with `goals decisions check` (invalid=0, drift=0 at every exit), plus `kind: checkpoint` files. Checkpoints were the only status surface that stayed accurate.
  - `delete-package --check` with the retired-packages registry, which gave three clean, reversible retirements.
  - Delegated Opus phase implementers with per-row progress notes.
  - `final <sha40> #N` comments with an attribution of each red.
  - Scoped per-file coverage runs.
  - Fixing inherited reds once on main (#3453, #3519, #3542).
  - The squash-stack retarget, which made patch identity provable: `git merge-tree` of `<sq>^` with the parent head equals `<sq>^{tree}`, then merge `<sq>^`, then `-s ours <sq>`. P5 and P6 each proved a byte-identical patch against main.
- **Didn't:**
  - final-check does not replay doctests.
  - `--skip coverage` hides the coverage ratchet's new-file rule.
  - `identity registry --check --base` fails silently.
  - Scoped `schema-catalog --write <dir>` is a no-op that reports success.
  - `delete-package` re-baselines the whole fallow health file.
  - `docgen:local` escalated to the full run at every registration row, so the scoped proof never ran once.
- **Frustrating:**
  - Eighteen hand-written cache-baseline requests, each with a hand-computed basis sha256 and a root `//` subject.
  - About 13 re-record commits after merges.
  - Regenerated projections left conflicted with no markers and no writer named.
  - A 20-minute law-practice-server audit re-run in full for row-level commits.
- **Wished existed:**
  - `yeet stack retarget`.
  - A cache-request drafter.
  - A changed-tests scope for package-verify.
  - A Stop hook that accepts a recorded external blocker.

## Implementation improvement opportunities

- **Composer IRI surface:** delete it from `Id.ts` once a decision accepts one CiRunners handler redeploy (decision 2026-11-20-p1-composer-stays-registry-free). The registry already guarantees that no published IRI is path-derived. The remaining work is the roughly 120 composer read sites.
- **Corpus-free pieces of #3554:** two parts need no corpus and could land first: the C1 measure mode, and switching `CanaryC2Live.ts` and `RuntimeProbeChild.ts` from `contentDigest` to `canonicalDigest`.
- **Generator output:** have the identity registry generator emit data with no clone groups, so `Registry.data.ts` needs no fallow exclusion.

## Goal & prompt critique

- **SPEC from measured facts:** write the SPEC from measured facts, and model CI-closure and handler couplings up front. This was the largest avoidable cost (see findings).
- **PLAN lane topology:** add it. Max two stacked layers. Merge main before the next layer. Repo-wide writer checks green at each registration row.
- **Acceptance mapping per checkpoint:** each phase-exit checkpoint should map every acceptance clause to met, amended or held. Held rows go in a manifest `holds[]` list, with an issue filed at the moment of the hold, not at closeout.
- **S31 wording:** state in the SPEC that S31 is measured against the P0 base for the whole program. P7 measured against its own parent and missed growth from P2 to P5.
- **SPEC decision-log projection:** shrink it to an index.
- **GOAL wait-state line:** add a line to GOAL.md on wait states.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Re-run the repo-wide writer and law checks (effect-vitest, oxlint, JSDoc ratchet, semantic-delta, fallow audit, sherif) on each layer before it is called content-complete. Per-package `package-verify` does not cover them, and P6 carried six classes of red into its final-check.
- **HIGH — Critical:** When a decision deviates from SPEC acceptance text, amend the SPEC in the same decision. Otherwise closeout finds the contradiction, and the deferred deletion has no owner.
- **MEDIUM — Best practice:** Retarget a stacked layer fully before opening it: merge the squash, regenerate, then run final-check. P5 did this, had no failed hosted Check runs, and merged soon after its checks went green.
- **MEDIUM — Best practice:** File the issue for an operator- or money-blocked row when the row is held, and name it in the checkpoint.
- **LOW — Consideration:** Keep decision files for contract-level calls and move implementation-level choices into the phase design. P6 alone wrote 80 decisions.
