## 4. How the repo pins external sources today

Three mechanisms, none of them in `@beep/identity`:

1. **`sync-data-to-ts` acquisition targets**
   (`packages/tooling/tool/cli/src/commands/SyncDataToTs/`). `fetchSource`
   (`internal/Source.ts:230`) downloads and hashes bytes through `Digest.Digest`
   (`:218-227`). `SparTerms.project` (`targets/SparTerms.ts:113-136`) refuses a
   byte-digest mismatch, checks `owl:versionIRI <prefix>:<release>` and
   `dcterms:license <licenseIri>` in the text, requires an explicit
   `owl:Class|ObjectProperty|DatatypeProperty|AnnotationProperty` declaration
   for every curated term, and checks a second "semantic" digest over the sorted
   term list. Only the curated projection is committed; source bytes are not.
   Targets are registered in `targets/index.ts:15-16,41-42`.
2. **Vendor asset manifest** `explorations/legal-ontology-landscape/assets/manifest.jsonl`
   (21 rows; row schema in `assets/README.md`; `fetch.sh` re-fetches into a
   gitignored `vendor/` and verifies `sha256`, since the repo is public and does
   not redistribute third-party bytes). Rows for `skos` (`:13`), `dcterms`
   (`:14`) and `prov` (`:15`: `https://www.w3.org/ns/prov.ttl`, sha256
   `d7ea634dbcd31347eba38157197f69d314077ef7f88fd4f90e4f24a78bfe1097`, "W3C
   Recommendation 2013-04-30 (retrieved 2026-07-08)", license "W3C document use
   rules"). `@beep/ontology/TaxonomyLoader` reads rows of this protocol
   (`VendorManifestEntry` `:172`, `VendorAssetManifestRow` `:556`).
3. **Conformance source registries**: `SpecificationSource`
   (`packages/foundation/modeling/schema/src/Conformance/Conformance.source.schema.ts:398-413`:
   `id`, `title`, `role`, `canonicalUrl`, `revision` (one of `gitCommit`,
   `release`, `datedSnapshot`, `registryVersion`, `retrievedSnapshot`,
   `packageRevision`, `:139-348`), `contentSha256: Sha256Hex`, optional `license`
   as a free `NonEmptyString`), with data in
   `packages/foundation/modeling/{md,html,lexical,pandoc-ast}/data/conformance/sources.json`
   (for example `md-commonmark-0.31.2-spec`, `license: "CC-BY-SA-4.0"`).

So no pinned source file for prov, oa, nif, xsd, gufo or as is committed, and
under the repo's practice none should be. Each needs a pin row: URL at an
immutable revision, revision, byte sha256, curated terms, semantic digest and
license. PROV and SKOS already have a byte digest recorded in the vendor
manifest, which P1 can reuse once it re-fetches and confirms them.

## 8. Open questions

1. **Pin scope.** The decisions pin the six new namespaces plus `skos` and
   `doco`. `dcat`, `rdf`, `rdfs`, `owl`, `dcterms`, `schema`, `deo`, `fabio` and
   `cito` are registry rows too. Does "every namespace the repo speaks" need a
   pin on each in P1, or only on the eight named? `dcterms` already has a vendor
   manifest digest (`manifest.jsonl:14`).
2. **Spoken namespaces in no registry.** SHACL (11 files) and VoID (3 files).
   Register them in P1, or record them as out of scope with their call sites?
3. **`PinnedSource.revision` shape.** It is a free `NonEmptyString` in
   `L6.interchange.ts:38`, while `@beep/schema/Conformance` already has six typed
   revision kinds that rdf can import. Reuse them?
4. **License identifiers.** W3C artifacts carry the W3C document notice, and the
   vendor manifest records "W3C document use rules", not an SPDX id. The revised
   design takes an SPDX expression (`L6.interchange.ts:46`), which fits NIF's
   dual license, but the W3C notice still needs an id: `W3C-20150513` after
   reading each artifact's notice, or a `LicenseRef-*`.
5. **SPDX check placement (resolved by the split decision).** The first design
   put the license check in identity, which would have needed an identity-to-spdx
   dev edge: a cycle, since `@beep/spdx` depends on `@beep/identity`. With the pin
   and its test in rdf, only a new rdf-to-spdx edge is needed.
6. **Home of `ContentHash` and `DomainTag`.** The decisions put the digest
   primitive in `@beep/schema` and the minter in `@beep/jsonc`; the brands can
   live in either. The domain brands of later layers (`OccurrenceId`,
   `AnnotationId`, ...) import whichever is chosen.
7. **The third canonical-JSON alias.** Retire
   `@beep/epistemic-domain/values/ContradictionDetection` `canonicalDetectionJson`
   with the two copies? And beyond it, the epistemics public alias pair and its
   internal wrapper, so that `JsoncFingerprint` is the only import? The census
   classes E1 as owner-backed, so this is a scope call, not a correctness one.
8. **Replacement import for the copies.** Their consumers need a
   `Result<string, S.SchemaError>`. The options: import
   `canonicalDetectionJsonResult` (a misleadingly named alias), map
   `JsoncCanonicalizeError` locally (a new wrapper), or add a `SchemaError`-channel
   twin to `JsoncFingerprint`.
9. **`as:` IRI form.** `http://www.w3.org/ns/activitystreams#` (Web Annotation)
   or `https://…` (AS2). Closed-world expansion admits one IRI per prefix, and the
   OA codec in P3 must emit the form its profile declares.
10. **xsd pin target.** A specification document (XSD 1.1 Part 2 or RDF 1.1
    Concepts) has no term declarations to check, so the semantic digest rests on
    the curated list alone.
11. **PROV artifact.** The vendor manifest pins `prov.ttl` (the namespace
    aggregate), while other research names `prov-o`. Pick one before computing
    the semantic digest.
12. **Dead trustgraph script.** `goals/trustgraph-doc-ontology/scripts/build-artifacts.ts:18`
    imports a deleted module. It is outside P1, but under the rule to fix defects
    where they are found it needs a disposition: delete the script or repoint the
    import.
