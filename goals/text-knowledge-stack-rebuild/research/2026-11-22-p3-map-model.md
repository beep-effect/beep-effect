Defects and gaps found in the model itself:

1. Kind IRIs are undeclared terms. The ten `TermIri.make("https://beep-effect.com/ns/annotation/<Kind>")` calls
   (`:315-429`) enter every `AnnotationId` preimage (`:503`), so they leave the process, and the P1 rule is that such
   IRIs are declared registry terms (decision `p1-registry-first-fold-terms-declared`; chapter 16 section 4,
   `16-knowledge-stack.md:475-484`). No `annotation` shard exists (section 1.1). The generator's predicate
   `https://beep-effect.com/ns/annotation/predicate/relatedTo` (`ops/design/generators.ts:92`) has a two-segment local,
   which chapter 16 rules out for new internal terms (`:481-484`).
2. `CaptureMismatch` is declared twice with the same tag and fields (`L2.annotation.ts:469`, `text/src/LocatorMap.ts:98`).
3. `verifyDocument` reports an unregistered kind and an empty target set as `DocumentKeyMismatch` on `annotations`
   (`:708-716`); neither is a key mismatch.
4. The document JSON is not canonical and repeated keys are silently collapsed. `S.HashMap`'s codec is the array of
   entries in iteration order (`Schema.ts:16021-16026`, encode `HashMap_.toEntries`) and decoding goes through
   `HashMap.fromIterable` (`Schema.ts:16079-16081`), where a later entry replaces an earlier one (`HashMap.set`, union
   semantics `HashMap.ts:893-894`). A JSON document with one annotation key twice is accepted when the last entry
   verifies.
5. `merge` reports the first conflict found by iteration with fixed `left` and `right` (`:567-582`, `:609`), so
   `merge(a, b)` and `merge(b, a)` can fail with different values; commutativity holds only on compatible documents.
6. `Generation` has no producer: the document holds `ActivityId`s only, while the producer and pins the PLAN handoff
   test asserts live in `ActivityStart` (`jsonc/src/ActivityStart.ts:86-94`), which no part of the document carries.
7. `Mention` is `{ class: TermIri }` only (`:271-275`). What consumers read today is wider (section 5.2): label, the
   model's text, attributes, alignment status, confidence.

## 3. The OA/NIF adapter (`L2-6`)

What the profile decision fixes is in section 1.3. What the codec cannot do as designed:

1. No source text. P2 ruled that the `oa:` selector codec cannot be text-free, because a code-point offset needs the
   text before it (decision `p2-text-anchor-oa-codec`; `WebAnnotation.ts:537`, `:581` take `sourceText`). `encodeOa`
   is `(kinds) => (input) => Dataset` (`L6.interchange.ts:311`), takes no text and returns no `Result`, although a split
   surrogate must fail closed; `decodeOa` (`:321`) and `normalize` (`:326`) take no text either. `oa:hasSource` is the
   caller's IRI (same decision), so the encoder also needs it.
2. The capture has no profile property. None of the 16 properties carries `scopeRef`, `sourceRef`, `locator`, the two
   digests, the extractor or `normalizationVersion`, so decoding cannot rebuild `Anchored` receipts or `document.text`.
   `decode(encode(d)) = d` needs the capture as a decoder argument (checked against `oa:hasSource`) or the
   `prov:Entity` projection of `SourceTextIdentity`, which is P5 (`rdf/src/Prov.ts`, ledger `L6-2`).
3. Bodies have no profile property. `oa:hasBody` and `rdf:type` can carry a kind IRI and a `Mention` class; nothing
   carries `Chunk.ordinal`, `Section.depth`, `Figure.label`, `RelationCandidate.{subject,predicate,object}` or
   `CorefCandidate.members`. The round trip of those kinds needs a wider profile (the reversal clause of decision
   `p0-item7-oa-profile` allows it by decision file before P3 opens) or a declared subset of kinds.
4. Native activities do not round-trip. An encoded activity is an IRI; the decoder gives every activity named by IRI
   `ActivityId = hash(imported-activity/v1, IRI)` (`L6.interchange.ts:241-246`), which is not the native id minted
   from `ActivityStart`. Without a rule that recognizes the codec's own activity, annotation and run-entity IRIs and
   maps them back, `decode(encode(d)) = d` fails on every native document. No IRI form for `AnnotationId`,
   `RunEntityId` or `ActivityId` exists; chapter 16 says a non-content instance is minted under a declared namespace
   (`16-knowledge-stack.md:508-509`), and a content id would need its own rule.
5. Third-party subject IRIs. Two third-party annotations with equal content are one `AnnotationId`; their input IRIs
   differ, and blank-node isomorphism does not rename named IRIs. `normalize` must re-mint subject IRIs from content,
   or `encode(decode s) = normalize(s)` is false on such input.
6. Time of imported attribution. `Generation.at` is required (`L2.annotation.ts:64`). For an unattributed annotation
   the only time at hand is the import time, which decision `p0-item7-oa-profile` keeps outside the id so that
   `normalize(s)` depends on `s` and the source digest only; putting it in `Generation.at` and encoding it as
   `prov:generatedAtTime` breaks that. `dcterms:created` is in the profile and is the candidate. An annotation with a
   `dcterms:creator` (an agent) and no activity has no stated rule.
7. The source document digest has no defined input: `ImportActivity.sourceDigest` (`:227`) is a digest of "the
   imported RDF document", but the decoder's input is a `Dataset`, whose canonical digest is `L6-1` (P5).
8. The quotient is not there. `L2-6` is stated on the dataset quotient; today `Dataset` is an array
   (`Rdf.ts:728-731`), `areDatasetsEquivalent` sorts and compares serializations (`Rdf.ts:1243-1251`), and
   `canonicalDigest` and `isIsomorphic` are `declare const` (`L6.interchange.ts:146-154`). The rdf-canonize driver
   (`packages/drivers/rdf-canonize`) cannot be a dependency of a `foundation/modeling` package.
9. NIF is export-only, so `Sentence` and `Word` must also be written as OA annotations or they are lost on decode;
   their NIF triples then decode into the residual. `nif:referenceContext` needs a `nif:Context` node with
   `nif:isString`; both terms are in the shard and neither is in `NifExportTerm` (`:192-199`).
10. Multi-capture input. A third-party dataset whose targets name two sources has no rule beyond the
    `capture-mismatch` refusal (`:285-290`): refuse the input or split it.
11. Unknown kinds. `unknown-kind` refuses the whole input; routing the annotation to the residual instead is the other
    reading of "never dropped silently".
12. The imported-activity table is not verified: the checked entrypoint checks anchors, annotations and run entities
    (`L2.annotation.ts:696-731`), not that each `importedActivities` key is `hash(imported-activity/v1, iri)`.
13. Constants: `@beep/rdf` has three OA constants, no NIF or AS module; P1's census row (`consumer-census.md:278`)
    sends hand-written constants to the registry. Read the terms from `@beep/identity/Registry` or add rdf vocab
    modules.
