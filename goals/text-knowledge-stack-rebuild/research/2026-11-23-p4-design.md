### 1.1 Schema construction rules

Every ordinary data record is a uniquely branded, annotated S.Opaque over S.Struct or S.TaggedStruct.
Factories return annotated ingredients and accept the caller's SchemaIdentity, matching
Factory/Factory.model.ts:41-58. Each concrete caller owns its Opaque wrapper. Tagged unions are
annotated union values with same-name derived types and schema-derived constructors/guards. Do not
extend a single Opaque class over a union: the throwaway compile proved TS2509 on that construction.
Each case needing a nominal record has its own branded TaggedStruct wrapper before union assembly.
No inventory exemption is necessary. Named literal domains use annotated LiteralKit without as const;
fixed fields use S.tag. No non-JSDoc source comments, including prototypes and tests. Exports have
compilable titled Example sections, categories and since. Errors alone use branded S.TaggedError.

No signal or identity/authority/provenance field receives a default. Optional keys use
OptionFromOptionalKey; encode None by omitting the key. Use HashSet/HashMap for set/map semantics;
CanonicalHashSet sorts encoded string values before a preimage. JSON codecs use S.toCodecJson,
fromJsonString and Effect codecs; expected boundary failures are translated once, never thrown.

### 1.3 Preimage and integrity

Declare ClaimPreimage through @beep/jsonc/Mint.definePreimage, domain claim/v1, tuple containing the
fully JSON-encoded core. The sketch already uses that object shape in mintClaimId, L4.claims.ts:249.
There is no arbitrary unknown public mint. Encode through the actual caller schema before minting.
Use an array-shaped generic preimage schema if generic S.Tuple inference fails, as P3 documented;
assert exactly one element at its boundary. A changed wire preimage bumps the tag immediately.

`decodeClaimRecord` decodes, re-encodes canonically, re-mints and compares key, then validates log
placement separately. A valid string hash is not evidence of content integrity. Golden fixtures are
written by the implementation's fixture commit, verified by Preimage.verifyGolden and an independent
SHA-256 over canonical bytes. Set permutation/duplication, proposition/parent/scope/supersedes
changes and optional-key omission are explicit golden/property cases. No design golden is claimed. A real core encode/mint over a duplicated support array was also run: reversing its decoded set preserved ClaimId (section 8).

## 2. Service contract, authority and errors

Foundation has no state or second implementation requiring Context.Service. It exports Effect.fn
arrows with explicit ports. Product services remain Context.Service and keep FileSystem/SqlClient/
Path in their layers. Digest.Digest is the only infrastructure requirement for hashing. The
schema table precedes these contracts deliberately.

- `promote(options)` takes typed candidate annotations, their checked document, verified anchors,
  proposition, explicit activity/start/generation time, actor and scope. It checks each support
  occurrence against the document and source identity, encodes/mints the core and returns proposed.
  Support is a canonical occurrence set, not a set of claim or assertion ids. AnnotationId remains
  available in a separate provenance link. Empty support is legal for an unsupported proposal; an
  admission still requires fresh nonempty grounding. Every supplied required creation fact is explicit.
- `admit(options)` takes ClaimRecord, requested principal/action/revision/scope, token, grounding,
  an authenticated principal port, token verifier and current-source resolver. Resolve current source
  text under the same authorized scope and re-verify each receipt. Re-mint occurrences; each must be
  in this core's supportAtCreation. This prevents borrowing the same occurrence's acceptance from
  another claim. Do not require every annotation Generation.at: imported annotation times can be None
  (P3 generation ruling). Creation of a new claim needs its own explicit native generating activity.
- The token verifier authenticates the attestation; matching token fields is necessary but insufficient.
  Verify actor/action/revision/scope and issuedAt <= admission at. Ports are Effect-returning functions;
  resolver returns Verified or a typed expected refusal value. Infrastructure errors remain typed port
  errors until the use-case translates them. Adapters log technical details and die as required by SPEC.
- Successful admission returns an Admission record; the slice's capability constructor is private and
  unavailable to schema decoding. Revalidation of stored records repeats authorization and current
  verification. Refusal is a value and produces no record append, no coordinate update and no signal
  mutation. P6 still owns deployment of the seven access-path MatterAuthority port.
- `appendClaim(log, record, generation)` checks integrity and all prefix laws before returning a new log.
  It does not mutate a database. A transactional slice repository enforces its own concurrency/unique
  constraints and preserves the existing valid-time exclusion constraint.

Observe ClaimCore.promote, ClaimCore.mint, ClaimCore.decodeChecked and ClaimAdmission.admit with ids,
digests and counts only. Refusal reason is safe; quote, matter text and token are never span attributes.
Regenerate instrumentation shards when implementation adds these functions.

## 3. Pure functions and law interpretation

`checkClaimLog` becomes a fold over validated append prefixes. Index by ClaimId with HashMap; verify
that supersedes names an earlier existing record in the same (scope, logicalKey), never a future or
missing record. Detect a repeated id before an index can overwrite it. Exact replay returns unchanged
state at the repository boundary; a duplicate is not a new append. Every derivedFrom parent already
exists and starts no later than the child. Generation end cannot follow knowledgeStart. At most one
superseder exists, and current Interval valid times are disjoint; Unknown asserts no interval.
Check overlap on each prefix so a future superseder cannot conceal an invalid historical overlap.

`knowledgeInterval` ends at its explicit superseder's start, not the next record with its key.
Half-open bounds include start and exclude end. Equal starts are allowed; stability at t begins only
when the append order has strictly passed t. Cross-scope identical bytes never merge partitions.
Acyclicity is conditional on minted ids and content-hash collision resistance; parent ordering provides
the operational proof even for hostile supplied hash strings. Challenges are a separate graph and may
cycle. Use effect/Graph.isAcyclic in generated law proofs; do not hand-roll graph algorithms.

Retraction uses the sketch's HashMap/HashSet dependency worklist: roots are never flagged merely for
having no parents, partial live support stays live, wholly dead nonempty derivation flags transitively.
It emits flags, never edits ClaimCore or silently retracts a person's assertion. Duplicate/reordered
retraction inputs are set semantics; challenge cycles do not affect the closure.

`updateAssessment` replaces exactly one declared coordinate. A refused transition returns the original
record; updates of distinct coordinates commute. Test gate monotonicity under explicitly supplied
owner orders. A lifecycle's chronological transitions are not automatically an increasing order of
admissibility. Test actual policy predicates, and include unknowns and ties. Triage ranking is a named,
versioned policy that never grants admission.

L4-5 owner equivalence is independent of the key implementation: party's proposition equivalence,
Kb's tag/subject/object/text equivalence, Holds same holdId equivalence. Holds renewal text/lease can
change while the logical subject remains the same; full core identity still changes. Never prove this
law by defining equivalence as key equality in the test itself.

## 7. Nanopublication adapter

The external structure is the four-graph form in the official
[Nanopublication Guidelines](https://nanopub.net/docs/guidelines/): a head links one assertion,
provenance and publication-info graph. This design adopts a restricted profile inside that structure,
not a claim to round-trip arbitrary third-party RDF. Namespace is http://www.nanopub.org/nschema#.
Registry writer adds the np terms and a checked source/license/version/digest NamespacePin in @beep/rdf;
identity stays RDF-free. Do not invent a license: use the official source's declared license and pin
its actual bytes in the implementation fixture commit before the adapter can pass its gate.

`makeNanopubCodec({ binding })` yields encode/decode/normalize. Encode takes a checked ClaimRecord plus
explicit publication metadata. Use instance IRIs under the existing registry, derived from ClaimId,
for the claim IRI. A separate NanopubId hashes `[ClaimId, canonical publication metadata]` under nanopub/v1; five distinct IRIs derived from that id name the publication and its four graphs. Changing publisher/time therefore changes the publication id even when the core is unchanged. Publish metadata is a total branded record with publisher IRI, publication time and optional source digest; no default provenance. Assertion contains
`<claim> epistemics:coreJson "canonical encoded core"^^rdf:JSON`; the typed literal is an explicit
Beep profile, not a legal ontology. The provenance graph uses the assertion graph as subject for prov:wasGeneratedBy and prov:wasAttributedTo from the core;
pubinfo names publisher/import metadata separately. No scalar confidence becomes certainty.

Decode requires one nanopublication and five pairwise-distinct publication/head/assertion/provenance/pubinfo IRIs, exact allowed profile
terms/cardinalities and no named graph mixing. Decode the JSON with the caller codec, re-mint ClaimId
and verify redundant provenance fields agree. Parsed assertions are proposals/import data; Admission,
token and mutable review authority do not enter the profile. Unsupported quads remain residual;
unsupported core/profile is a refusal containing the original input, never a silent partial core.

`decode(encode(record)) = record` for profile records with explicit publication metadata.
`encode(decode(dataset).accepted) = normalize(dataset)` as ground quad sets for accepted profile data;
normalize independently filters and canonically names the profile, retaining residual separately.
Fixtures: reordered quads, repeated identical quads, typed caller proposition, optional valid bound,
two support orders, wrong core hash, mismatched provenance, graph collision, missing head edge,
foreign predicates, and token-looking triples. Dataset blank-node quotient remains P5; this profile
emits ground quads and rejects blank graph names. No hash-of-RDF algorithm is invented.

`NanopubAdapter.test.ts` lives in epistemics/test, as PLAN specifies. An import-boundary test traverses
base entry imports and proves @beep/rdf is reachable only from rdf/NanopubCodec. Test the adapter using
existing Dataset APIs; do not re-export RDF types from the root. Round-trip proof remains implementation
work; the throwaway design did not simulate an RDF codec.

## 14. Review

Separate adversarial pass after the first draft: re-read the cited source lines and upstream API
exports, checked commit dependencies and every map consumer category against the matrix above.
Revised the design in response to these findings:

1. Opaque-over-union does not compile (TS2509). Use a schema union and nominal struct cases instead;
   recompiled the prototype with zero diagnostics. No schema-first inventory row was added.
2. A final-snapshot log check can hide earlier overlap and ignores missing predecessors/duplicates.
   Reproduced both zero-violation cases, then required append-prefix validation and integrity checks.
3. Old claim rows cannot supply authentic human tokens or full creation provenance. Added explicit
   imported records and missing facts, preserved historical bounds and old namespaces, prohibited
   backdated migration activities and distinguished a legacy review from an admission.
4. The first stored map treated semantica too generically. Live LedgerLive.ts has claims/batches and
   hashes full payloads under ids whose preimages omit confidence. Added both persisted forms,
   nested reader migration, raw-digest verification and immutable replay conflict tests. The map is
   amended below its original inventory with exact lines, not silently claimed complete by a cache.
5. Unavailable attachments need not make a proven message citation unknown. Specified match-first,
   then Unknown only for missing passages whose document text cannot be checked. Added all three
   policy branches and critic/field paths to row 7's gate.
6. An S31 rule for data classes cannot be met by inventing an exception for generic factory products.
   Specified annotated ingredients and caller-owned branded wrappers; tagged unions stay schemas.
7. Moving primitives affects L3 design imports and schema handler dependencies before final cleanup.
   Put these in the same move commit and added handler regression checks. No claim of unchanged
   bundle bytes is made without an implementation measurement.
8. Publication metadata cannot share a publication id derived only from ClaimId: it can change while
   the core stays fixed. Added nanopub/v1 identity over core id plus publication metadata, five distinct
   graph/publication IRIs, and the official requirement that provenance refer to the assertion graph.
9. Old scalar semantica confidence cannot distinguish a true model report from historical default 1.
   Kept raw numeric metadata, projected unprovable origin to legacy-unknown, and left provider cache
   bytes untouched. Never call an old fabricated 1 a calibrated or genuinely reported probability.
