### 1.5 The document codec: one checked decode, one canonical encode, one assembler

Decision `p3-document-json-is-canonical`. `S.HashMap` encodes entries in iteration order and keeps the last of a
repeated key (`Schema.ts:16021-16026`, `HashMap.ts:893-894`). `makeDocumentCodec({ schema, kinds })` returns:

- `decode(input: unknown)`: `Effect.fn("AnnotationDocument.decodeChecked")`. Decode the envelope
  (`internal/DocumentJson.ts`: `StructWithRest` over `anchors`, `annotations` and `attribution` entry arrays); refuse a
  repeated key with `DocumentKeyRepeated`; decode through `S.toCodecJson(schema)` (the pure checks); run the key
  verification (each anchors key is `mintOccurrenceId` of its row, each annotation key `mintAnnotationId` of its value,
  each generation's `run` `mintRunEntityId` of its pair), failing with `DocumentKeyMismatch`. Error channel:
  `S.SchemaError | DocumentKeyRepeated | DocumentKeyMismatch | PreimageMintError`; requirement `Digest.Digest`. The
  only decode path for this JSON from the wire or storage; the handoff decode is built on it. The OA decoder reads RDF,
  not this JSON, and builds its document through `assemble` and `merge` (section 8.4), so every key in its output is
  minted, never read.
- `encode(document)`: `Effect.fn("AnnotationDocument.encode")`. Schema encode, then `canonicalDocumentJson`: every
  table sorted by encoded key, every generation set by `run`. One byte form per document.
- `assemble(input)`: `Effect.fn("AnnotationDocument.assemble")`, the effectful constructor.
  `input = { text, generation: { activity, at }, anchors: Iterable<Anchored>, annotations: Iterable<Annotation<Kinds>> }`.
  It mints every key, gives every annotation one `Generation` of the activity, refuses an anchor whose receipt names
  another capture (`anchor-off-capture`), a target with no anchor (`target-without-anchor`) and a body reference with
  no annotation of an allowed kind (`reference-unresolved`), then validates through `S.toType(schema)`.

The bare schema stays exported for composition and generators only (it accepts a forged key, which `L2-4` proves).

### 1.6 `merge`, `restrict`, `closure`

`merge` (dual, `Result`), decision `p3-merge-refusals-are-symmetric`: over different captures, `CaptureMismatch` with
the two identities ordered by their eight fields; otherwise the union of anchors, annotations and attribution sets;
if any (content, activity) pair then has two times (`None` against `Some` included), the least
`GenerationTimeConflict` by (annotation id, activity id), with `left` the earlier time. Content-keyed tables make
the union idempotent; the symmetric refusal makes `merge(a, b)` and `merge(b, a)` the same `Result`.

`closure(kinds)(names)` is the least superset closed under each kind's `references`. `restrict(kinds)(keep)(doc)` takes
`keep: HashSet<KindName<Kinds>>` (an unregistered name is a type error; decision `p3-annotation-package-surface`),
refuses `RestrictionNotClosed { missing: closure(keep) - keep }`, and otherwise keeps the annotations of the kept
kinds, the anchors their targets use and their attribution. It never drops a dependent or widens.

`restrictToOa(doc: TextDocument): OaDocument` is `restrict` to the five OA kind names, then a decode of the result's
type side through `OaDocument`. The OA kinds reference no kind, so the restriction cannot refuse, and every annotation
left is of an OA kind, so the decode cannot fail; either failure is a defect and dies. An `ExtractionDocument` widens
to a `TextDocument` first.

### 1.7 Containment

Decision `p3-containment-levels-are-monotone`. `contains(kinds)(doc, outer, inner)` is true when both annotations
have one target and a level, `outer`'s range covers `inner`'s, and `outer.level <= inner.level`, strictly on equal
spans. Ranges are `Anchored.range` (`utf16-code-unit`). Extraction kinds and multi-target annotations take no part.
A one-sentence paragraph contains its sentence; a word whose range includes a sentence does not.

### 4.2 Handoff output

Decision `p3-handoff-output-shape`.

```ts
// Handoff.model.ts
export const ResidualReason = LiteralKit(["unaligned", "unmapped-label", "verification-refused",
  "relation-attribute-missing", "unmapped-predicate", "relation-endpoint-unresolved"]);
const CandidateFields = { candidate: S.Natural, label, text, attributes: S.OptionFromOptionalKey(S.Record(S.String, S.String)),
                          confidence: S.OptionFromOptionalKey(UnitInterval) };
class ExtractionReading    { ...CandidateFields, alignment: AlignedStatus }                       // Encoded the same, options as optional keys
class ResidualCandidate    { ...CandidateFields, alignment: AlignmentStatus, anchor: S.OptionFromOptionalKey(TextAnchor),
                             reason: ResidualReason }
  // check: anchor is Some exactly when alignment is not "unaligned" (the aligner's anchor, not verified)
class ExtractionActivity   { id: ActivityId, start: ActivityStart }
class ExtractionHandoff    { document: ExtractionDocument, activity: ExtractionActivity, candidateCount: S.Natural,
                             readings: S.HashMap(AnnotationId, S.NonEmptyArray(ExtractionReading)), residual: S.Array(ResidualCandidate) }
  // checks: readings keys are annotations; every generation names activity.id;
  //         the candidate indices across readings and residual are exactly 0..candidateCount-1, each once
export const HandoffRefusal = LiteralKit(["activity-id-mismatch", "readings-key-repeated"]);
class HandoffRefused extends S.TaggedError("HandoffRefused", { reason: HandoffRefusal, key: S.String })
class LangExtractResult    { handoff: ExtractionHandoff, diagnostics: LangExtractDiagnostics }
export const decodeExtractionHandoff;   // checked: readings-key-repeated, the document's checked decode (1.5),
                                        // then activity.id = mintActivityId(activity.start), else activity-id-mismatch
export const encodeExtractionHandoff;   // canonical: the document's canonical encode, readings sorted by key,
                                        // each reading array by candidate index
```

Encoded handoff:

```json
{ "document": { "...": "the canonical document of section 1.5" },
  "activity": { "id": "sha256:...", "start": { "operation": "https://beep-effect.com/ns/operation/Extract",
                "pin": { "_tag": "Engine", "engine": "anthropic", "edition": "claude-opus-4-6" },
                "promptDigest": "sha256:...", "used": ["sha256:<capture id>"], "started": 1763510400000 } },
  "candidateCount": 3,
  "readings": [["sha256:<annotation>", [{ "candidate": 0, "label": "distinction", "text": "...", "alignment": "match_lesser" }]]],
  "residual": [{ "candidate": 1, "label": "claim", "text": "...", "alignment": "unaligned", "reason": "unaligned" },
               { "candidate": 2, "label": "examiner", "text": "...", "alignment": "match_exact",
                 "anchor": { "startChar": 40, "endChar": 48, "quote": "examiner" }, "reason": "unmapped-label" }] }
```

`candidateCount` is the number of parsed candidates (today's `LangExtractDiagnostics.candidateCount`), so a handoff
that loses its last candidates fails its own check. A residual keeps the aligner's anchor whenever its candidate
aligned: the candidate's own range for a `Mention` target or an unmapped label, the evidence range for a relation. The
anchor is not verified (a `verification-refused` residual keeps the anchor that failed); a reader that uses it
verifies it, as semantica's canonicalizer does.

A reading belongs to the annotation its candidate became: a `Mention` from a `Mention` target, or a
`RelationCandidate` from a `Relation` target. An endpoint `Mention` minted for a relation, and a `CorefCandidate`,
have no reading of their own. Two candidates that read one class at one occurrence are one annotation with two
readings, in candidate order.

`LangExtractResult` is in-process only. A handoff from outside the process goes through `decodeExtractionHandoff`.
`ExtractionHandoff` and its two codecs are exported from `@beep/langextract/Handoff`. `toAnnotatedDocument`,
`AnnotatedDocumentInput` and the `Contract` import go.

### 4.3 The handoff run

`handoff(input): Effect<ExtractionHandoff, never, Digest>` is `Effect.fn("LangExtract.handoff")`. It is exported so
that semantica's cached canary can run it over a cached response. Its input is:

```ts
{
  targets: NonEmptyArray<ExtractionTarget>;
  verified: VerifiedSourceText;
  candidates: ReadonlyArray<GroundedExtraction>;
  activity: ExtractionActivity;
  at: DateTime.Utc;
}
```

`extract` runs these steps in order. Steps 1 and 2 are the service's; steps 3 to 6 are `handoff`'s.

1. **Verify the capture, then start the activity.**
   - `verified = verifySourceTextIdentity({ expectedSource: request.source, source: request.source, sourceText:
     request.text })`. A refusal fails the run with `source-text-mismatch` before any model call.
   - `started = Clock.currentTimeMillis`, then the prompt.
   - `activity = startExtraction({ prompt, source: request.source, started })`, built from:
     - operation `operation:Extract`;
     - pin `Engine { engine: ProviderName, edition: ModelName }`;
     - `promptDigest`, the SHA-256 of the prompt's UTF-8 bytes through `Digest.digestHex`;
     - `used = { CaptureId }`;
     - `started`;
     - `id = mintActivityId(start)`.
2. **Call the model and align.** The model call, `parseModelOutput` and `alignCandidates`, then
   `at = Clock.currentTimeMillis` once.
3. **Pass one, per candidate `i` in model order.**
   - An unaligned candidate goes to the residual as `unaligned`, with no anchor.
   - A label that names no target goes to the residual as `unmapped-label`, with the aligner's anchor.
   - Otherwise the candidate's `anchor` goes through `verifyTextAnchorAgainstVerifiedSource`. A refusal goes to the
     residual as `verification-refused`, with the anchor it refused. A verified anchor becomes
     `Anchored.make({ receipt: toTextAnchorVerificationReceipt(proof) })`.
   - A `Mention` target then gives `Mention { class }` over the occurrence, with a reading.
4. **Pass two, `Relation` targets.** Every residual of this step keeps the candidate's own anchor, the evidence range.
   - The subject, object and predicate attributes must all be present; otherwise `relation-attribute-missing`.
   - The predicate maps through `predicates`; otherwise `unmapped-predicate`.
   - Each endpoint surface is aligned by `alignCandidate` inside the evidence quote, at fuzzy threshold 1. Only the
     exact, lesser and minimal-fold tiers count, as in semantica's `scopedEndpointAnchor` (`ExtractorLive.ts:422-437`,
     `locateRelationEvidence` `:403-410`). The anchor is shifted by the evidence start, then verified and anchored.
     Otherwise `relation-endpoint-unresolved`.
   - Each endpoint becomes `Mention { class: endpoint }` over its occurrence. Content addressing makes a repeated
     endpoint one annotation.
   - The handoff does not choose among other Mentions at that occurrence: a reader that wants an entity there reads
     the anchors row, as semantica's `exactAnchoredEntity` (`:438-445`) does today.
   - The relation's reading sits on its `RelationCandidate`, whose one target is the evidence occurrence, whatever
     the endpoints' occurrences are.
5. **Coreference.** Mentions of one class whose readings share a coreference attribute value form a `CorefCandidate`
   over their Mention ids when there are two or more distinct Mentions. Its targets are the union of its members'
   targets (decision `p3-target-annotation-vocabulary`).
6. **Assemble.** `assemble` runs with `generation = { activity: activity.id, at: Some(at) }`. A minting failure over
   verified text dies. `candidateCount` is the length of `candidates`, one per parsed candidate.

`extract` returns `LangExtractResult { handoff, diagnostics }`, with the counts as today.

### 8.3 Signatures

Decision `p3-oa-codec-signatures-and-profile`:

```ts
encodeOa: (kinds: OaKinds) => (input: { document: OaDocument; importedActivities: HashMap<ActivityId, ImportedActivity> },
  options: { source: IRI; text: VerifiedSourceText }) => Result<Rdf.Dataset, OaEncodeRefused>
decodeOa: (kinds: OaKinds) => (input: Rdf.Dataset, options: { source: IRI; text: VerifiedSourceText; importActivity: ImportActivity })
  => Effect<{ document: OaDocument; importedActivities; residual: Rdf.Dataset; rejected: ReadonlyArray<OaRejection> },
            PreimageMintError, Digest.Digest>
normalize: (input: Rdf.Dataset, options: same as decodeOa) => Effect<Rdf.Dataset, PreimageMintError, Digest.Digest>
```

The encoder refuses `capture-mismatch` when `options.text` is not the document's capture; a code-point conversion
refusal cannot occur on verified anchors but is typed. The encoder needs no import record: an import generation is
written like a native one, under the instance IRI of its `ActivityId` (section 8.4). `importActivity.sourceDigest` is
the SHA-256 of the RDF bytes the caller parsed (the decision's last paragraph).

The decoder's only error is a minting failure. It mints every key itself and reads no annotation, occurrence or run IRI
as an id, so it has no key to verify and no `DocumentKeyMismatch`. The document it assembles has verified anchors,
targets that are those anchors, no body references (the OA kinds have none) and one time per (content, activity) pair
once the `time-conflict` rejections are made, so an `assemble` or `merge` refusal or a schema failure there is a defect
and dies.

### 8.4 Mapping

Encode, per annotation `a` (all IRIs printed by `instanceIri`, so the output is ground; decision
`p3-oa-instance-iris-and-ground-datasets`):

| Triples | Source |
| --- | --- |
| `<a> rdf:type oa:Annotation, <kind IRI>` | the annotation and its kind |
| `<a> oa:hasBody <class>` | `Mention` only |
| `<a> oa:hasTarget <o>`; `<o> rdf:type oa:SpecificResource; oa:hasSource <options.source>; oa:hasSelector <o>/position, <o>/quote` | each target occurrence `o`, shared by every annotation on it |
| `<o>/position rdf:type oa:TextPositionSelector; oa:start s; oa:end e` | `Anchored.range` converted to code points |
| `<o>/quote rdf:type oa:TextQuoteSelector; oa:exact q` | `Anchored.quote` |
| `<r> prov:specializationOf <a>`, plus `<r> prov:generatedAtTime t` when the time is stated | each `Generation`, whatever its activity (`r` the instance IRI of its run id) |
| `<r> prov:wasGeneratedBy <act>; <act> rdf:type prov:Activity`, `<act>` the instance IRI of the `ActivityId` | a generation whose activity is not in `importedActivities`: a native activity, the import activity included |
| `<r> prov:wasGeneratedBy <iri>; <iri> rdf:type prov:Activity` | an `ImportedActivity.Activity { iri }` generation |
| `<r> dcterms:creator <agent>` or `<r> as:generator <agent>`, and no `prov:wasGeneratedBy` | an `ImportedActivity.Creator` or `.Generator` generation |
| `<o> rdf:type nif:Sentence` or `nif:Word`; `nif:beginIndex s; nif:endIndex e; nif:anchorOf q; nif:referenceContext <options.source>`; `<options.source> rdf:type nif:Context` | `Sentence` and `Word` only, export-only |

Decode: every `oa:Annotation` whose targets name `options.source` is read: kind from its second `rdf:type`
(`unknown-kind` if absent from `OaKinds`), body from `oa:hasBody` (`body-refused` if its kind takes none or needs
one), targets through `webAnnotationTargetToTextAnchor` and verification against `options.text` (`target-refused`).
Its id is re-minted from kind, targets and body; the IRI of the annotation, and of every target, selector and run, is
never read as an id, even in the instance form. Attribution follows one rule, which `normalize` shares:

- Each `prov:wasGeneratedBy`, `dcterms:creator` and `as:generator` statement gives one generation, whether the
  annotation makes it or a run `r` with `r prov:specializationOf <a>` does. A `prov:wasGeneratedBy` object in the
  instance form is the native `ActivityId` it prints, the import activity's included; any other object is an
  `ImportedActivity.Activity`. A creator or a generator is `Creator` or `Generator`. Imported activities are keyed by
  `imported-activity/v1`.
- A run's statement takes the run's time, its `prov:generatedAtTime`, else its `dcterms:created`. An annotation's own
  statement takes the annotation's time, read the same way.
- An annotation with no statement gets one generation of the import activity (the id of `options.importActivity`),
  with the annotation's time when it states one.
- `time-conflict` rejects an annotation when one subject (the annotation or one of its runs) states two different
  times, and every annotation that gives one (content, activity) pair two different times, `None` against `Some`
  included, across its statements or across annotations of equal content.

Rejected annotations and every triple outside the profile (all `nif:` triples included) go to the residual (decision
`p3-oa-rejections-go-to-the-residual`). `assemble` gives every annotation one generation, so the document is the
`merge` of one `assemble` per distinct (activity, time) of the shared rule, each over the accepted annotations that
have that generation and the anchors of their targets; merge is associative and commutative (`L2-1`), so the grouping
order does not matter, and neither function can refuse here (section 8.3).

`normalize(s)`: project `s` to the profile over `options.source`, leaving out what the shared rule rejects; rename every
accepted annotation to the instance IRI of its re-minted `AnnotationId`, every target and selector to its occurrence
form; complete both selectors (the quote from the text, the position from a unique quote), dropping `oa:prefix` and
`oa:suffix`; write each generation of the shared rule as the encoder's run entity, at the instance IRI of
`mintRunEntityId(content, activity)`. The annotation-level and run-level `prov:wasGeneratedBy`, `dcterms:creator` and
`as:generator` statements move onto that run, `dcterms:created` becomes its `prov:generatedAtTime`, every
`prov:wasGeneratedBy` object is typed `prov:Activity`, and an annotation with no statement gets the import run, whose
`prov:wasGeneratedBy` is the instance IRI of the import activity's id. Last, add the NIF triples of `Sentence` and
`Word`. It is written as rules over quads, independently of `decodeOa` and `encodeOa`, so `L2-6` compares two
implementations.

## 14. Risks for the implementer

1. Commit 8 is the widest: run the four standing-list files, `Handoff.test.ts` and semantica's `Extractor.test.ts` in the
   edit loop, and each package's `bun run test` once at the end.
2. `S.Tuple` built from type-parameter schemas does not type-check under tsrs (the trap named above the first section); keep generic helpers
   on `S.Array` or at the JSON boundary.
3. `HashSet.make<T>` takes the tuple of values as its type parameter (`HashSet.ts:153`); upcast a `CaptureId` to
   `ContentHash` with the schema's `make`, not a type argument.
4. An L2-4 forgery must replace the key everywhere (annotation key, attribution key, generation content, re-minted
   run) or it fails in the schema before the key check and proves the wrong thing.
5. `Generation.at` is an option: `HashSet` deduplication by `Equal` still treats two records for one pair as two when
   the times differ, which is the refusal case; generators must draw one time per (content, activity).
6. The semantica relation lane depends on moving its endpoint policy into the handoff exactly (fuzzy threshold 1, the
   three non-fuzzy tiers); commit 1's frozen preview report is the check (section 6).
7. The wink span becomes none for every repeated entity surface; semantica's pattern-lane tests that expect a span on
   a repeated name change with it.
8. New test files need the 100 percent hosted coverage row, the effect-vitest law and, where the package shards, the
   shard list.
9. Every stub `LanguageModel` layer that feeds `LangExtractService.layer` must become an Effect model
   (`Model.make(provider, name, layer)`). Each missed site is a type error naming the two model services, which is how
   the list in section 2 is checked.
10. Semantica maps a relation residual in today's order: decode, then tier, then endpoints. A residual's `reason`
    alone would mislabel a fuzzy relation with an unresolved endpoint, which is `fabricated-span` today.
11. Do not write the lossless check as a comparison with `A.makeBy(candidateCount, identity)`. `makeBy` raises its count
    to at least one (`Array.ts:196-197`, `:219`), so an empty run would be refused. Compare the sorted indices'
    length with `candidateCount` and each index with its position.
