ambiguity fails closed, and callers that need candidates search for them explicitly.

### 1.5 Unit conversion

```ts
convertPosition: {
  (unit: OffsetUnit, sourceText: string): (position: Position) => Result.Result<Position, UnitConversionRefused>;
  (position: Position, unit: OffsetUnit, sourceText: string): Result.Result<Position, UnitConversionRefused>;
};
slicePosition: { (sourceText) => (position) => Result<string, UnitConversionRefused>; (position, sourceText): ... };
```

One forward scan over code points (`internal/scalars.ts`) keeps the three running offsets (UTF-16 units, scalars,
UTF-8 bytes; UTF-8 width by code-point range 1 to 4) and records the target offset when the source-unit counter equals
the boundary. A boundary the counter skips is `split-boundary` (a surrogate pair in UTF-16, a multi-byte sequence in
UTF-8). A boundary past the end is `out-of-range`. A lone surrogate met before both boundaries are resolved is
`ill-formed-text`. Same-unit conversion still checks the boundaries. `slicePosition` converts to UTF-16 and slices.
The scan is a plain loop with a "Performance boundary" comment, as `langextract/VerifiedSpan.behavior.ts` does.

### 1.6 `resolve`

```ts
resolve: { (selector: Selector): (sourceText: string) => Resolution; (sourceText: string, selector: Selector): Resolution };
```

Semantics (decision `p2-selector-resolution-semantics`):

- `Position`: convert to UTF-16; refusal is `NotFound`; otherwise `Unique` with the slice.
- `Quote`: every start at a scalar boundary where `exact` matches, the text before ends with `prefix` and the text
  after starts with `suffix`; overlapping hits count. 0 `NotFound`, 1 `Unique`, n `Ambiguous{count: n}`. One KMP scan
  whose needle is the concatenation `prefix + exact + suffix`; each hit reports the offset of `exact`, and the
  scalar-boundary test applies to the `exact` range only. The cost is linear in text plus needle: a hostile repeated
  quote with a long repeated context is not a product of the two.
- `Fragment`: `NotFound` (no fragment specification is interpreted over plain text).
- `Refined`: resolve `base`; on `Unique`, resolve `by` in that slice and shift by the base start.
- `Range`: from the start of `from` to the start of `to`, exclusive (W3C 4.2.8). Empty or inverted is `NotFound`.
- Composite: any `NotFound` part gives `NotFound`; otherwise any `Ambiguous` part gives `Ambiguous` with the product of
  the counts (`Unique` counts 1).

Resolution outcomes are values, never errors (SPEC "Error boundaries").

### 1.7 Text normalization

`normalizeText(normalization, text): NormalizedText`:

- `nfkc`: the joins-cluster scan: a scalar joins the open cluster when its own NFKC form starts with a combining mark
  (`\p{M}`) or when normalizing the two together differs from normalizing each. Each cluster becomes one segment:
  `Kept` when normalization leaves it unchanged (adjacent `Kept` segments are merged), else `Rewritten`. Property in
  `Normalization.test.ts`: the concatenation equals `Str.normalize("NFKC")(text)`. Clusters by grapheme are not enough
  ("ㄱㅏ" composes to "가"), and testing whether the scalar itself is a mark is not enough either: U+0E33, U+0EB3,
  U+FF9E and U+FF9F are letters whose NFKC form starts with a mark, and `"Z\uff9e\u0323"` normalizes to U+1E92 U+3099
  (decision `p2-nfkc-clusters-join-on-the-normalized-mark`).
- `dehyphenate`: remove `-` or U+2010 plus one line break (`\r\n`, `\n` or `\r`) when a letter (`\p{L}`) precedes and a
  lowercase letter (`\p{Ll}`) follows. The segment is the whole context the rule reads: the preceding scalar, the
  removed run and the following lowercase scalar become one `Rewritten` segment (`m-\np` to `mp`), and matches that
  share a scalar merge into one (`a-\nb-\nc` to `abc`). A cut before the lookahead letter is therefore inside a
  `Rewritten` segment and widens; with the letter outside the segment the target of `exam-\n` was `exam`, which is not
  the normalization of that quote.

`normalizeQuote("nfkc-dehyphenate/v1")` is `dehyphenate` after `nfkc`, text only.

### 1.8 `LocatorMap` and `reanchor`

`reanchor(anchored, map, target: VerifiedSourceText): Effect<Reanchoring, PreimageMintError, Digest.Digest>`, dual,
`Effect.fn("Reanchoring.reanchor")`:

1. `from = mintOccurrenceId(anchored)`.
2. `anchored.source` not equivalent to `map.from`, or `target.source` not equivalent to `map.to`: `Unmapped{capture-mismatch}`.
3. Walk the segments that overlap the range. A part of the range no segment covers: `Unmapped{outside-map}`.
4. A boundary inside a `Kept` segment maps pointwise; a boundary strictly inside a `Rewritten` segment moves to the
   segment edge and marks the result widened; an image that spans text inserted in the target is widened too.
5. A `Kept` part whose target text differs from the same part of the quote: `Unmapped{quote-mismatch}` (the recorded map
   does not describe this text).
6. Build the `TextAnchor` from the target slice and verify it with `verifyTextAnchorAgainstVerifiedSource`; a refusal is
   `Unmapped{split-boundary}`. The proof is projected to its receipt: `to = Anchored.make({ receipt })`.

`LocatorMap.identity(capture, length)` is one `Kept` segment. `LocatorMap.compose(first, second)` returns
`Result<LocatorMap, CaptureMismatch>` and fails when `first.to` is not `second.from`; it cuts the middle capture at
every segment edge of either map that is not strictly inside a `Rewritten` segment of the other, keeps the pieces both
maps cover without a gap, and marks a piece `Kept` only when one `Kept` segment of each map covers it.

Laws (decision `p2-reanchoring-shape-and-lax-direction`): identity gives `Exact` with the same id; when both steps and
the composite are mapped, the stepwise range is inside the composite range (the lax comparison runs from the steps to
the composite); `Exact` then `Exact` composes to the same `Exact`; on `Exact` the target quote is the normalization of
the source quote (naturality, for either normalization and for `dehyphenate` after `nfkc`). `Unmapped` is outside the comparison: an insertion the second map does not cover makes
the steps `Unmapped` while the composite is not. On gap-free maps (every `normalizeText` map of a whole text) the
comparison is total.

### 1.9 `VerifiedTextAnchor` and why a decoded receipt cannot become one

Unchanged. `VerifiedTextAnchor` is `S.declare` over membership in a module-private `WeakMap`; the only writers are
`verifyTextAnchor` and `verifyTextAnchorAgainstVerifiedSource`, the latter only from a `VerifiedSourceText` that is
itself in a private `WeakMap`. Decoding any JSON, spreading, cloning or forging a prototype produces an object that is
not a key of the map, so `S.is(VerifiedTextAnchor)` is false and `S.decodeUnknown*` fails. There is no function from
`TextAnchorVerificationReceipt` or `Anchored` to `VerifiedTextAnchor`; `toTextAnchorVerificationReceipt` goes one way.
`reanchor` and `@beep/md` `anchorAt` obtain proofs only through verification. `L1-6` tests exactly this.

## 2. Service contracts

None in `@beep/text` (decision `p2-no-context-service-in-text`). Every function is pure or needs only core's

`@beep/workspace-server`) and stays there. Instrumentation: the three moved spans plus `Occurrence.mint`,
`QuoteKey.mint`, `Reanchoring.reanchor`; attributes carry ids and counts, never quote text.

```ts

  "selector-conflict", "ambiguous", "not-found", "no-text-selector"]).pipe($I.annoteSchema("WebAnnotationAnchorRefusal", ...));

  => Result.Result<TextAnchor, WebAnnotationAnchorRefused>;                       // dual
```

Encode: the anchor's UTF-16 range becomes a `Position`, `convertPosition` to `unicode-code-point`, the slice must equal
`anchor.quote` (else `selector-conflict`), and the target carries
`[TextPositionSelector{start,end}, TextQuoteSelector{exact}]`. Decode reads every selector and fails closed:

1. Each position selector becomes a code-point `Position` (start >= end is `empty-range`) and converts to UTF-16. Two
   position selectors must give the same range, else `selector-conflict`. The quote is the slice.
2. Each quote selector, when there is a position, must equal the slice, and a stated prefix or suffix must match the
   text on that side of it; anything else is `selector-conflict`.
3. With no position, each quote selector goes through `resolve` with its own prefix and suffix and must be `Unique`
   (`not-found` or `ambiguous` otherwise); two quote selectors must resolve to the same range, else `selector-conflict`.
4. Fragments are ignored beside a text selector; a target with neither kind is `no-text-selector`.

The result is a candidate anchor, never a proof. A `TextAnchor` has no context and no fragment, so prefix, suffix and
fragments are not carried: encoding a decoded target is stable on the anchor, not on the target. The new literal domain
and error class carry `semanticSchemaMetadata` (the InteropAndMetadata audit covers every exported schema) or are listed
in that audit's exclusion with `WebAnnotationSelector`.

the maps and refuse a dangling one; (6) set the two tags. The live schema decode then runs the coherence filter.

no mention to map and is refused unless empty).
