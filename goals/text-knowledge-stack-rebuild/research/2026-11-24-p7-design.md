## 3. Migration order

No commit removes an API that something still reads. With no code consumer, the order instead
protects the references and the doctrine:

1. schema-org first (row 1): it couples to neither nlp nor the chapter. Its look-alike string
   fixtures, registration tables, `_typos.toml` lines and the one `turbo.json` policy input line
   are edited in the commit that runs `delete-package @beep/schema-org --allow-stale-packets`,
   before the run, so the hard refusal is gone when it starts. `lint policy-fingerprint --write`
   runs after the run, once the manifest is gone, and cannot write the line back.
2. The lane first merges a P6 head that contains P6 row 16 (the "Pending P6" rewrites of chapter
   16). If no such head exists yet, row 2 waits; P7 never rewrites lines P6 row 16 owns. Then the
   chapter absorbs every remaining `THEORY.md` claim (row 2) while the file still exists, so the
   commit that deletes it (row 3) removes no doctrine. The `nlp-processing` README gains the
   backend sentence citing `L5-4` in row 2, before §7's file leaves.
3. nlp (row 3): every hit of section 2.3 is edited in the commit that runs
   `delete-package @beep/nlp --allow-stale-packets` (the `turbo.json` input line before the run, the
   fingerprint after it), and the chapter's two remaining mentions move to "the former nlp package"
   in the same commit.
4. The vision correction (row 4) cites chapter sections by number, so it follows row 2.
5. The `DECISIONS.md` landing entry (row 5) records both retirements with their recovery commits,
   so it follows rows 1 and 3.
6. Packet records (row 6) and the cache and S31 reconciliation (row 7) close P7.
   `delete-package <name> --allow-stale-packets --check` must print clean for both names in row 7,
   after the cache baselines stop naming the retired subjects.

Before rows 1 and 3, the lane merges the current P6 head and re-runs the dry run, so the hit lists
are the merged tree's, not this design's. On that merged base, and before each `delete-package`
apply, the seven checks whose writers the apply re-runs in write mode
(`packages/tooling/tool/cli/src/commands/DeletePackage/DeletePackage.command.ts:489-515`, run at
`:567-598` after the tree is removed at `:846`) must all be green: `bun run beep lint schema-first`,
`bun run beep lint package-scripts --check`, `bun run fallow:health:baseline:check`,
`bun run fallow:dead-code:check`, `bun run beep lint schema-catalog`,
`bun run beep observability catalog --check` and `bun run beep lint package-test-typecheck`
(`fallow boundaries` is checked by `bun run fallow:boundaries:check`). A red one holds the row
until the owning layer's fix is merged into the lane. `--skip-baselines` is not the escape:
it also skips the in-process coverage subtraction (`:571-575`, `:860`), and a writer run over a red
base would admit another layer's entries (`lint schema-first --write` drops missing entries from
the failure set and writes the merged inventory, `Lint/internal/SchemaFirstScan.ts:694`, `:748`) or
rewrite another layer's manifest (decision
`delete-package-runs-only-on-a-green-writer-base-and-its-writers-only-remove`).
