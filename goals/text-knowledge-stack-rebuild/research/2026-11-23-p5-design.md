### 1.1 Schema construction rules

The P4 rules carry over: every exported schema carries an `$I.annote*` description from its package
composer; class schemas use `extends Parent.extend<X>()({})`; string-literal domains use `LiteralKit`
without `as const`; set-valued fields use `effect/HashSet` or `effect/HashMap` and never native
`Set`/`Map`; every effectful function is `Effect.fn`; no free comments. A set field whose wire form
must be deterministic encodes as a deduplicated, sorted array through the `CanonicalHashSet`
construction (`packages/foundation/modeling/schema/src/CanonicalHashSet.ts:64`: `S.toEncoded`,
`S.Array`, `S.decodeTo(S.HashSet(item), SchemaTransformation.transform(...))`), because `S.HashSet`
encodes in iteration order (`Schema.ts:16162`). Where the item is a struct, the sort key is stated
per schema below.

### 1.3 Identity and preimages

`DatasetDigest` is the one identifier digest of the SPEC Constraints: `sha256:` plus the hex of the
canonical bytes. The semantic-web `DatasetFingerprint.fingerprint` (`Sha256Hex`,
`semantic-web/src/services/canonicalization.ts:283-286`) stays a transient CAS token with its live
bytes: it hashes the `trimEnd`-ed canonical text (`drivers/rdf-canonize/src/adapters/canonicalization.ts:218`,
`:267`), while `DatasetDigest` hashes the canonical N-Quads, which end in a newline. They are not
equal and no test claims they are. The driver test asserts instead that, for `rdfc-1.0`,
`canonicalText` equals `trimEnd(CanonicalForm.nquads)`, so the CAS token keeps its bytes.

`ImportActivityPreimage` moves from `import-activity/v1` (`OaCodec.ts:351`, `S.Tuple([Sha256PrefixedDigest])`)
to `import-activity/v2` over `S.Tuple([DatasetDigest])`. `importedAt` stays a record field outside
the id (`OaCodec.ts:330`, "outside every id"; SPEC `:666`), so two imports of one dataset share an
id and `normalize(s)` stays a function of `s`. The hashed field changes meaning, so the domain tag
bumps. A new golden pins one v2 id.

`SourceTextEntity` mints no new id. Its subject is `instanceIri(CaptureId)` where the `CaptureId` is
the one `mintCaptureId` (`text/src/Capture.ts:184-190`, `Effect.fn.Return<CaptureId,
PreimageMintError, Digest.Digest>`) derives from `CapturePreimage` (`:140`). Both projection
directions are therefore effectful (section 2). The decoder re-mints from the decoded fields plus
the reader-supplied `scopeRef` and compares.

The mapping set id is `Registry.mint("annotation", "mapping-set", "doco-nif", version)`. Seed IRIs
are spelled only in the pack's JSON assets, as the literal strings `$SemanticFoundationId` printed
(`identity/src/packages.ts:529`). TypeScript in `packages/law-practice/*/src` derives every scheme
IRI through `$SemanticFoundationId.create(...)` and every pilot term through the identity `Registry`,
because the public-origin rule scans `packages/**/src/*.ts` and exempts only identity and public-site
(`cli/src/commands/Laws/RetiredIriAuthorities.model.ts:249-253`, `RetiredIriAuthorities.ts:380-391`).
No new composer is added, so `identity/src/packages.ts` stays out of the change.

### 3.3 L6-2: projection deterministic; kept fields satisfy GetPut and PutGet

A projection is a partial lens with a fixed complement: `get: S -> Effect<Dataset, E, R>` (kept
fields), `put: Omitted -> Dataset -> Effect<S, E, R>`, which may refuse, and the declared omitted part
`o: S -> Omitted`, compared under a declared quotient `~` on `S` (`Equal` unless an instance names
another). Laws, for every generated `s` and every generated candidate `v` (decision
`l6-2-instances-are-partial-lenses-with-a-fixed-complement-and-effectful-put`):

1. Determinism: `get(s)` succeeds, is `Equal` to `get(s)` across calls, and its `canonicalDigest` is
   stable.
2. GetPut: `put(o(s))(get(s))` succeeds with some `s'` and `s' ~ s`.
3. PutGet: if `put(o(s))(v)` succeeds with `s'`, then `get(s')` is `Equal` to `v`.

PutGet quantifies over candidates `put` may refuse, so it can fail. The candidate generator draws
`v` from four pools: `get(s)` itself; `get(t)` for an independent `t`, which includes the image of
the same fields under another `scopeRef`; and perturbations of `get(s)`: an extra quad about the
subject, a dropped kept quad, and a duplicated kept predicate with a second object. A `put` that
accepted any of the perturbations would break PutGet, because `get` of the result cannot reproduce
the extra or duplicated quad; the law therefore requires `fromDataset` to refuse unknown quads about
the subject (`unknownQuad`) and repeated kept predicates (`duplicateField`). A refusal satisfies the
law, so the harness also counts acceptances and asserts that the `get(s)` pool is always accepted.

### 3.5 L3-2: mapping sets coherent and consistent

Both checks run on the SKOS closure of the set, not on single pairs, because SKOS makes
`exactMatch` transitive and symmetric and makes `broadMatch` a sub-property of `broader`, whose
transitive closure is `broaderTransitive`. `checkMappingCoherence` first builds, with `effect/Graph`:

- exact classes: `Graph.undirected` (`Graph.ts:679`) with one edge per `exactMatch`, partitioned by
  `connectedComponents` (`:6745`); a class is named by its least IRI;
- the broader graph: `Graph.directed` (`:642`) over exact classes, an edge from the subject's class
  to the object's class per `broadMatch` and the reverse per `narrowMatch`; `broaderTransitive(C, D)`
  is reachability, read with `Graph.dfs` (`:10330`) from `C`;
- related pairs and close pairs, each lifted to their exact classes.

Consistency (`ConflictingPredicates`): an exact class with a related pair inside it, or that reaches
itself in the broader graph, violates S46 (`exactMatch` disjoint from `broadMatch` and
`relatedMatch`); a related pair `(C, D)` with `broaderTransitive(C, D)` or `broaderTransitive(D, C)`
violates S27 (`related` disjoint from `broaderTransitive`, the citation the repo's own SKOS record
uses at `explorations/identity-as-iri/DECISIONS.md:205`); and a cycle across two or more classes in
the broader graph, which includes broad and narrow in the same direction on one pair, is refused as
a repo rule. Coherence (`DisjointUpperTypes`): the comparison group of an exact class is the class,
plus every class joined to it by one close, broad or narrow edge. Every two typed members of a group
are compared. They conflict when their instance categories differ, or when each reaches exactly one
`Kind` through `specializes` and the two Kinds differ. Untyped terms never conflict, and a chain of
untyped terms no longer hides two typed members of one exact class.
