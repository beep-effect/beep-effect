# Reflection — gate-report-core (2026-11-19, claude)

## Summary

The goal ported the core of vitest-agent into four packages and put `test` and `check` on one
console contract, rendered from a typed record, for every package and at the root. A green test
run of `@beep/glob` prints one line of 47 characters, where it printed 13,450 at the exploration
baseline. It landed as three pull requests in one day. The design held; most of the review findings
were edge cases in two promises the code made too broadly.

## Tooling experience

- **Worked:** The architecture review before any code gave four package homes and the rule that
  kept every test task's hash small. Separate authors per slice, each resumed for its own review
  rounds, kept context where the code was. A read-only port review by a fresh reader found four
  defects the authors and two review bots had missed. Property tests over the report schema's
  arbitrary made the console laws cheap to hold.
- **Didn't:** Stacked lanes over squash merges. Every base merge after an ancestor merged was a
  conflict wall in code the lane already contained.
- **Frustrating:** Review arriving against a head that had moved, and follow-ups on resolved
  threads that no count shows. Each fix push re-armed the review window and needed another
  ten-minute proof.
- **Wished existed:** A final proof that re-proves one package after a one-package fix, and
  package-verify that includes the generated catalog checks.

## Implementation improvement opportunities

- Integration lanes at the root still stream their output; Turbo neither caches nor restores their
  records. They belong to the rollout goal.
- Coverage runs write no gate record, because the coverage planner replaces the reporter list.
- The slim check entry adds 25 to 40 ms to every package check. Reading the references once per
  root run and passing the result down would remove most of it.
- An occurrence ordinal is a position, not an identity. The history goal should match same-shape
  diagnostics by location before it trusts the ordinal.
- The input fingerprint outside Turbo is the run id. The history goal needs the digest of the head
  commit and the uncommitted changes that the spec describes.

## Goal & prompt critique

- Replace "P1 Schema, P2 Service contracts, P3 Implementation" with "P1 the model, pure and
  complete with its law tests; P2 the services; P3 the adapter and the wiring". The law tests need
  the reducer and the dispatch, so the pure core cannot wait for P3.
- Add to the spec's console contract: "an omission line is part of the frame and is never dropped;
  the body shrinks instead". The first budget fix dropped it.
- State the in-run identity rule beside the item key: "the cross-run key leaves out lines; within
  one run, things that differ only in what the key leaves out stay distinct".
- Name the pull requests in the plan: the model; the libraries; the adapter, wiring and closeout.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Test a "never" with a property — the run entry's promise was broken four
  times by unlisted cases and closed once by a property over arbitrary event lists.
- **HIGH — Critical:** Keep in-run identity apart from the cross-run key — three separate
  collapses came from reusing a key that leaves out location.
- **MEDIUM — Best practice:** Send a fresh reader over a port before the last pull request — the
  port review found four defects after two bots and the authors had passed the code.
- **MEDIUM — Best practice:** Split the code that every task hashes from the code that renders —
  the record library keeps the test hash near the size of one small package.
- **LOW — Consideration:** Fold the closeout into the last code pull request when the review of
  the port is already done — a fourth pull request would have added a cycle for documents only.
