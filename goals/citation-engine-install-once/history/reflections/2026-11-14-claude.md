# Reflection — citation-engine-install-once (2026-11-14, claude)

## Summary

The goal met every count it set. Per request the engine now performs 0 stage installs (14 before),
0 tokenizer builds (10 before over ten calls, now 1 per engine), 0 evaluator installs and 0
configuration detaches; engine construction performs 1 detach (10 at A3). Extraction output, the
public `CitationEngine` shape and the limit values are unchanged, and the 291 regex evaluations and
child processes per ten calls are unchanged, which is the next goal's target. Four slices merged:
A1 #3253, A2 #3265, A3 #3282, A4 #3319.

## Tooling experience

- **Worked:** The count fixture from A1. Every later slice was gated on a table of counts, with
  wall time reported beside it, so host load never decided whether a slice had worked. Independent
  review on a separate session found real defects in each slice, including installed `Duration`
  values reachable through a returned extractor report.
- **Didn't:** The coverage ratchet has no green route for rows a PR lowers on purpose; see the
  first finding. `final-check` measured the whole repository for a one-file PR.
- **Frustrating:** Delegated children ended their turn while a test sweep was still running, several
  times. Hosted-only gates (oxlint's inline-schema rule, the effect-vitest inventory) surfaced after
  local package checks had passed.
- **Wished existed:** A package audit mode that runs a chosen list of test files, and a coverage
  baseline prune that needs no suite run. Both are recorded in `research/OPPORTUNITIES.md`.

## Implementation improvement opportunities

- `S.Record` drops a descriptor capture name that fails `GroupIdentifier`; refuse it instead.
- `ownedDerive` is sound only because it has one production call site and its derivation builds
  fresh values. A lint rule limiting its callers would turn that discipline into a check.
- The separately callable artifact entry points still snapshot raw input themselves; they are
  listed in the A4 evidence file and sit outside the detach count.

## Goal & prompt critique

- The design contract was worth its cost: most stops were places where the code differed from what
  the design assumed, and each was settled by a recorded ruling and not by improvisation. Its one
  gap was derived configuration (finding four). Proposed edit to design section 2.1: add "the
  default engine derives its installed configuration; it is owned by derivation from the owned
  caller configuration, not decoded".
- The detach target read "2 + 8 per call to 1". After A3 moved installs to construction the count
  was per engine, not per call. The packet should have restated the target when A3 merged.

## TODOs worth codifying

- The three items in the frontmatter `todos`.
- A brief line for every slice that deletes tests: list each deletion with its reason in a decision
  file, and re-baseline with hosted-measured values.

## Lessons (confidence-tiered)

- **HIGH — Critical:** Gate performance work on counts from a fixture, not on wall time — the ten
  calls took 36.9 s to 62.5 s across runs at different host loads while the counts never moved.
- **HIGH — Critical:** Never trade a typed, closed refusal for a defect to satisfy a coverage floor
  — re-baseline the row and record why.
- **MEDIUM — Best practice:** After a decode moves to a boundary, delete the tests below it that
  can no longer fail and test the refusal at the real boundary — about 45 refusal blocks in A4
  asserted a reason the test itself supplied.
- **MEDIUM — Best practice:** Read hosted Coverage Regression before calling a head final; it is
  not a required check and a green rollup hides it.
- **LOW — Consideration:** Carry ownership in a brand with a module-private constructor; the
  compiler then shows every site that would otherwise copy defensively.
