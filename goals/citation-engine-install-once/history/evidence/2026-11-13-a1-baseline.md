# Slice A1 baseline: counted engine work on the full-span cohort

Recorded 2026-11-13 from `packages/law-practice/server/test/CitationCanonicalFullSpan.test.ts`
on the commit that adds the probe. The instrument is
`test/CitationEngineProbe.fixtures.ts`: an Effect `Tracer` that counts spans by
name, plus the observed spawner's count of child processes. Each of the ten
original calls now asserts its own row, so a later slice that moves a count
must change the row in `citationCanonicalFullSpanWork` in the same pull
request.

The span names counted are `Citation.makeMetadataOperation`,
`Citation.detachMetadataConfiguration`, `Citation.makeTokenizer`,
`Citation.makeRegexWorker` and `Citation.evaluateRegexProcess`.

What the numbers confirm from the exploration's source read:

- Every call installs 14 metadata operations, runs 8 configuration detaches and
  builds the tokenizer once. None of the three depends on the input.
- The ten calls start 291 child processes, all of them regex evaluations (the
  cohort is plain text, so no Diff or Markup process runs).
- Regex worker objects are constructed 56 times across the ten calls, between 3
  and 15 per call, which is the per-token construction the design moves to
  engine construction.
- The node runtime's replay of call 1 produced the same row as bun's.

Engine construction is outside these rows: the probe measures each call on one
shared installed engine.
