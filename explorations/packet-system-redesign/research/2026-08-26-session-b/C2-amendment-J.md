## Scope and method

I counted a **gate** when repository delivery, packet integrity, evidence quality, or developer operations can be reported green/red by an executable command, workflow job, or typed evaluator. I grouped aliases that invoke the same evaluator, and excluded product authorization decisions such as Epistemic egress `allowed | denied`; that is runtime business policy, not a repository conformance gate. (`packages/epistemic/domain/src/values/ExecutionVerdict/ExecutionVerdict.model.ts:202-233`)

The census starts from the executable registries rather than filenames: the 25-lane feature-branch Yeet full proof, the 23 `beep ci lane` ids, and the 25 leaf steps in the root lint-policy battery. (`packages/tooling/tool/cli/src/commands/Yeet/internal/Planner.ts:399-425`; `packages/tooling/tool/cli/src/commands/Ci/CiLane.ts:150-205`; `packages/tooling/tool/cli/src/commands/Quality/Tasks.ts:1989-2047`) It then adds typed gates that those process lanes wrap or that run independently: Goals/Explore, knowledge, reflection, QA, changeset, architecture, Fallow, coverage, docgen, commitlint, gitleaks, dependency review, AI-metrics installation, and agent effectiveness. (`packages/tooling/tool/cli/src/commands/Quality/internal/GithubChecks.ts:258-317`; `packages/tooling/tool/cli/src/commands/Quality/internal/GithubChecks.ts:365-451`; `packages/tooling/tool/cli/src/commands/Quality/internal/GithubChecks.ts:475-565`)

For the tables, **digest** means a digest of the actual verdict inputs, not a commit label, tool-image pin, or human-readable command line. **Skip** asks whether the emitted result distinguishes skipped/degraded from passed. **Reach** asks whether the result says what inputs or rules were and were not examined. The common subprocess adapter reduces success to `exitCode === 0`, and the local GitHub-check envelope reduces each lane to `passed | failed | not-run-early-stop`; neither carries input digests, assumptions, or examined subjects. (`packages/tooling/tool/cli/src/commands/Quality/Tasks.ts:1121-1141`; `packages/tooling/tool/cli/src/commands/Quality/Tasks.ts:1440-1477`; `packages/tooling/tool/cli/src/commands/Quality/Quality.schemas.ts:881-965`)

## Gates that report success after a skip or degradation

These are not hypothetical modeling objections. Each path below reaches a successful command or workflow result after a check did not run, ran with reduced evidence, or could not prove the scope implied by the green surface.

### 1. Dependency Review: Explicit Fail-Open On Unknown Availability

The required `Security` job first runs OSV, then asks GitHub whether the dependency graph is enabled. If the API command succeeds but the status is absent or unavailable, it writes `enabled=false`, warns that dependency review is being skipped, and the guarded dependency-review action never runs; the job remains green if OSV is green. (`.github/workflows/check.yml:754-760`; `.github/workflows/check.yml:761-825`) The machine-readable lane catalog calls this a deliberate fail-open, declares `dependency-review` required, and gives it no replay. (`packages/tooling/tool/cli/src/commands/Ci/CiLane.ts:506-525`) This is Amendment J's exact target: the truthful certificate is `abstain`, with an assumption naming unavailable dependency-graph status and reach limited to OSV, not PASS.

### 2. Yeet Closeout: `passed` And Exit Zero With Unknown Evidence

Closeout defaults disable all three numeric/text thresholds: empty Greptile score, negative Greptile issue limit, and negative review-comment limit. (`packages/tooling/tool/cli/src/commands/Yeet/Yeet.command.ts:158-178`; `packages/tooling/tool/cli/src/commands/Yeet/Yeet.command.ts:413-445`) With those defaults, unknown Greptile score/count makes `blocked=false` and produces `status: "passed"`; hosted checks are always recorded as `unknown`. (`packages/tooling/tool/cli/src/commands/Yeet/internal/closeout/Gates.ts:165-228`; `packages/tooling/tool/cli/src/commands/Yeet/internal/closeout/Gates.ts:251-282`) `runCloseoutMode` ignores the gate-state statuses and exits successfully whenever the separate `issues` array is empty. (`packages/tooling/tool/cli/src/commands/Yeet/internal/Handler.ts:917-960`) The report is bound to a reviewed head SHA, but that binding does not turn unknown hosted checks into evidence. (`packages/tooling/tool/cli/src/commands/Yeet/internal/closeout/Closeout.schemas.ts:144-180`)

### 3. Yeet Status And Watch: Missing Or Skipped Gate Evidence Becomes Green

`beep yeet status` runs the typed gate-staleness census through `Effect.orElseSucceed([])`, so any failure collecting the changed inputs or artifact witnesses becomes an empty verdict set. (`packages/tooling/tool/cli/src/commands/Yeet/internal/Status.ts:1075-1088`) The renderer turns that empty set into `gate staleness: none`, which is materially stronger than “staleness could not be assessed.” (`packages/tooling/tool/cli/src/commands/Yeet/internal/GateStaleness.ts:487-505`; `packages/tooling/tool/cli/src/commands/Yeet/internal/Status.ts:1223-1239`) This is a direct J violation despite the excellent `fresh | stale | unproven` leaf type: collection failure needs an assumption and `conforms: null`, not an empty passing reach.

Watch mode has the complementary aggregation bug. It faithfully classifies every hosted check as `pending | pass | fail | skip`, but declares `all-terminal` whenever no check is pending, counts only `fail`, and returns exit zero unless that failure count is positive or the end reason is closed/poll-error. (`packages/tooling/tool/cli/src/commands/Yeet/internal/WatchStream.ts:145-160`; `packages/tooling/tool/cli/src/commands/Yeet/internal/WatchStream.ts:642-681`; `packages/tooling/tool/cli/src/commands/Yeet/internal/WatchMode.ts:448-468`) Therefore an all-skipped check wave is a successful terminal watch. A certificate would preserve those skipped check ids as assumptions and prohibit pass.

### 4. QA Judge: Budget Drops And Read Failures Are Outside The Passing Inventory

The judge manifest honestly records byte-budget omissions and says the judge must not claim coverage of them. (`packages/tooling/tool/cli/src/commands/Qa/JudgePack.ts:293-323`; `packages/tooling/tool/cli/src/commands/Qa/JudgePack.ts:621-688`) `qa-inventory/v1`, however, contains findings, judge identity, required count, round, and session reference only; it has no manifest reference, assumptions, or reach. (`packages/tooling/tool/cli/src/commands/Qa/Inventory.schemas.ts:439-517`) `qa judge-lint` decodes that inventory and cross-checks only its cited events/artifacts, so an empty inventory with `requiredCount: 0` can pass while `judge/manifest.json.dropped` is non-empty. (`packages/tooling/tool/cli/src/commands/Qa/JudgeLint.ts:53-105`) Worse, candidate collection converts directory-read, canonicalization, and file-stat failures into empty arrays or `Option.none`, so those files disappear before budget selection and are absent even from `dropped`. (`packages/tooling/tool/cli/src/commands/Qa/JudgePack.ts:693-742`)

### 5. Knowledge Semantic Delta: Degraded Probes Still Produce A Green Gate

The report has an unusually good partial model: `enabled | skipped-untrusted-context | skipped-base-boot-failure`, and it documents that the skipped states omit `unknown-beep-command` and `index-drift`. ## Prior art

### The Existing Kernel Is About 80 Percent Of J

`@beep/skill-contract` is already the specific architectural home for this concept. It defines a closed `allowed | denied` outcome, an audit record with evaluator, gate id, timestamp, reason, and consumer-owned detail, and a tagged `GateVerdict`; adding another symbol with that name would collide with the live API. (`packages/foundation/modeling/skill-contract/src/Gate.ts:384-542`) It also defines named SHA-256 evidence subjects and in-toto-shaped receipts. (`packages/foundation/modeling/skill-contract/src/EvidenceReceipt.ts:20-111`) Its top-level gate summary carries a digest-bound contract subject, per-gate results, input attestations, policy, verifier, time, and `PASSED | FAILED`. (`packages/foundation/modeling/skill-contract/src/EvidenceReceipt.ts:192-218`; `packages/foundation/modeling/skill-contract/src/EvidenceReceipt.ts:248-337`)

The missing 20 percent is exactly J's honesty rule. `GateResultSummary` has `applicable: boolean` but no reason, assumption, rules-fired list, or reach object, and the blocking policy treats every `applicable: false` result as passing. (`packages/foundation/modeling/skill-contract/src/EvidenceReceipt.ts:248-301`) The existing binary `GateVerificationResult` has no abstain case. (`packages/foundation/modeling/skill-contract/src/EvidenceReceipt.ts:192-218`) The pull-forward should therefore add a certificate layer and migrate summary policy, not create a parallel packet schema.

No production gate vocabulary in this census implements the literal `abstain`. The nearest implemented states are kernel `applicable: false`, Yeet `unproven` and `skip`, AI-metrics `skipped`, agent-effectiveness `unavailable`, and SHACL `truncated`; each preserves one part of abstention but none enforces J's aggregate `conforms: null` rule. ## Architecture and smallest legal slice

### Placement

Put the reusable certificate schemas in `packages/foundation/modeling/skill-contract`, exported as `@beep/skill-contract`. The architecture routes domain-agnostic reusable substrate to `foundation`, repo execution to `tooling`, and tells the CLI to keep reusable helper models in an owning package instead of a command-private role. (`standards/ARCHITECTURE.md:47-60`; `standards/ARCHITECTURE.md:167-182`; `standards/architecture/07-non-slice-families.md:238-257`; `standards/architecture/07-non-slice-families.md:327-358`) The existing package already declares `family: foundation`, `kind: modeling`, describes itself as the typed agent-work contract kernel, and is consumed by repo-cli QA. (`packages/foundation/modeling/skill-contract/package.json:2-17`; `packages/foundation/modeling/skill-contract/README.md:1-18`)

Do **not** put the whole model in `@beep/schema`. That package is the canonical home for generic schema codecs/combinators and schema-adjacent helpers, while a gate certificate carries the durable semantics of evaluation, evidence, policy, and application. (`standards/architecture/07-non-slice-families.md:259-305`) Continue reusing low-level `Sha256Hex`, timestamps, URLs, and other generic value objects from `@beep/schema`; keep certificate identity, outcome, assumptions, rationale, and reach in `@beep/skill-contract`, beside `EvidenceSubject`, `GateDeclaration`, and `GateSummary`. (`packages/foundation/modeling/skill-contract/src/EvidenceReceipt.ts:20-111`; `packages/foundation/modeling/skill-contract/src/Gate.ts:238-382`)

Do **not** colocate the common shape under `commands/Qa`, `commands/Goals`, or `commands/Yeet`. Those are command adapters/private roles, and three live command families already need the semantics. (`standards/architecture/07-non-slice-families.md:327-358`; `packages/tooling/tool/cli/src/commands/Qa/JudgeContract.ts:35-71`; `packages/tooling/tool/cli/src/commands/Knowledge/Knowledge.schemas.ts:207-268`; `packages/tooling/tool/cli/src/commands/Yeet/internal/Verdict.ts:35-61`) Consumer-specific gate declarations, reach discovery, CLI rendering, and exit-code mapping remain colocated in their command families.

The accepted architecture “proof manifest” is not competing prior art: it is a static ordered descriptor list used to build operation plans, not a runtime proof, input digest, or verdict. (`packages/tooling/tool/cli/src/commands/Architecture/internal/AcceptedProofManifest.ts:38-48`; `packages/tooling/tool/cli/src/commands/Architecture/internal/AcceptedProofManifest.ts:115-160`) The runtime architecture check remains the `OperationPlanCheckResult` row in the census.

### Schema Reshape

Do not add the queued symbol `GateVerdict` verbatim because it already exists as the evaluator-level audited `allowed | denied` union. (`packages/foundation/modeling/skill-contract/src/Gate.ts:477-542`; `explorations/packet-system-redesign/MAP.md:136-151`) Preserve that leaf type and introduce a certificate-level name such as `GateCertificateOutcome`, or version/rename the existing binary `GateVerificationResult`; its closed values are `pass | reject | abstain`. The repository law requires finite result cases to be discriminated unions rather than a bag of optional/nullish fields. (`standards/ARCHITECTURE.md:114-131`)

The smallest coherent common model is:

1. `GateAssumption`: tagged `skipped | degraded`, with stable `checkId`, non-empty reason, and consequence; this generalizes Knowledge's probe policy, refs skip reason, and Fallow's failure statuses. (`packages/tooling/tool/cli/src/commands/Knowledge/Knowledge.schemas.ts:207-268`; `packages/tooling/tool/cli/src/commands/Knowledge/Knowledge.refs.ts:352-377`; `packages/tooling/tool/cli/src/commands/Quality/internal/FallowEnvelope.schema.ts:99-127`)
2. `GateReach`: a tagged `complete | partial` model with digest-bound `examined` subjects and named `unexamined` subjects/reasons. Encode the Amendment-J wire projection as `conforms: true | false | null` only at the boundary; keep the internal finite cases tagged. (`standards/ARCHITECTURE.md:126-131`; `explorations/packet-system-redesign/MAP.md:136-145`)
3. `GateCertificate`: stable certificate id, subject/input `EvidenceSubject[]`, certificate outcome, assumptions, reach, ordered fired-rule rationales, evaluator/policy identity, and creation time. Reuse the existing digest and audit shapes rather than copy them. (`packages/foundation/modeling/skill-contract/src/EvidenceReceipt.ts:20-111`; `packages/foundation/modeling/skill-contract/src/Gate.ts:412-475`)
4. Coherence filters: `pass` requires complete reach and zero skipped/degraded assumptions; partial reach with no rejecting rule is `abstain`; a rejecting fired rule is `reject`; an applicable passing result still requires a non-empty digest-bound subject. The current kernel already has the last invariant but currently treats every non-applicable blocking result as passing. (`packages/foundation/modeling/skill-contract/src/EvidenceReceipt.ts:248-301`)
5. A strict id registry/resolver that rejects an unknown certificate id. This preserves J's application invariant now without prematurely opening either packet application workflow. (`explorations/packet-system-redesign/research/2026-08-25-ontology-tooling-recon.md:86-90`; `explorations/packet-system-redesign/MAP.md:143-150`)

## Recommendation

Ratify a reshaped pull-forward with two boundaries:

- **Now:** extend `@beep/skill-contract` with a certificate-level three-way outcome, structured assumptions, digest-bound reach, rationale, coherence filters, and strict id lookup; prove it through the QA judge's manifested evidence reach. (`packages/foundation/modeling/skill-contract/src/Gate.ts:384-542`; `packages/tooling/tool/cli/src/commands/Qa/JudgeContract.ts:798-829`)
- **Still queued:** keep packet design approval, work-plan application, and evidence-closure lifecycle integration in candidates 2 and 4. Those packets own when a packet consumes a certificate, not the reusable shape or its first live proof. (`explorations/packet-system-redesign/MAP.md:169-176`)

After the QA slice, migrate by demonstrated dishonesty rather than by command popularity: hosted dependency review, Knowledge semantic delta, Knowledge refs, Yeet closeout, reflection lint, then the generic lint/CI envelopes. (`.github/workflows/check.yml:761-825`; `packages/tooling/tool/cli/src/commands/Knowledge/Knowledge.command.ts:161-207`; `packages/tooling/tool/cli/src/commands/Knowledge/Knowledge.command.ts:300-342`; `packages/tooling/tool/cli/src/commands/Yeet/internal/Handler.ts:917-960`; `packages/tooling/tool/cli/src/commands/Lint/ReflectionArtifact.ts:272-373`) Docgen and Fallow should be adapters, not rewrites: their proof manifest and envelope already supply most consumer-specific evidence. (`packages/tooling/tool/docgen/src/ProofManifest.ts:254-320`; `packages/tooling/tool/cli/src/commands/Quality/internal/FallowEnvelope.schema.ts:271-417`)

The acceptance rule should be monotonic: a consumer may map `reject` and `abstain` to the same non-zero process exit for compatibility, but it must never map `abstain`, unknown id, a non-empty assumption set, or partial reach to pass.
