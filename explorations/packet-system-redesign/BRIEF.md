# Brief — Exploration & Goal Packet System Redesign

Status: DRAFT FOR OPERATOR REVIEW 2026-08-13.

## Problem

The packet system validates document shape and hand-written lifecycle labels
more strongly than it validates legal transitions, design completeness,
approval freshness, or evidence binding. Stored stage/status fields drift,
parallel work can overwrite journal history, and an implementation can look
done before receipts are sealed against the landed commit. Meanwhile the
operator must open many READMEs to answer the simple pulse question: what can
start now, what is blocked, and what awaits me?

The redesign must make packet truth derivable, reviewable, and cheap enough to
use. It cannot turn exploration into big-design-up-front ceremony or create a
second tracker.

## Appetite

One bounded machinery cycle, self-hosted in advisory mode on this packet's
graduated goals. Land the control-plane core, migration/projections, design
gate, and receipts/flow metrics. Consume knowledge-surface-automation
Workstream D's static pulse-first HTML v1 as an upstream dependency and pilot
input. Ratchet checks from advisory to blocking only after the pilot
demonstrates affordable gates. This packet's only dashboard candidate
deliverable is the separately gated React v2.

## Solution Sketch

1. **Per-event CAS store.** Record immutable
   `ops/events/<seq>-<type>-<digest>.json` events with parent digest and
   expected revision. Parallel children make a visible fork. Cached
   projections bind `sourceTip` and projector version.
2. **Digest-bound approval.** A protected docs-PR merge approves exact DESIGN
   and change-tree digests. The packet stores PR URL, commit SHA, and subject
   digests; doctor re-derives staleness.
3. **Derived lifecycle.** Fold events into `furthestStage` and `resumeStage`;
   retire the ambiguous hand-edited stage. Keep packet paths permanent. State
   is rendered through generated projections, never folders.
4. **Risk-tier floor.** Doctor computes Light/Standard/Full from the declared
   change tree, public/export/persisted contracts, migrations, security/infra,
   and package count. Agents may raise tier; only the operator records a
   challengeable below-floor override.
5. **Graduation design gate.** Add exact change tree plus architecturally
   significant-symbol ledger as the fifth readiness check in MAP. Seed
   DESIGN.md at graduation for Standard/Full goals; Light skips it. Amendments
   update the living design and record events.
6. **One packet core.** Put transition tables, CAS fold, derivations, trace
   projection, and proof-manifest memoization behind existing `beep goals`
   plus a minimal read-only `beep explore --check`/doctor. `set-status`
   evolves into the guarded writer; no new `beep packets` vocabulary.
7. **Generated navigation.** Generate ATLAS wholesale and README status blocks
   first; keep Trail and Next Open Question authored. Add a generated by-state
   tree view rather than moving directories.
8. **Friction and proof.** Schema-validate systemic OPPORTUNITIES receipts,
   roll them up fleet-wide, and auto-draft one for contract-level design
   amendments. Separate deterministic `landed` from receipt-sealed `closed`.
   Observe approval wait, parked age, gate wall/cache rate, and amendment rate
   by tier.
9. **Upstream v1 pilot and React v2 candidate.** Consume
   knowledge-surface-automation Workstream D's self-contained, read-only,
   pulse-first HTML v1 as the pilot input: runnable frontier/parallel groups,
   blocked-by explanations, landed-not-closed work, and operator queue first;
   kanban, DAG, roadmap, and markdown drill-in second. This packet may deliver
   only the downstream React v2 candidate if daily v1 use proves an interaction
   gap. Both renderers consume the same projector, and Git packets remain the
   sole system of record.

## Rabbit Holes

- Event schema evolution needs versioned events, upcasters, fork repair, and
  golden-stream replay without event-sourcing prose.
- Human approval can become rubber-stamping; keep gates few, batched,
  digest-bound, and measured.
- Tier heuristics can produce ceremony theater or permission laundering;
  overrides and amendment-rate calibration must stay visible.
- Generated surfaces must not swallow authored Trail/open-question prose.
- Exact-symbol planning is limited to architecturally significant symbols;
  every-symbol inventories are forbidden.
- Gate computation must memoize by inputs/tool version so code-only work does
  not repeatedly pay packet checks.
- React/realtime can become product-building before the static viewer proves
  an interaction gap.

## No-Gos

- No stored readiness/status as canonical truth.
- No whole-packet/prose event sourcing and no merge-driver-dependent JSONL.
- No unverified Sigstore/in-toto artifacts.
- No `beep packets` command fork or premature new package.
- No React-first dashboard, write endpoints, drag-and-drop, or client-side
  frontier derivation.
- No hosted tracker as system of record or second writer.
- No state-named packet folders.
- No hard WIP cap or outcome optimization from the first observational sample.
