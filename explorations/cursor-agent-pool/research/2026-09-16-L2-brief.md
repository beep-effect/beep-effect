## 1. AGENTS.md vs `.cursor/rules`

- Cursor reads `AGENTS.md` natively as plain Markdown (no frontmatter); nested `project/frontend/AGENTS.md` applies to that subtree and descendants; parent + nested combine, more specific wins. **CONFIRMED** — https://cursor.com/docs/rules
- Project rules live in `.cursor/rules/` and **must** use `.mdc`; plain `.md` there is ignored. **CONFIRMED** — https://cursor.com/docs/rules
- `.mdc` frontmatter (only three documented): `description`, `globs`, `alwaysApply` — controls always-on vs glob-auto vs agent-selected vs manual-only. **CONFIRMED** — https://cursor.com/docs/rules
- Documented precedence among Cursor-native categories: **Team Rules → Project Rules → User Rules** (earlier wins on conflict). **CONFIRMED** — https://cursor.com/docs/rules, https://cursor.com/help/customization/rules
- **GAP:** rules page does **not** state where `AGENTS.md` sits relative to `.cursor/rules/*.mdc`. **INFERENCE** — treat as two injection channels; do not assume one always overrides the other. **INFERENCE** — https://cursor.com/docs/rules
- CLI reads root `AGENTS.md`, `CLAUDE.md`, and `.cursor/rules`. **CONFIRMED** — https://cursor.com/docs/cli/using
- Help center: project-root `AGENTS.md` auto-recognized; `CLAUDE.md` instructions apply to every conversation regardless of `alwaysApply`; legacy `.cursorrules` deprecated. **CONFIRMED** — https://cursor.com/help/customization/rules
- **GAP:** de-dupe when `CLAUDE.md` → `AGENTS.md` symlink pair may inject twice is undocumented. **INFERENCE** — https://cursor.com/docs/cli/using, https://cursor.com/help/customization/rules
- User rules: Settings → Customize → Rules or `~/.cursor/rules` (machine-local, no sync). Apply to Agent chat, **not** Inline Edit or Tab. **CONFIRMED** — https://cursor.com/help/customization/rules
- Cloud overview mentions `.cursor/hooks.json` + `environment.json` + team MCP; does **not** mention AGENTS.md/rules/skills on that page. **INFERENCE:** committed root `AGENTS.md` / `.cursor/rules` should be on disk via clone. **INFERENCE** — https://cursor.com/docs/cloud-agent

## 2. Hooks

### Headless `-p` and `stop`

- **Locally proven (do not re-derive):** under `cursor-agent -p`, these fire: `sessionStart`, `preToolUse`, `postToolUse`, `postToolUseFailure`, `beforeShellExecution`, `afterShellExecution`, `afterFileEdit`, `sessionEnd`. **SINGLE-SOURCE** — L2b local proof (report scope)
- **Locally proven:** `stop` and `beforeSubmitPrompt` did **not** fire under `-p`. **SINGLE-SOURCE** — L2b local proof (report scope)
- Official hooks page does **not** document CLI `-p` behaviour. **INFERENCE:** `stop` is interactive agent-loop; print-mode ends via `sessionEnd` without `stop` follow-up channel; `beforeSubmitPrompt` is user-submit-gated. **INFERENCE** — https://cursor.com/docs/hooks
- `stop` vs `sessionEnd`: `stop` can auto-submit follow-up (`followup_message`, `loop_limit`); `sessionEnd` cannot continue loop. **CONFIRMED** — https://cursor.com/docs/hooks
- Cloud Agents **do** list `stop` and `beforeSubmitPrompt` as supported (unlike local `-p` gap). **CONFIRMED** — https://cursor.com/docs/hooks

### Output schema per event (blocking events noted)

| Event | Output | Blocking? |
|---|---|---|
| `sessionStart` | `{env, additional_context}` | No |
| `sessionEnd` | none | No |
| `preToolUse` | `{permission, user_message, agent_message, updated_input}` | Yes |
| `postToolUse` | `{updated_mcp_tool_output, additional_context}` | No |
| `postToolUseFailure` | `{additional_context}` | No |
| `subagentStart` | `{permission, user_message}` | Yes |
| `subagentStop` | `{followup_message}` | loop_limit |
| `beforeShellExecution` | `{permission, user_message, agent_message}` | Yes |
| `afterShellExecution` | none | No |
| `beforeMCPExecution` | `{permission, user_message, agent_message}` | Yes |
| `afterMCPExecution` | none | No |
| `beforeReadFile` | `{permission, user_message}` | Yes |
| `afterFileEdit` | none | No |
| `beforeSubmitPrompt` | `{continue: bool, user_message}` | Yes (`continue`) |
| `preCompact` | `{user_message}` | Cannot block |
| `stop` | `{followup_message}` | loop_limit follow-up |
| `afterAgentResponse` / `afterAgentThought` | none | No |
| `beforeTabFileRead` / `afterTabFileEdit` | Tab-only | Tab |
| `workspaceOpen` | `{pluginPaths[]}` | N/A |

**CONFIRMED** — https://cursor.com/docs/hooks

- Exit `0` = parse stdout JSON; `2` = deny; other failures fail-open unless `failClosed: true`. Permission hooks with malformed JSON block even if fail-open. **CONFIRMED** — https://cursor.com/docs/hooks
- Priority: Enterprise → Team → Project → User; permission decisions: `deny` > `ask` > `allow`. **`ask` on `preToolUse` not enforced; `ask` on `subagentStart` treated as deny.** **CONFIRMED** — https://cursor.com/docs/hooks

### Cloud Agent hook limits

- Loads **command** hooks from repo `.cursor/hooks.json` + Enterprise/team; user `~/.cursor/` hooks unavailable; **prompt-type hooks do not run**. **CONFIRMED** — https://cursor.com/docs/hooks
- **Supported:** `beforeShellExecution`, `afterShellExecution`, `beforeReadFile`, `afterFileEdit`, `preToolUse`, `postToolUse`, `postToolUseFailure`, `subagentStart`, `subagentStop`, `beforeSubmitPrompt`, `preCompact`, `afterAgentResponse`, `afterAgentThought`, `stop`. **CONFIRMED** — https://cursor.com/docs/hooks
- **Unavailable:** `sessionStart`, `sessionEnd`, `beforeMCPExecution`, `afterMCPExecution`, `beforeTabFileRead`, `afterTabFileEdit`, `workspaceOpen`. **CONFIRMED** — https://cursor.com/docs/hooks
- Self-hosted workers: `sessionStart`/`sessionEnd` run on worker claim begin/end. **CONFIRMED** — https://cursor.com/docs/hooks

### Third-party / Claude hooks loader

- **Enable:** Settings → Rules, Skills, Subagents → **Include third-party Plugins, Skills, and other configs** (account feature-flagged). **CONFIRMED** — https://cursor.com/docs/reference/third-party-hooks
- Claude hooks loaded from merge stack (lowest priority last): Enterprise → Team → `.cursor/hooks.json` → `~/.cursor/hooks.json` → `.claude/settings.local.json` → `.claude/settings.json` → `~/.claude/settings.json`; all matching hooks run; higher priority wins on conflict. **CONFIRMED** — https://cursor.com/docs/reference/third-party-hooks
- **Mapped (Yes):** `PreToolUse`→`preToolUse`, `PostToolUse`→`postToolUse`, `UserPromptSubmit`→`beforeSubmitPrompt`, `Stop`→`stop`, `SubagentStop`→`subagentStop`, `SessionStart`→`sessionStart`, `SessionEnd`→`sessionEnd`, `PreCompact`→`preCompact`. **CONFIRMED** — https://cursor.com/docs/reference/third-party-hooks
- **Not mapped (official GAP):** `Notification`, `PermissionRequest`. **CONFIRMED** — https://cursor.com/docs/reference/third-party-hooks
- **Not in mapping table (not imported from Claude settings):** `PermissionDenied`, `PostToolUseFailure` (native Cursor has `postToolUseFailure` in `.cursor/hooks.json`). **CONFIRMED** — https://cursor.com/docs/reference/third-party-hooks
- Claude nested `hookSpecificOutput.permissionDecision` and Cursor flat `{permission, updated_input}` both work; Stop/SubagentStop: Claude `{decision:"block", reason}` ≡ `{followup_message}`. **CONFIRMED** — https://cursor.com/docs/reference/third-party-hooks
- Cloud VMs have no `~/.claude`; only repo `.cursor/hooks.json` (+ enterprise/team) load for Cloud. **CONFIRMED** — https://cursor.com/docs/reference/third-party-hooks, https://cursor.com/docs/hooks

- Claude/Codex-compatible auto-discovered: `.claude/skills/`, `.codex/skills/`, `~/.claude/skills/`, `~/.codex/skills/`. **CONFIRMED** — https://cursor.com/docs/skills

- Required frontmatter: `name` (must match folder), `description`; optional `paths`, `disable-model-invocation`, `icon`, `color`, `metadata`. **CONFIRMED** — https://cursor.com/docs/skills

- CLI/headless skill discovery **not specified** on skills page. **INFERENCE:** `-p` in trusted workspace should see repo skill dirs (workspace-relative discovery). **INFERENCE** — https://cursor.com/docs/skills

## 4. Subagents

- Supported in editor, CLI, and Cloud Agents. **CONFIRMED** — https://cursor.com/docs/subagents
- Discovery: project `.cursor/agents/*.md`, `.claude/agents/*.md`, `.codex/agents/*.md`; user `~/.cursor/agents/*.md`, etc.; precedence project > user; on name conflict `.cursor/` > `.claude/` > `.codex/`. **CONFIRMED** — https://cursor.com/docs/subagents
- **GAP:** Codex `.codex/agents/*.toml` **not** loaded; only `.codex/agents/*.md`. **CONFIRMED** — https://cursor.com/docs/subagents
- Documented frontmatter: `name`, `description`, `model` (default `inherit`, can pin e.g. `gpt-5.6-sol`), `readonly` (default `false`), `is_background` (default `false`). **CONFIRMED** — https://cursor.com/docs/subagents
- **GAP:** no documented `tools:` frontmatter (Claude agents often have it). **CONFIRMED** — https://cursor.com/docs/subagents
- Delegation via `description` ("use proactively" / "always use for"); Task tool spawns subagents; `subagentStart` hook can block. **CONFIRMED** — https://cursor.com/docs/subagents, https://cursor.com/docs/hooks
- `exploreSubagentModel` **not** on subagents page; is key in `~/.cursor/cli-config.json` per research brief. **INFERENCE:** CLI-config override for built-in Explore, independent of custom `.md` `model:` pins. **INFERENCE** — https://cursor.com/docs/subagents
- Headless: page says CLI support, no distinct `-p` caveats. **INFERENCE:** custom agents in `.cursor/agents` available to `cursor-agent -p` in trusted workspace. **INFERENCE** — https://cursor.com/docs/subagents

## 5. MCP

- Project `.cursor/mcp.json` and user `~/.cursor/mcp.json` merged; same server name → **project wins**. **CONFIRMED** — https://cursor.com/docs/mcp, https://cursor.com/help/customization/mcp
- **GAP:** Claude repo-root `.mcp.json` **not documented** as imported or auto-discovered. **CONFIRMED** — https://cursor.com/docs/mcp
- Env interpolation (in `command`/`args`/`env`/`url`/`headers`): `${env:NAME}`, `${userHome}`, `${workspaceFolder}`, `${workspaceFolderBasename}`, `${pathSeparator}` / `${/}`. **CONFIRMED** — https://cursor.com/docs/mcp
- `--approve-mcps`: official CLI flag — "Automatically approve all MCP servers"; pair with `--trust --force` for headless. **CONFIRMED** — https://cursor.com/docs/cli/reference/parameters
- Cloud Agents: team MCP from Dashboard; local `~/.cursor/mcp.json` does not follow agent to cloud VM. **CONFIRMED** — https://cursor.com/help/customization/mcp, https://cursor.com/docs/mcp

## 6. Plugins

- **Agent Plugin:** root `plugin.json` with `$schema: https://agent-plugins.org/schemas/1.0.0/plugin.schema.json` — skills + MCP only. **CONFIRMED** — https://cursor.com/docs/plugins
- **Cursor Plugin:** `.cursor-plugin/plugin.json` (`name` required) — rules, skills, agents, commands, hooks, MCP, variables. **CONFIRMED** — https://cursor.com/docs/plugins
- `${CURSOR_PLUGIN_ROOT}` is plugin root; `${PLUGIN_ROOT}` / `${PLUGIN_DATA}` **not** expanded in Agent Plugin `mcp.json`. **CONFIRMED** — https://cursor.com/docs/plugins
- **Claude plugin layout (`.claude-plugin/`, `enabledPlugins`) NOT claimed compatible** with Cursor; need root `plugin.json` or `.cursor-plugin/plugin.json`. **CONFIRMED** — https://cursor.com/docs/plugins
- `--plugin-dir` in `cursor-agent --help` (research brief) but **not documented** on plugins page. **SINGLE-SOURCE** — research brief (report); https://cursor.com/docs/plugins

## 7. Telemetry / OTel / Usage Export

- Enterprise OTel export only; Admin: Team Settings → OpenTelemetry Export; IDE + CLI + Cloud Agent lifecycle; headless not named separately. **INFERENCE:** CLI includes `cursor-agent -p`. **CONFIRMED** / **INFERENCE** — https://cursor.com/docs/enterprise/opentelemetry-export
- Transport: public HTTPS OTLP/HTTP binary protobuf; POST `/v1/metrics` and `/v1/logs`; no traces; prompt content not exported; no backfill. **CONFIRMED** — https://cursor.com/docs/enterprise/opentelemetry-export
- Families: `model_usage` (`cursor.token.usage`, `cursor.cost.usage`), `tool_calls`, `skills_hooks_plugins` (`cursor.skill.activated`, `cursor.hook.execution_complete`, `cursor.plugin.installed`), `cloud_agents`, `grok_bot_agent_actions`. **CONFIRMED** — https://cursor.com/docs/enterprise/opentelemetry-export
- Subagents have separate conversation IDs; parent rollups not exported; tool-call/cost metrics cannot be attributed to individual conversations. **CONFIRMED** — https://cursor.com/docs/enterprise/opentelemetry-export
- **GAP:** no first-party hook-to-OTel bridge for repo `hook-pulse.sh` / Grafana path; OTel is enterprise cloud-side, not local OTLP. **CONFIRMED** — https://cursor.com/docs/enterprise/opentelemetry-export
- OSS path: same hook scripts on Cursor events (`sessionStart`/`preToolUse`/… fire in `-p`) plus optional Enterprise OTel. **CONFIRMED** — https://cursor.com/docs/enterprise/opentelemetry-export, L2b local proof
- Analytics API index (not fetched this lane): teams analytics-api, admin-api, org usage-events URLs listed in report. **SINGLE-SOURCE** — https://cursor.com/docs/account/teams/analytics-api.md (index only per report)
