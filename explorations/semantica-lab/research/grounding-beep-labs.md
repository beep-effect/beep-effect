## 2. Lab lifecycle

The binding doctrine is `standards/architecture/15-lab-apps.md`; the normative design record is the completed-retained packet `goals/lab-apps-lifecycle/SPEC.md` (locked D1-D14), with implementation history in `PLAN.md`, terse local instructions in `apps/labs/README.md`, and promotion commands in `docs/runbooks/lab-promotion.md`. A lab is a real private workspace app at `apps/labs/<slug>`: production-shaped and durable while useful, but path-classified so it stays cheap to remove. Scratchpad remains the law-relaxed throwaway lane; a lab is the next, production-honest step. (`standards/architecture/15-lab-apps.md:3-33`)

1. **Create:** use `bun run beep create-package <name> --type app --app-kind <nextjs|vite|service|tauri> --lab --description "..."`; never `mkdir`. Creation emits a private app, package-local `@/*` imports, tests/check/lint/build scripts, a portless host, a real identity composer in the generated labs segment, and schema-decoded `lab.manifest.json`. The manifest starts with `schemaVersion`, non-empty `purpose`, `created`, and disposition `active`; it may later declare `postgresSchema: "lab_<slug>"`. Inspect all manifests with `bun run beep labs list`. (`apps/labs/README.md`; `packages/tooling/tool/cli/src/internal/cli/Labs/LabManifest.ts:27-107`)
2. **Operate under full code law:** schema-first and Effect-first modeling, package/test typechecking, Biome, Effect-LSP/native-runtime rules, import/cycle/dead-code/identity checks, secret/SAST/dependency security, and portless naming all apply. Labs are exempt only from ceremony: no docgen/public API, JSDoc or coverage ratchet, changeset requirement, or Storybook registration. A changed lab must pass its non-required Labs lane on its own PR. (`standards/architecture/15-lab-apps.md:12-33`; `goals/lab-apps-lifecycle/SPEC.md:248-265`)
3. **Keep the proof app-local:** product/durable workspaces may never import a lab. A lab may not publish a reusable `@beep/*` export, root `src/index.ts`, package export map, or docgen surface; it may not add tables/migrations under `packages/*/tables`. Reusable code first earns a lawful durable owner. (`standards/architecture/15-lab-apps.md:50-59,128-147`)
4. **Disposition:** `active` is still proving; `promote` means a result earned a durable home; `expired` means delete it. These are operator inventory, not TTLs or CI nags. (`standards/architecture/15-lab-apps.md:61-74`)
5. **Promote (reviewed move, not rename):** set disposition to `promote`, confirm `beep labs list`, then choose the smallest owner: durable `apps/*`; owning slice for product behavior/language; high-bar `shared/*` for deliberately cross-slice product language; `drivers/*` for external SDK/engine boundaries; `foundation/*` for domain-agnostic substrate; `tooling/*`; or gated `ecosystem/*`. Create/extend that home through `beep create-package` / `beep architecture`, onboard its full ceremony (exports/docgen/JSDoc/coverage/changeset/Storybook as applicable), move code, rewrite `@/*` to lawful `@beep/*` subpaths, and migrate consumers in the same change. Preserve identity when semantic ownership remains; otherwise record a retired-name transition. (`docs/runbooks/lab-promotion.md:9-56`)
6. **Remove:** review `bun run beep delete-package <lab> --dry-run`, execute it, then require `bun run beep delete-package <lab> --check` to report zero residue. Delete refuses live dependents even with `--force`, reconstructs writer-owned config, prunes generated identity/lockfile state, and removes ignored artifacts. It never silently drops data: manifest-owned Postgres cleanup requires explicit `--drop-data`, unique `lab_<slug>` ownership proof, and a second override for non-local connections; otherwise it reports a manual cleanup. (`docs/runbooks/lab-promotion.md:58-71`; `standards/architecture/15-lab-apps.md:108-126`)
7. **Retirement:** labs are pre-v1: consumer migration and removal occur in one PR, without a sunset period. Add an architecture DECISIONS entry only if the lab promoted a shared export or deletion changes a repository-wide promise; do not rewrite historical research/evidence to erase the old name. Finish promotion through the normal Yeet repair/verify/publish/monitor gates. (`standards/architecture/15-lab-apps.md:115-120`; `docs/runbooks/lab-promotion.md:73-81`)

## 3. Scaffolding and governance

`create-package` is app-aware. `AppKind` is `nextjs | vite | service | tauri | runtime-proof`; `--lab` accepts the first four and refuses `runtime-proof`, non-app types, a caller-supplied `--parent-dir`, or an empty description. `--lab` derives `apps/labs`; conversely `--parent-dir apps/labs` without `--lab` is refused. All creates reject invalid/occupied names and retired names unless `--reuse-retired-name`; lab creates also refuse if the one-time `apps/labs/*` workspace glob is absent. (`packages/tooling/tool/cli/src/commands/CreatePackage/CreatePackage.command.ts:135-141,963-1044,1118-1176,1361-1426`)

- **Templates:** Next emits app-router layout/page/CSS/config/test; Vite emits `index.html`, React entry/App/CSS/config/test; service emits `Api.ts`, app-local runtime `Layer.ts`, `main.ts`, and an Effect test (the server uses `effect/unstable/httpapi`, not `node:http`); Tauri emits the Vite shell plus `src-tauri/{Cargo.toml,build.rs,tauri.conf.json,capabilities/default.json,src/{main,lib}.rs,icons/icon.png}`. All real apps also get README, AGENTS, LICENSE, and `CLAUDE.md -> AGENTS.md`. (`packages/tooling/tool/cli/src/commands/CreatePackage/CreatePackage.command.ts:376-468,518-633`)
- **Tauri scaffold scope:** the stock Rust side is intentionally minimal—one `app_health` command and `tauri::Builder`; it does **not** emit Professional Desktop's Bun sidecar, Effect runtime, database, migrations, or IPC bridge. The icon is load-bearing for `tauri::generate_context!()` and is copied byte-for-byte. Portless `devUrl`/`devCsp` use the lab label. (`packages/tooling/tool/cli/src/commands/CreatePackage/templates/app-tauri-src-tauri-src-lib.rs.hbs`, `packages/tooling/tool/cli/src/commands/CreatePackage/templates/app-tauri-src-tauri-tauri.conf.json.hbs`, `packages/tooling/tool/cli/src/commands/CreatePackage/CreatePackage.command.ts:398-424`)
- **Manifests/scripts:** real apps are private and deliberately have no `exports`, public `src/index.ts`, or docgen config. Every kind gets `beep:{build,check,lint,test,audit}` plus portless `dev`; Tauri adds `dev:tauri`. Labs omit `coverage`; non-lab package scaffolds instead get export maps, docgen/docs, test/integration tsconfigs, coverage, and optional UI-system story tsconfigs. (`packages/tooling/tool/cli/src/commands/CreatePackage/CreatePackage.command.ts:1745-1937,1943-2067`)
- **Registration transaction:** after generating and advisory-Biome-formatting files, the command ensures workspace membership, updates normal identity registration or reconstructs the generated labs identity segment, runs root `syncTsconfigAtRoot` (references/aliases/syncpack/docgen-owned derived state), clears an intentionally reused retired name, and runs `bun install --lockfile-only` unless `--skip-lockfile`. `--dry-run` previews this. It does not run the scaffold's check/lint/test/build gates for the operator. (`packages/tooling/tool/cli/src/commands/CreatePackage/CreatePackage.command.ts:1403-1476,1515-1659`)
- **No per-lab Turbo/config rows:** root Turbo discovers workspace scripts; the permanent non-required Labs lane selects `apps/labs/**` and runs the lab task bundle, while required check/lint/test/integration/coverage graphs apply `--filter=!./apps/labs/**`. Root Vitest and Syncpack already contain `apps/labs/*` globs. (`packages/tooling/tool/cli/src/commands/Ci/CiLane.ts:539-552`; `packages/tooling/tool/cli/src/commands/Quality/Tasks.ts:752-768`; `vitest.config.ts:10-17`; `syncpack.config.ts:3-25`)
- **Ceremony/gates:** the generator creates no changeset. Lab-only work is path-exempt from changeset status, docgen/JSDoc inventory, coverage, and Storybook; durable non-lab destinations need the applicable changeset and full ceremony. Labs remain visible to Biome, schema-first/Effect laws, test-typecheck, Knip, Fallow/import boundaries, identity, gitleaks, SAST, and security. (`goals/lab-apps-lifecycle/research/12-p0-gate-scoping-ratified.md:17-54`)
- **Architecture metadata:** `create-package --family ... --kind ...` records `package.json#beep` family/kind metadata for non-slice packages; lab apps instead have the lifecycle manifest. `create-package` is not the slice/concept/role topology generator and emits no separate architecture plan manifest. New slice packages and concept-qualified role files go through schema-versioned `bun run beep architecture` operations. (`AGENTS.md:58-70`; `packages/tooling/tool/cli/src/commands/Architecture/Architecture.command.ts`; `packages/tooling/tool/cli/src/commands/CreatePackage/CreatePackage.command.ts:290-298,1525-1557`)

## 4. Concrete vertical-slice anatomy

`standards/ARCHITECTURE.md` is the binding constitution: paths and roles must change if they contradict it. The canonical (optional-by-need) slice spine is `packages/<slice>/{domain,use-cases,config,server,client,tables,ui}` named `@beep/<slice>-<role>`; do not create empty packages for symmetry. Domain is the pure inward core; use-cases declare commands/queries/ports; server implements ports with tables/drivers; client owns browser adapters/state; UI owns React; config is typed runtime configuration; tables are persistence projections. (`standards/ARCHITECTURE.md:1-17,304-348,1131-1298`)

**Canonical executable reference — `packages/architecture-lab/*`:** all seven roles exist around `WorkItem`. `domain/src/aggregates/WorkItem/` owns `WorkItem.{model,values,errors}.ts`; `use-cases/.../WorkItem/` owns `{commands,repository,service,use-cases,errors}.ts` and `/public`/`/server` facades; `config/.../WorkItem/` owns `{config,layer}.ts` plus public/server/secrets/layer/test exports; `tables/.../WorkItem.table.ts` projects persistence; `server/.../WorkItem/` implements `{repo,http,rpc,tools,layer}.ts` and package `Layer.ts`; `client/.../WorkItem.client.ts` adapts the browser; `ui/.../WorkItem.view-model.ts` presents it. `apps/architecture-lab-proof` composes the proof. (`packages/architecture-lab/**`; `standards/ARCHITECTURE.md:14-17`)

**Production reference — `packages/ontology/*`:** a six-role slice (no table role because it has not earned one). `domain/src/aggregates/Session/Session.{model,values,errors}.ts`; `use-cases/.../Session/Session.{commands,ports,service,rpc,reasoner,sparql,validation,visualizer,worker-protocol}.ts` with explicit `public.ts`, `server.ts`, `worker.ts`; `config/src/{McpConfig,ServerConfig,TestLayer,layer,public,secrets,server,test}.ts`; `server/.../Session.{file-store,layer}.ts`, `Layer.ts`, and tool handlers; `client/.../Session.{atoms,visualizer.worker}.ts`; `ui/.../Session/Session.{workbench,graph,explorer,inspector,document,sparql,...}.tsx`. (`packages/ontology/**`)

Binding details for a lab mirror: mirror concept folders and earned role suffixes app-locally, but keep imports behind `@/*` until promotion. Role grammar is `<package>/src/<domain-kind>/<Concept>/<Concept>.<role>.ts[x]`; canonical files are vocabulary, not an empty-file checklist. Domain cannot import config/drivers/adapters; use-cases cannot import server/client/UI/tables/drivers; client uses only `/public` and driver `/browser` subpaths; direct cross-slice imports are forbidden and cross-slice product language needs shared-kernel promotion. (`standards/ARCHITECTURE.md:255-302,827-1059`; `standards/architecture/13-onboarding-the-minimum-viable-slice.md:21-66`)

## 6. Precedent and Tauri reuse

- `apps/labs/trustgraph-workbench` is the only lawful lab precedent and the D13 first-wave external-system mirror. Its manifest is `active`, but its implementation remains the generated Vite heading/test shell. The broader design adopts effect-ontology-style typed authority and TrustGraph-style projection/retrieval—not a blind upstream clone. (`apps/labs/trustgraph-workbench/lab.manifest.json`; `apps/labs/trustgraph-workbench/src/App.tsx`; `docs/BEEPGRAPH_ARCHITECTURE.md:15-37,139-184`)
- The earlier `scratchpad/effect-ontology` experiment is a useful negative/transition precedent: a quarantined, production-quality Effect v4 reinterpretation of an external MIT Domain module, with frozen-source evidence and a per-symbol semantic port ledger, but explicitly non-importable and unauthorized for production promotion. Lifecycle research says not to keep growing it; a service lab is the lawful experimental home. (`scratchpad/effect-ontology/README.md`; `scratchpad/effect-ontology/PORTING_LEDGER.md`; `goals/lab-apps-lifecycle/research/03-apps-anatomy-variants.md:465`)
- Professional Desktop's **Rust Tauri shell does not itself host the Effect business runtime**. Tauri owns the native window/lifecycle, app-data paths, CSP/plugins, and bundled `externalBin`; Rust spawns/monitors the compiled Bun sidecar and bridges newline-delimited RPC over stdin/stdout to typed Tauri events/commands. The Effect `RuntimeLive` runs in `server/main.ts`, composes slice handler Layers plus Bun services/observability, and is bundled by `scripts/build-sidecar.ts`. (`apps/professional-desktop/src-tauri/tauri.conf.json`; `apps/professional-desktop/src-tauri/src/lib.rs`; `apps/professional-desktop/server/main.ts`; `apps/professional-desktop/scripts/build-sidecar.ts`; `apps/professional-desktop/src/runtime/Layer.ts:279-343`)
- Its local DB pattern is reusable: `@beep/pglite` provides one file-backed in-process database, `@beep/postgres` layers Drizzle over it, repositories share that Layer, and startup fails closed on incompatible existing data. Migration authoring remains in `packages/_internal/db-admin`; `scripts/sync-migration-bundle.ts` copies SQL byte-exactly into generated `Migrations.gen.ts`, the compiled sidecar embeds it, and `migrateOnBoot` applies it before writing the compatibility marker. (`apps/professional-desktop/src/runtime/Pglite.ts:274-388`; `apps/professional-desktop/src/runtime/Migrations.ts`; `apps/professional-desktop/src/runtime/Migrations.gen.ts`; `apps/professional-desktop/scripts/sync-migration-bundle.ts`)
- A new Tauri lab should start with the generator's repaired icon/portless shell, reuse lawful package capabilities (`@beep/pglite`, `@beep/postgres`, slice `/public`/`/server` contracts), and adapt the app-local sidecar/runtime/migration/IPC pattern only if the proof needs native-local effects. It must not import `apps/professional-desktop` or treat that app's internals as a public library. The Labs CI lane runs JS check/lint/test and **does not run Cargo**; add explicit local `cargo check --manifest-path apps/labs/semantica/src-tauri/Cargo.toml` proof for Rust changes. (`goals/lab-apps-lifecycle/PLAN.md:150-195`; `standards/ARCHITECTURE.md:62-67`)

## 7. `apps/labs/semantica` architect gotchas

1. Use `bun run beep create-package semantica --type app --app-kind tauri --lab --description "<specific proving purpose>"` (prefer `--dry-run` first). `semantica` is named in D13 as a first-wave source under `~/YeeBois/workstation-apps`, but no current workspace/identity/retired-name entry exists. (`goals/lab-apps-lifecycle/SPEC.md:248-265`; `goals/lab-apps-lifecycle/research/SOURCES.md:37`)
2. Do **not** edit root workspace/Turbo/Syncpack/Vitest/changeset/Storybook config. `package.json` already owns `apps/labs/*`; `syncpack.config.ts` and `vitest.config.ts` already own the depth-aware globs. `apps/labs/` itself must remain a package-less, source-less container. (`package.json:374-394`; `apps/labs/README.md`)
3. Do not add Semantica to `tsconfig.packages.json`: lab project references are intentionally excluded from the root TypeScript solution; package-local `beep:check` and the Labs lane own typechecking. Creation normally changes only the lab tree plus `bun.lock` and the fenced generated-labs identity segment outside it. (`standards/architecture/15-lab-apps.md:35-55`; `packages/tooling/tool/cli/src/commands/TsconfigSync/TsconfigSync.plan.ts:440`; `goals/lab-apps-lifecycle/PLAN.md:113-119`)
4. Non-required does not mean law-free. Required Turbo lanes exclude labs to prevent an experimental dependent from blocking unrelated upstream PRs, but a direct lab PR must make the Labs lane green, and repo-wide Biome/schema/Effect/import/Fallow/Knip/identity/security laws still inspect it. Only docgen/JSDoc/coverage/changeset/Storybook ceremony is excluded. (`goals/lab-apps-lifecycle/research/12-p0-gate-scoping-ratified.md:21-54`)
5. Keep `package.json` private and non-exporting; keep runtime modules on `@/*`; do not add `src/index.ts`, `exports`, `docgen.json`, `coverage`, changeset, lab Storybook glob, or package-table migrations. Promote earned product behavior to a slice, an external boundary to `drivers`, and generic substrate to `foundation` before any durable consumer imports it. (`standards/architecture/15-lab-apps.md:128-147`; `standards/ARCHITECTURE.md:45-67`)
6. The Tauri scaffold is a shell, not Desktop-in-a-box: plan separately for sidecar ownership, IPC vs loopback HTTP, Effect Layer composition, persistent data, migrations, native capabilities/CSP, shutdown, packaging, and compatibility recovery. If using Postgres, declare only `lab_semantica` in the lab manifest and require explicit cleanup consent; embedded PGlite/in-memory state is allowed without adding slice tables. (`packages/tooling/tool/cli/src/internal/cli/Labs/LabManifest.ts:50-98`; `goals/lab-apps-lifecycle/SPEC.md:151-167`)
7. Preserve `src-tauri/icons/icon.png`; generated Tauri crates need it at macro expansion. Run the JS gates plus explicit Cargo check because hosted Labs CI invokes no Rust. Use the repository dev shell/system dependencies for Linux Tauri rather than weakening the app or bypassing portless. (`goals/lab-apps-lifecycle/PLAN.md:150-190`; `packages/tooling/tool/cli/src/commands/CreatePackage/CreatePackage.command.ts:416-424`)
8. Graduation is extraction, not normalization of the lab into a reusable package: create the destination under full ceremony, move the earned code, migrate consumers, then delete the entire lab and require doctor-clean residue. There is no `beep labs promote` command. (`docs/runbooks/lab-promotion.md`; `goals/lab-apps-lifecycle/SPEC.md:38-56`)
