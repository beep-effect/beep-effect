**Reader notes:**

- No file in Service/ uses effect/unstable/ai EmbeddingModel: EmbeddingProvider.ts (188-235) is a hand-rolled Context.Service; unstable/ai is used only for LanguageModel/Prompt in Extraction, Grounder, GenerateWithFeedback, LlmWithRetry, CorrectorAgent, etc. The lab should build on effect/unstable/ai EmbeddingModel and add ModelIdentity on top.
- ProviderMetadata (EmbeddingProvider.ts:147-160) carries {providerId, modelId, dimension} only. Shared schema v1.1 ModelIdentity needs `revision` and `artifactHash` in addition; also consider carrying `taskType` because the experiment's cache key (Utils/Hash.ts:228-231) proves task type changes the vector.
- Server-Postgres coupling hazard: ClaimService.Default requires PostgresDrizzle (Service/Claim.ts:603); ClaimRepository deprecate/promote are drizzle `UPDATE` statements (Repository/Claim.ts:401-424); ClaimPersistenceService and makeClaimPersistenceActivity (DurableActivities.ts:1046-1069) write to PostgreSQL; CrossBatchEntityResolver is DrizzleError-typed and WorkflowOrchestrator.ts:740 says cross-batch resolution 'requires Postgres + pgvector'; EventBus.ts uses effect/unstable/sql SqlClient. None of this fits the PGlite/DuckDB lab envelope without a storage inversion.
- Append-only violation: claim lifecycle is create -> in-place deprecate (rank='deprecated', deprecatedAt, deprecatedBy) -> in-place promote (rank='preferred'). The lab's EvidenceBatch law needs these as Invalidated / ConflictResolved ProvenanceEvents referencing immutable claims; the CLAIMS-vocab quad projection in toReifiedTriples (Claim.ts:323-544) can stay as a derived view.
- Batch identity loss: StreamingExtraction folds per-chunk KnowledgeGraphs with Stream.runFold(mergeGraphs) (StreamingExtraction.ts:751-758) and Merge.ts picks attribute winners by lexical min (133-137), so per-chunk batches and conflicting values are collapsed before persistence. ClaimExtractionArtifact (ClaimFactory.ts:294-309) is the nearest EvidenceBatch but lacks batch id, model identity, and hash-chain link.
- Span fidelity hazard: evidenceForContext (StreamingExtraction.ts:132-137) invents a whole-chunk EvidenceSpan {0, context.length} when no mention span exists; ClaimData evidence offsets are document-relative NonNegativeInt with no CanonicalText ref. Neither meets the v1.1 CanonicalText/Chunk requirement of UTF-16 spans against a named canonicalization.
- Degradation hazard: EmbeddingProviderFallbackLive (EmbeddingFallback.ts:164-240) silently swaps voyage -> nomic (different model, 768-dim) and clusterEntities (EntityResolutionGraph.ts:121-141) silently drops failed embeddings to lexical-only; both should become tagged DegradedEmbedding states.
- Upstream API residue: GcsUri storage refs in every activity output (DurableActivities.ts:124-153, 1651-1672; StreamingExtractionActivity.ts:85-135), stripGsPrefix helpers, Voyage batch-size 128 constant (EmbeddingResolver.ts:385), and the closed providerId LiteralKit (nomic|voyage|openai) are Google-Cloud/Voyage-specific and should not leak into lab schemas.
- Things this code has that shared schema v1.1 does not name: (a) GroundingDecision tagged lifecycle (NotEvaluated|Supported|Rejected with confidence) as a per-observation verification state distinct from extraction confidence; (b) per-mention ResolutionEdge {confidence: UnitInterval, method} and VerifiedPair {sameEntity, confidence, originalSimilarity} -- the Deduplicated ProvenanceEvent should carry the resolution method and both scores; (c) MergeConflict {property, values, chunkIndexes} as attribute-level (not statement-level) conflict; (d) stage-level budgets (StageTimeoutConfig soft/hard Duration, TokenBudget per-stage allocations) as PipelineStep config; (e) Correction tagged-by-strategy union as a ConflictResolved payload; (f) temporal validity (validFrom/validTo) on claims, which v1.1 puts on Statement but not on EvidenceClaim.
- Agent/types.ts has a mis-annotated identifier: ExecutionContext is annotated $I.annote('AgentTask', ...) at lines 942-944; AgentTask itself is a plain interface of 19 Option fields (328-348), not a tagged step, so it should not be borrowed as a PipelineStep shape.
