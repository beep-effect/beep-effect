## BLOCKING

1. **RATIFIED-CONFLICT — The MAP admits an incomplete qualification.**
   The ratified disposition semantics require a disposition to reference a “completed qualification” ([DECISIONS.md:41](explorations/model-artifact-admission/DECISIONS.md:41)). The defined qualification envelope includes a frozen evaluation plan, corpus digests, per-case results, measures, risks, and expiry triggers ([BRIEF.md:34](explorations/model-artifact-admission/BRIEF.md:34); [02-admission-evidence-and-change-policy.md:34](explorations/model-artifact-admission/research/02-admission-evidence-and-change-policy.md:34)). The MAP instead admits a fixture after only identity evidence and deterministic invariants, while explicitly deferring the evaluation harness ([MAP.md:27](explorations/model-artifact-admission/MAP.md:27), [MAP.md:39](explorations/model-artifact-admission/MAP.md:39)). There is no fixture/provisional qualification status in the five-status model. This either violates the completed-qualification gate or quietly makes most of the promised evidence envelope optional.

2. **The “live pinned arrangement” fixture is not necessarily live or pinned.**
   The MAP equates the live arrangement with the Anthropic pinned-default config ([MAP.md:13](explorations/model-artifact-admission/MAP.md:13)). But the live layer reads `AI_ANTHROPIC_MODEL` and only falls back to the default ([Anthropic.service.ts:91](packages/drivers/anthropic/src/Anthropic.service.ts:91), [Anthropic.service.ts:113](packages/drivers/anthropic/src/Anthropic.service.ts:113)). The research explicitly says admission must bind the materialized runtime value, not the default constant ([01-hosted-identity-boundary.md:54](explorations/model-artifact-admission/research/01-hosted-identity-boundary.md:54)). Building the fixture from `ANTHROPIC_DEFAULT_MODEL` can therefore admit `claude-opus-4-6` while the executing process uses an override.

3. **“Every controlled component digest” has no closed or reproducible definition.**
   The artifacts specify neither:

   - component-kind vocabulary;
   - required versus optional components;
   - multiplicity and ordering;
   - canonical byte encoding;
   - digest algorithm and version;
   - whether the digest covers decoded values, source files, generated schemas, or runtime-materialized objects;
   - rules for representing an absent adapter, tokenizer, or modality encoder.

   “Canonical ordering” alone ([MAP.md:33](explorations/model-artifact-admission/MAP.md:33)) cannot establish a stable content address. The cited config exposes only `model` and `maxTokens` ([Anthropic.config.ts:250](packages/drivers/anthropic/src/Anthropic.config.ts:250)), while the actual arrangement also includes a system prompt, tool schema, tool choice, tool-resolution behavior, and stream fallback setting ([AnthropicTurnKernel.ts:46](packages/agents/server/src/AssistantTurn/AnthropicTurnKernel.ts:46), [AnthropicTurnKernel.ts:176](packages/agents/server/src/AssistantTurn/AnthropicTurnKernel.ts:176)). Failed output invokes a second model arrangement with `claude-haiku-4-5` and a separate token budget ([Anthropic.repair.ts:44](packages/drivers/anthropic/src/Anthropic.repair.ts:44), [Anthropic.repair.ts:143](packages/drivers/anthropic/src/Anthropic.repair.ts:143)). The first slice cannot truthfully claim “real component digests” without deciding whether that repair path is part of the arrangement.

4. **The two-axis query is impossible to specify from the proposed records.**
   The cited precedent works because every edge version stores `validFrom`, `validTo`, `recordedAt`, and `expiredAt` ([EdgeVersion.model.ts:112](packages/epistemic/domain/src/entities/EdgeVersion/EdgeVersion.model.ts:112), [EdgeVersion.model.ts:129](packages/epistemic/domain/src/entities/EdgeVersion/EdgeVersion.model.ts:129), [EdgeVersion.model.ts:170](packages/epistemic/domain/src/entities/EdgeVersion/EdgeVersion.model.ts:170)). Its query applies all four half-open bounds ([EdgeAuthority.repo.ts:132](packages/epistemic/server/src/EdgeAuthority/EdgeAuthority.repo.ts:132)). It also closes transaction time by updating the previous row’s `expiredAt` ([EdgeAuthority.repo.ts:357](packages/epistemic/server/src/EdgeAuthority/EdgeAuthority.repo.ts:357)), which conflicts with the MAP’s immutable-record mechanism if copied literally.

   The MAP names only `validAt`, `knownAt`, and a supersession link; it specifies no valid-time bounds, recording time, retroactive-decision policy, overlap prohibition, or tie-break rule ([MAP.md:33](explorations/model-artifact-admission/MAP.md:33)). Separate bitemporal storage is not inherently required, but immutable records must contain enough temporal facts to derive both intervals. These do not.

5. **Arrangement/qualification/disposition referential integrity is unstated at the safety boundary.**
   A qualification references an arrangement revision ([02-admission-evidence-and-change-policy.md:34](explorations/model-artifact-admission/research/02-admission-evidence-and-change-policy.md:34)); a disposition references a qualification ([02-admission-evidence-and-change-policy.md:47](explorations/model-artifact-admission/research/02-admission-evidence-and-change-policy.md:47)); and the consumer must apply that disposition to “the arrangement in use” ([BRIEF.md:46](explorations/model-artifact-admission/BRIEF.md:46)). No invariant requires those identities to agree. No mismatch rejection appears in the first-slice proof. A stale or malicious disposition/qualification pairing can therefore authorize revision B while execution uses revision A. Either the disposition must derive its arrangement exclusively through the qualification, or an enforced equality constraint is required.

## MAJOR

6. **`ProviderInstance` cannot supply the promised hosted identity envelope.**
   The envelope requires provider, service, deployment, requested model, resolved model, alias class, and assurance tag ([01-hosted-identity-boundary.md:13](explorations/model-artifact-admission/research/01-hosted-identity-boundary.md:13)). `ProviderInstance` stores a CLI binary path, environment, HOME, CLI kind, label, and auth probe ([ProviderInstance.model.ts:39](packages/agents/domain/src/entities/ProviderInstance/ProviderInstance.model.ts:39)). Its “public identity fields” are only generic entity type, serial ID, and public ID ([ProductEntity.ts:56](packages/shared/domain/src/entity/ProductEntity.ts:56)). Its provider vocabulary is `claude | codex`, explicitly describing CLI kinds rather than hosted API services ([ProviderInstance.values.ts:27](packages/agents/domain/src/entities/ProviderInstance/ProviderInstance.values.ts:27)). Reusing its identity can name a local CLI configuration, but cannot produce the “real identity envelope” claimed by the slice.

7. **The admission scope vocabulary does not yet exist, and the MAP never defines its literals.**
   The documents correctly identify the kits as net-new ([DECISIONS.md:5](explorations/model-artifact-admission/DECISIONS.md:5)), but the MAP jumps directly to a disposition “scoped to non-matter internal tooling” ([MAP.md:29](explorations/model-artifact-admission/MAP.md:29)). It never states whether that phrase is a role, data class, policy tier, or combination of fields, nor enumerates any role/modality/data-class members. Existing repository “roles” are unrelated chat-message or membership discriminators. Without concrete literals and a mapping from professional-runtime inputs, the fixture can store vocabulary but cannot demonstrate eligibility semantics.

8. **The named consumer cannot verify the arrangement it is approving.**
   The current approval gate contains candidate references, decision, evidence, lifecycle, policy basis, requested actions, and reviewer identity—but no arrangement, qualification, disposition, or usage reference ([ProfessionalRuntime.contracts.ts:482](packages/agents/use-cases/src/processes/ProfessionalRuntime/ProfessionalRuntime.contracts.ts:482)). `RuntimeUsageRecord` carries only provider and model strings ([ProfessionalRuntime.contracts.ts:659](packages/agents/use-cases/src/processes/ProfessionalRuntime/ProfessionalRuntime.contracts.ts:659)). The MAP excludes runtime enforcement from the slice ([MAP.md:39](explorations/model-artifact-admission/MAP.md:39)), so there is no proof that the disposition ID and actual execution arrangement are joined. Adding an opaque ID field would satisfy the noun-level contract while leaving the safety property unenforced.

## MINOR

9. **The digest mutation acceptance test proves the wrong boundary.**
   “A mutated component digest yields a NEW revision” ([MAP.md:34](explorations/model-artifact-admission/MAP.md:34)) only proves that changing an already-trusted digest string changes the outer digest. It does not prove that modifying a prompt, wrapper, tool schema, or decoding value recomputes the corresponding component digest. The test must mutate source component content and pass through the production canonicalization/digest pipeline; otherwise arbitrary or stale digest values satisfy it.
