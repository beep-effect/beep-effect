## Notes

- **v3 was not uniform on tests either.** Only knowledge/server (52 real tests) practised the mirror-and-`_shared` grammar; iam had 1 real test in 980 src files, and 8/10 tiers carried only a scaffold `Dummy.test.ts`. The "1:1 mirroring" from `41-v3-knowledge-engine.md` is 11/21 directories and 0.64 by LOC. Porting "mirroring" would be porting one package's habit.
- **The mirroring gap is real but v4 chose a substitute, not nothing.** Flat `test/` plus concept-prefixed stems (95/169) carries the same locate-the-twin information; the substitute is only 56.2% consistent and has no rule. If uniformity is wanted here, the cheapest gate is "test stem begins with a `src` concept folder name or a package-level composer name", scoped to slices, hosted on `PackageTestImports.collectPackageTestFiles` (the walker already enumerates exactly these files). Mirroring `aggregates/<C>/` under `test/` would fight the generator (`AcceptedProofManifest.ts` emits flat paths) for no boundary gain — do not port.
- **Placement is enforced by the runner, not by doctrine or lint.** A test under `src/` would be silently ignored by `vitest.shared.ts:141`, and `package-test-imports` would not see it. That is a stronger guarantee than v3's `bun test` (which discovers `*.test.ts` anywhere) but it is an accident of the include glob; a one-line doctrine sentence plus a lint that fails on `src/**/*.test.*` would make it explicit. Tooling-owned `src/internal/test/*.test-kit.ts` seams are already carved out by `PackageTestImports.ts:69-86`.
- **`/test` subpaths: the doctrine over-promises for domain.** `08` L55/L92/L192 imports `@beep/iam-domain/test`, while `13-onboarding` L43/L50 lists `./test` in use-cases/server export maps; 0/8 domain packages publish it, and every actual `/test` publisher is server/config/use-cases. `ARCH` L445-447 ("required names when that role exists") makes absence legal, so this is doctrine-example drift rather than a package violation. The test-specific isolation lenses do hold: 14/14 `/test` imports are same-slice, with 0 other-slice `-server`, cross-slice `/test`, or app-runtime Layer imports.
- **Suffix infixes are a lane grammar in disguise, and placement leaks.** The two `.pg.test.ts` files and 9/11 PGlite-shaped files live under `test/integration/`; the two law-practice PGlite files sit at `server/test/`. Lane selection comes from package scripts: 30/40 exclude `test/integration/**`, while law-practice/server runs bare Vitest. Those two database integration tests therefore enter Test Unit. Neither the general directory boundary nor `.pglite.test.ts` is written into doctrine.
- **Placeholder tests.** v3's `Dummy.test.ts` existed to keep `bun test` green on empty packages; v4 solves the same problem with `--passWithNoTests` (32/40 scripts) plus `test/.gitkeep`. The 8 packages whose `beep:test` lacks `--passWithNoTests` (bare `vitest run`) would fail if their tests were deleted; that is a script-shape inconsistency, not a doctrine matter.
- **Ratchets, not universal remediation, are the v4 enforcement posture.** Coverage (`coverage.regression-baseline.jsonc`, 131 package rows / 41 slice rows plus an explicit `follow_ups` parking lot of 8 slice packages) and test typecheck (`test-typecheck.blindspot-baseline.jsonc`, 25/40 slice packages blind) fail regressions or growth while preserving inherited debt. These mechanisms live in DECISIONS, baseline headers, and CLI code rather than `ARCHITECTURE.md`. `08`'s hard sentence (`Never bun test`) still has no dedicated lint gate; it is true today because all 40 package scripts use Vitest and `bun:test` imports are 0.
- **The doctrine's contract-suite pattern (`08` L206-287) has never been implemented** in either repo. The 14 `TaggedError.equivalence.test.ts` files and the `.pglite`/`.pg` integration suites are the closest live analogue. Either delete the section or make the generator emit `<Port>.contract.ts` for `.ports.ts`.
- **Scout-fact corrections in this family:** plain-suffix files are 126 total (123 `.test.ts` + 3 `.test.tsx`); "9 `.pglite.test`" is 9 plus 2 variant spellings, with 2/11 outside `integration/`; "use-cases `test.ts` all slices" is 2/8; `@beep/testkit` (v3) and `@beep/test-utils` (v4) are different packages — v4 tests import `@beep/testkit` 0 times.
