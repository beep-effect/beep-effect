# Convention inventory

This inventory reconciles the six verified family tables. Their verification logs are the errata layer: a corrected count or interpretation there supersedes the original row wording. Commands use `~` for the home directory. In compact cells, `<v3>` means `~/YeeBois/projects/beep-effect4/packages/{iam,knowledge}`; `<v4>` means the eight slice roots under `packages/{agents,architecture-lab,documents,epistemic,law-practice,ontology,shared,workspace}`. All counts exclude `node_modules`, `dist`, `coverage`, and `.turbo`.

## How to read the statuses

- `codified`: doctrine names the pattern and at least 90% of measurable v4 sites follow it.
- `codified-but-drifted`: doctrine names the pattern, but fewer than 90% of measurable v4 sites follow it; the decisive percentage remains in the evidence cell.
- `drifted`: doctrine does not choose a rule and v4 code is inconsistent.
- `missing`: neither doctrine nor v4 code supplies the pattern.
- `v4-only`: v4 has the pattern and v3 does not. This is the primary rollup label even when the v4-only rule is codified.
- `not-worth-porting`: the v3 pattern conflicts with v4 boundaries or the decided PascalCase concept grammar.

The 90% threshold comes from [DECISIONS.md](../DECISIONS.md), entry `2026-08-29 — status thresholds`. Each row receives exactly one rollup status.
