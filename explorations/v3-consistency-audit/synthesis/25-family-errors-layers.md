3. ## Notes

- **v3 was not uniform on the family's headline conventions.** The two error homes were two idioms (EL-04: 78 empty-identifier vs 87 `$I` classes, 47%/53%), and only knowledge had a central `errors/` (EL-02). Service declaration was 90% `Context.Tag`, with `Effect.Service` confined to `iam/client/*/service.ts` (10) and one server adapter. What *was* uniform is what the scaffold stamped: the 2-error kit (39/39), `RepoLive` (39/39), `Live` as the dominant Layer spelling (108/128 = 84%), and the `*Error` suffix (98%). Those are copy discipline, not a rule — no v3 gate existed either (10 §"no-structural-enforcement", 11 §"no-enforcement-docs-stale").
- **The only gate in this family is v4's `annoteError` rule (EL-05).** It is a declaration-shape check (`SFV4-tagged-error-equivalence` in `SchemaFirstDetectors.ts`), scoped to `packages/**/*.{ts,tsx}`, and it is at 100% with an empty exception inventory. It proves the repo can hold a 100% convention when a `lint policy` step backs it. Nothing checks *where* an error class lives, *what it is named*, or *where a Layer lives*.
- **The proof is a drift vector for EL-03, but the first draft undercounted both conformers and nonconformers.** The proof templates inline WorkItem/Worker errors, and documents copied the placement for 4 concepts / 9 classes. Seven port files import `.errors.ts` directly and workspace's `ThreadStore.ts` imports `Thread.errors.ts`, so 8 concepts / 16 classes conform. The 20 inline `.repository/.ports` classes, 2 `WorkspaceVaultStore` errors, and 2 Session capability errors produce 24 inline slice classes; `OfficeActionReview.ports.ts` is an additional inline reused-error union. The resulting concept conformance is 8/20 (40%), not 2/12. The server-only `CandorPromotionGate.ports.ts` seam remains a separate role question.
- **EL-16 is a real doctrine violation, not a spelling.** Law-practice exports three live/composition Layers (`CandorPolicyLive`, `LegalPositionRelatorPolicyLive`, `CandorRecordReaderFromRepository`) and ontology exports five (`OntologyToolServiceLive`, three Session runners, `SessionUseCasesLayer`) from use-cases. The direct syntax census also finds agents' `FixtureTurnKernel`, but `08-testing.md` explicitly permits test-only stub Layers, so it is not counted as live. A gate must distinguish test fixtures from runtime wiring rather than banning every `Layer` token under use-cases.
- **Layer suffix (EL-12) is where v3's uniformity is worth porting and the doctrine itself is the obstacle.** The doctrine's examples use `…Live`, `…Layer`, `…ServerLayer`, `…Test`, and `…InMemory`; direct v4 declarations follow all of them (45/37/4/9), with per-slice dialects (documents 22 `Layer` / 5 `Live`; epistemic 11 `Live` / 0 `Layer`; ontology 11/6). A one-line decision (for example `<Thing>Live` for default wiring, `<Thing><Adapter>Layer` for alternates, `<Slice>ServerLive`/`<Slice>ServerTest` for composers) plus a syntax-aware export check would close it. The root composer name `<Slice>ServerLive` is already 6/6, and `PackageShell.ts` generates that spelling, though no global census enforces existing packages.
