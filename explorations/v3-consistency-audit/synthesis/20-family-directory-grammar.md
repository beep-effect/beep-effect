Cross-check of the v3 inventories (`10-v3-iam-inventory.md`, `11-v3-knowledge-inventory.md`) against the v4
doctrine (`12-v4-doctrine-inventory.md`), the v4 slice census (`13-v4-slices-census.md`), the tooling audit
(`14-v4-enforcement-tooling.md`) and the lab diff (`15-architecture-lab-vs-doctrine.md`). Every number below
was re-run on 2026-08-29: v3 at `~/YeeBois/projects/beep-effect4` (HEAD `997a827454`, `packages/{iam,knowledge}`
only), v4 at `~/YeeBois/projects/beep-effect7` (HEAD `3435c24f94`, the 8 slice roots

a count without a command next to it was not verified.

## TL;DR

1. v4 has already ported v3's one genuinely uniform directory habit — PascalCase `<Concept>/<Concept>.<role>.ts` folders — and made it doctrine: 254 PascalCase dirs, 432/432 suffixed files PascalCase, and 403/432 (93.3%) named after their parent; the only kebab directory is the generated non-concept `free-law-project/`. v3 only had this discipline in domain/server (client/ui/tables were kebab), so v4 is *more* uniform here.
2. The consequential live drifts are v4-internal, not reasons to restore v3: domain-kind folders outside domain (21/32 packages use a kind folder, 65.6%, while onboarding contradicts the canonical tree), broad basename casing (549/621 PascalCase, 88.4%), and package-root composers (36/84 PascalCase, including `Layer.ts` 6/7 but `Tables.ts` only 1/7).
3. v3's flat kebab tables, kebab client operation folders, nested `contracts/`/`schemas/`/`rpc/` folders, and suffix-less topical server modules conflict with the decided PascalCase/role grammar and are not worth porting. No command walks slice directories today: `pascal-case-file` is tooling-CLI-only and `schema-topology` is `@beep/schema`-only.

## Notes

- **v3 was three dialects, not one.** The "v3 wins on uniformity" premise holds only for the domain tier (iam 20/20 folders × 11 files; knowledge 22/22 folders, 19/19 seven-role kits) and for the server `entities/<C>/` mirror. Tables (kebab flat), client (kebab operation folders, 0 PascalCase anywhere) and ui (kebab) each had their own grammar, and knowledge's server put 95 suffix-less files in 16 topical modules. v4's `<kind>/<Concept>/<Concept>.<role>.ts` reaches all tiers (403/432 same-name; 254 PascalCase dirs; one generated non-concept kebab dir), so v4 is already the more uniform codebase; what it lacks is a slice gate.
- **v3 uniformity was copy discipline, not the generator.** The v3 `create-slice` templates (`tooling/cli/src/commands/create-slice/templates`) emit `domain/src/value-objects/`, `domain/src/entities/Placeholder/Placeholder.model.ts` (one role file), `server/src/db/repos/Placeholder.repo.ts`, and `tables/src/tables/placeholder.table.ts`. Neither slice uses `value-objects/` (both have `values/`) or `server/src/db/repos/` (both use `server/src/entities/<C>/<C>.repo.ts`). The same thing is happening in v4 with the architecture-lab manifest: the proof reproduces `tables.ts`, `layer.ts`, per-concept `server.ts` on every `add concept`, and hand-written slices (epistemic, law-practice) diverge from it on domain-kind folders.
- **Row 4 is the decision that unblocks enforcement.** A folder gate cannot be written until the doctrine picks one of its two answers (`ARCHITECTURE.md` tree L827-941 and `01` L79-86 say `<kind>/<Concept>/` everywhere; `13-onboarding` L22-48/L129-137 says bare `<Concept>/` outside domain). Code is 21:9:3 (kind:bare:flat, counting the `workspace/server` mix as kind). Either answer is a mechanical rename of ≤ 9 packages; the epistemic and law-practice slices are the bulk of the bare side.
- **Row 8 is a doctrine gap, not just a casing drift.** The 48 lowercase root files (`public.ts`, `server.ts`, `test.ts`, `layer.ts`, `secrets.ts`, `tables.ts`, plus `shared/domain`'s kind shims) are subpath entry files named after their export key; the doctrine lists only PascalCase composers and lowercase *subpaths* and never says whether the entry file may be lowercase. `server/src/Layer.ts` behind `./layer` (6/7) proves the PascalCase-file/lowercase-subpath pairing is already normal; the tables tier (`tables.ts` 3 / `Schema.ts` 3 / `Tables.ts` 1) is the outlier that needs a ruling.
- **Rows 7 and 9 overlap by construction.** The 72 non-PascalCase basenames in row 7 decompose into 48 root entry files (row 8), 15 per-concept `server.ts`/`worker.ts` (row 9), 7 generated kebab data files under `law-practice/domain/src/internal/generated/`, and 2 strays (`spikeEntity.ts`, `primitives.ts`). Any casing gate needs an allowlist for exactly those first three groups or a doctrine ruling that removes them.
- **What is uniform without a gate today (candidates for a cheap freeze):** tier names 40/40 (row 1); domain kind use 8/8 and value folder-per-concept at 8/8 existing sites with 0 loose files (rows 3, 10); 432/432 suffixed files Pascal-first (row 7); and tables kind folders 7/7 (row 12). Flat concept folders are 253/254 and PascalCase dirs have one generated kebab exception, so those checks need one explicit exception or one cleanup each rather than claiming zero violations.
- **Enforcement inventory for this family (verified in code):** `Lint.command.ts` L254-284 `pascal-case-file` (tooling CLI only); `SchemaTopology.ts` L21 (`@beep/schema` only); `Fallow.command.ts` L119-132 (reads tier names but maps `use-cases`/`client`/`config` to `other`); `Architecture.schemas.ts` L33 (operation-plan input); root `package.json` L408-465 (explicit workspaces). `PackageTestTypecheck.ts` checks a package-test configuration concern, not directory grammar. Nothing walks existing slice packages for folder/casing shape.
- **Out of family, noted for collocation:** cross-tier concept-name drift (`GraphRag`/`GraphRAG`, `Agent/KnowledgeAgent.*` — the 7 v3 mismatches in row 6). Structural barrel placement is now measured in row 16 rather than deferred.
