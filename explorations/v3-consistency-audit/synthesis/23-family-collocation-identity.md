## Notes

**v3 was two slices with several `$I` grammars, not one uniform repository law.** The exact path rate is 100/101 in iam domain but 104/146 in knowledge domain; iam client deliberately keys 118/151 files to the operation folder. v4 repeats that plurality: 308/379 exact paths, 61 folder keys, and 10 other keys. Doctrine demonstrates all three styles and never chooses one, so CI-07 is drifted rather than codified-but-drifted.

**`$I` presence is optional doctrine, not an unenforced mandate.** `09-errors-across-boundaries.md` explicitly permits omission when no distinct identifier is needed. The corrected live count is 379/621; domain is 252/280, and `.model.ts` is 147/148 only because the remaining file is a pure re-export. A proposed universal `$I` gate would contradict doctrine. A narrower schema-identity policy would require a new decision and a role-accurate census, not extrapolation from all source files.

**Doctrine names the wrong ProductEntity API.** `ARCHITECTURE.md` says `ProductEntity.make(EntityId)`, but source exports `ProductEntity.Entity` and has 49 calls across 47 files; source has 0 `ProductEntity.make(` calls. The identity relationship is nevertheless uniform: every ProductEntity declaration takes an Id, and 30 table files project that model transitively.

**Only one projection exception is a generator template.** `WorkItem.table.ts` is hand-mapped and is copied by `AcceptedProofManifest.ts`; `Worker.table.ts` is projected but keeps inline converters. The second hand-mapped file, epistemic `ExecutionRecord.table.ts`, is not in the accepted proof manifest. The correct factory finding is therefore narrower: the generator reproduces one non-projected table and two inline-converter functions, not both `pgTable` exceptions.

**Converters are the largest undocumented live seam.** Twenty-five sibling files plus WorkItem/Worker inline converters cover 27/32 table modules, and all 15 server repos consume converter functions. Standards mention `.converters` zero times. This is a measured v4-only habit, not a codified role; its 84.4% table coverage also falls below the 90% threshold.

**Literal table-name duplication is limited to the hand-mapped exceptions.** Two files contain three typed literals (WorkItem one, ExecutionRecord two). Thirteen additional files export a value derived with `getTableName`; those are not duplicate literals. The draft's 8/32 figure was unsupported.

**Persisted folder mirroring is 32/32, including domain kind.** The apparent Contradiction and EvidenceVerification mismatches came from selecting their same-stem `values/` models while ignoring the same-stem `entities/` models actually imported by the tables. Broader cross-tier mirroring remains 65/94 because 29 workflow, policy, and adapter concepts have no same-name domain folder.

**v3 shapes that conflict with v4 remain not worth porting.** These are domain-resident generic `Repo` tags, `class Model ... $I\`<C>Model\`` identity, kebab table filenames, and `_check.ts`. PascalCase concept folders remain the decided winner. No row proposes restoring v3 package boundaries or recreating v3 iam/knowledge slices.
