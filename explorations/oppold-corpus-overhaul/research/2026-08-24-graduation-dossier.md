## 2. **Stop-condition candidates**

These are the four remaining align questions identified in `explorations/oppold-corpus-overhaul/DECISIONS.md` and `explorations/oppold-corpus-overhaul/ops/manifest.json`.

### ① Pipeline re-evaluation "from scratch"

1.  **Recommended.** Stop when a versioned matrix covers the current-T7 archive plus the existing governed-corpus run union, and every observed format, container, and pipeline stage has one `keep | replace | add | defer` decision with an owner, acceptance check, and unsupported/quarantine outcome.
2.  Stop after a two-week audit that ranks gaps by preserved bytes and loss risk, with every item below the approved risk threshold deferred to named re-entry packets.
3.  Stop when 100% of preserved occurrences and 99% of transformable bytes map to a supported or explicitly quarantined lane, regardless of long-tail format count.

**Recommended rationale:** a closed decision matrix turns "exhaustive" into a finite denominator without pretending every format has an engine; the missing denominator is the central attack in `explorations/oppold-corpus-overhaul/research/2026-08-17-adversarial/codex-b.md` section "MAJOR" and `explorations/oppold-corpus-overhaul/research/2026-08-17-adversarial/grok-b.md` section "4. Missing entirely."

### ② Capability incorporation "and more"

1.  **Recommended.** Stop after every capability named in `CAPTURE.md`, plus only capabilities required to close a matrix gap from ①, has a written input/output, precedence, fallback, privacy, cost, and acceptance contract or an explicit defer decision; package discovery alone does not add scope.
2.  Freeze the capability allowlist at BRIEF approval and admit one replacement only when a named engine fails its vertical-slice acceptance test.
3.  Evaluate at most two candidate engines per uncovered matrix cell, then choose one or defer the cell.

**Recommended rationale:** this composes live bricks while closing the blank check exposed in `explorations/oppold-corpus-overhaul/research/2026-08-17-adversarial/codex-b.md` section "MAJOR" and `explorations/oppold-corpus-overhaul/research/2026-08-17-adversarial/grok-b.md` section "2. Composition claim."

### ③ Per-step pipeline self-improvement

1.  **Recommended.** Freeze one immutable pipeline version per run, evaluate each stage against a fixed metadata-safe regression set in shadow mode, and stop when no candidate clears its predeclared quality gain and cost/regression thresholds; accepted changes apply only to the next run.
2.  Permit at most one promoted improvement per stage per pipeline version, with all other observations written to a ranked backlog.
3.  Run improvement review only after the vertical slice and after the full run, never between items in the same run.

**Recommended rationale:** the first option preserves reproducibility while retaining measurable learning, directly answering `explorations/oppold-corpus-overhaul/research/2026-08-17-adversarial/codex-b.md` section "MAJOR" and `explorations/oppold-corpus-overhaul/research/2026-08-17-adversarial/grok-b.md` section "4. Missing entirely."

### ④ Enrichment through "every avenue"

1.  **Recommended.** Stop when the closed set of authority sources tied to the approved v2 competency questions either meets each declared quality target or fails a license, privilege, authority, contradiction, cost, or marginal-gain gate, with every external assertion stored beside rather than over corpus evidence.
2.  Allow one public-authority source and one local deterministic source per measured gap, then defer unresolved gaps after the first capped pass.
3.  Defer all new enrichment until the restored-corpus baseline and bundle-v2 provenance checks pass, then reopen the exploration at `decompose`.

**Recommended rationale:** the first option bounds both source count and epistemic risk while preserving the prior incremental USPTO precedent in `goals/oppold-corpus-pipeline/history/outputs/2026-06-11-p4-enrichment-report.md`; the contamination attack is in `explorations/oppold-corpus-overhaul/research/2026-08-17-adversarial/codex-b.md` section "MAJOR."

## 5. **BRIEF skeleton**

### Problem narrative

The practice has a newly discovered removable-drive salvage that post-dates the completed June pipeline and July refresh, so the governed corpus and its current knowledge-graph projection do not include the full current-T7 evidence set. The corrected census shows that current-T7 preservation is urgent, that the opening loss balance must remain honest, and that loss risk concentrates in a large mail estate spread heavily through recycle data. The live pipeline cannot meet the ratified bar: hashing and PST extraction materialize whole files, recovered mail is not selected by current corpus orchestration, result ledgers are not crash-safe, attachment repair and DOC conversion are absent, and several named "bricks" are capabilities rather than pipeline stages. The overhaul must therefore preserve first, prove a mail-first transformation slice second, and only then run a bounded, versioned pipeline that emits a provenance-complete v2 projection without disturbing the live v1 front. ### Appetite recommendation

Use the operator-ratified split appetite in `explorations/oppold-corpus-overhaul/DECISIONS.md`: land and run the preservation gate this week, then give the mail, recycle, and DOC transformation gates one approximately three-week wave. Pipeline re-evaluation, semantic ingestion, enrichment, and bundle-v2 delivery get no implementation appetite now; they remain gated MAP candidates.

### Fat-marker solution sketch

1.  Define the current-T7 archive object and loss-ledger schemas, preflight capacity, then copy once while streaming digests into atomic destinations; independently reparse and verify the destination manifest before any transformation. Keep the large zip as its own archive object.
2.  Build immutable content, occurrence, and derivation records. Reconcile the three recycle volumes with safe restored paths and directory descendants; share bytes by digest without collapsing provenance.
3.  Prove one mail occurrence end to end, then expand store by store: source-path pffexport, `-m all`, concurrency one unless measured otherwise, append-only child/warning/failure rows, per-child digests, atomic attempts, type repair, and a second extraction pass.
4.  Format-validate distinct legacy Word digests, convert inside a pinned sandbox, compare the declared fidelity dimensions, retain the originals, and quarantine exceptions.
5.  Freeze a pipeline version and a closed format/capability matrix. Run a checkpointed DAG with disk/time/cost preflight, privilege gates, reversible prune-last policy, and shadow-only improvement proposals for the next version.
6.  Bootstrap from the ready semantic seed, extract a representative set, refine and freeze against competency questions, then apply the closed enrichment register as separately sourced assertions. Emit a v2 projection and quality report that gates a new disposable practice-KG bundle.
