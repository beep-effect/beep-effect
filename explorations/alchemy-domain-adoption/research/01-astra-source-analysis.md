## 1. What a Postgres platform actually has to implement

### Public contract, including what it does not promise

`Platform` is a Context service with one method, `model(HostedModel): Effect<ModelHost, never, Scope>`. Each model must have isolated storage; two distinct model definitions with the same model name must fail rather than alias data. `captureContext` deliberately omits construction-time Scope. A platform returns five factories: aggregate, view, policy, projection, stream. A persistent implementation also needs the semantics behind optional `start` and `history`: newly added consumers must receive history and clients must know whether catch-up is complete. Optional in the TypeScript interface is not evidence that silently omitting this behavior preserves beta.85 durable-host behavior. [A/packages/domain/src/Platform.ts:24; A/packages/domain/src/Platform.ts:610; A/packages/domain/src/Platform.ts:654; A/packages/domain/src/Platform.ts:677]

**Optimistic concurrency correction:** there is no public `append(expectedVersion, events)` method or `expectedVersion` in SendMeta. The contract is a single writer per aggregate instance; the kernel sees the current version and returns a new one. An accepted no-op can emit zero events, so stream version is not beep's “increment on every row write” token. A Postgres implementation can use row locks or an internal compare-and-swap/retry loop, but application stale-edit rejection must be modeled explicitly in a command and its decision. UI prediction is another separate concern. [A/packages/domain/src/Aggregate.ts:70; A/packages/domain/src/Aggregate.ts:242; A/packages/domain/src/Platform.ts:258; A/packages/domain/src/InMemory.ts:482; B/packages/shared/domain/src/entity/EntityKit.ts:66]

**Unique values correction:** there is no reservation factory in Platform. The documented solution makes the normalized unique value an aggregate key, then claims it before committing the customer operation through a policy. A Postgres unique index protects that aggregate's key; it does not replace the reservation lifecycle, owner, release, compensation or tenant-normalization semantics. [A/website/src/content/docs/domain/unique-values.mdx:6; A/website/src/content/docs/domain/unique-values.mdx:63; A/website/src/content/docs/domain/unique-values.mdx:94; A/packages/domain/src/Platform.ts:610]

**Saga correction:** there is no SagaStore factory. Model hosting discovers and requires `WorkflowEngine` when sagas exist, scopes it to the model, and supplies saga implementations. InMemory merges a workflow engine with Platform; Cloudflare integrates its Durable Object workflow engine. A Postgres event store alone therefore does not deliver restart-safe sagas. A production platform package should compose a compatible durable Effect workflow engine and prove activity/deferred/sleep recovery. Whether the exact installed Effect 4.1.1 SQL/cluster engine can supply every needed semantic without adaptation is **UNVERIFIED** here. [A/packages/domain/src/Model.ts:499; A/packages/domain/src/Saga.ts:310; A/packages/domain/src/InMemory.ts:1134; A/packages/cloudflare/src/Domain/index.ts:51; A/packages/cloudflare/src/Domain/index.ts:62]

**Timer guarantees are strong:** schedule replaces a pending command with the same commandId, survives restart, and is at least once. Scheduling already-receipted commands fails. Successful unschedule must prevent even a due command from executing and must remember cancellation; distinguish AlreadyExecuted, AlreadyCancelled and NotScheduled. Use the same serialization boundary for timer execution, cancellation and direct send. Cloudflare uses job tokens; InMemory demonstrates cancellation under the aggregate lock. [A/packages/domain/src/Platform.ts:266; A/packages/domain/src/InMemory.ts:531; A/packages/cloudflare/src/Domain/index.ts:801]

### Proposed Postgres design — engineering design, not implemented proof

Use an upstream-facing generic platform module with a typed SQL client dependency and a beep driver/config layer that provides the Postgres connection. Prefer Effect SQL's transaction/lifecycle facilities to introducing a new dependency on the entity kit scheduled for retirement. Drizzle is viable as a SQL construction tool behind that boundary; it does not supply the delivery/workflow guarantees. Exact `effect/sql` versus current `effect/sql/*` import/export compatibility must be checked against the pinned 4.1.1 package before implementation (**UNVERIFIED**). This placement follows beep's driver and layer ownership rules and Platform's infrastructure-neutral factory seam. [B/standards/architecture/03-driver-boundaries.md:1; B/standards/architecture/05-layer-composition.md:193; A/packages/domain/src/Platform.ts:610]

Proposed schema families, all scoped by stable model name and concept name:

- `aggregate_instances` (id, state JSONB, version), immutable `aggregate_events` (instance, seq, envelope, event), `command_receipts` (instance, commandId, reply/events/version), and `delivery_outbox`. Atomically commit all four. Create/lock the instance row safely on first command; decide while holding the lock. Publish wakeups only after commit. This realizes the aggregate contract; table names are proposals. [A/packages/domain/src/Platform.ts:258]
- `view_keys`, `view_entries`, downstream outbox and any input/replay state needed for generations. Store per-source checkpoints independently or as bounded JSONB; the latter is simpler but must be measured for high fan-in. Rebuild into generation-specific storage or reset only under an exclusive generation transition. [A/packages/domain/src/Platform.ts:329; A/packages/domain/src/Platform.ts:353]
- `consumer_inputs`, `consumer_progress`, worker leases/fencing tokens, retry state; distinguish policy and projection semantics. Claim ordered partitions, not arbitrary outbox rows: naive `SKIP LOCKED` on individual deliveries lets later work overtake a locked predecessor. After a crash, replay unacknowledged work. Poison deliveries need visible retry/quarantine operations without silently advancing checkpoints. [A/packages/domain/src/Platform.ts:64; A/packages/domain/src/Platform.ts:466]
- `stream_entries` and `stream_meta`, with transactional comparison of write origin and checkpoint advancement. Do not reuse aggregate receipt logic as stream deduplication. [A/packages/domain/src/Platform.ts:537; A/packages/domain/src/Platform.ts:581]
- `scheduled_commands` with due time, commandId, context, token and cancellation tombstone. A timer worker claims work then acquires the same aggregate lock, rechecks token/cancel/receipt, and executes exactly the normal commit path. Use database time consistently. [A/packages/domain/src/Platform.ts:266; A/packages/cloudflare/src/Domain/index.ts:814]
- Deployment/consumer-plan state and replay cursors. Enumerate aggregate/view keys from SQL indexes rather than copying Cloudflare's object-directory tree. Keep catch-up bounded, resumable, generation-aware and coordinated with live routing. [A/packages/domain/src/Platform.ts:625; A/packages/domain/src/InMemory.ts:501; A/packages/domain/src/InMemory.ts:1100]
- Workflow engine storage through its own supported adapter; do not invent a second saga journal in the domain platform unless the engine cannot satisfy the contract. Notification channels can reduce poll latency, but persisted sequence cursors must recover missed wakeups and close the initial-query/subscription race. These are proposed durability mechanisms derived from the required tail and workflow interfaces. [A/packages/domain/src/Platform.ts:301; A/packages/domain/src/Model.ts:499]

The hardest parts are replay/live ordering across generations, projection side-effect retry safety, and saga/timer cancellation during worker failure. The SQL inserts are the easy part. Evidence for this assessment is the substantial backfill machinery, commit routing, durable outbox and timer paths, not a benchmark. [A/packages/domain/src/Backfill.ts:1; A/packages/domain/src/InMemory.ts:501; A/packages/cloudflare/src/Domain/index.ts:205; A/packages/cloudflare/src/Domain/index.ts:415]

## 7. Risks / sharp edges

- **Row-version mismatch:** event count is not row-write count; accepted no-op behavior can break old optimistic locking expectations unless explicitly modeled. [A/packages/domain/src/Aggregate.ts:70; B/packages/shared/domain/src/entity/EntityKit.ts:66]
- **Numeric identifiers:** both Type and Encoded key must be string; changing only wire encoding is insufficient. [A/packages/domain/src/Key.ts:5; A/packages/domain/src/Aggregate.ts:100]
- **At-least-once effects:** external remote mutation may complete before a worker/checkpoint crash. Keep stable external idempotency keys and reconciliation; do not advertise exactly-once Box/calendar effects. [A/packages/domain/src/Platform.ts:64; A/packages/domain/src/Platform.ts:498; B/packages/documents/domain/src/entities/SyncOperation/SyncOperation.model.ts:68]
- **Single-process locks are not distributed proof:** current sync engine uses an in-memory workspace semaphore. Migration must demonstrate cross-process exclusion/leases, not just retain that lock. [B/packages/documents/server/src/aggregates/Sync/VaultSyncEngine.service.ts:103]
