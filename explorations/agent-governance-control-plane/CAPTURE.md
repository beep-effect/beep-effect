## 2026-07-14 — Distilled from the paused goal packet

### Durable design seed

- **One ordered canon.** Resolve conflict by preferring current repo law and
  enforcement, then live repo reality, then the approved scope/design record,
  then closed outputs and handoffs. Consumers inherit the canon; they do not
  fork generic policy into local prompts.
- **Every law has an owner and a proof surface.** The original families
  covered schema-first modeling, branded domains, typed failure boundaries,
  Effect-native data handling, service/Layer and HTTP boundaries, state
  primitives, reuse, documentation, and verification. The list is a research
  seed, not current doctrine; reconcile it with today’s `AGENTS.md`, standards,
  skills, and Yeet workflow before reuse.
- **Explicit authority by role.** An orchestrator owns integration and final
  packet emission; implementation/domain workers own bounded production;
  adversarial auditors own rejection authority for drift; a drift auditor
  compares the work with prior decisions and live repo reality. Workers cannot
  overrule auditors, auditors cannot widen product scope, and overlapping
  ownership is a defect.
- **Structured blockers.** A useful blocker records the law family, violated
  requirement, location, evidence, required change, severity, and a narrow,
  verifiable acceptance condition.
- **Universal gated lifecycle.** Research → Plan → Implement → Refine →
  Validate. Entry requires named inputs, output, and acceptance criteria. Exit
  requires substantive output, closed blockers or an explicit exception,
  resolved drift, and evidence ready for the next stage. Material conflict
  with repo reality, missing decisions, uncovered laws, hidden exceptions, or
  an under-specified output contract are stop conditions.
- **Decision-complete artifacts.** The reusable contract set was: category
  charter, research dossier, execution packet, refinement report, verification
  report, reuse inventory, dependency-boundary report, and exception ledger.
  Prompt assets should instantiate these contracts with domain context rather
  than duplicate generic governance prose.
- **Exceptions expire.** Each exception names the exact law and location,
  owner, rationale, removal condition, and target closure phase. Open-ended or
  hidden exceptions are invalid.
