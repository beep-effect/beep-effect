## Traps flagged

- **A probe that has rotted can look like a fix.** The jsdom hold reproduces
  only under `vitest --bun`. A probe run on the wrong runtime exits 0 and
  produces a confident, wrong unpin PR. Every probe needs a control run that
  must still fail at the known-bad version. Otherwise the verdict is
  `ProbeBroken`, not "fixed". Require two consecutive passes before acting.
- **GritQL can't carry the whole completeness check.** Biome GritQL can't read
  package.json keys or join against a ledger file. The two-way check is a
  TypeScript census. GritQL can still enforce `it.skip("... [hold:<id>]")`,
  because there the anchor is a string literal.
- **Anchoring every suppression grows the inventory.** That would mean roughly
  144 `@ts-expect-error`, 60 `biome-ignore` and 176 fallow suppressions, which
  conflicts with the S31 no-inventory-growth ruling. Wave 1 is the roughly 35
  dependency-shaped sites; test skips are wave 2.
- **gh-aw as the runner.** It rejects cross-provider fallback chains at
  compile time.

## Three ideas worked out

1. **Probe-backed holds on `makeClaimEnvelope`.**
   - A `HoldProposition` carries the subject, assertion, falsifier
     (`Scripted | Judgement`) and exit action (`Unpin | Rewrite |
     EscalateToGoal`).
   - `validTime` is the expiry, the `supersedes` chain is the renewal history,
     and `supportedBy` holds dated probe runs.
   - Storage is in the repo and append-only, following the
     `research/README.md` claims-plus-ledger laws.
   - GitHub issues are a derived projection only.
   - First step: hand-write one record for the jsdom hold and add a
     `beep holds probe <id>` command that runs both the control and the
     candidate version.
2. **Wake when the world changes, not on a calendar.**
   - Typed watch targets, with three cost tiers:
     - Tier 0: signal polls using ETags, effectively free.
     - Tier 1: the probe in a scratch worktree, CPU only.
     - Tier 2: an agent through the fallback chain, run only when the
       probe's verdict flips.
   - Re-check inside `deps:update`, and batch due holds into one PR.
   - A GitHub Actions dead-man's switch watches the box's heartbeat.
3. **Anchor and lint for completeness.**
   - `beep lint holds --write` renders the derived configs (syncpack,
     overrides, patches, OSV ignores) from the ledger and auto-tombstones a
     hold whose anchor is gone.
   - `beep holds why <pkg>` is the step agents run before bumping a
     dependency.

## Provocation

What if a hold is a failing test? Each hold would be a `test.fails` canary in
a `holds/` vitest project that asserts the upstream bug still reproduces.
When upstream ships the fix, CI goes red, and that red is the wake signal.
The CI that already runs becomes the scheduler.
