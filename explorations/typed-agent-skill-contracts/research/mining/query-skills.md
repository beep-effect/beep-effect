## Per-skill notes

### data-twingler

- **What it actually does:** classifies requests by language and intent, then selects SQL, SPARQL, federated SPARQL, SPASQL, or GraphQL and one of several execution transports; it is an agent decision document, not executable query-planner code. Defaults such as endpoint, timeout, row limit, cache TTL, vector thresholds, and fallback endpoints are declared centrally in `ai-agent-skills/data-twingler/SKILL.md`.
- It makes template selection a hard pre-execution gate: T1-T4 explore data spaces, T5 retrieves ordered `schema:HowTo` steps, T6 resolves Questions/Answers, T7 resolves DefinedTerms, and T8 describes a directly discovered entity. Concrete query bodies and placeholder contracts live in `ai-agent-skills/data-twingler/references/query-templates.md`.
- T5-T8 use a staged retrieval state machine: optional local RDF candidate extraction and cosine matching, graph discovery by Virtuoso full-text search, server-side vector fallback, up to three semantic variants, ordered fallback endpoints, an index result, a user confirmation checkpoint, then the final query. The stages, thresholds, early exits, and evidence to report are explicit in `ai-agent-skills/data-twingler/SKILL.md`.
- Remote-KG aliases are normalized into a structured function call: a remote query must bind both `url` and concrete `query`; SPASQL must bind `sql`; missing arguments abort before OPAL/A2A invocation. The contract and example argument objects are in `ai-agent-skills/data-twingler/SKILL.md` and `ai-agent-skills/data-twingler/references/protocol-routing.md`.
- **Notable files worth a human read:** `ai-agent-skills/data-twingler/SKILL.md` for the state machine; `ai-agent-skills/data-twingler/references/query-templates.md` for query shapes; `ai-agent-skills/data-twingler/references/sparql-syntax-rules.md` for the clearest reusable validator checklist; `ai-agent-skills/data-twingler/references/protocol-routing.md` for parameter preflight.
- **Standout mechanism — syntax policy as a separate artifact:** UNION placement, nested SERVICE `SELECT` plus inner `LIMIT`, operator-form `bif:contains`, boolean term extraction, FILTER scope, GRAPH bracing, and orphan-brace checks are isolated from workflow prose in `ai-agent-skills/data-twingler/references/sparql-syntax-rules.md`.
- **Standout mechanism — entity-type-directed recovery:** a vector hit dispatches to different retrieval shapes for `schema:Question`, `skos:Concept`, and `schema:HowTo`, rather than treating all semantic matches as text chunks; see `ai-agent-skills/data-twingler/SKILL.md`.
- **Standout mechanism — result-aware pivot:** a graph-discovery hit whose literal is already a description becomes a T8 direct-answer candidate; failed T6 indexes get two bounded alternative patterns and then pivot instead of looping indefinitely. See `ai-agent-skills/data-twingler/SKILL.md` and `ai-agent-skills/data-twingler/references/query-templates.md`.
- **Standout mechanism — memory seam:** the endpoint-first override explicitly delegates ordering to a `preferences.ttl` step, while local discovery scans skill RDF folders. This is the only direct interaction in this lane with the pre-existing agent-memory conventions; it names `preferences.ttl` but not `agent-rdf-memory/`, so the coupling is implicit and underspecified. See `ai-agent-skills/data-twingler/SKILL.md`.
- **Weaknesses / smells:** “must execute” rules are prose only; there is no parser, template registry, test corpus, or executable validator beside the Markdown references in `ai-agent-skills/data-twingler/`.
- `references/query-templates.md` opens by describing T5-T7 as index → similarity match → final query, while `SKILL.md` inserts mandatory local search, graph discovery, reporting, and a user checkpoint. Two sources therefore describe different state machines. See `ai-agent-skills/data-twingler/SKILL.md` and `ai-agent-skills/data-twingler/references/query-templates.md`.
- Result negotiation is inconsistent: the settings declare `text/x-html+tr` and “tabulate all,” while SPASQL REST advertises `json`, `jsonl`, or `markdown`; no typed result envelope reconciles them. See `ai-agent-skills/data-twingler/SKILL.md`.
- The server-side vector example selects `?type` and `?termName` but groups only by `?similarity ?term`, and the fallback process depends on endpoint-specific `bif:`/`sql:`/`vvec:` extensions. Port the decision structure, not these queries verbatim. See `ai-agent-skills/data-twingler/SKILL.md`.

### dbpedia-query-skill

- **What it actually does:** decomposes a natural-language question into subject, predicate, filters, sort, and limit; maps a small English phrase dictionary to DBpedia properties; emits SPARQL against a fixed endpoint; then asks for JSON, Markdown, or HTML output. See `ai-agent-skills/dbpedia-query-skill/SKILL.md`.
- “Report Harness Mode” is the most reusable part: it fixes the semantic source, requires SPARQL before execution, checks query shape, retains endpoint/query/route/timestamp/count/fallback provenance, preserves result IRIs, validates report links, and fails closed on unreliable results. See `ai-agent-skills/dbpedia-query-skill/SKILL.md`.
- **Notable files worth a human read:** `ai-agent-skills/dbpedia-query-skill/SKILL.md` for the harness contract; `ai-agent-skills/dbpedia-query-skill/examples/sample-queries.md` for the actual prompt-to-query corpus; `ai-agent-skills/dbpedia-query-skill/references/protocol-routing.md` for transport switching; `ai-agent-skills/dbpedia-query-skill/templates/html-template.html` and `ai-agent-skills/dbpedia-query-skill/christopher_nolan_films.html` for contract-versus-artifact comparison.
- **Standout mechanism — provenance minimum:** endpoint, exact query, route, timestamp, result count, and fallback route form a compact query-run record suitable for an Effect Schema `QueryEvidence` model. See `ai-agent-skills/dbpedia-query-skill/SKILL.md`.
- **Standout mechanism — protocol preference preservation:** an explicitly requested transport is not silently replaced; absent a preference, failures fall through a declared order and must be reported. See `ai-agent-skills/dbpedia-query-skill/SKILL.md` and `ai-agent-skills/dbpedia-query-skill/references/protocol-routing.md`.
- **Weaknesses / smells:** routing has already drifted. `SKILL.md` puts Virtuoso SPASQL first, while the routing reference and examples put direct DBpedia `curl` first. See `ai-agent-skills/dbpedia-query-skill/SKILL.md`, `ai-agent-skills/dbpedia-query-skill/references/protocol-routing.md`, and `ai-agent-skills/dbpedia-query-skill/examples/sample-queries.md`.
- The property mapper is a tiny prose lookup with no endpoint-driven ontology/property discovery, ID-resolution stage, or executable query validation. “Text search” is explicitly out of scope. See `ai-agent-skills/dbpedia-query-skill/SKILL.md`.
- The sample corpus is not trustworthy as a validation oracle: the Nobel example binds `?award dbo:year ?year` without connecting `?award` to the person, and several examples omit the default `LIMIT 100` required by the main skill. See `ai-agent-skills/dbpedia-query-skill/examples/sample-queries.md` and `ai-agent-skills/dbpedia-query-skill/SKILL.md`.
- The bundled HTML template hardcodes colors, lacks `rel="noopener noreferrer"`, and uses direct DBpedia links, despite the current skill requiring CSS variables, resolver links, and safe new-tab anchors. The generated Nolan sample likewise lacks the required execution timestamp/route provenance. See `ai-agent-skills/dbpedia-query-skill/templates/html-template.html`, `ai-agent-skills/dbpedia-query-skill/christopher_nolan_films.html`, and `ai-agent-skills/dbpedia-query-skill/SKILL.md`.
- `SKILL.md` advertises `scripts/index.js` and corpus-index templates that are not shipped in the assigned directory, so its index-page workflow is not executable from this skill package. See `ai-agent-skills/dbpedia-query-skill/SKILL.md`.

### s3-query-skill

- **What it actually does:** classifies a task as in-place data query versus object operation, detects available clients, selects DuckDB/AWS CLI/boto3/rclone, resolves an endpoint profile, then substitutes a T1-T7 command or SQL template. See `ai-agent-skills/s3-query-skill/SKILL.md` and `ai-agent-skills/s3-query-skill/references/query-templates.md`.
- Endpoint selection is data-driven: profiles capture auth mode, region, endpoint URL, path versus virtual-host addressing, checksum behavior, listing API version, and known gateway limitations. See `ai-agent-skills/s3-query-skill/references/endpoint-profiles.md`.
- Common Crawl recovery is unusually concrete: first cheap-probe anonymous S3, then use HTTPS range requests when S3 returns 403, discover exact Parquet keys through `*.paths.gz` manifests, and pass explicit URL lists because HTTPS cannot expand an S3 glob. See `ai-agent-skills/s3-query-skill/SKILL.md` and `ai-agent-skills/s3-query-skill/examples/common-crawl-aws-columnar-index.md`.
- **Notable files worth a human read:** `ai-agent-skills/s3-query-skill/references/endpoint-profiles.md` for capability profiles; `ai-agent-skills/s3-query-skill/references/query-templates.md` for operation contracts; `ai-agent-skills/s3-query-skill/scripts/duckdb-s3-query.sh` and `ai-agent-skills/s3-query-skill/scripts/s3-list.sh` for the thin executable layer; `ai-agent-skills/s3-query-skill/examples/common-crawl-aws-columnar-index.md` and `ai-agent-skills/s3-query-skill/examples/common-crawl-hf-storage-bucket.md` for recovery recipes.
- **Standout mechanism — capability discovery before planning:** Step 0 inventories clients; Step 1 distinguishes anonymous/profile/key auth and endpoint semantics; a cheap `head-object` validates claimed public access before composing the expensive query. See `ai-agent-skills/s3-query-skill/SKILL.md`.
- **Standout mechanism — path-level query budgeting:** templates teach projection, predicate pushdown, Hive partition pruning, and range-read execution instead of downloading entire objects. See `ai-agent-skills/s3-query-skill/references/query-templates.md` and `ai-agent-skills/s3-query-skill/examples/common-crawl-aws-columnar-index.md`.
- **Standout mechanism — operational symptom table:** DNS failure maps to addressing style, checksum errors to client settings, V1 listing failure to V2, and over-scanning to partitioned paths. See `ai-agent-skills/s3-query-skill/SKILL.md`.
- **Weaknesses / smells:** the DuckDB wrapper accepts keys/secrets as command-line arguments and interpolates them, endpoint, region, and arbitrary SQL into one CLI string. This exposes secrets to process inspection and permits quote-breaking/injection; it should accept a named secret/profile or protected environment reference and parameterize configuration. See `ai-agent-skills/s3-query-skill/scripts/duckdb-s3-query.sh`.
- The query path has no schema inspection (`DESCRIBE`), dry run, row/byte budget, `EXPLAIN`, output codec contract, or structured error parsing before arbitrary user SQL. See `ai-agent-skills/s3-query-skill/SKILL.md` and `ai-agent-skills/s3-query-skill/scripts/duckdb-s3-query.sh`.
- T7 includes destructive `rclone sync` beside `copy`, with only an inline comment that it deletes destination extras; there is no separate confirmation gate or dry-run requirement. See `ai-agent-skills/s3-query-skill/references/query-templates.md`.
- The dated “verified live” endpoint observations are valuable provenance but are snapshots, not capability negotiation; callers must rerun the documented probe. See `ai-agent-skills/s3-query-skill/SKILL.md` and `ai-agent-skills/s3-query-skill/examples/common-crawl-aws-columnar-index.md`.

### linked-data-skills

- **What it actually does:** runs one of two explicit state machines: a five-gate relational-to-RDF-View deployment or a four-step document-to-RDF generation/review/save flow. The RDBMS path separates table discovery, host/protocol resolution, IRI approval, artifact generation, mutation, audit, and live verification. See `ai-agent-skills/linked-data-skills/SKILL.md`.
- The tool inventory classifies operations by effect: read query, discovery, pure generation, write, audit, and last-resort LLM. `EXECUTE_SQL_SCRIPT` is prohibited for reads, while generated scripts are retained for later execution. See `ai-agent-skills/linked-data-skills/SKILL.md` and `ai-agent-skills/linked-data-skills/references/workflow-details.md`.
- **Notable files worth a human read:** `ai-agent-skills/linked-data-skills/SKILL.md` for the gating language; `ai-agent-skills/linked-data-skills/references/workflow-details.md` for generation/deployment contracts and rollback; `ai-agent-skills/linked-data-skills/references/document-to-knowledge-graph-prompt.md` for document modeling constraints; `ai-agent-skills/linked-data-skills/references/protocol-routing.md` for instance/auth routing.
- **Standout mechanism — authorization as state transition:** table selection is explicitly not authorization to generate; concrete host/protocol must exist before any IRI; generation requires a separate CONFIRM/OVERRIDE response; writes occur only after generated artifacts are reviewed. See `ai-agent-skills/linked-data-skills/SKILL.md`.
- **Standout mechanism — generated output is authoritative:** expected IRI templates are shown for approval, but actual graph and ontology IRIs are parsed back out of generated scripts and used for load/verification. This prevents a plan-time template from masquerading as deployed identity. See `ai-agent-skills/linked-data-skills/references/workflow-details.md`.
- **Standout mechanism — script integrity gate:** before execution, reject unresolved placeholders, empty arguments, and incomplete rewrite calls; preserve Virtuoso’s `^{URIQADefaultHost}^` macro; execute exact generated artifacts; audit errors; offer repair/rollback/abort. See `ai-agent-skills/linked-data-skills/references/workflow-details.md`.
- **Standout mechanism — evidence-derived compliance:** final entity samples and counts must come from a live query, every IRI is linked, and dereference failure is a compliance finding rather than a fabricated success. See `ai-agent-skills/linked-data-skills/SKILL.md` and `ai-agent-skills/linked-data-skills/references/workflow-details.md`.
- **Weaknesses / smells:** `README.md` claims version 1.0.0 and a non-existent `SKILLS.md`, while `SKILL.md` is version 3.2.0. See `ai-agent-skills/linked-data-skills/README.md` and `ai-agent-skills/linked-data-skills/SKILL.md`.
- The main file says to present all three generated artifacts, while the workflow reference says never display full scripts unless requested. See `ai-agent-skills/linked-data-skills/SKILL.md` and `ai-agent-skills/linked-data-skills/references/workflow-details.md`.
- The physical-sync call is shown as `RDFVIEW_SYNC_TO_PHYSICAL_STORE({})`, but the support-agent tool contract requires source graph, target graph, and optional `load_data`. See `ai-agent-skills/linked-data-skills/references/workflow-details.md` and `ai-agent-skills/virtuoso-support-agent/references/tool-reference.md`.
- Final verification differs across its own files: the main query counts all types and describes a hardcoded host substitution, while the workflow reference filters types to the extracted TBox namespace and builds from resolved protocol/host. See `ai-agent-skills/linked-data-skills/SKILL.md` and `ai-agent-skills/linked-data-skills/references/workflow-details.md`.
- Path D says syntax is checked and fixed but delegates generation to `chatPromptComplete` and ships no RDF parser/SHACL/JSON Schema validator. Its useful review gate is therefore not mechanically enforced. See `ai-agent-skills/linked-data-skills/SKILL.md` and `ai-agent-skills/linked-data-skills/references/document-to-knowledge-graph-prompt.md`.

### virtuoso-rdf-loader

- **What it actually does:** collects connection/graph/server-directory/pattern/mode, registers matching files with `ld_dir`, starts the asynchronous loader, polls `DB.DBA.LOAD_LIST`, and verifies the target graph with count/sample queries. See `ai-agent-skills/virtuoso-rdf-loader/SKILL.md` and `ai-agent-skills/virtuoso-rdf-loader/references/ldir-parameters.md`.
- The format matrix distinguishes triple-only from quad-bearing formats, documents compressed extensions, and explains server-side path requirements and loader states. See `ai-agent-skills/virtuoso-rdf-loader/references/ldir-parameters.md`.
- **Notable files worth a human read:** `ai-agent-skills/virtuoso-rdf-loader/SKILL.md` for the intended state machine; `ai-agent-skills/virtuoso-rdf-loader/references/ldir-parameters.md` for format/load contracts; `ai-agent-skills/virtuoso-rdf-loader/scripts/bulk-load-rdf.sh` for the implementation gap.
- **Standout mechanism — durable job-table polling:** registration and asynchronous execution are separated, and each file has pending/loading/done/failed state plus timestamps, row count, and error text. This maps naturally to a typed ingestion job model. See `ai-agent-skills/virtuoso-rdf-loader/SKILL.md` and `ai-agent-skills/virtuoso-rdf-loader/references/ldir-parameters.md`.
- **Standout mechanism — post-load proof:** the intended workflow requires waiting for every file to finish, surfacing `ll_error`, counting triples in the target graph, and sampling triples. See `ai-agent-skills/virtuoso-rdf-loader/SKILL.md`.
- **Weaknesses / smells:** the wrapper does not implement the documented `--mode` flag, clear/replace behavior, graph-count verification, per-file row reporting, or directory-wide no-archive mode. See `ai-agent-skills/virtuoso-rdf-loader/SKILL.md` and `ai-agent-skills/virtuoso-rdf-loader/scripts/bulk-load-rdf.sh`.
- It defaults to `dba/dba`, accepts the password on the command line, and builds a single unquoted `ISQL` command string; credentials are visible to process inspection and whitespace/metacharacters can break invocation. See `ai-agent-skills/virtuoso-rdf-loader/scripts/bulk-load-rdf.sh` and `ai-agent-skills/virtuoso-rdf-loader/README.md`.
- Its monitor query is global rather than scoped to this registration, and `grep -qi 'error'` can match the selected `ll_error` column heading. It can therefore stop because of unrelated jobs or the mere presence of the column name. See `ai-agent-skills/virtuoso-rdf-loader/scripts/bulk-load-rdf.sh`.
- When no stage directory is supplied, the script creates a client-local `/tmp` directory even though the docs correctly state `ld_dir` needs a path on the Virtuoso server; this works only when client and server share that filesystem. See `ai-agent-skills/virtuoso-rdf-loader/SKILL.md` and `ai-agent-skills/virtuoso-rdf-loader/scripts/bulk-load-rdf.sh`.
- The quad-format section first describes the `ld_dir` graph as a default, then says the loader will override embedded graph assignments; the behavior is internally contradictory and should be tested against the target Virtuoso version. See `ai-agent-skills/virtuoso-rdf-loader/references/ldir-parameters.md`.

## Cross-cutting patterns in this lane

- The reusable “query skill” shape is not a pile of sample queries. It is: intent classification → endpoint/capability resolution → concrete query compilation → structural preflight → transport selection → execution → result decoding → provenance → bounded recovery. `data-twingler` approximates the whole chain; DBpedia/Wikidata mostly cover compilation/presentation; S3 is strongest on capability resolution; `linked-data-skills` is strongest on mutation authorization. See `ai-agent-skills/data-twingler/SKILL.md`, `ai-agent-skills/s3-query-skill/SKILL.md`, and `ai-agent-skills/linked-data-skills/SKILL.md`.
- Query text should remain transport-invariant where possible, and transport selection should be a separate policy. DBpedia/Wikidata state this explicitly, while Data Twingler formalizes backend argument binding. See `ai-agent-skills/dbpedia-query-skill/examples/sample-queries.md`, `ai-agent-skills/wikidata-query-skill/examples/sample-queries.md`, and `ai-agent-skills/data-twingler/references/protocol-routing.md`.
- Endpoint discovery appears at four maturity levels: hardcoded URL (DBpedia/Wikidata), brand alias (Data Twingler), explicit endpoint profile plus cheap probe (S3), and user-confirmed instance plus server metadata discovery (Linked Data/Virtuoso). See `ai-agent-skills/dbpedia-query-skill/SKILL.md`, `ai-agent-skills/wikidata-query-skill/SKILL.md`, `ai-agent-skills/data-twingler/SKILL.md`, `ai-agent-skills/s3-query-skill/references/endpoint-profiles.md`, `ai-agent-skills/linked-data-skills/SKILL.md`, and `ai-agent-skills/virtuoso-support-agent/SKILL.md`.
- The best recovery flows are typed and bounded: auth status → OAuth after one retry, zero discovery results → at most three variants then two endpoints, SR324 → one reduced query, S3 403 → HTTPS manifest path. The generic support guide is weaker because many symptom lists do not define stop conditions. See `ai-agent-skills/data-twingler/SKILL.md`, `ai-agent-skills/linked-data-skills/references/workflow-details.md`, `ai-agent-skills/s3-query-skill/SKILL.md`, and `ai-agent-skills/virtuoso-support-agent/references/troubleshooting.md`.
- Human checkpoints are used for two distinct reasons and should stay distinct: semantic disambiguation (choose an entity/question) and mutation authorization (approve IRIs/scripts/destructive mode). See `ai-agent-skills/data-twingler/SKILL.md` and `ai-agent-skills/linked-data-skills/SKILL.md`.
- Result formats are strings, not contracts. JSON/JSONL/Markdown/HTML are named repeatedly, but none of the skills defines a normalized binding value, column schema, partial/truncated result marker, warnings array, or decoder error. See `ai-agent-skills/data-twingler/SKILL.md`, `ai-agent-skills/virtuoso-support-agent/references/tool-reference.md`, and the DBpedia/Wikidata `SKILL.md` files.
- Provenance is uneven. DBpedia/Wikidata define a strong run envelope; S3 preserves dated endpoint observations; the loader tracks per-file lifecycle; the support showcase substitutes narrative claims for evidence. See `ai-agent-skills/dbpedia-query-skill/SKILL.md`, `ai-agent-skills/wikidata-query-skill/SKILL.md`, `ai-agent-skills/s3-query-skill/examples/common-crawl-aws-columnar-index.md`, `ai-agent-skills/virtuoso-rdf-loader/references/ldir-parameters.md`, and `ai-agent-skills/virtuoso-support-agent/references/showcase-examples.md`.
- Validation is mainly aspirational prose. The only bundled executables are thin shell wrappers, and even the clean SPARQL syntax checklist is not machine-run. See `ai-agent-skills/data-twingler/references/sparql-syntax-rules.md`, `ai-agent-skills/s3-query-skill/scripts/duckdb-s3-query.sh`, `ai-agent-skills/s3-query-skill/scripts/s3-list.sh`, and `ai-agent-skills/virtuoso-rdf-loader/scripts/bulk-load-rdf.sh`.
- Cross-file drift is the dominant quality failure: routing order, version number, workflow step count, required tool parameters, generated report rules, and “required” deployment artifacts disagree inside packages. See `ai-agent-skills/linked-data-skills/README.md`, `ai-agent-skills/virtuoso-support-agent/CHANGELOG.md`, `ai-agent-skills/virtuoso-support-agent/references/workflow-details.md`, and the DBpedia/Wikidata routing and HTML files.

## Steal-worthy for beep-effect (ranked, concrete — name the mechanism and the port)

1. **Typed query-plan state machine.** Port Data Twingler’s stages into Effect Schema tagged variants such as `IntentResolved`, `EndpointResolved`, `QueryCompiled`, `Validated`, `AwaitingSelection`, `Executing`, `Recovered`, and `Completed`; make illegal skips unrepresentable. Source mechanism: `ai-agent-skills/data-twingler/SKILL.md`.
2. **Effect-separated capability services.** Define `EndpointRegistry`, `CapabilityProbe`, `QueryCompiler`, `QueryValidator`, `QueryExecutor`, and `ResultDecoder` as `Context.Service`s; keep network/file/database effects out of the pure compiler. Source separation: `ai-agent-skills/s3-query-skill/references/endpoint-profiles.md` and `ai-agent-skills/linked-data-skills/SKILL.md`.
3. **Executable SPARQL structural gate.** Turn UNION/SERVICE/bif/FILTER/GRAPH checks into parser-backed diagnostics with typed `QueryValidationError`s, then run them on every template fixture in CI. Source rules: `ai-agent-skills/data-twingler/references/sparql-syntax-rules.md`.
4. **Structured backend-argument preflight.** Model each tool call as a discriminated Schema—remote SPARQL requires `url + query`, local SPARQL requires `query + format`, SPASQL/SQL requires `sql`—and reject natural-language placeholders before invocation. Source contract: `ai-agent-skills/data-twingler/references/protocol-routing.md`.
5. **Endpoint profile plus live capability probe.** Store stable configuration separately from observed capabilities; record probe time, auth mode, accepted formats, SERVICE support, timeout/limit, listing version, and range-read support. Source mechanism: `ai-agent-skills/s3-query-skill/references/endpoint-profiles.md` and `ai-agent-skills/s3-query-skill/SKILL.md`.
6. **Typed, bounded recovery algebra.** Map `AuthRequired`, `Timeout`, `NoResults`, `SyntaxRejected`, `CapabilityMissing`, and `TransportFailed` to explicit `Effect.catchTag` branches and bounded `Schedule`s; retain every attempted query/endpoint rather than recursively “try something else.” Source playbooks: `ai-agent-skills/data-twingler/SKILL.md`, `ai-agent-skills/s3-query-skill/SKILL.md`, and `ai-agent-skills/virtuoso-support-agent/references/protocol-routing.md`.
7. **PROV-style query evidence envelope.** Persist endpoint, exact query digest/text reference, compiler/template version, transport, start/end time, result count, truncation, fallback chain, source graph/object, and agent/tool identity. Source minimum: `ai-agent-skills/dbpedia-query-skill/SKILL.md`, `ai-agent-skills/wikidata-query-skill/SKILL.md`, and loader lifecycle fields in `ai-agent-skills/virtuoso-rdf-loader/references/ldir-parameters.md`.
8. **Separate semantic confirmation from write authorization.** Use different domain events and UI prompts for `EntitySelected` versus `MutationApproved`; bind approval to a digest of the exact IRI plan or generated script. Source gates: `ai-agent-skills/data-twingler/SKILL.md` and `ai-agent-skills/linked-data-skills/SKILL.md`.
9. **Result-format negotiation as codecs.** Replace format strings with a `ResultMediaType` Schema and decoders for SPARQL JSON bindings, tabular Markdown, JSONL streams, HTML fragments, and DuckDB rows; carry datatype/language/IRI identity through rendering. Source gap: `ai-agent-skills/virtuoso-support-agent/references/tool-reference.md`, `ai-agent-skills/dbpedia-query-skill/SKILL.md`, and `ai-agent-skills/wikidata-query-skill/SKILL.md`.
10. **Generated-artifact integrity contract.** Retain exact generated text, compute a digest, parse authoritative IRIs back out, reject unresolved placeholders/empty arguments, and execute only the approved digest. Source mechanism: `ai-agent-skills/linked-data-skills/references/workflow-details.md`.
11. **Query-cost preflight for remote files.** Add schema discovery, projection/partition checks, byte/row budgets, and optional `EXPLAIN` before DuckDB/S3 execution; encode “range-readable but not listable” as a capability combination. Source mechanism and missing gates: `ai-agent-skills/s3-query-skill/references/query-templates.md` and `ai-agent-skills/s3-query-skill/examples/common-crawl-aws-columnar-index.md`.
12. **Pluggable local-RDF source adapter.** Preserve Data Twingler’s local-first candidate contract (`text`, entity IRI, source, answer link/text, score) behind an adapter that can point at the existing agent-memory/KG stack without coupling query planning to a particular memory directory. Source seam: `ai-agent-skills/data-twingler/SKILL.md`.
