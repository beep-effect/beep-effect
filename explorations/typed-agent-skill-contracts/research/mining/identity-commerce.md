## Per-skill notes

### youid

- What it actually does: `scripts/generate_identity.sh` orchestrates RSA-2048 key and self-signed certificate generation, PKCS#12 export, data extraction, template rendering, static-asset copying, and two blocking consistency gates (`ai-agent-skills/youid/scripts/generate_identity.sh`).
- The private key exists transiently as `key.pem`, is packed with the leaf certificate into `cert.p12`, then is deleted; the resulting bundle is password-protected but defaults to the literal password `youid` when the caller supplies none (`ai-agent-skills/youid/scripts/generate_certificate.sh`).
- The X.509 certificate carries the caller-provided WebID URI as a URI Subject Alternative Name and applies `CA:FALSE`, digital-signature, and key-encipherment extensions (`ai-agent-skills/youid/scripts/generate_certificate.sh`).
- The published identity bundle exposes certificate, public-key, and subject descriptions in Turtle, JSON-LD, RDFa, POSH/HTML, and vCard representations (`ai-agent-skills/youid/SKILL.md`; `ai-agent-skills/youid/templates/profile.ttl.tpl`; `ai-agent-skills/youid/templates/profile.jsonld.tpl`).
- The intended relying-party chain is explicit: complete mTLS, extract the WebID URI from the presented certificate SAN, dereference that URI, parse the published RSA key, and compare it to the certificate key (`ai-agent-skills/youid/README.md`).
- The identity graph shape is concrete: agent `cert:key` public key; agent `oplcert:hasCertificate` certificate; certificate `oplcert:hasPublicKey` the same key; certificate metadata includes SAN, serial, validity, issuer, subject, and fingerprints (`ai-agent-skills/youid/references/identity-ontologies.md`; `ai-agent-skills/youid/templates/profile.ttl.tpl`).
- Certificate fingerprints are projected into SHA-1/SHA-256 strings plus content-addressed `ni:` and `urn:di:` identifiers (`ai-agent-skills/youid/scripts/generate_certificate.sh`; `ai-agent-skills/youid/scripts/compute_fingerprints.sh`).
- The basic WebID gate extracts modulus and exponent back out of `cert.p12` and compares them with `profile.ttl`, `profile.jsonld`, and RDFa in `index.html`; any mismatch exits nonzero (`ai-agent-skills/youid/scripts/generate_identity.sh`).
- The delegation gate extracts `oplcert:hasIdentityDelegate` and `oplcert:onBehalfOf` from four files and multiple embedded representations, then requires set equality across them (`ai-agent-skills/youid/scripts/generate_identity.sh`).
- Delegation is modeled bilaterally: the principal publishes `hasIdentityDelegate`, the agent publishes `onBehalfOf`, and the relying party is expected to corroborate both profiles rather than trust an HTTP header alone (`ai-agent-skills/youid/README.md`; `ai-agent-skills/youid/references/delegation.md`).
- The delegation generator emits a SPARQL update, a Chrome `declarativeNetRequest` rule, and a deployment summary; its role enum is `identify | inform | consult | authority` (`ai-agent-skills/youid/scripts/generate_delegation.sh`).
- The template engine is a small deterministic contract: `%{key}` required substitution, `!{key}` conditional line, and `!!{key}`/`!!.` conditional block, implemented independently in Python and TypeScript (`ai-agent-skills/youid/scripts/template_fill.py`; `ai-agent-skills/youid/scripts/template_fill.ts`).
- The identity-card templates embed JSON-LD, Turtle, and hidden RDFa in the same human-readable credential surface, and use native closed `details` accordions for certificate/key inspection (`ai-agent-skills/youid/templates/index.html.tpl`; `ai-agent-skills/youid/templates/index_premium.html.tpl`; `ai-agent-skills/youid/templates/index_dark.html.tpl`).
- Social identity input is deliberately cross-projected as RDF `owl:sameAs`/`schema:sameAs`, HTML `rel=me`, and icon links (`ai-agent-skills/youid/SKILL.md`; `ai-agent-skills/youid/references/template-variables.md`).
- Upload guidance covers WebDAV, LDP, S3, Azure Blob, and Solid POD, but the executable path is principally curl PUT with Basic authentication and HEAD verification (`ai-agent-skills/youid/references/upload-backends.md`).
- The OPAL widget is not identity transport itself: it wraps either a Solid OIDC client or a simple bearer-auth fetch adapter around WebSocket/chat APIs (`ai-agent-skills/youid/templates/index.html.tpl`; `ai-agent-skills/youid/assets/auth.js`; `ai-agent-skills/youid/assets/opal.js`; `ai-agent-skills/youid/assets/opalx.js`).
- Notable files worth a human read: `ai-agent-skills/youid/README.md` for the cleanest protocol sequence; `ai-agent-skills/youid/scripts/generate_identity.sh` for executable gates; `ai-agent-skills/youid/scripts/generate_certificate.sh` for key custody; `ai-agent-skills/youid/references/delegation.md` for the bilateral relation; `ai-agent-skills/youid/templates/profile.ttl.tpl` for the graph contract.
- Standout mechanism: re-extract the authoritative public key from the deployable PKCS#12 artifact, then compare it against every generated projection instead of trusting intermediate template data (`ai-agent-skills/youid/scripts/generate_identity.sh`).
- Standout mechanism: represent a credential simultaneously as human UI and machine-readable linked data, with the same identity/key facts embedded in JSON-LD, Turtle, RDFa, and linked standalone resources (`ai-agent-skills/youid/templates/index.html.tpl`).
- Standout elicitation: the delegation workflow asks separately for delegator, delegate, role, and each party's local profile directory before mutation (`ai-agent-skills/youid/SKILL.md`).
- Weakness: the user-supplied certificate SAN is `WEBID`, but generated profile key assertions are primarily attached to derived `card_ident_url` and `prof_url#identity`; the gate checks key equality across files, not that the certificate SAN names an RDF subject that actually carries that key (`ai-agent-skills/youid/scripts/generate_certificate.sh`; `ai-agent-skills/youid/scripts/generate_identity.sh`; `ai-agent-skills/youid/templates/profile.ttl.tpl`).

- Weakness: the generated rule has `urlFilter: "*"`, so it sends the delegation header on every XHR rather than only to approved relying parties (`ai-agent-skills/youid/scripts/generate_delegation.sh`).
- Weakness: role is only a string in `schema:description`/`schema:additionalType`; there is no machine-enforceable action/resource scope, expiry, nonce, signature, revocation identifier, or audience restriction (`ai-agent-skills/youid/scripts/generate_delegation.sh`; `ai-agent-skills/youid/references/delegation.md`).
- Weakness: `verify_webid.sh` reads `WEBID`, `CURL_OUT`, and `OUT_DIR` from the Python process environment without exporting the shell variables first, so its parser receives empty paths in ordinary execution (`ai-agent-skills/youid/scripts/verify_webid.sh`).
- Weakness: the verifier's stated SPARQL queries are defined but never executed; actual verification walks triples and reports claims without comparing a presented certificate key to the profile key (`ai-agent-skills/youid/scripts/verify_webid.sh`; `ai-agent-skills/youid/references/verification-queries.md`).
- Weakness: ACME documentation and `acme_helper.sh` describe Let's Encrypt/ZeroSSL modes, but the invoked certificate generator exposes only the positional self-signed path and no documented `--mode` flags (`ai-agent-skills/youid/references/acme-workflows.md`; `ai-agent-skills/youid/scripts/acme_helper.sh`; `ai-agent-skills/youid/scripts/generate_certificate.sh`).
- Weakness: the claimed dark-mode contract requires `[data-theme="dark"]`, localStorage persistence, and no `prefers-color-scheme` rule, but the default and premium templates contain `@media (prefers-color-scheme:dark)` and no theme-toggle implementation (`ai-agent-skills/youid/SKILL.md`; `ai-agent-skills/youid/templates/index.html.tpl`; `ai-agent-skills/youid/templates/index_premium.html.tpl`).
- Weakness: premium/dark OPAL sections target an absent `opal-form` and condition script loading on `use_opal` while displaying the section on `use_opal_widget`; only the default template contains a full chat form (`ai-agent-skills/youid/templates/index_premium.html.tpl`; `ai-agent-skills/youid/templates/index_dark.html.tpl`; `ai-agent-skills/youid/templates/index.html.tpl`).
- Weakness: `cert.p12` is included in the recommended public upload batch beside public profiles and certificates, even though it contains the private key (`ai-agent-skills/youid/references/upload-backends.md`; `ai-agent-skills/youid/scripts/generate_certificate.sh`).

### mtls-curl

- What it actually does: provides two procedural routes around the same PKCS#12 credential—HTTP(S) requests through `curl`, or Virtuoso SQL sessions through its `isql` client (`ai-agent-skills/mtls-curl/SKILL.md`).
- Mode A validates the bundle with `openssl pkcs12`, then presents it through `curl --cert-type P12 --cert file:password`; Mode B adds a CA bundle and asserted WebID via `isql -X ... -T ... -W ...` (`ai-agent-skills/mtls-curl/SKILL.md`).
- Mode B documents the crucial empty-username convention: the SQL username is `""`, leaving authentication to the TLS client certificate and WebID verification path (`ai-agent-skills/mtls-curl/SKILL.md`; `ai-agent-skills/mtls-curl/references/virtuoso-isql-mtls.md`).
- The server-side chain is well articulated: verify certificate chain, dereference the `-W` WebID profile, compare profile key to certificate key, then check the WebID in the VAL ACL graph (`ai-agent-skills/mtls-curl/references/virtuoso-isql-mtls.md`).
- Input resolution has a useful priority contract: explicit values, dedicated environment variables, safe discovery, then interactive masked elicitation (`ai-agent-skills/mtls-curl/SKILL.md`).
- Session reuse intentionally retains only certificate path, CA path, and WebID—not the passphrase (`ai-agent-skills/mtls-curl/SKILL.md`; `ai-agent-skills/mtls-curl/references/virtuoso-isql-mtls.md`).
- Notable files worth a human read: `ai-agent-skills/mtls-curl/references/virtuoso-isql-mtls.md` for the authentication sequence; `ai-agent-skills/mtls-curl/references/pkcs12-openssl-guide.md` for conversion/inspection; `ai-agent-skills/mtls-curl/SKILL.md` for routing and elicitation.
- Standout mechanism: treat the certificate as proof of private-key possession and the dereferenceable WebID as the authorization subject, then independently bind them by public-key equality (`ai-agent-skills/mtls-curl/references/virtuoso-isql-mtls.md`).
- Standout gate: immediately run `SELECT USER;` after iSQL connection and require the returned identity to be the WebID rather than a fallback SQL user (`ai-agent-skills/mtls-curl/references/virtuoso-isql-mtls.md`).
- Weakness: Mode A's canonical command defaults to `-k`, disabling server authentication; the text recommends `--cacert` but makes insecure transport the happy path (`ai-agent-skills/mtls-curl/SKILL.md`; `ai-agent-skills/mtls-curl/references/curl-tls-options.md`).
- Weakness: both curl's `file:password` argument and iSQL's positional passphrase can be process-visible; the skill acknowledges this only for iSQL while claiming the password is never logged or exposed (`ai-agent-skills/mtls-curl/SKILL.md`; `ai-agent-skills/mtls-curl/references/virtuoso-isql-mtls.md`).
- Weakness: there is no executable wrapper, automated redaction test, target allowlist, certificate selection policy, or evidence bundle; the directory contains documentation only (`ai-agent-skills/mtls-curl/SKILL.md`; `ai-agent-skills/mtls-curl/references/curl-tls-options.md`).

### openlink-license-reader

- What it actually does: supplies an embedded Python parser for `openssl asn1parse` output and presentation rules for one license or a directory summary (`ai-agent-skills/openlink-license-reader/SKILL.md`).
- The decoder treats depth-4 consecutive `PRINTABLESTRING` values as key/value pairs and maps fields such as registered subject, product, edition, availability, limits, feature modules, platform, expiry, and host lock (`ai-agent-skills/openlink-license-reader/SKILL.md`; `ai-agent-skills/openlink-license-reader/references/asn1-field-map.md`).
- Entitlement status is a three-state projection: missing expiry is PERPETUAL, future expiry is ACTIVE with days remaining, and past expiry is EXPIRED; directory output is sorted expired-first (`ai-agent-skills/openlink-license-reader/SKILL.md`).
- Notable files worth a human read: `ai-agent-skills/openlink-license-reader/references/asn1-field-map.md` for the entitlement vocabulary and `ai-agent-skills/openlink-license-reader/SKILL.md` for parsing/status logic.
- Standout mechanism: translate a vendor binary license into an agent-readable normalized entitlement record while retaining the source-field names and decode tables (`ai-agent-skills/openlink-license-reader/references/asn1-field-map.md`).
- Standout policy: raw ASN.1 and hex dumps are withheld unless explicitly requested, reducing accidental disclosure/noise (`ai-agent-skills/openlink-license-reader/SKILL.md`; `ai-agent-skills/openlink-license-reader/references/openssl-asn1parse-guide.md`).
- Weakness: it parses but never verifies the RSA signature or payload hash; a structurally parseable license is therefore presented as an entitlement without authenticity proof (`ai-agent-skills/openlink-license-reader/references/asn1-field-map.md`; `ai-agent-skills/openlink-license-reader/SKILL.md`).
- Weakness: the parser is only a code block in the skill, with no checked-in executable, fixtures, malformed-input tests, or stable JSON output contract (`ai-agent-skills/openlink-license-reader/SKILL.md`; `ai-agent-skills/openlink-license-reader/README.md`).
- Weakness: unknown fields are not surfaced through a typed extension mechanism, and the date parser returns raw text on any failure rather than a typed parse error (`ai-agent-skills/openlink-license-reader/SKILL.md`).
- Weakness: nothing binds `RegisteredTo` to the active WebID/mTLS subject or binds decoded limits to a runtime authorization decision (`ai-agent-skills/openlink-license-reader/references/asn1-field-map.md`; `ai-agent-skills/mtls-curl/references/virtuoso-isql-mtls.md`).

### resource-access-offers-generator

- What it actually does: describes an RDF bundle for product, product license, offer, price specification, duration, and offer-group membership, specialized for file, graph, or API access (`ai-agent-skills/resource-access-offers-generator/SKILL.md`; `ai-agent-skills/resource-access-offers-generator/references/offer-shapes-reference.md`).
- File and graph variants require exactly one protected-resource IRI through `opllic:uriParameter` or `opllic:graphParameter`; API licenses forbid both (`ai-agent-skills/resource-access-offers-generator/shacl/file-access-offer-shape.ttl`; `ai-agent-skills/resource-access-offers-generator/shacl/graph-access-offer-shape.ttl`; `ai-agent-skills/resource-access-offers-generator/shacl/api-access-offer-shape.ttl`).
- Common SHACL requires document provenance timestamps/author, decimal currency prices with validity windows, duration, offer number, business function, and offer-to-price/item links (`ai-agent-skills/resource-access-offers-generator/shacl/common-offer-shape.ttl`).
- The validator parses Turtle, merges common plus type-specific shapes, runs pySHACL with RDFS inference, and exits nonzero on nonconformance (`ai-agent-skills/resource-access-offers-generator/scripts/validate-offers-shacl.py`).
- Loading is deliberately separated from generation: validated RDF is loaded into a named shop/cache graph using a no-sponge SPARQL `LOAD` command (`ai-agent-skills/resource-access-offers-generator/references/loading-instructions.md`).
- Notable files worth a human read: `ai-agent-skills/resource-access-offers-generator/shacl/common-offer-shape.ttl` for the shared contract; the three type shapes under `ai-agent-skills/resource-access-offers-generator/shacl/`; and `ai-agent-skills/resource-access-offers-generator/scripts/validate-offers-shacl.py` for the gate.
- Standout mechanism: use a shared shape plus product-specific shapes so commerce invariants and access-mode invariants can evolve independently (`ai-agent-skills/resource-access-offers-generator/scripts/validate-offers-shacl.py`; `ai-agent-skills/resource-access-offers-generator/shacl/common-offer-shape.ttl`).
- Standout mechanism: model the protected file/graph as an IRI-valued license parameter, creating a direct machine-readable join between resource and purchasable authorization (`ai-agent-skills/resource-access-offers-generator/shacl/file-access-offer-shape.ttl`; `ai-agent-skills/resource-access-offers-generator/shacl/graph-access-offer-shape.ttl`).
- Weakness: all three generation prompts are zero-byte files, so the workflow's “load prompt, substitute placeholders, generate Turtle” step has no implementation (`ai-agent-skills/resource-access-offers-generator/prompts/file-access-offer-prompt.md`; `ai-agent-skills/resource-access-offers-generator/prompts/graph-access-offer-prompt.md`; `ai-agent-skills/resource-access-offers-generator/prompts/api-access-offer-prompt.md`; `ai-agent-skills/resource-access-offers-generator/SKILL.md`).
- Weakness: violation counting sums result rows from a `COUNT` query, producing one rather than the count value; conforming output can be reported as “PASS - 1 violations,” and auto-detection tie-breaking is unreliable (`ai-agent-skills/resource-access-offers-generator/scripts/validate-offers-shacl.py`).
- Weakness: the API shape targets every `opllic:ProductLicense` and requires a duration despite being named “paid,” with no target condition that distinguishes paid from free tiers (`ai-agent-skills/resource-access-offers-generator/shacl/api-access-offer-shape.ttl`).
- Weakness: the shapes omit seller/payee identity, offer signature, accepted payment rail, challenge endpoint, refund semantics, entitlement issuance, receipt linkage, and PROV-O activity/agent associations (`ai-agent-skills/resource-access-offers-generator/shacl/common-offer-shape.ttl`; `ai-agent-skills/resource-access-offers-generator/shacl/api-access-offer-shape.ttl`).
- Weakness: API tier prices are documented as fixed prose but not constrained by SHACL, and there are no example offer fixtures or validator tests (`ai-agent-skills/resource-access-offers-generator/references/offer-shapes-reference.md`; `ai-agent-skills/resource-access-offers-generator/shacl/api-access-offer-shape.ttl`).

### set-webdav-resource-property

- What it actually does: reads resource paths, derives friendly titles from filenames, XML-escapes them, builds namespace-qualified WebDAV `PROPPATCH` XML, and sends each request through curl (`ai-agent-skills/set-webdav-resource-property/scripts/set-webdav-resource-property.sh`).
- Namespace resolution supports built-in `schema` and `dc` prefixes plus a caller-supplied namespace IRI; the namespace is placed on the root element (`ai-agent-skills/set-webdav-resource-property/SKILL.md`; `ai-agent-skills/set-webdav-resource-property/scripts/set-webdav-resource-property.sh`).
- Filename policy strips the extension, decodes `%20`, replaces underscores/hyphens, title-cases words, and appends media-type tags for common extensions (`ai-agent-skills/set-webdav-resource-property/SKILL.md`; `ai-agent-skills/set-webdav-resource-property/scripts/set-webdav-resource-property.sh`).
- Notable files worth a human read: `ai-agent-skills/set-webdav-resource-property/scripts/set-webdav-resource-property.sh` for actual request construction and `ai-agent-skills/set-webdav-resource-property/SKILL.md` for the intended verification/error model.
- Standout mechanism: metadata writes are namespace-aware and values are XML-escaped before interpolation (`ai-agent-skills/set-webdav-resource-property/scripts/set-webdav-resource-property.sh`).
- Weakness: the script has no explicit property-value option; it always computes a title, despite the skill claiming arbitrary custom properties and values (`ai-agent-skills/set-webdav-resource-property/SKILL.md`; `ai-agent-skills/set-webdav-resource-property/scripts/set-webdav-resource-property.sh`).
- Weakness: an unprefixed property becomes `<:localName>`, invalid XML, because `PROP_OPEN` always includes a colon (`ai-agent-skills/set-webdav-resource-property/scripts/set-webdav-resource-property.sh`).
- Weakness: unknown prefixes are allowed to proceed without an `xmlns` declaration, guaranteeing invalid/unbound QName behavior on compliant servers (`ai-agent-skills/set-webdav-resource-property/scripts/set-webdav-resource-property.sh`).
- Weakness: credentials can be supplied through `-p` and are placed in curl's `-u user:password` process arguments; there is no secret-reference or netrc/config-file path (`ai-agent-skills/set-webdav-resource-property/scripts/set-webdav-resource-property.sh`).
- Weakness: it prints HTTP codes but does not require 207/success, parse per-property Multi-Status, or perform the documented `PROPFIND` read-after-write check (`ai-agent-skills/set-webdav-resource-property/SKILL.md`; `ai-agent-skills/set-webdav-resource-property/scripts/set-webdav-resource-property.sh`).

### mpp-stripe-client

- What it actually does: launches a separately installed TypeScript project against a caller-provided URL and describes a two-request HTTP payment flow (`ai-agent-skills/mpp-stripe-client/SKILL.md`).
- The intended sequence is GET → 402 challenge → Stripe test payment method → challenge-scoped Shared Payment Token → retry with `Authorization: Payment ...` → 200 resource plus `Authentication-Info` receipt (`ai-agent-skills/mpp-stripe-client/SKILL.md`).
- It intentionally bypasses `npm run cli` because that project's dotenv behavior overwrites inline target configuration with localhost defaults (`ai-agent-skills/mpp-stripe-client/SKILL.md`).
- Notable file worth a human read: only `ai-agent-skills/mpp-stripe-client/SKILL.md`; no client source, protocol schema, fixture, or test is present in the assigned directory.
- Standout mechanism: treat HTTP 402 as a typed challenge/response handshake and scope the payment credential to the challenged amount before retrying (`ai-agent-skills/mpp-stripe-client/SKILL.md`).
- Standout evidence: return both the paid representation and the `Authentication-Info` receipt header, preserving protocol proof separately from the resource body (`ai-agent-skills/mpp-stripe-client/SKILL.md`).
- Weakness: the skill depends on an external hard-coded project path, so none of its challenge parsing, SPT construction, amount scoping, or receipt verification is auditable here (`ai-agent-skills/mpp-stripe-client/SKILL.md`).
- Weakness: it asks for a raw Stripe secret and interpolates it directly into a shell command/environment assignment, with no protected prompt, secret reference, redaction rule, or subprocess-leak analysis (`ai-agent-skills/mpp-stripe-client/SKILL.md`).
- Weakness: there is no spend ceiling, currency/payee display, user approval after parsing the challenge, live-key rejection, idempotency key, replay defense, timeout, or receipt-verification gate (`ai-agent-skills/mpp-stripe-client/SKILL.md`).
- Weakness: no field links payment to the agent's WebID, a specific RDF offer IRI, the protected resource license, or an issued entitlement (`ai-agent-skills/mpp-stripe-client/SKILL.md`; `ai-agent-skills/resource-access-offers-generator/shacl/common-offer-shape.ttl`).

## Cross-cutting patterns in this lane

- Credential chain: generate key/certificate/PKCS#12 → publish dereferenceable WebID profile → present PKCS#12 over mTLS → extract SAN → fetch profile → compare keys → authorize the WebID subject (`ai-agent-skills/youid/scripts/generate_certificate.sh`; `ai-agent-skills/youid/README.md`; `ai-agent-skills/mtls-curl/references/virtuoso-isql-mtls.md`).
- Delegated-agent chain: agent authenticates with its own certificate, declares a principal in `On-Behalf-Of`, then the relying party checks inverse statements published under both parties' control (`ai-agent-skills/youid/README.md`; `ai-agent-skills/youid/references/delegation.md`).
- The repo repeatedly favors deterministic local tools after LLM elicitation: shell generates credential artifacts, OpenSSL parses licenses, Bash constructs XML, and pySHACL gates offers (`ai-agent-skills/youid/SKILL.md`; `ai-agent-skills/openlink-license-reader/SKILL.md`; `ai-agent-skills/set-webdav-resource-property/scripts/set-webdav-resource-property.sh`; `ai-agent-skills/resource-access-offers-generator/scripts/validate-offers-shacl.py`).
