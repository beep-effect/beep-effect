# Round 1 Seat A — CQ answerability

## Findings

- [WARN] CQ-002 — The query is global, so it cannot answer for a given episode unless an unstated caller binding convention supplies `?episode`; it also drops the episode and tier from the result. — evidence: `ontology/docs/competency-questions.yaml`, CQ-002: `natural_language: "Which WorkUnits (lane x scope) are admissible for a given episode's diff and target tier?"`; `ontology/tests/cq-002.sparql`, CQ-002: `SELECT ?workUnit WHERE {` and `ciops:admissibleFor ?episode`.
- [BLOCKER] CQ-004 — The query covers only transitive dependents, not the touched package itself or any hash-surface path, and it is unscoped to the given change set. — evidence: `ontology/docs/competency-questions.yaml`, CQ-004: `natural_language: "Which packages are affected by a given change set, via dependency closure and hash surfaces?"`; `ontology/tests/cq-004.sparql`, CQ-004: `?change ciops:touchesPackage ?touched .` and `?pkg ciops:dependsOnTransitive ?touched .`.
- [WARN] CQ-005 — The tree and epoch are unbound and unprojected, so the query returns proofs across every tree/epoch rather than answering for the given pair. — evidence: `ontology/docs/competency-questions.yaml`, CQ-005: `natural_language: "Which proofs remain valid for a given tree state and cache epoch?"`; `ontology/tests/cq-005.sparql`, CQ-005: `SELECT ?proof WHERE {` and `?proof ciops:validInEpoch ?epoch ;`.
- [BLOCKER] CQ-006 — The query never binds or returns the held tier, branch, or head, and its negation is correlated only by lane: any proof on any tree/epoch can suppress a target obligation. The sample's `held` value is therefore unbindable. — evidence: `ontology/docs/competency-questions.yaml`, CQ-006: `natural_language: "What certainty tier does a branch hold at a given head, and what obligations remain to reach a target tier?"` and `held: ciops:TierRepairGreen`; `ontology/tests/cq-006.sparql`, CQ-006: `SELECT ?lane WHERE {`, `?proof ciops:dischargesObligation ?lane ;`, `ciops:provesTree ?tree ;`, and `ciops:validInEpoch ?epoch .`.
- [BLOCKER] CQ-007 — Queue wait is part of the natural-language decomposition but has no selected variable or graph pattern. — evidence: `ontology/docs/competency-questions.yaml`, CQ-007: `decomposition into queue wait, lock wait, execution, repair gap, and CI wait`; `ontology/tests/cq-007.sparql`, CQ-007: `SELECT ?ep ?total ?lock ?exec ?repair ?ci WHERE {`.
- [WARN] CQ-007 — `aggregation` silently relies on already materialized duration totals: the query performs only direct lookup and has no computed-externally note. — evidence: `ontology/docs/competency-questions.yaml`, CQ-007: `derivation_method: aggregation`; `ontology/tests/cq-007.sparql`, CQ-007: `?ep ciops:timeToCertaintyMs ?total ;`.
- [WARN] CQ-008 — The query does not restrict grant state to holding/waiting, so it also returns released grants even though the glossary lists `ReleasedGrant`. The sample can consequently label a non-holder as `holder`. — evidence: `ontology/docs/competency-questions.yaml`, CQ-008: `which active grants currently hold or wait on each?`; `ontology/tests/cq-008.sparql`, CQ-008: `?grant ciops:contendsFor ?res ; ciops:hasGrantState ?state .`; `ontology/docs/pre-glossary.csv`, CQ-008: `states: ActiveGrant | WaitingGrant | ReleasedGrant`.
- [WARN] CQ-010 — `inference` misclassifies a query-level numeric comparison; it is neither OWL/Datalog inference nor annotated as computed externally. — evidence: `ontology/docs/competency-questions.yaml`, CQ-010: `derivation_method: inference`; `ontology/tests/cq-010.sparql`, CQ-010: `FILTER (?p95 > ?max)`.
- [BLOCKER] CQ-011 — No timestamp, window, or caller-bound window parameter appears, so the query cannot answer which events occurred in a window. — evidence: `ontology/docs/competency-questions.yaml`, CQ-011: `natural_language: "What invalidation events occurred in a window, and what is each one's blast radius (lanes x packages)?"`; `ontology/tests/cq-011.sparql`, CQ-011: `SELECT ?event ?lane ?pkg WHERE {`, `?event ciops:touchesHashSurface ?surface .`, `?surface ciops:feedsLane ?lane .`, and `?event ciops:radiatesToPackage ?pkg .`.
- [BLOCKER] CQ-012 — The query neither scopes a window nor computes a fraction or the execution, repair, and CI-wait shares; the sample's `lockShare` cannot be bound from `lockTotal` and `grand`. — evidence: `ontology/docs/competency-questions.yaml`, CQ-012: `natural_language: "What fraction of total episode time in a window is lock contention, versus execution, repair, and CI wait?"` and `lockShare: 0.17`; `ontology/tests/cq-012.sparql`, CQ-012: `SELECT (SUM(?lock) AS ?lockTotal) (SUM(?total) AS ?grand) WHERE {`.
- [BLOCKER] CQ-013 — Grouping by every signature/lane and taking `MIN` per group neither ranks signatures by delay nor selects the earliest or cheapest lane; no delay or ordering term appears. The sample's `earliestLane` is not a query binding. — evidence: `ontology/docs/competency-questions.yaml`, CQ-013: `natural_language: "Which failure signatures most delay certainty, and which lane surfaces each signature earliest and cheapest?"` and `earliestLane: ciops:LaneCheapGates`; `ontology/tests/cq-013.sparql`, CQ-013: `SELECT ?sig ?lane (MIN(?p50) AS ?cheapest) WHERE {` and `} GROUP BY ?sig ?lane`.
- [BLOCKER] CQ-014 — The query joins every epoch to proofs in that epoch but has no branch relation or criterion for the branch's current epoch, so `direct_lookup` cannot answer the scoped question. — evidence: `ontology/docs/competency-questions.yaml`, CQ-014: `natural_language: "When did a branch's current cache epoch begin, relative to its held proofs?"` and `derivation_method: direct_lookup`; `ontology/tests/cq-014.sparql`, CQ-014: `?epoch ciops:beganAt ?began .` and `?proof ciops:validInEpoch ?epoch ; ciops:recordedAt ?provedAt .`.
- [BLOCKER] CQ-015 — The unbound existential `ASK` answers whether any proof/checkout pair shares an epoch and cache, not whether the given proof transfers to the given other checkout; it also does not establish that `?other` is another checkout. — evidence: `ontology/docs/competency-questions.yaml`, CQ-015: `natural_language: "Is a given proof transferable to another checkout (same epoch, shared cache) so one agent's green licenses another's skip?"`; `ontology/tests/cq-015.sparql`, CQ-015: `ASK {`, `?proof ciops:validInEpoch ?epoch ; ciops:cachedIn ?cache .`, and `?other ciops:mountsCache ?cache ; ciops:inEpoch ?epoch .`.
- [BLOCKER] CQ-016 — The SPARQL test returns only the intervention and landing instant, not either KPI distribution; the external ETL note documents the boundary but does not make the query answer the CQ, and both sample metrics are unbindable. — evidence: `ontology/docs/competency-questions.yaml`, CQ-016: `natural_language: "For a tagged control intervention, what is the KPI distribution before and after its landing?"`, `p50BeforeMs: 2478000`, `p50AfterMs: 1500000`, and `SPARQL fetches the partition point`; `ontology/tests/cq-016.sparql`, CQ-016: `SELECT ?iv ?landedAt WHERE {`.
- [BLOCKER] CQ-017 — The query implements only CI-merge-minus-local-full, not the requested reverse difference, and it never binds the sample's `onlyIn` tier. — evidence: `ontology/docs/competency-questions.yaml`, CQ-017: `and vice versa (the asymmetry map)?` and `onlyIn: ciops:TierCiMergeGreen`; `ontology/tests/cq-017.sparql`, CQ-017: `ciops:TierCiMergeGreen ciops:requiresLane ?lane .` and `FILTER NOT EXISTS { ciops:TierLocalFullProof ciops:requiresLane ?lane }`.
- [BLOCKER] CQ-019 — The natural language combines an inventory of every fail-open computation with a zero-row trust constraint, but the query returns only fail-open computations already trusted by a subject. Safe fail-open outcomes are therefore invisible, so one test cannot answer both clauses. — evidence: `ontology/docs/competency-questions.yaml`, CQ-019: `natural_language: "Which affected-set computations completed fail-open (lockfile detection failed, git ref missing, shallow clone), and is any proof or schedule trusting a fail-open affected set?"` and `expected_result: zero_rows`; `ontology/tests/cq-019.sparql`, CQ-019: `?proof ciops:scopedByComputation ?computation .`.

## Checked clean

- CQ-001 — The query projects both requested values (`?lane`, `?kind`); `direct_lookup` and both sample fields align.
- CQ-002 — The lane/tier join tests the stated target-tier obligation, the sample `workUnit` is bindable, and no fixpoint property is silently assumed.
- CQ-003 — The query projects WorkUnit, P50, P95, memory class, and provenance; its direct-lookup method and sample values are consistent.
- CQ-004 — The `dependsOnTransitive` fixpoint presumption is documented in the CQ note and ORSD operational-reasoning context; the sample package value is bindable.
- CQ-005 — The exclusion direction is sound under the packet's closed-world context: proofs with an `invalidates` edge are excluded, and the sample `proof` is bindable.
- CQ-006 — The inner `FILTER NOT EXISTS` is oriented toward missing obligations rather than discharged ones; the problem is its absent branch/head correlation, reported above.
- CQ-007 — The selected total, lock, execution, repair, and CI values correspond to the sample's available values; only queue wait and computation provenance fail review above.
- CQ-008 — Resource, grant, and state are all projected, and the sample resource/grant values are bindable; only state admissibility fails review above.
- CQ-009 — The zero-row query selects distinct active-grant pairs sharing one checkout, not compliant grants; `sample_answer: []` is consistent.
- CQ-010 — The zero-row query selects only admitted WorkUnits whose P95 exceeds the grant maximum, not compliant WorkUnits; `sample_answer: []` is consistent.
- CQ-011 — Once an event set is supplied, the query projects the requested lane-by-package blast-radius pairs, and the sample event/lane values are bindable.
- CQ-012 — `derivation_method: aggregation` matches the explicit `SUM` operations; there is no silent materialized-fixpoint dependency.
- CQ-013 — `derivation_method: aggregation` matches the explicit `MIN`; the query does not silently claim that OWL performs the aggregation.
- CQ-014 — The query only projects asserted timestamps, so it does not smuggle temporal arithmetic into OWL; the sample epoch/time values are bindable.
- CQ-015 — `ASK` matches the boolean expected result and sample shape, and the same-cache/same-epoch joins themselves are present.
- CQ-016 — The CQ note explicitly assigns the before/after partition and aggregation to ETL, so its external-computation boundary is documented.
- CQ-017 — The implemented CI-merge-minus-local-full half is a correctly oriented set difference with no undocumented fixpoint.
- CQ-019 — The zero-row pattern selects trust violations, not compliant fail-open outcomes; any subject using `scopedByComputation` can bind despite the variable name `?proof`, and `sample_answer: []` is consistent.
