# ADHD phase 2 — deepened branches (2026-10-14)

## 1. Tier-in-the-signal (cluster 1)
Sketch: `TelemetryTier` LiteralKit (privileged / standard / dev-verbose) in @beep/observability + one Effect Schema allowlist per tier for span attrs, log fields, metric labels. Privileged = closed struct (tool id LiteralKit, latency bucket, error _tag, version, counts, process CPU/RSS), no free string field. Enforcement at the EXPORTER boundary (wrap OTLP span/log/metric exporters in server/NodeSdk.ts with decode-or-drop keyed by tier) because Effect.fn spans, Cause pretty-printing, OTel resource detectors (host.name, os user, process.command_args) attach attributes no call site sees. Correlation ids → HMAC(salt-on-PC, id) declared as a schema transform. On the hub, an Effect HttpApi OTLP gateway in front of the Collector imports the same schema package and reads the sender's tier from Tailscale peer identity (whois → tag:privileged), refusing (4xx) batches that don't decode under that host's tier. Attorney PC sends heartbeat + shape metrics only; full-fidelity errors stay in a local ring buffer read by the attorney's own Claude as a morning card.
Load-bearing risk: ambient channels (tracer, Cause, resource detectors, span names, decode-error messages quoting input) carry content without a typed call site; allowlist must validate every serialized OTLP record, not just attributes we set. Tier-gap anomaly only works on aggregate distributions per version.
First step: add TelemetryTier + PrivilegedSignal schema; wrap exporters with decode-or-drop; vitest in apps/practice-kg-mcp seeding canary matter content, running every tool handler incl. failing paths, capturing OTLP via in-memory exporter, asserting no canary bytes and every record decodes under PrivilegedSignal.
Children: canary tokens scanned at CI and gateway; Tailscale node tag as tier authority (no per-host signing keys on a Windows bun binary); `telemetry_refused_total{host_tag,schema_failure_tag}` as the operator's page (a refusal = our bug, no content); local-only `practice_health_today` MCP tool → morning card; per-release shape fingerprints (tool × latency bucket × error _tag) diffed across tiers in Grafana.

## 2. Parcel lockers — the agent-facing Palantiri (cluster 3)
Sketch: every parcel is an `S.Class` from a ParcelSpec: typed key (session | lane | host | pr | app | account), `freshnessBound` Duration, sources (Prometheus, Loki/Tempo, Phoenix, AccountsUsage.service, GitHub checks), pure reducer raw series → small decoded value. A `Parcels` Context.Service on the hub pre-stages hot parcels on schedule (host pressure 30s, account headroom 60s), cold ones on first request; sealed results in a content-addressed store with `asOf`, `sources[]`, `sealHash`, `Freshness = Fresh | Unknown{reason}` checked at READ time. One HttpApi contract serves an MCP server (one tool per ParcelSpec) and `beep parcel <name> --lane …` printing the same encoded JSON. Emit side: one OTel resource-attribute schema (`beep.session`, `beep.model`, `beep.account`, `beep.lane`, `beep.goal`, `beep.pr`) stamped by the Claude/Codex/Cursor/Grok wrappers and backfilled by the ai-metrics ingester, so emitted data and parcel keys share one join key. "What changed since my last check" = delta against the remembered sealHash per (session, parcel).
Load-bearing risk: attribution join integrity across 5+ harnesses, CI runners, cloud VMs (Cursor + grok-bot-box have no wrapper hook; cloud VMs never see user settings; ai-metrics backfill is late) → parcels look complete when partial. Needs a completeness check (expected emitters vs seen) that downgrades to `Unknown{reason:'attribution-incomplete'}`.
First step: schema before service — Parcel envelope (ParcelKey tagged union, Freshness via LiteralKit-tagged classes, asOf, sources, sealHash) + one `AccountHeadroomParcel` wrapping packages/tooling/tool/cli/src/commands/Accounts/AccountsUsage.service.ts, exposed as `beep parcel account-headroom` with 60s bound and a test that it decodes to Unknown past the bound.
Children: parcel-gated actions (yeet publish/merge-gate/lane launch require a Fresh sealHash receipt → Decision Log cites it); parcel-demand ledger (request count × Unknown rate ranks what to pre-stage, exposes missing-label harnesses); push parcels at `beep session open` and in yeet inbox rows (<1KB) replacing stale HANDOFF prose; quota-arbitrage router over account-headroom + provider-availability parcels (would have caught the 10-12 gpt-6.1-sol loss); behaviour-change parcel per app diffing error-class histograms + p95 between two release SHAs citing Phoenix exemplars by trace id.

## 3. Proof-of-absence harness (cluster 2)
Sketch: canaries (fake file/client/matter names with high-entropy cores) fed through REAL practice-kg-mcp handlers; a hub watcher precomputes each canary's forms (raw, lowercase, URL-encoded, base64, truncated prefixes, unsalted SHA-256) and every 15 min searches Phoenix attrs, Prometheus label values (series API), Loki, CI logs (gh api), agent transcripts, ai-metrics archives; pages on any hit. Each hop (in-process SDK processor, collector attributes/redaction processors, ai-metrics forwarder) writes values-free ledger rows (hop, tier, attributeKey, action ∈ kept|dropped|hashed|blocked, count); per-hop balance keys-in = kept+dropped+hashed+blocked or alarm. CI vitest per tier against an in-memory OTLP exporter asserts: exported key set == golden per-tier allowlist (over-collection fails); no canary form in payload bytes; ledger counts match golden (silent under-collection fails). Existing CauseRedaction.ts + ai-metrics CredentialPatternBank become redactors UNDER test, never the detectors.
Load-bearing risk: coverage — document-body text in an error cause, LLM prompt/completion captured by Phoenix auto-instrumentation, dynamic attribute keys from file names, stack traces with local paths, meaning-level leaks (model paraphrases privileged text). If a redactor ever learns the canary format, runs go vacuously green.
First step: one vitest in apps/practice-kg-mcp wiring tracer/meter to in-memory exporters, one real tool call with a canary fixture under strict tier, assert exported key set vs a new golden file; define TelemetryTier LiteralKit, CanaryToken class, TierAttributeAllowlist schema first. The first red run is the first measured inventory of what strict actually exports today.
Children: canary exercise heartbeat (dead-man's switch: sighting = leak, missing heartbeat = canary not exercised); mutation-tested redaction (disable one rule/processor at a time; both detectors must go red); closed attribute-key grammar (keys only from a per-tier LiteralKit, unknown keys bucketed as salted hash + count); tier-diff as a reviewed PR artifact + weekly attorney "privacy receipt" (counts + key names, no values); LLM-span canaries with fuzzy n-gram/embedding match over Phoenix input/output spans.
