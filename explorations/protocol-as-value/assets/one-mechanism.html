Act I

The mechanism has a name

A journal is an initial algebra. An append-only log is μ(1 + Entry × −) — literally the List fixpoint that the categorical deep learning paper (Gavranović, Lessard, Dudzik, von Glehn, Araújo, Veličković; ICML 2024) uses as its first worked example. And once the journal is μF, your two folds stop being two features:

  • the identity fold (hash chain) is the catamorphism into the digest algebra;
  • every meaning fold (reducer) is the catamorphism into a domain algebra.

Same source, different target algebras. The part I think you’re underselling is the paper’s Remark 2.13: the homomorphism out of an initial algebra is unique — there can only ever be one. Fix the target algebra and the fold has zero degrees of freedom.

That uniqueness is the missing why under proof-by-recomputation. It needs no PKI, no trusted verifier, no zk machinery, because there is nothing to attest — the answer is forced. Re-running the fold isn’t gathering evidence; it’s checking the only possible value against the one you were handed. Your three questions, asked one way: which workflow is this is the catamorphism into names, what did it do is the catamorphism into state, and can you prove it is the fact that both arrows were the only ones that existed.

And “programs live in the same value universe as data” has a name too: Lambek’s lemma, F(μF) ≅ μF — one layer of description applied to the data is isomorphic to the data. There is no separate metadata plane to keep in sync, because the description and the described are the same fixed point. Lessard says the blunt version out loud on MLST: the difference between data and code — there isn’t one. I hit the same wall from the other side mid-refactor and wrote it up as a documented fever dream: we deleted 1,206 lines of hand-written traversal helpers because every one was a hand-written copy of the unique fold the schema had already determined.

Act III

The level above

“The question I was breaking my brain over was trying to stuff topology of a multi-agent async system into the schemas themselves — which doesn’t work… you need to model the topology to know what the protocol is, which is a universal type.”— you, last night

I think you answered it in the same breath — you just haven’t taken your own words literally yet.

It can’t live in the schemas because schemas are the objects. A topology isn’t a property of any vertex; it’s the shape of the diagram — which agents exist, which channels connect them, what may flow along each edge. Stuffing the diagram inside its own vertices is a level error. And it’s exactly the level split the paper is about: structure — symmetry, weight-sharing, wiring — never lives in the carriers. It lives one level up, as the functor whose algebras the carriers are. A G-CNN’s equivariance is not a property of its tensors.

“A universal type” is the literal answer, and the literature already half-cashed it: multiparty session types. A global type — the protocol — from which each participant’s local type is derived by projection, with compatibility checked once, globally. The topology is a value; each agent’s schema is a fold of it. Behavior precipitates from data — one level up.

Now put your own pieces on it:

  • Unison (you’re not late — you’re on time): the name of code is the hash of code. Apply it one level up. The protocol value is digest-named, so two agents agree on the topology the way foldlab agrees on anything: by naming the same canonical bytes.
  • Your git-hash workflow engine is this exact object. A continuation is data (Act I); its resume position is a committed digest (your Raft synthesis); and which continuations may resume where is decided by the protocol value, projected down per agent.
  • Effect<arbitrary> is fine — arbitrary is what the carriers should be. The protocol value is what refines arbitrary into lawful. You don’t need richer schemas; you need the one value above them.

And the part I only saw after writing Act II: beep already builds the level-above object — as infrastructure. @beep/identity’s composer mints a base category of literal-typed names (@beep/{package}/{path}, interned symbols), and every schema in the workspace attaches its meaning as a section over that base via $I.annote; the CURIE/IRI codecs make the path, the CURIE, and the IRI literal-typed encodings of one value. The design doc for its next step — locked 2026-07-01, before foldlab existed, before this thread — compresses it to a sentence:

“The identity path and the IRI become two literal-typed encodings of the same value; annotations become sections over the base category $I mints; retrieval becomes dereference.”— identity-iri-fibration-handoff.md

One value under several literal encodings, meaning attached as sections, lookup by dereference instead of search — a Grothendieck fibration doing at the metadata level exactly what the protocol needs at the agent level. So the remaining move isn’t inventing the level-above object; it’s re-pointing a fibration beep already runs: global type as the base, each agent’s local type a fiber over it, projection as the display map — then foldlab’s contribution, digest-naming the base and folding conformance out of each agent’s journal, is what makes the fibration operational across trust boundaries.

Smaller receipts, same shape: the goals capability projection never stores the portfolio topology — frontier, blockers, and cycles are a fold over per-packet declarations — and the dock engine computes its legal-event union from a literal domain, so the schema derives the program surface. Topology-as-data, folded into behavior.

The honest edge: a content-addressed global type that both generates the endpoints and audits them by recomputation over their journals is, as far as I can tell, the unbuilt thing. Session types stopped at typechecking; foldlab’s move — putting the program in the value universe and folding proof out of the journal — is what would make the protocol operational. That is where I want to start the call.
