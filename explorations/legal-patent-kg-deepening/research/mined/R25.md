# FLINT Ontology repository deep mine

## What this repo actually is

`flint-ontology` is the maintained RDF/OWL knowledge model behind FLINT normative-system interpretations, inspected at clean `main` commit `6be08c0bbbdc8bbbbea58f108a372f6e3bc025c7`.

It is not a statute corpus, legal search engine, complete Hohfeld ontology, or executable norm engine.
Its checked-in core is a 482-line ontology (`flint.ttl`), a 171-line function vocabulary (`functions.ttl`), two SHACL profiles, 22 SPARQL competency-question queries, two worked examples, and a small pySHACL utility.

The model treats a normative system as a state machine:

```text
FrameSet -> Act and Fact prototypes
current Fact values + Act preconditions -> valid transition
Act postconditions -> successor Fact values
```

The paper-era FLINT ontology reported 13 classes; this repository snapshot has evolved to 16 OWL classes, 19 object properties, one data property, and 14 function individuals.
The repository README says the root sources are Apache-2.0 but the entire `shacl/` subtree is separately MPL-2.0.

## Extractable gold

### 1. A compact state-transition class hierarchy (`flint.ttl:57-298`)

The actual class structure is:

```text
Frame = Act | Fact                         (Act disjoint Fact)
Fact = SimpleFact | ComplexFact            (SimpleFact disjoint ComplexFact)
|- Action | Agent | Object | ContextualizedFact
|- BooleanFact
|  `- Duty                                (also SimpleFact)
`- ComplexFact
FrameSet -> calc:Interpretation + co:Set
OperandList -> rdf:List
SlotCorrespondence -> co:Set of SlotReference
Postcondition
```

`Action`, `Agent`, and `Object` are Facts, so role fillers can participate in state descriptions.
`Action` is explicitly disjoint from both `Object` and `Agent`; Agent and Object are not declared disjoint.
`Frame` is equivalent to the union of Act and Fact, while Fact is equivalent to the union of SimpleFact and ComplexFact.
`BooleanFact` is an OWL equivalent-class restriction on `hasInstanceDatatype = xsd:boolean`.
`Duty` carries the load-bearing dual inheritance directly:

```turtle
flint:Duty rdfs:subClassOf flint:BooleanFact, flint:SimpleFact .
```

`FrameSet` is both a Calculemus interpretation and a Collection Ontology set whose elements must all be Frames and whose `calc:usesOntology` value is the FLINT ontology.

### 2. Act frames are typed, preconditioned state transitions (`flint.ttl:300-482`)

An Act may point to an `Action`, `Agent` actor, `Agent` recipient, `Object`, and BooleanFact precondition.
`hasPostcondition` points to a `Postcondition`, which pairs a contextualized fact frame with a literal or fact-derived value expression.
The convenience properties `creates` and `terminates` range over SimpleFact and mean post-state truth and falsity respectively.
An embedded SHACL-SPARQL rule expands those shorthands into explicit Postcondition blank nodes while avoiding an already-recorded equivalent value.

This is a concrete pattern for separating transition intent from its normalized state delta:
retain friendly domain commands, but materialize a canonical value-assignment event for reasoning.

### 3. Slots preserve n-ary identity across related frames (`flint.ttl:335-473`)

Every Frame can declare string-named slots with `hasSlot`; Acts infer `action`, `actor`, `object`, and `recipient` slots.
Duties infer `duty_holder` and `claimant` slots.
`SlotReference` pairs `slotFromFrame` with `slotLabel`.
`SlotCorrespondence` groups two or more references to state that their runtime atoms must be identical.
`hasCreatingSlot` marks Act slots that must receive an atom not previously assigned in the case history.

This is richer than attaching actor/object strings to a binary edge: it preserves the same book, person, game, or other atom across preconditions, postconditions, duties, and acts.

### 4. Contextualized facts separate reusable prototypes from act-local use (`flint.ttl:161-167,344-351`)

`ContextualizedFact` is a Fact whose `hasFactFrameType` points back to a generic Fact.
The library example uses separate contextualized versions of the return-book duty for borrowing, suspension, and return acts.
Slot correspondences then bind a generic duty's `book`, `duty_holder`, and `claimant` roles to the act-local object, actor, and recipient.

Take the prototype/use distinction, but give every use stable identity, source evidence, validity time, and interpretation provenance in Beep.

### 5. Complex facts are typed expression trees (`flint.ttl:132-159,257-273`; `functions.ttl`)

A ComplexFact has one `hasFunction` and one RDF `OperandList`; operands may be Facts or literals.
An embedded SHACL rule derives the complex fact's instance datatype from the Function Ontology return declaration.
`functions.ttl` defines 14 functions: conjunction, disjunction, negation, five comparisons, five arithmetic operations, and implication.
Several carry aliases with `owl:sameAs` (`and`, `or`, `not`, `plus`, `minus`, `times`, `if`); Boolean and comparison returns are `xsd:boolean`, while arithmetic returns are `xsd:decimal`.
The vocabulary describes return types but does not declare function parameters, arity, evaluator implementation, or error semantics.

### 6. Source traceability is an ontology rule, not optional prose (`flint.ttl:200-224,406-422`)

Frames can link directly to structural `src:Element` nodes with `hasSource` or to `src:TextFragment` nodes with `hasTextFragment`.
A SHACL TripleRule derives the containing source through `hasTextFragment / src:isFragmentOf`.
The tic-tac-toe example includes exact `src:CharacterRange` start/end indices for two local fragments and maps many frames to source lines.
`examples/README.md` separately demonstrates Web Annotation plus PROV for attributed, edited, and invalidated comments on frames.

Port the span-to-frame derivation, but make spans immutable evidence and interpretations versioned claims rather than treating a source link as endorsement.

### 7. The SHACL profiles form a useful two-tier gate (`shacl/full-flint.ttl`; `shacl/flint-warnings.ttl`)

`full-flint.ttl` declares hard violations:

- a Fact may not reach itself through one or more nested operand-list paths;
- a ComplexFact has exactly one function and exactly one operand list;
- an Act has exactly one actor and recipient, at most one action and object, and at least one postcondition.

`flint-warnings.ttl` declares advisory checks:

- functions outside a fixed FLINT whitelist receive `sh:Warning`;
- a SlotCorrespondence with fewer than two `co:element` references receives `sh:Warning`.

The warning whitelist includes aliases such as `and`, `or`, `not`, `plus`, and `minus`, but omits checked-in `times`, `division`, and `percentOf`; those built-ins can therefore warn as non-standard.
The SHACL README describes `partial-flint.ttl`, but no such file exists in the inspected checkout.

### 8. Competency questions are executable retrieval contracts (`competency-questions/`)

The README frames FLINT around possible worlds: what can happen to an agent, what it can do, consequences, and expected behavior.
The 22 `.rq` files query frame sets, acts and their roles, pre/postconditions, facts and sources, duties, operands, function datatypes, slot degree, new-atom slots, and slot correspondences.
Most queries use a `VALUES` placeholder for the input interpretation or frame, making the required lookup shape explicit.

The README is also honest about gaps: direct power-liability support is limited, and events, omissions, duty violations, immunity-disability, and liberty-no-claim queries are out of scope.
Several listed duty-holder/claimant and reverse act-lookup questions have no corresponding checked-in `.rq` file.

Use each CQ as a schema/test requirement, not merely documentation: missing holder, claimant, source, operand, or postcondition data should fail before graph publication.

### 9. The examples expose the n-ary pattern in executable Turtle (`examples/library/`; `examples/tic-tac-toe/`)

The 216-line library example interprets three rules as a FrameSet containing facts, one return duty, borrow/suspend/return acts, contextualized facts, and slot correspondences.
Borrowing creates a contextualized return duty; returning assigns that duty false; suspension requires both an overdue-book fact and a still-active duty.
Correspondences preserve that the borrower becomes duty holder, the administrator becomes claimant, and the returned object is the borrowed book.

The 521-line tic-tac-toe example is a larger non-legal fixture with four acts, simple and complex facts, shared game/grid/player slots, and exact source-fragment links.
It demonstrates that the ontology is domain-neutral, but it is still a hand-authored prototype graph rather than a concrete event log or state-machine execution trace.

### 10. The included inference utility is illustrative, not production-ready (`util/shacl_inference.py`)

The script intends to combine `flint.ttl`, `functions.ttl`, and `shacl/full-flint.ttl`, run pySHACL with OWL-RL and advanced rules, mutate the input graph in place, and serialize inferred triples.
As checked in, `Path("shacl/full-flint.ttl", format="turtle")` passes an unsupported keyword to `pathlib.Path`, so the utility cannot reach validation without repair.
No dependency lock, automated test suite, expected validation report, or CI proof for the examples is present.

Re-express the constraint ideas clean-room from this behavioral distillate and Beep's own schema requirements; do not copy MPL shape text, comments, or identifiers.

## Beep-relevance hooks

- `semantic-foundation SKOS / @beep/ontology`: register FLINT as a versioned donor and port the Act/Fact/Duty plus function vocabularies with mappings; keep Hohfeld correlativity and cardinality in Effect schemas, not SKOS hierarchy alone.
- `epistemic slice`: combine FrameSet, ContextualizedFact, SlotCorrespondence, exact source fragments, and PROV-style annotations into interpretation claims with analyst identity, evidence spans, valid/transaction time, and competing versions.
- `epistemic-bitemporal-edge-core`: translate `creates`/`terminates` into append-only postcondition events; never overwrite the prior fact, and distinguish prototype frames from concrete exercises and inferred state.
- `patent tooling / gov-legal data drivers`: use CQs and hard-shape behavior as import acceptance tests for regulations, assignments, licenses, and office actions; reject graphs missing actor, recipient, postcondition, source, or slot identity.
- `OIP practice`: use the library pattern for duty creation/termination and the authorization pattern for filings and responses, while modeling deadlines, omissions, violations, and office-generated events that FLINT leaves out.
- `agent memory (Cognee)`: retain source episodes and every frame/state derivation, but resolve the utility and validation gaps before treating inferred triples as trusted memory.
