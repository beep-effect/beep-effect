# KLIPA: A Knowledge Graph and LLM-Driven QA Framework for IP Analysis

## Problem & positioning

Patent analysis still relies on manual multi-database search, keyword matching, expert filtering, and rigid categorization.
KLIPA combines a patent KG, retrieval-augmented generation, and a ReAct agent to support explicit relations and latent semantic connections.
It targets technology companies, law firms, universities, and research institutions managing strategic IP information.
The KG supplies structured relations, RAG supplies semantic retrieval, and the agent chooses a strategy based on the query.
The paper also compares OCR-plus-LLM and vision-language extraction for constructing the KG from patent cover pages.

## Approach / architecture

The construction pipeline parses PDF, HTML, or text, enforces UTF-8, recursively splits text, and overlaps adjacent chunks.
Prompt templates constrain allowed entity types, relation types, and a JSON triple output schema.
Responses undergo normal JSON parsing, repair fallback, and schema validation before graph insertion.
Neo4j stores entities and relations, with uniqueness/property constraints, batch writes, caching, and asynchronous insertion.
The QA layer indexes patent documents in a Neo4j vector database using dense multilingual-e5-base embeddings.
Hybrid search combines semantic similarity and keyword matching at chunk and document granularity.
The ReAct agent uses query and chat history to select chunk retrieval for details or document retrieval for cross-document synthesis.
The generation function combines query, intermediate reasoning, and retrieved evidence into the answer.
A Gradio interface supports interactive queries.
For KG construction, OCR+text LLMs are compared with VQA models that read cover images directly.

## Ontology & KG modeling contributions

The graph is formalized as entities `V` and extracted relation edges `E`, with neighborhood and induced-subgraph operations.
Predefined entity types include inventors, technologies, companies, and patent classifications.
Example relations include invented-by, owned-by, references, applicants, assignee, background, abstract, prior data, and related-with/same-field.
The evaluated cover-page schema includes patent number, patent name, applicants, inventors, assignee, cited patents, and classification fields.
Extraction prompts carry a relation matrix that constrains source type, target type, and relation type.
Neo4j uniqueness constraints provide identity discipline at insertion time, while relationship constraints can require properties.
The paper's strongest reusable pattern is schema-constrained extraction followed by repair and validation, rather than free-form graph generation.
Chunk metadata includes sequence identifiers, offering a minimal path back to document order.
However, the formal relationship function is binary and does not model uncertainty, provenance, evidence spans, temporality, or contradiction.
The graph schema remains illustrative/configurable rather than a published patent ontology with axioms and stable identifiers.

## Evaluation & results

The experimental dataset is an unreleased internal university collection of public USPTO patent PDFs with varying layouts.
Only patent cover pages are evaluated, because the authors consider them sufficient for the selected fields.
RAE is correctly extracted ground-truth entities divided by all ground-truth entities; higher is better.
RIC is patents outside the expected common-applicant central cluster divided by all patents; lower is better.
Qwen2-7B OCR+LLM takes 6.54 seconds, with RAE 63.07% and RIC 12.92%.
Qwen2-VL-7B takes 5.05 seconds, with RAE 82.11% and RIC 9.58%.
Qwen2.5-7B OCR+LLM takes 9.80 seconds, with RAE 78.50% and RIC 15.04%.
Qwen2.5-VL-7B takes 8.38 seconds, with the best RAE (92.35%) and RIC (7.31%).
The VQA variants are both faster and more accurate than their same-generation text-only counterparts in Table 1.
The implementation uses Ubuntu 24.04.1, Xeon Gold 6442Y, 1 TiB RAM, and an NVIDIA L40S.
The paper states a constructed KG of more than 1,000 patents is planned for later release.
No quantitative experiment evaluates QA answer correctness, retrieval accuracy, response relevance, agent routing, or expert-effort reduction.

## Limitations (authors' own + yours)

The authors identify graph maintenance/update cost as the KG scales.
They identify dependence on inconsistent or missing patent metadata.
They state complex queries may still require domain-specific fine-tuning.
Future work includes multilingual support, causal reasoning, and deployment in legal/patent-office environments.
The nonreleased dataset prevents independent reproduction and obscures sample size and ground-truth annotation procedure.
RIC assumes one applicant organization should form one dense cluster; it is not a general relation-extraction or clustering metric.
Evaluation covers only front-page bibliographic facts, not claims, descriptions, legal events, citations in context, or multi-page evidence.
Broad claims about retrieval accuracy and QA relevance are not supported by reported quantitative QA evaluation.
Syntax repair can turn malformed generations into valid but incorrect triples; schema validity is not semantic truth.
The paper describes generated intermediate chain-of-thought, which is an unnecessary persistence/exposure risk; tool decisions and evidence traces are safer audit artifacts.
No citation-grounding contract, hallucination measurement, access control, or legal-practice safety evaluation is reported.

## Beep-relevance hooks

- semantic-foundation (SKOS/@beep/ontology): adopt constrained entity/relation matrices and schema validation, but bind them to canonical ontology identifiers rather than prompt-local labels.
- epistemic slice: extend every extracted triple with source document, page/span, extractor/model version, confidence, and recorded time; keep repaired syntax distinct from verified semantic claims.
- patent tooling (uspto-patent-driver-depth): test VQA as a fallback for layout-heavy front pages while retaining deterministic USPTO structured data as the preferred bibliographic source.
- patent tooling (agentic-cad-patent-tooling): route queries between exact graph traversal and semantic document retrieval, and expose which route/evidence produced the answer.
- OIP solo-practice workflows: require answer-level citations and explicit abstention before adopting the agent UI; reject unmeasured claims of reduced expert reliance.
- agent memory (Cognee): reuse coarse document/fine chunk retrievers plus graph neighborhoods, but store action/evidence traces rather than private chain-of-thought.

## Extraction confidence

High for prose, tables, formulas, and appendices using `pdftotext -layout`.
Two-column reading order interleaved some conclusion and limitations text, but section boundaries and metrics were recoverable.
Figures were flattened; their captions and surrounding descriptions were readable, while fine graph labels were only partially recoverable.
