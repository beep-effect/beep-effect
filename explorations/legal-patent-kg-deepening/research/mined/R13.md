## What this repo actually is

`LegalDatasets` is a collection of acquisition, normalization, benchmark-adapter, and corpus-accounting scripts for multilingual legal NLP. It is not an ontology, knowledge graph, patent corpus, or production ingestion service.
The inspected snapshot is commit `e8f01979694cefa28eb6b514856cd5cb4882dec0` (2023-06-16). Its substantive lanes are heterogeneous and only loosely integrated:

1. `README.md` declares a nine-field pretraining document contract: `id`, `type`, `language`, `jurisdiction`, `title`, `date`, `url`, `metadata`, and `text`.
2. `pretrain/Scraping/` contains six Selenium/BeautifulSoup court-decision scrapers with an older five-field record: `ID`, `URL`, `language`, `date_decision`, and `text`.
3. Adjacent `pretrain/*/prepare_data.py` adapters commonly project sources to the four training fields `type`, `language`, `jurisdiction`, and `text`, then emit compressed JSONL.
4. `finetune/lextreme/lextreme.py` is a Hugging Face `GeneratorBasedBuilder` that adapts 11 source tasks into 18 configurations and three common task shapes.
5. `scripts/create_statistics.py` and `scripts/Finished/` form a resumable corpus-inventory lane over Hugging Face configurations.

The repository therefore contains three different notions of “normalized.” The documented nine-field envelope is the best provenance-bearing target, the four-field projection is the actual pretraining interchange used broadly in code, and the LEXTREME `input`/`label`/`language` shape is an evaluation projection. Treating any one as the whole domain model would discard useful information.

No OWL, RDF, Turtle, JSON-LD, SPARQL, SHACL, spreadsheet, or local LEXTREME data payload was present. The only local corpus-like payloads are small CSV/JSON/Markdown statistics; the six scraper datasets are absent behind DVC pointers.

## Extractable gold

### 1. Preserve an evidence envelope, then derive task projections

The load-bearing contract in `README.md` is:

```text
id + type + language + jurisdiction + title + date + url + metadata + text
```

The README says a missing identifier should become UUIDv5, but no UUIDv5 implementation exists in the checked-in Python. The scrapers instead allocate source-local sequential integers, while many preparation utilities discard identity entirely.
`pretrain/CASS/prepare_data.py` demonstrates the loss concretely: `format_file()` extracts title, jurisdiction, source ID, decision text, date, URL, claimant, defender, and summary, but `pretrain/CASS/utils.py::select_and_clean()` later retains only:

```python
df = df[['type', 'language', 'jurisdiction', 'text']]
```

The portable pattern is a two-layer record, not that destructive projection: retain an immutable source/evidence envelope with source URI, source identifier, acquisition time, raw metadata, and content digest; derive a compact training or evaluation view from it. A deterministic ID should be namespaced by source and stable source identity, not by scrape order.

The repository's recurring legal-document vocabulary is concrete but intentionally coarse:

- domain types: `caselaw`, `legislation`, `contracts`, `other`; the filtered corpus adds `wikipedia`, and one preparer mentions unfinished `mc4-legal`;
- languages: 24 EU-language codes in `pretrain/MultiLegalPileWikipediaFiltered/MultiLegalPileWikipediaFiltered.py`, namely `bg cs da de el en es et fi fr ga hr hu it lt lv mt nl pl pt ro sk sl sv`;
- jurisdictions: 32 strings in that builder, covering EU member states plus `EU`, `Switzerland`, `UK`, `US`, `Canada`, and `N/A`.

These are seed concept schemes, not a sound ontology: jurisdiction capitalization is source-authored, the scraper uses `dk` where the rest of the repository uses Danish `da`, and “other” conflates unknown document kinds.

### 2. A source-driver pipeline with site-specific parsing isolated at the edge

All six scripts in `pretrain/Scraping/` instantiate the same pipeline:

```text
enumerate result pages -> collect decision links -> render each page -> parse date/text
-> normalize date to YYYY-MM-DD -> append one JSON object -> write JSONL -> print counters
```

The source-specific grammar is small enough to make declarative or typed-driver configuration:

| Script | Language | Listing extent and link selector | Date extraction | Text extraction |
|---|---|---|---|---|
| `legifrance.py` | `fr` | pages 1–99, `.title-result-item` | `.titreLecture span`, French month map | `.content-page` |
| `gesetze_bayern.py` | `de` | pages 1–499, `.hltitel` | `.col-sm-9 b`, `dd.mm.yyyy` | `.rsprbox` |
| `ris_bka_gv_at.py` | `de` | pages 1–39, `.nativeDocumentLinkCell` | second `.contentBlock`, `dd.mm.yyyy` | `.paperw.nextpage` |
| `bailii.py` | `en` | one 2019 EWCA Civil page, every `li` | `<date>`, English month or slash form | first `<ol>` |
| `sentenze_ti.py` | `it` | pages 1–999, nested result tables | fourth `tbody`, fourth `td`, `dd.mm.yyyy` | table `width="680"` |
| `retsinformation.py` | `dk` | pages 0–29, `.document-title` minus first item | trailing 10 chars of one `h5`, `dd/mm/yyyy` | `.restyling-html` |

This is useful as a driver contract, not as reusable selectors: every selector is layout-coupled, each scraper hard-codes a Windows ChromeDriver path, fixed sleeps stand in for readiness, and exception policy varies. Legifrance, BAILII, and Retsinformation skip malformed records; the other three can abort the whole batch.

`pretrain/Scraping/get_info.py` supplies a minimal postcondition pass—parse every `date_decision`, compute min/max dates, and count rows—but does not validate uniqueness, URLs, language codes, required text, or schema conformance. Those missing checks are the natural typed validation boundary.

### 3. DVC pointers are provenance records, not available datasets

The six `pretrain/Scraping/*.jsonl.dvc` files record content MD5, byte size, and a logical output path. Together they describe 466,069,559 bytes (444.48 MiB):

| Pointer | DVC output | Bytes | MD5 |
|---|---|---:|---|
| `bailii.jsonl.dvc` | `DBWebsite4.jsonl` | 25,431,970 | `85a3c41c2e29087e9357292e85741307` |
| `gesetze_bayern.jsonl.dvc` | `DBWebsite2.jsonl` | 6,077,316 | `5451b4719bc8bdde3e4d114bdd617846` |
| `legifrance.jsonl.dvc` | `DBWebsite1.jsonl` | 176,495,598 | `1111ea951f48385b4962d54ee5a34556` |
| `retsinformation.jsonl.dvc` | `DBWebsite6.jsonl` | 88,093,488 | `b52099e9983e3ff08a59a4c9c7f1e3f5` |
| `ris_bka_gv_at.jsonl.dvc` | `DBWebsite3.jsonl` | 14,203,213 | `b460275a8486d451bdc4e45049fc0288` |

`.dvc/config` points at a Google Drive remote. None of the six logical outputs exists locally, so row counts, field populations, duplicate rates, encoding, and correspondence to the current parsers could not be inspected.
There is also lineage drift: each current scraper writes `<source>.jsonl`, whereas its DVC pointer names `DBWebsiteN.jsonl`. Preserve pointer identity and generator revision separately; do not infer that rerunning current code reproduces those hashes.

### 4. The pretraining preparation lane encodes useful corpus-quality stages

The common utility pattern in `pretrain/*/utils.py` is: select four fields, drop null text, reject records shorter than 100 characters, trim text, write JSONL with Unicode preserved, and produce an `.xz` copy.
`pretrain/openlegaldata/prepare_data.py` shows a source adapter before that projection: rename `content` to `text`, remove source-only columns, strip HTML with BeautifulSoup, attach type/language/jurisdiction constants, and emit one caselaw and one legislation corpus.

`pretrain/MultiLegalPileWikipediaFiltered/prepare_legal_data.py` adds a scalable second pass:

- stream each language/type configuration from Hugging Face and shuffle with seed 42 and a 10,000-record buffer;
- apply Unicode NFKD and collapse tabs, spaces, and repeated newlines;
- require `alpha_percent > 0.7` after removing digits/punctuation (the implementation also leaves whitespace in that numerator) and more than 64 whitespace-delimited words;
- reserve the first 1,000 accepted records per configuration for validation;
- rotate compressed training shards at 500 MB and emit `{language,type,jurisdiction,text}` JSONL through `lzma`.

The checked-in `_DOMAIN_TYPES` default accidentally concatenates `'mc4-legal' 'wikipedia'` because a comma is missing, although the `__main__` path passes a correct explicit list. Port the stages and invariants, not the literal control flow; make accepted/rejected counts and rejection reasons first-class evidence.

### 5. LEXTREME provides a compact multi-task adapter algebra

`finetune/lextreme/lextreme.py` defines exactly three task kinds:

- `SLTC`: scalar string input and scalar `ClassLabel` output;
- `MLTC`: scalar string input and `Sequence(ClassLabel)` output;
- `NER`: `Sequence(string)` input and `Sequence(ClassLabel)` output.

Every shape also carries `language`. Each configuration declares its upstream Hub dataset/config, input column, label column, language fallback, citation, classes, and optional label level. `_generate_examples()` converts upstream integer `ClassLabel` values back to strings, drops invalid SLTC labels, and yields the common `{input, label, language}` projection. MultiEURLEX is the one special loading branch, parameterized by `language` and `label_level`.

The actual 18-configuration matrix in `BUILDER_CONFIGS` is:

| Source family | Configurations | Input -> label | Configured vocabulary |
|---|---:|---|---|
| Brazilian Court Decisions | 2 SLTC | `decision_description` -> judgment/unanimity | 3 outcomes; 2 unanimity states |
| Swiss Judgment Prediction | 1 SLTC | `text` -> `label` | `dismissal`, `approval` |
| German Argument Mining | 1 SLTC | `input_sentence` -> `label` | `conclusion`, `definition`, `subsumption`, `other` |
| Greek Legal Code | 3 SLTC | `text` -> `label` | 47 volumes, 389 chapters, 2,285 subjects |
| Online Terms of Service | 1 SLTC + 1 MLTC | `sentence` -> unfairness/topics | 3 fairness states; 9 topic codes |
| COVID-19 Emergency Event | 1 MLTC | `text` -> `all_events` | 8 event codes |
| MultiEURLEX | 3 MLTC | `text` -> `labels` | 21/127/567 EUROVOC IDs at levels 1/2/3 |
| LeNER-Br | 1 NER | `tokens` -> `ner_tags` | 13 BIO tags |
| LegalNERo | 1 NER | `words` -> `ner` | 11 BIO tags |
| Greek Legal NER | 1 NER | `words` -> `ner` | 17 BIO tags |
| MAPA | 2 NER | `tokens` -> coarse/fine labels | 13 coarse; 45 fine BIO tags |

The label inventories are ontology gold when kept source-scoped. LeNER-Br distinguishes organization, person, time, location, legislation, and jurisprudence; Greek Legal NER distinguishes legal references from public documents and geographic/personal/facility entities; MAPA fine adds building, city, country, territory, unit/value, date parts, age, profession, role, nationality, title, URL, and type.
Do not merge these tags by spelling. Represent each source label as a concept with scheme/version/config provenance, then assert reviewed `exactMatch`, `closeMatch`, `broadMatch`, or `narrowMatch` relations.

The builder's test in `finetune/lextreme/test_lextreme.py` is not a trustworthy invariant: `assert [condition for ...]` asserts a nonempty list rather than `all(...)`, and the local-script dataset name is overwritten by `joelito/lextreme`. A Beep port needs fixture-backed shape, split, sequence-length, label-domain, and language tests.

### 6. Corpus statistics are useful evidence with visible reproducibility gaps

`scripts/create_statistics.py` discovers configurations, resumes from per-dataset CSV, loads train/validation/test, maps document word length, optionally tokenizes with `xlm-roberta-base`, totals documents and lengths, computes per-document means, and attempts size enrichment. This is a good corpus-card pipeline shape: configuration identity, split aggregation, count family, tokenizer identity, byte size, and resumable checkpoints.

Directly read local artifacts in `scripts/Finished/` record:

- Multi Legal Pile: 124 unique configs over 25 language selectors (`24 + all`), 105,555,004,069 tokens and 25,235,644 documents in `all_all`; sources are caselaw/contracts/legislation/other plus aggregate, with no `ga_other` row;
- EUR-Lex resources: 200 unique configs, eight source selectors per language aggregate, 21,526,462,547 tokens and 8,267,651 documents in `all_all`;
- Pile of Law: 35 configs, 50,547,777,921 tokens and 9,872,444 documents in `all`;
- legal-mC4: 32 rows but only 24 unique configs; `bg` occurs five times and `cs`/`da` three times, so this artifact requires deduplication before use.

These numbers are snapshot evidence, not independently recomputed truth. The current script defaults to word counts, while the finished artifacts expose token counts; its size column names also differ from the edited CSVs. Tokenizer/model revision, dataset revision, download digest, run time, and successful/failed split inventory are absent. A port should make all of those part of the result identity.

## Port discipline notes

The repository root `LICENSE` is Apache-2.0. Its code and documentation may be copied and modified with attribution: retain the copyright and license notices, provide the Apache 2.0 license, preserve any applicable `NOTICE`, state material modifications, and retain the patent-license and warranty terms. There is no copyleft requirement.

That grant does not flatten the licensing of what the code fetches. `finetune/lextreme/README.md` declares CC BY 4.0 in its dataset-card metadata, leaves its licensing prose incomplete, and wraps 11 separately published datasets. Each upstream dataset, website corpus, model/tokenizer, and vocabulary needs its own license/provenance record before data or label descriptions are redistributed.

Do not vendor the absent DVC payloads merely because their pointer files are Apache-licensed. The Google Drive objects may contain court text subject to upstream copyright, database rights, access terms, and privacy constraints; `pretrain/Scraping/README.md` explicitly frames the project around testing anonymity in court rulings.
Likewise, Apache-2.0 does not authorize scraping the six websites or bypass their current technical/contractual controls. Port the driver and schema patterns with attribution; reacquire data only through an approved source-specific policy and privacy review.

Safe to port with Apache attribution: the adapter interfaces, pipeline staging, task-shape algebra, validation ideas, and source-code implementations after modernization. Must not be blindly vendored: DVC corpus bytes, Hugging Face datasets, website content, XLM-R assets, or upstream taxonomies whose separate terms have not been checked.

## Beep-relevance hooks

- **semantic-foundation SKOS / `@beep/ontology`:** create source-scoped schemes for document type, jurisdiction, LEXTREME task type, and each label inventory; carry EUROVOC IDs as notations and make cross-scheme equivalence a reviewed mapping assertion.
- **epistemic slice:** model DVC hash/size, acquisition, parse, normalization, projection, and benchmark-statistic claims as distinct evidence-bearing assertions; the nine-field/five-field/four-field drift is a concrete test case for schema-version belief revision.
- **patent tooling / law-docketing spine:** reuse the nine-field evidence envelope and add patent-specific identifiers, office/jurisdiction, prosecution event, family, citation, and document-kind schemes; never reduce the durable patent record to the four training fields.
- **gov-legal data drivers:** make `enumerate -> fetch -> parse -> normalize -> validate -> emit` a typed driver contract with source-specific pagination/date/selectors, bounded retries, explicit parse errors, checkpoint cursors, and accepted/rejected evidence counts.
- **OIP practice:** use the 18 LEXTREME configs as a multi-task evaluation pattern for legal-document classifiers and entity extractors, but pin dataset/tokenizer revisions and publish per-language/per-source slices rather than one aggregate score.

## Extraction confidence

**High for repository structure, code paths, vocabularies, configuration counts, DVC metadata, and local statistics.** The Python source, READMEs, full Apache license, six DVC pointers, builder configuration AST, and checked-in CSV/Markdown outputs were inspected directly. Counts were recomputed from those local artifacts.

**Medium for the semantic meaning of benchmark labels.** The configured labels and source descriptions are present, but the upstream annotation guidelines and live dataset rows were not local and were not independently checked. Several labels are opaque codes (`event1`, ToS abbreviations, EUROVOC IDs) without local definitions.

**Low for corpus content and scraper reproducibility.** The DVC outputs were missing, the web layouts were not replayed, the Hub datasets were not downloaded, and the fixed Selenium selectors date from this repository snapshot. No claim is made about current endpoint behavior, row quality, anonymity, or hash reproducibility.

**Not available from this repo:** ontology axioms, SKOS mappings, SPARQL shapes, SHACL constraints, patent-specific data, executable provenance tracking, or a license manifest covering all upstream corpora. Those must be designed or sourced elsewhere rather than inferred.
