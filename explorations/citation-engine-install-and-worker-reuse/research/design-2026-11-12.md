# Design: invocation binding, owned configuration, native lane, regex session

Dated 2026-11-12, revision 2. Revision 1 went to an independent adversarial
review against the code; its findings are in
[`design-review-2026-11-12.md`](./design-review-2026-11-12.md) and every
BLOCKER and MAJOR is resolved here.

Order is the repo's: data model, then service contracts, then how existing
modules change. The code blocks are contract sketches for review, not
implementation. Every Effect API named is cited against the 4.1.4 reference in
[`../RESEARCH.md`](../RESEARCH.md). `C/` means
`packages/law-practice/server/src/internal/Citation/`.

## 1. What is constant and what is per request

| Value | Lifetime today | Lifetime after |
| --- | --- | --- |
| Limits, runtime, configuration, patterns, descriptors, fingerprints | decoded and copied on every install, per request | engine |
| Stage tree (34 stage types), tokenizer, tries, recipes, regex descriptor registries, job preparation | per request, some per token | engine |
| Operation admission, native admission, Clock, Digest, Path, spawner | engine, re-captured per install | engine |
| Text budget | per request, reaches stages by install-time capture | invocation |
| Scope for process ownership | per request, captured by each worker's owner | invocation |
| Proof that the caller holds an admission permit | per request, a pass-through admission given to children | invocation |
| Native lease | one per child process | one lane per invocation |
| Regex worker process | one per evaluation | one at a time per invocation, lazy |
| Limits copied into a returned report | per request | per request, unchanged |

## 2. Data model

### 2.1 Owned configuration

```ts
// C/ConfigurationOwnership.ts (new). The brand constructor is module-private.
export type CitationOwned<A> = A & Brand.Brand<"CitationOwned">

export const ownCitationConfiguration: <A, I, E>(
  schema: S.Codec<A, I>,           // detached through S.toCodecJson(schema)
  raw: unknown,
  invalid: () => E
) => Effect.Effect<CitationOwned<A>, E>

export const ownedField:  <A, K extends keyof A>(owned: CitationOwned<A>, key: K) => CitationOwned<A[K]>
export const ownedItems:  <A>(owned: CitationOwned<ReadonlyArray<A>>) => ReadonlyArray<CitationOwned<A>>
```

Rules:

- `ownCitationConfiguration` runs where configuration crosses from a caller
  into the engine (`makeDefault` and `make` in `CitationEngine.layer.ts`, and
  the separate boundary in `CitationExtractor.layer.ts`) and nowhere below.
- The detach goes through the JSON codec, as the existing
  `detachCitationMetadataConfiguration` callers do. A type-side round trip
  would keep a caller's `Uint8Array` buffers, because `S.Uint8Array` is an
  instance check.
- Installers below take `CitationOwned<Config>` and neither decode nor detach.
- The brand asserts that no reference to the value or any part of it is held
  outside the engine. It does not assert immutability; the review confirmed no
  engine code mutates decoded configuration in place.
- Pattern fingerprints, the court table hash and the vocabulary artifact hash
  run inside `own` once and their results live on the owned value.
- **Return-path snapshots stay.** `captureCitationOperationPolicy` at
  `C/SourceExtraction.ts:81`, `C/SourceCleaning.ts:93`,
  `C/SourceResolution.ts:128` and `C/AnnotationOperation.ts:31` copies limits
  into each returned report so a caller mutating a report cannot alter the
  installed policy (the 2026-11-07 fix). Owned values never leave the engine;
  what leaves is a fresh copy. These four are excluded from the detach count.

### 2.3 Limits, policy v2

One new cross-field check in the `CitationEngineLimits` schema:
`concurrentRegexProcesses >= concurrentOperations`. A lane may host a regex
process at any time, so a policy with fewer regex processes than operations
cannot be honored. The default (2 and 2) and the test policy (1 and 1) pass.
No field is added and no value changes. Published as
`citation-engine-policy/v2`.

### 2.4 Regex worker protocol v3

```ts
const Version  = S.tag("citation-regex-worker/v3")
const Sequence = S.Natural                       // per-process job number, from 0

// argv: limits and engine only.
class CitationRegexWorkerStartup { limits; engine }

// parent -> worker, one LF-terminated frame per job
class CitationRegexWorkerJob extends S.TaggedStruct("Evaluate", {
  version: Version,
  sequence: Sequence,
  descriptor: CitationRegexPatternDescriptor,
  patternWidth, patternBytes, sourceWidth, sourceBytes, flags, maxMatches, mode,   // as v2
}) {}

// worker -> parent
class Ready   extends S.TaggedStruct("Ready",   { version: Version }) {}              // once
class Started extends S.TaggedStruct("Started", { version: Version, sequence }) {}    // per job
class Failure extends S.TaggedStruct("Failure", { version: Version, sequence, failure }) {}
// Complete is the existing result envelope plus `sequence`.
```

Changes to the frame rules that the per-job descriptor forces:

- The descriptor is bound before job preparation, and the exact size preflight
  includes the encoded descriptor, so the frame bound is still checked before
  any payload allocation and before the lane is used.
- The structural ceilings become depth 3 and a property ceiling of the flat
  field count plus the descriptor's fields plus a bound on capture names. The
  name-length bound moves from the argv check to job encoding, against
  `processMessageBytes`.
- The RPC request id is the sequence number, not a fixed 0, so a finished
  request can never be confused with the next.

Conversation, as the state machine the parent enforces:

```text
Spawned --Ready--> Idle
Idle --write job k--> Sent(k) --Started(k)--> Running(k) --Complete(k) | Failure(k)--> Idle
any state --EOF, wrong tag, wrong sequence, oversize frame, a frame while Idle,
            timer expiry, interruption, any non-success exit of the wait--> Killed
Idle --lane needed by another process, or invocation Scope closes--> Killed
```

`Killed` is the existing retirement: SIGKILL, re-check `isRunning`, close the
child Scope, then hand the lane back, or quarantine when unconfirmed. There is
no graceful exit.

Transport. v2 uses the child's stdin and stdout once each: the stdin sink ends
the pipe when its stream completes, the frame reader demands an exact count and
then EOF, and the worker reads to stdin EOF before `Started`. v3 replaces that
for the regex worker:

- The command opens stdin with `endOnDone: false`; the session writes one frame
  per job to the same pipe.
- The session forks one stdout reader into the process's Scope. It splits LF
  frames under the per-frame byte ceiling into a queue of capacity one and
  kills on EOF, on an oversize frame, and on any frame that arrives while no
  job is in flight.
- The worker program loops: read one frame, decode, `Started`, evaluate,
  terminal reply, repeat until its stdin closes or it is killed.

Unchanged: native carriers for pattern and source, closed source-free
failures, an empty child environment, no shell, stderr ignored.

## 3. Service contracts

### 3.1 `CitationInvocation`

```ts
export class CitationInvocation extends Context.Service<CitationInvocation, {
  readonly policy: CitationInvocationPolicy
  readonly budget: CitationTextBudget["Service"]
  readonly scope: Scope.Scope
  readonly lane: CitationNativeLane["Service"]
  readonly regex: CitationRegexSession["Service"]
  readonly receipt: Effect.Effect<CitationInvocationReceipt>
}>()($I`CitationInvocation`) {}

// The only constructor. Holding a CitationInvocation proves admission.
export const openCitationInvocation: <A, E>(
  policy: CitationInvocationPolicy,
  body: Effect.Effect<A, E, CitationInvocation>
) => Effect.Effect<A, E | CitationSafetyLimitExceeded | CitationAdmissionFailure, EngineConstants>
```

`openCitationInvocation` does, in order: `admission.run` (permit, queue and
operation deadline), the stage deadline for `policy.operation`, a fresh Scope
that closes before the permit returns, a fresh text budget, a lazy lane and
session bound to that Scope, then `Effect.provideService(CitationInvocation,
...)`. The engine Layer applies it over its captured constants, so each of the
four public engine methods, and the extractor boundary, stays
`(request) => Effect<A, E>` with no requirements.

Budget semantics, stated as the change it is. Today a stage shares a budget
with its parent only if a budget was in Context when the stage was installed;
otherwise each run makes a fresh one. After: one invocation, one budget,
always, read at call time.

That requires removing every install-time budget lookup, because
`Effect.serviceOption` adds nothing to the requirement channel and a hoisted
install would silently find no budget:

| Site | Hoisted without the change |
| --- | --- |
| `captureCitationTextReservation`: `C/RegexInput.ts:209` (feeds job preparation and the tokenizer source), `C/TokenContext.ts:130`, `C/ExtractionSelection.ts:165`, `C/DiffWorker.ts:82`, `C/XmlWorker.ts:52` | accounting becomes a no-op |
| `serviceOption(CitationTextBudget)`: `C/MetadataComposition.ts:209`, `C/Rendering.ts:185`, `C/PythonRepr.ts:131`, `C/ResourceCorrection.ts:117`, `C/NativeRendering.ts:21`, `C/CourtLookup.ts:98` | each call gets a fresh full budget |

`captureCitationTextReservation` is deleted. Each site reads
`(yield* CitationInvocation).budget`, which is a hard requirement the compiler
tracks. A Biome GritQL rule forbids `serviceOption(CitationTextBudget)` and
`serviceOption(CitationOperationAdmission)` under `C/`.

The install-time guard `enclosing.maximum > limits.producedTextUtf16` and its
`EnclosingRefusal` test sites are removed with the capture: one policy is
decoded once per engine.

Admission. The same treatment applies to nested admission. These sites capture
`CitationOperationAdmission` at install and call `run` on it; today they get
the pass-through view, and hoisted they would get the real admission and take
a second permit: `C/Tokenizer.ts:165, 277`, `C/ExtractionLoop.ts:239, 248`,
`C/ExtractionSelection.ts:163, 269`, `C/ReferenceTokenExtraction.ts:322`,
`C/PreCaseMetadata.ts:163`, `C/PostCaseMetadata.ts:206`,
`C/PinExtraction.ts:138`, `C/CaseMetadata.ts:300`, `C/LawMetadata.ts:224, 275`,
`C/JournalMetadata.ts:179`, `C/AnnotationEntry.ts:128`. Each nested `run` is
removed, `captureCitationOperationChildren` is deleted, and the stage tree is
installed in a Context that does not contain `CitationOperationAdmission`, so
a missed capture fails at engine construction instead of deadlocking a
request.

Nested stage deadlines are removed too. The review confirmed they have the
same duration as the outer one and start later, so the outer always fires
first and already carries the operation label.

### 3.2 `CitationNativeLane`

The first design held a regex lease for the whole request. That starves the
request's own Diff and Xml processes, which draw on the same total ceiling
(`C/NativeAdmission.ts:153-157`): with one operation the request waits on
itself, and with two, overlapping markup requests wait on each other. The lane
fixes the unit of account instead of the timing.

```ts
export class CitationNativeLane extends Context.Service<CitationNativeLane, {
  // Start a child in this invocation's lane. Any process already in the lane
  // is retired, with confirmation, first.
  readonly start: (
    kind: "regex" | "diff" | "markup",
    command: ChildProcess.Command
  ) => Effect.Effect<CitationOwnedNativeProcess, CitationNativeProcessFailure | CitationSafetyLimitExceeded>
  readonly snapshot: Effect.Effect<{ started: number; confirmed: number; occupied: boolean }>
}>()($I`CitationNativeLane`) {}
```

Contract:

1. A lane is one unit of the native `active` count, acquired from the existing
   shared admission on the invocation's first native need and held until the
   invocation's Scope closes. An invocation that starts no child takes none.
2. At most one process is alive in a lane. `start` first retires the current
   occupant and waits for confirmed death, then starts the next.
3. The lane's unit returns to the admission only after the last occupant's
   confirmed retirement. Unconfirmed retirement quarantines, as today.
4. Acquisition is uninterruptible and registers its finalizer before the OS
   spawn: release the unit if no process record exists, retire if one does.
   This closes the gap where a quarantine between acquire and start would
   strand a lease with no record.
5. Admitted operations never exceed `concurrentOperations` and each needs at
   most one lane, so an invocation never waits for a lane behind another. The
   process bound is unchanged: at most `concurrentOperations` children alive.

The Diff and Markup workers stay one process per job. They start through
`invocation.lane.start` instead of acquiring their own lease, and they keep
their own retirement after each job. The Recognizer sits behind a different
boundary and keeps its own lease.

### 3.3 `CitationRegexSession`

```ts
export class CitationRegexSession extends Context.Service<CitationRegexSession, {
  readonly evaluate: (job: PreparedRegexJob) => Effect.Effect<Uint8Array, CitationRegexExecutionFailure>
  readonly snapshot: Effect.Effect<{ jobs: number; state: "absent" | "idle" | "killed" }>
}>()($I`CitationRegexSession`) {}
```

Contract:

1. No process exists until the first `evaluate`.
2. When the session has no live process, `evaluate` calls
   `lane.start("regex", ...)` and waits for `Ready` under the startup timer.
   That is the first job, and any job after another kind of process used the
   lane. A plain-text request therefore spawns once; a markup request spawns
   once more for each time Diff or Markup work interleaves.
3. Jobs are serialized by a one-permit semaphore. The review confirmed no
   regex runs concurrently within a request today.
4. Each job, inside one job timer: write the frame, wait for `Started(k)`, wait
   for the terminal reply. The write is inside the timer because a large frame
   written to a stuck worker would otherwise block until the operation
   deadline.
5. The process is retired through `process.retire` on **any** exit of that
   wait other than success: timer expiry, interruption, a protocol violation,
   a reader failure. Retirement completes before `evaluate` returns. This
   holds for a timeout because `Effect.timeoutOrElse` is a `raceFirst` that
   awaits the interrupted loser, and the retirement's own bounded wait runs in
   a fresh fiber that the pending interrupt does not cut short (both checked
   in the reference and in `C/NativeProcess.ts:269`).
6. After a deadline or violation the session is `killed` and every later
   `evaluate` fails with the same closed failure. It does not respawn. A
   retirement that only yields the lane leaves the session `absent`, and it
   may start again.
7. Failures raised by the session itself (startup, cleanup deadline) carry
   `invocation.policy.operation`, not an evaluator's label.

### 3.4 Installed stages

```ts
// C/MetadataComposition.ts, reworked
export const makeCitationMetadataOperation: <Request, Patch, E>(
  limits: CitationEngineLimits,
  prepare: (request: Request) => Effect.Effect<Patch, E, CitationInvocation>
) => Effect.Effect<{
  readonly run: (request: Request) => Effect.Effect<readonly [Patch, number], E, CitationInvocation>
}, never, EngineConstants>
```

Install happens once; a parent installs its children in its own install body
and closes over their `run`. `run` no longer admits, times, makes a budget or
opens a Scope. Installs stay under the existing operation-label providers
(`C/SourceDocument.ts:148`, `C/SourceAnnotation.ts:197`,
`C/AnnotationEntry.ts:271`), so failure labels are unchanged.

Sharing. The review confirmed installed objects hold no per-request mutable
state: token objects, the tokenizer's counter and list, and the loop's models
are created inside `run`. The one exception is the Markup worker's private
semaphores (`C/MarkupWorker.ts:63-68`), which become engine-wide if the Xml
worker is hoisted; they are replaced by the lane's one-occupant rule.

### 3.5 Installed regex evaluators and tokenizer

`makeCitationRegexWorker` splits. The engine-constant half (limits, runtime,
descriptor registry, job preparation, control-frame preflight) becomes an
evaluator installed once per call site and operation. The per-request half is
the session.

```ts
export const installCitationRegexEvaluator: (
  limits, runtime, bindings: CitationOwned<ReadonlyArray<CitationRegexPatternDescriptor>>, engine?
) => Effect.Effect<{
  readonly evaluate: (pattern, source, flags, maximumMatches?, mode?) =>
    Effect.Effect<RegexEvaluation, CitationRegexExecutionFailure, CitationInvocation>
}>
```

`evaluate` binds the descriptor, prepares the job (reserving source text on
`invocation.budget`) and calls `invocation.regex.evaluate`. Call sites:
`ContextMatcher`, `MetadataStrings`, `CaseNameScan`, `CaseNameProcess`,
`StopWords`, `HtmlCaseName`, `HtmlDiscovery` (once for extract, once for
annotate), `GeneratedReferences` (two), `AnnotationWrap`, and the tokenizer.

The tokenizer splits the same way: `installCitationTokenizer(owned)` builds
ordering, tries, recipes and its evaluator once; `tokenize(source)` holds only
request state and requires `CitationInvocation`.

Until the worker goal lands, `invocation.regex.evaluate` is implemented on
protocol v2: one process per job through the existing owner. The binding and
hoisting slices therefore change no process behavior.

## 4. Guarantees, before and after

| Guarantee | v2 mechanism | v3 mechanism |
| --- | --- | --- |
| A catastrophic regex cannot hold the parent | child per evaluation, parent timer, SIGKILL | child in the invocation's lane, parent timer per job, SIGKILL |
| A slot is not reused before the process is gone | lease released only on confirmed retirement | lane occupant retired with confirmation before the next start; lane unit released only after the last confirmed retirement |
| At most `concurrentOperations` children alive | lease count | one lane per admitted operation, one occupant per lane |
| Unconfirmed retirement stops new native work | quarantine refuses acquisitions | unchanged |
| Cancellation cannot skip cleanup | `withCitationNativeProcess` finalizer | retire on any non-success exit of a job, and in the lane's Scope finalizer |
| A claimed lease always has an owner | wrapper releases an unused permit | lane finalizer registered before spawn |
| A late or forged reply cannot be accepted | exact frame count and EOF | sequence number, exact tag order, no frame while idle; any deviation kills |
| Text of one request is not visible to another's process | separate processes | unchanged |
| The worker validates what it runs | re-derives the program against the startup descriptor | re-derives against the per-job descriptor |

What weakens, all within one request:

- Jobs share a process, so an engine bug that corrupts memory in job *k* could
  affect job *k+1*. They already share a request, a budget and a result.
- v2 consumes a result only after the worker's acknowledged retirement
  (`C/Tokenizer.ts:151-152`). v3 consumes each result while the worker is
  alive and idle. The result is complete, bounded and validated at that point;
  what is lost is the ordering "process gone, then result used".

What strengthens: a job's bound no longer includes spawn time under host load,
and a lease can no longer be stranded between acquire and start.

Proof obligations for the worker goal, each against a real process:

1. The deadline fires on a catastrophic pattern while the parent stays
   responsive, and the process is confirmed dead before `evaluate` returns.
2. A job after a killed job fails closed without a spawn.
3. A wrong sequence, an early EOF, an oversize frame and a frame while idle
   each kill.
4. Interruption during `Sent` and during `Running` kills.
5. A markup request that interleaves regex, Diff and Xml work completes under
   the 1 and 1 policy, with one process alive at a time.
6. Two concurrent markup requests complete under the 2 and 2 policy.
7. A quarantine between lane acquisition and start strands nothing.
8. Started equals confirmed on every path.

Test clock. The manual clock fixture wakes every sleep equal to
`regexDeadline` on one trigger (`test/CitationNativeSpawner.fixtures.ts:294-308`),
so the startup timer and the job timer would fire together. The fixture
becomes sleep-counting so a test can expire one timer and not the other.

## 5. Measurement

One fixture, the ten-call bun cohort of `CitationCanonicalFullSpan`.

- Counts are the gate, because they do not move with host load: child
  processes started, metadata-operation installs, configuration detaches,
  tokenizer builds, regex evaluator constructions. Collected by a span
  recorder (`Tracer.make` plus `Effect.withTracer`) on the existing span names
  and by the observed spawner.
- Wall time is reported beside the counts with the host load, and taken on a
  remote worker for the record.

| Count per ten plain-text calls | Baseline | After install-once | After worker v3 |
| --- | --- | --- | --- |
| Regex processes started | 291 | 291 | 10 |
| Metadata-operation installs | 15 + 14 per call | 15 | 15 |
| Configuration detaches (report snapshots excluded) | 2 + 8 per call | 1 | 1 |
| Tokenizer builds | 1 per call | 1 | 1 |
| Regex evaluator constructions | per token | 12 | 12 |

The baseline column comes from the source read and the capture; the first
slice replaces it with recorded numbers, and adds a markup row.

## 6. Test churn to budget

- 86 assertions on exact `{ spawned, confirmed }` counts and about 100 call
  sites of `assertCitationRegexRuntimeReleased` change meaning with v3.
- The fake worker fixture sends `Started` on stdin end and must speak v3.

  `EnclosingRefusal`; both go with the binding slice.
