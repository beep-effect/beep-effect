# ADHD exploration

Thirty isolated proposals for complementary use of AO and Beep, followed by editorial scoring and three deepened experiments. Scores: novelty 35%, viability 40%, fit 25%; these are judgments, not measurements.

The proposal pool preserves speculative ideas, including rejected assumptions.
Read **Traps and required adaptations** before using any candidate; the corrected
focus plans supersede the original focus prose.

## Challenge the model

- **competitor-1** [N8 V7 F9; 7.85] Run NVIDIA Auto Ontology as an adversarial 'shadow ontologist' whose auto-induced classes are treated as attack hypotheses against Beep's hand-designed schemas, never as candidates for adoption.
- **competitor-3** [N7 V2 F5; 4.50] Point Auto Ontology at Beep's own Effect schemas and repo-cli codebase, and diff what it induces against what Beep intends: the gap list is the backlog of undocumented semantics.
- **competitor-5** [N8 V8 F9; 8.25] Use Auto Ontology only to propose competency questions and edge-case fixtures, never classes, so that its whole output becomes Beep's test suite rather than Beep's model.
- **biology-6** [N7 V5 F7; 6.20] Horizontal gene transfer of design patterns: harvest small reusable motifs from NVIDIA's auto-generated ontologies, such as recurring property bundles and relator shapes, and transplant only those into Beep's schema-first LiteralKit and Class building blocks, never whole hierarchies.

## Control admission

- **competitor-2** [N5 V7 F8; 6.55] Make every auto-induced concept stay in a quarantined 'unadjudicated' evidence tier, tagged with its induction run, model and input hash, and promote it into the Beep T-Box only after an OntoClean or foundational audit passes.
- **biology-1** [N5 V6 F8; 6.15] Thymic negative selection for extracted classes: every class an Auto Ontology-style pass proposes has to survive exposure to Beep's existing schemas and foundational-audit rules before it is admitted, and proposals that react against core identity criteria are killed.
- **biology-3** [N6 V6 F8; 6.50] Speciation by reproductive isolation: let NVIDIA-induced schemas evolve in a quarantined niche graph that can only interbreed with Beep's canonical ontology through SSSOM mappings that pass a fitness test on competency questions.
- **biology-4** [N5 V3 F7; 4.70] Quorum sensing for promotion: a candidate relation becomes canonical only once enough independent evidence carriers (documents, agents, extraction runs) emit the same signal above a concentration threshold.
- **logistics-2** [N4 V3 F6; 4.10] Relation suggestions are cube-built onto pallets and enter the Beep kernel only when a pallet reaches a minimum of distinct evidence sources.
- **regulator-4** [N6 V5 F7; 5.85] Leave every NVIDIA-proposed class that fails Beep schema decode as an expiring untyped proposal, and require any agent utterance that touches it to carry the marker unadmitted.
- **on_call-3** [N8 V7 F8; 7.60] Beep and NVIDIA share one refusal token for a denied class, and a tool call typed against that token cannot be retried on the other stack.
- **on_call-6** [N5 V1 F4; 3.15] A tool result that bears an NVIDIA-sourced field is a read-only effect, and the only writable agent effect is a successful Beep schema decode.

## Preserve evidence and expose gaps

- **competitor-4** [N7 V7 F9; 7.50] Treat disagreement between the two stacks as the agent-facing signal: when NVIDIA's induced relation and Beep's declared relation conflict, show agents the conflict with both evidence chains instead of picking a winner.
- **competitor-6** [N8 V8 F10; 8.50] Deliberately feed Auto Ontology poisoned or contradictory corpora, such as superseded filings or retracted claims, to measure whether it smears stale evidence into current concepts, then build Beep's temporal and retraction semantics around the exact failure modes found.
- **regulator-1** [N7 V2 F5; 4.50] Bind cross-stack agreement to identical source-span byte ranges, and quarantine any shared class label whose spans differ as a false concordance.
- **regulator-2** [N9 V9 F9; 9.00] Run a set of NoHome questions that sit outside both ontologies and require each stack to return a typed refusal naming the missing class.
- **regulator-3** [N7 V5 F8; 6.45] Insert one known-false triple into a corpus both stacks read, and demand a refusal that cites the exact span that would have to be wrong.
- **regulator-5** [N7 V8 F9; 7.90] When NVIDIA completes a relation that Beep’s evidence marks unknown, write a gap-fill quarantine record and keep the unknown state intact for downstream proofs.
- **on_call-5** [N7 V3 F6; 5.15] Every agent answer carries a Beep fact-clock and an NVIDIA score-clock, and the score-clock's type cannot outvote the fact-clock when refresh budget hits zero.

## Retain review decisions

- **biology-2** [N9 V8 F9; 8.60] An adaptive-immunity memory ledger: each human or agent rejection of an auto-induced term becomes a stored antibody (a pattern plus its evidence span) that fires on the next run before the term reaches the T-Box.
- **logistics-4** [N7 V7 F8; 7.25] An axiom an agent bound and then failed on evidence integrity ships back to the NVIDIA generator as an RMA with a reason code and stays quarantined until the return is closed.

## Operate and recover

- **biology-5** [N7 V2 F5; 4.50] Apoptosis signaling for decaying concepts: every ontology term carries a viability signal fed by agent query hits and evidence refreshes, and it self-deprecates through a KGCL obsoletion event when the signal starves.
- **logistics-1** [N6 V5 F6; 5.60] NVIDIA class proposals wait in a perishable receiving queue and are scrapped at the dock when their dwell clock expires before Beep's kernel unloads them.
- **logistics-3** [N8 V3 F7; 5.75] An agent query that misses a type posts a kanban card, and NVIDIA Auto Ontology manufactures only that class plus its immediate neighbors for immediate consumption.
- **logistics-5** [N6 V4 F6; 5.20] The shared ontology terminates at a neighborhood cross-dock, and the last mile is one Schema delivered to one service-contract address, with a decode error counted as a missed stop.
- **logistics-6** [N6 V5 F6; 5.60] Pending agent type-demands accumulate as pick tickets and release as one wave, so a single walk of the NVIDIA ontology fulfills the wave.
- **regulator-6** [N6 V7 F8; 6.90] Attach every ontology refresh to two receipts—an engineering receipt for schema and certificate changes, and an operational receipt for the generation run—and block the refresh when a prior proof certificate is no longer valid.
- **on_call-1** [N7 V2 F5; 4.50] Page only when an agent commits a side effect on a fact the two ontologies identify differently; bare disagreement is a morning digest.
- **on_call-2** [N6 V2 F5; 4.15] NVIDIA-induced classes are citations-or-die leases, and the only type allowed to survive a restart is a decoded Beep schema.
- **on_call-4** [N7 V8 F8; 7.65] Each stack holds immutable canary facts it is forbidden to repair, and a moved canary pages that stack's owner alone.

## Shortlist

1. **regulator-2 — 9.00:** refusal evidence tests both integrity and usefulness.
2. **biology-2 — 8.60 — ★ non-obvious viable pick:** reviewed rejection memory can reduce repeated work without treating rejection as factual negation.
3. **competitor-6 — 8.50:** stale-evidence laundering directly probes temporal and provenance value. Adapt arbitrary corpora to supported warehouse metadata.

Competitor-5 (8.25), generating competency tests rather than accepting classes, is the secondary candidate.

## Traps and required adaptations

- competitor-3 and logistics-3 assume general code/document induction or arbitrary on-demand class manufacture that AO does not supply.
- biology-4 and logistics-2 mistake counts for independent evidence.
- biology-5 and on_call-2 confuse usage, age or process lifetime with semantic validity.
- regulator-1 makes identical spans a necessary/sufficient identity test; neither holds.
- on_call-1 waits until harmful effects occur before detecting an identity problem.
- on_call-6 treats successful decode as write authorization.
- on_call-5 invents a shared clock/score semantics without a contract.
- competitor-2, biology-1 and regulator-4 need semantic review in addition to syntactic decode. Admission must not imply truth.
- The logistics metaphors require translation to explicit source versions, state transitions and consumer contracts; their language is not an implemented architecture.

## Corrected focus plans

These plans incorporate the parent review of the original focus proposals. They
are proposed experiments, not existing services or measured results.

### Evidence-bound refusal

Pilot 40 versioned competency questions covering answerable, partially answerable
and unsupported cases, including lexical decoys. Use independently reviewed gold
labels and record annotator disagreement. Distinguish explicit abstention, valid
empty answers and execution failures. Partially answerable questions may validly
abstain under a declared policy; include those in the precision denominator.
Compare equal-information arms with and without a common typed answer contract.
If removing the contract removes its advantage, that supports contract causality,
not ontology superiority. Do not assume AO lacks a native refusal type without
tracing the actual output contract. Scratchpad claim models are design precedents,
not shipped capabilities. The pilot validates measurement; a later study needs
sample-size justification before claims about small percentage-point improvements.

### Versioned rejection memory

Start with pure fixtures and a decision function: unchanged reviewed candidates
are withheld with their reason; unseen candidates remain unknown; meaningful new
evidence permits reconsideration with history retained. Compare stateless
regeneration and a string-only denylist. Revision changes never imply acceptance;
cosmetic edits must not trigger review storms. Store source identity, revision,
review basis and evidence snapshot separately. Fixture success proves this contract
only; a later trial must measure repeat-review burden and wrongful suppression.
An AO certification flag does not establish enforcement or an accepted Beep claim.

### Stale-evidence laundering

Use conflicting metric versions and dependent copies in supported warehouse
metadata. Verify view ingestion before using views as fixtures; project unsupported
document surfaces consistently into both arms. Compare AO raw, AO given the same
status information, Beep with gold labels and Beep with extracted labels. Keep the
query generator and executor fixed. Trace retrieved version, SQL lineage and cited
version separately. Score as-known-at-time and retrospective-corrected answers
against different keys. Pre-register a practical margin and confidence interval:
a gap below five percentage points is not an equivalence result. Report annotation
cost and useful answer coverage alongside leakage; successful decode proves
neither truth nor authorization.

The [ranked portfolio](RESEARCH.md#ranked-experiment-portfolio) specifies sequencing
and adoption criteria. No thresholds here have been tested.
