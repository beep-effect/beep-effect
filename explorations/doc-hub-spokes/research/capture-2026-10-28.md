### 1. The package question that started it

- "so @beep/markdown & @beep/md serve different purposes? should they?"
- "but couldn't @beep/markdown serve the same purpose as @beep/html as it relates to @beep/md?"
- Originally leaning toward merging `@beep/markdown` into `@beep/md` ("I really liked the
  structure, documentation & quality of the ~/YeeBois/references/effect/effected packages ...
  I didn't want to depend on the maintainer of that project since it is a new & not so stable
  one"). A message to the effected-promotion session was drafted and then withdrawn.
- Reframed mid-conversation: "if @beep/md stays as an underlying AST with projections to
  markdown, html, pandoc, etc wouldn't it make more sense to remove [the writers and parse
  bridge] from @beep/md?"
- Ruling (not yet sent): no merge, no single AST. Hub and spokes. `@beep/md` is the
  notation-free semantic hub; markdown, html, lexical, pandoc are spokes that depend on it.
  Today lexical and pandoc point the right way; markdown and html point the wrong way.
  `Md.render` (the 1,800-line string writer) becomes a projection `Doc.Document -> Root`
  serialized by `Markdown.stringify`; `Md.syntax`/`Md.parse` move to `@beep/markdown` (the
  D-50 remedy taken as a rule); `Md.html` moves to `@beep/html`. The hub keeps model,
  behavior, `SafeDocument`, `UrlPolicySpec`.
- Name: "I'm questioning the name of @beep/md as a result of this discussion." Candidates
  `@beep/doc` (namespace `Doc`) or `@beep/document`; neither taken; about 560 import sites;
  do it as phase 0 so imports churn once. Undecided between the two.
- Open: whether `SafeDocument` restates the heading-order rule on the hub tree or each spoke
  proves its own projection (the scratch program's `conform -> enforceSafeHtml` already does
  the latter). Recommendation on the page: each spoke proves its own projection.

### 3. The thesis, in Benjamin's words

- Discovered the effected packages' codecs, then fx0 (vercel-labs/fx0, libfx) "who's best
  trait is letting the llm simply just write pure html resulting in extreme speed."
- Raw HTML string: speed, quality, no restraints; but no certainty beyond valid HTML, no
  provable theme/semantic/accessibility consistency, no deterministic feedback.
- AST structured output (JSON component union): certainty, consistency, provable, semantic
  information to the LLM; but a giant schema in context and poor streaming.
- professional-desktop already does: structured output -> validate -> find issues -> feed
  back -> agent repairs only the invalid parts (`packages/agents/server/src/AssistantTurn/BlockRepair.ts`,
  JSON Patch, 2 attempts).
- "Now imagine you didn't have the restraints of either system but just the best parts of
  both ... all it would require is codec where the plain string could be parsed into
  @beep/html, @beep/pandoc, @beep/lexical, etc. using error accumulation you could in theory
  get the exact issues of the html string that violate whatwg html semantics with exact line
  column precision ... You could even take this so far as to use something like
  @opencode/codemode to enforce restraints on the inline javascript of html strings."
- "Does my idea seem sound? ... As an agent ... which would you prefer, the constrained
  structured output way, the pure string way? or what I'm proposing?" Answer on the page:
  the third, on condition that diagnostics are few, ranked, actionable, policy stated up
  front, repair by span.

### 4. One step further: the typechecker for work product

- "Imagine you're a lawyer creating a patent ... what takes the time in my estimation is the
  little things that if a semantic model & ontology with axioms existed to represent that &
  validate it with something like the 'third option' then I think this will have solved one
  of the hardest problems in AI right now. How do we make a typechecker for ... 'a compiler
  front end for agent output'."
- "The hardest part of getting LLM agents to be as game changing as they are for coding in
  other domains is fundamentally this problem of backpressure. There are no mechanisms to
  provide deterministic actionable feedback to LLM's when creating work product for various
  domains."
- Page section 7: four tiers of rules (formal; structural over an ontology; substantive
  judgment; behavioral prior), one finding shape for every judge (span, rule, severity,
  evidence, judge, confidence), obligations and holes as in proof assistants, five separable
  parts (notation, codec, model, profile, judges), ledgers under everything.
- Tier 3/4 enforcement list from Benjamin: agentic review loops (cross provider), review
  panels, decision/classifier models (TypeSafe System One, docs.typesafe.ai), confidence
  scores, provenance requirements with reasoning traces, source validation (does the link
  resolve, approved source, does it contain the quoted content), attorney approval and
  inline span-level feedback (an artifact comment anchored to a paragraph has the shape of a
  diagnostic).
- Correction from Benjamin: "Fundamentally these are totally in the scope of ontology. X
  must be true for Tier 3/4 agent outputs ... this would be process ontology." Admissibility
  of the process is axiomatizable over a provenance record (BFO occurrents, PROV-O); the
  content judgment stays probabilistic.
- "Think big though, I don't want us to build something that only works for lawyers or
  engineers ... a core foundation that allows us to build upon ... configure what
  specification & semantic rules are enforced for those codecs ... taking something like
  pandoc or docx codecs & adding domain specific axioms & rules to those codecs for patent

- DSL idea: a DDD-shaped declarative class DSL like Alchemy's `@alchemy.run/domain`

### 5. What the panel and the research said (digest on the page, section 8)

- Nobody has built the whole thing. Unclaimed after ~15-20 searches per area: a typed loss
  ledger with a stale-aware source map; a deterministic located document rule with measured
  precision used as an agent repair signal or reward; obligations discharged by witnesses
  over PROV-typed records with findings returned to the producer.
- All six models: tiers 3/4 do not reduce to provenance checks. Auditability, not
  correctness. Frame as liability engineering (standard of care, ALCOA+, Part 11); the
  ledger is the signing attorney's own 37 CFR 11.18(b) reasonable-inquiry evidence (GLM).
- Self-attestation is the hole: runtime-minted witnesses like `SafeHtml`, orchestrator
  signatures, capped judge attempts (Opus + provenance sweep, independently).
- A second provider is not independence. One finding shape is for transport only: add
  repair-applicability (rustc/Biome), coverage, cascade; obligations declare which judge
  classes may discharge them (Grok's lattice). DSL is a facade over typed IRs (OWL fragment
  for vocabulary, SHACL/Datalog for obligations, workflow policy for process, versioned
  evaluator contracts for probabilistic judges); rule bodies must be data, never closures;
  obligations never as OWL axioms. Span repair not shown to beat regeneration; deterministic
  fix first, then model-proposed span edits applied by a splicer, then regeneration.
- New ideas: coverage map as typed output (Muse); bitemporal rules and findings (Kimi); the
  agent does not own the goal, frozen scope obligation (Grok); frame conditions for repairs,
  Dafny `modifies` (Astra); Goodhart-test every rule in CI (GLM); antecedent basis has a
  tier-3 tail per MPEP 2173.05(e) (Astra).
- Corpora and bars: PEDANTIC arXiv 2505.21342 (14.5k claims, located §112(b) reasons,
  antecedent basis ~36%, LLM baseline ~55-57%); Tricorder admission bar (<10% effective false
  positives advisory, ~0 blocking, hand-labelled sample before admission); "Vibe Patenting"
  judge-vs-attorney correlation 0.83 figures / 0.04 prosecution resilience / 0.10 claim
  strength; Effect v4 `SchemaRepresentation` as the serializable-AST carrier.
- Two-week experiment, consolidated with pre-registered kills: (1) measure fold losses on
  real claim sets, three tier-1 rules via mutation corpus + PEDANTIC spans, kill below the
  Tricorder bar; (2) four repair arms (JSON Patch blocks; Markdown + prose findings +
  regenerate; Markdown + located findings + regenerate; Markdown + located findings + span
  repair), kill if <60% converge in three rounds or oracle-driven drafts are measurably
  narrower (vacuity test); (3) red-team the novelty gate with an agent told only the gate.
- Repo primitives the brief missed: `@beep/provenance` (`TextAnchor`, `VerifiedTextAnchor`,
  verification receipt) and `@beep/epistemics` (`EvidenceSpan`, `ClaimGate`,
  `ClaimGateViolation`).
