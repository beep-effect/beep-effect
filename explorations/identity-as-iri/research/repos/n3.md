# 2. Term/quad factory design

N3 exposes a `DataFactory` singleton with `namedNode`, `blankNode`, `variable`, `literal`, `defaultGraph`, `quad`, `triple: quad`, `fromTerm`, and `fromQuad`: `.repos/n3/src/N3DataFactory.js:14-25`. The package index re-exports `DataFactory`, `Term`, `NamedNode`, `Literal`, `BlankNode`, `Variable`, `DefaultGraph`, `Quad`, `Triple`, `termFromId`, and `termToId`: `.repos/n3/src/index.js:28-56`.

The base `Term` stores an internal `id`, returns that `id` as `value`, and treats two N3-created terms as equal when their `id` strings match: `.repos/n3/src/N3DataFactory.js:28-48`. If the other term is not an N3 `Term`, equality falls back to `termType` and `value`: `.repos/n3/src/N3DataFactory.js:39-48`. `Term.toJSON()` returns only `termType` and `value`: `.repos/n3/src/N3DataFactory.js:56-62`.

`NamedNode` is a thin `Term` subclass whose `termType` getter returns `NamedNode`: `.repos/n3/src/N3DataFactory.js:66-72`. The tests confirm that a `NamedNode` created from `http://example.org/foo#bar` has the same string as both `value` and `id`: `.repos/n3/test/NamedNode-test.js:34-40`, and equals both another N3 `NamedNode` with the same IRI and a plain RDF/JS-shaped object with `termType: "NamedNode"` and the same `value`: `.repos/n3/test/NamedNode-test.js:42-50`.

`Literal` is string-encoded internally. Its `value` getter slices the literal id between the opening quote and the last quote: `.repos/n3/src/N3DataFactory.js:81-84`. Its `language` getter detects `@...` after the closing quote and lowercases the language value: `.repos/n3/src/N3DataFactory.js:86-94`. Its `direction` getter detects the RDF 1.2 language direction suffix after `--`: `.repos/n3/src/N3DataFactory.js:96-103`. Its `datatypeString` getter returns an explicit datatype after `^^`, otherwise `xsd:string`, `rdf:langString`, or `rdf:dirLangString` depending on the suffix: `.repos/n3/src/N3DataFactory.js:105-119`. Literal equality compares N3 literal ids for N3-created literals, and otherwise compares `termType`, `value`, `language`, compatible `direction`, and datatype IRI: `.repos/n3/src/N3DataFactory.js:121-134`.

`BlankNode` prepends `_:` to the internal id and strips that prefix for `value`: `.repos/n3/src/N3DataFactory.js:147-161`. The tests pin `BlankNode("b1")` to `value: "b1"` and `id: "_:b1"`: `.repos/n3/test/BlankNode-test.js:34-40`.

`Quad` is also a `Term`, but its own `id` is initialized to the empty string and it stores `_subject`, `_predicate`, `_object`, and `_graph` properties, defaulting the graph to the default graph: `.repos/n3/src/N3DataFactory.js:300-308`. Its getters return those stored components: `.repos/n3/src/N3DataFactory.js:315-329`. Quad equality is component-wise by each component's `.equals`: `.repos/n3/src/N3DataFactory.js:342-348`. `Triple` is an alias of `Quad`: `.repos/n3/src/N3DataFactory.js:350`.

The internal `.id` encoding is centralized by `termToId`: N3 `Term`s reuse `term.id`; external RDF/JS `NamedNode`s become their value string; blank nodes become `_:value`; variables become `?value`; default graph becomes `""`; literals become `"value"`, `"value"@lang`, `"value"@lang--direction`, or `"value"^^datatype`; quads become JSON stringified arrays of component ids unless nested: `.repos/n3/src/N3DataFactory.js:263-296`. `termFromId` reverses the convention by first character: falsy/empty means default graph, `?` means variable, `_` means blank node, `"` means literal, `[` means encoded quad array, and otherwise the value is a named node: `.repos/n3/src/N3DataFactory.js:204-260`.

The README claims RDF/JS conformance for `N3.DataFactory`, its created terms, and its triples/quads: `.repos/n3/README.md:437-453`. The tests exercise interop with `@rdfjs/data-model`: `fromTerm` preserves N3 terms by identity and converts RDF/JS-shaped named nodes, blank nodes, literals, variables, and default graphs into N3 terms that still compare equal to the RDF/JS originals: `.repos/n3/test/N3DataFactory-test.js:206-259`. `fromTerm` and `fromQuad` also convert RDF/JS quads into N3 `Quad`s that compare equal to both the N3 quad and the RDF/JS quad: `.repos/n3/test/N3DataFactory-test.js:268-291`.

# 3. Prefix handling

Parser prefix declarations are recognized in top-level parse state: `PREFIX` sets SPARQL style and falls through to `_readPrefix`; `@prefix` also returns `_readPrefix`: `.repos/n3/src/N3Parser.js:127-145`. At parse start, `_prefixes` is reset to a null-prototype object and `_` is reserved for blank-node labeling: `.repos/n3/src/N3Parser.js:1205-1212`.

`_readPrefix` requires a lexer token of type `prefix`, stores its value in `this._prefix`, and then expects an IRI: `.repos/n3/src/N3Parser.js:774-780`. `_readPrefixIRI` requires an `IRI` token, resolves it through `_readEntity`, stores `prefixNode.value` in `this._prefixes[this._prefix]`, calls the prefix callback with the prefix and `NamedNode`, and then expects declaration punctuation: `.repos/n3/src/N3Parser.js:782-789`.

Parser expansion is direct concatenation: when `_readEntity` sees token type `type` or `prefixed`, it looks up `this._prefixes[token.prefix]`, errors if missing, and creates `namedNode(prefix + token.value)`: `.repos/n3/src/N3Parser.js:167-186`. Tests verify both callback styles: prefix callbacks receive `a -> NamedNode("http://a.org/#")` and `b -> NamedNode("http://b.org/#")`: `.repos/n3/test/N3Parser-test.js:1328-1351`, and final parse callbacks can receive a prefixes object with resolved base IRIs: `.repos/n3/test/N3Parser-test.js:1371-1385`.

The lexer handles prefix and prefixed-name tokenization separately. After `@prefix` or `PREFIX`, it uses `_prefix` to emit a `prefix` token; otherwise it uses `_prefixed` and unescapes the local component: `.repos/n3/src/N3Lexer.js:365-377`. `_prefixed` permits PN_LOCAL-like content including percent escapes, reserved escape sequences, non-leading colons, and dot-containing locals with special streaming handling: `.repos/n3/src/N3Lexer.js:47-48`, `.repos/n3/src/N3Lexer.js:371-376`. Tests pin non-leading colons, reserved escapes, and dot-containing locals: `.repos/n3/test/N3Lexer-test.js:162-174`, `.repos/n3/test/N3Lexer-test.js:183-194`.

Writer registration starts in the constructor. In non-line mode, `_prefixIRIs` is initialized and constructor `options.prefixes` are passed to `addPrefixes`: `.repos/n3/src/N3Writer.js:55-65`. `addPrefix` is just a single-entry wrapper around `addPrefixes`: `.repos/n3/src/N3Writer.js:264-269`. `addPrefixes` is ignored when `_prefixIRIs` is absent, which is the line-mode path for N-Triples/N-Quads: `.repos/n3/src/N3Writer.js:271-275`, `.repos/n3/src/N3Writer.js:66-69`.

Writer registration accepts prefix IRIs as strings or terms, stores an IRI-to-prefix mapping in `_prefixIRIs`, writes `@prefix ${prefix}: <${iri}>.`, and rebuilds the contraction regex: `.repos/n3/src/N3Writer.js:277-305`. Tests verify prefix declaration output, prefixed-name use when possible, fallback to full IRI when locals contain slash-like suffixes, expansion of already prefixed strings, and disabling prefixes in N-Triples mode: `.repos/n3/test/N3Writer-test.js:268-297`, `.repos/n3/test/N3Writer-test.js:440-450`.

# 4. Writer prefixed-name generation and escaping

N3Writer's NamedNode path is `_encodeIriOrBlank`. For non-`NamedNode` terms it returns an existing `id` if present or `_:${value}`; for `NamedNode`s it optionally relativizes against `baseIRI`, escapes control/string characters in the IRI string, applies `_prefixRegex`, returns `<iri>` on no match, returns the already-prefixed string when the first regex alternative matched, or returns the registered prefix plus captured local name when the expanded-IRI alternative matched: `.repos/n3/src/N3Writer.js:145-166`.

Verbatim code:

```js
  _encodeIriOrBlank(entity) {
    // A blank node or list is represented as-is
    if (entity.termType !== 'NamedNode') {
      // If it is a list head, pretty-print it
      if (this._lists && (entity.value in this._lists))
        entity = this.list(this._lists[entity.value]);
      return 'id' in entity ? entity.id : `_:${entity.value}`;
    }
    let iri = entity.value;
    // Use relative IRIs if requested and possible
    if (this._baseIri) {
      iri = this._baseIri.toRelative(iri);
    }
    // Escape special characters
    if (escape.test(iri))
      iri = iri.replace(escapeAll, characterReplacer);
    // Try to represent the IRI as prefixed name
    const prefixMatch = this._prefixRegex.exec(iri);
    return !prefixMatch ? `<${iri}>` :
           (!prefixMatch[1] ? iri : this._prefixIRIs[prefixMatch[1]] + prefixMatch[2]);
  }
```

Source: `.repos/n3/src/N3Writer.js:145-166`.

The writer does not implement a general Turtle PN_LOCAL escaper. Its only local-name generation rule is the regex assembled by `addPrefixes`: `.repos/n3/src/N3Writer.js:293-303`.

Source: `.repos/n3/src/Util.js:1-3`.

The generated regex has two alternatives. The first alternative, `^(?:${prefixList})[^\/]*$`, recognizes an already-prefixed string using one of the registered prefix labels and any subsequent characters except `/`: `.repos/n3/src/N3Writer.js:301-302`. Because that branch returns `iri` unchanged when `prefixMatch[1]` is absent, N3 can emit an already-prefixed string as-is: `.repos/n3/src/N3Writer.js:163-165`; the test with input strings `a:bc` and `b:ef` confirms this behavior: `.repos/n3/test/N3Writer-test.js:290-297`.

The second alternative, `^(${IRIlist})([_a-zA-Z0-9][\\-_a-zA-Z0-9]*)$`, contracts expanded IRIs only when the local part starts with ASCII underscore/letter/digit and then contains only ASCII underscore, hyphen, letters, or digits: `.repos/n3/src/N3Writer.js:300-302`. This branch excludes `/`, `.`, `:`, `%`, Unicode PN_CHARS, and escaped PN_LOCAL reserved characters in generated output: `.repos/n3/src/N3Writer.js:300-302`. Tests confirm that locals such as `bc`, `ef`, `bhi`, `3a`, `_a`, and `a3` are emitted as prefixed names, while slash-containing suffixes such as `bc/de`, `b#e#f`, and `b#x/t` are emitted as full IRIs: `.repos/n3/test/N3Writer-test.js:276-287`, `.repos/n3/test/N3Writer-test.js:409-417`.

The writer's IRI/string escape regexes only cover quotes, backslash, tab, newline, carriage return, backspace, form feed, control characters, and surrogate pairs; they do not target PN_LOCAL punctuation such as `/` or `.`: `.repos/n3/src/N3Writer.js:12-18`. `characterReplacer` maps common escapes or emits `\u`/`\U` codepoint escapes for controls/surrogates: `.repos/n3/src/N3Writer.js:380-398`. Tests pin control/unicode escaping for literals/IRIs and show blank nodes are not escaped the same way: `.repos/n3/test/N3Writer-test.js:99-163`, `.repos/n3/test/N3Writer-test.js:357-366`.

Verbatim code:

```js
function characterReplacer(character) {
  // Replace a single character by its escaped version
  let result = escapedCharacters[character];
  if (result === undefined) {
    // Replace a single character with its 4-bit unicode escape sequence
    if (character.length === 1) {
      result = character.charCodeAt(0).toString(16);
      result = '\\u0000'.substr(0, 6 - result.length) + result;
    }
    // Replace a surrogate pair with its 8-bit unicode escape sequence
    else {
      result = ((character.charCodeAt(0) - 0xD800) * 0x400 +
                 character.charCodeAt(1) + 0x2400).toString(16);
      result = '\\U00000000'.substr(0, 10 - result.length) + result;
    }
  }
  return result;
}
```

Source: `.repos/n3/src/N3Writer.js:380-398`.

The parser accepts more prefixed-name syntax than the writer generates. Lexer escape replacements include `.`, `/`, `?`, `#`, `@`, `%`, and other reserved characters: `.repos/n3/src/N3Lexer.js:7-15`. `_prefixed` includes percent escapes and `\\[!#-\/;=?\-@_~]` reserved escapes in local names: `.repos/n3/src/N3Lexer.js:47-48`. `_unescape` replaces those escape codes before parser expansion: `.repos/n3/src/N3Lexer.js:421-451`. Tests confirm reserved escape tokenization, dot-containing local tokenization, and rejection of Unicode escape forms in prefixed names: `.repos/n3/test/N3Lexer-test.js:169-174`, `.repos/n3/test/N3Lexer-test.js:183-194`, `.repos/n3/test/N3Lexer-test.js:221-255`.

Worked example for `https://ns.beep.sh/ontology/Ontology.models/HttpUrl`: with a registered writer prefix `{ beep: "https://ns.beep.sh/" }`, `IRIlist` becomes the escaped namespace and `_prefixRegex` is equivalent to `^(?:beep:)[^\/]*$|^(https:\/\/ns\.beep\.sh\/)([_a-zA-Z0-9][\-_a-zA-Z0-9]*)$`: `.repos/n3/src/N3Writer.js:293-303`, `.repos/n3/src/Util.js:1-3`. The sample IRI is not already `beep:`-prefixed, so the first alternative cannot match: `.repos/n3/src/N3Writer.js:301-302`. The expanded-IRI alternative captures the namespace, but the remaining local would be `ontology/Ontology.models/HttpUrl`, which contains `/` and `.`, characters not allowed by `[_a-zA-Z0-9][\\-_a-zA-Z0-9]*`: `.repos/n3/src/N3Writer.js:300-302`. Therefore `_encodeIriOrBlank` takes the no-match branch and emits the full IRI form `<https://ns.beep.sh/ontology/Ontology.models/HttpUrl>`: `.repos/n3/src/N3Writer.js:163-165`.

If the registered prefix were instead `{ model: "https://ns.beep.sh/ontology/Ontology.models/" }`, the remaining local would be `HttpUrl`, which matches the generated local regex and would emit `model:HttpUrl`: `.repos/n3/src/N3Writer.js:290-302`. If the registered prefix were `{ ont: "https://ns.beep.sh/ontology/" }`, the remaining local would be `Ontology.models/HttpUrl`, and the dot/slash would still force full-IRI output: `.repos/n3/src/N3Writer.js:300-302`. N3Writer never generates `beep:ontology\/Ontology\.models\/HttpUrl`; escaped slash/dot local generation is absent from the writer code and only appears on the parser side as accepted input syntax: `.repos/n3/src/N3Writer.js:293-303`, `.repos/n3/src/N3Lexer.js:47-48`.

# 5. Literal handling

The factory creates language literals by lowercasing string language arguments and stores them as `"value"@lang`: `.repos/n3/src/N3DataFactory.js:372-377`. It also supports `{ language, direction }` and stores `"value"@lang--direction` with lowercased language/direction: `.repos/n3/src/N3DataFactory.js:378-381`.

When no datatype argument is supplied, the factory infers XSD datatypes for booleans and numbers: booleans become `xsd:boolean`, finite integers become `xsd:integer`, finite non-integers become `xsd:double`, and infinities become `INF`/`-INF` typed as `xsd:double`: `.repos/n3/src/N3DataFactory.js:383-399`. If the inferred or supplied datatype is empty or `xsd:string`, it stores a plain `"value"` literal; otherwise it stores `"value"^^datatype`: `.repos/n3/src/N3DataFactory.js:401-405`. Tests pin factory conversion for strings, language tags, datatypes, integers, doubles, infinities, NaN, booleans, and xsd:string normalization: `.repos/n3/test/N3DataFactory-test.js:34-100`.

The writer escapes literal lexical values before any datatype abbreviation decision: `.repos/n3/src/N3Writer.js:168-174`. It emits language and optional direction as `"value"@language--direction`: `.repos/n3/src/N3Writer.js:175-179`. Tests pin language tags, direction, artificial language tags, quotes, backslashes, tabs, newlines, carriage returns, backspace, form feed, and control-character escaping: `.repos/n3/test/N3Writer-test.js:65-163`.

In line mode, the writer only abbreviates `xsd:string` and otherwise emits datatyped literals: `.repos/n3/src/N3Writer.js:180-185`. In Turtle/TriG mode, it emits plain strings for `xsd:string`, unquoted `true`/`false` only for exact boolean lexical values, unquoted integers matching `/^[+-]?\d+$/`, decimals matching `/^[+-]?\d*\.\d+$/`, and doubles matching `/^[+-]?(?:\d+\.\d*|\.?\d+)[eE][+-]?\d+$/`: `.repos/n3/src/N3Writer.js:186-207`. Invalid lexical values fall through to `"value"^^datatype`: `.repos/n3/src/N3Writer.js:210-211`.

Tests pin canonical output for booleans, integers, signed integers, decimals, signed decimals, doubles, signed doubles, and fallback for invalid boolean/integer/decimal/double lexical values: `.repos/n3/test/N3Writer-test.js:165-252`. The datatype IRI itself is serialized by `_encodeIriOrBlank`, so datatype IRIs can use registered prefixes only if they pass the same writer prefix regex: `.repos/n3/src/N3Writer.js:210-211`, `.repos/n3/src/N3Writer.js:145-166`.

# 6. Streaming architecture

The high-level README says `N3.Parser` can parse Node streams as they grow and return quads as soon as ready: `.repos/n3/README.md:173-181`. It identifies `N3.StreamParser` as a Node stream and RDF/JS Sink implementation and notes dedicated `prefix` and optional `comment` events: `.repos/n3/README.md:184-205`.

`N3StreamParser` is a `Transform` whose readable side is object mode: `.repos/n3/src/N3StreamParser.js:1-10`. It creates an `N3Parser`, wires parser callbacks so quads are pushed downstream and prefixes are emitted as `prefix` events, then implements `_transform` and `_flush` by feeding chunks/end into the parser callbacks: `.repos/n3/src/N3StreamParser.js:11-37`. Its `import(stream)` method forwards upstream `data`, `end`, and `error` events into the transform: `.repos/n3/src/N3StreamParser.js:39-45`.

`N3StreamWriter` is a `Transform` with UTF-8 output and writable object mode: `.repos/n3/src/N3StreamWriter.js:1-8`. It wraps `N3Writer` around a dummy stream whose writes push text chunks, then implements `_transform` through `writer.addQuad` and `_flush` through `writer.end`: `.repos/n3/src/N3StreamWriter.js:10-18`. Its `import(stream)` forwards quads, end, error, and upstream `prefix` events; prefix events are applied by calling the wrapped writer's `addPrefix`: `.repos/n3/src/N3StreamWriter.js:21-28`.

# 7. DIAMONDS

Phase 1 PN_LOCAL escaper design should copy N3's parser-side acceptance model, not its writer-side contraction model. The lexer explicitly recognizes reserved escaped local characters with `\\[!#-\/;=?\-@_~]` and unescapes through a fixed replacement table: `.repos/n3/src/N3Lexer.js:7-15`, `.repos/n3/src/N3Lexer.js:47-48`, `.repos/n3/src/N3Lexer.js:421-451`. That maps directly to the handoff's Phase 1 requirement for a PN_LOCAL escaper and round-trip tests: `explorations/identity-as-iri/assets/identity-iri-fibration-handoff.md:380-385`.

Phase 1 should still keep N3's prefix registry shape: prefix declarations are data, parser state is a prefix map, expansion is `prefix + local`, and callbacks surface prefix facts as structured events: `.repos/n3/src/N3Parser.js:782-789`, `.repos/n3/src/N3Parser.js:179-186`, `.repos/n3/test/N3Parser-test.js:1328-1351`. That fits the handoff's registry-as-data and expand/contract codec direction: `explorations/identity-as-iri/assets/identity-iri-fibration-handoff.md:128-162`.

Phase 3 Turtle projection should adopt N3's branch discipline: only emit a prefixed name when a local-name rule says it is valid, otherwise emit a full `<IRI>` form. N3Writer does that with `_prefixRegex` and a full-IRI fallback: `.repos/n3/src/N3Writer.js:163-165`, `.repos/n3/src/N3Writer.js:293-303`. The difference for beep-effect is that our valid-local rule must include Turtle PN_LOCAL escaping for slash/dot locals or intentionally choose full IRI fallback, exactly as the handoff calls out: `explorations/identity-as-iri/assets/identity-iri-fibration-handoff.md:198-200`, `explorations/identity-as-iri/assets/identity-iri-fibration-handoff.md:337-348`.

For Phase 3 literals, N3's writer gives a good minimal policy: canonical unquoted booleans and numerics only when lexical forms match strict regexes, otherwise preserve the datatype explicitly: `.repos/n3/src/N3Writer.js:186-211`. This matches the handoff's Turtle projection requirement to keep canonical boolean literals and string escaping tests: `explorations/identity-as-iri/assets/identity-iri-fibration-handoff.md:346-348`.

For projection streaming, N3's `StreamParser`/`StreamWriter` pattern is a useful API precedent: the parser pushes quad objects and emits prefixes as side-channel events; the writer consumes quad objects and applies prefix events before serializing future quads: `.repos/n3/src/N3StreamParser.js:15-20`, `.repos/n3/src/N3StreamWriter.js:21-28`. Phase 3 can use the same separation for assembled ontology projections that need deterministic prefix declarations before streaming graph statements: `explorations/identity-as-iri/assets/identity-iri-fibration-handoff.md:394-401`.

The internal id idea is useful only as an implementation detail. N3 gets cheap equality for its own terms through string ids: `.repos/n3/src/N3DataFactory.js:39-48`, and it can convert RDF/JS terms back into canonical N3 terms with `termToId`/`termFromId`: `.repos/n3/src/N3DataFactory.js:263-296`. For beep-effect, that suggests an internal canonical key for identity/IRI interning, while preserving schema-first public terms and projections: `scratchpad/identity/README.md:12-24`.

# 8. ROUGH

Do not copy N3Writer's generated local-name regex as a Turtle PN_LOCAL escaper. It only generates locals matching `[_a-zA-Z0-9][\\-_a-zA-Z0-9]*`, so it misses valid PN_LOCAL features that its own lexer can parse, including escaped reserved characters and dot-containing locals: `.repos/n3/src/N3Writer.js:300-302`, `.repos/n3/src/N3Lexer.js:47-48`, `.repos/n3/test/N3Lexer-test.js:183-194`.

Do not treat "already prefixed strings" as a primary IRI model. N3Writer's first regex alternative allows a registered prefix followed by anything except `/`, and the encoder returns that string unchanged when the first alternative matches: `.repos/n3/src/N3Writer.js:301-302`, `.repos/n3/src/N3Writer.js:163-165`. The test that emits `a:bc b:ef <c:bhi>.` from string inputs is useful compatibility behavior, but beep-effect's D4 says references should be handles, CURIEs, or absolute IRIs rather than loose writer strings: `.repos/n3/test/N3Writer-test.js:290-297`, `explorations/identity-as-iri/assets/identity-iri-fibration-handoff.md:92-95`.

Avoid N3's narrow writer/parser asymmetry. The parser accepts dot locals and escaped reserved characters: `.repos/n3/src/N3Lexer.js:47-48`, `.repos/n3/src/N3Lexer.js:421-451`; the writer does not generate escaped PN_LOCAL output and falls back for dot/slash expanded locals: `.repos/n3/src/N3Writer.js:293-303`. For beep-effect, the Phase 1 escaper and Phase 3 Turtle projection should share one codec so parseable and printable CURIE/local-name rules stay aligned: `explorations/identity-as-iri/assets/identity-iri-fibration-handoff.md:380-401`.

Avoid unused-argument/helper drift. `addPrefixes` calls `escapeRegex(IRIlist, /.../, '\\$&')`, but `escapeRegex` only declares one parameter and hardcodes the regex/replacement: `.repos/n3/src/N3Writer.js:300`, `.repos/n3/src/Util.js:1-3`. That is harmless JavaScript compatibility, but it is not a pattern to copy into a typed Effect/schema-first codebase.

Avoid making literal structure depend on ad-hoc string parsing. N3's `Literal.value`, `language`, `direction`, and `datatypeString` derive structure from positions inside the internal id string: `.repos/n3/src/N3DataFactory.js:81-119`. That is compact, but beep-effect should keep literal/datatype/language as schema-modeled fields and derive serialization at the Turtle projection boundary.

Avoid assuming the vendored source is the same version as the declared dependency. The inspected subtree is `2.0.1`: `.repos/n3/package.json:2-4`, while the root and scratchpad request `^2.1.0`: `package.json:221`, `scratchpad/package.json:15`. Any adoption decision should either pin to this vendored behavior or refresh the vendored source before treating it as evidence for the installed dependency range.
