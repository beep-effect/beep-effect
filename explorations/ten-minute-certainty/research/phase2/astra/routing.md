# Area I — change classification and routing

## Verdict

Package-aware routing is the largest plausible efficiency opportunity in this area, but the current evidence cannot quantify its incremental savings over Turbo's existing affected selection. Implement it as one evidence-bearing plan, not a second graph engine. Refresh and enrich replay first. Preserve full-main verdicts, full Doctest, canonical test census, coverage ownership and run identity, and every required context.

**The blanket #2999 goal-folder widening is not sound for all the lanes it suppresses.** There is a concrete live consumer outside those folders: `packages/drivers/eyecite/test/index.test.ts:41` reads `goals/citation-extraction-engine/history/evidence/2026-11-08-six-form-selection/profile.frozen.json.txt`, decodes it, asserts 29 cases and 33 occurrences. `packages/law-practice/server/test/CitationSixFormProjection.test.ts:208` and `CitationRecognizerWorker.test.ts:75` read the same fixture. The docs regex accepts this path, and `check.yml` suppresses Unit producers on docs-only changes. Changing the file to malformed JSON is a direct missed-red mutation candidate. This is a **source-proven consumer conflict**, not a claim that I ran the mutation or observed a historical missed red. `CoverageScope.ts` also lists `goals/` as noop and its explicit consumer lists do not name this fixture. Fixing only the hosted regex would therefore be insufficient.

This does **not** prove every goal helper needs product Build/Check: goal ops typechecking belongs to retained Repo Sanity, and ordinary asset helpers may have no product consumers. It disproves using the folder as a universal absence-of-consumption proof. The acceptance report for #2999 demonstrates allocation avoidance for a diagram/helper cohort, not equivalence for all packet data.

Six levers follow. Savings rank and implementation order differ: address the VR-2 known soundness conflict and VR-5 evidence gap before enforcing VR-1/VR-3. No tracked files were edited, proofs run, or other seat's output inspected. #3005/#3007/#3014 are treated as merged prerequisites, not proposed work.

### Ranking arithmetic

The 100-run sample spans 23h44m22s. Interarrival estimate `(100−1)/span` is about **100.1 PR runs/day**, or **700.6/week**. This is a burst planning rate, not a long-run forecast; cancelled runs are retained and are not presumed to have paid a full lane's cost. Local rates are **14.1 publish/week** and **11.8 verify/week** in the measured checkout. The brief's fleet count 2,596 is retained as context, not multiplied by an invented fleet mode split or exposure window.

Score = `(700.6 × hosted runner-min saved/run + 14.1 × local publish wall-min saved + 11.8 × local verify wall-min saved) / risk weight`. Weights are explicit ordinal decision aids: low 1, medium 3, high 5. This combines machine occupancy and developer wall only for the requested prioritization; they remain separate reported metrics. Critical-path minutes are never added again. All incremental savings below are **scenario guesses**, not measured causal effects. Using midpoints gives VR-1 ~1,407 min/week/risk-unit, VR-3 ~13, VR-4 ~4; zero-saving enablers tie. An evidence-only ranking has no positive measured savings for these unimplemented refinements.

## Smallest sound unit per gate

This table gives the **smallest presently defensible selection/proof boundary for the complete gate**, not the size of a scheduler subprocess. Affected-set gates can execute as package-sized scheduler leases; their selected union still includes consumers. Repo means a complete relevant census, not that every byte in the repository must be parsed. File means a whole file with configuration/implementation inputs, never a changed hunk. New smaller-grain implementations remain candidates until the named replay and mutation gate passes. Global config, unknown owner, deletion/rename ambiguity and unreadable evidence widen scope.
