## Verdict

Not yet, and the binding terms are queueing and one Yeet-only long pole, not lane bodies. #3005 merged at 17:15Z today (fa8c30740b0) and #3007 is still open. ## Rejected mechanisms considered

- Merge the always-on required jobs (SAST, Security, Secret Scanning, Commitlint, Nix, Codegen Drift, IPC Stdio) into one job to amortize setup: Each is a literal required context in ruleset 10240248. One job produces one check run, and posting synthetic statuses would change the trust source of required contexts (C8). Combined savings are only about 5 runner-min per run. Reopen evidence: A ruleset that binds contexts to a check-run source the merged job could legitimately emit, or a measured share of these jobs in first-wave queueing at the 60 ceiling above ~10%.
- Non-ephemeral (reused) heavy runners to skip Spot boot between lanes: Breaks the runner trust boundary (one job per VM, goals/runner-trust-boundary), and PR-editable steps would share a VM. Reopen evidence: None expected; this is a security constraint.
- Raise the heavy cap or keep a warm idle pool: Money lever, excluded by the brief (capacity is the operator's lever, ruling 57). Reopen evidence: Operator decision.
- Inherit a main commit's verdict from the PR run when the squash tree equals the tested synthetic-merge tree: Push runs use the full profile plus push-only secrets (DATABASE_URL etc.), so the PR verdict is not parity. With merges every ~5 min and a 20-min review window, tree equality is rare. It also amounts to hosted-receipt reuse, which is parked behind the parity ledger. Reopen evidence: A parity ledger showing PR synthetic-merge verdicts predict push verdicts at the same tree, plus a measured tree-equality rate above ~30%.
- Affected-vs-parent scope on main push runs plus a periodic full run: It moves an assurance class from every commit to a periodic gate (an operator trust question per Astra). The saving is small because 19/26 sampled PRs already run every Test Unit family. Reopen evidence: An operator ruling that per-commit affected depth satisfies 'every main commit gets a hosted verdict', plus a hub-edit share below ~50%.
- Disable superseded-run cancellation for PRs: Rejected on record (repository-performance.md:125); obsolete PR heads waste slots at the binding 60-job ceiling. Reopen evidence: None for PRs; C5 reopens it only for main.
- Put Test Unit shards on beep-ec2-heavy / merge small bins: Rejected (repair-decision-2: ~25.5 min cold bins, serial Vitest gains nothing from 8 cores). Reopen evidence: none
