# Phase 2 audit, Opus 5.5 seat: I: change classification and routing

Produced 2026-11-09 by a `claude-opus-5-5` (medium) auditor from the shared brief and the phase 1 inventory; read-only. Paths are repository-relative or `~`.

## Verdict

Routing is not what holds the PR critical path above 10 minutes. The long bodies are Test Integration, Property Laws and Lint Policy, which belong to other areas. Routing's lever is runner-minutes and trust. Inside a lane, package-grain selection already works: Turbo --affected is task-aware. Lint selects only the changed package because lint has no ^ dependency (measured on b80e110: 1 task). transit excludes test/**, so a 106-file law-practice test-only commit selects 3 test tasks. The real waste is at job grain. Every Test Unit shard runs checkout, install and setup before discovering it has nothing to do: 64-105 s each, measured. On sampled single-package PRs that is 7-9 empty shards with today's 13 shards and about 19-21 with #3007's 28. That makes a lane x package-set plan consumed before setup (VR-1a) the top minutes lever, at low risk. The docs-only regex (VR-2) has a measured soundness hole. Replaying it over the 5,083 corpus PR heads (paths computed locally in 14 s) found 9 Heavy / Lint Policy reds on docs-only heads whose base was green. One was confirmed via annotations: knowledge:semantic-delta and knowledge:refs-check failed on a packet-markdown-only head (run 39753415111). Since #2935 (11-08), those gates run on no hosted lane for docs-only PRs. #2999 widens the hole further: goals/*/ops/**/*.ts and manifests are read by a repo-cli unit test and by lint:opaque-roundtrips. So VR-2 is a trust repair that comes before any further skip widening, not a savings lever. The corpus (VR-5) needs three changes before any new refinement can be admitted: refresh past 10-30, map #3005's partition job names, and record failing steps/annotations. Without them, aggregator noise accounts for 170 of 214 apparent docs-only reds. VR-4 is rejected on evidence: the check closure was 57/58 build HIT locally and Heavy / Check took 60 s hosted. VR-6 should start as a differential test, not a rewrite.

## Ranked levers

### VR-1a. Lane x package-set plan consumed before setup: skip empty shards and lanes without booting the install

- **Mechanism:** Add a plan-only mode to the CI binary, e.g. `beep ci lane <lane> --partition <p> --affected --plan-only`. It returns the package set the lane would run: the Turbo --affected selection of the lane's task intersected with the partition's packages (CiLanePartitions.ts), plus CoverageScope's required owners for test-unit. Call it in each matrix job's 'Determine lane execution' step, after checkout and fetch-beep-ci and before 'Setup monorepo CI'. When the set is empty, mark the lane skip-satisfied with a receipt, as the docs_only branch does today. Apply it to every test-unit-shard and lint-shard, and to property-laws, labs, desktop-ipc and ecosystem. The plan is computed per job, so no new cross-job dependency and nothing is added to the critical path (avoids the rejected 'reuse Heavy Admission to skip shards' latency). Heavy lanes (Test Integration, Docgen, Doctest) get the same gate in heavy.yml (two-PR rollout because heavy.yml is @main). final-check and `yeet verify` consume the same plan to print and skip empty per-lane steps.
- **Files:** `.github/workflows/check.yml`, `.github/workflows/heavy.yml`, `packages/tooling/tool/cli/src/commands/Ci/CiLane.ts`, `packages/tooling/tool/cli/src/commands/Ci/CiLanePartitions.ts`
- **Grain:** affected-set. The job already runs Turbo --affected (plus CoverageScope owners) inside the lane. Skipping the job when that exact function returns an empty set for its partition changes no verdict: the same function runs earlier. Partition membership is by package or by file slice of one package. A slice job is empty only when its package is unselected.
- **Savings:** basis: derived; hostedRunnerMinPerPrRun: About 9-12 runner-min avg today (13 shards); about 18-25 on qualifying PRs after #3007 (28 shards); fleet average about 8-11 runner-min per PR run; criticalPathMinPerPrRun: 0 directly; frees about 10-20 concurrent jobs per qualifying run against the org concurrency ceiling, which shortens queue waits for other PRs (unmeasured); localWallMinPerVerify: Small (local lanes already use Turbo --affected); final-check prints 'empty plan' instead of booting Turbo per gate, about 5-20 s. Sources: gh api runs/42597203595/jobs: 9 empty shards = 742 s; gh api runs/42601097467/jobs: 7 empty shards = 513 s; turbo --affected dry-run over 25 main commits: 9/25 leave a whole shard family empty, 8/25 select nothing; gh run list: about 300 PR runs/day
- **Trust risk:** low. Failure mode: The plan-only path diverges from the executed path, e.g. CoverageScope required owners or a full-fallback trigger (cfg:baseline, global inputs) is not reproduced, so a shard that would have run a package is skipped. Stale-green on that partition. Mitigation: One function: plan-only and execution call the same planner (no reimplementation). Any planner error fails open to running. The skip-satisfied receipt records the plan digest. A differential test over the corpus heads asserts plan-only == executed selection.
- **Admission gate:** Parity proof: for every corpus PR head (5,083) plus post-11-09 heads, plan-only package set == the set the executed lane printed (from Turbo summaries; see VR-1b) or == `turbo run <task> --affected --dry-run=json` intersected with the partition. Mutation fixtures: hub src edit selects every shard; test-only edit selects the owner's shards only; root turbo.json/tsconfig/lockfile edit selects all; new workspace; deleted workspace; file moved across packages; standards/coverage baseline edit selects all coverage shards; vitest.setup.ts/@beep/glob edit selects all (T5 gap).
- **Prior art:** #2935 skips docs-only matrices before runner allocation (job-level, regex-driven). The storybook lane already does a pre-run Turbo --affected --dry-run probe intersected with a filter (CiLane.ts:688, 1975), the same pattern at lane grain. Hosted-CI lever L4 (job-level skip instead of booting a VM) is the same idea, and this is its routing half. Rejected: Heavy Admission as a shard gate (latency); removing skipped lanes from the matrix (missing required context). Neither is used here.
- **Depends on:** #3007 (partition table; assumed merged); #3005 (integration partitions; assumed merged); CI binary must be able to run the plan without a full bun install (open question)
- **PR slices:** feat(ci): plan-only mode for partitioned lanes returning the selected package set [M]; ci(check): gate Test Unit/Lint shards and Property/Labs/IPC on the plan before setup [S]; ci(heavy): gate Test Integration partitions, Docgen, Doctest on the plan [S]; feat(yeet): final-check and verify print and skip empty-plan gates [S]
- **Confidence:** medium
- **Open questions:** Can the CI binary compute the Turbo affected set without node_modules (a standalone turbo binary plus lockfile is enough for --dry-run), or must the gate use the binary's own workspace graph and prove parity? | Does Doctest's full-fleet ruling 20 exclude it from plan gating?
