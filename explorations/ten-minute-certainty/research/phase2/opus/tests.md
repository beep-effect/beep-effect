## Ranked levers

### F1. Property sweep runs only tests that consume the fcRuns floor, checked by a census tripwire

- **Mechanism:** Today the sweep's include list (vitest.shared.ts:129-161, propertyTestMarker) selects whole files. Every non-property test in a marker file replays a Test Unit run at the same depth: 4664 tests run for about 121 fcRuns sites in repo-cli. Change: (a) @beep/fc-runs fcRuns() is the only seam where BEEP_FC_NUM_RUNS/BEEP_FC_SEED take effect. In unit mode it records the current test id (vitest getCurrentTest()) into a per-run census file. (b) A committed, generated manifest `standards/property-tests.census.jsonc` (file -> test full names) drives sweep mode. vitest.shared sets testNamePattern, or tagsFilter:['property'] with the manifest applied as tags through a setup hook. The file include list still comes from the manifest, so the file grain is unchanged. (c) A drift gate: the Test Unit producer (hosted and local) fails when a test calls fcRuns and is missing from the manifest, or when a manifest entry no longer calls it. `bun run beep lint property-census --write` regenerates the manifest. The nightly 1000-run sweep uses the same selection. Property tests that do not call fcRuns run at the default depth with a random seed in both lanes, so the sweep adds nothing for them and dropping them loses nothing.
- **Grain:** file. Selection stays per package (--affected) and per file, plus a test-name filter inside the file. Soundness comes from the census: the only behaviour the sweep changes is fcRuns' floor and seed, and every test that reaches fcRuns is recorded on the same head by Test Unit, which covers the same affected scope. A test that starts calling fcRuns without a manifest row goes red in Test Unit before the sweep can under-select it.
- **Savings:** basis: derived; hostedRunnerMinPerPrRun: about 5-8 runner-min on runs that include repo-cli or hub packages (13 of 17 sampled). Mean Property Laws 714 s -> about 300-400 s estimated. Roughly 35-45 runner-h/week at about 60 non-cancelled PR runs/day; criticalPathMinPerPrRun: Property Laws drops from 10-23 min to an estimated 5-7 min; it was the second-longest job (18.1 min) on PR run 42637312401; localWallMinPerVerify: 0 (property is not in pre-push); a local `ci lane property` replay falls from about 15 to about 5 min; cpuSeconds: repo-cli sweep 2017 file-s -> estimated 300-500 file-s; other packages' 1825 s -> estimated 800-1000 s. Sources: run 42626103000 job 129190498338 log (per-file durations); f-jobs.tsv over 30 PR runs; grep of fcRuns( call sites (121 in repo-cli)
- **Trust risk:** low. Failure mode: A test reaches fast-check depth through a path that bypasses fcRuns (inline numRuns, a helper that reads the env directly), so the sweep stops deepening it. Or a test name changes and the filter drops it silently. Mitigation: A runtime tripwire in fcRuns, the census drift gate (missing or extra entries fail), and a lint that forbids reading BEEP_FC_NUM_RUNS anywhere except @beep/fc-runs. The manifest is keyed by test id plus file path, and an empty match for a manifest entry fails the run. Run floors (400 PR, 1000 nightly) and seeds stay unchanged.
- **Admission gate:** Route replay plus a mutation fixture. Replay the sweep on 3 recorded heads (one including 42626103000's head) in both the old and new shape and diff the set of fcRuns-consuming tests executed (it must be equal) and their seeds and run counts. A mutation fixture: add an untagged fcRuns test and prove Test Unit goes red; break a property under the 400 floor and prove the narrowed sweep goes red.
- **Prior art:** The marker-file selection shipped in one-round-loop P1 (the include predicate at vitest.shared.ts:116-161). Inventory T2 names 'select per test instead of per file' as an option. No rejection on record covers per-test property selection. Rejections that must still hold: property run-count cuts and the 'shard rebalance from mixed setup durations' rule.
- **Depends on:** #3007 merged (producer seam)
- **PR slices:** feat(fc-runs): record fcRuns consumers and generate property-tests census [M]; feat(vitest): property sweep selects census tests; drift gate in Test Unit producer [M]
- **Confidence:** medium
- **Open questions:** Do vitest 5.1 tags combine with testNamePattern per file, or should a custom sequencer filter on manifest ids? | How many tests repo-wide reach fast-check without fcRuns (default depth)? A census run would show this. | The property-only cost of repo-cli is a guess; one local `ci lane property --filter=@beep/repo-cli` replay with the prototype filter would measure it.
