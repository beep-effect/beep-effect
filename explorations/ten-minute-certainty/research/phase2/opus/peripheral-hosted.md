# Phase 2 audit, Opus 5.5 seat: L1: hosted surfaces nobody mapped (Vercel previews, storybook.yml, always-on security/commit jobs, Desktop IPC, Labs, Codegen Drift, Ecosystem, Shadcn, side workflows, compiled beep CI binary)

Produced 2026-11-09 by a `claude-opus-5-5` (medium) auditor from the shared brief and the phase 1 inventory; read-only. Paths are repository-relative or `~`.

## Verdict

Every surface in this area finishes in under 3 minutes per job, and with one exception none sits on the critical path to the 15 required contexts. That critical path is Change Profile -> Heavy Admission -> Heavy / *. So this area cannot move the 10-minute p95 by itself, apart from Heavy Admission. Heavy Admission spends a median 49 s of its 74 s on a full `bun install`, only to run a 2 s decision. Moving that decision onto the pinned CI binary takes about 0.8 min off every non-docs PR's path to required green. The bigger opportunity in this area is compute. Every job pays setup that dwarfs its work: Shadcn Lint takes 79 s, of which 16 s is checkout, 39 s is bun install and 4.4 s is oxlint, and it repeats lint:shadcn that the unrefined Lint Policy lane already runs. PR Size, Security, SAST and Rerun Runner Loss each install 2,336 packages to run a GitHub API call. Codegen, Ecosystem, Nix and IPC skip about 148 times per 58 runs, and each skip still pays a 24-28 s checkout. At the measured 7-day volume of 2,059 PR runs, 473 main pushes, 551 Heavy Admit runs and 2,500 Rerun Runner Loss triggers, the levers below remove about 9-10k hosted runner-minutes a week with trust risk of none to low. Vercel costs no GitHub minutes. Still, 77% of its preview statuses on the last 40 merged PR heads were 'rate limited', because oip-web and todox deploy on every push even though only about 13-15% of PRs touch their build closure. A Turbo-scoped ignored-build step would make previews real again and stop the merge-gate exemption firing constantly. The binary is pinned at beep-ci-d15ecf4ca610 (11-07), even though 64 releases have been published since (about 20 builds a day nobody uses). Its pattern file is also read from the PR head. Pin automation and base-ref policy reads are prerequisites for putting more onto the binary, and a trust improvement in their own right.

## Ranked levers

### L1-1. Retire the duplicate hosted Shadcn Lint job (fold the 4 s oxlint walk into a job that already installs)

- **Mechanism:** Delete the `shadcn-lint` job from .github/workflows/check.yml. Lint Policy is the authoritative carrier: `lint:shadcn` is a policyStateTask in Quality/Tasks.ts:3705, and RouteFootprints.ts:150 marks lint-policy `unrefined`, so it never route-skips. To keep an early signal on runs that are not yet admitted (forks, unlabeled drafts), add `bun run lint:shadcn` as one extra step in the Repo Sanity lane (`ci lane repo-sanity`), which already pays the install; it adds ~5-7 s there. Update CI_LANE_DESCRIPTORS (CiLane.ts:555 shadcn-lint), the WaveOrder gate-order fixture (WaveOrder.ts:423) and the workflow-lint expectations to match. The context is not required (standards/branch-protection-contexts.json), so the ruleset is untouched.
- **Grain:** repo. Unchanged: the same whole-tree oxlint walk over apps+packages (9,088 files, 4.4 s) still runs once per run in Lint Policy and optionally in Repo Sanity. Only the duplicate runner allocation and install go away.
- **Savings:** basis: measured; hostedRunnerMinPerPrRun: ~1.0 on the 74% of PR runs where it executes (81 s p50 job minus ~7 s added to Repo Sanity); ~2,300-2,500 runner-min/week at 2,059 PR + 473 push runs; criticalPathMinPerPrRun: 0 (not required, not on the Heavy path); localWallMinPerPublish: 0; localWallMinPerVerify: 0. Sources: check.yml:395-406; job log 129229068996 (16 s checkout, 39.18 s install, 4.4 s oxlint); 58-run job census: 43 ran, p50 81 s; 7-day totals via actions/workflows/check.yml/runs total_count
- **Trust risk:** none. Failure mode: An unadmitted fork or draft PR with a shadcn violation would surface it only at Lint Policy, unless the Repo Sanity step is added. Mitigation: Fold the step into Repo Sanity, which is required and always runs except goals-only. Lint Policy remains unrefined.
- **Admission gate:** none, pure waste removal. Prove with one PR that plants a shadcn violation and goes red in both Lint Policy and Repo Sanity (mutation fixture), plus workflow-lint green.
- **Prior art:** levers-compact L10 'Remove trivial hosted duplicates' (low confidence, no numbers). perf audit R6 (2026-11-02) removed the local duplicate only. P35 (one oxlint process for oxlint+shadcn) was rejected because the merged config leaked findings; this lever keeps the separate config and command, so it does not reopen P35.
- **PR slices:** ci: retire the duplicate Shadcn Lint job; run lint:shadcn inside Repo Sanity [S]
- **Confidence:** high
- **Open questions:** Does yeet's IssueClassification or the inbox key any remediation on the 'Shadcn Lint' context name rather than the lint:shadcn needle?

### L1-3. Automate the CI binary pin bump, narrow its publish trigger, and read policy data from the base ref

- **Mechanism:** (a) Change beep-ci-binary.yml so a publish is followed by an automated pin-bump PR (the same create-pull-request + App-token pattern knowledge-baseline-mint.yml uses) that edits BEEP_CI_RELEASE_TAG and SHA256 in .github/actions/fetch-beep-ci/action.yml, labelled ready-for-heavy. (b) Narrow the push `paths` filter from packages/tooling/library/**, packages/foundation/**, packages/drivers/** to the binary's real import closure, generated from `bun build --metafile` into a checked projection that workflow-lint verifies. (c) Make change-profile, and any binary command that reads policy JSON, read CiOperational.patterns.json from the PR base SHA (`git show $BEEP_CI_PR_BASE_SHA:<path>`) rather than the head checkout. A pattern change then binds after merge, as heavy.yml@main does.
- **Grain:** n/a. Not a selection change. It governs which binary version and which policy revision the selection runs under.
- **Savings:** basis: measured; hostedRunnerMinPerPrRun: 0 directly; ~40-50 runner-min/week from fewer unused binary builds (49/week x 69 s today, most never pinned); criticalPathMinPerPrRun: 0. Sources: 64 beep-ci-* releases versus a single pin d15ecf4ca610; beep-ci-binary 49 runs/7d, 69 s avg; CiOperational.service.ts:57,190-203 reads patterns from the head checkout
- **Trust risk:** none. Failure mode: Today a PR can edit CiOperational.patterns.json, for example widening `docs`, and its own Change Profile run reads the edited file. That makes it docs_only, and the Heavy required contexts become skip-satisfied without a proof. Reviewers are the only guard. Mitigation: Base-ref reads close the gap. The pin-bump PR runs the full Check, including the binary smoke, before it lands.
- **Admission gate:** route replay + mutation fixture: a fixture PR that widens `docs` in the patterns file must still be classified by the base patterns (not docs_only). The pin-bump PR proves itself through its own Check run.
- **Prior art:** #2906 introduced reading patterns from the checkout to avoid rebuilding the binary for pattern edits. knowledge-baseline-mint.yml is the in-repo automated-PR precedent. heavy.yml@main is the 'policy binds after merge' precedent (inventory K).
- **PR slices:** ci: classify against base-ref CI patterns [S]; ci: open a pin-bump PR after each binary publish; scope the trigger to the binary closure [M]
- **Confidence:** high
- **Open questions:** Should the pin-bump PR auto-merge at the Quality Operator gate, or wait for an orchestrator merge? | Which GitHub App identity should open it? The knowledge-mint App is scoped to one file.

### L1-4. Move the per-lane path gates into Change Profile outputs and skip at job level

- **Mechanism:** Codegen Drift, Ecosystem Contracts, Nix Shell, Professional Desktop IPC Stdio and Labs (labs_checks) each check out full history (19 s), fetch the binary and run a shell `git diff | grep -E` before echoing 'Skipping'. Move those regexes into CiOperational.patterns.json as named lane-relevance patterns, emit `<lane>_relevant` outputs from `beep ci change-profile` (the Change Profile job already has full history), and change each job's `if:` to `needs.change-profile.outputs.docs_only != 'true' && needs.change-profile.outputs.<lane>_relevant == 'true'`. A job skipped by `if:` reports skipped, which GitHub treats as passing for required checks. The repo already relies on that for docs_only. Pushes keep running everything.
- **Grain:** file. The same file-path regexes, reviewed per lane (for example, the flake evaluates no repo files, Ecosystem imports no workspace package, and the IPC closure is listed in check.yml:1046), are evaluated once instead of five times. The grain is unchanged, only the location moves. This depends on L1-3(c) so a PR cannot widen its own skip.
- **Savings:** basis: measured; hostedRunnerMinPerPrRun: ~1.07 (2.55 lane-skips per run x ~25 s); ~1,700-1,800 runner-min/week, plus ~5 fewer runner allocations per PR run in the hosted queue; criticalPathMinPerPrRun: 0. Sources: 58-run census: lane-skips Codegen 39, Ecosystem 36, Nix 40, IPC 33 at 24-28 s p50; check.yml:246-279, 1031-1051, 1781-1791, 446-461
- **Trust risk:** low. Failure mode: A transcription error in a moved regex skips a required lane (Codegen Drift, Nix Shell or IPC) that should have run, and the PR shows it as skipped/green. Mitigation: A parity ledger: run the old shell gate and the new profile output side by side for a week and compare. Fixture-test each lane pattern in ci-change-profile tests. Every main push still runs every lane, so a missed red surfaces on main.
- **Admission gate:** route replay + mutation fixture (per-lane fixture diffs that must and must not select), plus a parity ledger of old versus new should_run over a week of PR heads
- **Prior art:** levers-compact L4 is the heavy-VM analogue (job-level route skip instead of booting a VM to skip) and L7 is setup amortization. #2935 moved the docs-only skip before runner allocation for tier-1 matrices. This extends that mechanism to the remaining per-lane gates.
- **Depends on:** L1-3 (pin bump carrying the new outputs; base-ref patterns)
- **PR slices:** ci: emit lane-relevance outputs from change-profile with fixtures [M]; ci: skip Codegen, Ecosystem, Nix, IPC at job level from change-profile outputs (after the binary pin bump) [S]
- **Confidence:** high
- **Open questions:** Should IPC's rust_should_run (desktop pattern) and should_run collapse into one profile output with two fields?

## Rejected mechanisms considered

- Shallow checkout for Commitlint and Secret Scanning (checkout is 19 s of their 28-31 s): Rejected on record (L22, repository-performance.md:124): there is no merge-base proof, and Gitleaks needs the range history. Reopen evidence: A measured blobless depth-N fetch that proves the merge-base and range for 100% of the last 1,000 PR heads.
- Skip Security, SAST, Commitlint or Secret Scanning on docs-only or goals-only diffs: Inventory K/C constraint: these are 'never skip' required contexts. Secrets can live in markdown, and dependency review is cheap. Reopen evidence: An operator trust ruling. Performance data alone does not reopen this.
- Merge the short tier-1 jobs into one mega-job to amortize setup (levers-compact L7 as a merge): It loses per-context identity for required checks and the parallel early signal, and lengthens that job's wall. The binary and job-level-skip levers remove the same setup tax without merging. Reopen evidence: Evidence that the hosted queue (not runner-minutes) is the binding constraint for these ubuntu jobs.
- Tune the Playwright Chromium cache in storybook.yml: Already keyed on the Playwright version, saved only on trusted pushes. Hit-path install is 8-20 s, so not the cost driver. Reopen evidence: A Playwright install p50 over 60 s across a week.
- Drop free-disk cleanup from verification-steps jobs: Measured no-op: 85 GiB free is at least the 64 GiB threshold, so the cleanup already skips. Reopen evidence: Runner images shipping with less than 64 GiB free on /.
- Act on job-context-contract-pr, hub-pipe-security, history-notes-publish, skills-update-train, knowledge-baseline-mint or the cache-* family: Already path-filtered, scheduled or dispatch-only, at 3-215 s per run. Weekly cost is minutes, and cache-warm is biweekly. Reopen evidence: A trigger change that makes any of them fire per PR push.
- Disconnect Vercel previews, or upgrade the plan to lift the rate limit: Disconnecting removes a product preview, which is an operator call. Upgrading is money (escalation list). The ignored-build step removes the cause without either. Reopen evidence: An operator decision that previews are unwanted.
