# Phase 2 audit, Opus 5.5 seat: B. Coverage (touched-package ratchet before publish, file-scoped long poles, comparator latency, inherited vs introduced, baseline conflicts, required-context choice)

Produced 2026-11-09 by a `claude-opus-5-5` (medium) auditor from the shared brief and the phase 1 inventory; read-only. Paths are repository-relative or `~`.

## Verdict

Coverage can meet its share of the target only if two separate things change, and neither is a cheap fix. On hosted CI the coverage verdict is tied to the slowest Test Unit shard. In this window, push to Coverage Regression green was p50 29.0 min and p90 40.6 min, and the comparator job itself takes 313 s p50. While the slowest shard takes more than about 7 min, no change to the comparator brings Coverage Regression under 10 min. That is why making it a required context now would make the 10-minute required-context target unreachable. That trade cost it its required status on 2026-09-12 (it breached at 30m58s). Locally, the problem is trust rather than speed. The final-check coverage gate is skipped in 64% of receipts (101/159). When it does run it takes 13-50 min and fails 45% of the time (26/58), while only 1 of 43 completed hosted comparator runs in the last 24 h was a genuine ratchet red, a direct-owner drop. So the local signal is mostly noise: Node 24 against hosted Node 22 for 196 of the 197 coverage scripts, contention, no inherited/introduced labels, and a bare `bun run coverage` that judges without the merge-base self-judge. The biggest lever is a small advisory coverage run on directly touched packages, admitted by the scheduler, at publish (COV-L1). It runs under Node 22.23.4, uses the merge-base three-document judge, and labels rows (COV-L5/L7). The long poles are covered by file-scoped related-test runs (COV-L2), whose green is sound because per-file coverage from a subset of tests can never exceed coverage from the full test set. These levers do not shorten the hosted run. They catch the ~1-2 genuine reds a day about 25 min earlier and avoid a full re-run (~164 check.yml runner-minutes each). The one pure win on hosted latency is raising the comparator's discovery and verification concurrency (2 and 1 to 4), worth about 2-2.5 min on large-scope runs. Recommended operator choice: keep Coverage Regression non-required and keep it gating Yeet mergeable until Test Unit plus the comparator fit 10 min at p95. Do not drop the mergeable gate: that would let floor regressions reach main, where 42% of PR runs and most main runs are cancelled before a verdict.

## Ranked levers

### COV-L1. Advisory touched-package coverage ratchet at publish (direct owners only, merge-base judge, Node 22.23.4, scheduler-admitted)

- **Mechanism:** Add a `--direct` scope mode to the root coverage command (Tasks.ts resolveCoverageTaskOptions beside --affected). Selection = changedCoverageOwners(owners, changedFiles) (CoverageScope.ts:997), with repository-fixture owners and no dependents. Owners whose weight exceeds COVERAGE_SELECTED_SINGLE_RUN_MAX_WEIGHT_SECONDS (300 s: law-practice-server, repo-cli) go to COV-L2 file scope, or are reported as 'deferred to hosted' until COV-L2 lands. Full-fallback reasons (global inputs) are reported, not run. The judge reuses readComparisonBaseline(repoRoot, mergeBase) and compareCoverage unchanged, so floors, epsilon, self-judge, raised-row and minimum rules are byte-identical to the hosted comparator. Runtime: Node packages run with Node 22.23.4 on PATH (COV-L7); LPS stays on Bun. Exact command yeet runs: `TURBO_SCM_BASE=$(git merge-base origin/main HEAD) bun run coverage -- --direct --advisory`, wrapped in withQualityAdmission with a new AdmissionWorkKind (e.g. 'coverage-unit') weighted from CoverageScope weights (1 token under 60 s of weight, 2 under 300 s). It runs concurrently with cheap-gates inside `yeet publish`, never blocks the push, writes `.beep/yeet/coverage-direct/<head>.json`, and prints labelled rows (COV-L5) into the publish summary and the PR body section. Hosted Coverage Regression remains the proof of record.
- **Grain:** package. Most introduced coverage drops are per-file or per-package rows of packages the PR edited, as in the one genuine red this window (alchemy-postgres host.ts, a direct owner). Package grain reruns the owner's full canonical coverage script, so its rows match hosted rows exactly, given the same runtime and code. It deliberately drops dependents, the only part of hosted scope it omits, and says so in its output.
- **Savings:** basis: derived; hostedRunnerMinPerPrRun: ~2.8 runner-min/run amortised: genuine coverage reds ~1 in 43 completed runs (2.3%) x ~164 check.yml runner-min per avoided fix re-run (heavy.yml extra). ~100 PR runs/day gives ~1.7 avoided re-runs/day, ~1,900 check.yml runner-min/week.; criticalPathMinPerPrRun: 0 on the run itself. Mitigation: Output always states its scope ('direct owners only; N dependents, global inputs and merged-code effects are judged by hosted Coverage Regression'). The merge-gate never reads the receipt. Base-drift rows (selected owners whose baseline row differs between merge-base and origin/main) are flagged with 'merge origin/main for parity'.

Ship advisory immediately. Promote any class to blocking only after ≥50 paired publishes with zero local-green/hosted-red rows on direct owners and a recorded false-red rate. Route replay: a mutation fixture (delete a test covering one function in a small package) must turn the local run red with the same row text hosted prints.

### COV-L5. Label every ratchet failure row: introduced / indirect / dependent / base-drift / environment / cascade

- **Mechanism:** After compareCoverage, classify each failure row deterministically: (a) introduced-file: the row's file is in merge-base..HEAD; (b) introduced-package: the package has changed src or test files but this file did not change; (c) dependent: the package owns no changed file (only reachable through dependentSeedOwners); (d) base-drift: the row differs between the merge-base and origin/main documents; (e) environment: the run's runtime (process.versions.node) is not 22.23.4 for a Node package; (f) inherited: the same context failed on the merge-base commit's hosted run (reuse MergeGate's own-red lookup, compare/base...head check runs). Hosted, the comparator prints 'cascade: Test Unit failed (shards …)' when lane-gate fails on UNIT_RESULT (2 of 3 hosted reds this window). The labels go in final-check receipts (add failure-class counts to the coverage step) and in COV-L1 output. Floors and verdicts do not change.
- **Grain:** file. Pure classification of rows the existing judge already produced, using git diff and documents the judge already reads. No measurement changes.
- **Savings:** basis: derived; hostedRunnerMinPerPrRun: 0 directly; criticalPathMinPerPrRun: 0; localWallMinPerPublish: 0 (seconds of git diff); localWallMinPerVerify: Indirect. Local final-check coverage fails 45% (26/58, runs of 205-3165 s). If labels let agents act on introduced rows and pass environment and base-drift rows to hosted, part of the 101/159 skips become runs and part of the 26 red loops end at the first read instead of a re-run (unquantified).. Sources: final-check receipt census (covB-fc.tsv); check.yml lane-gate UNIT_RESULT condition; hosted red attribution (3 reds)
- **Trust risk:** none. Failure mode: A wrong label (e.g. 'environment' on a real drop) could tempt an agent to ignore a real red. Verdicts and floors are unchanged, so hosted still fails it. Mitigation: A label never changes exit status. 'inherited' is used only with a hosted red on the merge-base commit as evidence; otherwise the row stays 'unattributed'.
- **Admission gate:** Fixture replay: unit tests over synthetic diffs and documents covering each class, plus a replay over the three hosted reds in this window (cascade x2, introduced-file x1) that must reproduce their labels.
- **Prior art:** Inventory COV-L5. The merge-base document and self-judge scope already exist (CoverageRegression.ts:1098-1102, 3549-3555). MergeGate own-red attribution (2026-11-02).
- **Depends on:** none (COV-L1 consumes it)
- **PR slices:** feat(coverage): classify ratchet failure rows by authorship and environment [M]; feat(yeet): record coverage failure-class counts in final-check receipts; label hosted cascades [S]
- **Confidence:** high
- **Open questions:** Is the hosted run of the merge-base commit usually available? Main push runs are mostly cancelled, so 'inherited' will often fall back to 'unattributed'.

### COV-L2. File-scoped related-test coverage for touched files in law-practice-server and repo-cli

- **Mechanism:** For a long-pole owner with changed src files F: run, in the package dir and with its canonical runtime (LPS `bunx --bun`, repo-cli Node 22.23.4), `vitest related <F> --run --coverage --coverage.include=<F>` plus the package's canonical --exclude args. Judge only the per-file rows of F with the same compareCoverage file judgement (CoverageRegression.ts judgeFileFloor). Soundness: V8 and istanbul per-file coverage is a union over executed tests, so coverage from a subset of tests is ≤ coverage from all tests for the same file and code. A scoped green therefore implies the full-run per-file row is green (modulo flake); a scoped red may be a false red from a test the static map missed (dynamic import, fixture-path loading, subprocess). If any test file of the package changed or was deleted, untouched files can lose coverage; escalate to 'package-level needed' (run full package if weight allows, else defer to hosted) instead of guessing a closure. Escalate the same way when the related set exceeds ~30% of the package's test files.
- **Grain:** file. Sound for green on the touched files' rows by the subset-monotonicity argument. Not sound for package totals, untouched files, or the new-file 'introduced uncovered units' rule beyond F, so it never claims those rows.
- **Savings:** basis: derived; hostedRunnerMinPerPrRun: Extends COV-L1's catch rate to the 19% (LPS) and 29% (repo-cli) of PRs touching a long pole; same ~164 runner-min per avoided re-run; criticalPathMinPerPrRun: 0; localWallMinPerPublish: ~1 min for long-pole PRs (receipts reproduced a CreatePackage.command.ts row in 48 s) against 2680 s / 1192 s package runs that are never done at publish today; localWallMinPerVerify: Could replace part of final-check's long-pole coverage cost only if a later ruling allows; not proposed. Sources: inventory COV-L2 receipt 40-48 s; covB-owners.py long-pole touch rates; vitest 5.1.0 installed (supports `related`)
- **Trust risk:** low. Failure mode: Flake-driven green (a branch hit by timing in a subset run); false reds from an incomplete static mapping erode trust in the advisory. Advisory only, so no stale green reaches main. Mitigation: Advisory, with explicit scope text ('rows for N touched files; package totals and other files judged by hosted'). Escalate on test-file edits. Parity ledger against hosted per-file rows.
- **Admission gate:** Parity ledger replay: for the last ~30 merged PRs touching LPS or repo-cli whose hosted unit-coverage artifacts are still retained (7 days), run the scoped command at the PR head and require scoped_row ≤ hosted_row for every file in F (no violations), with equality in ≥90% of rows. Mutation fixture: remove a test that uniquely covers a function in a touched file; the scoped run must go red.
- **Prior art:** Inventory COV-L2 and T1 (file-level selection, high risk as a hosted producer change; this lever is local advisory only). Q3 'file-level plan alone' was killed for hosted shards (1,120 s single-file floor), which does not apply here. No code uses `vitest related` today.
- **Depends on:** COV-L1 (host command and receipts); COV-L7 for repo-cli
- **PR slices:** feat(coverage): related-test file-scoped rows for long-pole owners (advisory) [M]; chore(coverage): parity replay of file-scoped rows against retained hosted artifacts [M]
- **Confidence:** medium
- **Open questions:** Fan-out of `vitest related` on LPS (299 test files) for typical edits: if most LPS src files are reachable from most tests via barrels, the related set approaches the whole package and the lever degrades to 'defer'. Must be measured on a quiet host. | Does istanbul under Bun honour --coverage.include identically to the full run's file identity?

### COV-L9. Row-wise three-way merge driver for standards/coverage.regression-baseline.jsonc

- **Mechanism:** Register `merge=coverage-rows` in .gitattributes. The driver parses ours, theirs and base as CoverageRegressionBaseline and merges per package row: take the side that changed a row; conflict only when both sides changed the same package (or file row) to different values; keep the header from whichever side changed it. A failing or absent driver leaves the conflict (same contract as the regenerate driver). It never recomputes measurements, so it does not violate 'coverage evidence is bound to run + head'. The merged document is judged on the merge ref by hosted.
- **Grain:** file. Package rows are independent records; the hosted comparator re-judges the merged document on the merge commit.
